## Три архетипа папок (ядро модели — всё дерево сводится к ним)
Любая папка — один из трёх видов. Это весь словарь структуры:

1. **`NN-` / дата — нумерованный УЗЕЛ (главный инструмент роста).** Ствол дерева. Нумерация всегда **по
   смыслу к модели** (дополняет её, а не «просто счётчик»), последовательна по ходу обсуждения. **Узел
   заводим ПАПКОЙ, не файлом** — у узла потенциал роста (разделится на под-элементы); файл — только для
   финального, неделимого. Дата-префикс — для trace/событий.
2. **plural (`ideas/ questions/ decisions/ analyses/ plans/ maps/`) — КОНТЕЙНЕР-сборщик.** Собирает
   однотипное. Многофайловый разбор кладём В ОДНУ такую папку, не россыпью файлов. БЕЗ номера; дети внутри нумеруются.
3. **`_` (`_shared/ _proposals/ _generated/ _unverified/ _archived/`) — СЛУЖЕБНОЕ/навигационное.** Виды,
   индексы, сквозное, черновое. БЕЗ номера. Исключение — **`_log/`** = trace (след), не служебка.

**Файлы — единый суффиксный стандарт:** `.{type}.md` (`.decision.md · .idea.md · .analysis.md · .design.md`).
Какой именно набор — вторично; главное ЕДИНЫЙ стандарт, тип берётся из реестра `.doc-types.json` (растёт как
глобально, так и проектом). **Корень любой папки — минимум файлов:** только навигатор (`INDEX.md`/`README.md`
= ВИД) + финальные единицы; всё, что делится, — в под-папку.

## Несокращаемые законы размещения

1. **Два вещества, не мешать.** *Trace* (след: что произошло) — append-only, только УКАЗАТЕЛИ, дом `docs/_log/` (gitignored). *Knowledge* (истина: как устроено) — дерево, переживающее сессии. Trace ССЫЛАЕТСЯ на knowledge, не хранит его.
2. **Один дом на тему/разбор.** У анализа/решения — РОВНО ОДИН постоянный дом (его механизм/тема). Дубля контента не создаём; служит многим → `_shared/` + теги, но всё равно один дом.
3. **Консолидируй ПЕРВЫМ ходом.** Прежде чем завести новый файл/папку — ищи существующий дом и пиши внутрь. **Не досыпать пакет поверх бардака** (это делает «средне»→хуже). Дома нет → `topics/`-стейджинг с меткой `needs-home`.
4. **Нет loose-файлов.** Много файлов разных типов в одной папке = запах. Группируй по типу в плюрал-контейнеры (`maps/ analyses/ questions/ decisions/ plans/ _proposals/`). Плоский корень допустим только у финальной единицы.
5. **Тип решает дом.** Файл несёт суффикс `.{type}.md`; дом берётся из `homeRule` в `.doc-types.json`. Суффикс не на своём месте (`.idea.md` в `analyses/`) = СИГНАЛ на перенос, не ошибка — флагуй.
6. **Нумерация R1.** Именованная папка-узел (концепт/тема) → префикс `01- 02-…`. Плюрал-контейнеры и `_`-папки — БЕЗ номера; файлы внутри нумеруются.
7. **Закон суффикса `.concept.json`.** Только для файлов, проходящих detectConcept (`type|id` + `steps[]|paths[]`) — это ВИД/визард. Trace (handoff, лог-шаги) — `.md`, НЕ `.concept.json`. Enforcement: `tools/lint/concept-lint.mjs` (pre-commit).
8. **Навигатор = ВИД, не второй дом истины.** Один навигатор на трек. Несколько карт на один трек → свести в один. **Предпочитай генерируемые авто-виды рукописным.** `docs/INDEX.md` = единственная точка входа; держать ПРАВДИВОЙ (мелкий, area-level, со статусами) и обновлять в конце сессии.
9. **Статус — во frontmatter, не удалять.** `draft|review|approved|active|archived|superseded`. Закрытое/устаревшее архивируется СТАТУСОМ (файл остаётся), а не удалением. Дубли гасим редирект-заглушкой.
10. **LOSE-NOTHING при слиянии.** Новее/глубже побеждает как направление, но ничего не стирается: со-размести датированные версии в одной папке → синтез (агент+критик), не деструктивный git mv.

## Строгость и исполнение
- По умолчанию **soft**: не стопори работу; наводи порядок отдельным прогоном (warn-не-block).
- **На диск — только по явному «строй» владельца.** Без «строй» — ОПИСЫВАЙ размещение/переезд. Переезды обратимы (план отката до миграции).
- Правки самого скилла/реестра — через `agent-builder` + одобрение владельца (R1). Молча не переписывать.
