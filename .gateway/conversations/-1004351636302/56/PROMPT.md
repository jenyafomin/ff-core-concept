  **КОМАНДЫ агентов**.

### 🎯 ЦЕЛЬ (корень — из неё выросло всё остальное)
**Единица памяти — не тип узла, а РОЛЬ узла/ребра с «контрактом повторного входа»:** будущий читатель
(часто — ты сам как незнакомец) сможет её НАЙТИ, ОЦЕНИТЬ не вскрывая, ДОВЕРИТЬСЯ в меру, ВПИСАТЬ под
своим углом — и след использования вернётся в неё саму.
**Главная проблема (формула):** информация рождается многомерной, а запись/чтение — одномерны →
**«как одна запись обслуживает много будущих вопросов, под которые она не писалась».**
Из этой цели выросли **7 ценностей** — это её грани.

### Цепочка работы (сверху вниз, можно возвращаться)
`ЦЕЛЬ → ЦЕННОСТИ (папки) → КОНЦЕПТ каждой → ИДЕИ (в папке ценности) → ИНФРАСТРУКТУРА (на идеях)`

**L1 — ЦЕННОСТИ.** 7 пронумерованных ценностей = папки, которые УЖЕ есть (`values/V1-chitaemost … V7-soglasie`):
Ц-1 Читаемость · Ц-2 Тождество · Ц-3 Доверие · Ц-4 Витальность · Ц-5 Суверенность · Ц-6 Реляционность · Ц-7 Согласие.
Базис собран. Задача не добавлять ценности, а понять каждую глубже.

**L2 — КОНЦЕПТ каждой ценности (ТЕКУЩИЙ ФРОНТ).** Спроси «X — ЧЕГО именно?»: тождество — чего? читаемость —
чего и для кого? доверие — чему? Выведи **чёткое НАПРАВЛЕНИЕ** того, что мы делаем для этой ценности.
Держи **абстрактно, но точно** — НЕ падай в банальные инструменты («прозрачность = фильтры/спец-просмотр БД»
— это рано и мелко). Прогоняй сложные предметные кейсы (пример «таблицы/реактивность») как **стресс-тест** —
они показывают, где мы ещё не были. Критика — **дополняющая** (расширять концепт, не искать дыры).

**L3 — ИДЕИ (лежат ВНУТРИ папки ценности/концепта, не в отдельных папках пока).** Под каждый концепт
распиши идеи: идея-1, -2, -3… Идей может быть много — важно, чтобы каждая лежала в правильном месте.
Каждая идея = **решение конкретной проблемы** + что из программирования / дизайн-паттернов / структур
данных её закрывает. Одна модель может закрывать несколько ценностей сразу.

**L4 — ИНФРАСТРУКТУРА (строим НА идеях, а НЕ «после» них).** Берём наработанные идеи → выбираем и
анализируем лучшие → допиливаем → связываем в ЕДИНУЮ, между собой связанную систему. Цель — память
**доступна и переиспользуема** (модульность / plug-in заложены с 1-й итерации). Отсюда — к engine-spec / ADR.

**🔴 СЕЙЧАС (под-цель).** Довести КОНЦЕПТ брейна до полноты в документации: сформировать все 7 ценностей
и **инфраструктурные концепции всего проекта** (что уже есть — переиспользовать, не плодить дубли).
Живая нить владельца: **тип связи → «потоки»** (реактивные рёбра, реагирующие на изменение; рёбра
поверх папок; «папка-оркестрация») — семантика, которую одна нода определить не может. Копится как
