# Каркас покрытия: ценности · линзы · акты

> Формализация каркаса владельца (голос 2026-08-04) поверх несущей абстракции субстрата:
> субстрат хранит навсегда РОВНО одну вещь — ленту актов; всё остальное = `fold(journal)`.
> Цель файла — дать скоринг-агентам ЕДИНЫЕ определения и рубрику, чтобы карта покрытия
> и приоритеты считались одинаково. Это НЕ карта покрытия (её строит волна 2) — это её линейка.

Три слоя, из которых собрана картина, сверху вниз по СПЕЦИФИЧНОСТИ и снизу вверх по ЧИСЛУ:

```
ГРАНИ ЦЕННОСТЕЙ   (спрос: что субстрат ОБЯЗАН обслуживать)      ← много   (~40)
        ↑ обслуживаются
ЛИНЗЫ            (машинерия: как fold(journal) отвечает на вопрос) ← меньше (~7-12)
        ↑ сворачиваются из
АКТЫ (виды)       (предложение: атомы записанной правды в ленте)   ← меньше всего (~5)
```

Ключ к иерархии: **чем ниже слой, тем он БЕЗРАЗЛИЧНЕЕ к содержанию.** Акт-вид ничего не знает
о ценности; линза знает форму ВОПРОСА, но не ценность; грань знает ценность. Обобщённость растёт
вниз → одна нижняя единица кормит многие верхние → числа падают вниз. Это и есть воронка владельца.

## 1. Определения и критерий индивидуации

### 1.1 Грань ценности (value facet) — СПРОС
**Определение.** Атомарное обязательство субстрата, сформулированное как обещание человеку/агенту
(«я гарантирую тебе X»). Не сама ценность (их 7: Читаемость·Тождество·Доверие·Витальность·
Суверенность·Реляционность·Согласие), а её неделимая грань. «Ценностей много» у владельца = именно
ГРАНИ (7 ценностей × ~6 фасет-слотов `01-explain…06-nuances` ≈ 40), а не 7 корней.

**Критерий индивидуации (когда две грани — одна, когда разные).**
Две грани ТОЖДЕСТВЕННЫ ⇔ у них совпадает **множество отказов**: любой сбой мира, нарушающий одну,
нарушает и другую, и наоборот. Если существует состояние, которое ломает A, но не B — это РАЗНЫЕ грани.
Грань — это, по сути, класс эквивалентности «способов не сдержать обещание».
Тест на атомарность: грань нельзя разбить на две под-грани с непересекающимися множествами отказов.

### 1.2 Линза (lens) — МАШИНЕРИЯ
**Определение.** Переиспользуемый способ свернуть ленту в ответ на ОДНУ форму вопроса:
`fold(journal, question-shape) → view`. Линза — сторона предложения-обработки: она не хранит правду,
она её ПРОИЗВОДИТ (I-5/I-14: производна, сносима, пересобираема). Кандидаты-линзы из канона ядра:
current-state-fold · recall/salient (ранжированная память) · provenance/explain-chain · as-of/temporal ·
access/view-filter (`resolve()`-проекция) · semantic/RAG · staleness-маркер.

**Критерий индивидуации.**
Две линзы ТОЖДЕСТВЕННЫ ⇔ совпадают (a) форма вопроса, (b) входные потоки актов, (c) семантика редьюсера.
Различны, если для ответа нужен ДРУГОЙ редьюсер ИЛИ другой набор act-потоков. Признак «это уже другая
линза»: попытка обслужить новую грань требует изменить логику свёртки, а не только её параметры/фильтр.
(Смена только фильтра/параметра при том же редьюсере = та же линза, другой вызов.)

### 1.3 Акт (act) — ПРЕДЛОЖЕНИЕ (правды)
**Определение.** Атом записанной правды, добавленный в append-only журнал: одно неизменяемое событие
с `actor`+`provenance` (I-2/I-3/I-4). Для каркаса покрытия считаем **ВИДЫ актов (ActKind)**, а не
экземпляры (экземпляров бесконечно много — это не про число слоёв). Виды из I-3-хвоста:
`domain_event · observation · access_event · agent_trace · telemetry` (≈5), с семантикой authority/
retention/replay, различной по виду.

**Критерий индивидуации (вида).**
Два акта — ОДНОГО вида ⇔ у них одинаковая **семантика authority · retention · replay**: одинаково
влияют на канон (меняют его / только наблюдают), одинаково подрезаемы (I-4 carve-out: `domain_event`
не prunable, `observation`/trace — да), одинаково участвуют в replay/rebuild. Нужна другая политика
хотя бы по одной из трёх осей → это НОВЫЙ вид акта. (Не путать с типом УЗЛА `meta:type` — тот про
предметную схему; ActKind — про роль события в ленте.)

## 2. Иерархия |грани| > |линзы| > |виды актов| — почему естественна

Это НЕ строгая функция «многие-к-одному», а **двудольный граф покрытия с фан-ином вниз.**

**Почему линз меньше граней.** Линза générична по содержанию: `current-state-fold` обслуживает всякую
грань, спрашивающую «что истинно сейчас» — Читаемость (увидеть вид), Тождество (личность переживает
свёртку), Витальность (актуальность). Одна линза → много граней. Грань же почти всегда потребляет ≥1
линзу. Поэтому рёбер «грань→линза» много, но столбцов-линз мало → |линзы| < |грани|.

**Почему видов актов ещё меньше.** Один вид акта питает СРАЗУ несколько линз: `domain_event` кормит
и state-fold, и recall, и explain-chain, и temporal одновременно (одна лента — много проекций, ADR-0008
CQRS). Вид акта максимально безразличен к вопросу → самый широкий фан-ин → |виды актов| < |линзы|.

**Матрица связности (словами).**
- Матрица A — строки = ~40 граней, столбцы = ~7-12 линз. Плотная по строкам (грань бьёт в 1-3 линзы),
  разреженная по «уникальности» столбцов (линзы переиспользуются). Покрытая грань = непустая строка.
- Матрица B — строки = ~7-12 линз, столбцы = ~5 видов актов. Ещё плотнее слева-направо: почти каждая
  линза тянет из `domain_event`; `observation`/`agent_trace` кормят recall/explain; `access_event` —
  только access/audit-линзу. Пустой столбец акта = вид, который заведён, но ни одна линза его не читает
  (запах: мёртвый поток). Пустая строка линзы = линза без источника (не может существовать).

**Где воронка ВЫПИРАЕТ (важно для честности).** Инвариант неравенства держится обобщённостью, но НЕ
гарантирован. «Прожорливые» грани требуют СВОЮ линзу и/или СВОЙ вид акта 1:1:
- Право на забвение / hard-erase (Ц7 Согласие) → просит терминальный `erased`-акт (I-15) + свою линзу.
- Как-было-тогда / аудит доверия (Ц3) → просит as-of/temporal-линзу, отложенную из MVP (D-5).
Такие грани локально ломают пирамиду (там линз/актов не «меньше»). Это сигнал приоритета, не ошибка модели.

## 3. Определение покрытия и метрики %

### 3.1 Когда грань «покрыта»
**Одной фразой:** грань ПОКРЫТА, когда существует хотя бы одна цепочка `вид-акта → линза → ответ`,
которая реально удовлетворяет обещание грани НА СЛОЕ ПРОДУКТА и НЕ нарушает ни одного инварианта —
а не просто нарисована в дизайне.

Раскрытие цепочки-покрытия (все условия обязательны):
1. **Есть источник:** вид акта K долговечно журналируется (durable, S7).
2. **Есть свёртка:** линза L сворачивает K в ответ формы, которую грань спрашивает.
3. **Ответ удовлетворяет обещание** грани (закрывает её множество отказов).
4. **Цепочка не пробивает инварианты** (I-1..I-14): напр. линза, отдающая данные в обход `resolve()`
   (I-7), НЕ считается покрытием — это дыра, а не покрытие.

**Глубина покрытия (ось качества, не только да/нет)** — из S7-различия «зелено в юните / зелено на
слое продукта»:
- `0` нет цепочки · `1` designed (цепочка на бумаге) · `2` green-unit (доказана тестом ядра) ·
  `3` green-product (доказана E2E на поверхности продукта, как Ц1 после R1).

### 3.2 Метрики % (две честные + их слабости)
- **M1 — покрытие по граням (бинарное).** `% = (#граней с ≥1 цепочкой глубины ≥2) / (#всех граней)`.
  *Плюс:* просто, прямо отвечает на вопрос владельца «сколько картины закрыто».
  *Слабость:* бинарно — прячет глубину (слабая цепочка = сильной); знаменатель мягкий, т.к. «сколько
  граней» — вопрос зернистости (см. §4-риск). Игнорирует важность грани.
- **M2 — взвешенное покрытие по цепочкам (с глубиной).**
  `% = Σ_грань (вес_ценности × сила_цепочки) / Σ_грань (вес_ценности × 3)`,
  где сила ∈ {0,1,2,3} из §3.1. *Плюс:* учитывает и важность, и глубину; движется, когда цепочку
  доводят с designed до green. *Слабость:* требует весов и субъективной оценки силы → нужна рубрика
  (§4), иначе агенты разъедутся.

Рекомендация: показывать ОБЕ — M1 как заголовок для владельца, M2 как рабочий индикатор прогресса.
(Не-метрика, но полезна для здоровья: фан-аут линзы = сколько граней она держит; низкий фан-аут линзы =
кандидат на упрощение; пустой столбец акта = мёртвый поток.)

## 4. Определение приоритета — рубрика для скоринг-волны 2

Ранжируем НЕ ценности, а **дыры покрытия** (грани с силой цепочки < 3). Каждая грань-дыра скорится по
5 осям с ЖЁСТКО заякоренной шкалой (чтобы разные агенты давали один балл):

| Ось | Что мерит | Шкала (якоря) |
|-----|-----------|---------------|
| **V — вес ценности** | важность родительской ценности грани | 1 периферия · 3 значимая · 5 несущая (Доверие/Согласие/Суверенность = конституционные, ≥4) |
| **G — размер пробела** | как далеко до green-product | 0 покрыта(3) · 1 green-unit есть, продукта нет · 2 только designed · 3 нет даже линзы · 4 нет и вида акта |
| **R — риск бездействия** | что рвётся, если оставить дыру | 1 косметика · 3 деградация UX · 5 пробой инварианта/доверия (утечка мимо resolve(), потеря забвения) |
| **C — цена закрытия** | усилие довести до green | 1 тривиально · 3 модуль · 5 новый вид акта + линза + миграция |
| **Rdy — готовность/рычаг** | есть ли что переиспользовать | 1 с нуля · 2 линза есть, надо провязать · 3 и линза, и акт-поток уже green (только дособрать) |

**Формула приоритета (импакт / усилие, множительная — резче разводит):**
```
Priority = (V × G × R × Rdy) / C
```
Бакеты по результату: **P0 ≥ 60 · P1 30–59 · P2 12–29 · P3 < 12.**
(Множительная выбрана намеренно: грань с V=5,G=4,R=5 и дешёвым рычагом обязана всплыть над «важной,
но неподъёмной и не рискованной». Если владелец захочет линейную сумму — заменить в одном месте,
шкалы осей не трогаются.)

**Правило разрыва равенства:** при равном Priority выше идёт бОльший R (риск-инвариант всегда вперёд),
затем меньший C (дешёвое — раньше). Конституционные грани (Ц3/Ц5/Ц7) с R=5 не опускать ниже P1 вручную.

## Где каркас владельца ЛОМАЕТСЯ / нужно уточнить у него
1. **«Акт» = вид или экземпляр?** Иерархия |акты|<|линзы| держится ТОЛЬКО для ВИДОВ актов (ActKind).
   Экземпляров бесконечно — если владелец считает «акты» как отдельные записи ленты, слой не «меньше».
   Нужно подтвердить: акт в каркасе = семейство/вид записанной правды.
2. **«Ценностей много» = грани, не 7 корней.** Если считать 7 верхних ценностей, |ценности|=7 может
   оказаться < |линзы| и иерархия рушится. Модель держится, только если единица счёта = ГРАНЬ (~40).
   Подтвердить зернистость: считаем фасет-грани, а не ценности-корни.
3. **Воронка не строгая — есть выпирания.** Забвение (Ц7) и as-of (Ц3) требуют своих акта+линзы 1:1;
   там «меньше» не работает. Каркас как ТЕНДЕНЦИЯ верен, как ЗАКОН — нет. Согласен ли владелец, что
   несколько «прожорливых» граней задают львиную долю работы (и потому — верх приоритета)?
