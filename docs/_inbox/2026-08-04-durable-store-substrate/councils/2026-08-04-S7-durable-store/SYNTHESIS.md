# S7 durable StorePort — синтез

## 🔴 ГЛАВНАЯ КОРРЕКЦИЯ ПРЕМИССЫ (высокая уверенность)
Задача звучала «граф RAM-only, испаряется — надо СПРОЕКТИРОВАТЬ и построить durable-store».
**Это устарело. Ядро S7 УЖЕ ПОСТРОЕНО, протестировано и запечатано в коде.**

Доказательства (сошлись 3 независимых агента + проверено вручную оркестратором):
- `packages/engine/src/adapters/store-durable-fs.ts` (194 стр) — `DurableFsStore implements StorePort`:
  fsync'd JSONL-журнал, rebuild-from-journal на boot, append-only-forward, идемпотентность через ребут,
  advisory PID single-writer lock, drop оборванной последней строки.
- Тесты гоняют **настоящую границу OS-процесса** (spawn→exit→новый процесс стартует с диска):
  `packages/engine/test/survive-turn.test.ts`, `durable-reboot-matrix.test.ts` (5 тестов, 87/87 green по seal-плану).
- Коммит `b881212 seal GAP 1 — durable StorePort` — **предок HEAD** (`git merge-base --is-ancestor` = YES).
- OQ-1 (sync|async) — единственная owner-развилка дизайна — **решена кодом = (A) sync** (верно для короткого синхронного хода).

Канон-соответствие: as-built честно инстанцирует ADR-0008 (журнал=система-записи, граф=проекция),
ADR-0006 (persistence-as-policy), I-5/I-11 (состояние=производная). Журнал = engine-data, НЕ knowledge-tree
→ `doc-tree «файлы=истина»` не конфликтует (ADR-0006 §c развёл вещества).

## ✅ Что реально ОСТАЛОСЬ (ранжировано по ценности) — это и есть «настоящий S7-хвост»

**R1 🔴 Провязать durable-store в живой production-раннер (Ц1 ложно-зелёна на слое продукта).**
`DurableFsStore` зелён В ТЕСТЕ, но **ни один production-раннер его не потребляет** (M3 P4 `cli.ts --store` не написан).
«Память навсегда» доказана в юнит-границе, но не в реальном ходе шлюза. Это #1 по рычагу для Ц1.

**R2 🔴 file-first путь не построен (critic CRITICAL).**
ADR-0006 §(f): типы doc/adr/spec/prompt авторски-первичны ФАЙЛОМ, акт выводится диффом ФС через git-hook/watcher —
которого **физически нет** (`store-md.ts` = TODO M3). Триггер активен СЕГОДНЯ: владелец правит `.md` руками →
журнал не знает → граф молча расходится с файлом, без staleness-маркера. Абстракт-агент: файл играет роль
ПЕРО (вход человеческих типов) или ОТПЕЧАТОК (выход машинных), но не конкурент журналу — механику пера надо достроить.

**R3 🔴 Crash-mid-turn не покрыт (critic).**
AC тестируют graceful exit (P1 завершается штатно). Но проект сам задокументировал `gateway-agents-die-on-restart` —
шлюз убивает процесс ПОСРЕДИ хода. Не специфицировано: fsync-гарантия, что делать с оборванным хвостом журнала
на boot (тихо дропнуть vs fail-closed по I-9). Нужен adversarial-тест реального сценария (паттерн P-06:
не объявлять «строй», пока обход не проверен — проект ловил себя на этом 3 раза).

**R4 🟠 Batch/turn-level идемпотентность (analyst H, конкретная проверяемая дыра).**
Dedup работает по `(source_ref, snapshotHash)` — но **только для одного `domain_event` на ход**. Co-emitted
`observation`-акты НЕ дедупятся никогда → claim ADR-draft-0009 «exactly ONE act-batch» не держится на batch-уровне.
Плюс egress-outbox (T2 guard) вообще не построен → S7 закрыл лишь половину dup-LLM/dup-egress бага.

**R5 🟠 Дом журнала на диске (OQ-2, doc-discipline решение).**
Где физически живёт per-topic `journal.jsonl`? Рек. архитектора: ВНЕ коммитимого дерева — gitignored
`.store/<chat>/<thread>/`, НЕ в `docs/`. Нужно решить ДО wiring раннера (R1).

**R6 🟡 Рост журнала без retention (analyst).**
Full replay гоняется НА КАЖДЫЙ ход. Сейчас (~тысячи актов, <50мс) не проблема, но `observation`/`agent_trace`/
`system_telemetry` растут без retention (KQ-8 открыт, carve-out I-4 не ратифицирован). Стоимость replay-на-ход
растёт незаметно. Снапшот+хвост — аддитивная лестница (снапшот = КЭШ, никогда 2-й источник истины), но не срочно.

## 🧭 Развилка, которую НЕЛЬЗЯ решать кодом (abstract-thinker, уровень FQ25)
**Ветка-гипотеза (acts-as-git, Ц3) — это форк ЛЕНТЫ или вариант ПРОЕКЦИИ?**
- (A) форк журнала = расходящаяся история, merge/выброс — «настоящий git», тянет к concurrency/CRDT (дорого).
- (B) вариант проекции = та же лента, другой reducer — «ветка» = линза, дёшево, одна истина.
Пока открыта — StorePort нельзя расширять под acts-as-git без молчаливого пред-решения (рецидив P-06).
→ РЕШЕНИЕ владельца, не код.

## 💎 Несущая абстракция S7 (языком владельца, abstract-thinker)
Субстрат помнит навсегда РОВНО ОДНУ вещь — ленту того, что случилось (журнал актов). Всё прочее —
граф, файлы-выгрузки, ветки-гипотезы, кэш, новые слои — он ЗАНОВО сворачивает из ленты `fold(journal)`
под текущий вопрос. **Durable = сделай ленту несгораемой; всё foldable держи дешёвым.**
Инвариант-кандидат: ветка · синк · кэш · слой — это РОЛИ одной операции `fold(journal)`, а не подсистемы.
Аналогии: вести владельца git-картинкой, строить по субстанции Datomic (БД=значение из ленты фактов).
Basic Memory врёт вдвойне (2-сторонний sync = 2 источника, отклонён ADR-0006 Alt-3; нет иммутабельного журнала).
