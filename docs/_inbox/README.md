# 📥 _inbox — стейджинг (сквозной, без номера)

> `_`-папка (R1: сквозное, без номера, контент во множественном числе). **В git** — чтобы библиотекарь
> видел и разносил. Это НЕ дом истины, а перевалка.

## Зачем
Агент за ход кладёт сюда произведённое **чёткими отдельными файлами** (не одной кучей), лучше —
**концептами** (`*.concept.json`, которые перечисляют/ссылаются). Отдельный **библиотекарь** (навык
`doc-discipline`) параллельно разносит их в правильные дома по правилам дерева (тема→папки, R1, один дом).

## Правила
- Один продукт хода = один чёткий файл (делить, не сваливать).
- Предпочтение — концепт, который перечисляет, а не длинный текст.
- После разноса библиотекарём файл покидает `_inbox/` (остаётся заглушка-указатель при необходимости).
- Related-чек — часть «разнесено».

## Не путать с `_logs/`
- `_logs/` — **логи диалога** (сессия-как-тема, дата, номера = номера диалога), **gitignore**, локальный скретч.
- `_inbox/` — **артефакты на разнос**, в git.
