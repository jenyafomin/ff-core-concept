# C1 — Непрерывный ингест: данные ТЕКУТ, а не засеваются руками 🟢 быстрый РЕАЛ

**Суть.** Один адаптер «внешнее событие → `Act` в память». Первый источник — Telegram (владелец и так
живёт там, шлюз уже принимает его сообщения). Каждое сообщение владельца = грейн, записанный движком.

**Почему СЕЙЧАС / почему рычаг.** Мы РУКАМИ засеваем день (`day-seed.mjs` вербатим). Пока источник — руки,
«субстрат» не доказан на ПОТОКЕ, и хранилище остаётся пустым между сессиями. Живой источник разом снимает
корневую боль проекта («0 реальных данных за 2 мес»): данные начинают копиться сами, и всё остальное
(salience D3, розжиг C3, вопрос C4) получает топливо. Это самый прямой удар по «анализ как избегание».

**Ценность/цель.** Цель проекта (агрегатор всей жизни) буквально требует входа. Ц1 читаемость получает
реальные тела для label/summary. Провод — тот же, что B в HANDOFF (`ILoopStep`/`EngineClient.write`).

**Параллельной командой?** Да — 1 builder-команда: адаптер + идемпотентная запись (id по message_id) +
тест. Reuse: day-mirror write-путь, шлюзовой приём сообщений уже есть.

**Зависимость от данных.** Обратная — ГЕНЕРИРУЕТ данные. Данные только владельца (`actor=owner`), 0 внешних
гейтов, FORK-U3 не блокирует (пишем от владельца о владельце).

**Тонкий край.** Ц7 (референты в чужих сообщениях) — форма, не enforced; на своём потоке допустимо, пометить.
