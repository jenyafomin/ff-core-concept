# Собрать и направить

> Запрос владельца (голос 2026-08-04): подняться над линейной чехардой волн. Собрать **абсолютно всю
> информацию** (где что лежит), переосознать против **изначальной ценности**, разбить на ключевые
> направления, разложить как **последовательные состояния-папки** (каждое довести до правильной точки),
> сконвертировать линейный формат в правильную документацию, оформить хендофф. Советники сперва сами
> собирают факты, потом думают. Модели: Opus (рабочая лошадь) + Fable (скальпель на острых развилках).

## Три фазы
1. **Перепись фактов** (`census/`) — где лежит вся информация: brain·ядро, ga-rentacar, агентная система,
   процессный слой (состояния/планы/логи/inbox), код-реальность. Для каждого: локация · что · тип · зрелость
   · какой ценности служит · свежесть/дрейф.
2. **Совет-дизайн** (`design/`) — Opus+Fable из переписи проектируют: ключевые направления · какие станут
   последовательными состояниями-папками с целевыми точками · порядок · что кому (Fable/Opus) · как
   конвертировать линейный формат в документацию.
3. **Хендофф** — в `docs/_log/` + пульт `STATE.md`: следующая сессия явно продолжает.

## Принципы (владелец)
- Не линейный лог, а **правильная документация** привязанная к изначальной ценности.
- **Максимальная гибкость** — система сама осознаёт, где какие решения должны жить.
- **Гейт качества:** каждое состояние доводится до «правильной точки», не бросается на полпути.
