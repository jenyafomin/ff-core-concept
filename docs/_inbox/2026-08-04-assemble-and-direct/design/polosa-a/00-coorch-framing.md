# Co-pilot framing pass — Полоса A

> Второй вектор ДО запуска волны исследователей (И1..И4). Не патчит план, не пишет код — переписывает
> ширину, ищет риски постановки, даёт харвест-критерии. Один read-pass, компрессия для лида.

## 1. Перепись ширины «чистого плана» (Полоса A = D0-self-honesty class)

Полоса A — не «весь census», а узкая под-категория: места, где **план лжёт о самом себе** (декларирует
механизм/имя/факт, который код или собственное правило плана не подтверждает). Это отличает её от
content-coverage дыр (CG-01..10, Ц1/Ц6/Q4-Q6 unclaimed — те про ЦЕННОСТИ без дома, другой вектор → Полоса B
/ owner-forks). Перепись именно этого узкого класса:

| грань (self-honesty) | закрыта чем | статус |
|---|---|---|
| DV имя = 2 разных предмета (process vs graph) | И1 (CG-11) | закрыта |
| D0 enforcement(a) описывает генератор, которого нет (`doc-tree.mjs` не пишет root пульт) | И2 (CG-12) | закрыта |
| R-b census-gate — сам гейт прозой, план запрещает прозу-гейты себе же (§43-45 KILL-SHOT 2) | И3 (CG-13) | закрыта |
| D1.b precond 3 (`same-as` guard) тавтологичен — «зелёный» ничего не доказывает про R1 | И4 (CG-14/T-sameas-guard) | закрыта |
| **5-я, не заявленная**: CG-08 — DV-долг (selection/relevance «в DV» устно) не назван явной строкой в DV-карточке; та же порода бага, что CG-11/13 (план ссылается на механизм, которого явно нет в тексте карточки-адресата) | — | **ДЫРА**, P2, дом уже указан (`D0/DV — назвать долг явной строкой`) |
| D0 enforcement(b) — «generator check flags stale active» — не проверено, существует ли уже, или это то же самое, что «DV-process» из CG-11 (потенциальное ТРЕТЬЕ смешение имён, не только DV-process/DV-graph) | частично внутри И1 (см. §2) | накрыть явно в брифе И1 |

**Итог:** 4 задачи закрывают заявленную ширину этого узкого класса **кроме CG-08** (P2, тот же паттерн
«план называет механизм, который не назван явной строкой в доме»). Не блокер для старта волны (P2, дом
уже есть), но не отложить молча — либо добавить 5-й лёгкий пункт в И1 (он всё равно трогает DV-текст),
либо явно занести в пул со статусом deferred-with-home (R-e). Рекомендация: слить в И1 (один файл-семья,
DV §4), не заводить И5.

## 2. Framing-риски (P1) — где бриф может увести исследователя в сторону

- **И1 (CG-11):** бриф просит «расщепить DV-process vs DV-graph», но в плане (§4 D0 enforcement-b) уже ЕСТЬ
  третий, никак не названный кандидат — «generator check that flags stale active card». Если инвестигатор
  расщепит только на 2 сущности, он рискует оставить D0(b) висеть неопознанным (дублирует DV-process? часть
  DV-process? отдельное?). **Переформулировать бриф:** «сначала выясни, D0-enforcement(b) — это то же самое,
  что DV-process, или третья вещь; расщепление должно объяснить ВСЕ три упоминания, не два».
- **И2 (CG-12):** риск «пере-судить решённое кодом» не грозит (грепом подтверждено: генератор пишет
  `docs/_generated/doc-tree.view.md`, не root пульт — это ФАКТ, не мнение). Реальный риск другой:
  инвестигатор может решить, что чинить надо КОД (расширить генератор) — это уже выход за «чистый план» в
  строй. **Бриф должен явно разрешить ТОЛЬКО 2 исхода:** (a) назвать owner+сайзинг для расширения генератора
  как отдельную будущую задачу (не делать сейчас) ИЛИ (b) переписать текст плана честно («пульт ещё не
  генерируется, статус: todo»). Не позволять третий исход «я быстро допишу генератор» — это уже код, не эта волна.
- **И3 (CG-13):** риск «сделать полноценный generator-check без решённой схемы D0-пульта» (см. §3 зависимость
  ниже) — исследователь может изобрести свой формат карточки, конфликтующий с тем, что решит И2. **Бриф:**
  «первый срез генератора может читать НАПРЯМУЮ `task-pool.md` + `02-coverage-gate.synthesis.md` (уже
  существуют, не ждут И2); не проектировать под ещё не решённый root-пульт из CG-12».
- **И4 (T-sameas-guard):** самый острый риск. `cardinalityOf('same-as', …)` **структурно всегда** возвращает
  `'many'` (predicates.ts:57, lock-ceiling) — значит `assertForwardMonotone` для same-as **не может** упасть
  никогда, при любом реплее, это не баг реплея, это архитектурный факт функции. Если бриф не укажет это явно,
  исследователь рискует «починить» задачу, написав ещё один unit-тест на ту же функцию (`assertForwardMonotone`
  / `cardinalityOf`) — получится вторая тавтология с виду другими словами. **Переформулировать бриф жёстко:**
  «новый ассёрт должен читать РЕАЛЬНЫЕ ДАННЫЕ ПОСЛЕ FOLD (число элементов в same-as-группе графа до/после
  реплея), а НЕ вызывать `cardinalityOf`/`assertForwardMonotone` повторно — эти функции по построению не
  умеют увидеть коллапс группы, они видят только реестр предикатов, не граф».

## 3. Зависимости / порядок

- **И1, И4 — независимы, можно веером.** Разные файл-семьи (DV-текст плана vs `predicates.ts`), не пересекаются.
- **И2 → И3 — мягкая цепь, не строгая.** И3 может стартовать параллельно (первый срез читает task-pool/
  coverage-gate напрямую, см. риск выше), но **харвест-точка обязана свести их** — если И2 решит «root-пульт
  генерируется по схеме X», И3-генератор должен либо уже был совместим, либо получить ре-ворк. Не сажать в
  одну волну как «полностью независимые», указать в брифе И3 явную зависимость-к-проверке.
- **Скрытая связь, которую надо назвать в обоих брифах:** CG-12 (нет root-пульта) и CG-13 (нет
  generator-check census) оба указывают на один и тот же инструмент-кандидат `tools/lint/doc-tree.mjs` как
  естественное место расширения — если оба И2 и И3 предложат СВОЙ отдельный новый генератор, дом задвоится
  (закон 2 doc-tree.md, «один дом»). Харвест должен явно решить: один расширяемый генератор или два разных.

## 4. Gate-критерии харвеста (объективно, per задача)

- **И1:** принять, если патч называет ВСЕ ТРИ кандидата (DV-process/DV-graph/D0-enforcement-b), даёт каждому
  имя+дом, без потери ни одного в тексте плана + coverage-gate строки Ц4/CG-11. Отклонить, если только
  переименовал 2 сущности и не тронул D0(b).
- **И2:** принять, если патч содержит ОДНО из двух: конкретный owner+сайзинг задачи на расширение генератора
  (не выполненную сейчас) ИЛИ честную правку текста плана (убрать present-tense ложь). Отклонить любой
  патч, где строка плана продолжает утверждать факт, не подтверждённый кодом.
- **И3:** принять, если есть работающий (или хотя бы запускаемый, пусть минимальный) generator-check скрипт
  ИЛИ конкретный стаб+owner+acceptance-критерий, который читает существующие файлы (task-pool/coverage-gate)
  и падает на пустой P0/P1-клетке без задачи+дома. Отклонить прозу «будем делать генератор» без стаба/owner.
- **И4:** принять ТОЛЬКО если новый ассёрт проверяет данные графа после реплея (счёт участников same-as-
  группы до/после), а не переиспользует `cardinalityOf`/`assertForwardMonotone`. Отклонить любой патч, где
  «зелёный» результат структурно недостижимо-неверный (та же тавтология другими словами) — это именно тот
  паттерн, который CG-14 и должен убить.
