## Ответ владельца (вербатим-по-смыслу, N-040…N-043)
- Точно нужно СКРЕЩИВАТЬ; смотреть даже ШИРЕ — rentacar будет лишь ПРИМЕРОМ имплементации.
- Нужно ЛИЧНО: контролировать ВСЕ свои проекты; подключать проекты РАЗНЫХ людей с РАЗНЫМ доступом;
  разные могут делать разное.
- Можно создавать целые ПРОСТРАНСТВА (напр. rentacar = отдельное пространство под ~8 проектов, у них
  свои правила, внутри свои проекты). Внутри пространства/группы могут САМИ строить доступы: кто что
  видит, кто что может, разные роли.
- Это может быть либо целая СИСТЕМА, либо просто ЧАСТЬ ДАННЫХ.
- **Вопрос — КУДА всё это направлять и двигать (open).**

## Что копать (наметка для команд)
- Пространство = целая система ↔ часть данных (две гипотезы).
- Модель ролей/доступа ВНУТРИ пространства: кто видит/может, роли; композиция с глобальным доступом.
- Вложение проектов в пространство (rentacar = 1 пространство × ~8 проектов).
- rentacar как ПРИМЕР, не как рамка — не сужать под один кейс (Ц5 plug-in/продаваемость).
