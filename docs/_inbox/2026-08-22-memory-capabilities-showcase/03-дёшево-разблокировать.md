# 03 · Ближайшие 2-3 возможности — дёшево, без нового движка

Все три — надстройки над УЖЕ существующими примитивами (`edge-index`, `DayGraphView`). Ни одна не
требует нового `ViewDef`, миграции данных или изменения замороженных типов.

## Шаг 1 — фильтр «статус × предикат» поверх `DayGraphView`
Сейчас: `dayGraphView()` отдаёт готовую структуру `nodes[].out[]` с `status` на каждом узле.
Не хватает: маленькой функции `nodesWithStatusAndPredicate(view, status, predicate)`, которая берёт
узлы нужного статуса и вытаскивает их исходящие рёбра нужного предиката (пункт «кто вовлечён в мои
активные нити» из `01`, п.2). Оценка: ~10-15 строк, чистая функция над уже возвращаемой структурой,
без движковых изменений. [Опора: `day-graph.ts:34-56,97-114`]

## Шаг 2 — агрегатор «входящие рёбра на узел» (грубый salience-по-степени)
Сейчас: `edge-index.ts` уже считает `storedEdgeCount` и умеет `inverseSources(target, predicate)` —
все сырые данные для подсчёта входящих связей на КАЖДЫЙ узел уже вычисляются при построении индекса,
просто не агрегированы в сортируемый список. Не хватает: обхода по всем узлам графа + всем предикатам,
суммирующего входящие рёбра на id, и сортировки по убыванию — «топ самых связанных узлов». Оценка:
~15-20 строк поверх готового `EdgeIndex`, без нового движка/поля в данных. Честно: это НЕ salience-модель
(нет весов/времени/decay) — только количество связей, суррогат «на что чаще всего влияет структура».
[Опора: `edge-index.ts:16-36`]

## Шаг 3 — обобщённый «общий предок по любому предикату» (генерализация multi-hop)
Сейчас: `cost-tree` умеет обход графа рекурсивно/итеративно с loop-guard и depth-bound — но захардкожен
на предикат `delegates-to`. [VERIFIED `view-compiler.ts:67-121`, фильтр на `:96`] Не хватает:
параметризовать этот же обход предикатом (не переписывать логику loop-guard/depth-bound с нуля,
только вынести `'delegates-to'` в аргумент функции), чтобы пункт 3 из `01` («через что связаны rentacar
и спорт») перестал быть одноразовым скриптом и стал переиспользуемым запросом для ЛЮБОЙ пары узлов и
ЛЮБОГО предиката. Это самый большой рычаг из трёх: разблокирует не один вопрос, а целый класс вопросов
«что с чем неочевидно связано». Оценка выше, чем шаги 1-2 (трогает `view-compiler.ts`, требует решить,
остаётся ли это `cost-tree` с параметром или новый `kind` — упирается в замороженный enum `ViewDef.kind`,
`types.ts:190-202` — вероятно ОТДЕЛЬНАЯ лёгкая линза по образцу `day-graph.ts`/`day-mirror.ts`, не правка
enum).

## Что НЕ входит в «дёшево» (сознательно исключено)
Salience/decay-движок (V4), consent-enforcement на рёбрах (V7), аутентификация писателя (M5) — все три
требуют новых решений/ADR, не 15-строчных надстроек. См. `04`.
