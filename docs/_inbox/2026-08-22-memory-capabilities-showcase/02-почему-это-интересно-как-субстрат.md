# 02 · Почему это интересно именно как субстрат, а не как «заметки»

Пункты ниже — не про граф дня-1 конкретно, а про то, ПОЧЕМУ форма (типизированный граф + один PEP + один
источник для многих линз) даёт агенту что-то, чего плоский текст/заметки не дают.

## 1. Агенту не нужно заново «вычитывать» связи из прозы
`rentacar` и `спорт` затронуты одним и тем же `эмоц-ресурс` — это не вывод из перечитывания 9 абзацев
текста, это ОДНО ребро на узле (`predicate: 'affects'`). Агент читает типизированный факт, а не
парсит естественный язык заново при каждом обращении. Дешёвая грань (Ц1): `label`/`summary`/`out[]` без
разворачивания всего тела узла. [VERIFIED `day-graph.ts:74-91`]

## 2. Система видит связи, которые человек не держит в фокусе одновременно
Владелец писал 9 независимых нитей в разное время дня. Мало кто, договаривая мысль про "спорт — надо
собраться", тут же вслух связывает это с тем же самым дефицитом сил, который блокирует rentacar и движ.
Граф делает скрытую общую причину ЯВНОЙ структурой (один узел, 4 исходящих ребра) — это ровно то, для
чего нужен субстрат: не хранить факты, а держать их СВЯЗАННЫМИ так, чтобы агент мог их сопоставить
без дополнительного «понимания смысла».

## 3. Одни и те же данные — много ракурсов без пересборки схемы
Три поверхности уже читают ОДИН и тот же источник записи по-разному, не требуя новой модели данных
каждый раз:
- `day-mirror` — по свежести записи (`recordedAt`), лента журнала. [VERIFIED `day-mirror.ts:50-76`]
- `day-graph` — по структуре графа (узлы + типизированные рёбра). [VERIFIED `day-graph.ts:97-114`]
- `visible-to` — по праву чтения конкретного вьюера через ЕДИНЫЙ `resolve()`. [VERIFIED
  `view-compiler.ts:141-143`]

Новая линза = новый способ ПОСМОТРЕТЬ, а не новая схема хранения (CQRS: журнал пишется один раз,
проекции/линзы читают его по-разному). Для агентской платформы это значит: добавление нового «взгляда»
(агента-потребителя) не требует миграции данных.

## 4. У каждой связи есть источник, не голое утверждение
Каждое ребро дня несёт `provenance` — какой источник его заявил (`day-graph:2026-08-21`), не только
`predicate`+`target`. [VERIFIED `day-graph-seed.mjs:71-75`, форма `types.ts:26-51`] Это основа доверия
(Ц3/V3): агент может (в перспективе) спросить «откуда система взяла, что rentacar зависит от моего
эмоционального ресурса» и получить трассируемый ответ, а не непроверяемое утверждение.

## 5. Словарь связей растёт, не ломая старое
`affects/organizes/involves` — не встроенные в движок понятия, а ОТКРЫТЫЙ реестр предикатов,
инжектируемый арендатором на границе (движок несёт НОЛЬ доменных существительных — G1).
[VERIFIED `predicates.ts:19-33`] Новый тип связи (например, из другого проекта) добавляется КАК ДАННЫЕ,
без правки кода движка — а `assertForwardMonotone` не даёт по ошибке «сузить» кардинальность и тихо
потерять историю при пересборке. [VERIFIED `predicates.ts:90-103`] Это то, что делает субстрат
модульным/plug-in-совместимым по духу проекта (V5 суверенность): чужой тенант растит свой словарь рядом,
не трогая чужой.

## Итог одной строкой
Ценность не в том, что граф «хранит день» — блокнот тоже хранит день. Ценность в том, что агент читает
СВЯЗИ как структуру (дёшево, без переразбора текста), видит то, что человек не держит одновременно в
голове, и делает это через ОДИН источник правды, отдаваемый разными линзами без пересборки схемы.
