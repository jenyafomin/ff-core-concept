# 04 · Возможности: линзы (views) и страж (PEP)

«Возможность» базы = какой **взгляд** она может отдать и какое **решение о доступе** принять.

## Линзы (views) — готовые взгляды на граф
Движок компилирует декларативный `ViewDef` в исполняемую функцию `(graph, ctx) => Result`.
Единый 4-стадийный конвейер: `from · traverse · filter · shape`. [VERIFIED `view-compiler.ts:194-232`]

Три встроенных вида (enum заморожен):
- **`cost-tree`** — дерево стоимости по `delegates-to`, с прокруткой subtree/direct, защитой от циклов
  и обрезкой веток, которые читатель не видит. [VERIFIED `view-compiler.ts:24-121`]
- **`visible-to`** — «что этому читателю видно» (каждый узел через `resolve('read')`). [VERIFIED `:139-143,214-227`]
- **`actions-by-agent`** — действия, сгруппированные по агенту. [VERIFIED `:145-164`]

**Ключевое:** любая линза чтения ходит через ОДИН `resolve()` — второго, «всё-разрешающего» пути нет (I-7).
[VERIFIED `view-compiler.ts:9-13`]

### Линза «Зеркало дня» — честный пример, НЕ ViewDef
«Зеркало дня» — это лёгкая линза поверх `store.acts()`, а НЕ четвёртый вид `ViewDef`. Почему: узлы дня
пишутся как `observation`, а наблюдения — **боковой журнал**, они НЕ становятся узлами графа. Изобретать
четвёртый `ViewDef` = править замороженный enum, поэтому линза читает журнал напрямую.
[VERIFIED `surface/day-mirror.ts:1-14,50-96`]
Ранжирование — по `recordedAt` (прокси свежести). **Движка salience/затухания НЕТ.** [VISION — `day-mirror.ts:11-13,35-36`]

## Страж (PEP) `resolve()` — какие решения умеет
- Один механизм на read и write; `key` = `"read" | "write" | "write:<field>"`. [VERIFIED `resolve.ts:116-122`]
- **Способности (гранты) — данные.** Право проверяется по грантам в графе; комбинатор/порядок берутся
  из `policy:access-priority` (данные, не хардкод-ветка). [VERIFIED `resolve.ts:150-176`]
- **Гранты провенанс-связаны:** самочеканенный грант (`minted_by:'system'`) не покупает власть — движок
  **force-bind'ит** `minted_by` на реального писателя. [VERIFIED `engine.ts:106-108`; `resolve.ts:136-148`]
- **Мета-способности** контроль-плоскости: `core:manage-access / manage-grants / manage-core`. [VERIFIED `resolve.ts:66-101`]
- **Клапан согласия (valve)** для необратимых действий сверяет реальный флаг способности, не строку.
  [VERIFIED `resolve.ts:272-279`]

## Что из «возможностей» — форма без поведения (за швом)
- **Согласие (V7)** на рёбрах: `ConsentAssurance` — можно ЗАПИСАТЬ статус, но никто его не ЧИТАЕТ для
  решения о доступе. [VISION — `types.ts:73-97`; трипвайр-тест `test/consent-not-enforced.test.ts`]
- **Принципал-шов (аутентификация писателя, M5):** `PrincipalResolver` — только сигнатура, нет реализации,
  ничто не вызывает. [VISION — `ports/principal-resolver.ts:1-21,58-64`]
- **Время-на-ребре** (`validFrom/validTo`) — форма есть, проекция не читает. [VISION — `types.ts:38-41`]
- **Стирание by-ref PII** — split/redact функции есть, но shred реального blob — открытая развилка.
  [VISION — `core/erasure.ts:16-24` (T-D1b-shred-by-ref-pii)]
