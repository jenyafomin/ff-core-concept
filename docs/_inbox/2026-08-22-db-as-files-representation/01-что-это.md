# 01 · Что это за «база»

## Одной фразой
Наша «база данных» — это **движок памяти** `packages/engine` (пакет `@ff/engine`). Это НЕ таблицы SQL
и НЕ хранилище заметок. Это **журнал событий + граф-проекция + один страж доступа + линзы-виды** поверх них.

## Как она устроена (4 части)

1. **Журнал актов (write-model, система-записи).** Всё, что происходит, ложится строкой в
   **append-only** журнал: акт (`Act`). Журнал только дописывается, никогда не переписывается.
   [VERIFIED `packages/engine/src/ports/store-port.ts:16-27` — порт `writeAct`/`acts()`; append-only]

2. **Граф-проекция (read-model).** Из журнала **детерминированно** пересобирается граф узлов
   (`EnvelopeNode`). Граф — это НЕ отдельное хранилище, а «сжатый текущий срез» журнала.
   [VERIFIED `packages/engine/src/core/projection.ts:1-16,130-137` — `graph = reduce(acts)`, CQRS]

3. **Страж (PEP) `resolve()`.** ОДИН механизм решает «можно читать / можно писать» для читателя.
   [VERIFIED `packages/engine/src/core/resolve.ts:116-122` — единая точка входа read+write]

4. **Линзы (views).** Готовые «взгляды» на граф: дерево стоимости, «что мне видно», действия агента;
   плюс лёгкая линза «Зеркало дня» поверх журнала.
   [VERIFIED `packages/engine/src/core/view-compiler.ts:195-232`; `src/surface/day-mirror.ts:50-96`]

## Ключевой принцип (рефрейм msg 141)
База — это **рабочий субстрат для ИИ-агентов**, а не папка файлов. Агент читает граф через линзу,
делает работу и пишет обратно **актом** — который проходит через стража прежде чем попасть в журнал.

## Что реально работает СЕГОДНЯ (одной строкой каждое)
- Запись акта проходит **проверку ДО журнала** (fail-closed). [VERIFIED `engine.ts:73-155`]
- Только `domain_event` становится узлом графа; наблюдения/трейсы едут «сбоку». [VERIFIED `projection.ts:42-44`]
- Память **переживает перезапуск процесса** (журнал на диске, JSONL). [VERIFIED `adapters/store-durable-fs.ts:1-24`]
- Тесты как источник истины: ~143 it/test-блока зелёные. [VERIFIED `packages/engine/test/*.test.ts`]
