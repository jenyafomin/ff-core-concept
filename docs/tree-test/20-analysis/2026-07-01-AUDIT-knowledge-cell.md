# АУДИТ — ячейка знаний / граф узлов FF (критический)

> Тон честный: слабое названо слабым. Все находки — с путями. Ничего в существующих файлах не правилось.

## 1. Как устроена ячейка сейчас

Два слоя, которые важно не путать:
- **Слой ПРОДУКТА (спроектирован, не построен):** узел = «тонкий паспорт» (9 обяз. полей: id·type·schema·created·
  updated·epistemic·sensitivity·source·principal), связи на рёбрах (`home` ровно один, priority/cascade на ребре),
  control-plane = узлы (ТИП·ЛИНЗА·ПАТТЕРН). Канон: `docs/architecture/ADR/ADR-0002-thin-passport.md` (approved).
  Живой пример: `docs/graph-example/` (5 ячеек md+frontmatter).
- **Слой САМОЙ базы знаний проекта (работает сегодня):** 4-уровневая память —
  `docs/STATE.md` (точка входа) → `docs/DECISIONS-LOG.md` (выжимка) →
  `docs/dialogue/THREAD-2026-06-15-foundation.md` (граф диалога, N-001…N-097, типы+связи в тексте) →
  `docs/product/SYNTHESIS-*` + `docs/council/raw/*` (пирамида «синтез над сырьём»).
  Поверх — начатая 2026-06-24 миграция в нумерованное дерево `00-canon…99-qa` (`docs/TREE.md`,
  `docs/00-canon/DOC-CONVENTION.md`): создан только скелет README, файлы не перенесены.
Итого: 143 md-файла, ~2.4 МБ. Продуктовая модель ячейки — сильная; **собственная БЗ проекта эту модель не исполняет.**

## 2. Найденные ошибки и слабости (по убыванию тяжести)

### 2.1 Полу-мигрированное дерево = две параллельные структуры (КРИТИЧНО)
- 10 нумерованных папок (`docs/00-canon/`…`docs/99-qa/`) содержат ТОЛЬКО README. Все ~100 реальных файлов — в старых
  папках. Навигационная таблица `docs/TREE.md` («Resume after compact → `00-canon/01-STATE.md`») ведёт в
  несуществующие файлы. README новых папок написаны так, будто миграция завершена
  (`docs/40-dialogue/README.md`: «DECISIONS-LOG (in 00-canon)» — а он лежит в `docs/DECISIONS-LOG.md`).
- Миграция стоит с 06-24 (неделя). Чем дольше — тем больше новых файлов кладётся по старым путям и тем дороже перенос.

### 2.2 Миграционные артефакты противоречат ДРУГ ДРУГУ
- `docs/council/raw/2026-06-24-doc-tree/migration-plan.md` §2: **11 групп, есть `50-council`**, COUNCIL-* → 50-council.
- `docs/TREE.md` + фактический скелет: **10 групп, `50-council` нет**, COUNCIL-* → `10-synthesis/`.
- `docs/DECISIONS-LOG.md` (N-097): «скелет 11 групп». Счёт файлов тоже плывёт: 103 (migration-plan) vs ~132 (N-097)
  vs 143 фактически. Три документа одной сессии — три разных истины. Никто не заметил, потому что нет проверки целостности.

### 2.3 STATE.md нарушает собственное назначение (append-only вместо снапшота)
- Заявлено «свернуть контекст без потерь», по факту — журнал: 321 строка / ~15k токенов, ~20 хронологических секций,
  каждый раунд ДОПИСЫВАЕТСЯ, старое не сворачивается. Секция «✅ РЕШЕНО 2026-06-15 → ADR-0001» описывает схему,
  которую ADR-0002 уже superseded, — читатель обязан сам вычислять, что из прочитанного ещё правда.
- «Карта ключевых документов» в конце `docs/STATE.md` заморожена на ~06-14: в ней НЕТ ADR-0002 (единственный
  approved канон!), нет TREE.md, DECISIONS-LOG, graph-example. Файл «читать первым» заканчивается устаревшей картой.
- Рост линейный и неограниченный: при текущем темпе к августу вход подорожает вдвое.

### 2.4 THREAD — 42k-токенный монолит, антипод собственной модели ячейки
- `docs/dialogue/THREAD-2026-06-15-foundation.md`: 935 строк, ~42k токенов, 97 узлов в одном файле — не читается
  целиком за один Read. Проект проповедует «минимум информации в ячейке» и «дефектовку файла на мелкие узлы» (N-038),
  а его центральный граф — самый большой нерасщеплённый файл репозитория. Q11 (N-089) решился игрушечным
  `graph-example/` вместо промоушна реальных THREAD-узлов — dogfood-тест модели фактически отложен.

### 2.5 Граф диалога: конвенция связей и типов не соблюдается и не проверяема
- `CLAUDE.md` объявляет 5 rel (`refines/answers/raises/tension-with/grounds`) и 7 типов узлов. Фактически в THREAD
  ~25+ ad-hoc rel (opens, drives, relates, realizes, fulfills, proves, gates, defers, consolidates, method,
  answers-pending, supersedes-framing…) и лишние типы (`artifact`, `feedback`, N-029 имеет «тип» `resolved` —
  смешение типа со статусом). Есть висячие цели: N-002 `tension-with→N-00x`; многие links ведут в прозу, не в id.
- Продукт требует «типизированный реестр rel + связи по id»; собственный граф нарушает оба правила. Бэклинков нет,
  машинно граф никто не парсит — конвенция держится только на дисциплине одного Claude и уже поплыла.

### 2.6 Мёртвые ссылки и расхождение канона с примером
- `docs/architecture/ADR/ADR-0002-thin-passport.md` (строки 358, 467) и `docs/product/VERDICT-2026-06-21-ratify.md`
  дважды требуют `docs/qa/VALIDATION-0002-50cells.md` — файл никогда не создан; реально существует
  `VALIDATION-0002-10cells.md` (владелец сменил 50→10, N-053). Мёртвая ссылка внутри APPROVED-канона.
- `docs/graph-example/` заявляет «паспорт ADR-0002», но использует `external_ref` (в STATE §msg231 всё ещё открытый
  вопрос владельцу «добавить в паспорт?») и `seq` на ребре (кандидат, не ратифицирован). Пример впереди канона.
  Плюс 6 нематериализованных целей рёбер (project-ff, folder-core-src, category-*, plan-passport-v2, lineage-node-ts) —
  целостность даже 5-ячеечного примера непроверяема.

### 2.7 Конвенции противоречат сами себе / не исполняются
- **Где живёт superseded-канон:** `docs/00-canon/DOC-CONVENTION.md` («файл "ушёл" только когда живёт в 90-historical»)
  vs `docs/00-canon/README.md` («Superseded docs stay HERE»). Прямой конфликт.
- **Статусы:** «Do NOT skip frontmatter Status» — а Status нет у `docs/STATE.md`, `docs/DECISIONS-LOG.md`,
  `docs/HANDOFF-2026-06-16.md`, всех `docs/ideas/*` и `docs/graph-example/*`. ADR-0001 использует внесловарный
  статус `superseded (partial)`.
- **99-qa нумерация сломана по построению:** `docs/99-qa/README.md` — «VALIDATION-NNNN linked by number to the
  corresponding SPEC», но SPEC по Rule D номеров НЕ имеют; фактический VALIDATION-0002 ссылается на ADR-0002.
- **CLAUDE.md vs реальность:** «проблемы → в `docs/research/`» — там 1 файл от 06-14, мёртвая зона; «синтез →
  `docs/product/CONCEPT-*.md`» — реально решения уходят в SYNTHESIS-*. Воронка L0-L5 в поздних узлах — декоративные метки.
- Именование до миграции: `VERDICT2-2026-06-15-advanced.md` (хак «2»), `stress-test-2026-06-15-detailed.md` (lowercase).

### 2.8 Четырёхкратная запись одного и того же
Каждый раунд фиксируется в THREAD-узле + секции STATE + строке DECISIONS-LOG + SYNTHESIS. Write-amplification ×4
для ведущего агента и гарантированный дрейф (см. 2.2, 2.3). Правила «кто прав при расхождении этих 4 слоёв» нет.

### 2.9 Код и спека отстают от канона (известно, но не помечено)
`packages/core` + `docs/spec/SPEC-core-kernel.md` реализуют superseded ADR-0001 (9 хардкод-kinds). В самом
SPEC нет пометки «описывает v1, не соответствует ADR-0002» — читатель узнаёт это только из STATE.

## 3. Эффективность для агента

- **Цена входа после компакта** по заявленному порядку: CLAUDE.md (~2.5k) + STATE (~14.6k) + TREE (~3.8k) +
  DECISIONS-LOG (~4.6k) + SWEEP (~2.6k) + 4 свежих синтеза (~10k) ≈ **35-40k токенов до первого полезного действия**;
  с хвостом THREAD — 50-60k. Это ~20-30% контекстного окна на «вспомнить, где мы».
- **Скоупинга нет вообще.** Один глобальный вход для любой задачи: вопрос про вьюер заставляет читать историю движка,
  памяти и схемы. Нет тематических точек входа, нет роутеров по папкам.
- **Актуальная схема ячейки не читается дёшево:** единственный источник — ADR-0002 на ~21k токенов, где нормативная
  часть перемешана с историей дебатов и бухгалтерией ред-тима. Нет 1-страничной «карточки текущего паспорта».
- Ирония: `docs/ideas/IDEA-agent-context-budget.md` существует, но к собственной БЗ бюджет не применён.

## 4. Эффективность для человека

- Навигация: TREE.md ведёт в пустые папки; реальная навигация требует ПОМНИТЬ историю. «Дерева знаний» как
  представления нет — есть хронологическая лента.
- Свежего «что мы решили — просто» нет: `docs/product/SYSTEM-IN-PLAIN-WORDS.md` датирован **2026-06-13** — до
  паспорта, линз, клапана, движка. Владелец, который учится «по одной теме простыми сообщениями» (N-083),
  не имеет ни одного актуального простого документа.
- **Очередь решений владельца — главный bottleneck проекта — размазана по ≥6 местам:** 🟡-блоки в 5 секциях STATE,
  §🟡 SWEEP, вопросы в синтезах, A1-A6 в TREE.md, CRITICAL в DECISIONS-LOG. Накопилось ~15 открытых развилок,
  единого реестра нет. Это самый дорогой для человека дефект.
- Телеграфный стиль STATE (сокращения, вложенные скобки) оптимизирован под Claude; человеку через 2 недели — почти нечитаем.

## 6. Целевая модель (эскиз)

Три температурных слоя + скоуп по темам. Принцип: **БЗ проекта живёт по тем же правилам, что продуктовая ячейка.**

```
docs/
  00-canon/                    ГОРЯЧЕЕ (суммарно ≤10k токенов, вход после компакта)
    01-STATE.md                снапшот ≤150 строк, ПЕРЕПИСЫВАЕТСЯ; прежние версии → 90-historical
    02-OPEN-DECISIONS.md       ЕДИНЫЙ реестр развилок владельца (id, дата, статус, ссылка)
    03-MODEL-CARD.md           1 страница: текущий паспорт+ребро+инварианты (норматив, выжимка из ADR)
    ADR/  SPEC/                полные тексты (читаются по потребности, не при входе)
  1x-topics/<тема>/            ТЁПЛОЕ: schema/ engine/ viewer/ memory/ valve/ …
    &README.md                 роутер: статус темы, последний синтез, open-вопросы
    YYYY-MM-DD-SYNTHESIS-*.md  синтезы ЭТОЙ темы (не плоская куча в product/)
  40-dialogue/                 ХОЛОДНОЕ: THREAD расщеплён на файлы-раунды ≤100 строк
    &INDEX.md                  реестр узлов: N-id → файл → тип → статус (машиночитаемый)
  60-raw/ 90-historical/       архив, доступ только grep/FTS
```

- **Рост:** новое знание падает в свою тему мелким файлом; STATE только УКАЗЫВАЕТ. Новая тема = новая папка с роутером
  (правило «3+ файла» из DOC-CONVENTION уже это разрешает).
- **Скоуп под задачу:** вход агента = 01-STATE + 03-MODEL-CARD + `&README` своей темы (≈6-8k токенов вместо 40k).
- **Dogfood:** узлы THREAD получают frontmatter-паспорт по ADR-0002 (id, type, epistemic, links по id) — граф диалога
  становится первым РЕАЛЬНЫМ наполнителем продукта (закрывает Q11 по-настоящему) и валидируется скриптом
  (висячие ссылки, словарь rel, единственность home).
- **Гигиена:** санитарный проход раз в N сессий (битые ссылки, статусы, лимиты размеров) — по nudge-паттерну Hermes.
