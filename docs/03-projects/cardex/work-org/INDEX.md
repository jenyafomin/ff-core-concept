# Cardex — организация моей работы (operating model)

Отдельный трек: не «что за продукт», а **как я работаю** над ним. Роль — **главный программист**: реализую идеи экосистемы (см. `../graph.md`) быстро, точно, качественно; креатив — дополнение.

## Центральная развилка моей работы

**Telegram (поток) vs дерево/продукт (истина).**
Взаимодействий много в Telegram, но истина по задачам и идеям должна **ссаживаться в артефакты** (дерево FF / внутрь продукта), иначе теряется. Мост **capture → дерево** — ядро организации. (Это ровно правило «артефакты важнее чата».)

## 4 интерфейса — с кем и что течёт

| С кем | Что течёт | Канал | Ритм | Артефакт-истина |
|---|---|---|---|---|
| **PM / начальник** | большие идеи; отчёт по задачам и планам | созвон | **Пн + Чт** | план + статус (`docs/plan/`) |
| **DevOps** (помощник) | перенос инфры на новые серверы; безопасность; CI/CD | Telegram / созвон | по мере, но плотно | infra-чеклист + handoff |
| **Команда-пользователи** | их потребности; идеи/вопросы/предложения по продукту | Telegram + внутри продукта | постоянно | capture → узлы дерева |
| **Я сам** | ставлю и закрываю задачи между созвонами | — | ежедневно | личный борд задач |

## Ритм (сердцебиение недели)

- **Пн и Чт — созвоны:** сверка с PM, план на отрезок, запрос «моментов», отчёт по прошлому.
- **Между ними:** сам ставлю и закрываю задачи; коплю, что вынести на следующий созвон.
- Правило: каждая задача до старта получает **ожидаемый результат + как проверить** — тогда результат контролируемый.

## Захват идей (capture) — открытый под-проект

- Идея / вопрос / предложение по продукту → фиксируется (в Telegram или **внутри приложения**) → **ссаживается в дерево** в нужный узел (граф экосистемы / `questions/` / `decisions/`).
- Развилка: где живёт capture — **фича in-app feedback** внутри продукта, и/или **Telegram-бот** → дерево FF. Возможен гибрид.
- Это одновременно и мой процесс, и потенциальная фича продукта (узел «in-app capture» в графе экосистемы).
