# Capture + визуализация поверх Telegram (механизм)

Конкретизация выбранного направления: **Telegram-first на том, что уже есть** — движок кнопок, топики, редактирование сообщений. Визуализация — не покупной Confluence, а своё лёгкое, показываемое через Telegram.

## Большая находка: 3 куска уже у нас

- **Сбор / интеракция** — движок кнопок `telegtam-nestjs` (динамический JSON → кнопки + callback). Есть скилл `telegram-buttons`. Референс в реестре: `cardex → scaner/src/infrastructure/tamplate/register-button-template.service.ts` + `@grammy-nestjs`. → **reuse**
- **Визуализация в Telegram** — шлюз Движ **уже рендерит навигаторы дерева карточками** (concept live-card / wizard, `steps[]`/`paths[]`; `concept-graph.util.ts`). Это и есть «Confluence в Telegram». → **reuse**
- **Истина** — дерево FF (`concept.json` + `.md`). → **есть**

**Вывод:** свой «быстрый Confluence» = сшить эти три, а не строить новое.

## Сбор от пользователей — что и как (крух вопроса)

**Что собираем** (минимум полей): тип (идея / вопрос / баг / предложение) · текст · к чему относится (узел/роль/продукт) · автор · срочность.

**Режим — два уровня:**
- **Лёгкий:** пишут в нужный топик → бот-capture присваивает ID, ссаживает в узел дерева, **редактирует своё сообщение** в подтверждение («принял #C-42 → узел C1»).
- **Структурный:** мини-мастер на кнопках (тип → к чему → текст), правка сообщения на месте — одно сообщение меняется, без спама.

## UX, чтобы НЕ было неприятно

2–3 тапа максимум · кнопки вместо свободного ввода где можно · **edit-in-place** (одно сообщение-морф, не лента) · мгновенное подтверждение с ID и ссылкой на узел.

## Визуализация (наш «Confluence»)

Дерево рендерится **обратно в Telegram** карточкой-навигатором (переиспользуем wizard шлюза): команда листает идеи/статусы прямо в чате. Позже — веб-дашборд (doc-tree viewer FF) для богатого вида.

## Telegram как витрина знаний

Топики = потоки: **обзоры · документация · инструкции**. Закреплённые карточки рендерятся из дерева → доки живут в дереве, показываются в топиках (не дублируются руками).

## Агенты подкрепляют (задачи простые)

- **Триаж capture:** классифицировать → в узел → ответить ID (закрывает петлю «услышал»).
- **Дайджест:** недельный обзор по топику → карточка-сводка.

## Фокус (рекомендация)

- **Фаза 1:** capture поверх Telegram (движок кнопок) + автоссадка в дерево + подтверждение ID.
- **Фаза 2:** рендер дерева обратно карточками (wizard шлюза).
- Confluence не строим; кастом только там, где reuse не тянет.

## Развилки владельцу

1. Режим сбора: **лёгкий** (текст+триаж) или **структурный** (мастер на кнопках)? Или оба, начиная с лёгкого?
2. Что собираем первым — **идеи/предложения** или **вопросы/баги**?
3. Делаем **разведку в коде** (подтвердить reuse: движок кнопок + wizard шлюза), прежде чем обещать сроки?
