# Что сделано в Excel-инструменте — по факту

> Черновик для отправки (PM / DevOps). Тон: по-доброму, простыми словами; технические детали — в конце.
> Все пункты подтверждены кодом репозитория Forms-Sidebar.

## Коротко

За ~1.5–2 месяца сделан **рабочий инструмент для менеджеров прямо внутри Google-таблицы**: удобная
форма, где заводят и ведут сделки обменника. Он **уже развёрнут, менеджеры работают на нём ежедневно**,
Павел подключил к нему всех пользователей. Это не прототип — это живой рабочий инструмент.

## Что именно уже работает

**Ввод и ведение сделок**
- Форма создания сделки в 4 вкладки (сделка · деньги · экономика · переводы); одно сохранение
  аккуратно раскладывает данные сразу по нужным листам таблицы.
- Просмотр и **редактирование** уже созданных сделок (не только ввод).
- Комментарий к сделке.

**Деньги, курсы, экономика**
- Работа с деньгами: приход/расход, переводы, возвраты, способы выдачи.
- Курсы валют (единая логика «сколько USDT за единицу»), кросс-курсы, курс дня.
- Экономика сделки: маржа/прибыль, себестоимость (по фиксам или вручную), связка «процент ↔ сумма».
- «Фиксы» (расходы) и их автоматическая синхронизация с деньгами; математика формул по листам.

**Список сделок и удобство**
- Фильтры: по статусу, по датам (диапазон), по периоду; сортировка; поиск по клиенту/номеру.
- Прибыль за выбранный период — считается сразу по активным фильтрам.
- Скорость восприятия: кэширование, «ленивая» подгрузка сделки по клику, индикаторы загрузки,
  автоматическая синхронизация списка.

**Надёжность (это про реальные деньги — отнеслись серьёзно)**
- Формулы живут прямо в ячейках таблицы, привязаны по названию колонки (не по буквам) — устойчиво к сдвигам.
- Атомарная запись с откатом: если запись прервалась — прежнее состояние восстанавливается, не остаётся
  «половины сделки».
- Защита денег «на веру»: суммы показываются пользователю только после сверки с таблицей, не заранее.
- Безопасная сборка/деплой: страж не даёт залить «сырой» бандл, который сломал бы таблицу.

**Со стороны Павла**
- Подключил все скрипты ко всем пользователям, менеджеры перенесли туда сделки.
- Сейчас **пишет подробное ТЗ** (~140 вопросов, с помощью ИИ; коммит на этой неделе) — поэтому доработку
  «бот→Excel» ведёт/подхватывает владелец, чтобы не размывать фокус Павла.

## Честно о статусе

- **Что в проде:** форма, ведение сделок, деньги/экономика/курсы, список с фильтрами — менеджеры этим
  пользуются каждый день.
- **Что готово, но ещё не включено:** часть улучшений (например ускорение сохранения «на месте» вместо
  «стереть-и-переписать») уже написана и покрыта тестами, но пока не подключена в живую таблицу — ждёт
  одного передеплоя и живой проверки. То есть **сделано больше, чем видно в таблице**: «готово по коду»
  ещё не равно «включено в проде».

## Про перенос на новую инфраструктуру (главное для DevOps/PM)

- **Почему делали на Excel, а не сразу на новой инфре — это осознанное решение, не отклонение.** Павлу и
  менеджерам работа была нужна **корректной уже сейчас**, поэтому мы сознательно пошли быстрым путём на
  текущей таблице, чтобы бизнес не стоял (strangler-миграция: работающее не глушим, новое наращиваем рядом).
- **На новой инфре параллельно (исправлено — НЕ «миграция Bitrix»):** перенесён **бот сделок** (готов для
  всей команды); **отключение Bitrix** + **подключение базы клиентов**; закрыта часть уязвимостей, по
  остальным работа идёт.
- **Последняя доработка Excel (ключевая ближайшая задача):** сделки из **бота сделок** → сразу в Excel-таблицы
  (единый поток данных, синхронность, чтобы Павел вёл все просчёты). Детали интеграции — уточнить.
- **Хорошая новость по переносу:** фронтенд (сам интерфейс формы) перенести будет **заметно легче** —
  много готовых наработок: React-компоненты, чистая бизнес-логика вынесена в отдельные модули с тестами,
  UX-решения уже продуманы.
- **Честная оговорка:** это будет **не один-в-один**. Сейчас «движок» — это Google Apps Script + таблицы;
  под новую архитектуру часть вещей придётся **переделать** (серверную часть, хранение, интеграции). Но
  это переделка на прочном фундаменте, а не с нуля.

### Технический хвост (для DevOps)

- Стек Excel-инструмента: React (Parcel, инлайн-бандл) + Google Apps Script (HtmlService) + Google Sheets.
- Общий код клиента и сервера — в `shared/*.js` (единый источник истины полей/валидации/математики).
- Деплой строго prod-бандлом (`npm run push`), страж бандла `verify-bundle`.
- Логика вынесена из UI в чистые модули (`shared/`, `dealSort`, `dealFilter`-паттерн) — переносима и покрыта тестами.
- Известный технический долг: часть улучшений производительности написана, но не подключена (in-place
  запись вместо delete+reinsert); закомментированы служебные меню-инструменты; есть незакоммиченные правки.
