## 2. Канон ценностей v3 — 6 ценностей + метрика(и) на каждую

| # | Ценность | Native/Brain | Метрика(и) операционные | Заземлённость |
|---|---|---|---|---|
| 1 | **Финансовая целостность / правдивый учёт** | native | (a) 0 тихо-неверных сумм класса `orderIdForPlate` в проде за период · (b) доля заказов с полностью сведённым балансом (Remaining+Unpaid+Fines) без ручной правки > N дней | сильная — метрика уже есть как баг-класс |
| 2 | **Целостность актива (парк)** | native | (a) % машин с валидным, не просроченным occupancy-статусом (Booked/Available) на любой момент времени · (b) % автопарка с актуальным (не устаревшим > N дней) состоянием одометра/ТО | сильная |
| 3 | **Своевременность / готовность** (развилка b: оставлена отдельной) | native | (a) % дедлайнов (License Exp / Insurance Exp) с алертом, выставленным ≥ N дней до даты · (b) дни просрочки Expected Return до эскалации (цель → 0 непомеченных просрочек > X дней) | средняя — метрика есть, МЕХАНИЗМ (алерты) не построен, см. §3 |
| 4 | **Контроль риска контрагента / сведённый контрагент** | native + brain (Тождество/Реляционность) | (a) 0 ложных автослияний identity (`same-as` false-merge rate) · (b) доля заказов с полным KYC/риск-профилем клиента ДО подтверждения сделки | сильная |
| 5 | **Оперативная правда (anti-corrosion / стойкая память)** | brain (Доверие/Витальность/Согласие) | (a) 0 дублей после двойного прогона синка · (b) доля фактов из источника (чат/Sheets), переживших синк без потери (retention rate) | сильная |
| 6 | **Юр-щит / комплаенс-защита компании** ⚠ тонкий (развилка d) | native | (a) 100% PII-полей помечены классом чувствительности ДО экспорта · (b) 0 экспортов в обход гейта (по audit-логу) | слабая — метрика заявлена, юр.основание не валидировано на сценарии |

**Убрано из ценностей → constraint (развилка c):** «Усиление без замены CRM» — переносится как ограничение
доставки в `docs/product/CONSTRAINTS.md` (формулировка: «слой поверх Sheets/CRM не должен требовать
миграции существующего процесса компании; апгрейд возможностей — без замены источника»). Не ценность —
не проходит тест гардрейла (нет собственной операционной метрики компании).

**Tier2-плейсхолдер (развилка e, не измеряется сейчас):** «Возврат капитала инвестора / P&L-видимость» —
родитель #2 (владение парком), без метрики, вне MVP. Не забыть при следующем расширении контура.

## 3. Разрыв «Своевременность/Оперправда» — операционный механизм (вход архитектору, T5)

Ни F-3/F-4/F-5 (движок) не закрывают ценность #3 операционно — все три про дедуп/дом/потолок, ни один
не эмитит алерт по дедлайну. Формулировка механизма для архитектора:

- **Триггер:** поле с датой-порогом (License Exp, Insurance Exp, Expected Return, Follow-up) + окно
  предупреждения N дней (конфигурируемо per-поле).
- **Действие:** плановый скан (не событийный — даты не меняются per-write) эмитит узел-алерт при
  пересечении окна; алерт идемпотентен (не дублируется при повторном скане — ключ на `entity_id + поле +
  дата_порога`, согласуется с R7 seq/idempotency-хэшем из P1 spine).
- **Эскалация:** алерт без реакции > X дней поднимает severity (мягкая → жёсткая), не тихо гаснет.
- **Выход:** алерт — узел графа (не побочный e-mail/лог) → виден агенту и человеку, трассируем к
  ценности #3 метрике (a)/(b) выше.

Это НЕ спецификация — вход для system-architect (T5 из HANDOFF), после ратификации канона.
