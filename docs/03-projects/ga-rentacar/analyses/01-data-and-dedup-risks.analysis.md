# Анализ: слепые зоны первого среза (проход Fable)

## Грязь данных и дедуп
- **Клиента нет как строки** — размазан по N заказам → синк создаст N узлов-клиентов до дедупа; дедуп в критическом пути.
- **Телефон = идентификатор SIM, не человека** (турист/водитель) → `same-as` по телефону слепит разных; телефон = только кандидат.
- **Имена в транслите нестабильны** (Mohammed/Mohamed/Muhammad) → автослияние по имени НЕ делать, только ручное review.
- **`same-as` не транзитивен наивно** → модель кластера с уверенностью на ребре, иначе один ложный мега-кластер.
- **`Recent Note` — свалка НЛ-фактов** → заносим сырым узлом, извлечение = отдельная неделя (LLM-инжест).
- **Денежные поля грязные** (пусто/«cash»/валюты/депозит) → агенту деньги не считать на MVP.

## Изменение/удаление строк (дыры «идемпотентного upsert»)
- **Нет стабильного row-id в Sheets** (сортировка ломает позицию) → `source_ref` строить из содержимого (order number/составной), проверить уникальность.
- **Удалённая строка = молчаливое исчезновение** → **tombstone**: пропавшие метим `archived`, не удаляем, но и не показываем активным.
- **Изменённая строка** (остаток вчера 5000, сегодня 0) → **версионность** снапшота полей, иначе теряем историю или плодим дубли.
- **Время/статус** заказа → паспорт несёт время/статус явно, иначе агент говорит о прошлом как о настоящем.

## Факт из Telegram
- **Клиента ещё нет / кандидатов два** → сущность **«висячий факт»** (`about: unresolved`), привязка дорешивается позже.
- **Синк приносит противоречащий факт** → оба факта живут, разного происхождения, статус метит расхождение (тест «статус=метка»).

## Что данные заставят решить про единицу памяти
- **Гранулярность:** узел=заказ или заказ=связка (клиент)-(авто)-(период)-(деньги)?
- **Версионность** обязательна раньше, чем думали (живые денежные поля).
- **Идентичность узла vs содержимого** — первый мутирующий источник тестирует формулировку паспорта.
- **Ребро — тоже единица памяти** (уверенность/происхождение/время) — иначе дедуп не сработает.

## 🔴 Топ-3 недооценённых риска
1. **Дедуп людей — главный риск, телефон его не решает** (все три опоры гнилые). Ложный кластер/дубли = модель НЕ проверена.
2. **Версии + tombstone не покрыты «upsert»** — он доказывает только повтор на неизменных данных; жизнь меняется/удаляется ежедневно.
3. **«Доказать за неделю» — иллюзия**, если в срез войдут извлечение из заметок и подсчёт денег → явно вырезаны (см. decision).
