# Линзы/доступ/формулы рентакара ↔ ядро

> Вывод одной мыслью: **почти всё, что владелец описал про линзы, уже спроектировано в ядре.**
> Рентакар не открывает новое поле — он даёт первые конкретные инстансы и вскрывает 1 реальную дыру.

## 1. Ключевое разведение (не путать)
- **Линза (`lens`)** = КАК читается вещь (форма/угол). Ось ядра `thing×actor×scope×lens×time`.
  Владелец: `view`-поле + view-компилятор `from · traverse · filter · shape` (phase-1 R-1).
- **Доступ (capability)** = ЧТО разрешено видеть/писать. ADR-0004: reach (scope-стек) + authority (роль) +
  `viewer` + `can_read/can_write`, default-deny, Конституция-clamp ПОСЛЕ свёртки. Доказан killer-прогоном (15/15).
- **Линза формирует, доступ разрешает.** Линза может скрыть для удобства; доступ — запрещает жёстко. Разные механизмы.

## 2. Идеи владельца → куда ложатся (маппинг)
| Идея владельца | Механизм ядра | Статус |
|---|---|---|
| Линза на чат / на агента | `lens` привязана к `viewer` (actor) + `scope` (топик) | ✅ есть |
| Агент видит свой срез графа | ADR-0004 capability: `viewer=agent` + reach+authority | ✅ есть, доказан |
| Линза «под роль × топик» (зашита в топик) | топик = `scope`, роль = `authority`; view компилится под (viewer+scope) | ✅ есть — и это здравое решение |
| У сделки/форка своя линза | линза, привязанная к узлу-сделке (reach: `node` = вершина стека) | ✅ есть |
| Связь 1-к-1 «нельзя смотреть» части ролей | `can_read` на РЕБРЕ (ребро несёт паспорт, D6); линза прячет | ✅ есть |
| Ограничение обхода «до колена» / зацикленность | `traverse` в view-компиляторе — **нужен bound глубины + cycle-guard** | 🔴 ДЫРА — новое |

## 3. Единственная реальная дыра, которую вскрыл рентакар
**Обход графа без границы = зацикленность/взрыв** (клиент → его сделки → другие клиенты → …).
→ View-компилятору нужен **явный bound: max-depth («колено») + защита от циклов**.
→ Роутить в `docs/02-project/core/00-kernel/open-questions.md` как KQ (view-compiler traverse bound).

## 4. Формула / виртуальное поле (профит по дням) — это ПРОЕКЦИЯ, не хранимое
- В ядре: `state` = свёртка `acts[]`; **вычисляемое поле = линза (view), не истина в базе**.
- «Фактическое поле из CRM» = хранимый акт (`source = plugin:crm`).
- «Виртуальное поле» (профит по датам, дельта от последней синхронизации) = **считается на чтение** линзой.
- «Разница / дата-время последней синхронизации» = функция `recordedAt` (system-time уже в модели).
- **Правило:** производное НЕ храним — отдаём линзой. Совпадает с каноном «состояние = проекция актов».

## 5. Что осталось от владельца (вход в след. шаг)
- Бизнес-процесс проката **на словах** → прогнать через модель: какие акты (открыть/править/закрыть сделку,
  оплата, штраф, ТО), какие линзы (владелец/менеджер/бухгалтер/водитель), где форки.
- Подтвердить решение «линза зашита под (роль × топик)» (В-4).
