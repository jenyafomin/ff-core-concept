# Спек инжеста — первый вертикальный срез

> Одна страница. Задача среза (В-1): доказать, что **синк Sheets→граф идемпотентен** (два прогона = 0 дублей),
> **идентичность людей обратима** (`same-as`), и **факт из чата переживает синк**. Sheets = upstream, граф = проекция (D2).
> Кода этот файл НЕ содержит — это контракт, по которому код пишется отдельным «строй».

## 0. Границы (что в срезе / что вырезано)
- **В срезе:** листы **Orders** (~4102 строки), **Cars**, узлы-клиенты (производные от Orders).
- **Вырезано из MVP** (D1, анализ-01): извлечение фактов из `Recent Note` (заносим сырьём), подсчёт денег агентом
  (денежные поля грязные). Пульт/мультипроект/ABAC — не трогаем.

## 1. Паспорт узла (обязательные поля)
| Поле | Смысл | Пример из данных |
|---|---|---|
| `id` | локальный стабильный id узла в графе | `ord_45875-2870` |
| `project` | жилец-владелец (D4, грубый scope) | `ga-rentacar` |
| `source_ref` | **ключ идемпотентности** — из содержимого, не из позиции строки | `sheets:Orders#45875-2870` |
| `node_type` | тип узла | `order` · `car` · `customer` |
| `version` / `snapshot` | версия снапшота полей (меняется при изменении upstream) | `v3`, снапшот полей на момент синка |
| `tombstone` | статус жизни: `active` · `archived` (строка исчезла из Sheets) | `active` |
| `epistemic_status` | происхождение/достоверность: `synced` (из Sheets) vs `observed` (из чата) | `synced` |
| `valid_time` / `status` | время и статус самой сущности (не строки) | `Status=Active`, `Order Open Time` |

## 2. Паспорт ребра (тоже единица памяти — D6, анализ-01)
Рёбра `same-as`, `rented`, `drives` несут: **`confidence`** (0..1) · **`provenance`** (чем порождено: телефон/имя/ручное) ·
**`time`** (когда установлено) · **`tombstone`** (обратимость — раз-слияние = метка, не удаление).

## 3. Правило `source_ref` (идемпотентность)
- **Order:** `sheets:Orders#<numCore>`, где `numCore` = числовое ядро `NNNNN-NNNN` из колонки `#`,
  **отрезав мутабельные хвосты** (`Long term`/`Short term`/`Collection`/` [AL]`). Пример: `45832-2865Long term` → `45832-2865`.
  ⚠️ до прогона проверить **уникальность numCore** по всем 4102 строкам (гейт: 0 коллизий, иначе ключ расширяем).
- **Car:** `sheets:Cars#<Plate No>` (напр. `FF-81201`). Plate = идентичность авто.
- **Customer:** **НЕ имеет натурального ключа.** Создаётся per-occurrence как `sheets:Orders#<numCore>:customer`
  (клиент-как-упомянут-в-этом-заказе), затем дедупится рёбрами `same-as` (§4). Никакого ключа по телефону/имени.

## 4. Идентичность людей (Вариант А — D5, топ-риск анализа-01)
- Клиент **размазан по N заказам** → синк создаёт N узлов-кандидатов. Это **ожидаемо**, не баг.
- Дедуп = **рёбра `same-as` с `confidence`**, не слияние узлов. Телефон/имя дают только *кандидата* (обе опоры гнилые:
  SIM≠человек, транслит пляшет Mohammed/Mohamed). **Автослияния нет.**
- `same-as` **не транзитивен наивно** → кластер с уверенностью на ребре, не мега-склейка.
- Слияние ручное и **обратимое**: раз-слияние = tombstone на ребре (§2), узлы не трогаем.

## 5. Правило upsert (анти-коррозия — D2)
- Матчинг по `source_ref`. Есть → сравнить снапшот; изменился → **новая `version`** (историю не теряем), не второй узел.
- Строка пропала из Sheets → `tombstone=archived` (не удаляем, не показываем активной).
- **Синк владеет только своими полями** (`synced`). Поля `observed` (факт из чата) синк **НЕ трогает** — иначе затрёт.

## 6. Тест-план среза (критерии «готово»)
| # | Прогон | Ожидаемо |
|---|---|---|
| T1 | Синк Orders+Cars **дважды подряд** на живых данных | **0 новых дублей** на 2-м прогоне (счётчик = 0) |
| T2 | Уникальность `numCore` по 4102 строкам | 0 коллизий ключа |
| T3 | Два узла-кандидата клиента → ребро `same-as` → **ручное слияние → раз-слияние** | оба обратимы, узлы целы |
| T4 | Дописать факт из чата (`observed`) → прогнать синк ещё раз | **факт пережил синк** (не затёрт) |
| T5 | Изменить строку в Sheets (остаток 5000→0) → синк | новая `version`, старый снапшот жив |
| T6 | Удалить строку из Sheets → синк | узел `tombstone=archived`, не исчез |

**Срез засчитан, если T1 и T4 зелёные** (ядро В-1: идемпотентность + переживание факта); T2/T3/T5/T6 — сопутствующие гейты.

## 7. Что срез скормит ядру (driver → kernel)
- **KQ-11** (память=проекция): узел `observed` из чата = акт `observation`, адресуется insight-ребром — T4 это проверяет живьём.
- **KQ-8** (удаление/tombstone): T6 = поведение при исчезновении строки.
- **В-5** (traverse-bound): всплывёт при обходе клиент→сделки→другие клиенты (см. questions) — рассмотреть следом за спеком.
