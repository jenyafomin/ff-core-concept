# Решение: направление и границы первого среза

## Зафиксированные решения
- **D1. Узкий вертикальный срез.** Sheets → проекция в граф → один Telegram-топик, где агент отвечает
  про клиента и дописывает факт обратно в граф. Пульт/мультипроект/ABAC — НЕ проектируем до 2-го жильца.
- **D2. Источник истины = Sheets, граф = производная память.** Синк = идемпотентный upsert по `source_ref`.
  Анти-коррозия: синк владеет своими полями, граф/агенты/чаты — своими; друг к другу не пишут.
- **D3. MCP-обёртку CRM НЕ делаем сейчас** (процесс живёт в Sheets, не в CRM-коде). Из CRM — только словарь + идеи ABAC.
- **D4. ABAC откладываем.** На старте хватает грубого скоупа по топикам (топик=сессия=cwd). В паспорт заложить
  `project` + метку чувствительности; движок доступа — позже (ADR).
- **D5. Идентичность людей = Вариант А:** клиенты локальны в проекте + обратимое ребро `same-as` к общей личности.
  Никакого автослияния; телефон/имя дают только *кандидата*; слияние ручное и обратимое.
- **D6. Паспорт расширен** (после прохода Fable): узел несёт **версию/снапшот полей** и **tombstone-статус**;
  **ребро тоже несёт паспорт** (уверенность · происхождение · время).

## Границы первого среза
**Доказать:**
1. Синк Orders+Cars+Customers → узлы с `source_ref`; **двойной прогон → 0 дублей** (идемпотентность на 4100 строках).
2. Кандидаты-дубли клиентов → рёбра `same-as` с уверенностью; **одно ручное слияние + одно раз-слияние** (обратимость).
3. Один топик: агент отвечает «что знаем о клиенте …» и дописывает факт из чата.
4. **Критерий успеха:** факт из Telegram **переживает следующий синк** (два питания не затирают друг друга).

**Явно вырезать из MVP** (иначе «неделя» станет месяцем):
- извлечение фактов из `Recent Note` — заносим сырьём, без понимания;
- подсчёт денег агентом — денежные поля грязные, агент будет врать.
