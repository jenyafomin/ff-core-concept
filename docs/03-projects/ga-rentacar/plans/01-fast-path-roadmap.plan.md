# Быстрый путь: живая база знаний на ga-rentacar

> **Вопрос владельца (2026-07-26):** «как быстро внедрить базу знаний как одну систему — поднять базовую
> версию под бизнес-процессы, изначально из того же что есть, и дальше дорабатывать через общение».
> Этот файл = ответ-хребет. Синк — **с Google Sheets, не с CRM** (D2/D3): истина = Таблицы, CRM не поднимаем.

## 🎯 Что значит «базовая версия» (цель среза-0)
Один топик Telegram, где агент **отвечает про клиента проката из графа и дописывает факт обратно**, а под ним —
тонкий движок, кормящийся из Sheets. Живое, узкое, на реальных данных. Потом углубляем итерациями через диалог.

## 🧩 Из чего собираем (ничего с нуля — «то же самое»)
| Кусок | Что уже есть | Роль в срезе-0 |
|---|---|---|
| **Данные** | `RENTACAR_EXCEL_ANALYTICS` тянет Sheets→PostgreSQL (Orders ~4102, Cars…) | источник инжеста |
| **Движок-seed** | `run-view.mjs` (граф+линзы, доказан) + `run-view-depth2.mjs` (loop-guard) | ядро `TOOLS/ff-engine` |
| **Рантайм агента** | `agents-manager` (шлюз): топик=сессия, агент отвечает и пишет | оболочка топика |
| **Контракт инжеста** | `specs/01-ingest-slice.spec.md` (паспорт + idem-upsert + T1–T6) | как данные лягут в граф |

## ✅ Решение (владелец, 2026-07-26): целимся сделать ЦЕЛИКОМ, ведём ВЕХАМИ
Строим **полноценный движок фазы-1** (не выбросной минимум) — но лестницей вех, где **за короткий промежуток
уже есть работающий тестируемый минимум**, от которого идёт продолжение, корректировки и проверка на живом.
«Целиком» — это цель (M0→M6 все запланированы); «минимум за промежуток» — это M3 (живой агент), после которого
не переписываем, а углубляем. Строгие куски (capability, PG, масштаб) не выкидываем — они поздние вехи, не «до боли».

## 🪜 Лестница вех (каждая = тестируемый минимум + точка корректировки)
| Веха | Что даёт | Тест-гейт (DoD) | Живой минимум? |
|---|---|---|---|
| **M0 · Каркас-ядро** | `TOOLS/ff-engine`: seed `run-view`+`depth2` → импортируемое ядро (loader·validator·edge-index·view-compiler·resolve-stub), CLI | `invariants.test` зелёный, seed-корпус грузится, 1 линза через CLI | ⚙️ движок запускается |
| **M1 · Инжест рентакара** | store-адаптер + Sheets Orders/Cars → узлы с паспортом, idem-upsert | **T2** ключ уникален · **T1** двойной прогон = 0 дублей | 📥 реальные данные в графе |
| **M2 · Дедуп + линза клиента** | рёбра `same-as` (confidence) + линза «что знаем о клиенте X» | **T3** слияние/раз-слияние обратимо; линза отдаёт клиента+заказы | 🔎 запрос по клиенту работает |
| **M3 · Топик-агент живьём** | wire в `agents-manager`: агент читает линзу → отвечает → пишет факт `observed`; замок анти-коррозии | **T4** факт из чата пережил синк | 🟢 **ПЕРВАЯ ЦЕННОСТЬ** — живой агент с памятью |
| **M4 · Строгость движка** | `resolve()` PEP + capability · PostgreSQL read-model (CQRS-lite) · версии/tombstone | capability 15/15 · **T5/T6** (изменение/удаление строк Sheets) | 🔒 доступ+история строго |
| **M5 · Масштаб (Q-7)** | прогон 10³–10⁴ на адверсариальном корпусе, кеш грантов, индексы | P95 ≤ 200 мс (порог фазы-1) | 📈 держит объём |
| **M6 · Роли/доступ + В-4/В-5** | линза роль×топик (В-4, возможно несколько вариантов) · traverse-bound (В-5) · второй топик/роль | линза компилится под (viewer×scope); обход с bound | 👥 многоролевой доступ |

**Точки корректировки — между вехами:** после M3 (первый живой прогон) и после M4 сверяемся с реальностью и
правим модель/движок, прежде чем идти дальше. Каждая веха тестируется на живом, не «спроектировали и забыли».

### Как это ложится на общий план
- **M0–M3** = ядро фазы-1 в минимальном объёме + кусочек фазы-3 (развёртывание на один топик) → быстрый живой минимум.
- **M4–M5** = полнота строгой фазы-1 (`realization-plan/phase-1-engine`) — то самое «целиком».
- **M6** = вход в фазу-3 (роли/доступ/партиции) — сюда параллельно ложатся **В-4/В-5**.
- ga-rentacar остаётся **driver**: каждая веха вскроет, какие KQ ядра реально нужны — их и закрываем.

### Параллелизм (внутри вех)
После M0-каркаса независимы: store-адаптер ∥ view-компилятор ∥ resolve-PEP ∥ инварианты. **В-4/В-5** —
отдельная дорожка, можно вести параллельно с M1–M3 (владелец: «легко можно параллельно»).

## 🧭 Связь с общим планом
Это **не параллельный план**, а конкретизация `realization-plan` фаз 1→3 под первого жильца:
срез-0 = фаза-1-ядро (минимум) + кусочек фазы-3 (развёртывание на один топик). ga-rentacar = driver, который
покажет, какие KQ ядра и куски движка реально нужны — их и закрываем, не всё подряд.

**Статус:** active — путь выбран (целиком, вехами). Ждёт **«строй» на M0** (каркас-ядро `TOOLS/ff-engine`) — это первое касание кода.
