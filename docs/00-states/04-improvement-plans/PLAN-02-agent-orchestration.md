## Где мы
Готовность ~**30%**. Примитивы **STATE·PLAN·TASK·LOOP** описаны хорошим DRAFT'ом
(`01-orchestration/DESIGN.md`): каждая сущность = **узел-якорь + акт-журнал (истина) + линза (статус,
CQRS) + policy-as-data**. Рост через INSERT типа + view-def, без миграций (DL-01). Но:
- ADR `decisions/ADR-DRAFT-orchestration-state-plan-task-loop.md` в статусе **`proposed`, НЕ approved**.
- Заблокировано на **6 развилках**. Из них два — жёсткие:
  - 🔴 **Форк #1** — противоречие источников: `01-node/analyses/02-states.md` (до-CQRS) описывает
    `state.md` с **хранимым полем `status`, которое пишет агент напрямую**; DESIGN/ADR говорят «статус =
    линза, узел несёт лишь `status_cache` derived». Пока не сведено — разв.1 подписывать нельзя.
  - 🔴 **Форк #6** — политика материализации 4 линз (live-compute vs материализация): горячая тропа
    `state.current` читается ПЕРВОЙ на каждом `session-open`. Сам критик проекта зовёт это «реальным
    блокером»; без ответа форки 1 и 2 неисполнимы.
- Вторичный риск: **гонки записи** нескольких агентов в `state.md` `agents:[...]` — помечены, НЕ
  спроектированы (DL-26 Temporal-lite не подключён).
- Внешняя зависимость: финализация `node-types.md` ждёт числа примитивов brain (**FQ25**, сфера S-01).
