## 🌱 Модель контролируемого роста (как этот трек — и доки вообще — растут под контролем)

Не изобретаем новый закон — собираем существующие в один наблюдаемый цикл. Законы-владельцы:
**doc-discipline** (где живут доки), **R2** (`00-states/README.md` — конвенция состояний),
**`01-tree-rules-and-librarian`** (как растёт дерево).

Жизненный цикл единицы работы:
1. **Вход темы → стейджинг, не сразу дом.** Новая тема без дома → метка `needs-home`, не плодим папку
   (doc-discipline). Дом ищем ПЕРВЫМ ходом.
2. **Нужна параллельная работа → заводится `state`** (R2): плоско в `00-states/NN-slug/`, файлы
   `state.md` + `log.md`, тема = ПОЛЕ, не папка.
3. **Состояние держит `plan`** (ребро `plan --targets--> state`): backlog доработок (наш случай — 6 планов).
4. **Движение — скиллом `plan-driller`:** пункт `todo → in-progress → done`; углубление = подпункты
   ВНУТРИ плана, а не новые файлы/папки. Обновляется пульт (этот state.md) + `log.md`.
5. **Ничего не удаляем.** Закрытое → `status: archived` (файл остаётся). Дубли → редирект-заглушка.
6. **Один вход, виды ≠ дома.** `state` виден из канонического `STATE.md`; INDEX/навигаторы = ВИДЫ.
7. **Рост компенсируется архивацией/сжатием, не удалением** (R2). Клапан против бардака — дисциплина
   входа (п.1) и один дом на тему (doc-discipline), а не запрет на рост.
