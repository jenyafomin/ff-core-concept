# Критика Q-R4classes

## (1) Smuggle-check на fail-closed-аналогию — CLEAN

§5 анализа не протаскивает C. Само сравнение «unknown→conservative» пришло НЕ из этой ноды — оно уже
в исходном D4-brief как обоснование C («mirrors ADR-0009's existing 'unknown → conservative' pattern»,
`D4-decision-lens-briefs.analysis.md:~109`). §5 анализа явно ДЕФЛИРУЕТ его: «Это НЕ довод в пользу выбора
C» + называет асимметрию (соль — дешёвая операция vs R4 блокирует ingest целиком) —
`01-r4classes-menu.analysis.md:142-147`. Это корректирующий, не смуглящий ход.

**Остаточная асимметрия (NOTED, не DIRTY):** в per-class A/B/C-проекциях (§1-5) варианты B и C везде
получают явную «цену» инлайн (классификатора нет / ненадёжен / over-block), а вариант A — нет (напр.
`:32-34` для minors: «A — … сегодняшнее поведение» без встречной цены рядом). Цена A (необратимая ошибка
при первой записи) названа только на уровне question.md/D4-brief, не повторена в каждой строке таблицы.
Это лёгкий структурный крен к бездействию (A выглядит «бесплатным» построчно) — стоит поправить в
следующей итерации, но не смуглит к B/C и не меняет вывод.

## (2) Факт-claim про reduce.ts / admission.ts — CONFIRMED

Прочитан весь `packages/ingest-rentacar/src/core/reduce.ts` (160 строк) и
`packages/engine/src/core/admission.ts` целиком.
- `reduce.ts:75-77` — `name`/`phone`/`recentNote` через `str(row, ...)`, свободный текст для Note.
  **Поля возраста/даты рождения нет вообще в файле** (ни в `str()`-вызовах, ни в payload/snapshot) —
  claim подтверждён буквально.
- `admission.ts:26-43` — `DEFAULT_PII_KEYS` подтверждён как словарь ИМЁН ПОЛЕЙ (name/phone/email/passport/
  card/iban/nationalid…), не референт-класс; ключа возраста/даты рождения тоже нет — подтверждает вывод
  анализа «классификатору сегодня нечем сработать» для minors.
- ADR-0009 цитата «Unknown → трактуется как low-entropy (солёный, fail-safe)» найдена на строке 221
  (question.md заявляет :220-222) — точно.

## (3) VIP вне A/B/C — обоснованно, не натянуто

Логика §4.5/§6 держится: A/B/C в D4-brief буквально определены как admission-time действия (пустить/
исключить/fail-closed-до-классификации) — все три говорят про МОМЕНТ ВПУСКА. VIP-риск, как описан (§5),
не про факт впуска, а про ШИРИНУ доступа ПОСЛЕ. Это разные оси, конфликт реален, не притянут за уши.
Проверен и факт-якорь: `grep VIP OWNER-QUEUE.md` → только строка 56 (список классов Q-R4), в исходном
D4-brief R4-блоке (`D4-decision-lens-briefs.analysis.md:86`) VIP отсутствует — «добавлен позже, при
компрессии» подтверждено буквально.

## (4) Полнота классов — один правдоподобный пропуск

Financial/geolocation как ОТДЕЛЬНЫЕ референт-классы не тянут — geolocation уже покрыт классом «no-trace»
(§4), financial — поле-уровень (IBAN/card уже в `DEFAULT_PII_KEYS`), не референт-класс, сама нода уже
разводит это разграничение на примере Emirates ID (п.4 «Что не хватает»). Но **биометрия** (фото/
отпечаток при KYC-сканировании ID, правдоподобно для luxury-rental Emirates ID) — отдельная категория
особого режима в большинстве privacy-режимов, качественно ближе к «health» по юридическому весу, но
НЕ названа отдельно. Также **референты вне дееспособности по другой причине, чем возраст** (умершие —
проектный self-description «агрегатор всей жизни человека» подразумевает семейные/наследственные узлы,
Ц-7 «дееспособность давать согласие» логически совпадает с аргументом minors) — правдоподобный пропущенный
класс, не критичный для ga-rentacar M1, но релевантный для платформы. PROVOCATION, не CRITICAL — меню уже
явно себя называет неполным и открытым для дозаполнения владельцем.

## Меню остаётся линзой, не вердиктом

Подтверждаю: A/B/C нигде не выбираются нодой (`:159-161` — «Ни один пункт этой таблицы не выбран «за»
владельца»), варианты дословно взяты из уже существующего D4-brief, не изобретены здесь; per-class
таблицы дают цену/резон без «should». Асимметрия из п.1 — единственная найденная трещина, и она
косметическая (структура таблицы), не смысловая (нет явного текста-рекомендации).

## Вывод

**CLEAN.** Все 4 факт-claim'а подтверждены прямым чтением кода/доков. Smuggle не найден — §5 активно
деактивирует унаследованную из D4-brief C-аналогию, а не усиливает её. Один NOTED (асимметрия
A-без-цены в построчных таблицах — легко чинится добавлением одной фразы на класс) и один PROVOCATION
(биометрия + умершие референты как правдоподобные, не критичные дополнения к меню). Уверенность: высокая
по фактам, medium по интерпретации нейтральности (интерпретативный вопрос по природе).
