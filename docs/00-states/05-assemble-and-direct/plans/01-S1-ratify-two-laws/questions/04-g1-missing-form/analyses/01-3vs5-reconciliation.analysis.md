# Свод: 5 (UNIT-SPEC §7) vs 3 (U-L1 candidate) — что где, почему разошлись

## 1. Два списка verbatim

**5 форм — `UNIT-SPEC-v1.design.md:84-93` (§7, дата написания 2026-08-07, "большинство уже есть"):**
1. Три роли `author · owner · referent` на ячейке (:86)
2. Единственный путь записи через PEP `resolve()` (:87) — "один choke-point на запись **и чтение**"
3. Policy-слот на ячейке и на грани (:88)
4. Payload/act split + стираемость per-грань (:89-92)
5. Placement как поле политики (:93)

Тот же список цитируется в `HANDOFF.md:42` (2026-08-07, статус superseded, но содержание не отозвано):
"роли · единый путь записи/PEP · policy-слот · payload/act split+стираемость · placement-поле" — **совпадает
дословно с §7**, это одна и та же перепись, не два независимых источника.

**3 формы — `two-laws.invariant-candidate.md:47-57` (U-L1, дата 2026-08-08, продукт стресс-теста F1/F2/F6):**
1. Deref-seam — единая воронка payload-deref с параметром `viewer` (:48-50)
2. Opaque edge-identity — форма `Edge` заморожена append-only (:51-56)
3. Admission-точка + хук классификации (:57)

Тот же счёт в `DIRECTION-to-ready.md:28` ("2 из 3 швов не заложены") и `:71-72` (S2 применяет ровно эти 3) и
`SPEC-DELTA-DOCKET.md:67-71` ("Сводка: что retrofit-НЕВОЗМОЖНО" — те же 3, с пометкой "самый срочный"/"Owner:
направление F6"/"Owner: R4").

## 2. Сведение — не 3 vs 5, а 5 ⊃ (частично) 3, плюс один НОВЫЙ элемент

| U-L1 (3, найдено 08-08) | Отношение к §7 (5, написано 08-07) | Вывод |
|---|---|---|
| **Deref-seam** (read-side payload) | **Уточнение/трещина §7-п.2.** §7 заявляет "PEP — choke-point на запись **и чтение**" как ФАКТ. `F1-read-pep-design.design.md:26-47` (grounded 08-08, grep кода) показывает: чтение payload (L3) **не проходит через `resolve()` вообще** — `read:payload`-операции не существует (`resolve.ts:116-121`, подтверждено повторным grep этой ночью — 0 хитов `read:payload`/`derefPayload` в `packages/engine/src/core/*.ts`). §7-п.2 был **преждевременным canon-lie** (заявил форму как готовую, она не готова на read-стороне). | НЕ новая форма — **починка ложного статуса** уже названной формы. |
| **Admission-точка + классификация** | **Уточнение/трещина §7-п.3.** Policy-слот формально есть (`admission.ts`), но реальный барьер `admitHome` — fail-OPEN по умолчанию и не инжектится (`SPEC-DELTA-DOCKET.md:31-34`, подтверждено `code-ground-truth`/HANDOFF-3 ФАНТОМ①: `engine.ts:81` зовёт `admitHome` безусловно, но дефолт fail-open). | НЕ новая форма — **уточнение дефолта** внутри уже названного policy-слота (§7-п.3), не новый choke-point. |
| **Opaque edge-identity** | **ГЕНУИННО НОВОЕ.** §7 (5 форм, 2026-08-07) **ничего не говорит про идентичность рёбер** — ни слова про `Edge`-ключ, opaque vs value-aware. Найдено `F6-edge-identity-design.design.md` (2026-08-08) через фальсификацию хребта на 2-й форме (`time-on-edge`): `foldEdges` дедуплицирует по `(predicate,target)` (`predicates.ts:113`) — если ключ станет value-aware (интервал), форма `Edge` уже не заморозить постфактум (`SPEC-DELTA-DOCKET.md:35-36`: "Retrofit: **ДА** (форма `Edge` заморожена)"). | **Форма #6, не входившая в §7.** Канонический список 2026-08-07 объявлял себя ЗАКРЫТЫМ ("Швы, которые нельзя добавить позже — поэтому фиксируем в ядре v1", `:85`) и **пропустил её** — нашлась только через адверсариальную фальсификацию хребта день спустя. |

**Итог свода:** списки не противоречат друг другу по содержанию (3 не заменяет 5 — 2 из 3 это ремонт
существующих пунктов §7, третий — генуинно новый пункт §7 не предвидел). Расхождение "3 vs 5" в разных
документах — это **артефакт того, что ни один документ не публикует ЖИВОЙ объединённый список**; DIRECTION и
SPEC-DELTA-DOCKET считают только "то, что ещё не заложено" (3), а HANDOFF считает "весь канон" (5) — обе
цифры верны для своего среза, но НИ ОДНА не является текущим полным списком. **Текущий полный список форм,
если сложить всё найденное на сегодня = минимум 6** (5 §7 + opaque-edge-identity), из которых 2 требуют
починки статуса (deref-seam, admission), а не только "заложить".

## 3. Механизм расхождения (почему это будет повторяться)
§7 объявил себя закрытым списком ДО адверсариального прохода (F1/F2/F6 stress-test случился на день позже,
той же сессии другим методом — фан-аут 7 направлений). Значит: **закрытие списка форм в прозе происходит
РАНЬШЕ, чем стресс-тест, который такие формы находит.** Пока стресс-тест не гарантированно исчерпывающий
(фан-аут по 7 темам — это выборка тем, не полное покрытие поверхности кода), каждый следующий проход может
найти форму #7. Именно поэтому G1 не может оставаться "список, который мы ведём в prose" — см. `critique/
01-redteam-forgotten-forms.critic.md` §4 (предложенный фальсифицируемый тест).
