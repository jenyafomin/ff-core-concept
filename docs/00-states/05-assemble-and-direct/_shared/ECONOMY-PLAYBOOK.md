# ECONOMY-PLAYBOOK — качество × экономия для прогона S1..SN

> Закон владельца (2026-08-08): **экономим на ТОКЕНАХ, НЕ на РЕЗУЛЬТАТЕ.** Перепроверки/пересмотры/
> адверсариал — обязательны всегда; вопрос только В ТОМ, КАК делать их дешевле при том же качестве.
> Действует поверх `SESSION-CONTROL.md` (поведение/правила) каждую сессию.

## 1. Бюджет токенов на сессию → регулярные хендоффы
Сессия НЕ бесконечна. Каждая сессия = **одна ветка (один план S-N), закрывается хендоффом**. Это и есть
дробление токенов: не «один гигантский прогон», а серия ограниченных, каждая стартует с МЕНЬШИМ контекстом.
- **Целевой размер сессии:** ~8-15 agent-вызовов, 2-4 волны. Больше — дроби на две сессии.
- **Контекст лида ≤ ~40k:** лид читает ТОЛЬКО выжимки (см. §3.1), не сырьё. Раздулся — значит лид собирает
  сам вместо делегирования = ошибка.
- **STOP-триггеры (закрываем сессию хендоффом):** гейт достигнут · бюджет волн исчерпан · найдена
  находка-вне-ветки (→ `task-pool.md`, НЕ гонимся) · лид-контекст пухнет. Любой сработал → **пиши HANDOFF, стоп.**
- **Регулярность:** хендофф в КОНЦЕ каждой сессии — не опция. Следующая сессия обязана стартовать с него холодно.

## 2. Распределение нагрузки (под одним управляющим агентом)
Один лид-оркестратор + слои. Нагрузка НЕ на лида — на команды.
- **Лид (Opus, тонкий):** держит высоту, раздаёт волны, читает выжимки, синтезирует, эскалирует форки владельцу. Сам НЕ анализирует/не собирает сырьё.
- **2 планировщика (co-orchestrator, sonnet):** помогают расставить задачи — читают реальность, выдают тугие task-спеки. (Модель владельца: «2 доп-агента расставляют задачи остальным».)
- **Co-orchestrator для чтения СЫРЬЯ:** когда нужно прочесть много транскриптов/файлов — читает ОН, отдаёт лиду дайджест. Экономит контекст лида.
- **Воркеры по когнитивному типу** (не по одному «универсалу»): `analyst` вглубь · `system-architect` границы · `abstract-thinker` вверх/рефрейм · `critic` адверсариал · `builder` код/доки · `business-analyst` ценность.
- **Волны = слои зависимости:** recon → decompose (планировщики) → execute (воркеры) → critique (критики) → synthesize. Внутри волны — независимые агенты В ОДНОМ сообщении (параллельно, синхронно под шлюзом).

## 3. Best-practices: то же качество дешевле
1. **Контракт дайджеста.** Каждый агент пишет ПОЛНОЕ в файл, возвращает ≤200 слов: вердикт · топ-находки · `file:line` · уверенность · 1 открытый вопрос. Лид рулит дайджестами → его контекст мал → дёшево.
2. **Роутинг моделей по цене задачи.** Разведка/поиск/механика = **haiku** (explorer). Анализ/критика/бизнес/сшивка = **sonnet**. Несущий дизайн/архитектура/рефрейм/финальный синтез = **opus**. Не жечь opus на механику.
3. **Перепроверка ПРОПОРЦИОНАЛЬНА ставке.** Load-bearing/необратимое → 2-3 независимых скептика, каждый ПРОБУЕТ ОПРОВЕРГНУТЬ, разные линзы (correctness/security/repro). Низкая ставка → 1 критик. НЕ 3×-верифай всё подряд — верифай то, что роняет ставку. (Этот прогон: 3 критика на 5 выходов — сфокусированно, не 5×3.)
4. **Consolidate-first, не пере-выводить.** Прежде чем плодить агента — есть ли готовый синтез/дайджест? Агенты читают ХЕНДОФФ и дайджесты, не сырую историю. Картина закэширована в файлах.
5. **Параллель, не сериал.** Независимую работу — в одном сообщении разом (барьер только когда следующий слой реально нужен ВСЕ предыдущие результаты: dedup/раннее-нет/сравнение). Иначе теряем wall-clock и платим за простой.
6. **Размер команды под задачу.** Правка 2 файлов НЕ требует 10 агентов — лид пишет сам + 1 критик. Мега-фан-аут на мелочи = сжигание токенов. Масштаб — под ставку и ширину.
7. **Fable — только на несущей развилке.** Дорогая модель зарезервирована под острейшую дивергенцию/тупик, не под рутину.
8. **Тугие промпты + схемы.** Точный промпт с явным output-контрактом (или JSON-схемой) убирает круги переспросов.
9. **Гейт заранее.** DoD ветки известен НА ВХОДЕ → нет блуждания «а достаточно ли». Находки-вне-ветки → пул.

## 4. На чём НЕ экономим (жёстко)
- **Критик ПЕРЕД «готово»** — всегда. Пойманный на бумаге баг/смугл дешевле построенного.
- **Адверсариал на необратимом** (retrofit-невозможные формы, форки владельца) — минимум 2 независимых линзы.
  *Уточнение для ГЕЙТОВ РАТИФИКАЦИИ (без стройки):* если предмет уже выведен ≥2 линзами ВЫШЕ по потоку
  (напр. 2 закона = abstract-thinker + критик прошлой сессии), то в сессии-ратификации хватает **1 критик-на-смугл
  + ратификация владельца (= вторая независимая линза)**. Не дублируем уже пройденный адверсариал — экономия без потери качества.
- **Форки — владельцу линзой**, не решаем сами (дешёвая «экономия» решением за владельца = дорогая ошибка).
- **LOSE-NOTHING** — со-размещение/снапшоты; не стираем ради «чистоты».
