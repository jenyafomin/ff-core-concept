# SESSION-CONTROL — контракт прогона S1..SN

> **Зачем.** `HANDOFF.template.md` контролирует ОДНУ передачу (батон ветки). Этот файл контролирует ВЕСЬ
> многосессионный прогон: то, что не меняется от сессии к сессии — ПОВЕДЕНИЕ команды, НЕСОКРАЩАЕМЫЕ правила,
> КОНЦЕПТУАЛЬНЫЙ груз, дисциплину ЗАПИСИ. Каждая сессия S1..SN наследует всё ниже по умолчанию; хендоф
> заполняет ветко-специфику. **Хендоф ПРЕДПИСЫВАЕТ** (поведение · ядро-правила · концепты · задачи · запись),
> а не просто пересказывает. Этот файл — предписание; батон — его экземпляр на ветку.
>
> **Границы.** Здесь — только инвариант прогона. Механику батона НЕ дублируем → `./HANDOFF.template.md`.
> Живые задачи → `./task-pool.md`. Определение готовности/законы → `direction:` во frontmatter.

## 1. BEHAVIOR — как ведёт себя команда (каждая сессия)
- **Оркестратор держит высоту и делегирует.** Сам контекст НЕ собирает; раздаёт задачи агентам, держит
  абстрактный контроль. Минимум токенов на себя, максимум глубины контроля.
- **Волнами 3–6 агентов, СИНХРОННО** (`Agent(run_in_background:false)`, несколько вызовов в одном ходу).
  Под шлюзом фон умирает на конце хода → результат нужен ЭТОМУ ходу = синхронно. Обрыв стоит одной волны.
- **File-first.** Каждое утверждение якорится на `work/`-файл (`file:line`), не заявляется в чате. Чат эфемерен.
- **Критик ДО «готово».** Ни одна волна не закрывается без адверсариального прогона (вердикт может
  перевернуться — так и задумано). Гейт качества — отдельным агентом, не автором.
- **Форки → владельцу как ЛИНЗА, не вердикт.** Развилки оформляются нейтральными брифами (варианты + рычаг),
  владелец решает; агент не решает за него необратимое.
- **Планировщики помогают раздать.** 1–2 планировщика кросс-проверяют назначения задач до запуска волны.

## 2. CORE RULES — несокращаемые (несутся каждую сессию)
- **gateway-sync** — под шлюзом не запускать фон, чей результат нужен ходу (`~/.claude/rules/orchestration-sync-under-gateway.md`).
- **git-working-tree-safety** — грязное дерево = деструктив не трогаем; диагностику НЕ сцеплять с деструктивом;
  **без явного «строй»/«коммить» — не коммитим** (`~/.claude/rules/git-working-tree-safety.md`).
- **LOSE-NOTHING** — новее побеждает как направление, но ничего не стирается; закрытое → `status`, не delete.
- **80/20** — двигаем несущие 20% (критический путь), не всю ширину; готовность = критические грани зелёные.
- **concepts-stay-open** — фаза DESIGN; концепты держим открытыми, круги by-design, не провал.
- **no-build-without-«строй»** — на диск/в код только по явному «строй» владельца; иначе ОПИСЫВАЕМ.

## 3. CONCEPTS CARRIED — концептуальный груз (инвариант, держать каждую сессию)
- **ЦЕЛЬ — доверяемая композиция.** Единица, которой доверяют жизнь: агент растит, но не ломает
  тождество/правду/согласие. Разрез ядро/грань = цель в форме данных.
- **2 ЗАКОНА** (свод 4 нитей, `direction:` §1):
  - **Закон-1 — форма retrofit-НЕВОЗМОЖНА, политика retrofit-дёшева.** Заложить СЕЙЧАС структуру (choke-point,
    идентичность, ПРИСУТСТВИЕ admission-гейта+хук классификации) до первого прод-payload; enforcement-логику
    (в т.ч. fail-open/closed + классы = R4) — когда угодно/владелец.
  - **Закон-2 — юнит-статус ЗАРАБАТЫВАЕТСЯ жизненным циклом.** Растит идентичность+состояние+согласие →
    повышается до ЕДИНИЦЫ; иначе грань/ребро/payload. Один предикат = файл↔единица + монумент-рекурсия + N-020.
- **G1–G5 — определение готовности** (`direction:` §0, НЕ переопределять по ходу): G1 формы заложены · G2
  хребет доказан на ≥2 структурно разных формах · G3 спека честна (0 canon-lie) · G4 необратимые форки закрыты ·
  G5 несущие грани переписи зелёные. Сегодня honest ready ≈30–40%.
- **CUT-LIST (Fable — что НЕ строить сейчас):** не строить enforcement-логику внутри швов (только форму);
  не гнать всю ширину (только 20% несущих); не открывать слой агентов / межценностный арбитраж 7 ценностей;
  файл↔единица · монумент · N-020 — НЕ отдельные нити (свёрнуты в Закон-2, закрываются с S3).

## 4. TASKS — связка с task-pool.md
- **Карта планов прогона** — `../plans/INDEX.md` (узлы S1..S4, статусы, цепь C→A→B→D); каждый план несёт этот контракт.
- **Одна сессия = одна entry-ветка** (метка из `./task-pool.md`: S1 / S2 / D1.b / D0…). Неглубоко.
- **Гейт определён ЗАРАНЕЕ** — `gate` и `next` формулируются в начале ветки (см. `HANDOFF.template` §gate/§next).
- **Находка-ВНЕ-ветки → пул, НЕ гонимся.** Новое рождённое → задачей в `./task-pool.md` (id + ветка + якорь
  вербатим `file:line`), не в хендоф, не в текущую волну (STOP-правила батона).
- **Якорь = вербатим.** Инженерная задача несёт первичный код-якорь, иначе следующая сессия пере-судит
  решённое кодом (урок FORK-3). Концептуальная без кода — `needs-anchor` на прозу.

## 5. RECORDING DISCIPLINE — где живёт запись ЭТОГО прогона (не пересказ грамматики)
> Полная грамматика узлов (три архетипа · `.{type}.md` · один-дом · статус-не-delete) — в
> `docs/.claude/rules/doc-tree.md` (ВСЕГДА в контексте проекта) + скилл `doc-discipline`. Не дублируем её здесь.
- **Trace-дом ЭТОГО прогона:** `docs/_log/<дата>-<ветка>/` (append-only указатели, gitignored). **Knowledge-дом:**
  дерево планов `../plans/` + brain-дерево `docs/02-project/core/01-brain/`. Trace ссылается на knowledge, не хранит.
- **На закрытии сессии:** `docs/INDEX.md` держать ПРАВДИВЫМ (area-level, статусы) — обязанность §6.

## 6. HANDOFF-FILL — как сессия закрывается
Каждая сессия закрывается ТРЕМЯ действиями (иначе прогон рвётся):
1. **Заполнить `./HANDOFF.template.md`** → `docs/_log/<дата>-<ветка>/HANDOFF.md` (поля entry-branch · gate ·
   harvested · spawned · carried · next · read-first; удалить `<!-- -->`). Малый вход, якоря вербатим.
2. **Обновить пульт-указатель** → `../state.md` (карточка ветки: статус · gate достигнут? · handoff-ссылка).
3. **Прогнать гейт-чеклист прогона** (ниже) — сессия не «done», пока он не зелёный или расхождение не названо.

### Гейт-чеклист прогона (перед переводом ветки в done)
- [ ] Критик прошёл ДО «готово» (не автор); вердикт зафиксирован в `work/`-файле.
- [ ] Все claim-ы file-first (`file:line`), не в чате; инженерные задачи несут вербатим-якорь.
- [ ] spawned-находки уложены в `./task-pool.md`, не потеряны и не догнаны в этой ветке.
- [ ] LOSE-NOTHING: закрытое → `status`, ничего не стёрто; дубли → редирект.
- [ ] Ничего не коммичено без явного «строй»/«коммить»; грязное дерево не тронуто деструктивом.
- [ ] G1–G5 не переопределены задним числом; готовность отчитана по переписи, не по 80%-числу.
- [ ] HANDOFF.md заполнен + `state.md` пульт обновлён.
