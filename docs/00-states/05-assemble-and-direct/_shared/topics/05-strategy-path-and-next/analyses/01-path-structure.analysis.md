# 1. Реальный критический путь (структура, не пересказ)

Цепь материализована и однозначна (`plans/INDEX.md:52-59`):

```
C (S1 · форки-ворота) → A (S2 · заложить формы) → B (S3 · доказать хребет) → D (S4+ · ширина)
```

- **Строго последовательны C→A→B→D** для ЯДРА: «нельзя начинать D-стройку, пока A не заперла швы (иначе миграция)» (`INDEX.md:57`). D параллелизуема веером ТОЛЬКО после A+B (`INDEX.md:58`).
- Зависимости узлов подтверждены frontmatter: S1 `depends_on:[] unblocks:[S2]` (`01-S1.../README.md:17-18`); S2 `blocked-by S1`, S3 `blocked-by S2`, S4 `blocked-by S3 + owner-ratify списка граней` (`INDEX.md:46-48`).
- Готовность честно ≈ **30-40%** (`INDEX.md:39`), G1-G5 сегодня: G1⬜ G2🟥 G3🟥 G4⬜ G5🟥 (`DIRECTION-to-ready.md:28`). **S1-S3 = критические 20%** (`INDEX.md:39`, `DIRECTION:87`).

# 3. ОДНА следующая сессия (жёстко отрезано, структурно)

Структурный конфликт, который надо назвать честно: **истинный next-move — это owner-decision-проход, а не агент-сессия.** Значит «следующая агент-сессия» обязана быть тем, что делает owner-проход БЕЗОПАСНЫМ и однопроходным — иначе владелец подпишет НЕПОЛНУЮ retrofit-невозможную форму (red-team это уже поймал: `OWNER-QUEUE.md:171-193`).

**Рекомендуемая ОДНА сессия: «S1-пакет к подписи + маршрутизация владельцу».**
- **entry-branch:** C · «форки-владельца-как-ворота» (та же ветка, что у S1 — `README.md:28`). НЕ открывать A/B/D.
- **конкретный выход (2 артефакта, один дом):**
  1. `plans/01-S1-ratify-two-laws/work/two-laws.invariant-candidate.md` **пропатчен до signature-ready** по варианту (Б) Q-G1-scope-gaps (`OWNER-QUEUE.md:186`): Instance-1 переформулирован, чтобы явно исключить узкое чтение CRIT-1 (fold/снапшот/durable-fs deref-периметр — `04-threat-model/...02:44-51`), + добавлен Instance-4 «valid-time/as-of» (ось свежести, источник сам метит retrofit-НЕВОЗМОЖНОЙ).
  2. **OWNER-DECISION-SHEET** — один чек-лист, сводящий пять 🔴-форков в ОДИН проход (Law1·Law2·I4·R4-диспозиция·G1-scope), варианты без вердикта, ссылки на ноды. (Консолидирует `OWNER-QUEUE.md` «Утренний пакет» в один executable проход, не новый анализ.)
- **done-gate:** пропатченный документ существует + **critic «no smuggled decisions» CLEAN** (= DoD S1 п.5, `README.md:70`) + decision-sheet существует. После этого S1 закрывается В МОМЕНТ подписи владельца — агентам добавить нечего.
- **почему highest-leverage структурно:** это единственная работа, которая ФИЗИЧЕСКИ снимает бутылочное горло (owner-decision-гейт) вместо того, чтобы снова упереться в него. Двигает G4 (форки становятся закрываемыми в один проход) и де-рискует G1 (закрывает 2 дыры формы ДО необратимой подписи). Всё остальное (S2 формы, S3 хребет) заблокировано ЗА этим гейтом.
- **тест «тайно ли это три сессии?»:** нет. (a) патч одного документа, (b) сборка одного decision-sheet, (c) один critic-проход — это один architect + один critic одной синхронной волной (`README.md:88`). НЕ строит формы (S2), НЕ доказывает хребет (S3), НЕ перепись (S4). Одна сессия.

**Контр-кандидат, отклонён:** «просто отправить OWNER-QUEUE владельцу» — дешевле, но НЕБЕЗОПАСНО: red-team показал, что подпись as-is фиксирует неполную append-only форму (`OWNER-QUEUE.md:188`). Ремонт текста стоит одну правку сейчас против невозможного retrofit потом.
