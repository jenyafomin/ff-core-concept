# Value/Leverage — приоритизация следующего хода

## 1. Диагноз лида (9 итераций = 0 сдвинутых ворот) — верен ли с т.з. ЦЕННОСТИ владельца?

**В основном ДА, с одной поправкой.** `RUN-INDEX.md` подтверждает: G1-G5 статусы не сдвинулись за 9
итераций ночного прогона (см. `state.md:141-156`). Но это не значит, что анализ был бесполезен —
он превратил 8 открытых форков из «открытых вопросов» в **готовые к владельцу single-pass меню**
(R4 = 7 классов с ценой каждого; L1dom = 4 опции A/B/C/D; F6-грань A/B разнесены) — см.
`OWNER-QUEUE.md`. Это САМА ценность анализа: не решить за владельца, а сделать решение ДЕШЁВЫМ одним
проходом. Проблема — не в том, что анализ делали, а в том, что его **продолжают ПОСЛЕ того, как
пакет уже готов к подписи** (итерации 8-9 = U3/U6, ещё не закрывающие ни один 🔴-форк, спавнят
НОВЫЙ форк FORK-U3 🟡). Маржинальная итерация анализа сейчас имеет убывающую отдачу.

**Поправка к диагнозу лида:** «нет стройки» — неточно. Стройка УЖЕ была (2026-08-06, Этап 1+2 D1.b:
`store-durable-fs.ts:171-251`, verified reviewer PASS + runtime CONFIRMED) — просто **не закоммичена**
и её ветка (D1.b форма/шов) ОТДЕЛЬНА от того, что сейчас гейтит S1 (ратификация законов → I-4 → код
Шага-1: `erased`-акт + порт `shred`). Точнее: «следующий код заблокирован не отсутствием стройки как
навыка, а незакрытыми воротами перед НОВЫМ куском кода».

## 3. Самый маленький «видимый результат» шаг

Два кандидата, оба реализуемы В ЭТОМ ходу, не взаимоисключающие:
1. **Компоновка decision-packet** — не новый анализ, а сборка уже готового материала
   (`OWNER-MORNING-PACKET.md` уже это в 90%; не хватает: явно отметить, что Q-G1-scope-gaps ДОЛЖЕН
   решаться ПЕРЕД Q-Law1, а не параллельно — сейчас оба помечены 🔴 без явного порядка).
2. **Один из двух dev-only багов** (`T-grant-forgery` ИЛИ `T-policy-node-provenance`) — закрывается
   агентом без ожидания владельца → реальный коммитable диф, гейт G3 (честность) чуть подрастает.

Оба — **не анализ**, оба производят артефакт, который либо закрывает форк, либо чинит код.

## 4. Реальная цель владельца (из его же слов, `strategy.question.md:47-50`)

Владелец: «ключевую цель, скорее всего, ещё не озвучил», гипотеза лида — **доверяемое автономное
ведение проекта, человек только на форках**. С точки зрения ценности это ПОДТВЕРЖДАЕТСЯ именно
сегодняшним запросом «результаты, не разговоры»: он хочет увидеть механизм «человек решает ТОЛЬКО
развилки, всё остальное машина делает сама и показывает результат» — то есть decision-packet ОДНИМ
проходом ЕСТЬ демонстрация целевого режима работы, не побочный артефакт. Форки уже почти готовы к
такому проходу (`OWNER-QUEUE.md` формат: суть·варианты·цена·рычаг — без вердикта агента) — это ровно
то, что нужно.
