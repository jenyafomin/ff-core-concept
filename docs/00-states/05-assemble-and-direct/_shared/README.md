# _shared — служебное (переиспользуемое)

> Идея владельца (08-04): чтобы наработки не терялись между сессиями/планами, держим здесь
> **переиспользуемые состояния и паттерны**, на которые планы ссылаются ЯВНО (а не копируют). Плюс
> **снапшоты** ключевых развилок/решений — как точки возврата и материал для переиспользования.

## Что здесь лежит (сейчас)
- **task-pool.md** — живой пул задач S-D (не хроника): индекс + вербатим-якоря `file:line`. Стейт и планы
  наполняются отсюда; закрытое переводим в `done`, не удаляем (LOSE-NOTHING).
- **SESSION-CONTROL.md** — единый контракт входа/выхода планов (как сессия открывается, ведётся и сдаётся);
  на него ссылается `handoff-contract` каждого плана-узла.
- **ECONOMY-PLAYBOOK.md** — экономия/нагрузка/бюджет прогона: как дёшево гонять волны агентов под шлюзом.
- **HANDOFF.template.md** — шаблон батон-хендофа; копия кладётся в `docs/_log/<дата>-<план>/HANDOFF.md`.
- **RECOMMENDATION-2026-08-06-next-stage.decision.md** — снапшот-решение о следующей стадии (точка возврата).

## Правило ссылки
Состояние/план ссылается на `_shared/...` по пути в своём frontmatter (`reuses:` / `snapshot_of:` /
`session_control:` / `pool:`), не дублируя контент. Снапшот/решение — УКАЗАТЕЛЬ + краткая выжимка,
истина в исходном доме.

> Навигатор (ВИД), не второй дом истины. Обновлять при добавлении/удалении файлов в `_shared/`.
