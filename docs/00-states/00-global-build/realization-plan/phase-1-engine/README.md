# Фаза 1 — Тонкий движок

> Первый **рабочий бэкенд**, из которого уже вытягиваем информацию линзами. Дорастить доказанный seed
> `run-view.mjs` до сервиса. Один движок на все модули (память + agent-manager).

## 🎯 Цель
Движок, который держит граф (узлы+рёбра), исполняет `view`-запросы и отдаёт результат/аналитику.

## 📋 Что происходит
1. **Репо** `TOOLS/ff-engine` (общий, служит brain+agents; НЕ отдельный «brain-engine»).
2. **Хранилище** узлы+рёбра: `md+frontmatter` = истина (закон doc-tree №1), **PostgreSQL** (DL-21) под индекс/аналитику; язык TS/Node (DL-19).
3. **Компилятор `view-def`** — 4-стадийный запрос `from·traverse·filter·shape` (канон R-1), исполняется как `run-view`.
4. **Паспорт + policy-cascade (PEP)** — единый порог доступа; `visibility/access/capability` читаются движком.
5. **Инварианты** — валидатор конверта/рёбер-пар/meta-example (падает при нарушении, как в killer-прогоне).
6. **M-G1 Temporal-lite** (append-only + rebuild-from-journal) + **M-G3** (реестр типов, view-компилятор).

## 🚪 Вход
Фаза 0 закрыта (ADR-0004/0005 approved, Q-14 решён).

## ✅ Готовность (DoD)
- [ ] Движок грузит корпус узлов, исполняет линзы, отдаёт результат по CLI/HTTP.
- [ ] **Прогон масштаба Q-7** (10³–10⁴ узлов) вернул реальные числа и время — «всё в одной БД» не тормоз.
- [ ] Инварианты enforced; те же линзы (`cost-tree`/`visible-to`) работают на большом реальном корпусе.
- [ ] seed `run-view.mjs` перерос в сервис, не игрушку.

## 🔑 Ключевые решения к доработке
- `md`-vs-Postgres как истина (предложение: файлы=истина, PG=производный индекс/аналитика).
- Формат интерфейса: CLI → HTTP API (что первым).
- Границы M-G1/M-G3 (что в MVP-движке, что позже).

## ⚡ Параллелизм
После каркаса: хранилище ∥ view-компилятор ∥ инварианты — независимые треки.

## 🧪 Как проверяем
Killer-прогон на масштабе + бенчмарк; повтор доказанных линз на реальном большом корпусе; тесты инвариантов.

## ⚠️ Гейт/риск
**Q-7 масштаб** — если одна БД тормозит, вводим партиции по проекту (это и нужно Фазе 3).
