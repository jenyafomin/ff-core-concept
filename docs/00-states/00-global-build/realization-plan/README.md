# 🚀 План реализации — от доказанной модели к рабочему бэкенду

> **Общий review.** Читай этот файл первым: он держит цель, несущий инсайт и карту фаз. Детали каждой
> фазы — в её папке (`phase-N-*/README.md`), каждую дорабатываем ОТДЕЛЬНО перед запуском. План живой:
> статусы и находки обновляются по ходу.

## 🎯 Цель
Пройти путь **доказанная модель данных → тонкий движок-бэкенд, из которого реально вытягиваем информацию →
подключённая память → развёртывание на проект с людьми и доступами.** Не большая стройка сразу, а
walking-skeleton, который с каждой фазой углубляется.

## 💡 Несущий инсайт — ОДИН движок, не два
Разведка (2026-07-24) показала: **память и agent-manager — одна архитектура, разные фазы.** Один конверт
(узел = системные поля + `body` + рёбра), одна форма линзы-`view`, одна модель доступа (паспорт/capability).
Совместимость 100%.

→ Значит **«подключить память» — это НЕ отдельная стройка.** Движку всё равно, какие узлы читать —
агентские или узлы памяти. Мы строим **ОДИН движок**, а память, agent-manager и будущие модули — это
**разные корпуса узлов в нём**. «Развернуть на проект» = навести движок на партицию этого проекта.
Это и есть plug-in-цель, достигнутая по-настоящему: внедрять надо ОДИН раз, а не под каждый проект заново.
Наш доказанный `run-view.mjs` — seed этого движка.

## 🪞 Принцип-зеркало (инвариант, держим во всех фазах)
Агентская система должна быть **зеркалом взаимодействия**: всё взаимодействие идёт через агента, а его
**ограничения и возможности видны ЯВНО и живут В САМОЙ системе как данные** (`visibility · access ·
capability`), не в скрытом коде. Если возможность агента не выражена узлом — она нарушает принцип.
Это может потребовать достроить дополнительные узлы/линзы «система о себе» (`view:system-map`).

## ⚙️ Как мы работаем с этим планом
1. **Фаза за фазой, но каждую сперва ДОРАБАТЫВАЕМ** в её папке (важные детали, решения) — потом запускаем.
2. **Параллелим** внутри фазы, где куски независимы (помечено в каждой фазе).
3. **Тестируем и пробуем** на живом по ходу — не «спроектировали и забыли».
4. **Гейты между фазами:** не входим в следующую, пока не выполнены критерии готовности (DoD) текущей.
5. **agent-manager дорабатываем сквозняком** — каждая фаза вскроет, где модель узла надо углубить/синхронизировать.
