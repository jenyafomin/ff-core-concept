## 🎯 Цель
Закрыть все одобрения и блокеры архитектуры, чтобы Фаза 1 стартовала на твёрдом.

## 📋 Что происходит
1. **ADR-0004** (граница ядро/модуль + capability-доступ): critic-проход по `08-core-and-modules` → правки → статус **approved**.
2. **ADR-0005** (память: 9 форков F1–F9): ревью форков (`review`→`approved`) → ADR **approved**.
3. **Q-14 — приоритет политик/доступов** (ОБЩИЙ блокер обоих модулей): решить порядок разрешения конфликта (кандидат: `узел > space > project > module > deny`, дефолт-deny) → записать узлом `policy:access-priority`.
4. **Критические FQ-ценности** памяти: FQ1/FQ2/FQ9/FQ21 (оспорены) финализировать; FQ7 (hard-erase) SPEC-DRAFT → approved.

## 🧭 Рефрейм (владелец 2026-07-24)
Фаза 0 — работа РЕШЕНИЙ владельца, не производство агентов. Критический путь сжат: **реально блокирует код только Q-14** (модель доступа) + ратификация ADR-0004/0005. Ценностные форки (FQ1/FQ2/FQ21) = семантика единицы памяти, не конверт движка → несём как design-debt.
**Открытая тема от владельца:** слоистость `space.override > space.default > project > module` — вероятно НЕ только про доступ, а сквозной примитив (промпты-каскад, агенты, policy-as-data). Что контролируем жёстко, что гибко; можно ли делить policy-данные между слоями. → отправлено в abstract-thinker, результат вливается в ADR-0004.
