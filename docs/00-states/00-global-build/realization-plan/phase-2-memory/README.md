# Фаза 2 — Память как корпус

> «Подключить память» = загрузить её типы узлов в уже работающий движок. Отдельного бэкенда памяти НЕТ —
> это тот же движок, читающий узлы памяти.

## 🎯 Цель
Реальные узлы памяти живут в движке, линзы отдают по ним осмысленную аналитику.

## 📋 Что происходит
1. **Типы памяти как `meta:type`**: личность · событие · задача · факт · паспорт-поле (маппинг 4 доменов из 7 ценностей).
2. **Загрузка реальных узлов** памяти в движок.
3. **Линзы-аналитика** над памятью (тренды, срезы по человеку/проекту).
4. **Тождество и время в деле**: `canonical_id` (одно тождество) + bitemporal (управление временем) проверяются на данных.

## 🚪 Вход
Фаза 1: движок работает и держит масштаб.

## ✅ Готовность (DoD)
- [ ] Реальные узлы памяти → линза вернула осмысленную аналитику.
- [ ] `canonical_id` и bitemporal проверены на данных (тождество не двоится, история срезов читается).
- [ ] Согласуется с 7 ценностями/инвариантами (Читаемость·Тождество·Доверие·…).
- [ ] hard-erase (забвение) отрабатывает на данных (tombstone + наследование).

## 🔑 Ключевые решения к доработке
- Маппинг **4 домена → типы узлов** памяти.
- Паспорт-поля: что обязательно на узле памяти.
- hard-erase на реальных данных.

## ⚡ Параллелизм
Заведение типов ∥ загрузка узлов ∥ линзы-аналитика.

## 🧪 Как проверяем
Аналитический срез по реальной памяти владельца (напр. «что накоплено о человеке X», тренды во времени).
