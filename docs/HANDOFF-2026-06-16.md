  verdict.md raw/*.md` → отправить одним вложением (просьба владельца: «группируй в один файл»).

## 6. ТЕКУЩЕЕ лучшее понимание модели (зафиксировано в канвасе)
- **Архитектура:** ТОНКОЕ ЯДРО + ДВИЖОК/БД + МОДУЛИ. Сложности (перелинковка/выборка) = движок. Поля/валидация/
  логика per-type = модули.
- **Рефрейм ноды:** ядро ноды = **ПАСПОРТ интерпретации** — набор ГРАНЕЙ, читаемых ИИ БЕЗ вскрытия payload и БЕЗ
  знания типа (аналогия: морской контейнер — маркировки снаружи, груз внутри).
- **11 граней:** ЯДРО(7) — Identity · Belonging · Relation · Temporal · **Trust** · Provenance · Scope.
  МОДУЛЬ/гибрид(4) — Payload · Workflow · Branches · Reactivity. (Trust+Provenance = «2 поля» владельца + достройка.)
- **Архитектурный КЛЮЧ (Принцип 0):** тип/схема/ограничения/ветки = **тоже узлы графа** (control plane = данные).
- **Внутренняя структура:** тип = узел `model-def`; `mode: controlled|flexible|hybrid`; лестница constraints
  (декларативные → условные → «функции-как-условия» = узлы-предикаты, declarative-first); **Single Source of Schema**
  — одна декларация работает на ИИ (интерпретация) + движок (валидация) + человека (автоформа).
- **Безопасность (универсально в ядре):** `epistemic` (факт/черновик) + `decision`-клапан на внешние необратимые
  действия. ⚠️ **`decision` ещё НЕ реализован — закрыть ПЕРВЫМ** (главный риск автономии).
- **Ветки:** именованные + указатель активной + diff-оверлей; identity узла стабилен; ветка несёт свой epistemic.
- **Плагин:** манифест-узел, владеющий N моделями в неймспейсе; project-area scoping; system-тип≠user-тип;
  пользователь системы ≠ пользователь приложения (2 принципала).
