## 🎯 Главный вывод (сходится с нашим консилиумом)
Рынок 2026 сходится на паттерне, который мы уже вывели: **markdown-как-истина + производный
встраиваемый ИНДЕКС для быстрых граф-запросов + MCP для доступа ИИ.** Это ровно наш «документ=истина,
БД=тень». Ресёрч дал конкретные движки и подтвердил, что отдельный «ИИ-эксперт по БД» НЕ нужен.

## 1. Механизм хранения/графа (V1) — подтверждено
- **Лучшие встраиваемые движки для solo:** **DuckDB + DuckPGQ** (SQL/PGQ, переменно-длинные пути
  заменяют рекурсивные CTE, in-process, без сервера) и **Kuzu** (single-file embedded, но **АРХИВИРОВАН
  окт-2025 → форк LadybugDB**). Подтверждено 3-0: DuckDB умеет property-graph-запросы, variable-length
  path finding на векторизованном движке. [duckdb.org/duckpgq]
- **Два пути:** (а) встраиваемый граф-движок поверх данных, или (б) гибридная память над markdown-как-истина.
- ⚠️ **Убито при верификации (1-2):** конкретные перф-цифры «Kuzu 374× быстрее Neo4j» и «sub-3ms» —
  НЕ доверять числам. Архитектурный тезис (встраиваемый движок достаточно быстр на личном масштабе) стоит.
- **Не покрыто бюджетом ресёрча (честно):** MongoDB, SurrealDB, Memgraph, Postgres+Apache AGE — глубоко
  не оценены. → **Mongo как «идеальный» ответ НЕ подтверждён**; документная БД слаба на обходе графа.
  Делать Mongo источником истины — не рекомендуется по итогам.

## 2. Доступ ИИ (V2) — подтверждено 3-0
- **Отдельный суб-агент «эксперт по БД» НЕ нужен.** Claude сам открывает схему через MCP
  (инструмент get-schema / `apoc.meta.data`), пишет запрос (Cypher/SQL), и **сам себя исправляет**.
- **Neo4j выпустил ОФИЦИАЛЬНЫЕ MCP-серверы:** `mcp-neo4j-cypher` (запросы) + `mcp-neo4j-memory` (память).
  Паттерн переиспользуем для любого движка: тонкий MCP над индексом → Claude интроспектирует и запрашивает.
  [neo4j.com/mcp, neo4j «Claude converses Neo4j via MCP»]

## 3/4/5/6 — память, файлы, важность, загрузка (подтверждено)
- **Graphiti (getzep)** — инкрементальный real-time гибридный граф (semantic + keyword + graph), ships
  MCP-сервер. Мощно, но это LLM-пайплайн извлечения — **тяжелее, чем нужно solo** (отложить). [github/getzep/graphiti]
- **sqlite-memory / MemWeave** — паттерн «markdown-как-истина → индексируется в ОДНУ SQLite-БД атомарной
  заменой; гибридный поиск (вектор + ключевые слова)». «Markdown-файл, который побил $50M вектор-БД» —
  markdown-first + frontmatter для RAG. **Прямо наш случай.** [sqlite-memory, trysteakhouse markdown-first]
- **Важность = ЦЕНТРАЛЬНОСТЬ графа (betweenness), а НЕ бэклинки** (InfraNodus, подтверждено 3-0).
  → Контекстную/иерархическую важность можно ВЫЧИСЛЯТЬ из структуры графа, а не только проставлять руками.
  Это закрывает твою «иерархическую важность» элегантно + делает «данные живыми для ИИ». [infranodus/network-analysis]
- **Файлы:** паттерн markdown-как-истина побеждает; БД/индекс — производное. Подтверждает наш выбор
  «файлы=истина, индекс=тень»; виртуальный MD/хуки — валидный вариант, но истина остаётся в читаемом файле.
- **Представление/фильтры:** Tana (supertags=типизированные узлы), InfraNodus (центральность, gap-анализ),
  Obsidian (граф декоративный, не queryable — урок: граф должен быть ЗАПРАШИВАЕМ). [tana, infranodus, obsidian]

## ✅ Рекомендация для нас (solo на Claude Code)
**Не менять истину — добавить производный встраиваемый индекс + MCP.**
1. **`@ff/core` markdown-файлы остаются ИСТИНОЙ** (человекочитаемо, git, уже есть).
2. **Производный встраиваемый ИНДЕКС**, пересобираемый из файлов: **DuckDB+DuckPGQ** (рекоменд. — in-process,
   SQL+граф, есть node-биндинги, идеально для TS-монорепо) ИЛИ SQLite+sqlite-vec (паттерн MemWeave).
   Он закрывает: мульти-родители (DAG), типизированные рёбра, **обратный обход** (наша дыра!), лимиты/
   пагинацию/глубину, гибридный поиск для ИИ.
3. **Тонкий MCP-сервер над индексом** → Claude интроспектирует схему и сам пишет запросы (без «ИИ-эксперта по БД»).
4. **Важность** — добавить ВЫЧИСЛЯЕМУЮ центральность (betweenness) поверх ручной `importance`/якорей.
5. **Отложить тяжёлое:** Graphiti/Letta/Neo4j-сервер/Mongo — over-engineering для старта; вернуться, если
   индекс перестанет тянуть.

**Переиспользовать:** DuckPGQ/SQLite (движок индекса), официальный MCP-паттерн Neo4j (как образец), идею
центральности InfraNodus. **Строить кастомно:** проекцию файлы→индекс, нашу схему узла, фасеты/важность,
тонкий MCP под наш граф.
