# Стратегия — «умные категории» (гибкие типы через категоризацию)

- **Status:** draft (только ВЕКТОР, по просьбе владельца msg 254: «пока написать только стратегию, отложить, не терять план»)
- **Owner:** jenya.stasik@gmail.com · **Date:** 2026-06-23 · **Источник:** N-087 (рефрейм Q8)
- **Режим:** ЛЁГКО (токены/скоро compact). Глубокий многоэтапный разбор — ПОЗЖЕ (тема №2). Здесь — чтобы вектор не потерялся.

## L1 — Что это (идея владельца, в одной фразе)
Гибкость даёт **не «под-тип внутри типа»** (это ломает паспорт), а **слой КАТЕГОРИЙ**: вложенные «умные категории»,
**привязанные к типу**, у каждой — свои уровни определения/поля. Категория = мощный инструмент для **линзы** (срез/поиск).

## L2 — Как устроено (опорные тезисы — на доработку)
1. **Категория привязана к типу** (наследуется от него / `kind-of`-связь к типу). Тип «сделка» → категории «покупка», «продажа».
2. **У категории — свои уровни определения:** напр. «покупка».Категория2 содержит dropdown-значения, которых НЕТ у «продажи».
   → категория несёт **доп. поля/ограничения/валидацию**, специфичные для неё (не для всего типа).
3. **Категории вложенные** (категория в категории) — иерархия классификации, отдельная от иерархии принадлежности (home).
4. **Связи:** часть **авто** (создаются автоматически, но **только в определённых группах**), часть — **явные**.
5. **Может совпадать с типами** — граница «тип ↔ категория» размыта намеренно; категоризация — гибкий слой поверх открытого реестра.
6. **Сила — в линзе:** «продажа личных предметов» = тип-сделки × категория × проект/группа × … — пересечение осей = срез.

## L3 — Где живёт в модели (предварительно, держим инварианты)
- Категория = **узел control-plane** (рядом с ТИП/ЛИНЗА), либо специализация ТИП-узла; членство ячейки в категории = **`facet-of`
  ребро** (многомерность, N-081) — НЕ `home`. Доп. поля категории = её payload-контракт (как у типа).
- **Инвариант держим:** дискриминатор/валидация выбирается по «обложке» (тип/категория на ребре/в паспорте), **не из payload**
  (иначе движок вскрывает ячейку — запрещено). Это безопасная форма «вариант = тип/категория + линза».
- **Открытые вопросы (на глубокий этап):** категория-узел vs facet-тег vs под-тип — где грань? · авто-связи «только в группах» =
  правило какого узла? · вложенные категории + наследование полей = как валидируется? · пересечение с Q3 (группа=категория).
