## Вход
Сердце проекта — не органайзер, а три слоя ВМЕСТЕ: организация (граф nodes) +
агенты как горизонтальный слой во всей системе + агрегация (синтез across направлений).
Вход ИИ-driven. Примитив уже работает: Claude Code + docs/ + Telegram + советы + память.

---

## КОНСЕНСУС

1. **Объединяющий примитив (Reframer):** не три слоя, а ОДИН — **агент действует над узлом
   графа и пишет след обратно как узел.** Организация = граф в покое; агенты = граф в движении;
   агрегация = граф под запросом. **Один граф, три глагола.**

2. **Не строить новый субстрат — формализовать существующий** (Architect + Pragmatist + Reframer).
   `docs/` (Markdown + frontmatter + ссылки) = граф узлов; Claude Code = рантайм; это уже
   гексагональная архитектура: nodes = домен, агенты = адаптеры через ОДИН контракт
   (read / write / link / append-trace). Никакого Electron/БД на первом шаге.

3. **Агрегация — НЕ слой и НЕ хранилище**, а проекции-rollup, выводимые по запросу (on-demand,
   с TTL), которые агент пересобирает в диалоге. Это by-design убивает рассинхрон и главный
   enterprise-соблазн (фоновые пайплайны = путь к забросу для solo).

4. **Первый шаг = ОДИН замкнутый цикл с реальной пользой**, поверх существующих файлов.
   «Цикл из одного» (выбрать узел → прогнать агент → записать результат обратно) — это вся
   система в миниатюре; остальное — копипаст.

5. **Ценность = частота использования, не полнота охвата** (Pragmatist). Один скилл, запускаемый
   еженедельно, стоит больше пяти агентов, запущенных по разу.

---

## ГЛАВНЫЙ DISSENT — сохранён, не сглажен (Скептик, conf 0.82)

**Скептик ПРОТИВ рефрейма** и это нельзя усреднять:
- «Агенты как горизонтальный слой» = переименование сложности в архитектуру. Три петли
  обратной связи, ни одна не замкнута. Органайзер (совет #2) убивает тем, что не используется;
  рефрейм убивает тем, что **никогда не заканчивается** — каждый слой рождает «сначала нужно X».
- **«Примитив уже работает» — частично иллюзия:** Claude Code сам по себе не персистит состояние
  между сессиями по расписанию, не пушит автономно, не связывает граф с Telegram без оркестрации.
  «Формализовать существующее» может втихую превратиться в стройку с нуля.
  *(Прим. Председателя: часть пробелов закрывается штатным Claude Code — память = персистентность,
  `/schedule` = автономный push, Telegram-канал = доставка. Но Скептик прав, что это надо
  СОБРАТЬ, а не считать готовым.)*
- **Механизм смерти — «прогресс без доставки»:** каждую неделю есть что показать (новый агент,
  новый слой), но ты сам не получаешь ценность. Удовольствие от проектирования маскирует
  отсутствие замкнутых петель.

**GATE-критерий рефрейма (Скептик):** если через 2 недели агрегация не выдала **хотя бы один
синтез, который изменил реальное решение** — рефрейм провалился, вернись к одному слою.

> ⚠️ Этот gate применим и к самому процессу: три совета — это уже близко к «проектированию без
> конца», о котором предупреждает Скептик. Следующий шаг должен быть ДОСТАВКОЙ, не советом.

## РАЗВИЛКА — Push vs Pull (выбор владельца)

Оба — «один цикл агента над графом», разница в инициативе:
- **PULL — еженедельный дайджест-скилл** (Pragmatist): `/weekly-digest` читает `docs/**`,
  синтезирует статус по направлениям, пишет в `docs/reviews/YYYY-WNN.md`. Запуск руками в пятницу.
  Дёшево (1-2 дня), но требует, чтобы ты вспомнил запустить.
- **PUSH — ежедневный утренний брифинг в Telegram** (User-Advocate): агент по расписанию читает
  `docs/` + открытые задачи + память → шлёт 3-5 пунктов в Telegram («вчера ты оставил решение по X,
  контекст …, нужно 5 минут»). Ощущение расширения: ты НЕ думал о задаче, а она не потерялась.
  Механизм — персистентная память + проактивный push, не интеллект. Реализуемо через `/schedule`.

## Несокращаемые риски
- **Мета-игра** (critical/high): строить агентов для агентов; реальная задача не решается. → gate Скептика.
- **`docs/` как помойка без структуры** → агрегация даёт мусор (Pragmatist). → шаблон узла/frontmatter.
- **След агента не пишется обратно** → агрегации нечего читать (Reframer). → дисциплина следа.
- **Push надоедает / неточен → отключается** (User-Advocate). → конкретика, не шум.

## Вердикт Председателя
Рефрейм принят в форме Reframer'а (один граф + агенты пишут след), исполнен по Pragmatist/
User-Advocate (один крошечный цикл поверх существующего), под gate Скептика (2 недели → реальный
синтез или откат). Выбор push/pull — за владельцем. **Дальше — доставка, не ещё один совет.**
