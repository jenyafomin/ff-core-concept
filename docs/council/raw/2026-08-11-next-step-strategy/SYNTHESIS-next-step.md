# Синтез: какой следующий шаг самый эффективный (личная команда лида)

## Метод
Два независимых вектора, разные модели, разные позиции: Fable-стратег (pro-launch) + Критик (anti-launch).
Не доверяем одному ответу. Ценность — в их РАСХОЖДЕНИИ и в точке СХОЖДЕНИЯ.

## Расхождение
- **Fable:** запускать Волну-A сегодня (T1a demo + T3 + T4-spike, без владельца), один кивок Q-critical-faces.
- **Критик:** СТОП — все 4 трека выбраны по ДОСТУПНОСТИ (что можно делать без владельца / без реальных
  данных / без агентного слоя), а не по ЦЕННОСТИ. Это гниение реестра на уровне ФАЗЫ: активность ≠ прогресс.

## Схождение (сильный сигнал — оба, с разных сторон, назвали одно)
**3 trust-бага, где КОД СЕЙЧАС противоречит северной звезде «агент не может сломать доверие»:**
- `T-grant-forgery` — capability форжится (`resolve.ts:136-141`)
- `T-policy-node-provenance` — policy-узел перезаписывается
- `T-write-pep-unwired` — write-PEP не подключён (`engine.ts:73-108`)

Fable: «чинить ПЕРЕД T2, они всё равно сериальны с ним (те же файлы) → место в очереди ровно сейчас».
Критик: «эксплуатируемы СЕГОДНЯ, не чинит никто; агентного слоя (ближайшего к цели) в кнопке НЕТ вообще».
→ Вывод лида: это не «фича», это **закрытие разрыва между заявленным дизайном и реальностью кода** —
самая цель-выровненная, владелец-независимая, время-дешёвая работа. И она — пререквизит агентного слоя.

## Несущий вопрос владельцу (гейт ВСЕГО)
**Выбираем следующий трек по ЦЕННОСТИ (→ trust-баги → агентный слой) или по ДОСТУПНОСТИ (→ 4 удобных
параллельных трека)?** Назвать вслух, чтобы не спутать активность с прогрессом.

## Рекомендация лида (синтез обоих)
1. Первый шаг = **trust-баги**, НО не вслепую: сперва 10-мин premise-check (баги реальны? фикс дёшев? —
   самокритика самого Fable), timebox, только потом фикс.
2. НЕ запускать T1a-demo-на-фикстурах / T4-синтетику пока: критик прав про «иллюзию прогресса» + F3/F4
   меняют ПОВЕДЕНИЕ за портом → тихо ломают фикстур-демо на merge.
3. Жёсткая линия PII держится: критик поймал, что фаза СВОИМ релейблом размягчила PII-барьер (циклично) —
   ни одной реальной чувствительной строки без явного F-D. T1b, T5(VETO) — не трогать.
4. T3 (doc-гигиена) — единственный реально независимый дешёвый лейн; но тоже availability-driven,
   держать как филлер, не как «прогресс».

## Самокритика синтеза
- Premise-check багов ещё не сделан — рекомендация условна до него.
- Критик не читал council/raw — часть возражений могла быть снята там (проверить перед фиксацией).
- «Внимание владельца = всё» (модель Fable) может недооценивать его мотивацию демо.

# РАУНД 2 — premise-check подтверждён кодом + вскрытый гейт (2026-08-11)
inputs: PREMISE-CHECK-trust-bugs.analysis.md (builder/opus, по факту кода) · AGENT-LAYER-map.analysis.md (architect/opus)

## Премиса ПОДТВЕРЖДЕНА кодом — все 3 бага реальны
Корень = **F3 (write-PEP не подключён)**: `engine.ts:73-111` `write()` зовёт только `admit()` (PII) +
`admitHome()` + хеш-дедуп → `store.writeAct`. `resolve('write')`/`resolveWrite` НЕ вызывается в пути
записи вообще. Весь control-plane в `resolve.ts` объявлен, но не вклинён в горячий путь.
- **F1 grant-forgery** (`resolve.ts:136-141`): `grantValid` слепо верит `minted_by==='system'` как строке
  в body — ни подписи, ни провенанса. `canMintGrant` есть, но не зовётся. Пишешь grant `allow:['core:*']` → root.
- **F2 policy-overwrite**: защита `canWriteNamespace` живёт ВНУТРИ `resolveWrite` → путь записи её не зовёт;
  во всех фикстурах `protected_namespaces:[]`. Поглощён F3.
- **Зависимости:** F1+F2 правят `resolve.ts` (один write-lock), F3 правит `engine.ts`. Порядок: F3 → (F1+F2 одним проходом). ДВА write-lock, не три.
- **Timebox:** M (~3-5 ч). Контракт/`ports/` — БЕЗОПАСНО (сигнатура `write(act)` не меняется). Поведение — МЕНЯЕТСЯ: фикстуры, пишущие без грантов, упадут на merge → чинить вместе + досыпать авторизующие гранты.

## ВСКРЫТЫЙ ГЕЙТ (несущий) — FORK-U3: идентичность агента как write-principal
Архитектор поймал: если write-PEP гейтит по **самозаявленному** `Act.actor` — это ТОТ ЖЕ класс дыры,
что grant-forgery, на уровень выше. Фикс F3 без ответа на это = театр. Развилка:
- **force-bind** — систему/движок ШТАМПУЕТ actor на границе записи; body-поле actor игнорируется. Минимально-доверяемо, «агент не может назваться другим». (Как шлюз сам ставит thread_id.)
- **attest** — агент заявляет себя + предъявляет пруф (подпись/провенанс), движок верит. Гибче для
  мульти/плагинных агентов, но требует ровно той машинерии подписи, отсутствие которой и есть F1.
- Нюанс: для единственного ДОВЕРЕННОГО демо-агента (`balance-observer.ts`) баги не жмут — гейт про МУЛЬТИ/плагинный слой.

## Рекомендация лида
Гейт FORK-U3 → владельцу ПЕРЕД фиксом. Рек: **force-bind на Стадию-1** (штамп actor на границе, self-declared
игнор), attest — позже, когда реально появятся плагинные агенты, минтящие суб-идентичности. Тогда фикс F3+F1+F2 становится настоящим. Стройка кода — только по «строй» после решения FORK-U3.

## Самокритика раунда-2
- Builder про F3-blast «фикстуры упадут» — оценка, полный прогон тестов не делался.
- Architect «0 call-sites resolve(write)» частично взял из synthesis + сам грепнул; FORK-U3 как hard-block — его утверждение, есть мягкое чтение (attest-default уже сейчас).

# РАУНД 3 — Стадия-1 собрана→эксплойт→дизайн шва (2026-08-11)
inputs: BUILD-trust-plane-stage1.impl.md · REVIEW-trust-plane-stage1.review.md · DESIGN-principal-auth-seam.design.md · ABSTRACTION-recheck-trust-boundary.analysis.md · CRITIC-invariant-and-form.critic.md

## Что случилось
Стадия-1 (F3+F1+F2, force-bind `minted_by`) СОБРАНА (180/180 тестов, порты целы, НЕ коммичено). Независимый
reviewer ЖИВЫМ эксплойтом: подделку лишь перенесли `minted_by`→`actor` (самозаявленное поле). Цель НЕ достигнута.
Владелец: НЕ мерджить, сперва спроектировать шов; перепроверять на общих абстракциях.

## Схождение 2 линз (design-волна)
- **Abstract-thinker (подъём):** это ОДИН баг в 3 масках (`minted_by`/`source_ref`/`actor` = «самозаявленное
  свойство тела, которому верят как авторитету»). Несущая абстракция: **владелец шва штампует принципала; тело — не авторитет.**
  Модель-редуктор = «шлюз ставит thread_id» / «ядро ОС ставит uid». **FORK-U3 растворён:** force-bind vs attest =
  одна форма, разная реализация → ратифицировать ИНВАРИАНТ, не выбор.
- **Architect (форма):** 3 варианта — A канал-траст (дёшево, один шлюз) · B крипто-аттестация (дорого, marketplace=цель) ·
  C принципал-handle. Резерв по Закону ①. ADR-класс.

## Критик — 3 правки ДО ратификации (иначе retrofit-невозможная ошибка)
1. **НЕ ратифицировать «провенанс никогда из тела» — over-claim, ломает Закон ② (монумент).** Развести
   **АВТОРИТЕТ ≠ АТРИБУЦИЯ**: основание прав — никогда из тела; записанная атрибуция (кто сделал; импорт истории) —
   МОЖЕТ быть в теле, но это ДАННЫЕ, не авторитет. Однострочка не должна схлопнуть 2 оси обратно.
2. **`principal_trust` плоский enum схлопывает 2 оси + теряет issuer.** Резервировать доверие ПЕР-ОСЬ
   (кто-действовал vs под-чьим-авторитетом) + идентификатор штампующего (тоже retrofit-невозможно), не плоский 3-enum.
3. **НЕ размораживать подпись `write()` (это преждевременно фиксирует A над B).** Резервировать АДДИТИВНЫЕ поля
   конверта (A/B-совместимо, 0 миграций — доказано `provenance`), подпись не трогать.
- Плюс: channel-trust как enforce-СЕЙЧАС даёт ~ноль сверх force-bind (аутентифицированного принципала сегодня нет: ViewerResolver/M5 не построен; баги шлюза dup/restart подрывают «доверенный канал»).

## Финальная рекомендация лида (на ратификацию владельцу)
- **Ратифицировать ИНВАРИАНТ (исправленный):** движок НИКОГДА не берёт ОСНОВАНИЕ ПРАВ (авторитет) из
  самозаявленного поля тела; записанная АТРИБУЦИЯ в теле допустима как ДАННЫЕ. (Это растворяет FORK-U3 и убивает весь класс из 3 масок.)
- **Зарезервировать СЕЙЧАС (Закон ①, аддитивно, без смены подписи порта):** доверие принципала пер-ось +
  issuer-id + слот делегации (2 оси). Форма A/B-нейтральна.
- **Отложить ПОВЕДЕНИЕ:** enforcement (какой источник — канал A / аттестация B), force-bind самого `actor`,
  верификация — пока не построен аутентифицированный источник принципала (M5/ViewerResolver). НЕ строить channel-theatre.
- **ADR** (смена модели доверия + резерв формы). Стадия-1 остаётся uncommitted как честное частичное ужесточение (мерджить — отдельное решение).

## ОДИН вопрос владельцу (растворяет класс)
**Может ли движок КОГДА-ЛИБО брать ОСНОВАНИЕ ПРАВ из самозаявленного поля тела акта — да/нет?**
(Записанную атрибуцию в теле — можно, это данные.) «Нет» → ратифицируем инвариант + резерв формы → ADR.

## Самокритика раунда-3
- Критик не проверил in-process vs out-of-process агентов (влияет на силу concern про шлюз).
- Импорт внешней истории может быть вне scope сейчас — тогда C1 смягчается до concern, но монумент-атрибуция всё равно всплывёт.
- 3 линзы сошлись на форме, но ни одна не построила её в коде — резерв формы = следующий (мелкий) build-шаг после ратификации.
