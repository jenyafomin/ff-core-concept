# Адвокат ЛИНЗЫ — уровень абстракции НЕ есть несущее поле паспорта

- **Status:** draft
- **Owner:** advocate-lens
- **Date:** 2026-06-21
- **Роль:** Адвокат позиции «Б» в автономном дебате (N-048). Задача — стилмань и довести
  до максимума тезис: *уровень абстракции (почему/что/как/data) — это ОСЬ ЛИНЗЫ (проекция
  подграфа), максимум — опциональный тег-подсказка `level?`, но НЕ обязательное поле ядра.*
- **Контрпозиция, которую я разбиваю:** «без обязательного поля уровня абстракции ИИ вынужден
  вскрывать payload или знать тип → значит это несущее поле» (адвокат-поля, опора аналитика, §3.1).
- **Опора:** RESEARCH-2026-06-21-load-bearing.md §3.1, §5; THREAD N-037, N-042, N-046.

## 0. Тезис в одну фразу

**Уровень абстракции — это не свойство ноды, а ОТНОШЕНИЕ «наблюдатель → нода в подграфе».**
Один и тот же узел одновременно «почему» для одного наблюдателя и «как» для другого — поэтому
записать его В ноду как обязательное поле = зафиксировать ЛОЖЬ для всех наблюдателей, кроме одного.
Правильное место истины — проекция (линза), которая ВЫЧИСЛЯЕТ уровень из позиции узла в подграфе
плюс предиката запроса, **не вскрывая payload и не зная тип** — то есть удовлетворяет тому же
инварианту несущести (§3.1 / N-046), что требует адвокат-поля, но без раздувания ядра.

## 1. Аргумент относительности: уровень = отношение, не атрибут

### 1.1 Формальная позиция

Поле паспорта по определению (инвариант §0 ресёрча, N-046) — это то, по чему ИИ принимает решение
об обращении с ячейкой, **одинаковое для всех наблюдателей** (id один, created один, epistemic один —
они инвариантны к тому, кто смотрит). Уровень абстракции этим свойством НЕ обладает: он
ко-вариантен наблюдателю. Если значение поля меняется в зависимости от того, кто читает ноду, —
это НЕ поле ноды, это функция `level(наблюдатель, нода, подграф)`. Записывать значение функции от
трёх аргументов в один из аргументов — категориальная ошибка.

### 1.2 Конкретные узлы — один узел, разные уровни

Беру реальные типы узлов проекта (субстрат агентов, N-016: задачи, метрики, люди, сообщения, планы).

**Узел A — «Похудеть к лету» (цель/план).**
- Линза CEO-себя (стратегическая): это **«что»** — конкретная цель среди десятка жизненных.
- Линза «зачем я вообще живу так» (выше): это **«как»** — лишь способ достичь «чувствовать себя
  хорошо / нравиться себе» (которое стоит выше).
- Линза дейли-агента (ниже): это **«почему»** — корневая причина, объясняющая, зачем сегодня
  стоит задача «не есть сахар».
→ Один узел = почему / что / как одновременно. Какое значение зашить в `level`? Любое — ложь для
двух наблюдателей из трёх.

**Узел B — сообщение в чате «давай перенесём созвон на 15:00».**
- Линза «исполнение» (агент-календарь): это **«как»** — механика, деталь исполнения.
- Линза «история отношений с человеком X»: это **«что»** — факт-эпизод коммуникации.
- Линза «почему проект буксует» (ретро): это **«почему»** — одно из звеньев причинной цепи срыва.
→ Уровень узла буквально определяется ВОПРОСОМ, который задаёт агент, а не содержимым сообщения.

**Узел C — метрика «вес = 78 кг».**
- Линза «данные»: это `data` — сырое измерение.
- Линза «прогресс к цели»: это **«что»** — точка на траектории.
- Линза «почему мотивация упала»: это **«почему»** — объяснение, триггер.
→ Тот же узел скользит по ВСЕЙ оси почему↔data в зависимости от линзы.

### 1.3 Вывод раздела

«Уровень» — это **ярус узла относительно фокуса наблюдателя в подграфе**, ровно как «высоко/низко»
относительно того, где стоишь. Высота горы — атрибут (несущее). «Это надо мной» — отношение
(производное). Адвокат-поля пытается записать «надо мной» в гору.

## 2. Линза покрывает ВСЕ сценарии адвоката-поля — без обязательного поля

Метод (N-044): не «подходит ли под 3 сценария», а взять сильнейшие сценарии оппонента и показать
покрытие. Адвокат-поля будет махать сценариями, где «ИИ должен знать уровень не вскрывая payload».
Ниже — как линза вычисляет уровень из **позиции в графе + предиката**, удовлетворяя ровно тому же
инварианту.

### 2.1 Механизм: откуда линза берёт уровень БЕЗ payload и БЕЗ типа

Уровень узла для запроса = его **глубина/ярус в проекции подграфа относительно якоря линзы**. Это
чисто структурная величина: считается по рёбрам (`home`/каскад/`refines`/`grounds`), которые и так
несущие и видны движку (§1 ресёрча: связи на ребре, обход — движок). Движку НЕ нужно открывать
payload и НЕ нужно знать тип, чтобы сказать «этот узел на 2 яруса выше якоря по оси refines» —
ему достаточно топологии. Это ТОЧНО тот же инвариант, что защищает паспортные поля (N-046:
«обращаться с ячейкой, не вскрывая payload и не зная тип»). Значит линза НЕ нарушает инвариант —
она его выполняет ДРУГИМ носителем (топология вместо поля).

> Ключевой удар по контрпозиции: «без поля ИИ вскрывает payload» — ЛОЖНАЯ дихотомия. Есть третий
> источник уровня, который не payload и не тип: **позиция в подграфе + предикат линзы**. Адвокат-поля
> молча предполагает, что уровень можно узнать только (а) из поля или (б) вскрыв payload. Топология —
> опровергающий контрпример.

### 2.2 Сценарий «отфильтруй только „почему“ для брифинга CEO»

- *Поле:* `WHERE level = 'why'`.
- *Линза:* предикат проекции `корневые-узлы(якорь, ось=refines/grounds, depth≤k)` — берёт узлы, у
  которых нет родителя-объяснения внутри проекции. Уровень = вычислен из позиции. Тот же результат,
  и он КОНТЕКСТЕН (для другого якоря «почему» будут другие узлы — а поле дало бы те же, то есть
  неверные).

### 2.3 Сценарий «не утони в деталях — покажи верхний уровень большого чата»

- *Поле:* `WHERE level IN ('why','what')`.
- *Линза:* это в точности «зум огромных секций» (N-043, §5: ЛИНЗА = зум секций). Проекция отдаёт
  `section-index`-узлы / заголовки, скрывая листья. Уровень = ярус в дереве секций, не поле.
  Бонус: поле бы пришлось проставить вручную на МИЛЛИОНЕ сообщений чата (N-043) — линза считает
  ярус из структуры бесплатно.

### 2.4 Сценарий «агент-стратег не должен видеть „как“-детали (перцептивный угол)»

- *Поле:* фильтр по `level`.
- *Линза:* это N-037 дословно — «угол обзора, за который агент не выходит без пропуска». Это
  сохранённая линза-узел control-plane (§3.3 ресёрча, единогласно: вектор = линза-узел, не поле).
  Поле тут вообще не при чём — это политика проекции, а не атрибут данных.

### 2.5 Сценарий «смешанная выдача — пометь каждому его уровень»

Самый сильный у адвоката-поля: «мне нужна МЕТКА на каждом узле в ответе». Покрытие: линза при
проекции **аннотирует** каждый узел вычисленным `projected_level` в виде эфемерной метки ответа
(как движок проставляет `stale`, `derived` — §1: производное-в-ответе). Узел получает уровень —
но как СВОЙСТВО ПРОЕКЦИИ, не записанное в файл-истину. Для другой линзы метка другая. Это и есть
корректная семантика: метка живёт там, где живёт её смысл — в отношении.

### 2.6 Опровержение «линза не спасает» (предвосхищение)

Адвокат-поля скажет: «линза дороже — каждый запрос считает топологию; поле = O(1) индекс». Ответ:
1. Уровень-из-топологии и так нужен движку для зума/каскада/maxDepth (§4 блокеры) — это не новая
   стоимость, это та же машина проекций, амортизированная.
2. Где нужна скорость — линза МАТЕРИАЛИЗУЕТ свой результат (кэш проекции = производное ребро,
   как авто-связи `derived:true`, §1). Это инженерная оптимизация линзы, а НЕ возврат поля в ядро.
3. Поле, наоборот, НЕ спасает в главном сценарии (контекстность): один индекс по `level` даёт
   ОДИН ответ всем наблюдателям — то есть в мульти-наблюдательной системе (а проект именно такой:
   N-037 перцептивные углы, N-016 много агентов) поле системно неверно, а не просто медленно.

→ «Линза не спасает» опровергнуто: линза покрывает все 5 классов сценариев тем же инвариантом,
а в контекстных сценариях — единственная, кто даёт ПРАВИЛЬНЫЙ ответ.

## 3. Минимум, который реально нужен на ноде: опциональный тег `level?`

Честно признаю: есть остаточный случай, где топологии недостаточно — **автор хочет ЗАЯВИТЬ
намерение узла** независимо от структуры. Пример: заметка написана как «принцип» (намеренно «почему»),
но ещё не вплетена в граф — рёбер нет, топология молчит. Тут полезна подсказка.

**Решение: опциональный `level?` как ТЕГ-ПОДСКАЗКА, не несущее ядро.**

| Свойство | Несущее поле паспорта | Тег-подсказка `level?` |
|---|---|---|
| Обязательность | каждая нода ОБЯЗАНА иметь | опционально; чаще пусто |
| Дефолт | нет дефолта (иначе мусор) | от типа (`principle→why`, `metric→data`) или пусто |
| Кто истина | поле = истина об уровне | **проекция = истина; тег лишь ПРИОР/подсказка линзе** |
| При конфликте с топологией | поле побеждает (и врёт) | топология/линза побеждает; тег — слабый приор |
| Инвариант обращения | ИИ обязан читать, чтобы обращаться | ИИ может игнорировать; обращение строит линза |
| Множит ли наблюдателей | нет (один уровень всем) | да (линза переопределяет под наблюдателя) |

**Граница чёткая:** поле несущее ⟺ движок/ИИ ОБЯЗАН по нему действовать, не вскрывая payload, и
оно одинаково для всех. `level?` это правило НАРУШАЕТ по двум пунктам (необязательно + не одинаково
для всех → линза переопределяет), следовательно по инварианту N-046 это НЕ несущее поле. Это
опциональная аннотация-приор, ровно в категории «теги» N-042(б) («к чему относится» — для группировки),
а не в категории идентичности/времени/доверия.

Аналогия: `level?` относится к линзе как `lang` метаданные относятся к поиску — поиск работает и
без них, но если автор подсказал язык, ранжирование точнее. Никто не делает `lang` несущим ядром
документа.

## 4. Честный риск моей позиции

Где линза реально ДОРОЖЕ/СЛОЖНЕЕ поля — называю прямо, без смягчения:

1. **Холодный старт и пустой граф.** Пока рёбер мало, топология бедна → линза не может вычислить
   уровень, и система опирается только на слабый `level?`/дефолт-от-типа. В ранней жизни узла
   поле дало бы более стабильный ответ. (Митигация: дефолт-от-типа + тег покрывают ранний этап;
   с ростом графа линза берёт верх. Но окно слабости реально.)
2. **Стоимость и сложность движка.** Линза требует работающего движка проекций с обходом,
   maxDepth, кэшем (§4 блокеры). Это БОЛЬШЕ кода до первого полезного результата, чем `WHERE level=`.
   Поле можно зафильтровать наивным индексом в день один; линза — нет.
3. **Объяснимость для человека.** «Почему этот узел показан как „почему“?» — для поля ответ
   тривиален (так записано). Для линзы — «потому что в этой проекции он на верхнем ярусе оси
   refines», что сложнее объяснить пользователю (хотя N-040 требует «контролируемой, объяснимой
   системы» — линзе придётся уметь объяснять свою проекцию).
4. **Риск недоопределённой линзы.** Если предикаты линз спроектированы плохо, уровень будет
   «прыгать» непредсказуемо между запросами — хуже, чем стабильное (пусть и неточное) поле.

### Почему чистота ядра всё равно перевешивает (просьба владельца)

- **N-040 (философия ячейки):** «ячейка ПРОСТАЯ, простота даёт МНОГО возможностей; минимум нужного,
  но гибкий». Обязательное `level` — это параметр, который НЕ строит фундамент (по нему нельзя
  однозначно обращаться с ячейкой — см. §1), но раздувает ядро и плодит мусорные/непоследовательные
  значения (прямой прогноз §3.1: «будет заполняться непоследовательно»). Это анти-N-040.
- **§5 рычаг:** уровень абстракции — одна из ПЯТИ вещей (вектор/уровень/авто-связи/зум/паттерны),
  которые оказались ОДНИМ механизмом ЛИНЗЫ. Вытащить уровень обратно в поле = расщепить единый
  рычаг на «4 в линзе + 1 в поле», вернуть ту самую фрагментацию «пять подсистем», от которой §5
  ушёл. Концептуальная цена несоразмерна.
- **Множитель наблюдателей:** проект по построению мульти-наблюдательный (N-037 перцептивные углы;
  N-016 много агентов). Любое обязательное поле, ко-вариантное наблюдателю, — системная ложь,
  масштабируемая на весь граф. Окна слабости линзы (холодный старт) — локальны и временны;
  ложь поля — глобальна и постоянна.
- **Обратимость:** начать без поля и добавить `level?`-тег позже (или даже промотировать его, если
  практика докажет) — дёшево и безопасно. Начать с обязательного поля и потом ВЫНУТЬ его из ядра —
  ломает все ноды и все запросы (миграция миллионов узлов). По асимметрии риска (R0/обратимость,
  rules/evolution) дефолт — НЕ класть в ядро.

## 5. Вердикт-рекомендация

- **Уровень абстракции = ось ЛИНЗЫ** (проекция подграфа из топологии + предиката). Истина об уровне
  живёт в проекции, не в ноде. Это удовлетворяет инварианту несущести (§3.1/N-046) без поля.
- **Обязательное поле `level` в паспорте — НЕТ.** Оно ко-вариантно наблюдателю → категориальная
  ошибка + анти-N-040 + расщепляет рычаг §5.
- **Опциональный тег `level?` — ДА, как слабый приор/подсказка линзе** (дефолт от типа), строго в
  классе «теги/аннотации» N-042(б), с явным правилом «при конфликте линза/топология побеждает».
  Чёткая граница: подсказка ≠ несущее (необязательна + переопределяема + не одинакова для всех).
- **Честная слабость:** холодный старт пустого графа и более высокая инженерная стоимость движка
  проекций до первого результата. Перевешивается мульти-наблюдательной природой системы, единством
  рычага §5, философией простой ячейки (N-040) и асимметрией обратимости.
- **Следующий шаг:** зафиксировать `level` как ось control-plane-ЛИНЗЫ (рядом с вектором/зумом/
  паттернами, §5), добавить опциональный `level?`-тег в спецификацию тегов (не в ядро паспорта),
  и передать архитектору на оформление контракта проекции (viewport) — отдельно от паспорта (§3.3:
  два документа — оси-фильтрации в паспорте vs контракт запроса с viewport в движке).
