# Interaction-дизайн вьюера: ходить по agent-first графу с клавиатуры, редактировать под клапаном

> Фаза = DESIGN. Это спецификация ВЗАИМОДЕЙСТВИЯ и информационной архитектуры, не реализация.
> Принцип каждого решения: **паспорт тонкий и читается без вскрытия payload → список/граф рендерим из паспорта,
> payload открываем лениво**. Это и есть наш рычаг против «толстого узла» конкурента.

---

## 0. Несущие принципы вьюера (откуда всё выводится)

1. **Passport-drives-the-view.** Любой узел в списке/графе/палитре рисуется из ~9 полей паспорта (`id·type·schema·
   created·updated·epistemic·sensitivity·source·principal` + опц. `level?`). Payload НЕ читается, пока человек явно не
   откроет узел (Enter / O). Это даёт мгновенный рендер тысяч узлов и прямо эксплуатирует тонкий паспорт.
2. **Edges-are-the-terrain.** Человек не «листает файлы» — он ХОДИТ ПО РЁБРАМ. Две оси ходьбы: **вдоль home-спины**
   (вверх/вниз по лесу принадлежности — это «где я в жизни») и **вдоль facet-of** (вбок по измерениям — «тот же узел
   с другой стороны»). Это прямой ответ на слабость конкурента (стрелки заняты турами → по графу клавишами не пройти).
3. **Lens-is-a-view, not a filter toggle.** Линза = узел control-plane. Переключение линзы — это смена ПРОЕКЦИИ:
   какие рёбра видны, какая глубина, какие поля паспорта показаны, как считается `projected_level`. Линза
   пользовательская (можно добавить свою), поэтому переключатель линз — first-class, не хардкод (в отличие от
   persona-view конкурента).
4. **Valve-bounded editing.** Создание/правка/связывание узлов с клавиатуры — наш дифференциатор против read-only
   конкурента. Но граница СВОБОДНО / ПОД-КЛАПАНОМ строго следует ADR-0002: свободно — всё внутреннее и обратимое;
   клапан — только внешнее необратимое (+ повышение epistemic→fact, которое автор не делает сам).
5. **Single source of truth для шорткатов.** Один массив `{key, category, description, action, context}` → из него
   генерится И раскладка биндингов, И модалка справки `?`. Глушим ввод в полях, кроме Escape (паттерн конкурента,
   осознанно заимствован). Кросс-платформа: рендерим ⌘ на macOS / Ctrl на остальных из одной декларации `mod`.

## 1. Модель навигации (как человек ходит по графу)

### 1.1. Фокус и две оси ходьбы

В каждый момент есть **ровно один сфокусированный узел** (focus node). Вокруг него — две независимые оси движения:

```
                 [home-родитель]            ← k  (вверх по спине принадлежности)
                       │ home
   facet ─ [сосед-фасет] ─ [ФОКУС] ─ [сосед-фасет] ─ facet     ← h / l  (вбок по facet-of)
                       │ home
              [home-дети: d1, d2, d3...]     → j  (вниз по спине; j/k циклят между сиблингами-детьми)
```

- **k** — подняться к home-родителю (ровно один, спина ациклична → детерминированно).
- **j** — спуститься к home-детям. Среди детей j/k (или ↓/↑) листают сиблингов; **Enter / l** проваливается в
  выбранного ребёнка (делает его фокусом).
- **h / l** — шаг ВБОК по facet-of рёбрам (другие измерения того же сюжета): h — предыдущий фасет, l — следующий.
  Это «тот же узел под другим углом», не смена принадлежности.
- **Стрелки** дублируют hjkl (↑=k, ↓=j, ←=h, →=l) — но в отличие от конкурента стрелки НЕ заняты турами, ходьба по
  графу первична.

Почему две раздельные оси, а не одна «соседи»: home — это **позвоночник** (где узел живёт, спина каскада), facet —
это **рёбра-измерения** (тот же предмет с другой грани). Смешать их в один список соседей = потерять главное различие
модели (ADR-0002: «дом» ≠ «фасет»). Раздельные клавиши делают это различие тактильным.

### 1.2. Хлебные крошки = home-спина

Поскольку у каждого узла ровно один home-родитель, путь от корня до фокуса **уникален и ацикличен** → идеальные
breadcrumbs без неоднозначности:

```
🏠 Жизнь ▸ Здоровье ▸ Сон ▸ [Эпизод: бессонница 2026-06-20]      (g h = прыжок в любую крошку)
```

- Крошки кликабельны и адресуемы клавишей: `g` затем цифра/буква крошки → прыжок на этот уровень спины.
- `g g` — в корень home-леса; `g i` — в inbox (системный home для re-home сирот, ADR-0002 §2).
- Боковые (facet) переходы НЕ меняют хлебные крошки спины — они показываются отдельной строкой «фасеты фокуса».

### 1.3. Прыжки по типу / линзе (не только ходьба)

Ходьба хороша локально. Для дальних перемещений — прыжки по ОСЯМ паспорта (они несущие, видны без payload):

- `t` — «показать все узлы type X» (фильтр-список по `type`).
- `f` — отфильтровать текущий вид по оси паспорта (epistemic / sensitivity / source / level?). Это фильтр ВНУТРИ
  линзы, не смена линзы.
- `Cmd+K` — командная палитра: прыжок к ЛЮБОМУ узлу/типу/линзе/паттерну по имени (см. §2).

### 1.4. Состояния и режимы вьюера (state machine)

Вьюер — конечный автомат с горизонтальными РЕЖИМАМИ и вертикальным стеком OVERLAY. Escape всегда снимает верхний
слой (Escape-каскад конкурента, заимствован):

```
            ┌──────────────────────────────────────────────────────────────┐
            │                      ВИД (один из трёх)                        │
            │   LIST  ⇄(v)  GRAPH  ⇄(v)  FOCUS(один узел + панель паспорта)  │
            └──────────────────────────────────────────────────────────────┘
                   ▲ Esc                                   │ open overlay
                   │ (закрыть верхний overlay / снять выделение / выйти из edit)
            ┌──────┴───────────────── OVERLAY-стек (LIFO) ──────────────────┐
            │  PALETTE (Cmd+K)  │  HELP (?)  │  PAYLOAD (Enter/O)            │
            │  LENS-SWITCH (L)  │  SEARCH (/) │  EDIT-INLINE (e)             │
            │  CONFIRM/VALVE (при внешнем необратимом действии)             │
            └───────────────────────────────────────────────────────────────┘

Переходы фокуса (в любом виде, когда нет overlay и фокус не в input):
  k / ↑ → home-parent          j / ↓ → home-child (листание сиблингов)
  h / ← → prev facet            l / → → next facet / drill-in
  Enter / O → открыть PAYLOAD overlay (ленивое чтение содержимого)
  g … → прыжок по home-спине / корень / inbox

Escape-каскад (приоритет сверху вниз):
  есть открытый overlay   → закрыть верхний overlay
  иначе есть выделение/мультивыбор → снять выделение
  иначе FOCUS-вид         → вернуться в LIST/GRAPH (родительский вид)
  иначе                   → no-op (корень навигации)
```

Инвариант фокуса: при любом переходе вида (`v`) фокусный узел СОХРАНЯЕТСЯ (переключили линзу/вид — фокус тот же,
меняется только проекция вокруг него). Это «не теряю место» — критично для доверия к навигации.

## 2. Командная палитра (Cmd+K) — таксономия команд

Палитра = единая точка «сделать что угодно по имени». Делится на разделы по ПРЕФИКСУ ввода (как в Linear/Raycast):
пустой ввод = недавнее + предложения; префикс сужает домен.

| Префикс | Домен | Что делает | Пример |
|---------|-------|-----------|--------|
| (нет)   | Узлы  | Fuzzy/semantic поиск по узлам, прыжок к узлу | `бессонница` → фокус на узел |
| `>`     | Действия (commands) | Запустить команду вьюера или агента | `>переключить линзу`, `>создать узел` |
| `@`     | Тип   | Прыжок к списку узлов типа / к узлу-ТИПу control-plane | `@task`, `@metric` |
| `#`     | Линза | Переключить активную линзу (lens=узел, в т.ч. свои) | `#power`, `#planner` |
| `~`     | Паттерн | Применить паттерн-сборку подграфа | `~today`, `~retro-week` |
| `!`     | Агент | Поставить агенту задачу над фокусом/выделением | `!суммируй ветку`, `!найди дубли` |
| `+`     | Создать | Создать узел заданного типа (под home-родителем = фокус) | `+task под фокусом` |

**Двухрежимный поиск (заимствовано у конкурента, усилено):** в домене «Узлы» — Fuzzy (по строкам паспорта: имя/тип/
теги, мгновенно, BM25/FTS) и Semantic (по смыслу). Per SYNTHESIS §3: semantic на старте = агент-запрос к графу, НЕ
vector store; векторы — derived-индекс позже, только на доказанной боли. Переключение режима — `Tab` внутри палитры.

**Таксономия команд (`>` домен), сгруппирована = категории шортката (см. §5):**

- **Navigation:** go-to-root, go-to-inbox, go-to-node-by-id, focus-home-parent/child, next/prev-facet.
- **View/Lens:** switch-lens, cycle-view (list/graph/focus), expand-depth, collapse-depth, show-facets,
  toggle-passport-panel.
- **Edit (свободные):** create-node, rename, edit-payload, set-epistemic (кроме →fact), link-edge (facet/cascade),
  set-home (re-home), tag, set-sensitivity, archive (epistemic→archived = обратимо).
- **Edit (под клапаном):** promote→fact (требует не-автора), delete-permanently, любой external connector send.
- **Agent:** run-agent-on-focus, summarize-branch, find-duplicates, propose-links, consolidate (sleeptime-уборка),
  explain-this-node (почему агент так обращается с узлом — читает паспорт).

Палитра ВСЕГДА показывает рядом с действием его эпистемический/клапанный статус значком: ⚪ свободно · 🔒 под клапаном.
Человек видит границу ещё ДО запуска.

## 3. LENS как first-class переключатель вида

Линза — узел control-plane (ADR-0002 §2б): `{ predicate, disclosure_policy, class: hard-ABAC | soft }`. Во вьюере она
управляет ЧЕТЫРЬМЯ регуляторами одновременно (потому и «вид», а не «галочка-фильтр»):

| Регулятор линзы | Что меняет в рендере |
|-----------------|----------------------|
| **Какие рёбра видны** | напр. линза «планировщик» показывает home+cascade и priority; линза «исследователь» — facet-of+grounds/refines |
| **Глубина проекции** | сколько хопов от фокуса разворачивать (maxDepth проекции) |
| **Какие поля паспорта в карточке** | планировщик: priority+due; аудитор: epistemic+source+principal; читатель: только имя+level? |
| **`projected_level`** | линза вычисляет уровень узла из топологии (ADR-0002 §1) и красит/группирует по why/what/how/data |

Переключение: `L` (overlay со списком линз) или `#имя` в палитре. Цифры `1..9` — быстрые слоты любимых линз
(пользовательски назначаемые, т.к. lens=узел). Активная линза всегда видна в статус-баре: `Линза: #planner`.

**hard-ABAC линза (класс политики):** если линза несёт hard-ABAC (раскрытие/доступ), она не просто «прячет поля» —
движок ФИЗИЧЕСКИ не отдаёт payload/поля, к которым нет права по sensitivity+principal. То есть переключение на такую
линзу = смена не только вида, но и реально доступных данных (enforce на движке, не на клиенте). Это и есть «клапан
доступа» как класс линзы, а не отдельный род.

Инвариант: смена линзы НЕ двигает фокус и НЕ меняет данные на диске — только проекцию. Откатываемо мгновенно.

## 4. Редактирование под клапаном (наш дифференциатор)

Граница ровно по ADR-0002: **свободно = внутреннее обратимое; клапан = внешнее необратимое + epistemic→fact.**

### 4.1. Карта операций редактирования

| Операция | Клавиша/команда | Статус | Почему |
|----------|-----------------|--------|--------|
| Создать узел | `n` / `+type` | ⚪ свободно | внутренний, обратимый (можно archive/delete-as-draft) |
| Переименовать / правка payload | `e` (inline) / `>edit-payload` | ⚪ свободно | внутренний; история версий = обратимость |
| Связать ребром facet-of / cascade | `c` (connect-mode) | ⚪ свободно | внутренняя топология; ребро гасится, не теряется |
| Re-home (сменить home-родителя) | `>set-home` | ⚪ свободно* | внутренний, НО движок проверяет инвариант «ровно один home» и ацикличность; отклонит цикл |
| set-epistemic: draft→proposal→hypothesis | `s` | ⚪ свободно | first-party ход по лестнице; обратимо вниз |
| **epistemic → fact** | `>promote-fact` | 🔒 **клапан** | ADR-0002 §3: автор НЕ повышает себя; нужен человек/verifier ≠ автор |
| set-sensitivity повысить (private→secret) | `>set-sensitivity` | ⚪ свободно | внутреннее ужесточение безопасно |
| set-sensitivity понизить (secret→public) | `>set-sensitivity↓` | 🔒 **клапан** | раскрытие = риск утечки; проверка disclosure-policy |
| Archive (epistemic→archived) | `>archive` | ⚪ свободно | терминально-но-обратимо (узел остаётся виден ИИ) |
| **Delete-permanently** | `>delete` | 🔒 **клапан** | необратимо; «ничего не стирается» — удаление = исключение |
| **External send** (telegram/почта/оплата) через CONNECTOR-узел | `!`/`>send` | 🔒 **клапан** | внешнее необратимое — каноничный случай клапана |

\* re-home «свободно» в смысле клапана, но НЕ без правил: движок-валидатор инварианта (один home, ацикличность,
re-home сирот, ADR-0002 §2) — это integrity-check, не клапан внешнего действия. Если правило типа требует — может
заблокировать (вариант (в) re-home).

### 4.2. Что показывает клапан-overlay (CONFIRM/VALVE state)

Когда действие 🔒, вьюер открывает CONFIRM-overlay, который рендерит результат движковой проверки клапана
(ADR-0002 §3, граница v1 = только ПРЯМО задействованные ноды):

```
🔒 КЛАПАН: отправить «сводка недели» в Telegram (внешнее, необратимое)
Прямо задействованные узлы (граница v1):
  • [summary-2026-06-24]  epistemic: proposal  ❌ не fact
  • [metric: сон]         epistemic: fact       ✅
Решение движка: ЗАКРЫТО (есть не-fact узел).  sensitivity: ok · principal: ok
[A] эскалировать владельцу   [O] override (залогируется трейс-узлом)   [Esc] отмена
```

Ключ: вьюер НЕ решает клапан сам — он ВИЗУАЛИЗИРУЕТ вердикт движка и предлагает разрешённые движком ходы
(escalate / override-с-логом). Дефолт-закрыто сохраняется. Это держит «всё видно, ИИ не ограничен, видно что он
делает»: человек видит ровно те узлы, из-за которых клапан закрыт.

### 4.3. Inline-edit и глушение
Режим `e` открывает inline-редактор payload/полей. Пока курсор в input — все навигационные шорткаты ГЛУШАТСЯ
(паттерн конкурента), КРОМЕ Escape (выйти из edit) и `mod+Enter` (сохранить). Это единственное исключение из
suppress-in-inputs.

## 5. Архитектура системы шорткатов + полная карта

### 5.1. Один источник истины
```
type Shortcut = {
  key: string            // "j", "mod+k", "g g"  (chord через пробел)
  category: 'General'|'Navigation'|'Lens'|'Edit'|'Agent'
  description: string    // в модалку ? И в палитру (>)
  action: ActionId       // та же ActionId, что и в командной палитре — ЕДИНЫЙ реестр
  context?: 'global'|'list'|'graph'|'focus'|'input-exempt'
  valve?: 'free'|'valve' // ⚪/🔒 — рисуется значком в справке и палитре
}
```
Из ОДНОГО массива генерится: (1) keymap-биндинги, (2) модалка `?`, (3) подписи в палитре, (4) значки клапана.
Реестр `ActionId` общий для шортката и палитры → нет дрейфа «клавиша делает одно, палитра другое».

Правила: `mod` рендерится ⌘ на macOS / Ctrl иначе. В input глушим всё, кроме `Escape` и `mod+Enter`
(`context: input-exempt`). Аккорды (`g g`, `g h`) — таймаут 800мс.

### 5.2. Полная предлагаемая карта шорткатов

**General**
| Клавиша | Действие | Клапан |
|---------|----------|--------|
| `?` | Открыть справку (из массива шорткатов) | ⚪ |
| `mod+k` | Командная палитра | ⚪ |
| `/` | Фокус поиска (Fuzzy/Semantic, Tab — переключить) | ⚪ |
| `Esc` | Каскад: закрыть overlay → снять выделение → выйти из FOCUS | ⚪ |
| `v` | Циклить вид LIST → GRAPH → FOCUS | ⚪ |
| `.` | Повторить последнее действие | зависит |

**Navigation**
| Клавиша | Действие | Клапан |
|---------|----------|--------|
| `j` / `↓` | home-ребёнок / след. сиблинг | ⚪ |
| `k` / `↑` | home-родитель / пред. сиблинг | ⚪ |
| `h` / `←` | предыдущий facet | ⚪ |
| `l` / `→` | следующий facet / провалиться | ⚪ |
| `Enter` / `o` | открыть PAYLOAD фокуса (ленивое чтение) | ⚪ |
| `g g` | в корень home-леса | ⚪ |
| `g i` | в inbox | ⚪ |
| `g h` | прыжок по хлебной крошке спины | ⚪ |
| `t` | список узлов типа фокуса | ⚪ |
| `f` | фильтр по оси паспорта (epistemic/sensitivity/source/level) | ⚪ |
| `[` / `]` | пред./след. узел в текущем отфильтрованном списке | ⚪ |

**Lens**
| Клавиша | Действие | Клапан |
|---------|----------|--------|
| `L` | Открыть переключатель линз (overlay) | ⚪ |
| `1`..`9` | Быстрый слот линзы (пользовательский) | ⚪ |
| `+` / `-` | Увеличить / уменьшить глубину проекции | ⚪ |
| `p` | Тоггл панели паспорта (показать все ~9 полей) | ⚪ |
| `x` | Показать/скрыть facet-рёбра в графе | ⚪ |

**Edit**
| Клавиша | Действие | Клапан |
|---------|----------|--------|
| `n` | Создать узел (home-родитель = фокус) | ⚪ |
| `e` | Inline-редактор payload/полей | ⚪ |
| `c` | Connect-mode: протянуть ребро facet/cascade | ⚪ |
| `s` | Поднять epistemic (draft→proposal→hypothesis) | ⚪ |
| `S` | Понизить epistemic | ⚪ |
| `mod+s` | Сохранить (в input — единственный не-Esc выход) | ⚪ |
| `mod+shift+f` | promote → fact | 🔒 |
| `mod+backspace` | delete-permanently | 🔒 |

**Agent**
| Клавиша | Действие | Клапан |
|---------|----------|--------|
| `a` | Запустить агента над фокусом/выделением (палитра `!`) | зависит от действия агента |
| `A` | Суммировать home-ветку фокуса | ⚪ (читает) |
| `mod+enter` (в CONFIRM) | подтвердить разрешённый движком ход | 🔒 |
| `>send` | Внешняя отправка через CONNECTOR | 🔒 |

Конфликты разрешены осознанно: `+`/`-` = глубина (Lens) только вне палитры; в палитре `+` = «создать» (другой
контекст ввода → не конфликт). `s`/`S` = epistemic (shift = вниз). Стрелки = ходьба (НЕ туры — отличие от конкурента).

## 6. Что рендерим из паспорта vs из payload

| Слой | Источник | Когда читается | Содержит |
|------|----------|----------------|----------|
| **Список / граф / палитра / крошки** | ТОЛЬКО паспорт (~9 полей + `level?`) | всегда, мгновенно | id, type, имя (из паспорта/schema), epistemic-значок, sensitivity-значок, projected_level (от линзы), home-позиция |
| **Карточка узла (превью в фокусе)** | паспорт + дешёвый rollup движка (напр. кол-во детей, последний трейс) | при фокусе | поля паспорта по выбору линзы + счётчики рёбер |
| **PAYLOAD overlay** | payload файла | ТОЛЬКО по Enter/O (ленивое) | полное содержимое узла |

Это прямой контрапункт «толстому узлу» конкурента (всё в одном JSON, нельзя прочесть метаданные без парса всего):
у нас паспорт-в-frontmatter читается без открытия payload → список из 10k узлов рисуется по паспортам, payload
открывается по одному. Эпистемический/sensitivity статус виден ВСЕГДА (значки), не требуя чтения содержимого —
ровно «всё видно ИИ и человеку; статус = метка, не стена».

## 7. Открытые вопросы владельцу

1. **GRAPH-вид на старте — нужен ли вообще, или LIST+FOCUS достаточно для v1?** Граф красив, но agent-first работа
   часто = «список под линзой + фокус». Граф-канвас (React Flow и т.п.) — большой объём. Предложение: v1 = LIST+FOCUS
   с клавиатурной ходьбой; GRAPH — позже. (Связь: развилка №4 SYNTHESIS.)
2. **`weight(0..1)` на ребре (развилка №3 SYNTHESIS):** если примем — facet/cascade-ходьба может СОРТИРОВАТЬ соседей
   по weight (сильные связи первыми при j/k/h/l). Без weight — порядок по cascade_order/id. Принимаем weight?
3. **Семантический поиск в палитре на старте = агент-запрос (не вектор), per SYNTHESIS §3 — подтверждаем?** Векторы
   откладываем до доказанной боли; палитра пока Fuzzy(FTS)+«спросить агента».
4. **Многовыбор и bulk-действия:** нужен ли v1 множественный выбор (Space-mark) для пакетных агент-действий
   (`!суммируй выбранные`)? Это умножает поверхность клапана (bulk external send). Предлагаю отложить.
5. **Override клапана — кто имеет право?** В §4.2 override логируется трейс-узлом, но КТО может его нажать —
   только владелец-человек, или делегируемо доверенному агенту? Это вход в ADR-0003 (trust horizon), не решаем тут.
6. **`projected_level` как раскраска/группировка:** красить узлы по why/what/how/data всегда, или только в линзах,
   которые это просят? (Цвет — дорогой когнитивный канал, не тратить зря.)
7. **Re-home жестом:** делать ли drag-style «перевесить home» с клавиатуры (вырезать узел `X` → встать на нового
   родителя → `mod+v` «вставить как home-ребёнка»)? Удобно, но легко случайно перестроить спину. Нужен ли undo-стек
   именно для топологии отдельно от payload-undo?

## 8. Чем мы бьём конкурента (сводка дифференциаторов)

| Их слабость (understand-anything) | Наше решение |
|-----------------------------------|--------------|
| Стрелки заняты турами → по графу клавишами не пройти, только мышь | hjkl+стрелки = ходьба по home/facet рёбрам; туры не первичны |
| Всё read-only, агенты только строят | Создание/правка/связывание с клавиш ПОД КЛАПАНОМ |
| Нет Cmd+K палитры | Cmd+K с таксономией доменов (узлы/действия/тип/линза/паттерн/агент/создать) |
| Persona-view захардкожен | LENS=узел, пользовательский, слоты 1..9, 4 регулятора проекции |
| Толстый узел в одном JSON | Паспорт-в-frontmatter → список из паспортов, payload лениво |
| Нет epistemic/sensitivity/principal | Значки статуса ВСЕГДА видны; клапан-overlay показывает вердикт движка |

Заимствуем осознанно: `/`+`?`+Escape-каскад, один-массив-шорткатов→биндинги+справка, suppress-in-inputs-кроме-Esc,
⌘/Ctrl кросс-платформа, двухрежимный поиск (но semantic=агент, не вектор).
