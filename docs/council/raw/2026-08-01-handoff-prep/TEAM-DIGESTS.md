# Handoff-prep: 3 свежих контекста (для пересборки хэндоффа)

Владелец (08-01) попросил «взять команду, переобдумать запрос в НЕ моём контексте, найти что упустили».
Ниже — тугие дайджесты трёх агентов (value / gaps / new-seeds-map). Полные транскрипты — в journal сессии.

## A. Ценностная карта (business-analyst)

**5 корневых ценностей (ранжировано):**
- **Ц1 · Непрерывность памяти (P0)** — не забывает/не путается; граф достоверен, файл не единственный источник. Модуль: **durable StorePort (S7)** — сегодня граф RAM-only → «граф=истина» пока бумажный.
- **Ц2 · Доверенное делегирование (P0/P1)** — область видимости/права едут с агентом, не переписываются на проект. policy-as-data (global+project), actor=ось. Частично построено (capability 15/15, growth 0 правок движка).
- **Ц3 · Безопасный эксперимент/само-улучшение (P1)** — «GitHub для агентов»: идея=ветка-гипотеза, merge=принять, reject=не терять, аудит решений. Модуль: branch-as-label (поверх S7); as-of отложен D-5.
- **Ц4 · Дешёвое расширение без инженерного взрыва (P1)** — «n8n-тулкит»: новый «клиент» = настройка 4 примитивов + policy, не новый код. Тип=данные (`.doc-types.json`). Sync-адаптер заблокирован S7.
- **Ц5 · Растущая структура без потери управляемости (P2)** — цели-в-целях, пересборка веток, новые слои абстракции; стадия=вычисляемая линза. doc-tree lint (soft).

**Наивысшая ценность следующим ходом:** закрыть **S7 (durable StorePort)** — разом переводит Ц1/Ц3/Ц4 из «обещание» в «в руках».

**В руках:** 4-примитивная модель (I-1..14, capability 15/15, growth 0 правок); `@ff/engine` 44/44 + первый write-back цикл (P1 rental-balance); policy-as-data (`.doc-types.json`, admission fail-closed на PII); ADR-0008 approved+подтверждён кодом; doc-tree+lint.
**Обещание (далеко):** персистентность (S7); acts-as-git целиком (0 кода, as-of отложен); job-sync/кэш/«клиент»-тип (заблок. S7); само-апгрейд (нет enforcement, дрейф ДОКАЗАН — state-01 не тронут с 07-21); динамическая пересборка абстракций (сейчас только ручная); мультиклиент/n8n (не прогнан на 2-м инстансе кроме ga-rentacar).

## B. Пробелы — что упустили (critic, ранжировано)

1. 🔴 **Папки-в-папках / динамическая пересборка дерева** — НЕ разобрана ни одним потоком + КОНФЛИКТ с doc-tree.md (стабильные узлы, переезды вручную). Двусмысленность: это про `docs/`-дерево или про граф данных? → спросить владельца ПЕРВЫМ.
2. 🔴 **Само-апгрейд системы** — не сверен с иммутабельностью Конституции / KQ-3 (само-референция policy). → вопрос: управляемая эволюция (система предлагает, человек утверждает — покрыто) ИЛИ автономная самомодификация правил (может быть запрещена)?
3. **«Версии как грань»** — НЕ прогнаны через 5-воротный тест T-FACETS (прогнали 5 др. кандидатов, version пропущен). → прогнать.
4. **Policy reuse между проектами / глобальные policy** — не связаны с осью scope (ADR-0004) и с уровнями Universal/Domain/Project/Experimental (constitution.md). → Р1 закрыт неполно: узел с каким scope?
5. **«Клиенты» + n8n-тулкит** — не разобраны; термин «клиент» двусмыслен (потребитель API vs бизнес-сущность vs generic-конструктор).
6. ⚠️ **Over-claim:** свод «ни один запрос не требует новой грани — сошлись все 4» покрывает 4 УЗКИЕ темы, а голос 08-01 шире (пп.1-5 выше не проверены). STATE.md звучит как закрытый вердикт → **ослабить**, иначе ложная уверенность тиражируется.
7. **«Агрегация» (GitHub-цепочка действие→решение→агрегация)** — звено «агрегация многих решений в системный вывод» не смоделировано (не одно merge).
8. **sync-intent не зашёл владельцу** — объяснение было жаргонным (`acts[]`, `source_ref`, outbox). → объяснять бытовым примером.
9. **Ветка = метка-линия vs узел-hypothesis** — недооценена по срочности; метафора «GitHub/PR» подразумевает адресуемую (=узел-hypothesis). → поднять приоритет.
10. **copy-forced кейс уже есть:** шаблон-проект → инстанс-проект (`docs/03-projects/`) — вероятный ответ на «когда COPY принудителен».

**Solid (дыр нет):** state=узел+линза+policy (двойное подтверждение); copy≠второй источник истины; блок T-SYNC на S7.

**Простая картина «max возможности» (языком владельца):**
- Помнит навсегда (акт не переписывается, только дописывается).
- Проецирует под вопрос (любой ответ = свежий пересчёт из памяти, можно снести и пересобрать).
- Версионирует гипотезы как git-ветки (черновик-идея → слить или бросить, брошенное не теряется).
- Переиспользует правила (policy) между проектами (написал раз — подключил везде).
- Синкает по правилам (для каждого типа заранее решено, где истина и как обновляется).
- Сама растит новые уровни абстракции (много деталей → предлагает группирующий слой, без потери старого).
- Сама себя чуть-чуть апгрейдит — но под клапаном (типовые правила предлагает сама, необратимое — за человеком).

**3 развилки из новых зёрен:** (1) граница само-апгрейда (зона между «обычным правилом» и Конституцией не размечена); (2) механизм пересборки абстракций (нужен ли `restructure`-акт; кто триггерит); (3) что такое «client» (домен-тип / коннектор-plugin / generic n8n-слой — 3 разных объёма работы).
