# Вердикт — расширенный стресс-тест (сложные сценарии)

- **Status:** review (раунд 2: версии-варианты, типы на лету, логика, ABAC, ограничения)
- **Owner:** jenya.stasik@gmail.com
- **Date:** 2026-06-15
- **Метод:** 5 кластеров (A типы-на-лету · B варианты · C логика · D ABAC · E ограничения).
  Сырьё: `docs/council/raw/2026-06-15-stress2-advanced/`.
- **Related:** ADR-0001, `VERDICT-2026-06-15-adr0001-stress.md` (9 проблем).

## TL;DR
Наша модель — отличный СЛОЙ СОСТОЯНИЯ (что истинно, кому принадлежит, когда, насколько доверяем).
Но этот раунд вскрыл, что для «сложных систем» не хватает целых ЧЕТЫРЁХ СЛОЁВ, которых в модели НЕТ:
1. **Жизненный цикл типов** (создание/правка/миграция типов людьми и ИИ) — 0✅/3⚠️/7❌.
2. **Варианты** (параллельные версии одного и того же) — 0✅/3⚠️/7❌.
3. **Логика/реактивность** («ACT-ось»: события, триггеры, вычисления, инварианты) — 0✅/2⚠️/8❌ (худший).
4. **Доступ/ABAC** (приватность, песочница модулей, мульти-юзер) — доступа сегодня НОЛЬ.
+ E: набор жёстких инвариантов («система НИКОГДА не должна…»).

## 🔗 Сквозная идея (объединяет A, C, D — самое важное)
**Управляющий слой должен быть такими же УЗЛАМИ в графе, как и данные.** Типы (`type-decl`), политики
доступа (`policy`), принципалы (`principal`), триггеры/правила (`trigger`), вычислимые определения
(`computed`) — всё это узлы и рёбра. Тогда:
- работает твой принцип «всё видно ИИ» и для управляющего слоя (а не только для данных);
- не нужен отдельный движок-реестр/конфиг — граф самохостится;
- расширяемость и модульность (твоя цель) получают единый механизм.
Это прямое продолжение «всё — узел + тип».

## A — Типы на лету (обычные люди + ИИ) · 0✅/3⚠️/7❌
Сегодня нельзя: создать тип из обычной фразы, понять/одобрить что ИИ создал, мигрировать старые узлы,
сделать разовое поле, развести коллизии из маркетплейса, откатить правку типа.
**Улучшения:** (1) **Тип-как-узел** `type-decl@1`: `human_label/описание`, поля с человеч. подписями,
`namespace/тип@версия`, `decision: proposed|approved|rejected` (ИИ предлагает → виден, но НЕ валидатор
пока не одобрен), `supersedes`. (2) **Миграция-как-узел** (additive безопасно; breaking → план+подтверждение;
старые валидаторы не удаляем; миграция = ручка отката). (3) **`adhoc:{}`** на узле для разовых полей +
человекочитаемый `conversation`-узел «что я создал и зачем» = поверхность для не-технаря.

## B — Варианты · 0✅/3⚠️/7❌
«Два разных плана одного и того же» — ТРЕТЬЯ ось (параллельное сосуществование), которой в модели нет.
`supersedes` (время) для этого — НЕ годится (пометит проигравший как «прошлое»).
**Улучшения:** (1) ребро **`variant-of`** + узел-якорь **`variant-group`** с `active_variant` + рационалом
решения; каскад по умолчанию идёт в активный вариант. (2) `diff_base` + `fork_depth: shallow|deep`
(делить ли детей при ветвлении поддерева). (3) Правило в контракте запросов: какой вариант видят агенты
по умолчанию (активный).

## C — Логика/реактивность · 0✅/2⚠️/8❌ (худший кластер)
Модель умеет ХРАНИТЬ, но не умеет ДЕЙСТВОВАТЬ. Нет событий, триггеров, формул, пересчёта, приоритетов.
Движок инертен (хранилище + роутер, без часов и вычислителя). Валидация одно-узловая (zod), а все
интересные правила сложных систем — меж-узловые.
**Улучшения (→ ADR-0002 «Логика и реактивность»):** (1) **Событие/триггер** (`trigger`-узел + `event` +
шов `evaluate` на записи; тонкие внешние «часы» только впрыскивают события). (2) **Вычислимый узел**
`computed:{formula,inputs,stale}` + граф зависимостей/инвалидации (инвариант = вычислимый булев + действие).
(3) **Логика модуля** = код/скил, на который УКАЗЫВАЕТ узел; `enforced_by: code|data|none`; приоритеты как
данные. Правило истины: **код — исполнитель, данные — декларация** (данные не переопределяют код в рантайме).

## D — Доступ/ABAC · доступа сегодня НОЛЬ
**Важно для будущего маркетплейса/мульти-юзера.** Нужно ПЕРЕопределить Принцип 3: «всё видно ИИ» — это про
ПЕРВОСТОРОННЕГО агента (твоего). Сторонние модули и другие пользователи = по умолчанию ЗАПРЕТ. ABAC бьёт по
записи / раскрытию / шарингу / действиям, не по чтению твоим ИИ.
**Улучшения (→ ADR-0003 «Доступ и ABAC»):** (1) `sensitivity: private|shareable|public` (каскад
МАКС-ограничительный, иначе переезд утечёт). (2) **Принципалы как узлы** (first-party / user / module) с
капабилити — это и делает «ИИ видит всё» безопасным (всё прочее default-deny). (3) **Гейт по классу
действия** (read|write|expose|external-act) — клапан доверия = ветка external-act, `decision:approved` =
токен. (4) Политики/гранты как узлы (грант живёт на bitemporal `valid_until` → бесплатный отзыв) за
ЖЁСТКИМ owner-only корнем доверия. **Точка применения = контракт запросов (проблема 9) → это БЛОКЕР пути
маркетплейса.**

## E — Жёсткие инварианты (engine-level, «НИКОГДА»)
1. Не создавать тип без проверки на дубликат. 2. Внешнее необратимое действие — только при
`decision:approved` И `epistemic:fact` (движок, не промпт). 3. Breaking-правка типа — только с миграцией+
подтверждением; новые поля nullable. 4. `supersedes:X` атомарно архивирует X. 5. Любой обход — с maxDepth+
сигналом усечения. 6. Модуль не пишет вне своего namespace без явного гранта. 7. Поля вида
secret/token/credential — только с флагом security-review. 8. Цепочка правил — не более N (5) срабатываний.

## ❗ Самое острое
Митигатор риска №1 автономии — **поле `decision` (клапан) — сейчас НЕ реализован**. ИИ может опереться на
`proposal` и совершить внешнее действие. Закрыть `decision` ПЕРВЫМ.

## Что это значит для плана (предложение)
Это не правки в одну ADR, а слоёный набор. Предлагаю:
- **ADR-0001 v2.1** — ядро узла + 9 проблем + **тип-как-узел** (фундамент для всего).
- **ADR-0002 «Логика и реактивность»** — ACT-ось (события/вычисления/приоритеты).
- **ADR-0003 «Доступ и ABAC»** — sensitivity/принципалы/гейт/политики + переопределение Принципа 3.
- **Варианты** — в v2.1 (3 поля + 1 узел-тип) или малой ADR-0004.
- Контракт запросов (проблема 9) — общий БЛОКЕР, нужен всем трём.
Порядок реализации: `decision`-гейт и тип-как-узел → логика → ABAC. Перед кодом — ещё раунд тестов на новые слои.

## ⏳ Решение за владельцем
**Переопределить Принцип 3: «всё видно ИИ» = первостороннему агенту; сторонние модули/юзеры = default-deny.**
Это разблокирует ABAC и безопасный маркетплейс, не трогая твой опыт с собственным ИИ.
