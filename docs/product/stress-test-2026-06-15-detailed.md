# Стресс-тест модели данных — детальные результаты (сырьё)

- **Date:** 2026-06-15
- **Метод:** 5 агентов × ~50 ячеек. Синтез → [CONCEPT-2026-06-15](CONCEPT-2026-06-15-data-model-stress-test.md). Здесь — детали по кластерам.

## Кластер 1 — Области жизни (3 ✅ / 4 ⚠️ / 3 ❌)
Примеры: тренировка с подходами, замер веса, серия медитаций, привычка с расписанием, семейное событие,
хобби-проект, цель здоровья с под-целями, абонемент (Финансы×Спорт), инсайт из медитации, план техники.
Дыры:
- **Временные ряды/метрики** (6/10): нет `value/unit/occurredAt`, всё в meta, не агрегируется.
- **Рекуррентность/расписание** (4/10): `due` = одна дата, нет повторов.
- **Мультипринадлежность**: parentId(1)/tags/links перекрываются — нет канонического «принадлежит».
- **Внешние ссылки** в `Link.to` (YouTube/файл) — нет `href`.
- **due/status** семантически «task-only», но нужны на event/goal.
- Отсутствуют kind `person/event/goal/file`; механизм модулей не реализован в коде.

## Кластер 2 — Карьера / Коммуникация / Обучение (3 ✅ / 4 ⚠️ / 3 ❌)
Примеры: карьерная цель, подобласти, навык с прогрессом, курс↔навык↔цель, урок, человек-контакт,
встреча с участниками, обязательство (я→), задолженность (→мне), рабочий проект со стейкхолдерами.
Дыры:
- **Социальный граф**: нет `kind person`; история взаимодействий не структурирована.
- **Встреча**: участники в `meta` дублируют links; `store.query` не фильтрует по `rel`.
- **Обязательство vs задолженность**: «я должен» vs «мне должны» только в meta; note без `due/status`.
- **Многие-ко-многим** люди↔проекты: нет обратного обхода рёбер (`backlinks`).
- **Прогресс навыка во времени**: снимок в meta, истории нет.
- Rollup прогресса проекта/курса не синхронизирован с детьми.

## Кластер 3 — Технические/системные (2 ✅ / 6 ⚠️ / 2 ❌)
Примеры: промпт с версиями, определение агента, понимание кода, коммит, PR, лог агента, баг, релиз,
правило-валидации-типа, модуль-регистратор типа.
Дыры (КОРЕНЬ — закрытый enum kind):
- **Закрытый `NODE_KINDS as const` + `z.enum`** против «типов-модулей» — рантайм-разрыв. Блокирует
  технические типы (commit/pr/bug/prompt) и правила-как-данные.
- **Коммит/PR/релиз: узел или внешняя истина?** git уже БД коммитов → зеркалить = две истины.
- **«Понимание кода»** устаревает при изменении файла — нет инвалидации (freshness/hash).
- **Версии промпта**: zoom (L1-L3) их НЕ покрывает; не выбрано (meta.version+git vs узлы-supersedes).
- **Правило-типа как данные** ≠ исполняемая валидация (Zod в TS) — нет моста; риск бесконечной мета-регрессии.
- Ссылочная целостность `links.to` не enforced (висячие рёбра).

## Кластер 4 — Память / Агенты / Чаты / Команды / Модели (0 ✅ цельных / 7 ⚠️ / 5 ❌)
Примеры: меняющийся факт, память агента vs заметка, многоагентный чат, топик=агент+контекст,
сообщение-агрегатор, команда агентов, конфиг модели, диалог агент↔агент, proposal-узел, контекст-каскад,
компакт/резюме, один агент — две памяти.
Дыры (три оси: время, экземпляр, эпистемика):
- **Темпоральность фактов** (самая дорогая): `created/updated` = время файла; нет `validFrom/Until/supersedes`;
  «дай только актуальное» невозможно.
- **Template vs Instance**: агент-роль vs агент-в-чате (своя память) не различены; один агент в 2 чатах.
- **Эпистемический статус**: факт/гипотеза/предложение смешаны; нет `proposed/approved`.
- **Членство в чате/команде**: parentId vs links не сходятся с каскадом контекста; ребро членства негде хранить.
- **Конфиг модели/цена** — нет понятия «справочная запись»; нет учёта токенов↔тариф.
- **Thread/reply**: нет `inReplyTo`; `parentId` = контейнер, не ответ.
- **Компакт**: старые message не помечаются «архив/свёрнуто» → попадают в горячие запросы.
- Нет `kind team`; ростер/протокол команды не выражены.

## Кластер 5 — Крайние случаи (критик, «ломаю намеренно»)
CRITICAL:
- **C1 Мульти-родитель ⟂ каскад**: `effectiveContext`/`ancestors` идут ТОЛЬКО по `parentId` → связь
  через `links` контекст не получает. Полиморфизм и каскад несовместимы в коде.
- **C2 Циклы по links**: cycle-guard только для parentId; `maxDepth=3` обещан, но В КОДЕ ОТСУТСТВУЕТ →
  `getContext`/broadcast зациклятся (infinite loop / memory exhaustion).
- **C3 Полиморфный kind «всё сразу»** невозможен при `z.enum` (один kind).
- **C4 Broadcast (500 links)** + `query()` грузит весь каталог O(N) — тяжёлый граф без пагинации/лимита.
- **C5 Конфликт валидаций** базовый-vs-модульный тип — нет registry/composed-schema/приоритета.
Concerns: наследование importance при мульти-родителях не определено (max/min/взвеш?); поиск
«обязательства людям за неделю» невозможен (нет фильтра due/range/rel/backlink); перемещение узла рвёт
актуальность контекста (нет инвалидации); переименование направления-тега (строка) теряет связь;
нет фильтра по `due`.
Provocations: «файлы=истина, индекс=эфемерный» при 50 trace/мин = постоянный full-scan; `description`
в задании есть, в коде НЕТ; summary никто не инвалидирует при правке листа; `actor` без проверки существования.

## Сводный паттерн (общий вывод всех 5)
Модель отлично держит **структуру+контент**. Ломается на **4 осях**: ВРЕМЯ, ПРИНАДЛЕЖНОСТЬ(1-дом-vs-связь),
СТАТУС-ЗНАНИЯ, ОТКРЫТЫЕ-ТИПЫ — всё висит на `meta` без схемы/запросов. + инфра (циклы, maxDepth,
обратные рёбра, внешние ссылки, description).
