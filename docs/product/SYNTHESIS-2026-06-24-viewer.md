# Вьюер / интерфейс (направление 1)

> 2 агента: дизайн взаимодействия + критика. Фаза = DESIGN. Цель — спроектировать наш вьюер так, чтобы он
> ПРЕВОСХОДИЛ understand-anything (их слабость: read-only + нельзя ходить по графу с клавиатуры).

## Сквозной вывод
**Главная развилка ДО любой стройки: что есть основная поверхность — «граф» или «результат LENS-запроса с панелью
деталей»?** Критик прав: реальные сценарии владельца («что застряло в X?», «что делать сегодня?») — это ВЫВОДЫ
запросов, а не блуждание по графу. Рекомендация обоих агентов: **v1 = LIST + FOCUS (агенда/инбокс на LENS-запросах)**,
граф-канва — позже, как инструмент power-user. Force-directed как основной вид = анти-паттерн на 10k+ узлов (волосяной
клубок).

## Модель навигации (две оси — делает home/facet тактильным)
Всегда один **focus-узел**. Две независимые оси ходьбы:
- **k/↑ ↔ j/↓** — вверх/вниз по **home-хребту** (ацикличный лес → путь уникален). j/k — между сиблингами, Enter/l — внутрь.
- **h/← ↔ l/→** — вбок по **facet-of** (тот же узел, другое измерение; принадлежность НЕ меняется).
- **Хлебные крошки = home-хребет** (уникальны, потому что ровно один home). Facet-переходы — отдельной строкой, не в крошках.
- Длинные прыжки: `t` (тип), `f` (фильтр по оси паспорта), **Cmd+K** (палитра).
- **3 вида (LIST ⇄ GRAPH ⇄ FOCUS, `v`) + стек оверлеев; Escape-каскад** (оверлей → снять выделение → выйти из FOCUS).
  Focus сохраняется при смене вида/линзы («не теряй моё место»).
- ⚠ **Клавиатурная ходьба — только по home-хребту** (ацикличен по инварианту); ходьба по reference-рёбрам — отдельная
  команда с движковым maxDepth-гардом (reference может быть циклом). Это прямое применение «принадлежность ⟂ ссылка».

## Командная палитра (Cmd+K) — маршрутизация по префиксу
`(нет)`=узлы (Fuzzy/Semantic, Tab) · `>`=действия · `@`=тип · `#`=линза · `~`=паттерн · `!`=агент · `+`=создать.
Один общий реестр ActionId для палитры И шорткатов (нет рассинхрона). У каждого действия иконка ⚪free / 🔒valve до запуска.
**Семантический поиск на старте = агент-запрос к графу, НЕ vector store** (векторы отложены, см. движок).

## LENS = переключатель вида (4 регулятора, не просто фильтр)
Смена линзы (линза = узел!) перерисовывает: какие рёбра видны · глубину проекции · какие поля паспорта в карточке ·
вычисленный `projected_level`. Слоты `1..9` назначает пользователь. **hard-ABAC-линза** = движок физически не отдаёт
payload/поля по sensitivity+principal (доступ-как-линза). Линза никогда не двигает focus и не пишет на диск.

## Граница клапана в редактировании (наш дифференциатор vs их read-only)
- **СВОБОДНО ⚪:** создать, переименовать/править payload, связать facet/каскад, **сменить home (через диалог
  целостности с превью последствий — НЕ клапан)**, epistemic draft→proposal→hypothesis, **повысить** sensitivity, архив.
- **КЛАПАН 🔒:** **epistemic→fact** (автор≠авторизатор), **удалить-навсегда**, **понизить** sensitivity,
  **внешняя отправка через CONNECTOR**. Confirm-оверлей лишь ВИЗУАЛИЗИРУЕТ вердикт движка; вьюер клапан не решает.

## Система шорткатов (5 категорий, один массив → биндинги + `?`-модалка + подписи палитры)
Массив `{key, category, description, action, context, valve}`. `mod`→⌘/Ctrl; глушить в полях кроме Esc и mod+Enter; чорды 800мс.
- **General:** `?` `mod+k` `/` `Esc`(каскад) `v` `.`
- **Navigation:** `j/k/h/l`+стрелки, `Enter/o`(lazy payload), `g g`/`g i`/`g h`, `t` `f` `[ ]`
- **Lens:** `L` `1-9` `+/-`(глубина) `p`(панель паспорта) `x`(фасеты)
- **Edit:** `n` `e` `c` `s/S`(epistemic ↑/↓) `mod+s`, `mod+shift+f`🔒(→fact), `mod+backspace`🔒(удалить)
- **Agent:** `a` `A`(суммировать ветку) `>send`🔒
**Стрелки = ходьба по графу (НЕ туры)** — прямое исправление главной слабости конкурента.

## Паспорт vs payload
Список/граф/палитра/крошки = ТОЛЬКО паспорт (мгновенно, 10k узлов). Карточка = паспорт + дешёвый rollup движка.
**Payload читается лениво только на Enter/O.** Иконки epistemic/sensitivity видны всегда без вскрытия содержимого.

## 🔴 Топ design-рисков (критик, ранжировано) → митигатор
1. **Force-graph как основа → клубок** → home-хребет outline как ОСНОВНОЙ вид; граф = опц. «карта».
2. **Drag-to-relink молча меняет home** (каскадные эффекты) → нет drag-репарента; явный диалог с превью влияния.
3. **Стрелки без контракта обхода** → задать контракт ДО стройки (j/k сиблинги; h/l collapse/expand; Enter открыть).
4. **Bulk-edit обходит per-node клапан** → клапан перепроверяется на КАЖДОМ узле по его ПОСЛЕ-правочной позиции.
5. **Циклы reference-рёбер ломают навигацию** → клавиш-ходьба только по home; reference — отдельная команда с maxDepth.
6. **Epistemic/sensitivity спрятаны** → бейдж на каждом узле; ошибка блокировки ссылается на КОНКРETНЫЙ блокирующий узел.
7. **Многомерный узел «не на своём месте»** → показывать home-родителя + «ещё в: X, Y»; LENS-контекст в крошках.
8. **Section-index огромных списков** (Telegram-сообщения) → ленивое раскрытие + virtual scroll + контракт с 1-го дня.

## 🟡 Вопросы к владельцу
1. **v1 = LIST+FOCUS** (рекоменд.) или сразу graph-канва?
2. Берём **`weight(0..1)`** на ребре (сортировка соседей при j/k/h/l)?
3. Подтвердить: семантический поиск = агент-запрос, векторы отложены?
4. Multi-select + bulk agent-actions в v1? (умножает поверхность клапана — рекоменд. отложить).
5. Кто жмёт valve-override — только владелец или делегируемо? → ADR-0003 (trust-horizon).
6. Цвет `projected_level` всегда или только на линзах, что просят?

## Заметка по ADR
CONNECTOR трактуется как ТИП узла для внешних интеграций (через что идёт внешняя отправка), НЕ как 4-й род control-plane
(ратифицированы 3: TYPE/LENS/PATTERN). Если задумывался род — это переоткрытие ADR-0002.
