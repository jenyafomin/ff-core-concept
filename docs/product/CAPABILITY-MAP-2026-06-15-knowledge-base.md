## Принцип чтения
КЯдро БЗ = граф узлов (файлы-истина). «Возможность» = глагол, который система делает со знанием.
Часть возможностей — это **движок графа** (не агент), часть — **агент со скилом**.

## Спайн возможностей (9)

### C1 · ЗАХВАТ (capture / inbox)
Принять сырьё из любого канала (голос, текст, файл, ссылка, авто-извлечение) → inbox.
- **Есть в экосистеме:** `garrytan/gbrain@capture`, `nicepkg/ai-workflow@capture-triage`,
  `sean-esk/second-brain-gtd@second-brain` (245).
- **У нас уже:** `tools/whisper` (голос), Telegram-канал.
- **Вердикт:** ⚙️ ТОНКО СТРОИМ поверх своих каналов + берём паттерн triage из скилов.
- **Владелец-агент:** *Inbox-агент* (приём + первичная сортировка).
- **Открытый Q:** какие каналы на 1-й итерации (Telegram-текст/голос + файлы — достаточно?).

### C2 · ИЗВЛЕЧЕНИЕ (extract → структурированный узел)  ⭐ сердце ИИ
Сырьё → узел(ы): тип, title, body, предложенные связи/теги/важность. Это «ИИ тянет сам».
- **Есть:** `jmsktm@entity-extractor`, `danielmiessler/personal_ai_infrastructure@parser` (99),
  фреймворки памяти — Zep/**Graphiti**, **mem0**, Cognee (делают entity+relation extraction).
- **Вердикт:** 🔨 СТРОИМ свой скил (наша типизация), опираясь на паттерны Graphiti/mem0.
- **Владелец-агент:** *Библиотекарь* (понимает входящее → предлагает узел).
- **Открытый Q:** извлечение — это скил, который владелец подтверждает, или агент пишет сразу?
  (связано с эпистемическим статусом «предложение vs факт», решение #4).

### C3 · МАРШРУТ + ОБОГАЩЕНИЕ (route / enrich)
Поставить узел в его ОДИН дом (контекст), статус, прогрессивное обогащение `inbox → routed → enriched`.
- **Есть:** паттерн GTD/second-brain; но правила типизации — наши.
- **Вердикт:** 🔨 СТРОИМ (это наша модель данных — тут живут 5 открытых решений).
- **Владелец-агент:** *Библиотекарь* (тот же) / *Роутер*.
- **Открытый Q:** решения #1 (один дом + связи), #2 (метрики), #3 (открытые типы) — блокируют.

### C4 · СВЯЗЫВАНИЕ (relate)
Типизированные рёбра, мульти-родитель (принадлежность vs связь), обратный обход (backlinks).
- **Вердикт:** 🔨 СТРОИМ (движок графа, не агент). Backlinks требуют индекса (C9).
- **Владелец:** *движок графа* (ядро `@ff/core`).
- **Открытый Q:** решение #1; цикл-гард по links (дыра C2 из стресс-теста).

### C5 · ВЫБОРКА / КОНТЕКСТ (retrieve)
`getContext(узел, бюджет)` — собрать релевантный контекст для агента/вида. Фильтры (дата/статус/rel/важность), zoom L1-L3.
- **Есть:** `yonatangross/orchestkit@rag-retrieval` (653), `neo4j-contrib@neo4j-graphrag-skill` (222),
  `latestaiagents@graphrag-patterns` (161).
- **Вердикт:** 🔨 СТРОИМ `getContext` (канонический запрос из Консилиума №2) + адаптируем паттерны GraphRAG.
- **Владелец-агент:** *Контекст-сборщик* (то самое «контекст-конверт»).
- **Открытый Q:** что строить раньше — этот запрос или ежедневный «что застряло» (нерешённое из №2).

### C6 · ВИДЫ / НАВИГАЦИЯ (view)  ⭐ крупный рычаг переиспользования
Граф/mind-map, углы обзора (глубина/фокус/абстракция), раскрываемый обзор-до-уровня-N, поиск внутри вида.
- ~~**Есть:** экосистема Obsidian (kepano 44.5K, json-canvas, cli)~~ — рассматривалось как рычаг.
- **РЕШЕНО владельцем (msg 141): Obsidian-формат/навигация ОТКЛОНЕНЫ.** БЗ — субстрат для агентов («всё, с чем
  работают агенты»), а не хранилище файлов/заметок; привязка к vault сужает. Связи по `id`, не wikilink;
  `home` — логический указатель, не папка. См. ADR-0001, N-016.
- **Вердикт (обновлён):** 🔨 СТРОИМ свои виды (agent-first). Можно переиспользовать общие граф-движки
  визуализации (не Obsidian-специфику). Виды/углы/фильтры — позже, отдельной проработкой.
- **Владелец:** человек (вид) + скил-генератор вида.
- **Открытый Q:** какой минимальный первый вид нужен (раскрываемый обзор-до-уровня-N? фокус по узлу?) — позже.

### C7 · ПОДДЕРЖКА / ЭВОЛЮЦИЯ (maintain)
Время-истинности (`validFrom/until/supersedes`), эпистемический статус (факт/гипотеза/предложение),
архив/компакт, свежесть/инвалидация.
- **Есть:** `anthropics/knowledge-work-plugins@memory-management` (4.6K), `obra/episodic-memory` (8.6K);
  **Graphiti** — би-темпоральная модель (эталон).
- **Вердикт:** 🔨 СТРОИМ (оси ВРЕМЯ+СТАТУС из стресс-теста), опираясь на би-темпоральность Graphiti.
- **Владелец-агент:** *Хранитель/Архивариус* (помечает устаревшее, сворачивает).
- **Открытый Q:** решения #4 (статус знания), #2/время.

### C8 · ФАЙЛЫ (files)
Произвольные файлы + описание + важность, вшитые в тот же граф. Файл-как-истина.
- **Вердикт:** 🔨 СТРОИМ тонко (узел-файл + описание + ссылка `href`). Дыра «внешние ссылки» из стресс-теста.
- **Владелец:** движок графа.
- **Открытый Q:** файл хранится как узел-обёртка + сам файл рядом? (паттерн из ресёрча — да).

### C9 · ИНДЕКС / ПРОИЗВОДИТЕЛЬНОСТЬ (index)
Эфемерный индекс для быстрого обхода на масштабе; цикл/глубина-гарды.
- **Есть:** SQLite+better-sqlite3 (вывод ресёрча), позже DuckDB+DuckPGQ.
- **Вердикт:** 🔨 СТРОИМ позже (~300 узлов). Сейчас закрыть дыры: maxDepth в коде, цикл-гард по links.
- **Владелец:** движок графа.
- **Открытый Q:** не блокер сейчас; зафиксировать как «отложено до порога».

## Три вывода
1. **Obsidian-выравнивание — крупнейший рычаг.** Узел в формате Obsidian-markdown → даром получаем
   виды/canvas/поиск/мобайл/CLI + 44K-экосистему скилов. Прямо обслуживает «человекочитаемо+контролируемо».
   Это ФОРК формата узла — решать рано.
2. **Ядро БЗ — в основном кастомная стройка** (C2-C5,C7-C9), потому что оно личное/специфичное; но
   каждая возможность опирается на сильный эталон (Graphiti=время, GraphRAG=выборка, mem0/Zep=память,
   Obsidian=формат+виды). Не изобретаем с нуля — стоим на плечах.
3. **Возможности группируются в агентов** → это и есть зерно ростера «модуля управления агентами»:
   Inbox · Библиотекарь · Контекст-сборщик · Хранитель + слой чистого движка графа (связи/файлы/индекс).
