# graph-example — живой пример графа (dogfood, Q11/N-089)

Маленький РЕАЛЬНЫЙ срез нашего собственного проекта, представленный так, как будет жить в системе:
**каждая ячейка = один объект-файл** (md + frontmatter = «паспорт» + рёбра), плюс раздел
**«Поведение»** — комментарии, описывающие, как движок/линза трактуют ячейку. Без кода, на md+frontmatter.

## Что показывает
- **Паспорт ячейки** (ADR-0002): `id · type · schema · created · updated · epistemic · sensitivity · source · principal`
  (+ опц. `level`, `external_ref`). Тонкий — читается БЕЗ вскрытия тела.
- **Рёбра** (`links`): `home` (ровно одно — «где лежит», по нему наследуется контекст) и много обычных/`facet-of`
  («про что», связи) — `rel · to · home · priority`.
- **Многомерность (N-081):** `file-node-ts` лежит в ОДНОЙ папке (`home`) и сразу в НЕСКОЛЬКИХ категориях (`facet-of`).
  Файловая система так не умеет — здесь это естественно.

## Файлы (каждый = ячейка)
| Файл | type | роль в примере |
|------|------|----------------|
| `goal-second-brain.md` | goal | корневая цель |
| `decision-adr0002.md` | decision | решение (паспорт ратифицирован), `realizes`→цель |
| `file-node-ts.md` | file | **многомерность**: один `home` + много `facet-of` |
| `category-service.md` | category | цель `facet-of` (классификация, НЕ home) |
| `insight-multidimensionality.md` | insight | вывод, `about`→file, `grounds`→ADR-0002 |

> Примечание: часть упомянутых в рёбрах ячеек (folder, spec, lineage, project) НЕ материализована здесь — держим пример
> лёгким. В реальном графе каждая из них = свой объект. ID здесь читаемые (`goal-001`…); в системе — ULID.
