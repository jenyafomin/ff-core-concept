## Инвентаризация
`PROJETS/` (~35 проектов), `TOOLS/agents-manager` (шлюз), `MODULES/` (пусто). Схемы: **CRM-Rent** (SQL), **InstaApp** (104 supabase-миграции), **Cardex/DropHacker** (Prisma), **jenek/vibecoding** (supabase).

## 🥇 CRM-Rent (`database-schema.sql`) — наши абстракции УЖЕ работают
- **`order_snapshots` названы «The Brain Memory»** — замороженное состояние (тариф/состояние) на момент = ровно наш **Г9 снапшот-в-момент-решения** + bitemporal. Владелец уже изобрёл «снапшот-как-память». ✅
- **status-жизненный цикл везде** (`orders: draft→booking→active_contract→completed→cancelled`; cars/leads/charges/payments) → подтверждает **Г41 (статус ≠ epistemic)**. ✅
- **`activity_logs(entity_type, entity_id, action, changes JSONB)`** — универсальный лог операций над ЛЮБОЙ сущностью = буквально **«ячейка-операция» Sonnet (память 2-го порядка)** + audit-log. ✅
- **`charges.reference_id + reference_type`** — полиморфная ссылка = **типизированное ребро/прокси** (Реляционность). ✅
- **Planned vs Actual** (`pickup_date` vs `actual_pickup_date`) = **память о будущем (намерение≠факт)**. ✅
- **`custom_fields JSONB`** = тонкое ядро + открытый payload; **`is_active`** = мягкий статус; **триггеры `updated_at`** = авто-версии.

## 🥈 InstaApp (104 supabase-миграции) — зрелый эталон ценностей
- **RLS / owner-data / partition RLS** → **Согласие** (row-level видимость). ✅
- **`tenants`** → **Суверенность** (multi-tenant, Г44 классы). ✅
- **`creator_posts_soft_delete`** → **«забыть≠удалить»** (Витальность) — решение нашей развилки. ✅
- **embeddings + `match_rpc`** → **Читаемость** (дешёвый матч). ✅

- **`post_stats_history`, `drift_log`** → тренды/дрейф = Opus «память об отсутствии». ✅
- **104 нумерованные миграции** → **Г46 эволюция без ломки**. ✅

## Вывод по дееспособности
Почти все ключевые грани **уже проверены боем**: снапшот-память · status-lifecycle · generic activity-log (операция-над-сущностью) · soft-delete · RLS · tenants · embeddings · миграции · полиморфные ссылки. Мы не изобретаем — **обобщаем работающее до agent-first уровня.**

## Рекомендации (перенять/обсудить)
1. **`order_snapshots` → в фундамент**: снапшот-на-момент даёт Г9/bitemporal дёшево (замораживать в точке решения, не версионировать всё).
2. **`activity_logs` → прототип «ячейки-операции»**: `(entity, action, changes)` = память 2-го порядка. Взять как модель.
3. **InstaApp RLS+tenants → референс Согласия/Суверенности** (готовый ABAC).
4. **soft-delete vs hard-erase** — оба нужны: soft = владельческое забывание, hard = право референта (FQ7 подтверждён практикой).
5. **Planned/Actual → модель «памяти о будущем»**.

## Не найдено
Графовых БД (Neo4j/RDF), векторных графов знаний, bitemporal-движков, policy-as-data — этого нет. Единица памяти новее; но её ЧАСТИ дееспособны по отдельности.
