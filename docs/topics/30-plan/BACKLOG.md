# BACKLOG / «прожиг» — идеи и задачи

- **Owner:** JenyaFomin · **Обновлено:** 2026-07-04
- **Правило:** каждую запись вести парой **Проблема → Идея** (идея всегда привязана к проблеме).

## T1 — Allowlist через Telegram
- **Проблема:** топик/чат добавляется в allowlist только вручную в терминале; при добавлении не всплывает автоматически.
- **Идея:** approve-флоу прямо в Telegram (выдача доступа из чата).
- → Владелец: топик **агенты (65 / agents-manager)**.

## T2 — Отдельный топик для Fable-адвайзера
- **Проблема:** Fable нужно накапливать контекст и постить вехи, но сейчас нет своего места; неясно, готова ли система агентов.
- **Идея:** отдельный чат/топик, где живёт Fable; владелец задаёт вопросы напрямую. Сначала проверить готовность агентов.
- → Владелец: топик агенты (65).

## T3 — Принцип «как взаимодействовать с адвайзером» (кандидат в скилл)
- **Проблема:** сильная модель (Fable) оправдывает себя, только если ей доверяют творить, а не диктуют; иначе теряем ценность.
- **Идея:** оформить принцип скиллом: Fable запускать ОТДЕЛЬНО (накапливает знания); Opus даёт контекст и **доверяет суждению** Fable («улучшай, если видишь как»); Opus+sonnet — управление/дешёвые задачи. Разные роли у разных агентов проекта — можно делать параллельно.
- → Владелец: пульт (92) / агенты (65).
