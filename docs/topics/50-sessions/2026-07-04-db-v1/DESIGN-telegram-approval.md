# Выдача прав только через Telegram — разбор (seed ADR)

## Свойство, которое нужно (владелец)
Одобрение права идёт ТОЛЬКО от владельца через Telegram; **агент не имеет доступа** к каналу одобрения
и не может сам себе выдать право. Открытые под-вопросы владельца: (1) триггер «процесс ждёт»,
(2) как вносить выбор (кнопки/стрелки).

## Ключевая развилка: КТО владеет каналом одобрения

### Вариант A — программный колбэк прав (РЕКОМЕНДАЦИЯ)
Канал одобрения принадлежит **шлюзу** (родительский процесс НАД агентом), не агенту.
- Claude Code CLI (headless) имеет флаг **`--permission-prompt-tool <mcp-tool>`**: когда сессии нужно
  право, CLI сам вызывает назначенный MCP-инструмент и ЖДЁТ его ответа allow/deny.
- Этот MCP-инструмент реализует шлюз: он (1) шлёт владельцу в TG карточку с inline-кнопками, (2) блокируется
  до нажатия, (3) возвращает решение в CLI. Агент физически не участвует — решает родитель + владелец.
- То же на уровне SDK = колбэк **`canUseTool`** (если runner перевести на Claude Agent SDK).
- **Триггер «процесс ждёт»** решается сам собой: вызов инструмента = событие → пуш в TG.
- **Ввод выбора = inline-кнопки Telegram** (`callback_query`), НЕ стрелки в терминале. У шлюза уже есть
  grammY + /approve /reject — это та же механика, расширенная на права инструментов.
  Карточка: `[разово · на сессию · навсегда · отказ]`; выбор → грант пишется узлом в BRAIN → енфорсит шлюз.

### Вариант B — драйвинг терминала (твоя идея с tmux) — ХАК, фолбэк
Сессии живут в tmux, по ID достаём пейн; при появлении TUI-запроса парсим экран → шлём в TG → по кнопке
инжектим нажатие (стрелка/enter) обратно в пейн.
- Работает, но хрупко: парсинг TUI-промптов, гонки, инжект клавиш, адресация сессий, ломкость при обновлениях.
- Это эмуляция человека за клавиатурой. Нужен только если обязаны оборачивать ИНТЕРАКТИВНЫЙ CLI как есть.
- Наш шлюз и так запускает `claude -p` (headless) → драйвить TTY НЕ нужно; Вариант A закрывает всё чище.

## Вывод
Твоё свойство «только TG, агент без доступа» достигается **архитектурно** (A), а не инжектом клавиш (B).
Кнопка Telegram = и есть механизм ввода. tmux/стрелки — не требуется.
Быстрый путь: `claude -p --permission-prompt-tool <mcp>` (без переписывания runner на SDK).
Полный путь: runner → Agent SDK + `canUseTool` (даёт и контроль жизненного цикла = чинит снос агентов).

## Открытые вопросы к реализации
1. Гранулярность гранта (разово/сессия/навсегда/по-ресурсу) и хранение узлом-грантом в BRAIN.
2. Таймаут ожидания кнопки (что делать, если владелец не ответил N минут — deny by default?).
3. Точная сигнатура `--permission-prompt-tool` / `canUseTool` — выверить по актуальной доке ПЕРЕД сборкой.
4. Стык с ADR-0003 (клапан/ABAC) и default-deny модулей.
