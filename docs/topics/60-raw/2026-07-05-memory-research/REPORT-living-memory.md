# REPORT — Живая память: salience, забывание, всплытие (prior art)

> Дата: 2026-07-05 · Статус: draft · Автор: Opus (inline, веб недоступен — по знаниям) · Шов Р-1
> Питает цели: Г7 (живое доверие), Г8 (годность), Г12 (менять не теряя), Г15 (бюджет внимания), В3 («запах»)

## 1. Когнитивистика — как забывает живой мозг

- **Кривая забывания Эббингауза + spacing effect.** Сила следа падает экспоненциально во времени, НО каждое извлечение/повтор поднимает её и **уплощает будущий спад** (интервальное повторение, SM-2/Anki). Перенос: `salience` ячейки затухает во времени, но каждое использование не просто «поднимает», а **снижает будущую скорость затухания** (β уменьшается) — часто используемое становится «твёрже».
- **Консолидация (гиппокамп→кора).** Свежее хранится «дорого и хрупко» в быстром буфере, со временем важное переписывается в «дешёвое стабильное» хранилище, неважное отсекается во сне. Это прямой аналог **фазы C (метаболизм)** и слоёв Core/Recall/Episodic. «Sleeptime-консолидация» = батч-переработка.
- **Реконсолидация.** Извлечённая память становится пластичной и перезаписывается при возврате — т.е. чтение может ИЗМЕНИТЬ след (риск искажения). Обоснование, почему «Переработать» и «Подтвердить» опасны без контроля версии.
- **Retrieval-induced forgetting + интерференция.** Активное вспоминание одного ПОДАВЛЯЕТ конкурентов; похожие следы мешают друг другу. → сигнал для дедупа (Г17: конфликтующие ячейки должны видеть друг друга, а не тихо интерферировать).

## 2. Кэш-политики — инженерная модель salience

- **LRU** (recency), **LFU** (frequency) — по отдельности слабы: LRU выбивает редкое-но-важное, LFU держит устаревшее-но-когда-то-частое.
- **ARC** (Adaptive Replacement Cache) — держит БАЛАНС recency↔frequency, адаптивно. Концептуально: salience должна быть композитом свежести и частоты, а не одним.
- **W-TinyLFU** (Caffeine) — лучший практический дизайн: частотный эскиз с **экспоненциальным старением** (счётчики делятся пополам периодически) + admission-фильтр. Это готовая формула «частота с забыванием»: **frequency-with-decay**.
- **TTL** — жёсткая годность по времени (= волатильность Г8). Разное TTL для разных классов.

## 3. LLM-agent memory — самый близкий прецедент

- **Stanford Generative Agents (2023)** — эталон. Каждое воспоминание в `memory stream` имеет скор извлечения = **α·recency + β·importance + γ·relevance**:
  - `recency` — экспоненциальный спад с последнего обращения;
  - `importance` — ставится 1 раз при записи (LLM оценивает «насколько значимо», 1–10);
  - `relevance` — косинус к текущему запросу.
  - Плюс **reflection**: периодически из потока фактов синтезируются выводы-узлы (= консолидация, наша фаза C).
- **MemGPT** — ОС-подобный пейджинг: main context (окно) ↔ external storage; агент сам решает, что «выгрузить/подгрузить». Прямой аналог слоёв Core (в окне) / Recall (по запросу) / Episodic (архив).
- **Vector-store TTL / summary buffers** (LangChain и пр.) — практика: сырое стареет и сжимается в саммари.

## 4. Рекомендация (для ячейки, несущей свою политику)

**Одна ось `salience`, композитная, по мотивам Generative Agents × W-TinyLFU:**

```
salience(t) = w_r · recency(t) + w_i · importance + w_u · use_freq_decayed
recency(t)  = exp(−λ · Δt_last_access)          # экспоненциальный спад
use_freq_decayed — счётчик использований с периодическим делением пополам (aging)
importance — базовая значимость (ставится при записи, ПЕРЕСМАТРИВается глаголом Подтвердить)
```

- **Один рычаг — два глагола (подтверждает угол Fable У-2):**
  - `salience ≥ порог_всплытия` → ячейка сама всплывает (push / «запах», В3);
  - `salience < порог_доступа` → ячейка «забыта» (тонет, не удаляется).
- **Классы через параметры, не через форматы** (связь с Р-2): λ (скорость спада) и веса — это и есть «политика жизни» ячейки (Г14). Живое: большой λ, importance пересматривается. Холодное: λ≈0 (не спадает), доступ только по фильтру/поиску, не по salience.
- **Забыть ≠ удалить.** Порог меняет ВИДИМОСТЬ (эпистемический `archived` / понижение). Реконсолидация → «Переработать» обязан порождать версию, не мутировать вслепую (см. В2).
- **Консолидация (фаза C)** = батч-джоб «reflection»: trace[] → reflection-узел → memory-fact(hypothesis); повышение до fact — другим актором.

**Цена/риск:** salience-скор надо где-то считать/хранить (дёшево: 2-3 числа в паспорте); главный риск — реконсолидация без версионирования (искажение истории) и «зомби-память» (забыто по salience, но всплывает через кэш эмбеддинга — нужен единый порог доступа на ВСЕ каналы извлечения).
