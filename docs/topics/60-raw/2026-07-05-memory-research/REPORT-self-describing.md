# REPORT — Знание, носящее свой контракт: self-describing, portable, ребро-с-паспортом (prior art)

> Дата: 2026-07-05 · Статус: draft · Автор: Opus (inline, по знаниям) · Шов Р-3
> Питает цели: Г1 (оценить не вскрывая), Г10 (провенанс), Г14 (своя политика), Г19 (портируемость); решает В4 (ребро-с-паспортом)

## 1. Self-describing данные — как знание переносится без внешней схемы

- **RDF (тройки subject-predicate-object) + IRI.** Каждый факт самоадресуем глобально; смысл не зависит от локальной схемы. Цена: многословность, всё дробится в тройки.
- **JSON-LD** — прагматичный компромисс: обычный JSON + `@context`, который отображает локальные ключи на глобальные IRI. **Данные читаемы и без контекста (как JSON), и машинно-совместимы с ним.** Это прямой аналог нашего замысла: payload остаётся простым, а `@context`/`schema`-ссылка даёт переносимость.
- **schema.org** — общий словарь типов; показывает ценность ОТКРЫТОГО реестра типов (= наши «типы-как-узлы»).
- **Embedded-schema форматы (Avro, Protobuf).** Avro носит схему рядом с данными → читается без внешнего знания и **эволюционирует** (schema resolution: reader/writer разных версий совместимы). Ключ для Г19: единица должна нести ССЫЛКУ на свою схему-версию (у нас уже есть `schema: type@version`).

**Минимальный набор полей переносимости** (что должно быть в паспорте, чтобы ячейку понял чужой движок):
1. `id` (глобально уникальный, ULID/IRI) — адрес.
2. `type` + `schema@version` — что это и по какой схеме читать (эволюция без ломки).
3. `epistemic` + `confidence` — статус истинности.
4. `time` (created/updated + valid-time) — темпоральность.
5. `provenance` (source/principal + цепочка) — откуда.
6. `sensitivity`/scope — кому можно.
→ **Вывод: ратифицированный тонкий паспорт (9+2) УЖЕ ≈ этот минимум.** Портируемость почти бесплатна, если payload сериализуется как JSON-LD-подобный (`@context` = ссылка на type-узел).

## 2. Provenance — происхождение как первоклассные данные

- **W3C PROV** — модель из 3 сущностей: **Entity** (данные), **Activity** (процесс, что их создал/изменил), **Agent** (кто отвечает). Рёбра: `wasGeneratedBy`, `wasAttributedTo`, `wasDerivedFrom`, `used`.
- Перенос: наши `source`/`principal` — зачаток PROV. Для Г10/Г14 (аудит «почему агент так сделал», Г9) нужна **`wasDerivedFrom`-цепочка** — из чего выведена ячейка. Это дёшево: ещё один тип ребра, не новое поле.
- **Nanopublications** — паттерн: {утверждение + его provenance + его публикационные метаданные} как ОДИН атомарный, цитируемый пакет. Прямая модель нашей «единицы памяти как самодостаточного письма».

## 3. Доверие/время на РЁБРАХ — ключ к вопросу В4

- **Property graph** (Neo4j) — у ребра свои свойства (weight, confidence, timestamp) НАТИВНО. Дёшево и прагматично.
- **RDF реификация** — чтобы сказать что-то О тройке (её уверенность/время), тройку надо «овеществить» в узел. Громоздко → породило:
- **RDF-star (RDF*)** — синтаксис «тройка как субъект другой тройки»: `<<A rel B>> confidence 0.8`. Именно то, что нужно: **метаданные на связи без превращения её в тяжёлый узел.**
- **Bitemporal** — два независимых времени: **valid-time** («истинно в реальности с…по…») и **transaction-time** («записано/действовало в базе с…по…»). Забывание = закрыть transaction-time, НЕ удаляя (Г12, «забыть ≠ удалить»). Аудит прошлого (Г9) = запрос «as-of transaction-time T».

## 4. Рекомендация

- **(а) Переносимость:** payload сериализовать в JSON-LD-стиле, где `@context` = ссылка на type-узел (control-plane). Тогда чужой движок читает ячейку, зная только протокол паспорта. Ратифицированный паспорт менять не нужно — добавить лишь конвенцию сериализации и `wasDerivedFrom`-рёбра для провенанса.
- **(б) Ребро-с-паспортом — ДА, но ТОНКИМ и АСИММЕТРИЧНЫМ:**
  - Модель — **property-graph / RDF-star**: метаданные живут НА ребре, ребро не становится полноценным узлом-гражданином по умолчанию.
  - **Мин. паспорт ребра:** `confidence · provenance(wasDerivedFrom) · valid-time · epistemic`. Это подмножество узлового паспорта, не дубль.
  - **priority остаётся отдельно** (per-parent важность ≠ confidence инсайта).
  - **Не всем рёбрам** нужен паспорт: структурным (home, facet-of) — нет; **инсайт-рёбрам** («A→B», выведенным паттернам) — да. Т.е. ребро становится «единицей памяти» ТОЛЬКО когда оно само является утверждением. Это снимает страх «вдвое больше сущностей»: паспорт несут единицы-инсайты, а не каждая ниточка графа.

**Вывод по В4:** повышаем до 1-го класса не «все рёбра», а **рёбра-утверждения**, тонким подмножеством паспорта (RDF-star-стиль). Цена умеренная, выигрыш (паттерны как первоклассное знание) — большой. Bitemporal — фундамент и для забывания, и для аудита; заложить с начала.
