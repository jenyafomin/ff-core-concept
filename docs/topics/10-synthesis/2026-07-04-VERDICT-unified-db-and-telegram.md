# ВЕРДИКТ — Единая БД + Telegram-коммуникация (2026-07-04)

## Как это было сделано (метод — по сценарию владельца)
Два Fable-агента параллельно (концепт БД / концепт Telegram), требование про плагины доброшено на лету,
затем перекрёстное ревью (каждый смотрел работу второго со своим контекстом), принятые правки внесены
авторами в свои документы (ред.2). Первый живой прогон паттерна «две сессии коммуницируют между собой».

## Итог одним абзацем
Концепты СОВМЕСТИМЫ и усиливают друг друга. Единая БД = **V3: один логический граф знаний + рантаймы
модулей + коннекторы** (одно пространство id, один паспорт ADR-0002, один движок-writer; SQLite для
структуры + md для authored-тел, в папке-«единице»). Telegram = **проекция графа**: каждое сообщение —
узел, истина в БД (Bot API истории не даёт). Стык — **Outbox**: gateway пишет только к себе (продюсер),
движок забирает асинхронно с ack (единственный writer графа) — бот не падает вместе с движком, клапан
не обходится.

## Ключевые решения (7)
1. **V3** выбран из 3 вариантов; V1 (всё в одной физической БД) ломается на плагинах окончательно; V2
   (федерация) ломает синхронность.
2. **Умные папки = 0 новых механизмов**: группа-узел + home-каскад + topic/index-типы + фасеты + паттерны;
   «не папки поумнели, а граф умеет притворяться папками».
3. **Stream-класс** (сообщения/трейсы/метрики — целиком SQLite, append-only, без md-файла на запись) —
   честная дельта №1 модели.
4. **Pack-формат экспорта подграфа** — честная дельта №2 (плагины сделали его обязательным свойством БД).
5. **Плагины ложатся на существующее**: pack с epistemic=proposal → гейт R4 (свои политики не привезёшь) →
   scope default-deny → вариации через variant-of/lineage. ADR-0003 (ABAC) становится блокером маркетплейса.
6. **Большие сообщения**: ступенчатая политика (текст ≤3500 · куски i/N ≤~7000 · резюме+md-вложение);
   README-статус = pinned-сообщение, редактируемое на месте; reply-маршрутизация по (chat_id,message_id)→узел.
7. **Redis не нужен в v1** (движок и есть кэш); ротация = 3 температуры узлами-политиками; sessions/jobs/
   leases остаются в рантайме gateway НАВСЕГДА, в граф переезжают только topics+messages.

## Найденные пробелы кода gateway (подтверждено чтением кода)
- НЕ сохраняет telegram message_id и не читает reply_to_message → reply-семантика сейчас невозможна;
- нарезки под лимит 4096 нет → подозрение владельца о падении больших сообщений ВЕРНО;
- parse_mode не задан (plain).
→ всё это — конкретные пункты в спеку доработок (Этап 3), первые два — приоритетные.

## ⚑ Развилки владельцу
**БД:** A — ратифицировать stream-класс · B — имя «единицы» (Организация/CORE/Brain; латиницей?) и переезд
@ff/core в неё · C — движок = СЕРВИС (рекомендуют оба агента; закрывает старый OQ-2 «библиотека vs сервис») ·
D — окна ретенции (30 дней?) · E — решено ревью: sessions невыносимы, messages=transitional outbox ·
F — ратифицировать default-deny для сторонних модулей + pack-формат.
**Telegram:** 1 — группировка: форум-топики (рекоменд.) vs боты vs reply-нити · 2 — порог «резюме+вложение»
~7000 симв.? · 3 — parse_mode: HTML (рекоменд.) vs MarkdownV2 · 4 — неоднозначный reply: эвристика+переспрос (рекоменд.).
