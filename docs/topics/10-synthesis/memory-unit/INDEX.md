## Ревизия скелета/дерева (твоя просьба «правильно ли описывает система себя»)

- **Дерево ≠ граф.** Цель связана с НЕСКОЛЬКИМИ ценностями; ценность — с несколькими целями. Файлы/папки дают дерево (один home), а нужен граф (много рёбер). **Это ровно то, что решает единица памяти — и чего документы не могут.** Фрактал: трек болеет диагнозом, который лечит.
- **Пока БД нет — этот INDEX работает как «граф-оверлей»:** перекрёстные ссылки (цель↔ценность↔сценарий) держим ЗДЕСЬ явно, руками. Когда появится движок — этот индекс мигрирует в рёбра `facet-of`/`covers`.
- **Правило роста дерева:** узел = либо ФИНАЛ (готовый ответ — просто файл), либо АБСТРАКЦИЯ (растёт вглубь — заводим папку заранее). Ценности — абстракции → у каждой папка с идеями/вопросами/сценариями. Так новые ветки видны и не мешают старым.

## Хребет (обновлён после классификации Fable)

Не один столп, а **три уровня:**
1. **КОНСТИТУЦИЯ** — инварианты над ячейкой (согласие референта, единый порог доступа, право на забвение).
2. **Политика ячейки (policy-as-data)** — «что я есть», ячейка носит своё поведение.
3. **Целостность-как-долг-движка (integrity-as-engine-duty)** — «что мы вместе»: категории, связи, дедуп, конфликты, циклы — только база гарантирует.
> DATA = «что я есть» · DB = «что мы вместе» · CONSTITUTION = «что нельзя нарушить».

## Крупные кандидаты в фундамент (из сценариев, L2-масштаб)

1. **Ячейка-операция** (память 2-го порядка: паспорт у АКТА над памятью) — Sonnet.
2. **Tritemporal + глагол «Переосмыслить»** (interpretation-time = недостающая механика «волны») — Opus.
3. **Наследуемое согласие (consent-taint)** — производная берёт строжайшее согласие предков (маркетплейс).
4. **4-я роль субъектности `successor/steward`** (bus factor владельца).
