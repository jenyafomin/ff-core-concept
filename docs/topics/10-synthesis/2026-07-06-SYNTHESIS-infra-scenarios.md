# Синтез: инфраструктурные решения + упущенные сценарии (5-агентный веер)

> Веер из 5 параллельных агентов (4 инфра-угла + критик полноты). Каждый читал существующий
> 16-модульный инфра-слой (`docs/02-project/core/01-brain/infrastructure/ideas/candidates.md`)
> ДО генерации, чтобы не дублировать. Сырьё — в `docs/topics/60-raw/2026-07-06-*.md`.

## СХОДЯЩИЙСЯ МЕТА-ВЫВОД (независимо у 3 из 5 агентов)

**Весь 16-модульный хребет спроектирован ОНТОЛОГИЧЕСКИ (что за сущности), но физический
WRITE-PATH и ПРИНУЖДЕНИЕ не решены ни в одном модуле.** Три независимых подтверждения:
- Хранение: нет атомарности записи и разрешения конкуренции (агент 1).
- Агент-интерфейс: «эпистемический отмыв» confidence по цепочке деривации без проверки (агент 2).
- Доверие: «клапан на необратимое» — самый цитируемый принцип, существует только как ТЕКСТ
  в CLAUDE.md, без движка/таксономии/audit (агент 3).

Общий корень: **принципы записаны как онтология и как норма-текст, но не как примитив движка.**
А проект УЖЕ работает многосессийно (топики шлюза = параллельные claude-сессии) и УЖЕ поймал
живой баг этого класса (gateway dup-kill). По правилу «заложить сейчас» — не ретрофитится.

## ПО ИНФРАСТРУКТУРАМ

### 1. Хранение и тождество
Модули: File-Truth↔Index Sync (индекс — производная, всегда пересобираем из файлов);
canonical_id Minting + Collision Registry (кто минтит офлайн, что при коллизии); **Git-native
concurrency + структурный merge** (текстовый git-merge бьёт YAML frontmatter — нужен single-writer-lock
или optimistic+structural-merge; + атомарная запись tmp+rename); Schema Migration Runner (`schema_version`,
чтение смешанных версий).
Упущено: файловая гонка двух сессий в один файл; правка .md мимо движка → тихий дрейф индекса;
оборванная запись при краше; `rm` руками → осиротевшие рёбра.

### 2. Интерфейс агент↔субстрат
Модули: Agent Write Gateway (запись = draft/nascent + provenance-ребро + optimistic-concurrency,
конфликт → узел `conflicts-with`, не overwrite); Run/Trace Ledger (трейс и промпт — узлы с версией);
Write Authorization / Trust Tiers (read-only/draft/verified/steward; verified ставит ДРУГОЙ актор);
Agent Memory as Nodes (открытый вопрос: память агента — узлы или внешнее хранилище).
⚠️ Противоречие: `core/02-agents/runs/INDEX.md` говорит «реестр — только ссылки, не тела», а
Run/Trace Ledger хочет трейс-узлом → нужно решение владельца.
Упущено (главное): **эпистемический отмыв** — гипотеза (conf 0.3) → дериват (0.7 «раз уже в графе»)
→ committed-факт без следа корня; confidence растёт по цепочке без реальной проверки.

### 3. Доверие / согласие / эпистемика
Модули: **Action Gate / клапан внешнего эффекта** (таксономии «что необратимо» НЕТ вообще;
нужен confirm-step + audit-cell; PEP гейтит чтение, Gardener — внутренние правки, внешний мир — никто);
Epistemic Status Label (`observed/inferred/agent-generated/disputed/superseded/retracted` — отдельно
от числового confidence); Referent Consent Loop (referent как ДАННЫЕ есть, ПРОЦЕССА нет); Unified
Action/Consent Audit Trail.
Упущено: аудит-трейл сам как утечка (payload стёртого остаётся в неизменяемом логе); утечка
приватного узла в АГЕНТА (агент-как-канал не типизирован); нет компенсирующего действия для уже
совершённого необратимого.

### 4. Связи и витальность
Модули: **Typed Edge Contract** (поля на тип ребра: structural/semantic, on_delete cascade/tombstone/block,
cardinality — прямо решает home↔category: `home`=1 замещение, `category`=N накопление); единый Traversal
Primitive (провенанс + consent-taint + forgetting-cascade ходят по одному lineage-графу — один сервис,
не три обхода); Vitality-на-ребре (производная от salience узлов × confidence); Архивация без потери
связей (sleep → `target-dormant`, hard-erase → tombstone; FK-инвариант: нет ребра на нерезолвящийся id).
Упущено: гонка при hard-erase (окно, где dangling-ребро восстанавливает след стёртого); масштаб 10⁴-10⁵
без индекса = O(E) на каждый каскад.
Корень-риск: **рёбра — second-class** относительно узлов (у узла паспорт/bitemporal/salience, у ребра —
никакого состояния); на целевом масштабе баг статистически неизбежен и недиагностируем.

### 5. Критик полноты — целые классы, которых НЕТ
1. **Угрозная модель стороннего плагина = 0** — при цели «маркетплейс с 1-й итерации» это дыра
   первого порядка: плагин читает referent-данные без согласия, пишет в чужие узлы, зовёт hard-erase.
2. **Prompt injection через импортированный контент** — голос/email/скан несёт инструкцию, агент-садовник
   ИСПОЛНЯЕТ вместо хранить. Не постулировано «контент никогда не директива».
3. **Экспорт/выход из системы** (импорт разобран, обратного потока нет → Суверенность декларативна).
4. **Смерть владельца операционно** (кто инициирует hard-erase от имени умершего; наследование согласия).
5. Распад совместного владения (развод/расставание) домохозяйного графа.
6. Забвение оставляет обнаружимую «полость» (разрыв в хронологии — сам по себе утечка).
7. Dry-run миграции движка на живых личных данных.

**Слишком гладкое допущение:** двухстолповый хребет (integrity-as-engine-duty + Конституция)
предполагает ОДИН доверенный движок. Но цель — «ячейка живёт в ЛЮБОМ движке» (маркетплейс).
Нет аттестации / conformance-теста / независимого от интерпретатора слоя принуждения. «Конституция»
без механизма проверки — просьба, не гарантия.

## КАНДИДАТЫ В РЕШЕНИЕ (для владельца)
1. Признать **write-path (атомарность + конкуренция + принуждение)** отдельным инфра-треком наравне
   с онтологией — иначе ретрофит невозможен.
2. Завести **таксономию необратимых внешних действий** — без неё клапан не срабатывает.
3. Ратифицировать инвариант **«confidence деривата ≤ f(confidence источников)»** движком, не паспортом.
4. Поднять **untrusted-engine/plugin threat model** — сейчас 0, а второй движок и есть цель проекта.
5. Решить противоречие Run/Trace: трейс-узел vs только-ссылка.
