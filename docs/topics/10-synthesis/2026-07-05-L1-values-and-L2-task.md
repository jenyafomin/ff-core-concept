## 1. Ревизия целей — что забыли (Г35+)

- **Г35. Композиция/фрактальная сборка.** Единицы собираются в бóльшую единицу, которая сама единица (nanopublication-обёртка, саммари-узел как гражданин). Целое читается тем же контрактом, что часть.
- **Г36. Наблюдаемость собственного метаболизма.** Единица показывает, что с НЕЙ происходило (кто читал, подтверждал, переработал) — «видно, что ИИ делает» на уровне ячейки. Трейс жизни как часть единицы.
- **Г37. Самосознание стоимости.** Единица знает свою цену доступа/верификации (дорого достать? дорого перепроверить?) — чтобы агент планировал бюджет, а не узнавал постфактум.
- **Г38. Субъективная значимость для человека.** В агрегаторе ЖИЗНИ у ячейки есть вес для владельца (эмоция, приоритет жизни) ≠ importance для системы. Отдельная ось.
- **Г39. Обратимость операций.** Любое действие над памятью (переработать/забыть/слить) откатываемо — конституционная ценность, спроецированная на единицу.

## 2. Ценности — пересборка (7 несводимых сущностей)

Заострил мои V1-V7 до однословных эссенций. Каждая — то, что «дорого» само по себе, не сводимо к другим:

| # | Ценность | Суть одной фразой | Цели |
|---|----------|-------------------|------|
| **Ц-A** | **Прозрачность** (Legibility) | понятна без вскрытия, на любом зуме, машине И человеку | Г1·Г3·Г4·Г6·Г37 |
| **Ц-B** | **Полисемия** (Polysemy) | одна истина → много ответов/проекций под разные углы | Г2·Г5·Г21·Г23·Г35 |
| **Ц-C** | **Доверие** (Living Trust) | калибровано, живёт от использования, с провенансом и защитой | Г7·Г8·Г9·Г10·Г11 |
| **Ц-D** | **Витальность** (Metabolism) | живёт во времени: меняется не теряя себя, забывает правильно, не раздувается | Г12·Г13·Г15·Г36·Г39 |
| **Ц-E** | **Суверенность** (Sovereignty) | носит себя: политику, рецепт доступа, переносимость | Г14·Г19·Г22·Г26·Г27·Г29·Г30·Г33·Г34 |
| **Ц-F** | **Реляционность** (Relationality) | связи/варианты/наследование первоклассны — ткань, не мешок | Г16·Г17·Г25·Г28·Г32 |
| **Ц-G** | **Согласие** (Consent) | знает, кому и что показать, и ЧЬЯ она | Г18·Г20·Г24·Г31·Г38 |

**Пересечения (где ценности совпадают по целям):**
- Г8 ∈ Ц-C и Ц-D (годность = и доверие, и триггер забывания) — мост Доверие↔Витальность.
- Г17 ∈ Ц-F и Ц-C (конфликт связей = сигнал доверию).
- Self-describing ∈ Ц-A, Ц-B, Ц-E (паспорт служит и прозрачности, и проекциям, и переносимости).
- Г38 (субъект. значимость) ∈ Ц-G и Ц-D (вес для человека влияет и на согласие, и на метаболизм).

## 3. Менять ли будущую «структуру поведения»? — ДА, один сдвиг

Главный вывод ресёрча: **единица носит СВОЮ политику жизни (policy-as-data).** Это меняет структуру поведения: раньше поведением памяти управлял бы внешний движок-правила; теперь **движок тонкий и лишь ИНТЕРПРЕТИРУЕТ политику, лежащую в самой ячейке** (salience-параметры, видимость, TTL, рецепт доступа). Поведение спускается из центра в ячейку. Это надо заложить в следующий этап, а не проектировать движок-командир.

## 4. Задача L2 — в каком направлении копать каждую ценность

Формат: ценность → паттерны/структуры/модели, где искать решение.

- **Ц-A Прозрачность** → progressive disclosure / иерархии саммари / эмбеддинги для дешёвого матча / JSON-LD `@context`. *(двойное попадание с Ц-E: self-describing.)*
- **Ц-B Полисемия** → проекции / материализованные представления (CQRS-read) / несколько индексов / обход графа по линзе. *(двойное с Ц-A: проекции = дешёвые виды.)*
- **Ц-C Доверие** → байесовское обновление confidence / PROV-граф провенанса / bitemporal / авторизация записи (capabilities). *(двойное с Ц-G: авторизация.)*
- **Ц-D Витальность** → salience-модель (Generative Agents × W-TinyLFU) / батч-консолидация (reflection) / bitemporal-версии / lifecycle-tiering. *(двойное с Ц-C: bitemporal.)*
- **Ц-E Суверенность** → self-describing схема (Avro/JSON-LD) / policy-as-data / foreign-data-wrapper (прокси-ячейка) / capability-токены. *(тройное: с Ц-A и Ц-G.)*
- **Ц-F Реляционность** → property-graph / RDF-star (ребро-с-паспортом) / git-ветка (варианты) / DAG+union-find (конфликты/слияния) / шаблон→экземпляр (наследование).
- **Ц-G Согласие** → ABAC/линза-политика / row-field-level security / capability-based access / tenant-изоляция. **+ ОТКРЫТО: «чья память, когда предмет — третье лицо» (Г20) — своя ветка копания, prior-art не дал.**

**«Двойные попадания» — модели, что закрывают многое сразу (кандидаты в фундамент):**
1. **Policy-as-data** (ячейка носит свою политику) → Ц-E + Ц-G + Ц-D + Ц-C. Самый мощный рычаг.
2. **Bitemporal** → Ц-D + Ц-C + Ц-F (варианты).
3. **Self-describing паспорт (JSON-LD)** → Ц-A + Ц-B + Ц-E.
4. **Тонкий движок-интерпретатор** (не командир) — архитектурный хребет под всё.
