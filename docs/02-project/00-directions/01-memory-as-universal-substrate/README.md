# D1 · Память как универсальный субстрат + policy-as-data

## Маркер узла
- **Что это:** НАПРАВЛЕНИЕ (начало: answer + insight). Растёт — вокруг лягут анализы/идеи/вопросы.
- **Scope:** GLOBAL (ядро субстрата, касается всего продукта).
- **Тип:** начало / фундамент.
- **Зависимости:** ФУНДАМЕНТ — от него зависят D2, D4, D5.
- **Статус:** draft · needs-home.
- **Предлагаемый постоянный дом:** `02-project/core/01-brain/` (спин `policy-as-data`, ур.2 Хребта) +
  `02-infrastructure/04-modules/M-G3-type-registry-policy/`. Часть якорей УЖЕ есть — вливать туда.

## Ответ владельца (вербатим-по-смыслу, N-010…N-014)
- Использовать базу ПОЧТИ ВЕЗДЕ. Двойное использование: (1) агенты её ЗАПОЛНЯЮТ; (2) САМА СИСТЕМА тоже
  понимает данные и что-то делает для владельца / показывает информацию.
- Взаимосвязи наращиваются ПО НАПРАВЛЕНИЯМ (напр. «приложения», «бухгалтерия»; бухгалтерия — большой
  объём разных связей, много математики, теоретически цепляется ко всему).
- Приложение просто ХРАНИТ данные в системе; часть данных — для агентов. Разные направления — разные вещи.
- **Приватность/безопасность = POLICY В САМОЙ БАЗЕ (policy-as-data).** Что агенты делают/не делают —
  прописано в базе. Приложение может ДОПОЛНЯТЬ и понимать. У агентской системы — свой «ЛИЧНЫЙ МОДУЛЬ»,
  в рамках которого читает полисы. Полисы: универсальные ИЛИ разные по типам/паттернам.

## Что копать (наметка для команд)
- Разрез «агенты-заполняют» ↔ «система-сама-действует/показывает» — это одна память с двумя потребителями.
- Приложение-как-хранилище: где кончается «хранит» и начинается «понимает/действует».
- policy-scoping: универсальный полис ↔ полис-по-типу/паттерну; «личный модуль» агентов, читающий полисы.
- Сверка с существующим: спин Хребта (policy-as-data) + M-G3 (реестр типов/полисы) — НЕ переоткрывать.
