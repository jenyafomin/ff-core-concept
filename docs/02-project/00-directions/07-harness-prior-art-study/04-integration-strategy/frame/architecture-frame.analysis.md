# Архитектурная рамка (Этап 1)

> **Это РАМКА, не решение.** Задача этапа — точно назвать интеграционный шов, поле кандидат-архитектур
> и оси решения, на которых Этап 2 будет делать глубокие дайвы. Ничего не выбираем. Всё — на источник.
> Внешний код read-only, не исполнялся (предохранители `_synthesis §2`).

## 0. Две реальности, между которыми стоит шов

| | Cordis / Harness (A) | Память-субстрат FF (наш тезис) |
|---|---|---|
| Где живёт истина | В **живом рантайме**: fiber-граф, service-registry, epoch-строки, isolation-labels — in-memory, восстанавливается из `cordis.patch.yml` при старте (`architecture-facts.md` #5, #13-14) | В **графе узлов**: Unit/Event/Ref, md+frontmatter «файлы-истина», связи по `id`; policy+схема = ДАННЫЕ на единице (CLAUDE.md рефрейм msg 141; ADR-0005 у Движа — `dvizh-facts.md §7`) |
| Единица композиции | ОДИН примитив: плагин `{inject?, apply(ctx)}` / `Service` (`architecture-facts.md` #2, #10, #12) | Узел графа (agent-first): задачи, метрики, память агентов, конфиги — «файл лишь один тип узла» |
| Персистентность | Своя session/state-модель, `SESSION_FORMAT_VERSION=0`, dev-preview с breaking changes (`_synthesis §1`) | Event-sourced fold («свёртка Events = текущая форма»), identity `namespace:slug` (`dvizh-facts.md §7`) |
| Портируемость | **ВНУТРИрантаймовая**: плагин переносим между bundle'ами Cordis, но `inject`-имена бессмысленны вне Cordis-Context (`architecture-open-questions.md:21-30`) | **Межрантаймовая (V5)**: единица несёт policy+схему и переживает перенос в ДРУГОЙ движок — продаваемое ядро |
| Согласие/доверие | Approval = состояние FSM (`awaiting-approval`), действует на тул-коллы/mount плагинов (`architecture-facts.md` #19) | Consent-как-данные на единице (`use_consent`/`read_consent`/`hard_erase`) — V3/V7; enforcement пока НЕ подключён |

**Ключевая асимметрия (предохранитель Q1, не потерять):** «всё-плагин» Cordis = композиция ВНУТРИ одного
рантайма (`inject`/`provide` в одном Context). Это **прецедент**, а не реализация нашей V5. Не цитировать
«strongest signal» (`architecture-and-plugin-model.analysis.md:84`) как «они решили plug-in» без этой
коррекции (`_synthesis §2.1`).

## 1. Что КОНКРЕТНО значит «посадить Harness на нашу память» (α) — разбор шва

Cordis держит своё состояние в двух местах:
1. **Живая композиция** — fiber-граф, service-registry, epoch, isolation (`architecture-facts.md` #4-9).
   Это эфемерно, пересобирается из `cordis.patch.yml` при старте. **В граф FF это НЕ ложится и не должно.**
2. **Durable state отдельных плагинов** — те из 78 строк bundle'а, что реально хранят данные:
   `session`, `workspace`, `credentials`, `schedule`, состояние `agent`
   (`architecture-and-plugin-model.analysis.md:23-26`).

«Посадить на память» = **шов проходит только через (2)**: заменить дефолтный стор этих stateful-плагинов
на адаптер-Service, читающий/пишущий граф FF. Механически это исполнимо родным словарём Cordis:

- Наша память становится **Cordis-Service** (`ctx.memory`), самрегистрируется по имени
  (`architecture-facts.md` #10); плагины объявляют `inject: ['memory', ...]`.
- Дефолтный `sessions`-плагин заменяется на `sessions`-over-memory (тот же контракт `inject`/`provide`,
  другой backend) — Cordis это штатно допускает через isolate/intercept и патч-строку
  (`architecture-facts.md` #9, #14).
- Cordis **владеет рантайм-циклом** (Fiber mount/unmount FSM, event-dispatch, agent-loop, approval-FSM,
  dynamic-plugin `cordis_define/run` — `architecture-facts.md` #16-20).
- FF **владеет durable-истиной** через адаптер за session/state.

### Точки СТЫКОВКИ (где α садится чисто)
- **S1. Service-контракт как порт.** `ctx.memory` = ровно наш «порт памяти», выраженный в их ABI
  (`Service.invoke`/`check`, `architecture-facts.md` #10). Реактивный DI сам не поднимет агента, пока
  `memory` недоступна — бесплатный gate готовности (`architecture-facts.md` #5).
- **S2. Append-only совпадает.** Их dynamic-plugin identity «versioned, never overwrite»
  (`architecture-facts.md` #17) идейно = нашему «append + supersede» (doc-tree закон 10). Их session
  fold ↔ наш Event-fold — одинаковая семантика накопления.
- **S3. Teardown-как-контракт.** `ctx.effect()` требует отдавать undo вместе с регистрацией; unmount =
  строгий LIFO (`architecture-facts.md` #6-7). Если у узла появится «cold→release ресурса» — готовый
  паттерн (Q2, `architecture-open-questions.md:52-58`). Заимствуемо ДАЖЕ без α.

### Точки ТРЕНИЯ (честно, с якорем) — вход в дайв Этапа 2
- **F1. Две власти над состоянием — где проходит линия «истины».** Наш тезис — «истина в графе». Но живая
  композиция Cordis (fiber/epoch/isolate) — это авторитетное runtime-состояние, которого В ГРАФЕ НЕТ и не
  будет (`architecture-facts.md` #4-9). α жизнеспособна ТОЛЬКО если явно принять: рантайм — одноразовый/
  пересобираемый, граф — durable-истина. Линию «что обязано жить в графе vs что Cordis может держать у себя»
  придётся резать хирургически; размытие = «две истины».
- **F2. Импеданс session/state + lock-in к их текучке.** Cordis ждёт стор своей формы
  (`SESSION_FORMAT_VERSION=0`, dev-preview, breaking changes — `_synthesis §1`). Наш адаптер обязан
  fold-ить Events → их форму и append-ить их мутации → Events без потерь. Это ORM-подобный шов поверх
  **движущейся мишени**: каждый их breaking-change бьёт по адаптеру. Lock-in не к «коду вообще», а к
  **скорости их дев-превью** (критерий C2).
- **F3. Шов согласия/политики отсутствует между действующим движком и движком-истиной.** Наши V3/V7 —
  consent как ДАННЫЕ на единице. Но действует (мутирует, зовёт тулы) — Cordis, а его approval — FSM на
  тул-коллах/mount'ах (`architecture-facts.md` #19), БЕЗ точки крепления к `use_consent`/`read_consent`/
  `hard_erase`. Это ровно тот gap, что `_synthesis §4` назвал для Движа, — в α он **наследуется**:
  носитель согласия (граф) и исполнитель (Cordis) не делят один consent-контракт. Плюс явное раскрытие
  Cordis: «sandbox — не граница безопасности; динамический код с `inject` получает реальный сервис с его
  authority, отдельного capability-gate НЕТ» (`architecture-facts.md` #21) — прямой конфликт с «клапаном
  доверия» FF.
- **F4. V5 раскалывается по слою.** Приняв α, наши агенты/сервисы становятся Cordis-плагинами —
  `inject`-связаны с именами сервисов Cordis, бессмысленны вне Cordis-Context
  (`architecture-open-questions.md:21-30`). Итог: **данные суверенны, агент/плагин-слой — заперт в Cordis.**
  Поскольку продаваемое ядро (V5, `README.md:17`) — именно «единица+экосистема, переживающая смену движка»,
  α сохраняет V5 для ДАННЫХ, но делает маркетплейс плагинов Cordis-локнутым, не FF-суверенным. Это бьёт
  прямо по «что продаём» (критерий C6).

## 2. Кандидат-архитектуры

Формат: **где истина · кто владеет рантайм-циклом · что переносимо/продаваемо · что заимствуем.**

### α — Harness НА нашей памяти (принять рантайм Cordis, backend его stateful-сервисов = граф FF)
- **Истина:** РАСКОЛОТА — durable в графе (через адаптер-сервисы), живая композиция — в рантайме Cordis.
- **Рантайм-цикл:** Cordis (fiber-FSM, dispatch, agent-loop, approval-FSM, dynamic-plugin).
- **Переносимо/продаваемо:** ДАННЫЕ переносимы; агент/плагин-слой = Cordis-плагины (V5 только внутрирантаймово);
  маркетплейс — экосистема Cordis, не FF.
- **Заимствуем:** максимум — весь рантайм + 78 плагинов + `cordis_define/run` + approval-FSM.
- **Цена:** самый быстрый путь к БОГАТОМУ рантайму, но самый медленный к НАШЕЙ-форме данных (F2) и
  наибольший lock-in к дев-превью (F2) + расколотая V5 (F4) + унаследованный consent-gap (F3).

### β — СВОЙ рантайм на нашей памяти (построить FF-рантайм; граф = субстрат)
- **Истина:** ЕДИНА в графе; рантайм — тонкий пересобираемый исполнитель над графом.
- **Рантайм-цикл:** FF (собственный луп, спроектированный под Unit/Event/Ref + consent-как-данные).
- **Переносимо/продаваемо:** полная V5 — единица несёт policy+схему, движок наш, плагины FF-нативные и
  суверенные → маркетплейс НАШ и продаваемый.
- **Заимствуем:** ПАТТЕРНЫ Cordis как словарь дизайна (реактивный DI, effect-как-undo, mount-FSM,
  approval-как-состояние, append-only versioned identity), реализованные нами, НЕ их кодом.
- **Цена:** максимум суверенности и кастомизации, ноль lock-in; но дольше всех и риск «перманентной беты»,
  если строить рантайм-с-нуля до реальных данных (антипаттерн Eval Vacuum, `_synthesis §2.3`).

### γ — ГИБРИД (владеем слоем память+суверенность; Cordis-кусок как ВНУТРЕННИЙ движок за портом FF)
- **Истина:** граф FF = истина; Cordis (или его отдельные плагины) = внутренний исполнитель КОНКРЕТНЫХ
  подсистем (sandbox, mcp, lsp, tool-exec) за портом FF.
- **Рантайм-цикл:** FF владеет ВНЕШНИМ циклом (session/consent/policy/граф); Cordis владеет ВНУТРЕННИМ
  исполнением заимствованных подсистем, запертым за одним портом.
- **Переносимо/продаваемо:** контракт памяти+агента — FF (суверенный); Cordis — сменяемый внутренний
  адаптер → V5 держится на границе, которой владеет FF; их текучка заперта в одном адаптере (гасит F2).
- **Заимствуем:** избранные плагины как вендоренные адаптеры (sandbox/mcp/lsp/`tool-cordis`) + паттерны везде.
- **Цена:** лучший баланс, но требует дисциплины границы (порт не должен протечь Cordis-семантикой наружу —
  риск, что `ctx`-Proxy/`inject` просочатся в наш контракт, `architecture-facts.md` #8).

### δ — ПАТТЕРНЫ-ТОЛЬКО / прецедент (0 кода Cordis; рантайм = уже готовый Движ SDK-runner)
- **Истина:** граф FF, единая власть.
- **Рантайм-цикл:** Движ SDK-runner — уже **approved, in-process `query()`** (ADR-0001, `dvizh-facts.md §3`),
  эволюционируем его, не строим новый.
- **Переносимо/продаваемо:** максимум суверенности, ноль Cordis-lock-in; но отказываемся от их проверенного
  рантайма и dynamic-plugin-машинерии → медленнее к богатой плагин-поверхности.
- **Заимствуем:** чистый словарь/прецедент (честное чтение `_synthesis §2.1`).
- **Почему δ честнее «просто β»:** β предполагает СТРОИТЬ новый рантайм; но рантайм у нас уже ЕСТЬ (Движ,
  ADR-0001 approved + per-tool approval-мост, `dvizh-facts.md §3, §6`). δ = «β, реализованная переиспользованием
  Движа», а не greenfield. δ — быстрее всех к реальным данным и прямо согласуется с committed-ходом владельца
  «перепись загорания на реальных эпизодах, не ещё слой» (`_synthesis §2.3, §5`).

> **Разворот δ обязателен как самостоятельный кандидат:** без него «β» тихо смешивает две разные ставки
> (строить-новый vs переиспользовать-Движ) с очень разной ценой-до-данных и разным риском беты.

## 3. Критерии решения (оси для дайва Этапа 2)

| # | Ось | Вопрос, на который отвечает дайв | Якорь |
|---|-----|----------------------------------|-------|

> Cordis) и для статус-кво (Движ), поэтому это критерий выбора, а не свойство одного варианта.
