# γ — deep dive: FF-цикл снаружи, Cordis-исполнитель внутри за ОДНИМ портом

> **Что оцениваем.** γ переворачивает α. В α наша память — ОДИН сервис среди 78 внутри рантайма Cordis,
> подчинённый его Fiber/epoch-циклу (`premise-critique.analysis.md:40-43`). В γ **наоборот**: внешним
> циклом (session · consent · policy · истина-в-графе) владеет FF; Cordis-кусок — сменный внутренний
> исполнитель КОНКРЕТНЫХ подсистем, запертый за одним FF-портом, вызываемый по запросу и снова гасимый.
> Внешний код read-only, не исполнялся.

## 1. Порт-интерфейс между FF-циклом и Cordis-исполнителем

### 1.1 Форма порта — узкий stateless request→result, инверсия Host/Client-шва Cordis

Cordis уже содержит готовый образец нужной нам границы, но с **противоположным направлением инициации**:
Host/Client общаются ТОЛЬКО lossless-JSON, направление вызова строго Client→Host
(`architecture-facts.md` #18: «only lossless JSON may cross it... The direction is Client→Host»). γ
берёт эту дисциплину шва и инвертирует роли:

- **FF = инициатор** (аналог Client-роли: владеет циклом, решает ЧТО и КОГДА исполнить).
- **Cordis-адаптер = исполнитель** (аналог Host-роли: получает запрос, исполняет подсистему, возвращает).

Шов пересекает **ровно один тип пары**:

```
FF-цикл ──ExecRequest{capability, op, args, grant}──▶ Cordis-адаптер (isolate)
FF-цикл ◀──ExecResult{status, payload:lossless-JSON, provenance}── Cordis-адаптер
```

- **`ExecRequest`** несёт: `capability` (какая подсистема — sandbox/mcp/lsp/tool-exec), `op` + `args`
  (что исполнить), и **`grant`** — уже-выданный FF-ом capability-талон (что этой операции РАЗРЕШЕНО;
  см. §1.4). Никакого `inject`-имени, никакого `ctx`-хендла, никакой ссылки в граф через шов НЕ идёт.
- **`ExecResult`** — только lossless-JSON + `provenance` (что за источник: sandbox-файл-эффект /
  внешний MCP-tool / lsp-ответ), которую FF навесит на записываемый Event (V3, §2.3).
- Порт **безсостоятельный по контракту**: между двумя `ExecRequest` Cordis не обязан ничего помнить;
  всё, что должно пережить вызов, FF уже вынул в граф. Это прямое отличие от α, где адаптер обязан
  fold-ить наши Events в их session-форму (`architecture-frame.analysis.md:80-83`, F2).

**Одной фразой:** порт = FF-инициируемый stateless-вызов `execute(capability, op, args, grant) →
lossless-JSON + provenance`, за которым Cordis-подсистема исполняет и сразу гасится, а истина остаётся у FF.

### 1.2 Что ОСТАЁТСЯ у FF (не пересекает шов, живёт в графе)

Истина и всё, что несёт V-семантику, — на стороне FF, ДО и ПОСЛЕ порта:

- **session / внешний цикл агента** — FF (не Cordis session `SESSION_FORMAT_VERSION=0`; его вообще не
  трогаем — см. §2.2). Это гасит корень F2.
- **consent-как-данные** (`use_consent`/`read_consent`/`hard_erase`) и **policy** — на единице графа,
  проверяются FF ДО делегации (§1.4).
- **истина/провенанс** — Event-fold графа FF; результат порта становится Event'ом ПОСЛЕ возврата.
- **тождество** (`canonical_id`/`namespace:slug`), **рёбра-как-память**, **витальность** — граф FF.

### 1.3 Какие подсистемы Cordis реально стоит держать за портом — и какие НЕТ

Критерий отбора: **самодостаточность + отсутствие Cordis-семантики истины/согласия**. Держим то, что
является commodity capability-seam (`capabilities-facts.md:36-38` — «Service Def/Provider/Consumer»),
а не композиционным движком.

**ДА, за портом (вендоренные адаптеры — коммодити, не наше ядро):**

| Подсистема | Почему годна за портом | Якорь |
|---|---|---|
| **sandbox** (`ctx.sandbox.confine(argv, policy)`) | Нативный launcher (bwrap/Landlock/Seatbelt, ~300 строк C11), fail-closed `SANDBOX_UNAVAILABLE`, вокабуляр политики = ТОЛЬКО файловые эффекты — чистый исполнитель без состояния и без истории | `capabilities-facts.md:178-196` |
| **mcp-client** | Чистый stdio/HTTP-мост: `mcp__<server>__<tool>`; сам «не качает сервер, не мигрирует данные, не супервизит сервис»; вычищает креды из child-env перед запуском | `capabilities-facts.md:154-165` |
| **lsp** (`dsh-tool-lsp` + `dsh-lsp-stdio`) | Код-интеллект через stdio-провайдер — детерминированный ответ на запрос, истины не держит | `capabilities-facts.md:138` |
| **tool-exec** (bash/pwsh/fs/grep одноразовые) | Единичный эффект «исполни argv» — но ТОЛЬКО под `grant` FF (§1.4); результат → Event | `capabilities-facts.md:131-137` |

**НЕТ, НЕ за портом (здесь Cordis-семантика протечёт наружу — риск границы γ):**

- **agent-loop / dynamic-plugin (`cordis_define/run`)** — это ИХ композиционный цикл; отдать его за порт
  = вернуться к α (Cordis владеет циклом). Внешний цикл — FF. `architecture-facts.md` #16-20.
- **session / workspace / schedule / состояние agent** — durable-истина, дом = граф FF, не их стор
  (`architecture-and-plugin-model.analysis.md:23-26`, цит. во `frame §1`).
- **approval-FSM** (`awaiting-approval`, `architecture-facts.md` #19) — approval действует на тул-коллы
  внутри ИХ машины и НЕ крепится к consent-как-данные (§4-gap). Гейт согласия — на стороне FF, ДО порта.
- **credentials** — секретный шов остаётся у FF; в `ExecRequest` секрет не кладём (мост mcp сам вычищает
  `DSH_*`/cred-переменные, `capabilities-facts.md:163` — совпадает с нашим направлением).

### 1.4 Где consent/policy проверяются — НА НАШЕЙ стороне ДО делегации

Ключевая инверсия γ против α/F3: **носитель согласия (граф) и исполнитель (Cordis) больше НЕ делят
один рантайм; между ними стоит FF-гейт.** Последовательность одного действия:

```
[1] FF читает единицы графа, вовлечённые в операцию
[2] FF проверяет consent-как-данные (use_consent≠read_consent, hard_erase) + policy единицы   ← V7/V3, наш код
[3] FF выдаёт capability-GRANT (что именно этой операции разрешено: какие файлы/какой MCP-tool/лимиты)
[4] FF ──ExecRequest{..., grant}──▶ порт ──▶ Cordis-подсистема исполняет ПОД grant (напр. sandbox policy = проекция grant)
[5] Порт ──ExecResult──▶ FF записывает Event с provenance (V3) и обновляет граф (истина)
```

Это прямо закрывает раскрытую дыру Cordis: «sandbox — НЕ граница безопасности; динамический код с
`inject` получает реальный сервис с его authority, отдельного capability-гейта НЕТ»
(`architecture-facts.md` #21). В γ capability-гейт СУЩЕСТВУЕТ — он у FF, ДО порта; `SandboxMode`
(`read-only`/`workspace-write`, `capabilities-facts.md:180`) становится **листом-энфорсером** решения FF,
а не самим решением. Cordis никогда не видит граф, consent-данные и не получает голую authority — только
уже-обрезанный grant.

> **Честная граница (V7).** γ даёт согласию лучший ДОМ (гейт до делегации), но НЕ даёт enforcement
> бесплатно: сам consent-энфорсмент в движке FF пока не подключён — только форма (правило
> `recursive-orchestration-method.md`, V7-нота; `_synthesis §4`). γ localizes gap, не растворяет его.

## 2. Как истина остаётся в графе, пока Cordis живёт

### 2.1 F1 «рантайм одноразовый, граф durable» — правило и его механизм

Живая композиция Cordis (fiber-граф, service-registry, epoch, isolate) — авторитетное runtime-состояние,
которого в графе нет и не будет (`architecture-frame.analysis.md:75-78`, F1). В γ это НЕ конфликт, а
дизайн: **Cordis-подсистема поднимается на время исполнения `ExecRequest` и гасится строгим LIFO-teardown**
через её же родной примитив — `ctx.effect()` отдаёт disposer вместе с регистрацией, `_unload()` разматывает
в обратном порядке (`architecture-facts.md` #6-7). Правило:

- **Durable (система записи) = граф FF.** Всё, что «произошло и должно пережить» — пишется Event'ом FF
  ПОСЛЕ возврата порта (шаг [5]). Cordis in-memory композиция **никогда не система записи**.
- **Disposable (scratch) = рантайм Cordis.** Fiber/epoch/registry пересобираемы; если процесс упал —
  теряется только scratch, истина в графе цела. Их «versioned, never overwrite» (`architecture-facts.md`
  #17) идейно совпадает с нашим append+supersede, но мы его НЕ импортируем в граф — граф ведёт свой Event-fold.

### 2.2 F2 «импеданс session/state + lock-in к дев-превью» — гасится тем, что мы НЕ берём их session

Корень F2 в α: адаптер обязан fold-ить Events↔их session-форму (`SESSION_FORMAT_VERSION=0`, dev-preview)
— ORM поверх движущейся мишени, каждый breaking-change бьёт по адаптеру (`architecture-frame.analysis.md:79-83`).

**γ вырезает этот шов целиком:** порт stateless (§1.1), FF **не адаптирует их session вообще** — session
внешнего цикла ведёт FF. `SESSION_FORMAT_VERSION=0` и его breaking-changes становятся **невидимы графу**,
потому что их session-стор в γ не используется как истина (он — их внутренний scratch, если вообще нужен
подсистеме). Blast-radius их breaking-change сжимается с «наша схема данных» (α) до «один адаптер-файл на
подсистему» (γ).

**Изоляция адаптера (не даём Cordis-семантике протечь наружу — риск границы γ):**

- **`ctx.isolate(name, label)`** (`architecture-facts.md` #9): Cordis-подсистема живёт в ДОЧЕРНЕМ контексте,
  родитель (наш) не мутируется. Порт — единственный шов; `ctx`-Proxy/`inject`-имена
  (`architecture-facts.md` #8) остаются ЗА портом и в наш контракт `ExecRequest/ExecResult` не входят.
- **Пиннинг версии:** Cordis уже вендорен, не npm-чёрный-ящик (`architecture-facts.md` #1) — γ пинит
  конкретный rc (`0.1.1-rc.2`, `capabilities-facts.md:12`), апгрейд — осознанное действие, не авто-дрейф.
  Операционный lock-in сжимается до «мы выбираем, когда синкать один адаптер», а не «гонимся за их
  дев-превью-темпом» (снимает то, что `premise-critique.md:66-72` назвал операционным lock-in α).

## 3. Стоимость / усилие — что строим сами

| Строим сами | Объём | Комментарий / якорь |
|---|---|---|
| **Порт-контракт** `execute(capability,op,args,grant)→JSON+provenance` | S (малый) | Узкий типизированный request/response; форму заимствуем у их Host/Client-шва (`architecture-facts.md` #18), инвертируем инициацию |
| **Cordis-адаптер за портом** (sandbox + mcp + lsp + tool-exec) | M (средний) | Обернуть `ctx.sandbox.confine`, mcp stdio-мост, lsp-провайдер под FF-порт; держать `isolate()`-границу; пиннинг. Ongoing sync-долг ОГРАНИЧЕН адаптером |
| **Consent-шов V3/V7** (гейт до делегации + provenance на результат) | M-L | **Net-new при ЛЮБОМ α/β/γ** (`rubric §3`: «главный актив строить самим в любом случае»). γ даёт ему чистый дом (§1.4). Форма есть, enforcement строить |

**НЕ строим (заимствуем как вендоренные подсистемы/паттерны):**

- Нативные sandbox-launcher'ы (bwrap/Landlock/Seatbelt/ACL, C11) — берём готовыми (`capabilities-facts.md:182-196`).
- MCP stdio/HTTP-мост, lsp-провайдеры — готовые подсистемы.
- Generic reactive-DI, Fiber-FSM, LIFO-teardown-инфра — НЕ наше ядро; в γ они остаются ВНУТРИ адаптера,
  наружу (в наш цикл) не выносятся (в отличие от α, где они — наш рантайм).

**Итог по цене:** γ дороже δ (надо построить порт+адаптер+consent-шов до ценности) и дешевле β по
подсистемам (sandbox/mcp/lsp не изобретаем). Sync-долг чужого дев-превью **есть, но ограничен адаптером**,
не бьёт по графу.
