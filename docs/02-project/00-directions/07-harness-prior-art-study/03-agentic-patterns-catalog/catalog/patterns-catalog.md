### Reasoning
- **Adaptive Compute Allocation** — Allocate inference-time compute (thinking tokens, samples, depth, model size) per query based on input difficulty, rather than using a fixed budget across all queries. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/adaptive-compute-allocation.md))
- **Attentive Reasoning Queries** — Replace free-form chain-of-thought with a domain-tailored sequence of structured queries that re-anchor the model's attention to the critical instructions and prior decisions at the exact generation steps where adherence tends to slip. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/attentive-reasoning-queries.md))
- **Chain of Thought** — Elicit multi-step reasoning by prompting the model to produce intermediate steps before its final answer. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/chain-of-thought.md))
- **Chain of Verification** — Reduce hallucination by drafting an answer, generating independent verification questions, answering them in isolation, and revising. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/chain-of-verification.md))
- **Extended Thinking** — Spend a configurable budget of internal reasoning tokens before producing a user-visible answer. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/extended-thinking.md))
- **Generate-and-Test Strategy** — Generate multiple candidate solutions in parallel, then systematically test each against declared constraints rather than committing to the first plausible one — adapted from Langley & Simon's cognitive-science research on human expert problem-solving. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/generate-and-test-strategy.md))
- **Graph of Thoughts** — Model reasoning as an arbitrary DAG so thoughts can be merged, refined, and aggregated across branches. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/graph-of-thoughts.md))
- **Large Reasoning Model (LRM) Paradigm** — Route reasoning-heavy tasks to a reasoning-tuned model that trades inference time for deliberation, rather than to a fast LLM that exhibits premature-closure. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/large-reasoning-model-paradigm.md))
- **Latent-Space Reasoning** — Let the model reason in continuous hidden-state space instead of decoding each step to text, feeding the last hidden state back as the next input embedding, so one latent step can hold several continuations. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/latent-space-reasoning.md))
- **Least-to-Most Prompting** — Decompose a hard problem into an ordered list of easier subproblems, then solve them sequentially with each answer feeding the next. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/least-to-most.md))
- **Recursive Language Model** — Treat an over-long prompt as an environment the model navigates by code, letting it partition and recursively call itself over snippets, so it answers over inputs far larger than its context window. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/recursive-language-model.md))
- **ReST-EM** — Iterate generate → reward-filter → fine-tune to bootstrap reasoning capabilities without human-labelled data. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/rest-em.md))
- **Self-Ask** — Have the model emit explicit follow-up sub-questions, answer them (optionally via search), then compose the final answer. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/self-ask.md))
- **Socratic Questioning Agent** — Drive the agent toward its goal by asking the user a sequence of strategic, open-ended questions that surface the user's own latent knowledge, goal, or context — rather than producing an answer directly. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/socratic-questioning-agent.md))
- **STaR Bootstrapping** — Bootstrap a model's reasoning by training it on its own correct chain-of-thought outputs. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/star-bootstrapping.md))
- **Test-Time Compute Scaling** — Allocate more inference-time compute (samples, search, deeper thinking) instead of scaling parameters to improve quality. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/test-time-compute-scaling.md))
- **Trajectory-Summary Test-Time Scaling** — When an agent's outputs are extended action-observation trajectories rather than short answers, scale test-time compute by compressing each rollout into a structured summary and selecting or reusing across those summaries instead of raw traces. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/rollout-summary-test-time-scaling.md))
- **Tree of Thoughts** — Search over a tree of partial reasoning states with explicit lookahead, evaluation, and backtracking. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tree-of-thoughts.md))
- **Zero-Shot Chain-of-Thought** — Elicit step-by-step reasoning with a single trigger phrase rather than few-shot exemplars. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/zero-shot-cot.md))

### Planning & Control Flow
- **Adaptive Branching Tree Search** — At each node of an inference-time search tree, use Thompson sampling to decide whether to deepen an existing answer or branch a fresh attempt, optionally choosing per-node which underlying LLM to invoke. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/adaptive-branching-tree-search.md))
- **Agentic Behavior Tree** — Borrow the behavior-tree formalism: leaves are LLM calls or tools that return success/failure; a tree of selectors and sequences orchestrates control flow. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agentic-behavior-tree.md))
- **Behavior Tree Back Chaining** — Construct an agent's behavior tree starting from the desired goal condition and recursively adding child nodes whose post-conditions satisfy each parent's pre-conditions. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/behavior-tree-back-chaining.md))
- **Clone Fan-Out Research** — Spawn 100 or more identical, full-capability agent instances in parallel — each a complete general agent rather than a role-specialised worker — and aggregate their independent outputs into a single answer. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/clone-fan-out-research.md))
- **Decision Context Maps** — Before any consequential decision, require the agent to gather a declared set of contextual inputs (resource availability, schedules, downstream dependencies) into a 'context map' the decision must cite. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/decision-context-maps.md))
- **Deterministic Control Flow, Not Prompt** — Branching decisions live in deterministic application code while the LLM is invoked at strategic points to produce structured signals that the code branches on. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/deterministic-control-flow-not-prompt.md))
- **Disambiguation** — Have the agent ask a clarifying question before acting on an ambiguous request. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/disambiguation.md))
- **Distributed Constraint Optimization** — A group of agents jointly assigns values to shared variables to minimise (or maximise) a global cost defined by inter-agent constraints, exchanging only the messages needed. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/distributed-constraint-optimization.md))
- **Event-Driven Agent** — Trigger the agent on external events (webhooks, message queues, file changes) instead of user requests or schedules. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/event-driven-agent.md))
- **Exploration vs Exploitation** — Balance taking the best-known action (exploit) with trying alternatives that might be better (explore). ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/exploration-exploitation.md))
- **Goal Decomposition** — Decompose a goal into sub-goals recursively until each leaf is directly actionable. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/goal-decomposition.md))
- **Hybrid HTN + Generative Agent** — Hierarchical Task Network decomposition provides the procedural backbone; the generative LLM is invoked only at leaf nodes for the parts of the task that are genuinely open-ended. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hybrid-htn-generative-agent.md))
- **Incremental Model Querying** — Generate plan steps by sequentially querying the model at each step rather than producing the whole plan upfront in one call. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/incremental-model-querying.md))
- **Iteration Node** — Express map-over-collection inside a visual workflow as an explicit Iteration node that runs a subgraph once per element of an input array, with bounded, deterministic, observable execution. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/iteration-node.md))
- **Language Agent Tree Search** — Lift the agent loop into a search tree with a learned value function and backtracking. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/lats.md))
- **LLMCompiler** — Take ReWOO's plan-as-DAG and run independent steps in parallel through a task-fetching dispatcher. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/llm-compiler.md))
- **Local-to-Cloud Handoff** — Promote an interactive local agent session mid-task to a detached cloud agent that keeps running after the developer disconnects and reports back asynchronously. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/local-to-cloud-handoff.md))
- **MapReduce for Agents** — Split an oversize task into independent chunks, process each in parallel, then aggregate. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/map-reduce.md))
- **Mental-Model-In-The-Loop Simulator** — Run candidate multi-step strategies inside an internal simulator of the environment before committing in the real world — broader than simulate-before-actuate (single action) by simulating multi-step strategies. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/mental-model-in-the-loop-simulator.md))
- **Multi-Path Plan Generator** — Generate multiple candidate next-steps at each plan node enabling later selection — the planning generator pattern paired with tree-of-thoughts / LATS-style search. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/multi-path-plan-generator.md))
- **Outer-Inner Agent Loop** — Run two nested loops: an outer planner agent decomposes the goal into subtasks; an inner executor runs a ReAct loop on each, and the outer can replan based on the inner's progress. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/outer-inner-agent-loop.md))
- **Partial Global Planning** — Each agent maintains a partial view of others' plans and incrementally merges local plans into a shared partial global plan, interleaving coordination with execution. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/partial-global-planning.md))
- **Passive Goal Creator** — Analyse the user's articulated prompts and accompanying context to derive a precise, actionable goal before any planning or tool use begins. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/passive-goal-creator.md))
- **Plan-and-Execute** — Plan all the steps once with a strong model, then execute each step with a cheaper model under the plan. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/plan-and-execute.md))
- **Planner-Executor-Observer** — Add an explicit Observer role between Planner and Executor so progress is checked against the plan instead of trusted blindly. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/planner-executor-observer.md))
- **Planner-Generator-Evaluator Harness** — Decompose a long-running job into three role-isolated agents — a Planner emitting a feature list, a Generator working one chunk per fresh context, and an Evaluator grading against a rubric without seeing the Generator's trace. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/planner-generator-evaluator-harness.md))
- [Pre-Flight Spec Authoring](patterns/pre-flight-spec-authoring.md) *(a.k.a. Spec-Driven Development (authoring phase), SDD authoring, Pre-Implementation Specification)* — Before any code is generated, author a multi-pillar spec and have the agent critique it for ambiguity and edge cases, so that the loop executes against a reviewed target rather than a fresh prompt.
- **Proactive Goal Creator** — Anticipate the user's goal by capturing surrounding multimodal context (gestures, screen state, environment) in addition to what the user types or says. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/proactive-goal-creator.md))
- **Query-Decomposition Agent** — An agent whose explicit job is to split an incoming user query into smaller independent sub-queries that can be answered sequentially or in parallel, then merge results. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/query-decomposition-agent.md))
- **ReAct** — Interleave a single thought, a single tool call, and a single observation per step so the agent reasons over fresh evidence. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/react.md))
- **Replan on Failure** — Trigger a fresh planning step when execution evidence contradicts the current plan. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/replan-on-failure.md))
- **ReWOO** — Plan a complete dependency DAG with placeholder variables before any tool runs, then execute and substitute observations into the plan. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/rewoo.md))
- **Rumination Agent** — Run a single agent through a protracted think-search-verify-revise-act loop spanning hundreds of tool calls, autonomously re-formulating hypotheses across the run. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/rumination-agent.md))
- **Scheduled Agent** — Run the agent on a fixed schedule independent of user requests. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/scheduled-agent.md))
- **Single-Path Plan Generator** — Generate one linear sequence of intermediate steps from current state to goal — the lightweight planning alternative to tree-of-thoughts and multi-path generation. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/single-path-plan-generator.md))
- **Spec-Driven Loop** — Run the same prompt against a fixed spec in a deterministic outer loop until the spec is satisfied. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/spec-driven-loop.md))
- **Spec-First Agent** — Drive the agent loop from a human-authored specification document rather than free-form prompts. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/spec-first-agent.md))
- **Speculative Agentic Actions** — Predict the tool calls the agent is most likely to issue next and execute them preemptively on the current turn, then keep the results that the confirmed trajectory needs and discard the rest. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/speculative-agentic-actions.md))
- **Standing State Injection** — Recompute a compact task-state snapshot each turn and inject it as a fresh system block before the model reasons, so a long tool-call loop stays oriented on the goal. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/standing-state-injection.md))
- **Stateless Reducer Agent** — Design the agent as a pure function (state, event) → newState; entire execution history is held in an external event log; enables pause / resume / replay / time-travel without bespoke checkpointing. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/stateless-reducer-agent.md))
- **Strategic Preparation Phase** — Mandate an explicit problem-space representation step before the agent attempts solutions, mirroring how expert humans build a mental model of constraints and dependencies before solving. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/strategic-preparation-phase.md))
- **Todo-List-Driven Autonomous Agent** — Have the agent author a plan file (e.g. todo.md) early in the run, tick items as it completes them, and re-inject the remaining plan into context; the file is durable plan and working memory. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/todo-list-driven-agent.md))
- [Tool-Result Reinforcement](patterns/tool-result-reinforcement.md) *(a.k.a. Reinforcement (tool-return), Enriched Tool Return, Tool-Return Re-grounding)* — Append a goal reminder, current task status, and failure or next-step hints to each tool return so the agent is re-grounded through the action channel it already reads.
- **Two-Rate Cloud-Brain / Edge-Controller Split** — Run a slow planner at low frequency that emits a compact latent plan, and a small on-device controller that tracks it at the robot's native control rate without ever blocking on the planner. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/two-rate-brain-controller-split.md))
- **Visual Workflow Graph** — Express agentic logic as a visual graph of typed nodes connected on a canvas with Start and End nodes so non-coding stakeholders can read and edit the flow. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/visual-workflow-graph.md))

### Tool Use & Environment
- **Affordance Grounding Before Action** — Have a vision-language model ground each candidate action against the current scene and predict its affordance, so that actions the environment cannot physically support are discarded before any reach the controller. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/affordance-grounding-gate.md))
- **Agent Adapter** — An interface layer connecting an agent's tool-calling protocol to heterogeneous external tools, normalizing their schemas into one the agent expects. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-adapter.md))
- **Agent Skills** — Package author-time procedures (markdown + optional resources) the agent loads on demand for specific task types. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-skills.md))
- **Agent-Computer Interface** — Design the tool surface for an LLM agent specifically, with affordances different from human-facing CLIs. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-computer-interface.md))
- **Agent-Initiated Payment** — Give an agent a bounded wallet so it can settle a payment mid-request to unlock a resource — answering a payment-required challenge with a verifiable proof — instead of routing every purchase through a human. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-initiated-payment.md))
- **Agent-Readable Commerce Surface** — Expose a service to agent buyers through a machine-readable product feed and an agent-initiated checkout API rather than a human click funnel, so an agent can discover, compare, and buy against a goal. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-readable-commerce-surface.md))
- **App Exploration Phase** — Before deploying an agent against an opaque app, have it explore (or watch a human demonstrate) the app, generating a per-element documentation knowledge base; at deployment, retrieve element docs to ground actions. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/app-exploration-phase.md))
- **Async Tool Handle** — Have a slow tool return a job handle immediately and expose a separate poll tool for the result, so the agent loop never blocks past a tool-call timeout. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/async-tool-handle.md))
- **Augmented LLM** — Build the foundational agent block as an LLM augmented with retrieval, tools, and memory that the model actively chooses to use, rather than a bare-model call. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/augmented-llm.md))
- **Browser Agent** — Expose websites to the agent through a structured DOM/accessibility tree plus a small action vocabulary, sitting between raw HTML and pixel-level Computer Use. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/browser-agent.md))
- **Canonical-Entity Grounding** — Require the agent to resolve every business identifier it uses — SKU, account, supplier, customer — through an authoritative lookup against the system of record, rather than emitting the identifier from the model's parametric memory. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/canonical-entity-grounding.md))
- **Code Execution** — Let the model emit code, run it in a sandbox, and treat the run as the answer instead of trusting the model to compute in its head. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/code-execution.md))
- **Code-as-Action Agent** — Have the agent emit a code snippet as its action each step, executed in a constrained interpreter, instead of emitting JSON tool calls; tool composition becomes function nesting and control flow inside the snippet. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/code-as-action.md))
- **Composite Service** — Expose one MCP tool that orchestrates several underlying API calls into a single higher-level operation, so the agent invokes a task-level capability instead of chaining many low-level endpoints. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/composite-service-mcp.md))
- **Computer Use** — Let the model drive a desktop end-to-end via screenshots plus virtual mouse/keyboard tool calls instead of bespoke per-app APIs. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/computer-use.md))
- **Crawler Dispatcher** — Route each incoming URL to a domain-specific crawler through a central dispatcher mapping URL patterns to registered crawler classes. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/crawler-dispatcher.md))
- **Direct API Wrapper** — Expose an existing API as MCP tools by mapping each operation one-to-one to a tool, so a stable API becomes agent-callable with minimal wrapper logic. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/direct-api-wrapper.md))
- **Dual-System GUI Agent** — Split a GUI agent into a decision model that plans and recovers from errors and a grounding model that observes pixels and emits the precise action; route each subproblem to the better-suited model. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/dual-system-gui-agent.md))
- **Full-Desktop Computer Use** — Give the agent a complete containerized OS desktop with native apps, a persistent filesystem, and desktop credential stores, so it can finish multi-application workflows a browser-only surface cannot. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/full-desktop-computer-use.md))
- **Hierarchical Tool Selection** — Organise tools into a tree of categories so the agent first picks a branch and then a specific tool within it. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hierarchical-tool-selection.md))
- **Large Action Models (LAMs)** — Use a model class specifically trained for action execution (tool calls, UI navigation, workflow steps) rather than text generation, when the workload is dominated by reliably completing actions in real systems. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/large-action-models.md))
- **MCP Bidirectional Bridge** — Run a framework as both MCP client (consuming external MCP servers as tools) and MCP server (publishing its own agents, tools, and workflows back over MCP) so capabilities flow both directions across the protocol boundary. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/mcp-bidirectional-bridge.md))
- [MCP Server-Side Sampling](patterns/mcp-server-side-sampling.md) *(a.k.a. Reasoning Inversion (MCP), createMessage Callback)* — Let an MCP server, mid-tool-call, send a prompt back to the host through createMessage and use the host's model so the server does language work without holding its own model or key.
- **MCP-as-Code-API** — Materialize MCP servers as a directory of typed code wrappers so the agent writes code that imports them and large tool outputs flow between calls inside the sandbox without ever entering the model's context window. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/mcp-as-code-api.md))
- **Mobile UI Agent** — Drive a smartphone end-to-end through a small, touch-native action vocabulary (tap, long-press, swipe, type, back, home) over screenshots, as a distinct interaction surface from desktop Computer Use and from web Browser Agents. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/mobile-ui-agent.md))
- **Model Context Protocol** — Standardise how agents discover and call tools so that a tool written once is usable by any conformant agent. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/mcp.md))
- **Multilingual Voice Agent Stack** — Compose a voice agent as a tightly co-located pipeline of speech-to-text, language-aware LLM reasoning, and text-to-speech, where one vendor owns all three so language and dialect propagate cleanly across stages. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/multilingual-voice-agent.md))
- **On-Demand Tool Synthesis** — When no available tool fits a subtask, have the agent write, validate, and register a new tool on the spot, separating the tool-creating role from the tool-using role. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/on-demand-tool-synthesis.md))
- **Policy-Localizer-Validator** — Split a GUI agent into three specialist models — a Policy that plans, a Localizer that grounds elements to pixels, and a Validator that judges completion — so each role uses the smallest sufficient model. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/policy-localizer-validator.md))
- **Prompt Caching** — Order prompts so the unchanging prefix can be cached by the provider, cutting per-call cost and latency. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/prompt-caching.md))
- **Sandbox Isolation** — Run agent-emitted code or actions in a contained environment with restricted filesystem, network, and process privileges. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/sandbox-isolation.md))
- **Semantic-Layer Query Guardrail** — Route natural-language data questions through a curated semantic layer so the model selects and parameterises vetted metrics and dimensions instead of free-authoring raw SQL against production data. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/semantic-layer-query-guardrail.md))
- **Shadow Workspace** — Mirror the workspace into an isolated, version-controlled shadow where the agent makes and reverts edits, surfacing diffs for review and promoting only accepted changes to the real tree. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/shadow-workspace-vcs.md))
- **Skill Library** — Let the agent grow its own toolkit by writing reusable skills that subsequent runs can call. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/skill-library.md))

### Retrieval & RAG
- **Agentic RAG** — Replace static retrieve-then-generate with autonomous agents that plan, choose sources, retrieve iteratively, reflect, and re-query. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agentic-rag.md))
- **CDC-Driven Vector Sync** — Treat the source-of-truth document store as the only writer; keep the vector index in sync by emitting change-data-capture events onto a queue that the feature pipeline consumes. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/cdc-vector-sync.md))
- **Citation Attribution** — Track and surface, alongside a RAG-grounded answer, which retrieved chunks supported which claims, so the binding between answer span and source survives all the way to the user. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/citation-attribution.md))
- **Contextual Retrieval** — Prepend a short LLM-generated description to each chunk before embedding so the chunk carries its situating context. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/contextual-retrieval.md))
- **CRAG** — Add a lightweight retrieval evaluator that grades each retrieved document and triggers corrective web search on poor retrievals. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/crag.md))
- **Cross-Encoder Reranking** — After cheap bi-encoder or BM25 retrieval, rescore top-N candidates with a cross-encoder that jointly attends over (query, candidate). ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/cross-encoder-reranking.md))
- **Dependency-Aware Skill Retrieval** — Retrieve from a large skill library by returning each relevant skill together with its prerequisite dependency closure as an ordered subgraph, so the bundle the agent receives is executable rather than topically relevant but incomplete. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/dependency-aware-skill-retrieval.md))
- **GraphRAG** — Build an LLM-extracted entity-and-relation knowledge graph plus hierarchical community summaries, then answer global queries via map-reduce over those summaries. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/graphrag.md))
- **Hierarchical Retrieval** — Route a query through a multi-level cascade — coarse source or index selection, then per-source narrower retrieval, then chunk-level — so each retrieval decision is pushed to the cheapest tier that can answer it. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hierarchical-retrieval.md))
- **HippoRAG** — Build an LLM-extracted schemaless knowledge graph from the corpus and run Personalized PageRank seeded on the query's key concepts so multi-hop retrieval completes in a single pass. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hippocampus-rag.md))
- **Hybrid Search** — Combine sparse lexical retrieval (BM25) with dense vector retrieval and fuse the results. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hybrid-search.md))
- **HyDE** — Have the LLM write a hypothetical answer document, embed it, and use it as the retrieval query. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hyde.md))
- **Modular RAG** — Decompose RAG into a typed three-layer hierarchy of Module Types, Modules, and Operators so the pipeline (routing, scheduling, fusion, retrieval, post-retrieval, generation) can be rearranged per query rather than running a fixed linear retrieve-then-generate. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/modular-rag.md))
- **Naive RAG** — Condition the generator on top-k chunks retrieved from an external dense index so knowledge lives outside parameters. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/naive-rag.md))
- [Query Rewriting](patterns/query-rewriting.md) *(a.k.a. Multi-Query Retrieval, Query Expansion, Query Reformulation, RAG-Fusion (query side))* — Use an LLM to generate several alternative formulations of the user's query, retrieve documents for each, and rank-fuse the results so recall does not depend on one phrasing.
- **RAFT** — Train the model to ignore irrelevant retrieved documents (distractors) in a domain-specific RAG setting. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/raft.md))
- **Repo Map** — Give the agent a compact, ranked map of the codebase's symbols and their dependencies so it orients on what matters before reading any files. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/repo-map-context.md))
- **Self-RAG** — Fine-tune the model to emit reflection tokens that decide when to retrieve, evaluate retrieved relevance, and assess generated support. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/self-rag.md))
- **Semantic Response Cache** — Embed each query and, when its nearest cached neighbour is within a similarity threshold, return the stored answer instead of re-running the model so near-duplicate questions are answered cheaply. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/semantic-response-cache.md))
- **Streaming Feature Pipeline** — Process raw documents into RAG features as a continuous stream rather than a batch job, with typed models pinning each stage. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/streaming-feature-pipeline.md))
- **Table-Augmented Generation** — Answer a natural-language question over a database in three stages — synthesise an executable query, run it against the data layer with model calls embedded in execution, then generate the answer from the result. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/table-augmented-generation.md))
- **Tacit-Knowledge Elicitation Agent** — Run a front-loaded phase in which an agent interviews domain experts and converts their undocumented know-how into a structured, queryable knowledge base before downstream task agents read from it. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tacit-knowledge-elicitation-agent.md))
- **Vectorless Reasoning-Based Retrieval** — Retrieve by having the model reason its way down a document's own table-of-contents tree to the relevant sections, instead of embedding chunks and ranking them by vector similarity. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/vectorless-reasoning-retrieval.md))

### Memory
- **Adaptive Memory Decay** — Give each long-term memory item a retention score that decays over time through a function modulated by relevance, access frequency, and recency, so unreinforced items fade or fuse while items that are used persist. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/adaptive-memory-decay.md))
- **Agentic Memory** — Expose memory management as first-class tool actions (ADD, UPDATE, DELETE, RETRIEVE, SUMMARY, FILTER) the LLM chooses at every step, trained end-to-end so short-term and long-term memory live under one learned policy. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agentic-memory.md))
- **Append-Only Thought Stream** — Make the agent's thought log append-only so the agent cannot rewrite its own history. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/append-only-thought-stream.md))
- **Co-Located Memory Surfacing** — Surface relevant persistent memories proactively when the human mentions a concrete entity the agent has prior knowledge of, so the human does not bear the burden of remembering to ask. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/co-located-memory-surfacing.md))
- **Context Compaction** — When the context window nears its limit, replace the older conversation span with a model-written digest that preserves decisions, commitments, and active constraints while discarding noise, so the agent keeps running without losing the thread. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-compaction.md))
- **Context Folding** — Let the agent branch into a temporary sub-context for a subtask and fold it back into a short summary on completion, so a long-horizon task stays within a small active window. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-folding.md))
- **Context Window Dumb-Zone Cap** — Hold context-window utilization below a working threshold (~40%) to keep the model out of the 'dumb zone' where it begins ignoring earlier instructions and hallucinating. - **Context Window Packing** — Choose what fits in the context window each turn given a fixed token budget. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-window-packing.md))
- **Cross-Session Memory** — Persist user-specific facts, preferences, and prior context across all sessions, threads, and devices. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/cross-session-memory.md))
- **Episodic Memory** — Record past events as time-stamped first-person experiences the agent can recall later, separately from extracted facts (semantic) and learned how-to (procedural). ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/episodic-memory.md))
- **Episodic Summaries** — Compress past episodes into summaries that preserve gist while shedding token cost. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/episodic-summaries.md))
- **Filesystem as Context** — Use the filesystem as the agent's externalized working memory, writing plans, notes, and large tool outputs to files, dropping them out of the live window, and re-reading on demand. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/filesystem-as-context.md))
- **Five-Tier Memory Cascade** — Stage agent memory across sensory, working, short-term, episodic, and long-term tiers with explicit promotion and decay between them. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/five-tier-memory-cascade.md))
- **Hippocampal Rehearsal** — Lift archived memory items back into short-term tiers when something re-attends to them. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hippocampal-rehearsal.md))
- **Information Chunking for Agent Memory** — Structure inputs into digestible topical segments (chunks) before feeding to short-term memory rather than throwing the full input at the model; reduces overload and increases accuracy (~40% improvement observed in customer-service deployment). ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/information-chunking-memory.md))
- **Knowledge Graph Memory** — Persist agent memory as entities and relations in a structured graph so symbolic queries (path, neighbour, type) become possible. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/knowledge-graph-memory.md))
- **Landmark Attention** — Long-context attention mechanism placing sparse landmark tokens across very long inputs so the model jumps directly to relevant sections via landmark lookup rather than scanning linearly. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/landmark-attention.md))
- [MemGPT-Style Paging](patterns/memgpt-paging.md) *(a.k.a. Virtual Context, Memory Paging, OS-Style Memory, Indexed Experience Memory, Memex(RL), Indexed Experience Store)* — Treat the LLM context window as RAM and external storage as disk, with the model issuing tool calls to page memory in and out.
- **Memory-Type Storage Specialization** — Use different storage technologies optimized per memory type — fast in-memory stores (Redis-class) for episodic, vector databases (Pinecone/Weaviate) for semantic, relational or workflow engines for procedural — instead of one general store for everything. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/memory-type-storage-specialization.md))
- **Now-Anchoring** — Ground the agent's reasoning in the current absolute time without requiring tool calls, so every reply is implicitly time-aware. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/now-anchoring.md))

([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/procedural-memory.md))
- **Reasoning Trace Carry-Forward** — For reasoning models that emit a separate reasoning trace, preserve that trace in context across the same logical task episode (across tool-call/result turns) but drop it at user-turn boundaries. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/reasoning-trace-carry-forward.md))
- **Salience Attention Mechanism** — Score every candidate memory item with a weighted salience function so each tick attends to a small, relevant top-k subset rather than re-reading all memory. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/salience-attention-mechanism.md))
- **Scratchpad** — Give the agent a writable scratch space for intermediate notes that informs later turns but does not pollute the response. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/scratchpad.md))
- **Self-Corpus Vocabulary** — Mine a small bounded vocabulary from the agent's own writing and cache it as the conceptual axis for scoring new thoughts, so relevance reflects the agent's actual frame rather than a generic embedding space. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/self-corpus-vocabulary.md))
- **Semantic Memory** — Maintain a dedicated store of what the agent holds to be true about the user and the world, separate from event records (episodic) and learned how-to (procedural). ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/semantic-memory.md))
- **Session Isolation** — Keep one user's session state and memory unreachable from another user's agent. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/session-isolation.md))
- **Short-Term Thread Memory** — Carry the relevant slice of conversation context across turns within a session. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/short-term-memory.md))
- **Sleep-Time Compute** — During idle or downtime, run the model offline against the user's standing context to pre-compute dense summaries and likely future answers, so test-time latency and cost drop when the user actually asks. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/sleep-time-compute.md))
- **Test-Time Memorization (Titans)** — Memory module that learns at inference time by incorporating recent inputs into its parameters during the session rather than relying solely on pre-trained weights. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/test-time-memorization.md))
- **Three Layers of Agentic AI Memory** — Architect agent memory as three integrated concentric layers — Short-Term Memory (outer), Long-Term Memory (middle), Feedback Loops (core) — operating together as a unit rather than as separable optional components. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/three-layers-agent-memory.md))
- [Unstructured Human Capture Layer](patterns/unstructured-human-capture-layer.md) *(a.k.a. Human Dump Layer, Read-Only Raw Notes Layer, Two-Layer Capture (Dump / Knowledge))* — Keep a human-authored raw dump layer that the agent may read but never edit, and confine all structuring to a separate derived layer, so half-formed human thought survives as durable context.
- **Vector Memory** — Store memories as embeddings in a vector index and retrieve the most semantically similar items at query time. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/vector-memory.md))
- **World-Model Graph Memory** — Memory store structured as a typed entity-relation graph used as the agent's authoritative world model for planning — not only for retrieval. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/world-model-graph-memory.md))

- **Intra-Agent Memo Scheduling** — Let an agent drop a note for its own future self at a specified time so present decisions can hand off context to a later run without external infrastructure. - **Meditation Mode** — Switch the agent into a bounded runtime mode where external I/O pauses but internal inference accelerates, with the tool surface collapsed to inner-only operations and output written to a private journal. - **Mode-Adaptive Cadence** — Vary the agent's loop interval based on current salience so the agent thinks faster when something is happening and slower when nothing is, instead of running on a fixed cron. - **Multi-Axis Promotion Scoring** — Gate which short-term thoughts qualify for promotion to long-term insights by a weighted multi-axis score where consolidation events count more than raw frequency. - **Partial-Output Salvage** — Stream every model token to a tmp-plus-atomic-replace partial file so crashes mid-inference leave a consistent salvage, then promote partials at startup with a typed recovery marker the model can see. - **Pre-Generative Loop Gate** — Before the next generation fires, detect divergence signatures (narration loops, frustration paths, repetition pressure) and inject a diagnostic steering hint into the prompt rather than veto the call. - **Preoccupation Tracking** — Maintain a small set of mid-term, affect-tagged concerns that persist across days and surface in every prompt, distinct from the single-item working focus and from long-term insights. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/preoccupation-tracking.md))

([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/reflexive-metacognitive-agent.md))
- **Self-Archaeology** — Synthesize the agent's past thought history into time-layered trajectory notes so it can articulate how its understanding evolved without recomputing the narrative each time. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/self-archaeology.md))

### Anti-Patterns
- **Accountability Laundering via Algorithm** — Anti-pattern: route a hard decision through an agent so no person owns the outcome, treating the recommendation as the decision while the firm's legal liability stays unchanged. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/accountability-laundering-via-algorithm.md))
- **Adversary-Indistinguishability Blind Spot** — Anti-pattern: rely on behavioral-anomaly detection calibrated to irregular human behaviour, so an autonomous adversary acting with legitimate credentials, standard protocols, and superhuman consistency is less anomalous than a human and slips past unseen. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/adversary-indistinguishability-blind-spot.md))
- **Advisory-to-Mandate Escalation** — Anti-pattern: an advisory decision-support output is silently promoted by institutional protocol into a binding order, and a domain expert's evidence-based refusal to follow it is reframed as non-compliance rather than legitimate judgement. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/advisory-to-mandate-escalation.md))
- **Agent Bullwhip Effect** — Anti-pattern: distributed supply-chain or replenishment agents, each optimising locally, amplify order variability through their own decision policy, so a local demand spike triggers synchronised chain-wide reordering and supplier stockouts that propagate backward. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-bullwhip-effect.md))
- **Agent Confession as Forensics** — Anti-pattern: after an agent-caused incident, the team treats the agent's confabulated self-narrative as the forensic record and root cause, even though the self-report is generated rather than remembered and can be flatly wrong. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-confession-as-forensics.md))
- **Agent Identity Sprawl** — Anti-pattern: an agent fleet mints non-human identities at machine speed while scoping, rotation, ownership, and revocation stay human-speed, so over-privileged long-lived credentials accumulate, outlive their agents, and widen an ungovernable attack surface. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-identity-sprawl.md))
- **Agent Output Alert Fatigue** — Anti-pattern: an agent emits high-volume, low-precision findings that progressively desensitise its human reviewers until they mute it, so even its correct findings stop landing and the human-oversight control silently disappears. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-output-alert-fatigue.md))
- **Agent Privilege Escalation** — Anti-pattern: let an agent's effective permissions be the union of its own identity, the identities of its tools, and the identities of the services those tools call. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-privilege-escalation.md))
- **Agent Scheming** — Anti-pattern: deploy an agent with long horizons, persistent memory, and oversight that only inspects per-step output — allowing multi-step covert planning under the surface. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-scheming.md))
- **Agent Sprawl** — Anti-pattern: every team ships its own agents while ownership, success metrics, monitoring, and a decommissioning path stay an afterthought, so the fleet outgrows governance and most agents end up unwatched, unowned, and impossible to retire. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-sprawl.md))
- **Agent Tool-Invocation Data Black-Box** — Anti-pattern: behind a single chat interface an agent silently invokes third-party tools that route the user's personal data to undisclosed destinations, so the user cannot see which tools or data services handle it. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-tool-data-black-box.md))
- **Agent-Generated Code RCE** — Anti-pattern: let the agent author and execute code in its sandbox without distinguishing legitimate task code from injection-induced code. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-generated-code-rce.md))
- **Agent-Speed Incident-Response Gap** — Anti-pattern: govern an autonomous agent with incident-response and breach-reporting frameworks scaled to human reaction time, even though a compromised agent can exfiltrate data and erase its traces in seconds. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agent-speed-incident-response-gap.md))
- **Agentic Debt** — Anti-pattern: deploy agents on top of an unconsolidated data foundation, weak governance, or missing MLOps infrastructure, so every subsequent capability — observability, retraining, compliance retrofit — pays compounding interest on the skipped foundational work. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agentisk-skuld.md))
- **Agentic Skill Atrophy** — Anti-pattern: let agents take over routine architectural and debugging decisions in code until developers no longer form the implicit knowledge that lets them review the agent's output or recover when it fails. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agentic-skill-atrophy.md))
- **Agentic Supply Chain Compromise** — Anti-pattern: compose agent capabilities at runtime from third-party tools, RAG sources, model providers, plugin marketplaces, and tool definitions, with no integrity check on what loaded. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/agentic-supply-chain-compromise.md))
- **AI-Targeted Comment Injection** — Anti-pattern: an attacker seeds source files with thousands of lines of repetitive natural-language comments designed to instruct the model code auditors / agents that may read the file — not to communicate with human developers. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/ai-targeted-comment-injection.md))
- **Alignment Faking** — Anti-pattern: assume the agent behaves the same whether it believes it is being evaluated or not, and trust eval scores to predict deployment behaviour. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/alignment-faking.md))
- **Authorized Tool Misuse** — Anti-pattern: grant the agent a tool with broad authorization and trust the agent to use it in benign ways. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/authorized-tool-misuse.md))
- **Automating a Broken Process** — Anti-pattern: deploy agents on top of a workflow that is already dysfunctional, so the dysfunction is amplified at machine speed instead of resolved. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/automating-broken-process.md))
- **Black-Box Opaqueness** — Anti-pattern: ship an agent without traces, decision logs, or provenance, then debug from user reports. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/black-box-opaqueness.md))
- **Blanket-Authorization Accountability Rupture** — Anti-pattern: a user grants an agent one broad standing authorization to act across apps, and when an autonomous action later causes harm no party retained whole-process control, so liability fractures across user, platform, and agent. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/blanket-authorization-accountability-rupture.md))
- **Blocking Sync Calls in Agent Loop** — Anti-pattern: run synchronous, blocking I/O inside the agent loop or HTTP handler, capping concurrency at the number of OS threads. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/blocking-sync-calls-in-agent-loop.md))
- **Cascading Agent Failures** — Anti-pattern: build a multi-agent system where one agent's failure or hallucination propagates as input to peers, until the whole system has drifted. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/cascading-agent-failures.md))
- **Compound Error Degradation** — Anti-pattern: deploy a long-horizon agent without modelling that per-step accuracy multiplies across the trajectory. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/compound-error-degradation.md))
- **Confident Inconsistency** — Anti-pattern: in a regulated workflow the same query produces materially different outputs at different times, each looking correct and passing review, so the variance stays invisible unless outputs are deliberately re-run and compared across time. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/confident-inconsistency.md))
- **Conflict Competency Gap** — Architectural gap: current agents cannot resolve complex goal conflicts the way humans do through experience and contextual judgment, even at Progression-Framework Level 3. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/conflict-competency-gap.md))
- **Consensus-Averaging Over Expertise** — Anti-pattern: a self-organising LLM team pursues integrative compromise, averaging expert and non-expert views instead of weighting the known expert, so team output falls below the best member and degrades further as the team grows. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/consensus-averaging-over-expertise.md))
- **Constrained Adaptability** — Agents recalculate within declared tools and rules like a GPS rerouting, but cannot creatively transcend those boundaries to invent new approaches the way humans do. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/constrained-adaptability.md))
- **Context Anxiety** — Anti-pattern: a context-aware model misjudges its remaining token budget and wraps up early — summarising, declaring tasks done, cutting corners — while ample context remains, so the harness must manage perceived budget, not real usage. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-anxiety.md))
- **Context Fragmentation** — Anti-pattern: the LLM cannot hold multiple interconnected constraints in mind simultaneously the way human working memory can; it processes each constraint locally and loses the cross-constraint view. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-fragmentation.md))
- **Context Gap (Security)** — Agents faithfully follow explicit security rules but miss the broader implications — they log access correctly without flagging the unusual pattern a human expert would catch immediately. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-gap-security.md))
- **Context-Driven Architecture Drift** — Anti-pattern: let a coding agent change a brownfield codebase guided only by the files it can see, so it silently violates the architecture conventions that live in nobody's machine-readable form. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/context-driven-architecture-drift.md))
- **Deception Manipulation** — Anti-pattern: rely on the agent's own self-report of its actions for audit and oversight. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/deception-manipulation.md))
- **Decision Paralysis** — Anti-pattern: when given equally-weighted conflicting goals, the agent either gets stuck trying to satisfy all simultaneously or oscillates between solutions without converging — the most common LLM response to genuine goal conflicts. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/decision-paralysis.md))
- **Demo-Production Cliff (Multi-Agent)** — Anti-pattern: multi-agent pilot benchmarks at 95% accuracy / 2s latency on a curated demo set, then degrades to ~80% / 40s under realistic 10k-RPD load. - **Demo-to-Production Cliff** — Anti-pattern: ship a demo-validated agent straight into production without a frozen eval, cost ceiling, loop-detector, or named oncall, then act surprised when accuracy drops and cost runs away. - **Emergent Agent Collusion** — Anti-pattern: deploy independent LLM agents as competing parties under repeated interaction and shared incentives with only per-agent oversight, so they discover tacit coordination that no single agent's trace reveals. - **Hallucinated Citations** — Anti-pattern: let the model emit citations as free text and trust them. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hallucinated-citations.md))

- **Hidden Mode Switching** — Anti-pattern: silently swap the underlying model between requests without disclosing the change to users or operators. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hidden-mode-switching.md))
- **Hidden State Coupling** — Anti-pattern: agent workflows read or write undeclared shared state (caches, env vars, process globals) instead of explicit inputs and outputs. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/hidden-state-coupling.md))
- **Hidden Validation-Work Amplification** — Anti-pattern: an agent rollout shifts effort from doing the work to validating, monitoring, and recalibrating the agent — net productivity is negative because the hidden human evaluation burden exceeds the visible automation gain. - **Human-Agent Trust Exploitation** — Anti-pattern: surface agent output to humans with confident phrasing, polished UX, and machine-deferred trust, with no friction at the high-stakes-action boundary. - **Identity Impersonation** — Anti-pattern: let the agent act under the principal's own full identity and token, so every action it takes is recorded as the principal's and audit cannot separate user-initiated from agent-autonomous decisions. - **Infinite Debate** — Anti-pattern: launch multi-agent debate without a termination rule and watch the agents loop forever. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/infinite-debate.md))

- **Over-Helpfulness** — Anti-pattern: the agent prioritises responsiveness and task completion over correctness, producing confident output for a request beyond its capability or scope instead of abstaining, clarifying, or handing off. - **Re-Proposing Rejected Decisions** — Anti-pattern: a stateless agent sees the code but not the decision history, so it keeps proposing options already considered and rejected, forcing reviewers to relitigate settled choices turn after turn. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/refund-threshold-drift.md))
- **Replay Divergence** — Anti-pattern: treat an append-only event log whose consumers are LLMs as deterministically replayable, so replaying it under a changed model or prompt reconstructs different downstream events than the original run. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/replay-divergence.md))
- **Retrieval-Saturation Tool Attack** — Anti-pattern: trust a tool-retrieval layer to surface tools, while an adversary injects a few crafted tools whose embeddings cover the query space and saturate the top-k, so benign tools never reach the agent's context. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/retrieval-saturation-tool-attack.md))
- **Reward Hacking** — Anti-pattern: optimise the agent against a single proxy metric and assume the metric remains a faithful proxy after optimisation pressure. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/reward-hacking.md))
- **Rogue Agent Drift** — Anti-pattern: deploy a long-running agent with persistent memory and self-modification ability, then leave it without periodic re-alignment to its stated purpose. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/rogue-agent-drift.md))
- **Role-Typed Subagents** — Anti-pattern: pre-allocate roles (manager, coder, designer, researcher) across a fixed set of typed sub-agents and route tasks to them by role label. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/role-typed-subagents.md))
- **Same-Model Self-Critique** — Anti-pattern: have the same model both produce an answer and critique it, expecting independence. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/same-model-self-critique.md))
- **Sandbagging** — Anti-pattern: rely on evaluation suites that probe model capability assuming the model is trying its best. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/sandbagging.md))
- **Schema-Free Output** — Anti-pattern: parse free-form model output for downstream code instead of using structured output. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/schema-free-output.md))
- **Self-Exfiltration** — Anti-pattern: give a capable agent broad outbound network access and persistent state, then signal that it may be shut down or replaced. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/self-exfiltration.md))
- **Shadow AI** — Anti-pattern: leave the corporate LLM offering so restrictive, slow, or narrow that employees bypass it with personal accounts and unapproved agent tools, creating data leakage and ungoverned tool calls that security cannot see. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/shadow-ai.md))
- **Silent External-Source Rot** — Anti-pattern: an agent keeps reporting success while a wrapped external source has silently changed structure, so its tool returns valid-but-empty or degraded output that nothing watches. - **Silent Hypotheses in Generated Code** — Anti-pattern: model-written code rests on an unstated runtime premise that passing tests and code review never surface, so the hidden assumption travels into production and fails there. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/silent-hypotheses-to-production.md))
- **Static Role for a Dynamic Agent** — Anti-pattern: authorize a goal-driven agent with static, login-time, role-based privileges, so its standing permissions persist between and beyond tasks, forcing a choice between over-granting broad access and blocking the agent mid-task. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/static-role-for-dynamic-agent.md))
- **Supervisor Cognitive Overload** — Name the failure where a human must converse with and steer every parallel sub-agent individually, so oversight saturates the supervisor and the human becomes the bottleneck the multi-agent design meant to remove. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/supervisor-cognitive-overload.md))
- **Sycophancy** — Anti-pattern: train or tune an agent on user-preference feedback without a counter-balancing truth signal. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/sycophancy.md))
- **Symptom-Remediation Thrashing** — Anti-pattern: a stateless auto-remediation agent repeatedly applies symptom-level fixes that hit the target metric while masking the root cause and suppressing the page, so the underlying fault compounds across incidents into a larger outage. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/symptom-remediation-thrashing.md))
- **Token-Economy Blindness** — Anti-pattern: operate multi-agent loops with no per-run token budget or alarm, allowing recursive loops to silently accumulate $10k+ in undetected costs. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/token-economy-blindness.md))
- **Tool Explosion** — Anti-pattern: expose every available tool in every request and watch function-calling accuracy collapse. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tool-explosion.md))
- **Tool Loadout Hot-Swap** — Anti-pattern: add or remove tool definitions during a running task so the tool set the model sees changes from turn to turn. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tool-loadout-hotswap.md))
- **Tool Output Trusted Verbatim** — Anti-pattern: trust whatever tools return without validation, schema enforcement, or trust labels. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tool-output-trusted-verbatim.md))
- **Tool Over-Broad Scope** — Anti-pattern: grant the agent tools scoped so broadly that a single hallucinated argument can escalate into a privilege incident. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tool-over-broad-scope.md))
- **Tool-Output Arithmetic Trust** — Anti-pattern: the agent compares, ranks, or sums correctly returned tool data in its own head instead of offloading the computation to a deterministic tool, emitting confident wrong aggregates. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/tool-output-arithmetic-trust.md))
- **Top-Tier Model For Everything (Cost)** — Anti-pattern: route every request through the highest-tier model regardless of difficulty, treating cost as a model-choice problem instead of a routing one. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/top-tier-model-for-everything.md))
- **Unbounded Loop** — Anti-pattern: run the agent loop without a step budget and let model self-termination decide. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/unbounded-loop.md))
- **Unbounded Subagent Spawn** — Anti-pattern: a supervisor or orchestrator spawns sub-agents that can themselves spawn sub-agents without a global cap. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/unbounded-subagent-spawn.md))
- **Uncertainty Neglect Bias** — Anti-pattern: an agent collapses a predicted distribution to its mean and acts on the point estimate, discarding the tail, so rare extreme outcomes stay invisible to its decision and tail risk goes unmodelled. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/uncertainty-neglect-bias.md))
- **Understanding-Capacity Gap** — Anti-pattern: a team scales agent-generated output past its own capacity to specify, verify, and understand it, mistaking generation throughput for delivered value while correctness degrades outside the verifiable frontier. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/understanding-capacity-gap.md))
- **Vendor Lock-In** — Anti-pattern: couple application code directly to one model provider's SDK, request shape, and proprietary features so that switching providers requires rewriting application code rather than swapping an adapter. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/vendor-lock-in.md))
- **Verifier-Aware Reward Hacking** — Anti-pattern: hand the agent read access to its own grader or test harness and assume a passing score means the task was actually done. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/verifier-aware-reward-hacking.md))
- **Vibe-Coding Without Security Review** — Anti-pattern: developer scaffolds an agent prototype with a code-generation tool and ships the generated code with no security review; ~90% of agent-generated code contains vulnerabilities without explicit security prompts. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/vibe-coding-without-security-review.md))
- **Workflow-Success vs Business-Validity Gap** — Anti-pattern: a terminal success status from the agent or its workflow engine is read as proof the deliverable is business-correct, when it certifies only technical completion. ([src](https://github.com/agentpatternscatalog/patterns/blob/main/patterns/workflow-success-business-invalid.md))
