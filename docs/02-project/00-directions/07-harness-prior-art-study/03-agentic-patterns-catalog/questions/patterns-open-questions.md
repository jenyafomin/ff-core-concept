# Открытые вопросы — что у нас УЖЕ есть vs чего не хватает (для синтеза A/B)

> Advisory, сырьё скаута C. Не решение — вход в приёмку co-orchestrator / синтез лида.

## Что у нас УЖЕ ЕСТЬ (паттерн-каталог это подтверждает, не открывает)

1. **Рекурсивная оркестрация** (`.claude/rules/recursive-orchestration-method.md`, 6 законов) ≈ связка
   `Orchestrator-Workers` + `Lead Researcher` + `Parallel Fan-Out/Gather` + `Board-Mediated Coordination`.
   Наш метод СИЛЬНЕЕ каталожных паттернов в одном месте: явно называет 3 роли (лид/помощник/команды) и
   привязывает волну к экономике (закон 4, gateway-sync).
2. **Критик-до-готово** (закон 5) ≈ `Generator-Critic Separation` + `Cross-Reflection` (частично —
   decorrelation модели не гарантирована систематически, см. вопрос ниже).
3. **Помощник-дайджест** (co-orchestrator, приёмка вместо лида) ≈ `Blind Grader with Isolated Context` —
   почти буквальное совпадение, но НАШ контракт не формулирует явно «не читай reasoning исполнителя».
4. **Волны, не мега-фан-аут** (закон 4) ≈ структурно снимает риск антипаттерна `Ghost Delegation` (синхрон
   гарантирует, что волна не закрывается, пока все саб-агенты не вернулись) — но эта связь нигде не
   зафиксирована как ПРИЧИНА правила, только как экономика gateway.
5. **Банк вопросов по 7 ценностям** (обязанность помощника 3д) ≈ `Frozen Rubric Reflection` — рубрика
   зафиксирована заранее, помощник не изобретает критерии на лету.
6. **Doc-tree как координация между волнами** ≈ `Blackboard` / `Stigmergic Coordination` — файлы как общее
   пространство, через которое агенты одной волны не общаются напрямую, но следующая волна читает след.

## Чего НЕ хватает (гэпы, кандидаты для форков A/B)

1. **Commitment Tracking** — «owner-pending» пункты в каждом хендоффе (I-4, R3/R4/R5, F-D, ратификации —
   см. MEMORY.md) живут ПРОЗОЙ внутри HANDOFF.md, не как типизированный ledger со статусом
   `open/followed-through/expired`. Риск: пункт тонет в тексте, следующая сессия не видит явно «что
   провисло». **Вопрос владельцу:** заводить ли это как новый тип узла (`commitment`) в brain-графе, или
   это over-engineering на 0 реальных данных (см. владельческий вердикт 2026-08-16 «шлифуем замок на
   пустом хранилище»)?
2. **Adaptive Memory Decay — механизм** — Ц4 Витальность названа как ценность («может затухать→cold»), но
   формула (retention score modulated by relevance/frequency/recency) не спроектирована. Это ОДНА из
   развилок-светофоров SYNTHESIS §8 (🟡 salience(Ц4)) — паттерн-каталог даёт конкретную отправную точку
   (не решение, а vocabulary — "salience scoring", "decay curve").
3. **Salience Attention Mechanism — алгоритм** — Ц1 Читаемость («грань по цене») тоже названа, но КАК агент
   выбирает top-k при чтении графа — не решено. Пересекается с 🟡 edge-id(Ц6) и scope=A/B развилкой.
4. **Preoccupation Tracking** — MEMORY.md ⭐-записи это ручной, нетипизированный аналог. Каждая новая
   сессия ЧИТАЕТ ВСЮ MEMORY.md целиком (уже нарушение Ц1 — не «грань по цене», а полное вскрытие). Паттерн
   предлагает: отдельный тип узла со своим decay/surfacing правилом вместо плоского списка.
5. **Hypothesis Tracking (`next-test` поле)** — наши insight-узлы редко несут явное «как это проверить».
   Легковесный гэп: можно закрыть добавлением одного поля в существующий тип, не новой сущностью.
6. **Cross-Reflection (decorrelated model)** — уточнить: наш `critic` систематически на ДРУГОМ классе
   модели, чем производитель, или иногда совпадает (sonnet-критикует-sonnet)? Если совпадает — слепая зона
   антипаттерна `Same-Model Self-Critique`.

## Связки к развилкам A/B (из HANDOFF 2026-08-16, SYNTHESIS §8)

- 🟢 `plan/INDEX.md` (slim canon) — паттерн `Re-Proposing Rejected Decisions` объясняет, ЗАЧЕМ этот canon
  нужен структурно (не просто гигиена): без него каждый новый агент рискует переоткрывать закрытые
  развилки, потому что видит код/доки, но не историю решений.
- 🟡 scope=A/B(Ц7), edge-id(Ц6), salience(Ц4) — все три развилки получают СЛОВАРЬ из паттерн-каталога
  (Session Isolation/Tenant Separation для scope; Knowledge Graph Memory для edge-id; Adaptive Memory
  Decay + Salience Attention для salience), но каталог НЕ решает их — решает владелец после переписи
  загорания на реальных эпизодах (владельческий next-move).
- 🔴 F-D адверсариал-чекпойнт до данных — паттерн `Perma-Beta`/`Demo-to-Production Cliff` формализует РИСК,
  который этот чекпойнт призван поймать (ship без реальных данных = маскировка недоделанности анализом).

## Явный НЕ-вывод (страховка от переусложнения)

World-Model Separation, Preoccupation Tracking, Self-Identity Accumulation) НЕ рекомендуется строить
сейчас. Это словарь для БУДУЩЕГО форка self-memory (agent-run→память), который уже начат (F3, 2026-08-22
handoff), но при 0 реальных данных за 2 месяца (владельческий вердикт) — приоритет остаётся на переписи
загорания, не на добавлении новых типов узлов из внешнего каталога.
