# Открытые вопросы — Движ vs DeepSeek Harness, связки к A и C

Эти вопросы не решены этим разведпроходом (скаут B читал только `agents-manager`, не читал разбор A).
Они — вход для синтеза лида/помощника, когда оба скаута (A и B) закончат.

## Связки к A (DeepSeek Harness)

1. **Плагин-модель: строить ли у Движа plugin-реестр сейчас, или ждать «правила двух» (ADR-0009)?**
   Движ явно отложил generic-конструктор паттернов до 2-го прецедента-механизма и явно назвал риск
   «plugin hell» без реестра типов (`../facts/dvizh-facts.md` §7). Если Harness (A) уже прошёл через эту
   развилку и имеет рабочий реестр — стоит проверить, решил ли он проблему «hell» и как (типизация? версии
   схем? sandboxing?). Это прямой источник паттерна для будущего ADR Движа, не только сравнение.

2. **Мультиканальность: чего конкретно не хватит Движу, чтобы завести второй `IChannel` (например,
   Slack/Discord/веб-виджет)?** Порт `IChannel` уже существует (`core/ports/channel.interface.ts`), но
   единственная реализация — `TelegramChannel`, плотно завязанная на forum-topics (`ITopicRepo`,
   `message_thread_id`). Нужно понять: у Harness мультиканальность — это тонкий адаптер поверх
   универсальной модели сессии, или тоже завязана на специфику одного транспорта? Если у Harness модель
   сессии универсальнее topic-based — это конкретный урок для рефакторинга Движа ПЕРЕД вторым каналом.

3. **Роли/governance: сравнить ADR-0002-access-roles-and-approval-policy (draft, Движ) с моделью прав
   Harness.** Движ спроектировал GREEN/YELLOW/RED классификацию действий + owner/operator/viewer, но код
   не начат на момент последнего чтения ADR. Если Harness уже эксплуатирует многоролевую модель — можно
   сверить, не изобретает ли Движ то же самое другими словами (или наоборот — не упускает ли класс риска,
   который Harness уже закрыл).

4. **Реальный токен-стрим:** у Движа `SdkRunner.stream()` сейчас = финал одним чанком (не токен-стрим в
   Telegram-эдиты). Есть ли у Harness рабочий паттерн потокового вывода в чат-подобный интерфейс, который
   можно перенять?

## Связки к C (agentic-patterns-catalog)

5. **Паттерн-как-данные (ADR-0009) — это НЕ уникальная идея Движа.** Стоит проверить каталог паттернов (C)
   на предмет: «декларативный workflow, исполняемый частным интерпретатором, с обобщением по правилу двух»
   — устоявшийся ли это паттерн вообще, и если да — какие типовые ловушки каталог называет (совпадают ли
   с «plugin hell», который уже назвал критик Движа сам)?

6. **Strangler-миграция хранилища под живым единственным каналом владельца (ADR-0006)** — насколько это
   специфично для сценария «единственный владелец, единственный канал», и является ли operability-инвариант
   (флаг off = байт-в-байт откат) переиспользуемым паттерном для FF, если FF тоже когда-то мигрирует свою
   схему памяти под живой процесс?

## Внутренние вопросы (для лида FF, не про сравнение)

7. **Расхождение факта:** `package.json` описания Движа фиксирует стадию «M2», хотя README называет
   текущий статус «M4/M4.5». Это гигиенический долг документации самого Движа, не блокер сравнения, но
   стоит явно отметить лиду — если Движ берётся как reference-архитектура для FF, не копировать эту
   рассинхронизацию.

8. **Дублирование номеров ADR** (два `ADR-0002`, два `ADR-0004` с разными темами и разными статусами) —
   прямое нарушение принципа «дисциплина дерева» (`doc-tree.md` FF: «один дом на тему»). Стоит ли FF
   явно отметить это как антипаттерн-урок (не повторять), учитывая что FF сам держит строгую нумерацию?

9. **Пересечение с планом памяти FF (D1):** ADR-0005 Движа (Unit/Event/Ref, append-only, fold=текущая
   форма) концептуально близко к тому, что ищет FF для «базы знаний как субстрата для агентов»
   (`CLAUDE.md` FF, «Ключевой рефрейм msg 141»). Стоит ли следующей сессии FF явно прочитать ADR-0005/0006
   Движа целиком (не только выжимку здесь) как готовый прецедент вместо изобретения с нуля? Это не вопрос
   сравнения с Harness — это прямой reuse-кандидат, найденный побочно в этом разведпроходе.

10. **Не проверено в этом проходе (честно назвать):** фактическая реализация Unit-стора на диске
    (существуют ли уже таблицы `unit`/`unit_type`/`unit_event` в коде persistence-слоя, или ADR-0005/0006
    остаются чисто дизайн-документами) — не читал `src/server/persistence/entities/`. Аналогично не
    проверен факт продвижения ADR-0002-access-roles (draft → реализация) после Addendum 2026-07-19. Если
    лиду нужна точная картина «что уже В КОДЕ» (не в ADR), нужен отдельный точечный проход по
    `src/server/persistence/entities/` и `git log` по ключевым файлам.
