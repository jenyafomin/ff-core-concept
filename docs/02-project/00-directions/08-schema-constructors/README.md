# D8 · Схема как живой настраиваемый конструктор — концепт-эксплорация

> ⚗️ **Status: experimental.** Это НЕ ратифицированная архитектура и НЕ план стройки. Это дом для
> **исследования идей** (Reserved-Form): фиксируем грани направления владельца, привязываем каждую к
> ценности и к УЖЕ существующему механизму, честно помечаем, что решённого тут нет.

## Что за направление
Слова владельца (verbatim-смысл): «Схему/дизайн нужно ПОСТОЯННО концептуально улучшать — представь LOOP,
где агент периодически поднимается и всегда пытается улучшить/обогатить схему. Хочу инструмент ГИБКИМ —
настраиваемым КОНСТРУКТОРОМ, где каждая единица памяти сама себе помогает; для этого нужны управляемые
правила и системные. И это должно продолжаться. Не ждать данных, чтобы улучшать — брать несколько
концептуальных моделей на направление и прорабатывать.»

Три сцепленные грани:
1. **Единица помогает сама себе** — правила-как-данные НА единице/типе, порождающие виды и поведение.
2. **Loop-агент улучшает схему** — периодический подъём «сверху», обогащение схемы под адверсариалом.
3. **Конструктор** — схема как набор компонуемых примитивов, расширяемых без переписи.

## Границы (жёстко)
- **Исследование идей, не стройка.** Ничего отсюда не идёт в код без отдельного явного «строй».
- **Reserved-Form:** описываем ФОРМУ и напряжения, не включаем поведение. Enforcement не проектируем здесь.
- **НЕ ждём данных, но и НЕ строим вперёд данных.** Прорабатываем концептуальные модели; ратификация — позже.
- **Не переоткрываем механизмы.** policy-as-data, integrity-as-engine-duty, Reserved-Form, canonical_id/
  edge-identity — берём как ДАНО и надстраиваем, а не изобретаем заново.
- **Один дом.** Формулировки ценностей — в каноне Ц1–Ц7, здесь только ссылки; контент не дублируем.

## Куда растёт (следующий шаг)
Отдельная **глубокая волна `value-decomposition` + критик**: разложить каждую идею по лестнице
цель→ценность→идея→инфраструктурный примитив, прогнать острые вопросы через адверсариал, вынести
кандидатов в ADR/спеки только по «строй» владельца.
