# Идея 02 · Loop-агент улучшает схему

> ⚗️ Reserved-Form. Форма безопасной петли, не включённое поведение. Enforcement согласия пока НЕ подключён.

## Суть
Периодически (не по данным, а по расписанию/триггеру «подняться сверху») **агент-улучшатель** смотрит на
схему целиком и предлагает обогащение: новый примитив, новое правило-вид, консолидацию типов, недостающую
грань. Владелец хочет, чтобы это «продолжалось» — то есть петля постоянна, а не разовый акт.

Опасность очевидна: агент, меняющий фундамент, — это агент, который может фундамент сломать. Поэтому идея
не про «дать агенту менять схему», а про **как сделать это БЕЗОПАСНО**.

## Ментальная модель: «схема как код под ревью»
Схема — не живой оракул, а **артефакт под контролем версий**. Каждое предложение loop-агента = pull-request
к схеме, а не прямая запись. Тогда переносятся дисциплины кода:
1. **Критик/адверсариал в петле.** Предложение проходит ДРУГОГО агента-критика ДО применения (закон 5
   метода). Самопроверка улучшателя — не верификатор.
2. **Человек-в-контуре на необратимом.** Обратимое обогащение (добавить вид, предложить правило) может идти
   с низким трением; **необратимое** (удалить примитив, слить типы, сузить инвариант) — только через явное
   «да» владельца. Это тот же «клапан доверия на внешние необратимые действия».
3. **Версии схемы + откат.** Каждое изменение версионировано, откат существует ДО применения (git-подобно).
   Точка возврата обязательна перед деструктивом.
4. **Retrofit-граница.** Явно фиксировать, что нельзя добавить задним числом (см. вопрос б) — это НЕ отдаём
   loop-агенту, это решается формой заранее.

## Привязка к ценностям
- **Ц3 Доверие** — предложение несёт провенанс (кто/почему предложил), калибруемое доверие; критик защищает
  от отравления схемы. Агент не действует на непроверенной «ячейке-правиле».
- **Ц7 Согласие** — изменение схемы, затрагивающее данные под согласием, проходит consent-шов (честно:
  enforcement пока форма, см. вопрос в).
- **Ц4 Витальность** — сама схема остаётся живой (дорастает, переосмысляется), не застывает и не раздувается.

## Риск, названный честно
🔴 **Усложнение ради усложнения.** «Всегда улучшать» без метрики пользы → теплица, где агент плодит правила,
чтобы быть занятым. Нужна граница «улучшение vs усложнение» (вопрос а) как ВХОДНОЙ фильтр петли, иначе
петля вредна. Второй риск — стоимость постоянной петли (токены/шум предложений) против реальной отдачи.
