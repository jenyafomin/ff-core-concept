# KQ-1 · Критик-прогон: assertion — 7-й примитив или проекция?

**Мой исходный лин:** assertion НЕ отдельный хранимый примитив = проекция свёртки events; 5 примитивов
хранения (Entity·Relation·Event·Projection·Policy); провенанс/эпистема — в payload акта. Гипотеза-твист:
assertion схлопывается в «паспортное ребро» (KQ-1/2/11 = одно решение).

**Вердикт критика: `AMEND`.** Верно для простого случая, опасно недоспецифицировано как общий ответ.
KQ-1 склеивает два разных вопроса:

## Расщепление
- **KQ-1a — простые значения полей** (`task.priority=high`): **проекция**, подтверждено. Провенанс на уровне
  акта (I-2) достаточен; state = свёртка events (I-5). Адресуемость не нужна.
- **KQ-1b — инсайты/производные убеждения**, которым нужен свой ACL или быть целью ребра
  (`contradicts→`/`verifies→`): да, это **паспортное ребро** (Relation с эпистемо/провенанс-метаданными).
  Но это **узкий** carve-out из KQ-11, НЕ весь KQ-1. Твист переобобщил.
- **Третья дыра (фальсификатор):** single-entity, **field-scoped** эпистемо-претензии. Пример: «покажи все
  догадки за неделю, confidence<0.5, по всем полям». Под проекцией — надо либо недокументированная
  per-field конвенция в payload, либо материализованный индекс (по I-6 неотличим от хранимого примитива в
  «шляпе проекции» — тихий 6-й примитив **без governance/тестов/fail-closed**). Под ребром — неприменимо
  (`task.priority` не связывает два entity). **Оба предложенных вида проваливают этот тест.**

## Что ещё вскрыто
- **Противоречие в каноне:** `terminology.md` уже пишет «relation связывает ДВА entity; assertion описывает
  ОДНО» → «assertion = passported relation» без правки этой строки оставляет канон само-противоречивым.
- **confidence — процесс, не last-write-wins** (L0 Г7/Г9): поздний `Подтвердить`-акт меняет confidence
  прошлой claim → нужен адресный указатель `confirms:{actId, field}`. Схема акта/конверта такой
  field-path-адресации сегодня НЕ описывает → «assertion = проекция» пока аспирационно.
- **Асимметрия цены:** ошибиться в «проекция-only» = сложность мигрирует в недокументированные payload-
  конвенции (тихий рост ядра, без ADR/тестов). Ошибиться в «6-й примитив» = видимый surface-bloat, но
  ADR-губируемый и обратимый. Конституция (ADR-дисциплина, «консолидируй первым») → склон к **явности**.

## Рекомендация критика (владельцу)
НЕ ратифицировать KQ-1 как «5 примитивов, assertion=проекция» одним махом. Порядок:
1. Подтвердить **KQ-1a** = проекция.
2. Для **KQ-1b** — либо (i) явно расширить Relation на `entity→literal/field` (и поправить строку
   terminology.md), либо (ii) явно спроектировать **field-path-адресацию в акт + эпистемо-индекс** для
   field-level запросов.
3. KQ-1 / KQ-2 / KQ-11 — три решения с ОДНОЙ общей зависимостью («что считается независимо-адресуемым»),
   не одно; не паковать в один ADR, чтобы не замять field-scoped дыру.
