## Q2-fix — operational порог admission (замена тавтологии «когда-нибудь»)

**Старая формулировка** («агент КОГДА-НИБУДЬ линкует/фильтрует/применяет policy») не ограничивала рост:
у любого факта есть гипотетическое «когда-нибудь» → T-4 не гасится. Заменяем на **проверяемый в текущей
итерации** триггер.

**Правило (admit-порог, оператора «есть акт», а не «возможен акт»):**
Факт поднимается в граф как узел **⇔ уже существует конкретный акт-потребитель этого узла в этой
итерации**, а именно выполняется хотя бы один из:
1. **на него есть ребро** (что-то уже ссылается/связано), или
2. **он фигурирует в фильтре/скоупе реального `view` или `resolve()`-запроса** (по нему уже фильтруют), или
3. **на нём висит policy-решение** (`homeRule`/visibility/эрейж уже применяются к нему).

Нет ни одного из трёх сейчас → **остаётся git-сырьём** (указатель `path@rev`, читается on-demand). Не
«может понадобиться» — а «уже используется». Гипотетика не поднимает узел. Это даёт **явное «нет»-множество**
(осиротевшие байты без ребра/фильтра/policy), которого не было у старого теста, → T-4 реально ограничен:
граф растёт по факту связей/запросов, не по факту существования данных.

**Разрешение противоречия с I-14 (тело документа ⟂ поиск по содержимому).** Тело doc-типа НЕ инлайнится в
граф как контент-узел (остаётся git-байтами), НО должно быть **графо-адресуемым**, иначе семантический
поиск (I-14) слепнет. Вводим лёгкий **content-projection узел** — не копию тела, а адрес+отпечаток:

| Поле | Смысл |
|------|-------|
| `id` | графовый идентификатор проекции содержимого |
| `ref` | указатель на сырьё: `path@rev` (тело живёт в git, не в узле) |
| `hash` | контент-хэш тела (детект дрейфа, идемпотентность reindex) |
| `searchable: true` | флаг: индексатор строит `SemanticIndexEntry` из тела по `ref` |

Так I-14 соблюдён по всем трём его требованиям: канон хранит **исходный `ref`+`hash`** (не только вектор
→ модель embedding можно менять без потери знания); индекс полностью пересобираем (`rebuild-index` идёт по
`ref`); retrieval остаётся `rights → similarity` (проекция несёт node-level policy как любой узел, I-7 не
обойдён). Тело — по-прежнему сырьё (не раздувает обходы графа); адресуемость и поиск — через дешёвый
content-projection, а не через инлайн контента. Content-projection САМ проходит admit-порог по критерию
№2 (по нему фильтрует семантический `view`) → не нарушает собственное правило.

**Итог для скорости+удобства.** Граф = адресуемый скелет + тонкие content-projection для поиска; тяжёлые
байты лениво. Быстрые обходы + рабочий семантический поиск, без комбинаторного взрыва.

## Q4-fix — развести две оси (project-scope ≠ folder-node)

Критик прав: исходное «проект = folder-node» отождествило **два разных концерна**. Разводим явно как два
поля/ребра одной сущности «проект», НЕ как равенство типов:

| Ось | Что это | Домен | Кто потребитель |
|-----|---------|-------|-----------------|
| **`project-scope`** | access-партиция LSR-стека (`node>space>project>module`), слой-ДАННЫЕ | политика доступа | вход в `resolve()` (I-7 PEP), I-10, KQ-12 |
| **`folder-node`** (F1) | структурный узел ДЕРЕВА ДОКОВ (корень под-графа доков) | организация doc-tree | doc-discipline: перенос/слияние (закон №10) |

**Мост (связь, не равенство):** `project-scope` — это **атрибут/ребро** сущности «проект». Проект МОЖЕТ
иметь `folder-node`-представление (физический якорь в дереве доков), но `project-scope` = **отдельное
поле** `scope-partition`, на которое смотрит `resolve()`. Связь односторонняя: `folder-node --anchors-->
project`, но `scope-partition` НЕ выводится из положения folder-node в дереве.

**Зачем именно так (скорость+удобство + безопасность).** doc-tree реорг (перенос/слияние folder-node по
закону №10) меняет структурный якорь, но **НЕ трогает `scope-partition`** → access через `resolve()` не
уезжает молча при реорганизации доков. Агент по-прежнему подключает проект как под-граф одним действием
(удобство Q4 сохранено), но реорг доков и партиция доступа развязаны (T-3 снят без протаскивания doc-tree
операций в access-зону). I-10 соблюдён: партиция = данные в поле, не `if(project===X)` и не «позиция в
дереве».

## Q5-fix — честная стоимость крючка (ingest только через порог Q2)

Критик прав: «near-zero cost» неверно, если КАЖДЫЙ коммит ингестируется как `observation` — журнал растёт
на всю git-историю без фильтра (тот же дефект Q2, протёкший сюда). **Фикс:** ingest коммита = `observation`-акт
**ТОЛЬКО когда коммит трогает уже графо-адресуемые узлы** (прошедшие admit-порог Q2 — есть ребро/фильтр/policy
или content-projection). Коммит, меняющий лишь неподнятое git-сырьё, `observation` НЕ порождает (его дифф
и так читается по указателю on-demand). Так рост append-only журнала ограничен множеством адресуемых узлов,
а не объёмом истории → «дёшево» становится правдой (крючок = поле-указатель + переиспользование `observation`,
но с фильтром-на-входе). I-3/I-4 не тронуты: журнал по-прежнему у графа, git — read-only сигнал.
