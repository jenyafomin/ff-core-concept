# Идея: наслойность агентской системы + независимый TG-бот

> **Статус: захваченная параллельная мысль, НЕ в стройку.** Владелец просил «закинуть, чтобы не потерять».
> Возвращаемся после прогона ga-rentacar-driver. Пересекается с VISION-agents (личности, 07-15) и orchestration ADR.
> Узел заведён ПАПКОЙ (есть потенциал роста → разобьётся на под-элементы).

## 1. Замысел
Слегка доработать Telegram-агентскую систему → **гибкая база для взаимодействия агентов**. Создать **свой
независимый Telegram-бот**, подключаемый к агентской системе через **коннекторы (NestJS)**. У бота — **глобальные настройки**.

## 2. Наслойность промптов (проверить, что модель агентов её держит)
- **system-промпт для ВСЕХ агентов** (общий слой);
- **промпт конкретного агента**;
- **промпт под топик / роль**;
- **личности** (не просто агенты): свой промпт + подключённые скиллы, **реплицируемы** в разных местах;
- конкретный агент, подключённый к **правилам** + к **топику** или к **поддерживающей сессии** топика;
- всё хранится в **ОДНОЙ системе знаний** (+ скиллы учитывать при сборке слоёв).

## 3. Адресация и «кто отвечает»
- часть агентов **нельзя адресовать линейно**, часть — можно;
- настройка ответа: **все** / **один в чате** / **в топике** / **и в чате, и в топике** — это наслойка.

## 4. Гибкость представления
- настройки **хедеров/футеров**;
- уже есть инструмент взаимодействия агентов с концептами → **docs как пространство презентации** им:
  логировать, потом переигрывать → агенты видят историю;
- **инструмент их взаимодействия — гибко по типам**: спец-настройки прямо в базе знаний (как отображается,
  общие этапы, просмотр conversations) → внедрять.

## 5. Бизнес-процесс через агентскую систему + логи ↔ память
- нужен **свой бизнес-процесс, контролируемый через агентскую систему**;
- **память скоординирована с логами**: логи сохраняются по-своему; со временем **теоретически можно удалять**
  (на первое время — не заморачиваться, ничего не удалять, смотреть поведение вдолгую); разные логи — по разным граням;
- связать: **агентская система ↔ система знаний ↔ проект ↔ настройки TG-проекта**.

## 6. Несколько наборов настроек TG-проекта
- одни — **чисто под агентскую систему** (расширяют возможности через модульность) = «общий/general»;
- другие — **под конкретный запуск для клиента** (цена/тенант).

## 7. Референс для реализации
