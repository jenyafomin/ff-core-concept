# Процесс: space-scope

## Суть
Пространство (TG-группа/топик, в т.ч. вложенное) решает «можно/нельзя» для КОНКРЕТНОГО пользователя —
через `policy_default` + точечные `policy_overrides`, а не одну строку прав на всё пространство.

## Вход
- `space(U4)` — `members[]`, `policy_default`, `policy_overrides[]`, `roles[]`, `binding`.
- Актор (`user`), пытающийся выполнить действие (`read`/`write`/`trigger_agent`/…).
- Родительское пространство (`space.parent`), если пространство вложенное (топик внутри группы).

## Шаги
1. Актор пытается выполнить действие внутри пространства.
2. Резолвится `member`-запись актора в ЭТОМ пространстве (ребро `user --member-of--> space`); если
   записи нет — статус актора в пространстве не определён.
3. Ищется `policy_overrides` для этого пользователя в этом пространстве.
4. Если override ссылается на `role` — резолвится `role.allow/deny`.
5. Если override отсутствует — используется `space.policy_default`.
6. Если пространство вложенное и у него нет собственного override/default для этого случая — правило
   наследования от `space.parent` ПОКА НЕ ЗАФИКСИРОВАНО (см. Ограничения).
7. Решение (allow/deny) применяется к действию.

## Выход
- Allow/deny-решение для конкретного действия конкретного пользователя.
- При отказе — возможен новый `event` (напр. `agent.error` или системное уведомление), если попытка
  всё равно предпринята.

## Ограничения
- **Наследование вложенных пространств не решено.** Топик внутри группы — переопределяет default группы
  полностью, или мержит? Открытый вопрос владельца (Q-1 в space-team-role.design.md — вообще неясно,
  одна ли это единица с гранями или три разные: space/team/role).
- **Конфликт role.deny vs override.allow не разрешён правилом.** Если роль запрещает, а точечный override
  разрешает (или наоборот) — чья воля побеждает, не описано.
- **Отсутствующий member не определён.** Если актора нет в `members[]` — тихий deny или ошибка? Сейчас
  оба чтения возможны.

## Открытые вопросы
- Q-1: `policy_overrides` наследуются ли от группы к топику, и как разрешается конфликт «default группы»
  vs «override топика»?
- Q-2: роли живут внутри каждого `space` или в общем справочнике `roles/` (плюрал-контейнер), на который
  пространства ссылаются?
- Q-3: становится ли отказ (denied-попытка) сам по себе логируемым `event`/актом (аудиторский след), или
  остаётся просто молча заблокированным?

## Мини-пример
```json
// до: гость пытается триггернуть агента в топике без override
{ "user": "user:guest-1", "action": "trigger_agent", "space_policy_default": { "can_trigger_agent": false } }

// после: default применён — отказ
{ "decision": "deny", "reason": "policy_default.can_trigger_agent=false, override отсутствует" }
```
