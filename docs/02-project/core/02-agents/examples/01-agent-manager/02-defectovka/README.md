# Дефектовка — накидываем каждую единицу как данные

> Здесь мы **вширь** разбираем каждую единицу карты: какие у неё переменные, под-сущности, связи с
> другими единицами, и какую **форму данных** она хочет. Одна единица = одна подпапка `NN-<единица>/`
> с файлом `<единица>.design.md`. Нумерация — по ходу разбора модели (см. `../concept.json`).

## Формат каждой единицы (`.design.md`)

Каждый файл держит один шаблон, чтобы всё сходилось в граф:

1. **Суть** — 1–2 фразы, чем единица является в системе.
2. **Переменные (поля)** — таблица `поле · тип · зачем · пример`. Не наивно: где нужен вложенный
   конструктор — показываем конструктор, а не строку/массив.
3. **Под-сущности** — что внутри само становится узлом (напр. у agent → skill, mcp-binding).
4. **Связи (рёбра)** — `--предикат--> другая-единица` (совпадать с картой в overview).
5. **Форма данных (конструктор)** — короткий JSON: как единица рождается/управляется как данные
   (`id · тип · состояние · связи · линза · акты/история`). **1 быстрый пример + 1–2 варианта.**
6. **Дизайн-паттерн / метод** — что хорошего этот кусок дал (конструктор, линза, снапшот, scope…).
7. **Открытые вопросы** — что неясно (уходит в `../concept.json`).
