# U11 · cost/snapshot — токены и контекст как история срезов

## 1. Суть
Как «живёт» ресурс во времени — токены, потребление, размер контекста. **Не текущее число**, а
**серия срезов** (`snapshot`), каждый привязан к моменту и субъекту (агент/действие/контекст).
Тренд и «кто сколько потратил» (сам агент vs другие агенты) считаются НАД историей срезов, а не
хранятся отдельно как единственная истина.

## 2. Переменные (поля)

| Поле | Тип | Зачем | Пример |
|------|-----|-------|--------|
| `id` | node-id | тождество среза | `snapshot:agent-ff:2026-07-23T14-05` |
| `at` | timestamp | момент среза | `2026-07-23T14:05:00+03:00` |
| `subject` | ref | что измеряем | `agent:ff-personal` |
| `subject_kind` | enum | тип субъекта среза | `agent \| action \| context` |
| `metrics` | конструктор | сырые числа НА момент среза | `{tokens_in, tokens_out, tokens_total, context_size}` |
| `delta` | конструктор | изменение относительно предыдущего среза того же subject | `{tokens_total: "+1240"}` |
| `bound_to` | конструктор (было `scope` — переразведено; тот же паттерн, что `skill.bound_to`) | к чему привязан срез — полиморфно (loop-run/задача) | `{axis: "loop-run", ref: "loop-run:2026-07-23-a"}` |
| `attribution` | конструктор | разбивка «я vs другие агенты» ВНУТРИ границы `bound_to`; `others` — массив записей, не плоская карта по ключу | `{self: 1240, others: [{agent: "agent:critic#1", tokens: 300}]}` |

## 3. Под-сущности (сами становятся узлами)
- `metrics-slice` — сами числа среза (вложенный конструктор, не плоские поля верхнего уровня).
- `attribution-entry` — доля конкретного агента в общем расходе (кто именно и сколько); элемент массива
  `attribution.others[]`, не значение по ключу в плоском объекте.
- `aggregate-view` — производная сумма/тренд по СЕРИИ снапшотов — это **view** (было «линза»),
  вычисляется поверх истории, а не хранится как отдельный узел-истина (иначе рассинхрон при новых срезах).

## 4. Связи (рёбра)
```
snapshot --measures--> {agent(U1), action(U13), context, task(U6), loop-run(U9), event(U10), output(U12)}
snapshot --bound-to--> {loop-run(U9), task(U6)}   (было `scoped-to` — переразведено на предикат из словаря, полиморфно, несёт axis — см. bound_to)
snapshot --follows--> snapshot                    (предыдущий срез того же subject → цепочка для delta)
agent(U1) --produces--> snapshot                  (эхо agent.acts — каждый акт может рождать срез)
```
> Реципрокность (реконсиляция): `measures` расширен до `{task, loop-run, event, output}`, потому что
> 06-planning, 09-graph-loop, 10-event и 12-output ссылаются на `cost/snapshot --measures--> {их узел}` —
> граф не должен «лгать» в одну сторону.

## 5. Форма данных (конструктор)

**Быстрый пример (срез по агенту, внутри лупа):**
```json
{
  "id": "snapshot:agent-ff:2026-07-23T14-05",
  "type": "snapshot",
  "at": "2026-07-23T14:05:00+03:00",
  "subject": "agent:ff-personal",
  "subject_kind": "agent",
  "metrics": { "tokens_in": 3200, "tokens_out": 1100, "tokens_total": 4300, "context_size": 48120 },
  "delta": { "tokens_total": "+1240", "context_size": "+820" },
  "bound_to": { "axis": "loop-run", "ref": "loop-run:2026-07-23-a" },
  "attribution": {
    "self": 4300,
    "others": [ { "agent": "agent:critic#1", "tokens": 900 } ]
  },
  "follows": "snapshot:agent-ff:2026-07-23T13-50"
}
```

**Вариант A (`subject_kind: "action"`):** срез привязан к конкретному tool-call/действию, а не ко
всему агенту целиком — точечная стоимость одного шага.

**Вариант B (`subject_kind: "context"`):** срез самого ОБЪЁМА контекстного окна в момент лупа (не
расход токенов, а «сколько сейчас весит контекст») — нужен для трендов «раздувается ли контекст».

## 6. Дизайн-паттерн / метод
- **Snapshot-as-history** — ресурс никогда не «текущее число»; всегда серия срезов + цепочка `follows`
  для вычисления `delta`. Тренд читается по серии, а не хранится отдельно.
- **Attribution-inside-bound_to** — «сам агент vs другие агенты» считается ВНУТРИ конкретной границы
  `bound_to` (луп-прогон/задача), а не глобально — иначе непонятно, за что именно платили.
- **Aggregates are views, not truth** — суммы/тренды — `view` над снапшотами (как `views` у U6/U7),
  никогда не отдельный хранимый узел-истина.

## 7. Открытые вопросы
- Q-1: с какой частотой рождается snapshot — на каждый tool-call, на фазу лупа, или по таймеру?
  Это прямо определяет объём данных истории.
- Q-2: `attribution.others` — считается только по прямым `delegates-to`-детям агента, или по всему
  поддереву делегирования (внуки под-агентов тоже входят)?
