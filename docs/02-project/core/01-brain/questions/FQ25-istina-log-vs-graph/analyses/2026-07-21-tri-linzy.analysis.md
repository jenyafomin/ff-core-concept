# Полнота 4 примитивов — синтез трёх линз (2026-07-21)

Вопрос владельца: полны ли «4 грани» (узел · ребро · view-def · поле-паспорта); достаточно ли гибка
структура, чтобы поверх нужны были только системные механики; или нужна 5-я грань. Три независимые
линзы — abstract-thinker (базис/аналоги), critic (адверсариальная атака), analyst (заземление на
DL-01…29 и FQ01-24) — сошлись.

## Сходимость (все три линзы)
1. **Как модель ДАННЫХ 4 примитива почти полны.** Заземление: 17/19 реальных потребностей ложатся
   чисто; все прежние «упущения» (календарь/`validFrom`, отношения людей, забвение-soft, 10 полей
   паспорта, consent/scope, grant-как-узел) закрыты полем/узлом/ребром — **ни разу пятым механизмом
   данных**. Прецедент важен: проект де-факто ни разу не добавлял примитив, только поля/узлы/рёбра.
2. **Единственная настоящая течь — ВРЕМЯ/ЖУРНАЛ.** Проект принял ВСЕ следствия event-sourcing
   (append-only · rebuild-from-journal день-1 · «паспорт = read-time проекция» · bitemporal), но сам
   журнал назвал «механикой-позвоночником» (OVERVIEW §2), а не примитивом. Журнал онтологически
   первичнее паспорта (из него всё пересобирается) → это спрятанный 5-й примитив.
3. **«Движок глупый» — ложно.** Движок уже несёт: propagation согласия («2-й столп движка»),
   integrity-каскад, порядок записи (concurrency), merge по canonical_id, расщепление
   метаданные/payload при erase. Это активные обязательства целостности, не «глупое кручение».

## Развилка над развилкой
Настоящий вопрос — **не «4 или 5», а «что первично: ЛОГ или ГРАФ?»** (см. INDEX, варианты A/B).
Структурно базис = *property-graph + поднятая-в-примитив проекция*; порождающий принцип = скрещение
{вещь|связь} × {записано|вычислено}. Ближайший богатый аналог — event-sourcing: из него взяты ВЫВОДЫ
(append-only, rebuild, паспорт-проекция), но не взят ПРИМИТИВ (event). Полнота базиса контингентна
выбору A/B — поэтому спор о числе примитивов нельзя закрыть, не ответив на лог-vs-граф.

## Прогон кандидатов в 5-ю грань (сводится к 4 или требует примитива)
| Кандидат | Вердикт | Комментарий |
|---|---|---|
| ВРЕМЯ / event / лог | **НЕ сводится** (единственный) | семантика лога (порядок, immutability, «паспорт — его проекция») — свойство субстрата, не строка в нём |
| ПРОЦЕСС / loop / садовники | сводится | агент(узел) читает виды, пишет узлы/рёбра/поля; состояние = поля |
| ТОЖДЕСТВО / identity | данные — да, операция — нет | `canonicalId` — поле; merge — глагол движка |
| СОГЛАСИЕ / грант | данные — да | `scope/consent/categorized-as`; Конституция = каскад-закон движка |
| НЕОПРЕДЕЛЁННОСТЬ / epistemic | сводится | `epistemic/confidence/status` — поля |

## Вторая ось, которую проект не выписал
Рядом с «4 примитивами данных» есть **ось «контракты движка»**, нигде не сведённая в один список:
`append-only/rebuild · propagation согласия · integrity-каскад · порядок записи · policy-каскад ·
merge по canonical_id`. Терминологическое следствие: `Act`/`Lens` в дереве помечены `primitive-home`,
хотя OVERVIEW §3 их в «4 примитива» не включает → иллюзия 5-6 примитивов у нового читателя.

## Недостающие системные механики (не примитивы)
1. **Компакция лога / crypto-shredding** — мирит append-only с hard-erase (иначе death-by-design; COMPLETENESS §6).
2. **Порядок записи (concurrency)** в журнал одного `state` — открытый блокер ADR оркестрации.
3. **Reconcile реестра типов** (namespacing + merge-by-canonicalId) — чтобы «рост без миграций» был правдой.
4. (минор) **Алгебра рёбер** — композиция/тождество (CT-долг); проверить, stateless ли `view-def`.

## Топ-места, где базис реально протекает (по риску)
1. **Журнал** — назван механикой, работает как примитив (источник истины, rebuild).
2. **hard-erase** — append-only и true-erase не могут быть оба абсолютны (нужен crypto-shred).
3. **Concurrency** — нет понятия «эксклюзивная запись»/консенсус порядка (признано в ADR).

## Вердикт
Базис ПОЛОН как **форма данных**; НЕ полон при собственных ES-инвариантах проекта (нужен примитив
event) — но это решается выбором A/B, а не механически. Рекомендация: system-architect фиксирует
развилку «лог vs граф» отдельным ADR (R4); fable-advisor даёт резкий вердикт.

## Источники (линзы)
- abstract-thinker — порождающий принцип, аналоги (RDF/LPG/CT/event-sourcing), реврайт «лог vs граф».
- critic — журнал как замаскированный примитив; «движок не глупый»; смешение двух наборов «4-х».
- analyst — инвентарь 19 потребностей (17 чисто / 1 ❌ hard-erase-каскад / 1 ⚠️ Act); прецеденты закрытия пробелов.
