# FQ20 — «Биография» как род узлов

## 1. Вопрос
«Биография» как отдельный род узлов (не грань ячейки)?

## Зачем / откуда
Из activity_logs; `synthesis/2026-07-05-brain-components-and-source.md:89-91,128,158`. Источник
говорит больше, чем упрощённая формулировка: «взаимодействие — это РОД узлов (хранение, План III)
+ ЛИНЗА (взгляд, План IV). Оба, не одно» (:89). Также: «провенанс = только первая строка
биографии» (:91) — переименование «провенанс» → «биография» несёт смысл, не сводимый к одному
роду.

## Варианты ответа
- A — биография = отдельный хранимый append-only род (наравне с прочими родами)
- B — биография = линза/вычисляемое представление над журналом операций (не отдельное хранение)
- C — **оба**: append-only РОД (План III, хранение) + ЛИНЗА над ним (взгляд, План IV) — не одно и то же

## 2. Рекомендация
**Да — по онтологии; C, не A.** Биография — не грань ячейки. Но формула не «род ИЛИ линза», а
«род (хранение, План III) + линза (взгляд, План IV), оба не одно» (источник :89). Статус понижен
с «✅ очевидно-да» до **«да — по онтологии; механизм сборки линзы → ADR/architect»**: онтологическое
место решено, но сам факт «оба, не одно» уже требует, чтобы architect специфицировал (а) контракт
рода-хранилища и (б) правило материализации линзы — это не готовый к реализации контракт, а решение
уровня плана (согласовано с FQ16, План III).

## 3. Выбор / что делаем (план)
1. Зафиксировать формулу «род (append-only, План III) + линза (вычисляемая, План IV), оба не
   одно» — не терять половину решения при дальнейших выжимках.
2. Развести/увязать с FQ13: **под-вопрос без ответа** — «биография-род» это тот же журнал операций,
   что фиксирует FQ13, или отдельный ВТОРОЙ (производный/агрегатный) род, материализуемый из
   журнала FQ13? Без явного ответа architect получает две пересекающиеся формулировки одного
   артефакта. Передать вопрос как есть, с пометкой «требует совместного решения с FQ13».
3. Явно пометить зависимость от FQ24 («вещь ⟂ встреча», нератифицирован): FQ20 фактически
   ПРЕДВОСХИЩАЕТ вывод FQ24 («биография — встреча, не вещь»). Принять FQ20 как локальный
   прецедент, который по ратификации FQ24 должен быть сверен задним числом — не блокировать
   на этом FQ20, но не считать его независимым от FQ24 основанием.
4. Механизм сборки линзы (как именно вычисляется взгляд «жизнь ячейки» из рода-журнала) —
   передать system-architect вместе с законами propagation (кандидат в ADR «Конституция памяти»,
   источник :158). Не решать здесь.

## B. Возражения (стилман → опровержение)
Стилман: «биография = проекция activity_logs, не отдельный род» — частично ВЕРЕН на уровне слов
источника («биография — не в ячейке, а в потоке операций вокруг неё; ячейка лишь несёт `id`, по
которому биография СОБИРАЕТСЯ», :91) — это описание ЛИНЗЫ, а не отдельного хранимого рода. Но
источник отдельно и прямо называет «взаимодействие» родом (хранение, План III) — то есть сам
термин «биография» двусмыслен уже в первоисточнике: то имя рода-хранилища, то имя
линзы-представления. Опровержение стилмана: источник не выбирает одно из двух — явно требует
«оба, не одно» (:89). Скрытое допущение упрощённой версии FQ20 (что биография — хранимый род
наравне с прочими, без линзы) неверно; скрытое допущение чистого стилмана (что биография —
только линза, без своего рода) тоже неверно. Верно C.

## Критерии готовности
- В INDEX явно присутствует формула «род + линза, оба не одно» (не только «род»).
- Явно решено (совместно с FQ13), различаются ли «биография-род» и «журнал операций FQ13», или
  это один и тот же артефакт под двумя именами.
- FQ24 ратифицирован ИЛИ FQ20 явно принят как локальный прецедент с пометкой «сверить с FQ24
  задним числом».
- Architect получил: (а) контракт рода-хранилища, (б) правило материализации линзы, (в) законы
  propagation — как единую спецификацию, не как россыпь из синтеза.
