# FQ7 — referent + hard-erase
> Родитель: [../INDEX.md](../INDEX.md) · Слой L (время/операции/происхождение) · 🔴✅ критично-сейчас
> **Эталон формы папки-вопроса** — по этому шаблону строятся остальные FQ.

## 1. Вопрос
Заложить грань `referent` (запись о третьем лице) + операцию `hard-erase` (жёсткое удаление) С ИТЕРАЦИИ 1?

## 2. Рекомендация
**ДА.** Death-by-design: грань нельзя восстановить постфактум (почему → [zachem.md](zachem.md)).
Разбор вариантов → [overview.md](overview.md).

## 3. Выбор / что делаем
_ждёт финального «да» владельца._
План действий при «да»:
1. Зарезервировать грань `referent` в паспорте ячейки с 1-й итерации.
2. Заложить операцию `hard-erase` (жёсткое, не soft-удаление) в контракт движка.
3. **Со-проектировать с FQ13:** контракт журнала append-only обязан хранить hard-erase как
   МЕТАДАННЫЕ операции (кто/когда/тип/target-id вечны), а payload заменять tombstone-маркером —
   иначе право на забвение физически неисполнимо (см. Возражения).

## Связи
- **FQ13** (append-only) — `tension-with` / co-design **КРИТИЧНО**: hard-erase = операция, значит по
  FQ13 ложится в неизменяемый лог; разрешимо только через разделение метаданные/payload+tombstone.
- **FQ3** (хребет) — `grounds`: инвариант «согласие референта нельзя переопределить политикой владельца»
  = первый жилец уровня Конституции.
- **FQ19** (import≠human) — `refines`: разметка происхождения записей о третьих лицах.
- **FQ5** (эмердженс) — `tension-with`: эмерджентные/производные узлы должны НАСЛЕДОВАТЬ hard-erase
  источника, иначе право референта обходится через «инсайт».
- **FQ10** (custodial-override) — `sibling`: та же death-by-design природа audit-грани.
- Ценности: **Ц-7 Согласие**, **Ц-5 Суверенность** — несущие.

## Возражения / что может сломать
- **append-only ↔ hard-erase.** Если журнал (FQ13) копирует стираемый payload внутрь лога — стирание
  формально, право на забвение нарушено. Снимается только со-проектированием (лог = метаданные + tombstone).
- **Невыводимость завышена.** Записи, связанные ребром с узлом-персоной, выводимы постфактум; реально
  невыводим лишь неструктурированный остаток — но его достаточно, чтобы death-by-design держался.
- **Склейка грани и операции.** `referent` (грань — истинно death-by-design) и `hard-erase` (операция —
  критична из-за формата лога, а не самой грани) — разные по типу; держать как два обязательства.

## Критерии готовности
Закрываем, когда: (1) владелец сказал «да»; (2) контракт журнала FQ13 согласован (метаданные/payload/
tombstone); (3) правило наследования hard-erase производными узлами (FQ5) сформулировано; (4) грань
`referent` внесена в паспорт-контракт итерации 1.
