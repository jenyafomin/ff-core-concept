# FQ15 · Зачем / почему возник

Дом дееспособен — владелец уже построил куски единицы памяти в собственных прошлых проектах
(CRM-Rent, InstaApp), а не изобретает всё с нуля. Обзор дома — самый недооценённый вход за все
витки дожима: он переводит спор из «красивая ли идея» в «что уже работает боем». Источник:
[`synthesis/2026-07-05-fable-nonlinear-dig.md:85,102`](../../analyses/2026-07-05-fable-brain-dig/2026-07-05-fable-nonlinear-dig.md).

Оригинал (строка 102): «Рекомендую сделать обзор чужих проектов ПОСТОЯННЫМ входом (не разовым):
перед каждым новым примитивом спрашивать "а нет ли этого уже в CRM-Rent/InstaApp?". Дешевле
подтвердить, чем вывести.» «Чужих» здесь = «других (не этого проекта)» — CRM-Rent/InstaApp
принадлежат самому владельцу, это не данные третьих лиц.

8 из ~15 несущих граней единицы памяти уже прошли продакшн в этих проектах: снапшот-в-момент
(order_snapshots), append-only операционный лог (activity_logs), status-lifecycle, soft-delete ⟂
hard-erase (FQ7 подтверждён практикой), RLS/tenants (Ц-5 Суверенность + Ц-7 Согласие),
planned/actual поля, полиморфное ребро (reference_id + reference_type), embeddings-матч.

**Важно не путать с чем:** это эвристика ПРОЕКТИРОВАНИЯ (Fable/Opus смотрят на архитектуру дома за
паттернами), не канал ДАННЫХ в работающую память. Если это когда-либо станет буквальным импортом
операционных данных (тенанты/клиенты CRM-Rent) — см. guard-rail в [INDEX.md](INDEX.md) раздел 3 и
связку FQ19+FQ7.
