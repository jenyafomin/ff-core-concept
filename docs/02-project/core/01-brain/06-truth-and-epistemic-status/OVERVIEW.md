# 06 — Правда и эпистемический статус (простыми словами)

## Что это
Память хранит не только факты, но и **насколько мы им верим**. У каждого утверждения (claim) есть
6 «осей правды»: откуда пришло (провенанс), совпадает ли с миром, не противоречит ли другим,
свежее ли, какой у него эпистемо-статус (точно / предположение / слух), и полное ли (или чего-то
не хватает / кто-то молчит). Это узел, где мы решаем, **как субстрат ведёт себя с сомнительной правдой.**

## Зачем это нужно
Агенты постоянно читают память и действуют по ней. Если факт **спорный** (конфликтует с другим) или
**протух** (свежесть просрочена), у движка есть выбор: либо вообще **не отдавать** его (fail-closed,
безопаснее для доверия, но полнота страдает), либо **отдать с честной меткой** «это сомнительно»
(fail-open, полнее, но риск, что метку не прочитают). Без решения агент может действовать на ложной
или устаревшей ячейке — это прямой удар по доверию (Ц3).

## Статус
DRAFT. Форк НЕ решён — ждёт владельца. Форма-первоисточник (RESOLVED по 6 осям, но сам выбор default
открыт) лежит указателем в `docs/00-states/.../topics/02-truth-keystone/`. Кода по этому узлу не пишем
до явного «строй».

## Светофор
- 🔴 **Односторонняя дверь:** выбор refuse vs serve-with-label задаёт поведение доверия — как только
  первые агенты начнут действовать по claim'ам, ретрофит поведения дорог. Изоморфно R4 (PII).
- 🟡 Под-вопрос: правда — это **3-я «нога» субстрата** (равный примитив рядом с узлом/ребром, тогда
  нужен свой ADR) или **read-time-лицо** поверх узла/ребра (тогда — раздел внутри assertion-механизма).
- 🟢 Разбор осей уже сделан (truth-keystone) — здесь только дом-тема + указатель на форк.
