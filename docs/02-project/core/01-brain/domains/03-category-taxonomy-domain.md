# Домен 03 — 🗂️ КАТЕГОРИИ / ТАКСОНОМИЯ (кандидат — история)

> Кандидат-домен. Решить в след. сессии: отдельный домен или грань графа знаний (01)?

## Вопрос
Нужен ли **отдельный домен категорий/таксономии**, или категория = обычный узел-контейнер + рёбра
`member-of` внутри домена 01 (как «папка = узел», по совету Fable)?

## Опора
- Уже принято в каноне: **дом + категория = ДВА отдельных ребра** (не слитое), см. `docs/STATE.md` / brain INDEX.
- Fable: папка/категория = узел особого типа, не новый примитив → скорее **грань домена 01**, но глубина
  таксономии (иерархии, мульти-принадлежность) может оправдать выделение.

## Policy-as-data + поведение в БД (заложить)
Категория = узел-контейнер + рёбра `member-of` (**папка = узел**). policy: глобальные vs проектные таксономии =
`scope` на policy-узле. Мульти-принадлежность — **read-time вид**, не дубль узла. Если глубина иерархий не
оправдывает отдельный домен → **грань домена 01** (решает Fable).

## Открытые вопросы
- Мульти-категорийность (узел в N категориях) — VariantGroup(`and`) или просто N рёбер?
- Категории глобальные (все проекты) vs проектные — стык с доменом 02.
