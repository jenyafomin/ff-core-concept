# Реестр edge-type — домен 01

> Критерий класса: нужно ли когда-либо СОСЛАТЬСЯ на само отношение (оспорить, забыть, дать/отозвать
> согласие, спросить «кто утверждает?»). Да → assertion-edge. Нет → thin-ref. Одна концепция «связь», два
> класса хранения (В4). Инварианты 🔴 сейчас: тип ребра из открытого seed-реестра · endpoint всегда
> `canonicalId` (никогда path) · DAG на derived/cascade-рёбрах.

## Класс 1 — thin-ref (поле узла, без паспорта, судьба = судьба узла)
Навигация, никто не оспаривает, живёт и умирает с узлом-владельцем.

- **home** — принадлежность узла «дому» (отделено от категории, канон уже решил: 2 разных ребра).
- **facet-of** — узел как грань другого узла (не полноценный факт-отношение).
- **member-of** — узел-член в узле-контейнере (папка-грань → структура, множественная принадлежность =
  read-time вид, не дубль узла). Ставит **ВЛАДЕЛЕЦ**, не оспаривается → thin-ref (расщепление членства, §3).

## Класс 2 — assertion-edge (сущность: свой `canonicalId` + узкий паспорт + тип)
Свой автор/провенанс/жизненный цикл; forgetting-cascade стирает ЕГО, не трогая узлы-концы; несёт
consent-taint (Ц-7).

- **categorized-as** — акт отнесения узла к категории (расщепление членства, §3): несёт **автора + consent**,
  оспорим, участвует в `confirms`-петле (FQ19). Отличие от `member-of`: `member-of` = структура от владельца
  (thin-ref), `categorized-as` = чьё-то утверждение «это относится к X» (assertion, чинит дыру Ц-7 Согласие).
- **caused** — эпизодический инсайт «A вызвало B» (derived, кандидат на каскадное forgetting).
- **derived-from / computed-from** — производность (деривационные рёбра — каскадно hard-erase при FQ05).
- **contradicted-by** — supersession-duty (Ц-3 Доверие): новый факт аннулирует старый, старый не удаляется.
- **provenance** — откуда факт (W3C PROV-стиль `wasDerivedFrom`).
- **variant-of** — узел как вариант другого (внутри VariantGroup, git-ветка по смыслу).
- **chosen-in** — разрешение VariantGroup: какой вариант выбран (append-only, передумать = дописать, R-C).
- **confirms** — origin → effective (FQ19: импорт ≠ человек; `origin` не мутирует, `effective` — read-time
  проекция по `confirms`-рёбрам).
- **refines / raises / tension-with / answers / grounds** — граф диалога/узлов-вопросов (уже используется в
  `docs/dialogue/`; переносится в реестр как формальный тип).

## Слот реактивного триггера
Декларативное поле на ребре под будущий push (`🟡 сейчас поле, механика read-time позже`) — не хранимая
подсистема, просто зарезервированная грань паспорта assertion-edge.

## Открыто (наследие Н-1/Н-5)
Полный seed-список (caused/derived-from/computed-from…) не догфужен на реальных эпизодах владельца —
Fable ждёт живой пример «ребро над папками», чтобы проверить, не прячется ли 3-й примитив.
