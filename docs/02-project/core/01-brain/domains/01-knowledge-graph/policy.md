# Policy-as-data — домен 01

> Хребет (принят, ждёт ратификации деталей): **Конституция > policy-as-data > integrity-as-engine-duty**.
> Каждая из 7 ценностей = **отдельный `policy-node`** в реестре (см. `node-types.md`), НЕ один гигантский
> узел. Разрешение конфликтов policy — каскад, читается как вид `effective` (не руками).

## Каскад
1. **Конституция** — неотменяемые аксиомы (напр. `canonicalId` обязателен — I-1; поведение-данными — I-2).
2. **policy-as-data** — 7 policy-узлов ниже, каждый со `scope`/`appliesTo`, может быть переопределён per-
   проект/tenant (override, не перезапись).
3. **integrity-as-engine-duty** — движок исполняет: дедуп, циклы, каскады, forgetting-consent — код читает
   policy-узлы, не хардкодит правила.

## 7 ценностей → policy-узлы (что требуют от данных/поведения домена 01)

**Ц-1 Читаемость** — паспорт дёшево сканируется, payload вскрывается только по запросу; любой узел отдаёт
нужную грань по цене запроса, не целиком (`view-def` вместо предвычисленного дублирования).

**Ц-2 Тождество** — каждый адресуемый объект имеет `canonicalId` (I-1); bitemporal (В2) различает «тот же
узел изменился» от «это другой вариант» (`variant-of` ≠ мутация); конфликт-протокол для двух assertion-edge
об одном факте — открыт (не покрыт).

**Ц-3 Доверие** — `provenance`-ребро обязателен для assertion-edge; confidence калибруется использованием
(байесово, не хранится статично); `contradicted-by` — supersession без удаления.

**Ц-4 Витальность** — `salience` на cell как поле-политика (не константа); забывание/консолидация исполняет
движок по policy-узлу, не по ad hoc коду; метаболизм не рвёт Тождество (canonicalId переживает консолидацию).

**Ц-5 Суверенность** — каждый узел self-describing: несёт свою policy как данные, а не зависит от кода
конкретного движка — условие портируемости (plug-in, ADR «единый субстрат» переносим FF↔agents-manager).

**Ц-6 Реляционность** — assertion-edge — полноценная единица памяти (свой паспорт/провенанс/жизнь), не
служебная связка; ткань, не мешок узлов.

**Ц-7 Согласие** — consent/scope живёт на узле и на ребре (кому видно, чья это память); forgetting-cascade
обязан учитывать согласие (flag «проводит согласие» на derived-рёбрах, FQ05); auto-close потоков не должен
обходить согласие.
