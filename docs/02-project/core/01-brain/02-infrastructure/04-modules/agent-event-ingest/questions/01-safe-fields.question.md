# ❓ Q1 — какие поля события НЕ-PII и безопасны для графа

## Вопрос
Событие агента (из `gateway.db` / раннера) несёт набор полей. Какие из них считаем **метаданными**
(структура: что/кем/когда/какого рода) и потому безопасными для записи в граф сами по себе — а какие
могут нести содержание переписки/личные данные владельца и требуют отдельного решения (см. Q2/Q3)?

## Кандидаты «да» (метаданные, не содержание)
- `eventId` — тождество события (техн. id, не смысл).
- `unitId` — на какой узел графа событие ссылается (ссылка, не тело).
- `scope` — область/тема (chat:thread и т.п. — техн. адрес).
- `kind` — род события (`query` / `agent_run` / `agent_trace`).
- `severity` — уровень (info/warn/error).

Все пять — **форма**, а не **текст**: их можно писать в граф, не раскрывая, ЧТО именно сказал/сделал
владелец. Они уже покрыты типовой границей D1 (`isProjectable` по `actKind`, telemetry≠life — см.
первоисточник ночи, HANDOFF §4).

## Под вопросом (решить владельцу)
- `summary` — свободный текст → отдельный вопрос **Q2** (это несущая односторонняя дверь).
- Любые `payload`/`args`/`content`/`prompt`/`result` поля события — по умолчанию считаем **PII до
  доказательства обратного** (fail-closed): в граф не пускаем, пока владелец не назвал поле безопасным.
- Идентификаторы третьих лиц (собеседники, контакты) внутри `scope`/адреса — проверить: не утекает ли
  референт третьего лица (V7 — «пишем о 3-м лице без его воли»).

## Что решить владельцу
1. Подтвердить пятёрку «да» (eventId/unitId/scope/kind/severity) как безопасный **allow-list**.
2. Явно назвать любые ДОПОЛНИТЕЛЬНЫЕ поля, которые можно пускать (по умолчанию — ничего сверх пятёрки).
3. Зафиксировать принцип: **allow-list, не deny-list** — новое поле безопасно только после явного «да»,
   иначе не проецируется (fail-closed). Это защищает от тихого расширения утечки при смене схемы события.

## Почему это важно
Пятёрка задаёт **минимальный безопасный экспорт** — на нём можно прогнать «один реальный факт» в
песочницу (Q3) даже без решения по `summary` (Q2). То есть Q1 разблокирует первый шаг сам по себе.
