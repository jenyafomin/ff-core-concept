# ❓ Q2 — судьба свободного текста `summary`

## Вопрос
Поле `summary` события — **свободный текст**, который может содержать фрагменты переписки, тексты
запросов, имена, содержание. В отличие от метаданных (Q1) его нельзя объявить безопасным «по форме».
Что с ним делать при записи в граф?

## Варианты
1. **Обрезать (drop).** Не писать `summary` вообще — в граф идёт только метаданные Q1. Максимально
   безопасно, но теряем читаемость факта (V1: «что произошло» без текста беднее).
2. **Хешировать.** Писать хеш вместо текста — можно сверять «то же/не то же», нельзя прочитать. Даёт
   дедупликацию/тождество без раскрытия, но человеку/агенту нечитаемо (полу-мёртвая грань).
3. **Фильтровать через admission.** Пропускать `summary` через PII-скруббер/классификатор на границе
   приёма; писать только очищенное. Самый гибкий, но самый дорогой и НИКОГДА не даёт 100% гарантии
   (риск ложно-безопасного пропуска — новая поверхность утечки).
4. **Пускать как есть — под явное согласие владельца.** Владелец сознательно разрешает свой личный
   текст в граф. Законно по V7 (это ЕГО данные), но: (а) не решает текст о **третьих лицах** внутри
   `summary`; (б) фиксирует поведение (см. ниже).

## Почему это ОДНОСТОРОННЯЯ дверь 🔴
Граф — **append-only** журнал (`observation`/agent_trace движка M-G1). **Первая реальная запись
`summary` фиксирует поведение**: как только реальный текст лёг в журнал, он там есть — откатить можно
только через `hard_erase`/tombstone (которого enforcement пока НЕ подключён, только форма — см. V7,
ADR-0014 C3/C4). Значит выбор варианта нельзя «попробовать и передумать» на реальных данных: наивный
прогон = необратимая утечка. Поэтому решение принимается ДО первой строки, а первый прогон — только в
ПЕСОЧНИЦУ (Q3), не в боевой журнал.

## Что решить владельцу
1. Выбрать вариант (1–4) для **первого** прогона. Рекомендация ночи: начать с **(1) drop** или **(4)
   под согласие — но в песочнице**, чтобы дверь оставалась дешёвой.
2. Отдельно решить **текст о третьих лицах** в `summary`: даже согласие владельца не покрывает референта
   3-го лица (V7 — «под одним согласием утекают в другое использование»).
3. Зафиксировать: где живёт гейт — в раннере Движа (ДО того как FF увидит данные) или на границе приёма
   FF (это открытый пункт **ADR-0014 C3**, пересекается с Q3).
