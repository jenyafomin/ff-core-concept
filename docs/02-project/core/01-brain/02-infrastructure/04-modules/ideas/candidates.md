> именами — один и тот же механизм под 5 названиями сведён в **один модуль**. Ничего из урожая не
> потеряно: где имён много, они перечислены в колонке «Источник (свёл)». Определённое (подтверждённое) —
> забираем отсюда в **корень** `infrastructure/` отдельной папкой `NN-модуль/`. Разборы по пунктам — в
> `../analysis/`. Всплывшие вопросы — в `../../01-overview/infrastructure-open-questions.md`.

## Складки (binding-типы, НЕ отдельные модули)

> Как в образце agents-manager: часть урожая — это **тип привязки / поле** на уже названном модуле,
> а не самостоятельный модуль. Фиксируем, чтобы не плодить сущности.

- **Бейдж авторства** (system/human/agent, Ц1+Ц3) — поле паспорта (**#7**), питает провенанс (**#4**).
- **Температура / плавные фазы видимости** (Ц1+Ц4) — policy-поле паспорта (**#7**), крутит садовник (**#14**).
- **Trace для высоко-ставочных** (Ц1+Ц3) — верхняя ступень progressive-disclosure + audit-as-cell (**#16**).
- **capability-токены** (Ц5+Ц7+Ц3) — креденшел, который проверяет PEP (**#5**); custody живёт в engine-contract (**#15**).
- **`variant-of` / branch / fork / `template-of`** (Ц6+Ц2) — типы рёбер на Edge Engine (**#11**).
- **`conflicts-with`** (Ц2+Ц3+Ц6) — тип ребра (**#11**), включается Event/Referent Anchor (**#3**).
- **Ephemeral / visibility-scoped агент-класс + приватная эскалация pending** (Ц4+Ц7) — binding на Gardener (**#14**) + PEP (**#5**).
- **Materialized policy / предвычисленное согласие под нагрузкой** (Ц7+Ц1, тема 07.S) — перф-слой (кэш решений) поверх PEP (**#5**) + Read-scale Index (**#12**), инвалидация точечная по событию отзыва.
- **contagion threshold circuit-breaker** (Ц3+Ц6) — предохранитель внутри Confidence Engine (**#8**) / Edge Engine (**#11**).
