# Свод F6 — «кухня шлюза в память»: не «никогда», а лестница · 2026-10-09
- **Status:** review (ждёт «да» владельца на новую формулировку F6) · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-09
- **Потребитель:** владелец → ADR-0017 F6 + будущий ADR-0018 · **Поглощает:** приложение — `analyst-kitchen-reality` · `architect-kitchen-path` · `critic-f6`

## Сходятся 3/3 линзы
- «Никогда» снимается: это была ленивая дверь (вечное второе хранилище вне линзы = «файлы рядом с проектом», что владелец уже отверг 2026-10-08).
- Новая рамка: **правда в памяти, горячая проверка/копия — локально в шлюзе.** Страх «память упала = Telegram молчит» лечится кэшем и откатом, а не отдельным хозяином правды.
- Шлюз УЖЕ так устроен для дедупа (журнал в SQLite + проверка в памяти процесса) → меняется только хозяин журнала.
- Факт: «lease» — это список PID дочерних `claude` для убийства сирот (`print-runner.ts:207-232`), а не замок Telegram. Он привязан к машине → остаётся локальной копией всегда; в память — как событие.

## Лестница R1–R6 (каждый шаг: флаг `GATEWAY_<X>_SOURCE=local|shadow|brain`, 7 дней shadow без расхождений, локальный снимок/WAL, откат флагом)
R1 промпт-слои (линза compose) — мало · R2 привязки тем — мало · R3 зеркало decision_journal/messages (PG-проекция + согласие V7) — средне/много · R4 jobs (CAS) — средне · R5 дедуп-журнал (insert-if-absent+TTL) — средне/много · R6 PID/владение поллером (CAS+fencing) — много, последним.

## R1 — промпт-слои через линзу (первый шаг)
`sys:prompt-layer` (тело, приоритет, правило слияния, статус proposed/active/retired) + ребро `applies_to` → бот/чат/тема/пользователь/проект/агент. Сборка = линза-данные `lens:prompt-compose@1` (+ список версий слоёв, хэш на ход). Шлюз зовёт сервис напрямую (не MCP, ~150 мс) → иначе последний снимок → иначе старый файловый каскад. Правки: `/prompt` владельца = active; агент = proposed (чтобы агент не повышал себе права). Пер-юзер слои — согласие V7 (пока только форма).

## Новая формулировка F6 (предложение)
«Кухня шлюза переносится в память по лестнице R1–R6; правда — в памяти, горячая проверка/копия — локально в шлюзе; дедуп и PID-реестр — последними, с предусловиями CAS/fencing/WAL/снимок/kill-switch.»

Итог: решение (ждёт «да» владельца) — F6 = лестница R1–R6, первым R1 промпт-слои; ADR-0018 «кухня» по скелету из `architect-kitchen-path`.
