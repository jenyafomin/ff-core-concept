## (1) Атрибуция пакета: оба частично правы
Тип-id не даёт атрибуции записей: баг-трекер, создающий core-`task`, несёт `type: task`. Но «стамп на каждой записи» тоже не нужен: у каждого акта уже есть `actor` и `meta.author` (to-act.ts:134,159,196), рёбра несут `meta.author`, а engine привязывает принципала силой (engine.ts:92). Атрибуция = принципал-писатель, не тип. Определения типов и предикатов атрибутируются префиксом имени. Настоящая дверь: **формат принципала**. ADR молчит, что `actor` пакета = `pack:<id>`. Если первые записи придут с произвольным actor, uninstall/export/согласие по пакету станут эвристикой навсегда. Оговорка: делегирование (агент пишет за пакет, engine.ts:97-98) ломает вывод из actor. Поэтому опциональный `provenance.pack` дёшев, но не обязателен.
**Патч D1, «На записи СЕЙЧАС»:** «Новых полей нет. Атрибуция записи и ребра к пакету = принципал-писатель (`actor`/`meta.author`), штампуется шлюзом, не клиентом; принципал пакета ВСЕГДА `pack:<id>`, системного — `sys:<id>`. Определение типа/предиката принимается только от принципала, чей префикс совпадает с префиксом имени. Делегирование за пакет пишет `provenance.pack` (необязательное; отсутствует = атрибуция по actor).»

## (2) Коллизия `comment`: ADR прав по замыслу, текст не закрывает
Подтверждено: `Registry.addType` (registry.ts:29-34) пишет по голому имени, последний побеждает; id узла `typedef:<name>` один. Правило «голое = ядро» закрывает коллизию **только если** запись голого не-ядерного определения отклоняется. Сейчас отклонять нечему, а `foldAct` терпим при replay. Это дверь данных: однажды записанное голое определение останется в журнале.
**Патч D1 (+абзац):** «Валидатор записи type-def/predicate-def, обязательный ДО первого определения кроме genesis: (а) голое имя допустимо только из замороженного списка `CORE_NAMES` (genesis); (б) префикс ∈ {`sys:`,`pack:`,`u:`}, иначе отказ; (в) правило действует и для предикатов (`registry.preds`, cardinality глобальна); (г) определение ядерного имени от не-genesis отклоняется (иначе `task@2` от плагина перекрывает ядро); (д) в replay голое не-ядерное имя читается как `u:<имя>` (alias), журнал не правится.» Проверить: все ядерные имена из D1 (`note`, `day`, …) действительно есть в GENESIS_TYPES.

## (3) D3: честно частично
ADR честен про engine.ts:145,153 и список sync-вызовов, но **не называет** `BrainDomain.store: DurableFsStore` (schemas.ts:48,84), `scanJournalRegistry` в обход порта (registry.ts:200) и backup по файлу. Все они кодовые двери: данные не затрагивают, цена растёт линейно с кодом. Вариант C тяжелее аналитикова (c) (хук `JournalSink.append` после fsync, ~20 строк, без правки ядра); ADR должен показать (c) как вариант F2-bis. Реальная дверь данных: перенос идёт только адаптер-в-адаптер с сохранением `seq`/`recordedAt` (Engine.write перештамповывает время, engine.ts:74).
**Патч D3 «Формат журнала»:** «Миграция и replay идут НИЖЕ Engine (адаптер→адаптер), сохраняя порядок строк и `recordedAt`; через `Engine.write` запрещены. Битые строки replay сообщает, не теряет молча. Предпосылки (код): типизировать `BrainDomain.store` на `StorePort`; вынести проход 1 реестра и backup за порт.»

## (4) Ловушки
- `persistence_class`/`placement` в type-def (D2) — мёртвые данные: `parseTypeDef` молча отбрасывает неизвестные ключи (registry.ts:~140), потребителя нет, `ephemeral` обещает «не в журнал» без исполнителя. Обязательное поле «навсегда» без потребителя — уровень N+1 до прогона N. **Патч:** вынести D2 в «зарезервировано, не писать до первого потребителя»; `friction→event` оставить как чтение.
- Слои: `sys:` и `pack:` различаются только доверием, кода-различия нет. Резервировать префикс, не реализовывать.
- D6 (лестница шлюза) не относится к типам: уйти в ADR-0018, здесь оставить инвариант fail-open.
- `validate-act.ts:90` считает любую строку с `:` готовым id: проверить, что namespaced-имена не попадают в ref-позиции.

## Перед первыми реальными данными (двери данных)
1. Валидатор имён типов и предикатов (п.2) и замороженный `CORE_NAMES`.
2. Формат принципала `pack:/sys:<id>`, штамп только шлюзом, правило «префикс определения = префикс писателя».
3. Закрыть id входящего сообщения (ADR-0016 D10) и пространство idem.
4. Правило «replay ниже Engine» как тест.

## Может подождать (двери кода)
StorePort-типизация, JournalSink/ProjectionPort, read-порт, `i2:` (читатель раньше писателя), расширение rand id, `persistence_class`, манифест.

Итог: решение — ADR верен в канонах (голое=ядро, непрозрачные id), но требует 3 патчей (принципал пакета, валидатор имён с CORE_NAMES, replay ниже Engine) и снятия D2 до появления потребителя; остальное — задача в плане SPEC.
