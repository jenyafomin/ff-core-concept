# Плагины и системные типы — что это на самом деле

## 1. Настоящий паттерн
Пять аналогий — одна форма: **закрытое ядро-словарь + расширения, описанные ДАННЫМИ в том же субстрате + внешний код, который на них реагирует.**

| Аналогия | Что совпадает | Где ломается |
|---|---|---|
| **Kubernetes CRD + операторы** (лучшая) | запечатанный core API (у нас — genesis-пакет, ADR-0016 D3) + custom resources (типы пакета) + контроллер-софт, который читает/пишет через тот же API | в K8s типы не «рождаются из использования»; нет тропы, нет остывания (V4) |
| **Datomic / event sourcing** | схема = факты в том же журнале (у нас `type-def`/`pred-def` актами) | нет согласия/области (V7), нет пакетов как единицы распространения |
| ОС + пакеты | ядро/дистрибутив/userland — три уровня стабильности | пакеты в ОС не делят одну БД |
| Notion/Obsidian-плагины | UI-расширения | у них данные — файлы/страницы, плагин владеет поведением, не схемой — это ровно тот «notes-first», от которого проект ушёл (msg 141) |
| БД + схемы | типы как таблицы | жёсткая схема против тропы |

**Вывод:** плагин = **пакет-контракт** (type-defs + pred-defs + виды + политики) **+ контроллер** (софт, говорящий только 4 глаголами MCP). Ломается K8s-аналогия на одном месте — эмерджентность, и её закрывает тропа (п. 3).

## 2. Какую боль решает владелец (5 «почему»)
Плагины → чтобы инструменты не плодили свои хранилища → чтобы агент, пользователь и софт видели ОДНО → чтобы поведение было **предсказуемым**: каждый участник знает контракт заранее. Корень — **одна поверхность с одним контрактом**. Композируемость — следствие («всё остальное = связи»), предсказуемость — цена входа. Маркетплейс — далёкая форма той же мысли, не цель.

## 3. Тропа vs запечатанные типы — не конфликт, а лестница
Три уровня стабильности одного механизма:
1. **Ядро (sealed):** мета-типы — `type-def`, `pred-def`, акт, область, актёр. Немигрируемо, без него реестр не читается.
2. **Пакет (pinned):** установленные, версионированные (`name@v`), расширяемые через `extends@pinned`. Это **ратифицированная тропа**.
3. **Тропа (candidate):** формы, рождающиеся из использования.

Тропа — путь снизу вверх; «запечатанность» — конец пути. «Нередактируемо, но расширяемо» = неизменна *версия*, а не набор. ADR-0016 это уже допускает формой.

## 4. «Кухня шлюза в памяти» как первый плагин — скорее НЕТ
Против:
- Сообщения/джобы — **поток с высоким объёмом и низкой ценностью**, остывает за часы (V4). Именно кухня порождает «миллионы записей»: требование мгновенности на миллионах **создано выбором первого плагина**, а не нуждой.
- Ставит мозг на **горячий путь шлюза**: падение мозга = немой шлюз; плюс известный баг дублей.
- Доказывает self-hosting, но **не доказывает «пакет + связи + софт»**: у кухни нет связей с жизнью владельца.

За: предсказуемость, единый вид «что делал агент» (V3 провенанс). Это сохраняется дешевле — **указателями** (job → решение/задача), а не копией потока.

**Лучший первый плагин — задачи/баг-трекер:** типы `task`/`bug` уже частично в v0.5, связи с решениями/проектами/людьми естественны, есть читатель-человек (утренний список), объём мал.

## 5. Вопрос, вскрывающий неверную рамку
**«Плагин — это прежде всего набор ТИПОВ или набор ПОВЕДЕНИЙ, которым нужны типы?»** Если поведение (софт) — главное, то рычаг не в реестре типов, а в контракте контроллера (глаголы, подписки, права), и маркетплейс = магазин приложений над общей памятью. Тогда работа над наследованием/версиями сейчас — полировка не той двери.
Вспомогательный: **«кто, кроме самого шлюза, будет ЧИТАТЬ кухню?»** Нет читателя — это лог, не память.

## 6. Самый дешёвый тест (бумажный, 0 кода)
Описать **баг-трекер как манифест-данные** поверх текущего genesis и 4 глаголов (`record·find·read·link`): типы, предикаты, вид, политика + сценарий контроллера (создать баг → связать с задачей → закрыть). Посчитать, что требует правки кода мозга.
- 0 правок → рамка «пакет-контракт» держит, ядро готово.
- Нужны подписки/триггеры/права пакета → верна рамка «поведение первично»; следующее — ADR на контракт контроллера, не на типы.

## 7. Что модель скрывает
Права пакета (что плагин может читать — V7, область), удаление пакета (что с данными, V2/V4), конфликт имён двух пакетов, производительность — отдельная ось, двери (`id` без типа, D2) уже закрыты верно.
