# F6: путь всей кухни в память

## 0. Рефрейм, снимающий «никогда»
Опора на код: каскад промптов в шлюзе — `bot → chat → topic`, склейка, читается каждый ход, файлы = истина
(`agents-manager/src/server/orchestration/conversation-config.ts:60-66`, `turn-executor.ts:257`). Прецедент
переключателя источника по env уже есть: `GATEWAY_PULT_SOURCE=memory|file` (`persistence/pult-source.factory.ts`).

«В памяти» ≠ «в журнале». **«В памяти» = у сущности есть тип в ЕДИНОМ реестре, хозяин — сервис мозга,
доступ — через его порт.** Физическая полоса — по `persistence_class` (ADR-0017 D2): `config` → журнал+снимок,
`event` → журнал/PG, `state` → CAS-ячейка, `ephemeral` → TTL-полоса ВНУТРИ сервиса, в журнал не идёт.
Так дедуп и lease могут переехать в мозг, не раздувая журнал (V4). «Никогда» было ответом на вопрос «в
журнал?», а не на вопрос «в память?».

## A. Промпт-слои как память

**Тип `sys:prompt-layer`** (`persistence_class: config`):
`{ body | body_ref, priority:int, merge: append|prepend|replace|section(<имя>), status: proposed|active|retired }`
+ **ребро `applies_to`** → единица-цель (V6: цель — не строка, а узел). Виды целей открыты: `bot · chat ·
topic · user · project · agent · role · …` — новый вид = новый узел, без правки кода.

**Композиция = ЛИНЗА (данные)**, тип `sys:lens`, конкретная линза `lens:prompt-compose@1`:
- `from`: контекст хода `{bot, chat, topic, user, project(cwd), agent}` (шлюз передаёт кортеж);
- `traverse`: обратные рёбра `applies_to` → слои; `filter`: `status=active`, согласие/видимость;
- `shape`: `compose{ order: [rank вида цели, priority], merge-правило слоя }`.
Сегодня `view-compiler.ts:196-229` знает 3 замороженных вида — `compose` = **4-й вид, одна аддитивная
дверь кода**. Линза сама — единица с id/версией (V5: переносима, шарится).

**Выход:** `{ text, manifest: [layerId@rev…], hash }` — провенанс склейки (V3, видно, из чего собрано).

**Доставка до старта агента.** Шлюз в `buildTask` зовёт сервис мозга **напрямую** (HTTP по unix-сокету,
ADR-0016 D1), не MCP. Таймаут ~150 мс (спавн `claude -p` стоит секунды — бюджет есть).
Порядок источника: **мозг → снимок last-known-good → старый файловый каскад**. Каждый успешный ответ
пишет снимок `.gateway/conversations/<chat>/<thread>/.composed.lkg.md` + manifest. Отказ мозга ≠ отказ шлюза.

**Кто правит:**
- владелец `/prompt …` → шлюз пишет ревизию слоя, принципал = владелец (штамп шлюза, ADR-0017 D1) → `active` сразу;
- агент → `record sys:prompt-layer` со `status: proposed` → активация владельцем (`/approve`). Политика-данные
  на цель `self_edit: allow` может разрешить агенту свой topic-слой (как сейчас с файлом).
- Правка файла PROMPT.md руками в режиме `brain` → расхождение хэша → ингест как `proposed` (не теряется).

**Напряжение с ADR-0016 D7** («файл = истина для документов»): снимается направлением. Сейчас: файл = истина,
мозг = зеркало (`source:{kind:file,hash}`). После флипа: мозг = истина, файл = сгенерированный снимок. **Тот
же файл служит откатом** — переключение флагом, без миграции.

## B. Лестница кухни (F6 = последняя ступень, не «никогда»)

**Общий паттерн безопасности (одинаков для каждой ступени):**
1. Флаг на тип: `GATEWAY_<ENTITY>_SOURCE = local | shadow | brain` (повтор прецедента пульта).
2. `shadow`: истина локальна, мозг считает параллельно, расхождения → лог. Гейт: 7 дней 0 расхождений.
3. `brain`: мозг первичен; локально **всегда** пишется снимок/WAL (outbox, ADR-0016 D12) → при отказе мозга
   шлюз работает с локальным, при восстановлении — **replay с idem** (D10), ниже Engine (ADR-0017 D3).
4. Откат = флаг `local` или переключение ветки владельцем: локальный снимок полон → ничего не теряется.
   Правило: локальная полоса не удаляется, пока ступень не прожила 30 дней в `brain`.

| Ступень | Сущность | class | Предусловие в мозге | Цена | Вес |
|---|---|---|---|---|---|
| R1 | промпт-слои | config | тип+ребро, линза `compose`, endpoint чтения | мало (~2-3 дня) | много: V1,V5,V6 + новые слои user/project |
| R2 | bindings (cwd/model) | config | та же линза (`shape: winner`, нижний побеждает); валидация cwd остаётся в шлюзе | мало | средне |
| R3 | decision_journal / зеркало сообщений | event | **C-bis PG-проекция** (41k на старте), тексты → `body_ref`, **гейт согласия V7** (сообщения третьих лиц) | средне; V7-гейт — много | много: память читает жизнь |
| R4 | jobs / sessions | state | **CAS** `record(if_rev)`, read-your-writes, батч | средне (новый примитив) | средне |
| R5 | dedup (seen_update) | ephemeral | атомарный `insert-if-absent+TTL`, p99 <20 мс, локальный LRU-фронт, явная политика при отказе (fail-open: лучше дубль, чем потеря) | средне-много | мало-средне |
| R6 | lease | ephemeral | CAS+TTL+**fencing token**, локальный арбитр при отказе (иначе split-brain) | много | мало |

Честно про R5–R6: выигрыш — единая модель и видимость (V1), а не новая способность. Цена реальная: мозг на
горячем пути каждого апдейта Telegram. Поэтому — последние, и только когда R4 дал CAS «бесплатно».

## C. Почему первая ступень — промпты
- **Ценность сразу:** владелец сам назвал боль — слоёв нет для user/project/agent. Сегодня новый вид слоя =
  правка кода шлюза; после R1 = новый узел. Это новая способность, не переезд.
- **Дёшево:** низкий объём (десятки единиц), только чтение на горячем пути, 1 раз за ход.
- **Обратимо:** снимок LKG + старый файловый каскад = двойная страховка.
- **Компаунд:** R1 строит ровно то, что нужно дальше — флаг/shadow/LKG-паттерн (R2–R6), первую живую линзу
  (кандидат lens-as-data получает реальный прогон, а не статью), endpoint прямого вызова мозга.
- Альтернатива «первым — зеркало сообщений (R3)»: больше ценности памяти, но упирается в V7 и PG — не первая.
