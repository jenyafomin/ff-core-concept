# 🔌 API: GraphQL vs REST  ← P6

## Что это / решаем
Слой доступа к субстрату для агентов/клиентов/визора.

## Гипотеза владельца
Возможно, идём дальше REST → **GraphQL**: под нашу структуру данных ложится грамотнее — **цикличные,
многоуровневые запросы** по графу. Хорошо стыкуется с **графовой БД**. Это «отдельная ветка», её надо понять.

## Зачем (для кого)
Агенту и визору нужно обходить граф вглубь (узел → рёбра → узлы → …) за один запрос — REST это дробит,
GraphQL/граф-язык — нет.

## Открыто
- GraphQL-слой поверх Postgres vs нативный язык графовой БД (Cypher/Gremlin) vs гибрид.
- Стоимость/сложность GraphQL-схемы при «рост = INSERT типа» (схема API не должна мешать росту данными).
- Кто резолвит проекции (view-def app-level) — совместимо ли с GraphQL-резолверами.

## Связи
→ БД (решаются вместе) · концепт-навигация/визор (потребитель) · модель (форма диктует запросы).

## Готово к потоку
**Fable-советник** (в одном разрезе с БД) + context7 для актуальных доков GraphQL/драйверов.
