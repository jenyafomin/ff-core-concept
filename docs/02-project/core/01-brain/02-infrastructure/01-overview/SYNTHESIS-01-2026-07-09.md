## 1. Запрос (что просили)

Владелец (голосом, 2026-07-09): разложить каждую из **7 ценностей единицы памяти** по направлениям и
идеям — по образцу проекта `agents-manager` (ценности → направления → инфра-решения), общие
инфраструктурные идеи собрать отдельно. Затем — два добавочных штурма: (2) ещё креатива, сильные
нестандартные идеи; (3) пройтись по **пропущенным сценариям** и вывести, какая **общая инфраструктура**
из них напрашивается. Фаза проекта: **НЕ строим — разбираемся КАК построить** (идеи, не код).

## 2. Как собирали (метод)

Скилл `value-decomposition`: лестница **Цель → Ценность → Направление (грань) → Идея (паттерн) →
Инфра-модуль**; дивергенция (ничего не режем) → подъём сквозных идей (≥2 ценности) в `infrastructure/`.
Работу вели субагенты (Fable-оркестратор делегирует, сам контекст не копит):

| Цикл | Что | Агенты | Выход |
|------|-----|--------|-------|
| **1 — Дивергенция** | каждая ценность → 6 направлений + пул идей | 7 (sonnet/opus) + 1 architect (сведение) | `values/NN-*/` (42 направления) + `infrastructure/` (16 модулей) |
| **2 — Креатив** | доп. сильные идеи, кросс-доменные аналогии | 7 (sonnet) | `values/NN-*/IDEAS-CYCLE2.md` (~95 идей, ~30 wildcard) |
| **3 — Сценарии→инфра** | пропущенные сценарии → напрашивающаяся инфра | 7 (sonnet/opus) | `infrastructure/scenarios/01…07-*.md` (~90 сценариев → ~20 новых модулей) |

### 3.3. Новая инфраструктура из сценариев (цикл 3, ~20 кандидатов, на подтверждение)

Сгруппировано по кластерам (источник — `scenarios/`):

- **A. Agent-first безопасность памяти** *(крупнейшая дыра — в 16 не было)*: изоляция «память ≠ команда»
  (instruction-trust taint) · подделко-стойкость паспорта (tamper-evidence + attestation) ·
  детективный/форензик слой + bulk-revert · action-risk gate = f(confidence×staleness×irreversibility).
- **B. Социальная ось (референт как живой субъект)**: движок жизненного цикла референта (политика по
  событиям жизни, не по tx-time) · арбитраж мульти-референтного согласия (кворум/вето).
- **C. Операции над корпусом**: Migration/Recompute Engine · Query Cost Planner (бюджет чтения) ·
  Identity-Operation Log (обратимые merge/split, un-merge).
- **D. Портируемость / plug-in**: Engine Identity/Attestation · Degradation-Disclosure (поле
  `capability-status`) · Module Capability Manifest · Federation Protocol · Cold-Archive Format.
- **E. Долговечность**: Backup/Archive Lifecycle + Tombstone Propagation · Generation-bounded consolidation
  (анти реконсолидация-дрейф).
- **F. Человек ↔ канал**: привратник уведомлений (бюджет прерываний) · линза с каналом как первокласс.
  параметром · ось «черновик≠факт» + промоция ephemeral→постоянное · Consented Export Bundle.

## 4. Конституционные развилки (ждут владельца)

1. **hard-erase** (FQ7 расширился): безусловность vs tombstone vs покрытие бэкапов; риск «оружие абьюзера»
   (стереть улику) и анти-форензика (стереть след стирания).
2. **Согласие-как-ключ** (криптo) — принять как развязку FQ7? (отзыв = уничтожение ключа; блоб цел, но нечитаем).
3. **«Память инертна или может быть командой?»** — архитектурный запрет vs фильтр (модуль A).
4. **Кто подписывает паспорт** — движок (меньше суверенности) vs самоподпись (подделываемо).
5. **Батч-пересчёт** — конституционное исключение от per-cell consent vs PEP-налог на 10⁷.
6. **Конфликт двух со-референтов** — кворум / вето / приоритет владельца.
7. **Федерация vs N попарных контрактов** — развилка уровня ADR до проектирования портируемости.
8. **Предохранительный клапан безопасности vs согласие референта** — узкое аудируемое исключение?

## 5. «Заложить сейчас» (ретрофит невозможен) — приоритет ратификации

Engine Identity/Attestation · канал в контракте линзы · Backup+Tombstone propagation · подпись паспорта.
