# 🧱 DB-готовность: где ломается субстрат

## Цель (одной фразой)
Запустить БД самым быстрым **корректным** способом — найти, где субстрат (2 таблицы + реестры)
ломается, ДО стройки. Зелёный чек-лист → строим M0.

## Главный результат витка 1 (2026-07-16)
**Субстрат НЕ ломается ни на одном злом кейсе.** Три независимых разбора сошлись:
модель хранения выдерживает всё **без третьей единицы и без пятого примитива**.
Реальная работа сместилась из МОДЕЛИ ДАННЫХ в:
1. **Паттерн реификации** — «адресуемо ⇒ узел» (reify-on-demand); рёбра строго узел→узел.
2. **Слой движка (runtime)** — граф инертен (описание + append-only журнал + состояние-как-проекция);
   исполнение/курсор/развилки = движок, не граф.

БД для v1 = **PostgreSQL**; стек = **TS/Node**; Rust преждевременен (пересматривается под мульти-юзер/маркетплейс).

## Чек-лист готовности
| Кейс | Итог витка 1 |
|---|---|
| Реификация / третья единица | ✅ держится |
| Луп/процесс как данные | ✅ держится (поведение → движок) |
| Файлы / строки / дубли | ✅ держится |
| Интеграции / MCP / авторизация | ✅ держится (секрет = ссылка, не значение) |
| Чтение / поиск / масштаб | ✅ Postgres; TS достаточно |
