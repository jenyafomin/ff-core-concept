# Направление 06 — Движковый долг: порядок времени и конкуренция записи

## Суть

Не «грань» тождества, а **субстрат-долг движка**, без которого все пять предыдущих граней рассыпаются:
«as-of T» (02) бессмыслен без **глобального порядка времени**; union-find/merge (01) ломается при
**гонке записи двух агентов**; варианты и anchor плывут при **рассинхроне часов**. Объект — переложить
целостность тождества на **движок как обязанность** (не на инструкцию агенту): кто присваивает
монотонный T, как разрешается одновременная запись, кто хранит хребет `canonical_id`. Это костяк
«заложить сейчас — ретрофит невозможен»: без порядка и хребта с первого дня данные накопятся кривыми.

## Границы

- **Входит:** источник глобального монотонного времени (transaction-time для 02); протокол конкурентной
  записи агентов (Г16 — без молчаливого затирания следа); рассинхрон часов (валидность valid-time при
  расходящихся источниках); присвоение/владение `canonical_id` (кто «раздаёт» и хранит хребет);
  атомарность merge/split (01) и версионирования (02); DB-control-план (L0 «control plane»).
- **НЕ входит:** СЕМАНТИКА «что есть та же вещь» → 01; политика забвения → 02/Ц-4; модель ролей/прав
  «кто вправе писать» → Ц-5 Суверенность / Ц-3 (Г11 отравление); физический выбор БД/движка — L2-инженерия
  (тут — какие ГАРАНТИИ движок обязан дать, не какой продукт).
- **Тонкая граница с Ц-3 (Г11) и Ц-5:** здесь — **механическая** целостность (порядок, атомарность,
  без гонок); ПРАВО писать/подтверждать и защита от отравления — Доверие/Суверенность. Один шов: «кто
  вправе» (Ц-5) × «как без затирания» (06).
- **Природа:** это одновременно направление И сквозной субстрат — как «гуарды vs инструкции» в соседней
  ценности Безопасности были не гранью, а механизмом enforce. Держим направлением из-за конституционного
  веса, но помним: он под всеми пятью.

## Развилки (веер «как», не режем)

1. **Источник глобального времени.** Централизованный монотонный счётчик/сиквенсер [+ строгий порядок,
   простой as-of / − единая точка, боттлнек] vs логические часы (Lamport/vector) [+ распределённо,
   causal / − нет «настенного» времени для valid-time] vs гибрид (HLC — hybrid logical clock) [+ и
   порядок, и близко к настенному / − сложнее]. Влияет на весь bitemporal (02).
2. **Конкурентная запись агентов (Г16).** Оптимистично (версии + разрешение конфликта версий при
   коммите) [+ без блокировок, масштаб / − отбои, надо мержить] vs пессимистично (лок на `canonical_id`)
   [+ просто рассуждать / − боттлнек, дедлоки] vs append-only лог событий, состояние = свёртка (CQRS/
   event-sourcing) [+ нет затирания в принципе, роднит с 02 / − сложность чтения «сейчас»].
3. **Рассинхрон часов.** Доверять valid-time источника как есть [+ просто / − кривой порядок при
   расхождении] vs нормализовать к серверному T на входе (адаптер) [+ единый порядок / − теряем «когда
   на источнике»] vs хранить оба (source-time + ingest-time) [+ честно, аудит / − ещё поле; но роднит
   с bitemporal 02].
4. **Владение `canonical_id`.** Централизованная раздача (сервис id) [+ гарантия уникальности /
   − точка отказа] vs самогенерируемый (UUID/ULID, ULID даёт и порядок) [+ офлайн, без координации /
   − нет смысловой уникальности, дедуп на 01] vs контент-адресуемый (id = хэш, шов с дедупом 01)
   [+ авто-дедуп буквальных / − id «плывёт» при правке].
5. **Атомарность операций тождества.** Merge/split/версия — транзакционно (всё-или-ничего) [+ нет
   полу-слитых состояний / − нужен транзакционный движок] vs идемпотентно-повторяемо (операция
   переносима, повтор безопасен) [+ устойчиво к сбоям шлюза / − сложнее спроектировать] vs сага с
   компенсацией [+ распределённо / − сложно].
6. **Где живёт control plane (L0-слой «для системы»).** Отдельный служебный слой узла (схема/индексы,
   L0 из В1) [+ явный DB-control, оптимизируем / − ещё слой] vs целостность вне узлов, в движке
   [+ узел чист / − «магия» снаружи] vs гибрид: хребет (`canonical_id`, T) в движке, метки целостности —
   на узле [+ и то, и то видно ИИ / − две точки правды].
