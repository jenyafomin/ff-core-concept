## Суть

Тождество ломается не только временем и ветвлением, но **сменой ФОРМЫ**: части собираются в целое
(композиция), целое рассыпается на части (распад), и ячейка **меняет свой ТИП** (заметка → задача →
метрика). Объект защиты — граница «та же/другая» **при агрегации и переклассификации**: у композита
**свой `canonical_id` или производный** от частей? Переживает ли единица смену типа, или это уже другая?
Смыкается с «волной» L0: группа/атом — вопрос ВЗГЛЯДА, значит тождество композита должно быть дёшево
собираемо и разбираемо, а не жёстко зашито.

## Границы

- **Входит:** id композита (собственный / производный-детерминированный из частей / нет id — композит =
  вид/запрос); part-of рёбра и их роль в тождестве; распад (что с id частей и целого при разборке);
  смена типа ячейки (сохраняется ли `canonical_id`); что переносится между типами (паспорт, история, рёбра).
- **НЕ входит:** дедуп частей → 01; версии во времени → 02; варианты-сиблинги → 03; КАКИЕ структуры
  несут разные типы (это Ц-1 Читаемость / Г26) — тут только «переживает ли тождество смену типа»;
  сам механизм рёбер part-of как связей → Ц-6 Реляционность (шов).
- **Тонкая граница с «волной» (L0):** если группа — это свойство ВЗГЛЯДА (проекция через рёбра), то у
  композита может НЕ быть собственного носителя-id вовсе — он вычисляемый вид. Развилка «композит =
  вещь или взгляд» — центральная и роднит грань с Ц-1/Ц-6.
- **Тонкая граница с 02:** смена типа во времени — это новая ВЕРСИЯ того же id (02) или новая ячейка +
  `succeeds`? Шов явно вынесен сюда из 02.

## Развилки (веер «как», не режем)

1. **Id композита.** Собственный `canonical_id` (композит = полноправная вещь) [+ адресуем, стабилен /
   − ещё сущность, дрейф от частей] vs производный детерминированный (id = f(id частей)) [+ авто-тождество,
   пересборка даёт тот же id / − меняется при смене состава] vs НЕТ id: композит = сохранённый
   запрос/вид над частями (волна) [+ дёшево, самоподобно Г6 / − нельзя «повесить» паспорт на группу].
2. **Роль part-of в тождестве.** part-of — структурное ребро без паспорта (как home/facet-of) [+ легко /
   − состав не аудируем] vs ребро-с-паспортом (когда «A входит в B» — само утверждение, В4-стиль)
   [+ провенанс состава / − тяжелее] — развилка смыкается с Ц-6 и В4.
3. **Распад.** Части переживают распад со своими id, композит закрывается (bitemporal, шов 02) [+ части
   вечны / − «осиротевшие» части] vs распад = удаление композита-вида, части не трогаются [+ чисто, если
   композит был видом / − только для варианта 1.3] vs распад запрещён/только форк [+ безопасно / − негибко].
4. **Смена типа — сохраняет ли id.** ДА, `canonical_id` стабилен, тип — версионируемое поле паспорта
   (02) [+ непрерывность адреса, история цела / − паспорт «прыгает» тип, валидация структуры Г26] vs
   НЕТ, смена типа = новая ячейка + `succeeds`/`was` [+ чисто по типу и структуре / − рвём адрес, теряем
   Г12] vs гибрид: мелкая смена = версия, радикальная = новая ячейка (порог) [+ баланс / − где порог?].
5. **Что переносится между типами.** Всё (паспорт+история+рёбра мигрируют) [+ ничего не теряем /
   − несовместимые поля] vs только `canonical_id` + провенанс, остальное заново [+ чисто / − теряем
   историю] vs перенос по карте-адаптеру типов (policy-as-data: тип несёт правило миграции) [+ автономно
   / − нужна карта на каждую пару типов].
