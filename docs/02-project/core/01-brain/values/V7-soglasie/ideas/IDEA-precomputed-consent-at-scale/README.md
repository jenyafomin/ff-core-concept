# IDEA · Предвычисленное согласие для масштаба

**Суть:** проверка согласия (обход графа рёбер, разрешение наследования/taint) — дорогая операция.
При больших объёмах (тема C) она обязана быть предвычислена и закэширована на самой записи или
в индексе линзы на момент записи/агрегации, а не пересчитываться на каждое чтение. Инвалидация
кэша триггерится точечно — по событию отзыва согласия, не полным пересчётом графа.

**К какой под-грани:** пересекает #3 (visibility-consent), #5 (consent-taint) — вопрос
производительности, не новая грань, но условие дееспособности всех остальных под нагрузкой.

**Открытые вопросы:** где именно кэшируется результат (денормализация на ячейке vs отдельный
индекс линзы) и как инвалидировать без полного пересчёта графа (Q-cost-of-consent-check)?
