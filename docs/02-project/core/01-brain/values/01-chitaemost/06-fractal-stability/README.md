# Направление 06 — Фрактальная устойчивость (любой зум + смена типа)

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md` (ценность 01-chitaemost), П8 в
  `../../V1-chitaemost/questions.md` (Q5), Г6/Г35 и решение В2 (bitemporal-версионирование)
  в `../../../L0-memory-unit.md`

## Суть

Два родственных требования на одном стержне «то же правило работает независимо от
масштаба и времени»: (а) единица читается на ЛЮБОМ зуме — атом/группа/весь граф — по
ОДНОМУ правилу самоподобия (Г6, фрактальная сборка Г35: снаружи дёшево, внутри дорого,
рекурсивно); (б) когда единица меняет тип/роль, старые грани не превращаются в молчаливый
мусор — либо мигрируют, либо явно помечаются устаревшими (П8).

## Границы

- **Входит:** правило самоподобия для композитных узлов (группа читается тем же
  контрактом, что и атом); что происходит с гранью при смене типа узла во времени
  (миграция vs версионирование vs явная пометка stale); где физически проходит граница
  «атом» (абсолютная vs относительная запросу).
- **НЕ входит:** сама лестница раскрытия ОДНОЙ ячейки (→ 03 progressive-disclosure — здесь
  вопрос в том, что ТА ЖЕ лестница работает и для ГРУППЫ ячеек без отдельного правила);
  полисемия граней одной ячейки под разных читателей (→ 02 polysemy-lens).
- **Тонкая граница с 03:** 03 — вертикаль, глубже внутрь ОДНОЙ ячейки; 06 — горизонталь
  (та же лестница на композите из многих ячеек) и время (та же ячейка меняет форму, не
  теряя читаемости прошлых версий).

## Развилки (веер «как», не режем)

1. **Правило самоподобия.** Группа — обычная ячейка, где payload = ссылки на детей,
   рекурсия без спецкода [+ одна реализация контракта чтения на все уровни зума /
   − паспорт группы должен уметь агрегировать rollup (см. 03), не всегда тривиально для
   разнородных детей] vs группа — отдельный тип с собственным контрактом чтения,
   composite-паттерн явно выделен [+ можно оптимизировать агрегацию отдельно / − это уже
   не «одно правило», а два похожих, риск расхождения со временем].
2. **Смена типа ячейки — что с гранями.** Авто-агент-садовник сразу переносит/адаптирует
   старые summary/паспорт под новый тип [+ нет молчаливого долга читаемости / − ещё один
   фоновый процесс, может ошибиться при нетривиальной миграции] vs явная пометка
   `stale-facet` + ручная миграция владельцем/агентом по требованию [+ безопаснее, долг
   виден, а не скрыт / − копится, если никто не разбирает очередь] vs старые грани просто
   версионируются (bitemporal, решение В2 из L0) и не мигрируют вовсе — новый тип пишет с
   нуля, старое читается «as-of» [+ прошлое не трогаем, аудит цел / − текущий обзор графа
   может по умолчанию показать устаревшую грань, если явно не различать «сейчас» от
   «as-of T»].
3. **Кто задаёт правило зума.** Одно глобальное правило для всех типов, движок навязывает
   [+ гарантированная предсказуемость по всему графу / − негибко для нестандартных/
   нестандартно составных типов] vs правило — часть policy-as-data типа, но обязано
   соответствовать общему интерфейсу-контракту, а не конкретной реализации [+ гибко внутри
   контракта / − сложнее верифицировать соответствие на практике].
4. **Где граница «атом».** Неделимая ячейка всегда лист графа, абсолютно [+ просто
   объяснить и реализовать / − некоторые ячейки концептуально составные, но физически
   хранятся как один узел] vs «атом» релятивен глубине запроса — то, что для одного вопроса
   неделимо, для другого распадается на детали [+ честно соответствует «зерно — свойство
   взгляда» из L0 / − сложнее объяснить человеку, где именно остановиться при чтении].

## Пул идей

| Идея | Индекс | Задевает ещё | Метка |
|---|---|---|---|
| Группа = обычная ячейка + payload-как-ссылки (одна реализация на все уровни зума) | P1 · M · высок | — | заложить сейчас (архитектурный инвариант, retrofit дорог) |
| Bitemporal-версионирование вместо миграции граней при смене типа (В2 из L0) | P1 · M · высок | Ц2 тождество, Ц3 доверие | **→ infra** |
| Агент-садовник для явной пометки `stale-facet` при смене типа | P2 · S · сред | Ц4 витальность (фоновый метаболизм) | **→ infra** |
| «Атом» релятивен запросу, а не абсолютная граница листа графа | P3 · M · сред | — | новое (тонкая альтернатива, требует обсуждения с владельцем) |

> Теги: Ц2 (тождество — «та же память» сквозь версии при смене типа), Ц3 (доверие — аудит
> as-of), Ц4 (витальность — кто фоново разбирает stale-facet). Развилка 2 напрямую
> пересекается с решением В2, уже принятым на уровне L0 (bitemporal) — direction здесь не
> изобретает новое решение, а явно наследует его и разворачивает альтернативы, которые были
> отклонены, для полноты веера.
