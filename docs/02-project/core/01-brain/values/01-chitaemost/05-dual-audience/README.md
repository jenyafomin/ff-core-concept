## Суть

Один и тот же паспорт должен быть одновременно машинно-парсируемым (структурные поля) и
человеко-читаемым (естественный язык) — не два разных объекта с риском рассинхрона, а одна
проекция с двумя гранями. Закрывает П7 и напрямую питает Г4: у владельца должен быть
независимый канал проверки, если агент сломан, скомпрометирован или просто недоступен.

## Границы

- **Входит:** dual-format объект (структура + summary синхронно, одна правда); кто
  генерирует human-readable summary и когда (запись vs первое чтение vs шаблон без LLM);
  fallback-режим «агента нет, человек читает сырое и понимает то же самое».
- **НЕ входит:** сама структура полей паспорта, что именно в нём лежит (→ 01 passport —
  здесь только требование, что КАЖДОЕ поле/уровень читается ОБОИМИ адресатами без перевода);
  машинный матчинг вопроса к грани через эмбеддинги (→ 02 polysemy-lens — это про поиск
  нужной грани, не про формат представления уже найденной).
- **Тонкая граница с 01:** 01 определяет ЧТО лежит в паспорте (набор полей); 05 определяет,
  что каждое из этих полей читается человеком напрямую, без агента-переводчика.

## Развилки (веер «как», не режем)

1. **Кто пишет human-readable summary.** LLM генерирует при записи узла (дёшево на
   чтении, риск рассинхрона при последующей правке структурных полей) [+ дешёвое чтение /
   − может соврать о текущем состоянии после правки] vs генерируется на лету при первом
   чтении и кэшируется [+ актуальнее в момент генерации / − первый читатель платит цену
   генерации] vs template-based без LLM, детерминированный рендер прямо из структурных
   полей [+ дёшево и предсказуемо / − менее естественный язык, более «роботизированный»
   тон].
2. **Синхронизация при изменении структурных полей.** Инвалидация и регенерация summary
   при любом изменении структуры [+ всегда согласовано с реальностью / − частые
   регенерации дороги на масштабе] vs summary остаётся неизменным до явного пересоздания
   [+ дёшево, стабильно / − риск лжи о текущем состоянии — прямое нарушение Г7 (живое,
   калиброванное доверие)].
3. **Fallback без агента (Г4).** Человек открывает сырой файл/страницу и видит буквально
   то же самое, что видел бы через агента — полный паритет [+ настоящая независимость от
   агента / − требует держать полноценный UI-слой без агента] vs человеку всё равно нужен
   минимальный нейтральный рендерер (не агент, но и не голый JSON) [+ реалистичнее в
   реализации / − уже не «без посредника» в чистом виде, тонкий компромисс].
4. **Единый объект vs два связанных объекта.** Строго один объект с двумя проекциями
   (структура + NL, одна запись, одна правда) [+ нет риска рассинхрона источников /
   − schema объекта сложнее, оба формата должны эволюционировать вместе] vs два
   параллельных объекта, связанных по `id` (human doc ↔ structured record) [+ проще
   эволюционировать каждый независимо / − риск, что кто-то отредактирует один и забудет
   про парный].
