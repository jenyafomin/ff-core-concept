## Суть

Ось «КОГДА грань доступна» — отдельная от «какая грань доступна» (→ 02) и «сколько стоит
её вскрыть» (→ 01/03). Cold-единица не всплывает сама (не толкается в сводки/push), но
остаётся полностью читаемой по прямому запросу; hot-единица видна по умолчанию. Закрывает
П5 и Г13-режим (live/cold).

## Границы

- **Входит:** поле температуры как явный статус на единице; контракт «кто ЧИТАЕТ
  температуру при сборке сводок и push-уведомлений и обязан её уважать»; фазы видимости
  как плавный переход, а не бинарный флаг (В1 из L0: «грань фокуса» плавает, не щёлкает);
  push vs pull видимость («запах» — единица сама сигналит о резонансе, если не cold).
- **НЕ входит:** сам механизм остывания/разогрева, скорость метаболизма, что запускает
  переход hot→cold и обратно (→ Ц4 Витальность — это её обязанность менять температуру;
  здесь — только контракт «как читать и уважать» текущее значение).
- **Тонкая граница с Ц4 Витальность:** здесь — «читаемость обязана уважать текущую
  температуру при построении сводок/push»; в Ц4 — «что решает, когда и почему температура
  меняется». Явно зафиксированное открытое напряжение (см. `../../V1-chitaemost.md`) —
  риск задублировать логику, если границу не провести жёстко на уровне контракта поля.

## Развилки (веер «как», не режем)

1. **Бинарная vs плавная температура.** hot/cold, 2 состояния [+ просто реализовать и
   объяснить / − резкий порог, а «грань фокуса» по владельцу описана именно как плавная]
   vs непрерывная шкала 0..1 (recency + частота использования, decay-функция) [+ точнее
   отражает реальность / − сложнее показать человеку одним словом или иконкой] vs
   несколько именованных фаз (hot/warm/cool/cold) [+ баланс простоты и нюанса / − нужно
   откалибровать пороги переходов между фазами].
2. **Кто уважает температуру при push («запах»).** Централизованный движок сводок сам
   фильтрует cold-единицы при построении push-очереди [+ единая точка контроля /
   − движок должен знать правило температуры для каждого типа единицы] vs сама единица
   отказывается «пахнуть», если она cold (policy-as-data, суверенно) [+ единообразно,
   правило живёт с данными / − нужно проверять поле у каждой единицы отдельно при сборке
   push, дороже на масштабе].
3. **Прямой запрос к cold-единице.** Полная цена как у любой другой единицы, без
   дисконта [+ честно, не путает читателя ожиданиями / − читатель не знает заранее, что
   «разбудит» потенциально дорогую операцию восстановления] vs cold всегда отдаёт паспорт
   бесплатно (согласуется с 01 passport), дороже — только сам payload [+ дешёвая проверка
   самого факта существования / − отдельное правило только для cold, усложняет общий
   контракт цены].
4. **Температура абсолютна vs относительна роли.** Одна температура на всех читателей
   [+ просто, один флаг / − архивариусу может быть нужен именно cold-архив как основной
   рабочий набор, а не «спрятанное»] vs температура релятивна роли/линзе (для архивариуса
   cold = «мой рабочий набор», для владельца cold = «спрятано и не мешает») [+ точнее
   отражает разных потребителей / − температура превращается в проекцию, а не поле —
   тонкая граница съезжает в сторону 02 polysemy-lens].

## Пул идей

| Идея | Индекс | Задевает ещё | Метка |
|---|---|---|---|
| Температура как явное поле policy-as-data (единица сама решает видимость) | P1 · S · высок | Ц4 витальность | **→ infra** (из `IDEA-temperature-as-visibility-gate`) |
| Плавные фазы видимости вместо бинарного hot/cold-флага | P2 · M · сред | Ц4 витальность | **→ infra** |
| «Запах» как push-сигнал, фильтруемый самой ячейкой (не централизованным движком) | P2 · M · высок | Ц5 суверенность (policy-as-data) | **→ infra** |
| Cold всегда отдаёт паспорт бесплатно, payload — по полной цене | P2 · S · сред | — | новое (согласуется с 01) |
| Температура как проекция линзы, а не абсолютное поле | P3 · M · сред | — | новое (риск съехать в 02, держать как альтернативу) |

> Теги: Ц4 (витальность — владелец механизма изменения температуры), Ц5 (суверенность —
> policy-as-data для «запаха»). Главное открытое напряжение направления: жёсткая граница
> с Ц4 «читает vs меняет» ещё не формализована как контракт (см. NOTES на уровне ценности).
