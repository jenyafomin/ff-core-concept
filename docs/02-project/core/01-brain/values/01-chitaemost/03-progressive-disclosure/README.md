# Направление 03 — Прогрессия раскрытия (лестница цены)

- **Related:** `../README.md` (ценность 01-chitaemost), П3 в
  `../../V1-chitaemost/questions.md`, Г3 (сводка под бюджет) в `../../../L0-memory-unit.md`,
  соседи: `../01-passport/README.md` (нулевая ступень), `../02-polysemy-lens/README.md`
  (прогрессия работает внутри уже выбранной грани)

## Суть

Грани единицы упорядочены по цене: `label → one-liner → summary → payload → трейс`.
Читатель платит РОВНО за глубину, которая ему нужна, а не за всё дерево целиком. Закрывает
П3 (progressive disclosure) и напрямую питает Г3 (сжаться в сводку под бюджет контекста —
сотни единиц в одну сводку без потери контракта доверия, rollup).

## Границы

- **Входит:** число и грануляция ступеней лестницы; иерархии саммари (rollup сотен единиц
  в одну сводку, инкрементальное обновление); переходы между ступенями (кто решает «читать
  дальше»); JSON-LD `@context` как способ самоописать, как углубиться дальше; хранение
  «трейса» (глубочайший уровень, аудит Г9).
- **НЕ входит:** сам паспорт как нулевая ступень (→ 01 passport, это дно лестницы, дешевле
  некуда); КАКУЮ ИМЕННО грань отдавать разным читателям на данной ступени (→ 02
  polysemy-lens — прогрессия ортогональна выбору угла: лестница работает ОДИНАКОВО внутри
  уже выбранной линзой грани).
- **Тонкая граница с 01:** 01 определяет, что лежит НА ДНЕ (паспорт); 03 — вся лестница НАД
  дном и правила подъёма/спуска по ней, включая сколько вообще ступеней существует.

## Развилки (веер «как», не режем)

1. **Число ступеней.** Фиксированные 3 (label/summary/payload) [+ просто, легко
   реализовать / − для сложных типов не хватает промежуточных срезов] vs фиксированные 5
   (label/one-liner/summary/payload/трейс, как в L0) [+ покрывает и аудит (трейс) / − больше
   состояний поддерживать и валидировать] vs произвольное число, тип сам объявляет свою
   лестницу (policy-as-data) [+ гибко под нестандартные типы / − нет единого контракта
   чтения графа, движок не может обобщённо строить сводки].
2. **Rollup сотен единиц в одну сводку (Г3).** Агрегация на лету при запросе (LLM
   суммирует N паспортов прямо сейчас) [+ всегда свежо / − дорого и нестабильно между
   вызовами, разный текст на одинаковый набор] vs предвычисленная иерархия саммари,
   инкрементально обновляемая (summary-tree, снизу вверх) [+ дёшево читать / − нужен
   механизм инвалидации при изменении листьев, риск рассинхрона] vs гибрид: кэш с TTL +
   фоновое обновление по расписанию.
3. **Явность перехода между ступенями.** Читатель явно запрашивает «глубже»
   (`expand()`, pull) [+ прозрачно, читатель сам контролирует бюджет / − лишний
   раунд-трип на каждый шаг] vs движок сам решает, сколько отдать сразу, по эвристике
   ставок (Г5, цена ошибки) [+ меньше трения, меньше запросов / − читатель не понимает,
   почему получил именно такой объём, менее предсказуемо].
4. **JSON-LD `@context` как самоописание глубины.** Каждый уровень несёт свой `@context`
   для машинного парсинга и связывания смысла [+ стандарт, бесплатная интероперабельность с
   внешними системами (Г19 портируемость) / − оверхед для простых внутренних типов, которым
   вовне выходить не нужно] vs простой internal-only шейп без веб-стандартов [+ легче
   реализовать и читать / − теряется бесплатная переносимость при смене хоста].
5. **Хранение «трейса» (аудит Г9).** Всегда доступен по прямому запросу для любой единицы
   [+ аудит гарантирован всегда / − хранить полный трейс для всего дорого на масштабе] vs
   трейс хранится только для единиц с высокими ставками/волатильностью (Г5-обусловленно)
   [+ дешевле / − риск, что именно нужный трейс не был сохранён задним числом].

## Пул идей

| Идея | Индекс | Задевает ещё | Метка |
|---|---|---|---|
| Фиксированная 5-ступенчатая лестница (label→one-liner→summary→payload→трейс) | P1 · S · высок | — | заложить сейчас (контракт чтения, retrofit дорог) |
| Иерархии саммари / summary-tree с инкрементальным обновлением снизу вверх | P1 · M · высок | Ц4 витальность (обновление сводки = часть метаболизма) | **→ infra** |
| JSON-LD `@context` на каждой ступени раскрытия | P3 · M · сред | Ц5 суверенность (Г19 портируемость между хостами) | **→ infra** |
| Гибрид: default auto-раскрытие по ставкам + возможность force-`expand()` | P2 · S · сред | — | новое |
| Трейс только для единиц с высокой волатильностью/ставками (не для всех) | P2 · M · сред | Ц3 доверие (аудит Г9 избирательно) | **→ infra** |

> Теги: Ц3 (доверие — избирательный аудит), Ц4 (витальность — обновление summary-tree),
> Ц5 (суверенность — портируемость через `@context`).
