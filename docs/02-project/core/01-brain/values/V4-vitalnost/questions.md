# Открытые вопросы · Ц4 Витальность

- **VQ1 — Эмердженс vs автоиндекс (тема B):** это один механизм с двумя выходами (инсайт-ребро /
  домен-узел), или два разных процесса, которые случайно похожи? Если один — общий движок-примитив
  «садовник сгущает похожее» проектируем сразу под оба use-case.
- **VQ2 — Бюджет внимания: кто именно решает срез?** Грань 7 говорит «бюджет принадлежит базе», но
  не решает МЕХАНИЗМ: жёсткий лимит (top-N живых единиц) vs мягкий (штраф за превышение, но без
  насильного забывания)? Разные ответы по-разному ломаются под нагрузкой (тема C).
- **VQ3 — Pending и Согласие референта.** Открытая петля про третье лицо — эскалировать её вообще
  нельзя без риска утечки внимания к чужой приватной теме, или достаточно, чтобы эскалация была
  видна только владельцу и никогда не всплывала в шеринге/маркетплейсе?
- **VQ4 — Confidence выведенного знания (эмердженс) vs первичной записи.** Нужна ли отдельная шкала
  доверия для «рождённых» единиц, или существующая ось Доверия (Ц-3) уже достаточно широка, если
  просто пометить `derived: true`?
- **VQ5 — Заморозка вручную.** Человек может «заморозить» единицу (запретить забывание) — это
  переопределение политики ячейки владельцем. Не конфликтует ли это с policy-as-data (ячейка сама
  решает свой рецепт)? Где граница: чей голос выше — рецепт ячейки или явная воля владельца?
- **FQ5 (унаследован из ревизии Fable):** эмердженс — полноценная фаза наравне с забыванием, или
  всё ещё частный случай консолидации? Владелец пока не подтвердил.
- **FQ6 (унаследован из ревизии Fable):** `pending`/открытые петли — отдельная ось метаданных, или
  можно выразить через существующий salience + внешний слой задач? Владелец пока не подтвердил.
