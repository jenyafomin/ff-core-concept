# Направление 02 — Живая калибровка (confidence как процесс, не поле)

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md`, `../../V3-doverie/README.md` (Д2, Д3 прошлого цикла),
  `../../V3-doverie/ideas/IDEA-confidence-as-engine-primitive/README.md` (перенесённая идея),
  `../01-provenance/README.md` (откуда пришло стартовое значение), `../../V4-vitalnost.md` (тонкая
  граница «жива ли ячейка» vs «можно ли ей верить»)

## Суть

Confidence — не число, зафиксированное один раз при записи, а живая величина: растёт с подтверждением,
падает со старением и опровержением. Отдельно — запись знает свою временную ГОДНОСТЬ ВПЕРЁД
(волатильность): курс валюты протухает за час, дата рождения — никогда. Объект защиты — **процесс
пересчёта истинности**, отличный от процесса «жива ли карточка вообще» (Ц-4 Витальность).

## Границы

- **Входит:** байесовское обновление confidence по акту использования; confidence как синхронный примитив
  движка vs фоновая задача; явное поле волатильности (Г8, «как быстро протухает») на паспорте или
  выводимое из типа данных.
- **НЕ входит:** кто автор события использования и вправе ли он вообще менять confidence (→
  03 poisoning-defense); что делает запись, когда confidence падает настолько, что она формально
  опровергнута (`contradicted-by`, → 04 supersession-audit); откуда пришло стартовое значение при
  создании (→ 01 provenance).
- **Тонкая граница с Ц-4 Витальность:** там — «видна ли ещё карточка агенту/человеку» (доступность),
  здесь — «можно ли ей верить именно сейчас» (истинность). Запись может быть СВЕЖЕЙ, но НЕПРАВДИВОЙ
  (только что кто-то соврал), или СТАРОЙ, но всё ещё верной (дата рождения). Путать оси — терять
  именно это различие.

## Развилки

1. **Место пересчёта — движок vs садовник.** *(сквозной спин, см. `../README.md`)* Синхронно при каждом
   чтении, формула живёт в паспорте, пересчёт — дешёвая операция движка [+ всегда актуально при чтении
   / − риск конфликта с дешевизной чтения, целью Ц-1 Читаемость] vs асинхронно, фоновый «садовник»
   пересчитывает периодически [+ не тормозит чтение / − окно устаревания между пересчётами, агент может
   действовать на ещё-не-пересчитанном значении].
2. **Формула обновления.** Байесовское обновление (prior × likelihood сигнала использования)
   [+ математически обосновано, соответствует Г7 / − нужно явно определить, откуда брать likelihood для
   разных типов сигналов] vs эвристический decay (экспонента по времени + буст на подтверждение)
   [+ просто внедрить и объяснить / − менее строго обосновано, произвольные константы].
3. **Волатильность — явное поле vs выведенное свойство.** Явное поле «как быстро протухает» на паспорте
   каждой записи (Г8 из L0-канона: «Время-истинности + Волатильность» — уже решённая ось канона)
   [+ запись сама сигналит срок годности, ничего не нужно угадывать / − ещё одно обязательное поле
   на каждый паспорт] vs выводится из класса/типа данных через справочник (курс валюты — часы, дата
   рождения — никогда) [+ не раздувает паспорт отдельной записи / − неявно, требует поддерживаемой
   таблицы типов, которая сама может устареть].
4. **Единица измерения confidence — число vs категория.** Непрерывное число 0-1 (годится для Байеса,
   точное сравнение) [+ математически строго / − требует объяснения человеку, «0.73» не читается
   мгновенно] vs категория (низкое/среднее/высокое, 3-5 уровней) [+ читается человеком с одного взгляда,
   смыкается с Ц-1 Читаемость / − грубее для машинной калибровки, теряется точность на границах].
