# Направление 01 — Происхождение (кто создал и кто до сих пор ручается)

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md` (ценность 03-доверие), `../../V3-doverie/README.md` (Д1, Д5 прошлого цикла),
  `../../V3-doverie/ideas/IDEA-source-origin-effective/README.md` (перенесённая идея),
  `../02-calibration/README.md` (что происходит с confidence ПОСЛЕ создания)

## Суть

Запись несёт явный, читаемый след: кто/что её создало и НА КАКОМ ОСНОВАНИИ (наблюдение / вывод /
чужие слова / агент-генерация без верификации). Без этого confidence — декларация, а не факт. Объект
защиты — **момент рождения доверия**: что записано ПРИ СОЗДАНИИ и кто изначально за это отвечает,
в отличие от того, как это доверие живёт и меняется дальше.

## Границы

- **Входит:** пара origin (кто изначально внёс факт) / effective (кто сейчас подтверждает его
  актуальность); provenance как явное ребро `wasDerivedFrom` (W3C PROV) vs текстовое поле; стартовое
  confidence агент-сгенерированных записей без верификации человеком (потолок или явная метка).
- **НЕ входит:** сама формула калибровки confidence после создания (→ 02 calibration); кто ВПРАВЕ
  менять confidence чужой записи (→ 03 poisoning-defense); что делает запись, когда её провенанс
  расходится с текущим подтверждением настолько, что она опровергнута (→ 04 supersession-audit).
- **Тонкая граница с 02:** здесь фиксируется, ОТКУДА пришло значение в момент создания; там — как оно
  живёт и дрейфует дальше. Провенанс не пересчитывается при каждом чтении, confidence — да.

## Развилки

1. **Провенанс как поле vs как ребро.** Текстовое поле `source` [+просто, ничего нового в модели данных
   / − граф нельзя пройти «откуда взялась эта уверенность»] vs явное ребро `wasDerivedFrom` (W3C PROV)
   [+ граф проходим, провенанс — гражданин графа, не строка / − третья сущность (ребро с паспортом) на
   каждую запись, эхо решения В4 (ребро-утверждение) из L0].
2. **origin vs effective — одно поле или два.** Одно поле «кто сказал» [+ просто / − теряет «кто ДО СИХ
   ПОР ручается», если первый автор давно неактивен, но никто не опроверг] vs пара origin+effective
   [+ честно отражает дрейф ручательства во времени / − двойное поле, двойная запись при каждом акте
   подтверждения].
3. **Стартовый потолок для агент-сгенерированных записей (TQ2).** Жёсткий потолок confidence (например
   ≤0.7 без подтверждения человеком) [+ защищает от слепого доверия автомату / − мешает автономии
   агентов, может быть избыточной жёсткостью] vs без потолка, но обязательная явная метка
   `provenance=agent-generated` [+ не тормозит работу агента / − человек должен САМ заметить метку,
   иначе тот же риск слепого доверия].
4. **Кто фиксирует provenance.** Сам движок при записи, автоматически из контекста вызова (кто
   аутентифицирован, какой инструмент) [+ не забудут, дёшево / − не всегда знает «на каком ОСНОВАНИИ»
   — наблюдение это или вывод] vs явное поле, которое обязан заполнить автор записи [+ точнее, несёт
   эпистемический статус / − можно забыть или указать неверно].
