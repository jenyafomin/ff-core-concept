# IDEA · Масштаб/скорость как изюминка продукта (не НФТ)

> Статус: draft · Дата: 2026-07-08 · Родитель: [../../README.md](../../README.md)

## Суть

Владелец назвал big-data/скорость/масштаб не "просьбой не тормозить", а изюминкой продукта:
если хоть одна грань (объём узлов, латентность запроса, конкурентный доступ агентов к графу)
слабая — продукт НЕДЕЕСПОСОБЕН целиком, а не "медленнее среднего". Это меняет статус
масштаба с обычного нефункционального требования (можно улучшить потом) на **условие
существования продукта** (нельзя ретрофитить дёшево, как и другие вещи в разделе "заложить
сейчас").

Практическое следствие: масштаб нельзя оставить "на потом, когда данных станет много" —
решения о форме единицы памяти (конструктор-ячейка, авто-индекс-волна) должны СРАЗУ
проверяться на вопрос "переживёт ли это 10⁶–10⁹ узлов и параллельный доступ множества
агентов-читателей/писателей". Это не 8-я ценность узла (см. К-2 в основном README), а
**инвариант движка уровня КОНСТИТУЦИИ**: движок обязан сохранять все 7 ценностей под
нагрузкой, деградация — дефект, не приемлемый компромисс.

## Какие ценности задевает

- **Все 7 — как constraint, не как содержание.** Масштаб не добавляет смысла узлу, но ставит
  жёсткое условие: любая реализация Ц1-Ц7 обязана оставаться корректной при росте объёма.
  Конкретно уязвимые точки:
  - Ц1 Читаемость — под нагрузкой первой жертвой падает читаемость (денормализация,
    сокращённые представления ради скорости).
  - Ц2 Тождество — дедуп/конфликты (integrity-as-engine-duty) на большом графе — это NP-трудная
    в общем случае задача, требует явной стратегии (не "решим по ходу").
  - Ц6 Реляционность + IDEA-auto-index-wave — волна по рёбрам на большом графе — самая
    рискованная операция с точки зрения производительности во всём каноне.
  - Ц5 Суверенность — портируемая ячейка "живёт в любом движке"; не все движки одинаково
    масштабируются — конфликт между портируемостью и масштабом нужно решить явно.

## Открытые вопросы

- Какой порядок объёма закладывать как целевой (10³? 10⁶? 10⁹ узлов)? Без числа "изюминка"
  остаётся лозунгом, не инженерным требованием.
- Где граница движка (integrity-as-engine-duty) и ответственности ячейки (policy-as-data) в
  вопросах масштаба — может ли ячейка сама заявлять "я тяжёлая, требую отдельного индекса"?
- Нужен ли отдельный документ уровня ADR "Инварианты движка" рядом с КОНСТИТУЦИЕЙ, куда
  выносится этот пункт вместе с уже названными (referent+hard-erase, единый порог доступа)?
