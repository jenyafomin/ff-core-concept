## Суть

Объект здесь — **ПРЕДЕЛ**: где суверенность ячейки/владельца ОСТАНАВЛИВАЕТСЯ. Над `policy`-блоком (02)
стоит **конституционный слой инвариантов**, который ячейка не может переопределить собой:
**согласие референта (Ц-7) — референт над владельцем**; **единый порог доступа** для всех каналов
извлечения (против «зомби-памяти» — обхода сбоку); **право на забвение референта** (hard-erase).
Без этого потолка policy-as-data превращается в лазейку. Суверенность = «свобода внутри конституции».

## Границы

- **Входит:** конституционный потолок над политикой; **референт > владелец** (Г20 — данные о людях, не
  давших согласия быть узлом); единый порог доступа / анти-обход через боковой канал (линза, авто-индекс,
  волна не обходят политику); анти-ложь ячейки о себе (нельзя объявить «я вечная/публичная», чтобы
  уклониться от забывания/скрытия) → внешний арбитр, не только декларация; opt-out от чужой волны/
  авто-индекса (тема B); где технически арбитраж (Q-S3); как показать конфликт владельцу (Q-S6).
- **НЕ входит:** сами правила ячейки → `02`; чей ключ/воля → `05`; полная модель Согласия (референт,
  hard-erase) — живёт в `../../07-soglasie/`, здесь только **арбитраж напряжения Ц-5↔Ц-7**.
- **Тонкая граница с 02 и с Ц-7:** 02 = «ячейка задаёт правила»; 06 = «каких правил НЕЛЬЗЯ»; полная
  ветка согласия — в Ц-7. 06 — это шов, где суверенность встречает согласие, не дубль обеих.

## Развилки (веер «как», не режем)

1. **Где живёт арбитраж (Q-S3).** Отдельный сервис-валидатор политик [+ единая точка, гарантия / −
   компонент, единая точка отказа] vs встроенная проверка в КАЖДОМ движке (обязанность движка —
   integrity-as-engine-duty) [+ нет обхода при переносе / − каждый движок реализует честно] vs конвенция
   без техгарантии [− рискует остаться декларацией] — **на этой развилке висит, лазейка policy или нет**.
2. **Единый порог доступа (анти-зомби).** Один PEP для ВСЕХ каналов (pull/push/линза/волна/авто-индекс)
   [+ нет бокового обхода / − всё через одну точку] vs проверка на каждом канале отдельно [− риск, что
   новый канал забудут] — линза-исполнитель из 02 = реализация этого.
3. **Анти-ложь ячейки.** Внешний арбитр валидирует самодекларации статуса («вечная/публичная») [+ нет
   самозванства / − кто арбитр] vs декларация + провенанс, доверие по источнику [+ дёшево / − обходимо]
   vs критичные статусы (публичность, вечность) вообще не самоназначаемы ячейкой.
4. **Референт > владелец на практике (Q-S6).** Владелец видит запрет (удалить/показать) с объяснением
   «референт не согласен» [+ честно / − выглядит как баг, трение] vs данные о третьем лице вообще не
   попадают как полноценный узел без согласия [+ чисто / − теряем контекст] vs теневой режим (владелец
   видит факт существования, но не содержимое) [+ баланс / − сложно].
5. **Opt-out от волны (тема B).** Ячейка может пометиться «не участвую в чужом авто-индексе» [+ приватность
   не обходится сбоку / − фрагментирует агрегацию] vs авто-индекс по умолчанию уважает `policy`-блок
   каждой частицы (нет отдельного opt-out — политика и так барьер) [+ единообразно / − нужен PEP везде].
6. **Жёсткость потолка.** Hard-invariant (нельзя переопределить ничем, кроме совместного акта — согласие
   референта + hard-erase) [+ надёжно / − негибко] vs settable-с-аудитом (можно, но всё логируется)
   [+ гибко / − потолок дырявый] — для референт-данных склоняемся к hard.
