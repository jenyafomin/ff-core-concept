# IDEA — Confidence как примитив движка (не садовник)

**Суть:** Байесовское обновление confidence по акту использования — не фоновая асинхронная задача агента-садовника, а один из четырёх минимальных синхронных примитивов "тонкого движка" (в духе Fable §2: хранить / считать salience / применять линзу / разрешать id). Формула калибровки живёт в ячейке (policy-as-data), но САМ пересчёт при каждом чтении/использовании — синхронная, дешёвая операция движка. Иначе Доверие не тянет масштаб (тема C).

**К какой под-грани относится:** Д2 (Калибровка использованием) × тема C (масштаб/скорость).

**Открытые вопросы:** Не конфликтует ли синхронный пересчёт при каждом чтении с требованием дешевизны чтения (Читаемость, Ц1)? Нужен ли батчинг/лениво-отложенный пересчёт?
