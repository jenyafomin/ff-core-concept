# IDEA — Trust-write authorization (кто вправе менять confidence)

**Суть:** Ввести отдельную, явную роль "верификатор" — не равную автору/владельцу/референту (Fable §4) — которая одна имеет право поднимать/опускать confidence записи. Обычное чтение/использование НЕ меняет confidence напрямую, а лишь генерирует "сигнал" (акт-со-следом), который агрегируется по формуле в отдельном, авторизуемом шаге. Защищает от тривиального отравления через массовое "фейковое использование".

**К какой под-грани относится:** Д5 (Авторизация записи), пересекается с Д4 (Защита от отравления).

**Открытые вопросы:** Не превращает ли отдельная роль верификатора Доверие в бюрократию, замедляющую живую калибровку? Совместимо ли с масштабом (тема C)?
