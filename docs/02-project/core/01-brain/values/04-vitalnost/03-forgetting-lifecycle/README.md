## Суть

Единица теряет **доступность**, не содержимое: уходит из поля зрения явными наблюдаемыми стадиями,
а не бинарным щелчком видно/не видно. Объект защиты — **честность перехода** (причина видна, откат
возможен) и риск **«тихой эрозии»** — потери важного без единого сигнала о том, что это произошло.

## Границы

- **Входит:** конечный автомат стадий видимости, причина перехода как наблюдаемое событие
  (аудит), обратимость soft-забывания (Г12), «память об отсутствии» — как система вообще замечает и
  признаёт, что что-то тихо выпало из фокуса.
- **НЕ входит:** сама формула веса, что количественно двигает переходы (→ 01 salience-weight);
  read-cost холодной записи и кто видит cold по умолчанию (→ ценность 01-chitaemost — здесь только
  МЕХАНИЗМ перехода, следствие живёт там); полное необратимое удаление как контракт версий
  (пересекается с 02-tozhdestvo bitemporal, здесь — только момент, когда единица В ПРИНЦИПЕ входит в
  эту зону).
- **Тонкая граница с 01:** здесь — стадии как события и их видимость; в 01 — число (вес), которое эти
  события вызывает.

## Развилки

1. **Число стадий.** Минимум 2 (live/cold, бинарно) [+просто, уже есть как temperature в паспорте /
   −не даёт плавной эрозии, которую хотел владелец («фазы, не бинарно»)] vs 3-4 явные
   (nascent→active→cooling→cold) [+видна траектория, соответствует прямому запросу владельца / −больше
   состояний для объяснения и UI] vs континуум (просто число веса, стадия — лейбл поверх диапазона)
   [+одна переменная / −лейбл может «прыгать» туда-сюда, менее стабилен для аудита].
2. **Обратимость перехода в cold/dormant.** Всегда обратима по явному запросу (Г12, доступность
   восстанавливается без изменения содержимого) [+безопасно / −база физически никогда не «худеет»] vs
   после `erased` — необратимо, но с гарантией невлияния через эмбеддинги/копии (по L0 В4) [+честный
   конец / −нужен отдельный контракт отката, отличный от Rework].
3. **Как замечать «тихую эрозию» (память об отсутствии, Opus #7).** Явный лог перехода виден по
   запросу [+прозрачно, недорого / −никто не смотрит лог, пока не спросит] vs периодическая сводка
   садовника «что незаметно остыло за неделю» — push, а не pull [+ловит именно тихость / −ещё один
   канал уведомлений, шум] vs ничего специального — если важно, Подтвердить не даст остыть [+
   минимализм / −прямо противоречит запросу владельца «заметить отсутствие»].
4. **Кто ведёт стадии.** Синхронно движком при каждом чтении [+нет отдельного прохода / −нет единого
   садовника, труднее ввести сложные правила заодно с консолидацией] vs асинхронный садовник батчем
   [+можно совместить с направлением 02 в одном проходе / −задержка между «заслужил cold» и переходом].
