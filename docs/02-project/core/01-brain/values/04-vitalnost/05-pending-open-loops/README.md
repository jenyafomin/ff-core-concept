## Суть

Единица может быть одновременно низкой по весу (давно не использовалась) и высокой по
незакрытости — важный вопрос, обещание, ожидание. Объект защиты — **своя, отдельная от веса,
динамика**: открытая петля не должна тихо утонуть вместе с общим затуханием, пока не получит явного
разрешения (ответ / отмена / эскалация по таймауту).

## Границы

- **Входит:** поле/сущность «pending» и его причина, правило «не участвует в decay», механизм
  разрешения, согласие референта при эскалации о третьем лице.
- **НЕ входит:** сама механика затухания веса (→ 01 salience-weight); является ли pending поводом для
  эмердженса — нет, pending именно НЕ обрабатывается автоматом (→ 02 consolidation-emergence, граница
  явно проведена); отдельный модуль task-tracker за пределами базы, если такой уже существует — здесь
  только интерфейс единицы памяти к нему.
- **Тонкая граница с 06:** будильник/эскалация по таймауту использует ДРУГОЙ бюджет — внимания
  владельца, а не salience-бюджет базы (Г15). Не путать два разных «бюджета» с одним словом.

## Развилки

1. **Тип поля.** Булево `pending:true/false` + причина строкой [+просто / −нет градации срочности] vs
   enum срочности (`low/med/high/overdue`) [+richer сигнал для эскалации / −больше состояний, кто их
   присваивает?] vs pending как ОТДЕЛЬНАЯ единица-ребро «открытый-вопрос-к» (не поле, а связь к
   породившей единице) [+соответствует принципу «ребро — полноценная память» из L0 / −тяжелее для
   простого случая «напомни мне позвонить»].
2. **Эскалация по таймауту.** Жёсткий дедлайн → авто-напоминание владельцу [+ничего не теряется /
   −шум, если таймаутов много одновременно] vs мягкий «второй план» — pending просто не даёт единице
   остыть, но не толкает уведомление [+не навязчиво / −реально забывается, если владелец сам не
   заглянет] vs владелец сам настраивает срочность per-класс единицы (задача vs идея vs вопрос)
   [+гибко / −конфигурация растёт].
3. **Pending о третьем лице (VQ3, цикл 0).** Эскалация видна ТОЛЬКО владельцу, никогда не всплывает в
   шеринге/маркетплейсе [+защищает референта по умолчанию / −владелец сам должен решить, поднимать ли
   тему с человеком, без помощи системы] vs эскалируется как обычно, ограничение только на
   экспорт/шеринг наружу [+проще, одна ось приватности вместо двух / −сама внутренняя эскалация уже
   давление думать о чужой теме без согласия референта].
