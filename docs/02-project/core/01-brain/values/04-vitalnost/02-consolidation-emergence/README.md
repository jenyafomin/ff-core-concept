## Суть

Периодически несколько связанных единиц либо **сжимаются** в одну сводку без потери прослеживаемости
к исходным (консолидация), либо из них **рождается** новая единица-инсайт, которой не было ни в
одном источнике по отдельности (эмердженс). Это две разные операции — сжатие теряет объём, эмердженс
добавляет смысл, — и их легко перепутать.

## Границы

- **Входит:** триггер запуска консолидации, `derived_from`-ссылки на источники, природа эмердженса
  (узел или ребро), confidence выведенного знания, гипотеза «эмердженс = механизм автоиндекса» (тема
  B цикла 0).
- **НЕ входит:** как считается вес узла после консолидации (→ 01 salience-weight); как долго живёт
  «поглощённая» единица, прежде чем стать cold (→ 03 forgetting-lifecycle); переосмысление ОДНОЙ
  единицы без участия других источников (→ 04 reinterpretation — другой глагол, не путать).
- **Тонкая граница с 04:** здесь — новая единица рождается ИЗ НЕСКОЛЬКИХ источников (эмердженс) или
  заменяет несколько одной (консолидация); в 04 — ОДНА и та же единица меняет свой смысл во времени,
  без нового «сырья» извне.

## Развилки

1. **Триггер консолидации.** По расписанию (крон, «ночной сон») [+предсказуемо, ресурс контролируем
   / −задержка до суток] vs по порогу сгущения (N похожих активных единиц обнаружены) [+реактивно /
   −нужен детектор similarity, дороже] vs по явному запросу владельца/агента [+контролируемо /
   −не автоматизировано, требует инициативы].
2. **Природа эмердженса.** Ребро-инсайт (A→B), расширяя уже принятое в L0 «ребро-утверждение» [+
   переиспользует В4, не плодит сущности / −эмердженс не всегда бинарная связь двух узлов] vs
   узел-инсайт (полноценный узел с паспортом) [+единообразно с остальной памятью / −плодит узлы] vs
   гибрид: узел только при ≥3 источниках, иначе ребро.
3. **Эмердженс = автоиндекс? (VQ1, цикл 0).** Один механизм с двумя выходами — садовник сгущает
   похожее и рождает либо инсайт, либо домен-узел [+один движок, дешевле / −разные потребители, риск
   смешать назначения] vs два разных процесса — эмердженс это про смысл (content), автоиндекс это
   про навигацию (volume) [+чистое разделение ответственности / −дублирование механики «искать
   сгущение» в двух местах].
4. **Confidence выведенного знания (VQ4, цикл 0).** Отдельная более низкая шкала для derived,
   требующая явного human-confirm для повышения [+честно отражает «это вывод, не факт» / −усложняет
   паспорт, новое поле] vs та же шкала confidence + флаг `derived: true` [+не расширяет паспорт (курс
   L0 — 0 новых обязательных полей) / −теряется нюанс «как далеко от источника» это знание].

## Пул идей

| Идея | Индекс | Задевает ещё | Метка |
|---|---|---|---|
| Эмердженс = узел/ребро-инсайт с явным `derived_from`, источники не переписываются | P1 · M · высок | 02-tozhdestvo (прослеживаемость), 06-relyacionnost (ребро-инсайт), 03-doverie (доверие выведенного) | перенесено из цикла 0, **→ infra** (общий модуль «производные узлы/рёбра») |
| Автоиндекс как частный случай эмердженса (садовник сгущает похожее → домен-узел) | P2 · M · высок | 01-chitaemost (читаемость по зуму) | требует сначала решения VQ1 |
| Derived-confidence = флаг `derived:true` поверх существующей шкалы, без новой шкалы | P1 · S · сред | 03-doverie | экономит паспорт, конкурирует со следующей идеей |
| Отдельная (более узкая) шкала доверия для выведенного знания | P2 · M · сред | 03-doverie | альтернатива предыдущей, точнее, но дороже |

> Теги: 04 (сам процесс), 02 (тождество/derived_from), 06 (ребро-гражданин), 03 (доверие выведенного).
