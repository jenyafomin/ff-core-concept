# Карточки 7 ценностей ячейки — поэтапное понимание (2026-07-08)

Объективные компактные карточки по каждой из 7 ценностей единицы памяти. Источник —
`_SYNTHESIS-2026-07-08.md` и папки `V1..V7`. Где решение не принято — помечено «развилка Рn».
Где канон молчит — помечено «канон молчит».

**Тонкий обязательный паспорт (пол для ВСЕХ ячеек, развилка Р3-а, рекомендация):**
`id · type · label · salience · temperature · author · referent`. Ниже в «минимумах» эти поля
привязаны к своей ценности; value-специфичные поля добавлены сверх пола.

**Три независимые роли на каждой ячейке (раздел A свода, КК-1):**
`author` (кто создал) · `owner` (кому принадлежит) · `referent` (о ком). Заложить СЕЙЧАС — ретрофит невозможен.

---

## Связующий паттерн

Общий каркас повторяется у всех 7 ценностей. Каждая ценность = один и тот же скелет:

**[поле-состояние на ячейке] + [обязанность движка над этим полем] + [scale-вариант (КК-3)] + опц.[gate перед необратимым/авто-действием] + [провенанс / derived_from, где значение выведено (КК-5)].**

Каркас подтверждён по фактическим карточкам. Что оказалось СКВОЗНЫМ (сошлись на КК-1..КК-6):

| Элемент каркаса | Кто это несёт | Сквозной механизм |
|---|---|---|
| Поле-состояние | все 7 | у каждой ценности есть своё поле/поля на ячейке |
| Обязанность движка | все 7 | движок что-то делает с полем (пересчёт, каскад, gate) |
| Scale-вариант | все 7 | **КК-3** — «дожить до масштаба» есть у каждой → аргумент за конституционный инвариант масштаба (Р2) |
| author/owner/referent | все 7 | **КК-1** — одно лёгкое поле-роль, не 6 механизмов |
| gate перед авто-агрегацией | Ц3+Ц7 | **КК-4** — contagion-threshold (доверие) и consent-taint (согласие) сводятся к одному «gate на авто-индекс» (Р5) |
| derived_from / провенанс | Ц2,Ц3,Ц4,Ц6,Ц7 | **КК-5** — маркировка «выведено, не наблюдено» на emergent-узлах/рёбрах |
| canonical_id переживает всё | Ц2,Ц5,Ц7 | **КК-6** — единый жизненный цикл id (смена типа, перенос движка, tombstone после erase) |
| линза / авто-волна | Ц1,Ц2,Ц3,Ц5,Ц6,Ц7 | **КК-2** — один механизм, обязан уважать consent+policy+trust ПЕРЕД материализацией |

**Где элемент каркаса честно ОТСУТСТВУЕТ (не приукрашиваю):**
- **Ц4 Витальность** — своего «gate перед необратимым» у неё нет: забывание намеренно мягкое
  (`cold`, не `delete`). Необратимое удаление делегировано Ц7 (hard-erase). Это осознанная асимметрия, не пробел.
- **Ц1 Читаемость** — провенанс не «родной»: derived_from приходит к ней только через линзу (КК-2),
  сама грань его не хранит. Канон молчит, хранить ли price/lens-провенанс на паспорте (развилка вокруг Р4).
- **gate у Ц6 Реляционность** — не «согласие», а ссылочная целостность при разрыве стороны (сироты-рёбра);
  это gate иного рода. Отмечаю, чтобы не выдавать за один механизм с Ц3/Ц7.

Вывод: каркас реален и держит все 7. Сквозные примитивы (роли, scale, gate-на-авто-индекс, derived_from, canonical_id)
нельзя проектировать внутри одной ценности — они общие. Это и есть «связующий паттерн».

## ЦN-карточки

### Ц1 · Читаемость (Legibility)
**Ценность чего.** Гарантирует, что ячейка отдаёт нужную грань нужному читателю по нужной цене, не вскрываясь целиком.
**Зачем / что ломается без неё.** Без неё каждое чтение = загрузка всего тела; агент не может дёшево решить «брать/не брать» и захлёбывается.
**Примеры (2).**
1. Агенту нужно оценить узел, не читая payload — по одной строке `label` понимает «не моё», проходит мимо (Г1).
2. Ячейка `cold`: не всплывает в обычной выдаче, читается только по явному запросу — иначе шумит (Г13-режим).
**Поля в ячейке:**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `label` | string | дешёвая грань для оценки без вскрытия |
  | `type` | enum/str | задаёт форму чтения (как читать этот узел) |
  | `temperature` | cold/hot | всплывает vs читается по запросу (одна цифра; механизм перехода — в Ц4, Р13) |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `summary` | text | средний уровень прогрессивного раскрытия (label→summary→payload→trace) |
  | `facets` | list | полисемия: много граней одной памяти |
  | `price_hint` | map(level→cost) | self-pricing: ценник на каждом уровне (развилка — идея, не решено) |
  | `payload` / `trace` | any / ref | полное тело и самый глубокий уровень |
**Обязанность движка.** Отдавать запрошенный уровень по его цене; коллапсировать грань линзой (КК-2); уважать `temperature` как гейт видимости.
**Scale-вариант (КК-3).** Стресс-тест читаемости: дешёвый паспорт/линза должны держать цену чтения при росте объёма.

### Ц2 · Тождество (Identity)
**Ценность чего.** Гарантирует, что ячейка знает, где кончается «та же самая» и начинается «другая» — до всякого метаболизма и слияния.
**Зачем / что ломается без неё.** Без неё нельзя «менять не теряя себя» и нельзя слить конфликт: не определено «себя» → дубли и потеря истории.
**Примеры (2).**
1. Три свидетеля описывают одно событие: это ко-референция события (`event_anchor`), а НЕ «та же запись» — три ячейки, один якорь события (Opus-1).
2. Композит распадается на части: у композита свой `id` или производный от частей? (Sonnet-1, развилка).
**Поля в ячейке:**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `id` / `canonical_id` | immutable | неизменяемый якорь; переживает смену типа, перенос движка, tombstone после erase (КК-6) |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `valid_time` / `tx_time` | bitemporal | вариант ≠ эволюция; аудит «что знали тогда» |
  | `variant_of` | ref/edge | три отношения: версия / вариант / новая единица |
  | `merged_from` / `split_from` | provenance | композиция/распад с историей (КК-5) |
  | `event_anchor` | ref | ко-референция события, отдельно от тождества записи |
**Обязанность движка.** Разрешать «та же / другая»; при слиянии — union-find + конфликт-протокол; держать индекс кандидатов на слияние.
**Scale-вариант (КК-3).** Индекс кандидатов слияния + дедуп ДО импорта (не после), чтобы тождество не деградировало на объёме.
**Развилки.** Р10 (hard-erase → оставить `canonical_id`-tombstone). Р11 (слияние автономно агентом, КРОМЕ referent≠owner / низкий confidence / неразрешённый конфликт → человек).

### Ц3 · Доверие (Living Trust)
**Ценность чего.** Гарантирует, насколько запись — правда: калибруется использованием, несёт провенанс, защищена от отравления.
**Зачем / что ломается без неё.** Без неё агент действует на устаревшей/ложной ячейке → каскадная катастрофа; базу можно «отравить» вбросом.
**Примеры (2).**
1. Агент берёт устаревшую ячейку как истину и совершает необратимое действие — нужен `confidence` + годность вперёд (Opus #6).
2. «Тихая ложь»: единицы/валюта/локаль записаны неявно и подставляют движок — провенанс должен это ловить (DATA-side).
**Поля в ячейке:**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `source` | origin+effective | откуда пришло и что реально применялось |
  | `author` | роль | потолок доверия к агент-записи vs человеку (КК-1) |
  | `confidence` | number | калибруется использованием (байес-обновление) |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `effective_time` / validity | temporal | годность вперёд (до каких пор верить) |
  | `superseded_by` / `contradicted_by` | ref | supersession-duty: самоаннулирование при чтении (Opus #6) |
  | `verifier` / trust-write cap | capability | кто вправе писать confidence |
  | `contagion_threshold` | number | порог заражения при авто-агрегации (КК-4) |
**Обязанность движка.** Пересчёт `confidence` при чтении (дешёвое — синхронный примитив, Р6-а); применять supersession; проверять порог заражения ДО материализации (gate, КК-4).
**Scale-вариант (КК-3).** `confidence` как синхронный примитив движка, чтобы калибровка не отставала при потоке записей.
**Развилка.** Р6 (гибрид: confidence синхронно, консолидация/stale — асинхронный садовник).

### Ц4 · Витальность (Metabolism)
**Ценность чего.** Гарантирует, что ячейка меняется во времени — затухает, консолидируется, забывает, рождает новый смысл — не теряя Тождества и не раздувая базу.
**Зачем / что ломается без неё.** Без неё память = свалка: всё вечно и равнозначно, бюджет внимания исчерпан, нового смысла не рождается.
**Примеры (2).**
1. Старая обида переосмыслена как благодарность — прошлое реинтерпретировано, не удалено (Opus #3, глагол «Переосмыслить»).
2. Память об ОТСУТСТВии / тихая эрозия: что-то перестало подтверждаться и должно остыть само (Opus #7).
**Поля в ячейке:**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `salience` | number | вес внимания; затухает во времени (бюджет принадлежит БАЗЕ, не ячейке) |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `decay_policy` | policy-as-data | рецепт затухания в самой ячейке |
  | `lifecycle_stage` | enum | nascent→active→cooling→cold (наблюдаемые стадии) |
  | `last_access` / reinforcement | temporal | подкрепление использованием |
  | `pending` | flag | открытая петля как отдельная ось (развилка FQ6) |
  | `derived_from` | ref | эмердженс: узел-инсайт помечен как выведенный (КК-5) |
**Обязанность движка.** Садовник батчем: decay, консолидация, эмердженс, перевод в cold — асинхронно и инкрементально (только задетые узлы).
**Scale-вариант (КК-3).** Инкрементальный метаболизм: пересчитывать лишь затронутые узлы, не всю базу.
**Честно:** своего gate «перед необратимым» нет — забывание мягкое (`cold`, не delete); необратимое удаление живёт в Ц7. Развилка FQ5 (эмердженс — полноценная фаза?).

### Ц5 · Суверенность (Sovereignty)
**Ценность чего.** Гарантирует, что ячейка носит свою политику и рецепт доступа сама и переживает перенос в другой движок. Основа plug-in/маркетплейса.
**Зачем / что ломается без неё.** Без неё данные — заложник конкретного движка; нельзя портировать, нельзя дать ячейке свои правила доступа.
**Примеры (2).**
1. Данные мигрируют в собственную БД за API — движок обращается к ним через прокси-ячейку (foreign-data-wrapper, Г27).
2. What-if песочница: copy-on-write копия ячейки живёт по своим правилам, не трогая оригинал (Sonnet #9).
**Поля в ячейке:**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `type` / schema | self-describing | ячейка описывает свою форму (Avro/JSON-LD) |
  | `policy` | policy-as-data | своя политика доступа при ячейке |
  | `engine_contract_version` | string | контракт с движком (заложить сейчас) |
  | `key_mode` | anchored/portable | ключ «дома» vs «с ячейкой» (заложить сейчас, Р9) |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `policy_source` | роль | чью волю исполняет движок (КК-1) |
  | `materialization` | live/cache/copy | как ячейка представлена (Г34) |
  | foreign-data-wrapper | descriptor | прокси на внешнюю БД |
  | capability-токены | list | гранулярный доступ |
**Обязанность движка.** Исполнять `policy` ячейки; handshake по `engine_contract_version` при переносе; уважать `key_mode`. Ограничен сверху конституционным потолком Ц7.
**Scale-вариант (КК-3).** fast-lane / slow-lane: суверенные проверки не должны душить пропускную способность.
**Развилка.** Р9 (`key_mode: anchored` по умолчанию, `portable` — осознанный выбор). FQ3 (трёхуровневый хребет: Конституция > policy-as-data > integrity).

### Ц6 · Реляционность (Relationality)
**Ценность чего.** Гарантирует, что связь и вариант — сами память: ребро — единица того же ранга, что ячейка, со своим паспортом.
**Зачем / что ломается без неё.** Без неё связи — служебные нити без доверия/истории; конфликт не виден третьей стороне, каузальный шлейф теряется.
**Примеры (2).**
1. Решение отменено, но его последствия живут — `caused`-ребро переживает родителя, `derived-from` падает бы с ним (Opus #2).
2. Связь деградировала, хотя узлы целы — ребру нужен свой `stale`, отдельный от узлов (Sonnet #7).
**Поля в ячейке (ребро = ячейка, Р7-а):**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `id` | own | ребро того же ранга, свой якорь |
  | `edge_type` | enum | типизация связи (закрытое ядро: caused/derived-from/variant-of/member-of/references, Р8) |
  | `from` / `to` | endpoints | направленность + ретро-навигация |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `confidence` | number | у ребра своё доверие (не наследует у узлов) |
  | `stale` | flag | деградация связи отдельно от узлов |
  | `derived_from` / declared | marker | выведенное ребро ≠ заявленное человеком (КК-5) |
  | cascade physics | по типу | derived-from падает с родителем, caused переживает |
**Обязанность движка.** Каскад по типу ребра; ссылочная целостность при разрыве стороны (не плодить сироты-рёбра); держать derived-рёбра отдельно от заявленных.
**Scale-вариант (КК-3).** Нагрузочный тест графа: обход/целостность на большом числе рёбер.
**Развилки.** Р7 (ребро — отдельная ячейка). Р8 (закрытое ядро типов + контролируемая расширяемость). gate здесь — целостность, не согласие (см. связующий паттерн).

### Ц7 · Согласие (Consent)
**Ценность чего.** Гарантирует, что ячейка знает КОМУ показать и ЧЬЯ она; вводит третью роль — референт (о ком запись).
**Зачем / что ломается без неё.** Без неё данные под одним согласием утекают в другое использование; о третьем лице пишут без его воли; нет права на забвение.
**Примеры (2).**
1. Данные, собранные под одним согласием, используются агентом для другой цели — нужен `use_consent` ≠ `read_consent` (Opus #4).
2. Семейная/групповая память: у записи несколько совладельцев и референтов, скрыть от одного, показать другому (Sonnet #4 / Opus #1).
**Поля в ячейке:**
- _Минимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `referent` | роль | о ком запись (≠ owner ≠ author); заложить сейчас |
  | `owner` | роль | кому принадлежит |
  | `visibility_scope` | scope | кому показывать |
- _Максимум:_
  | поле | тип | что делает |
  |---|---|---|
  | `existence_consent` | bool/policy | согласие на само существование записи |
  | `use_consent` | policy | согласие на использование отдельно от чтения |
  | `consent_taint` | inherited | наследуемая строгость при агрегации (КК-4/КК-5) |
  | `revocation` / `hard_erase` | два примитива | отзыв vs право на забвение (Р10) |
  | `custodial_role` | роль | опекун согласия; акт сокрытия = аудируемая ячейка |
**Обязанность движка.** Gate перед показом и использованием (visibility + use); при hard-erase — уничтожить payload, оставить tombstone (Р10); consent-taint до материализации (КК-4).
**Scale-вариант (КК-3).** Предвычисленное согласие: проверки доступа не пересчитывать с нуля на каждый запрос при масштабе.
**Развилки.** Р12 (роль «опекун согласия» для референта без доступа к платформе). FQ7 (референт + hard-erase сейчас, конфликт с bitemporal «забыть≠удалить»). КОНСТИТУЦИЯ: согласие референта нельзя переопределить policy ячейки (потолок над Ц5).

## Открытые/непокрытые места (объективно)
- Тонкий паспорт `id·type·label·salience·temperature·author·referent` — **рекомендация Р3-а, не решение**.
- Линза/волна (КК-2) — что она (сохраняемая единица / derived-класс рёбер / чистая функция) — **развилка Р4**.
- `price_hint` на паспорте (Ц1) и «эмердженс как фаза» (Ц4, FQ5) — идеи, канон ещё не закрепил.
