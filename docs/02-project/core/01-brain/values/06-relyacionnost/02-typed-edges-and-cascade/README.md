## Суть

Тип ребра — не ярлык для UI, а контракт движка: что происходит с рёбрами, когда одна из сторон
удаляется, забывается или переносится. Объект защиты — **предсказуемость каскада**: движок обязан
знать заранее, какие рёбра тянут цель за собой, какие переживают источник, а какие вообще не несут
обязательств.

## Границы

- **Входит:** словарь родов связи (`caused`, `derived-from`, `variant-of`, `template-of`,
  `member-of`, `references`) и явное поведение каждого при удалении/забвении стороны; ссылочная
  целостность и стратегия для рёбер-сирот (DB-control); закрытый enum vs открытая схема типов.
- **НЕ входит:** есть ли у ребра вообще паспорт (→ 01); варианты/ветки как отдельная модель поверх
  `variant-of` (→ 03, здесь только каскадное поведение самого типа); выведенные (derived/computed)
  рёбра домена-как-волны — это отдельный КЛАСС рёбер, не тип каскада (→ 05).
- **Тонкая граница с 03:** здесь — «`variant-of` при удалении оригинала ведёт себя как?»; там —
  «как выглядит переключение между вариантами и активная ветка».

## Развилки

1. **Набор типов v1.** Закрытый enum (`caused/derived-from/variant-of/template-of/member-of/
   references`) [+ предсказуемо, легко проверить каскад / − новый тип связи = миграция схемы] vs
   открытая расширяемая схема (тип = произвольная строка + декларация каскада) [+ гибко для
   будущих plug-in / − типизация теряет смысл контракта, если типы плодятся бесконтрольно, RQ2].
2. **Каскад `caused` vs `derived-from`.** `caused` переживает удаление причины (истории решений
   важны и после отмены, сценарий Opus #2) [+ честный аудит-след / − «висящие» рёбра на удалённый
   узел] vs `derived-from` падает вместе с источником (производное без источника бессмысленно)
   [+ чистота графа / − теряется след, что производное вообще существовало].
3. **Рёбра-сироты.** Мягкое удаление узла оставляет «призрак» с меткой, на который рёбра
   продолжают указывать [+ ничего резко не рвётся / − граф копит призраков, если забывание частое]
   vs каскадное закрытие (transaction-time) всех зависимых рёбер при закрытии узла (модель В2)
   [+ чисто, консистентно с bitemporal-версионированием / − нужно явно решить для каждого типа,
   «зависимый» или нет].
4. **Гранулярность каскада.** Правило на уровне ТИПА ребра (все `derived-from` ведут себя
   одинаково) [+ просто, декларативно / − не учитывает контекст конкретного ребра] vs правило на
   уровне ЭКЗЕМПЛЯРА ребра (можно переопределить для конкретной связи) [+ гибко для исключений /
   − непредсказуемо, ломает «контракт»].
5. **Кто утверждает новый тип.** Любой агент может предложить новый тип связи по мере надобности
   [+ не блокирует работу / − типы плодятся, теряют контракт] vs новый тип требует мини-ADR/ревью
   владельца [+ контракт остаётся контрактом / − трение, блокер для быстрой итерации].
