## Суть

Группа узлов может временно вести себя как одна единица (композит) и потом рассыпаться обратно —
реляционность обслуживает оба направления, не только «склеивание». Отдельно — домен/категория как
ЭМЕРДЖЕНТНЫЙ паттерн множества слабых рёбер (плотность связей = «запах» домена), которые никто явно
не создавал — их вычисляет движок. Объект защиты — **честное различение того, что кто-то заявил, от
того, что система сама вывела**, при этом не запрещая системе выводить.

## Границы

- **Входит:** `member-of`/композиция как обратимый процесс (распад = не удаление, а разрыв
  временной связи); класс «выведенных» (derived/computed) рёбер отдельно от явно заявленных, с
  паспортом-автором «алгоритм/движок», не человек; порог, после которого плотность связей
  признаётся «доменом».
- **НЕ входит:** каскад удаления `member-of` при исчезновении члена группы (→ 02, это вопрос типа
  и его физики); может ли выведенное ребро «повыситься» до заявленного при подтверждении человеком
  — пограничный случай с 04 (изменение confidence) и 01 (смена авторства при подтверждении).
- **Тонкая граница с 04:** там — «протухает ли уже существующая связь»; здесь — «возникает ли связь
  вообще, если её никто явно не писал».

## Развилки

1. **Явные vs выведенные рёбра — одна сущность или разные.** Один тип объекта с флагом
   `derived: bool` [+ проще схема, одна таблица / − риск, что выведенное ребро воспринимается как
   подтверждённое утверждение, ложное доверие] vs структурно разные объекты (derived-edge —
   отдельный класс без паспорта-человека) [+ честно разводит «кто-то сказал» от «система
   посчитала» / − два похожих объекта в API, RQ4].
2. **Порог «стало доменом».** Фиксированный порог плотности связей (N узлов с M общими
   метками/соседями → авто-создаётся domain-узел) [+ детерминированно, воспроизводимо / − магическое
   число, не объяснимо интуитивно] vs мягкий скор без жёсткого порога (домен «проявляется»
   постепенно в ранжировании, никогда не материализуется как отдельный узел) [+ не плодит
   артефактные domain-узлы / − нет стабильного адреса, на который можно сослаться].
3. **Композит: временная склейка vs постоянная.** Группа существует, пока держится критерий
   (например, «все задачи одного спринта» — спринт закрылся, композит распадается автоматически)
   [+ обслуживает и склейку, и распад одним правилом / − нужен явный критерий распада на каждый тип
   композита] vs композит создаётся явным действием и живёт, пока явно не распущен [+ предсказуемо,
   под контролем / − легко забыть распустить, копится «мёртвых» композитов].
4. **Повышение derived → заявленное.** Человек может подтвердить выведенную связь, и она
   становится обычным утверждением с паспортом-человеком (наследует confidence как стартовое
   значение) [+ выведенное становится полноценным без потери истории откуда взялось / − смена типа
   объекта на лету, нужна миграция] vs выведенное остаётся выведенным навсегда, подтверждение —
   отдельное новое ребро поверх [+ проще, класс объекта неизменен / − задвоение (два ребра об одном
   и том же — выведенное + подтверждённое)].
5. **Кто вычисляет плотность.** Фоновый батч-индексатор по расписанию (пересчитывает
   домены/паттерны для всего графа) [+ предсказуемая нагрузка / − задержка, домен «проявляется» не
   сразу] vs инкрементально при каждой записи нового ребра (индекс обновляется на лету) [+ всегда
   свежо / − дороже на запись, потенциальный узкий момент при массовой загрузке (адаптеры, Г22)].
