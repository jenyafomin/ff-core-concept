# Направление 04 — Деградация связи (edge-decay)

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md`, `../../V6-relyacionnost/ideas/IDEA-edge-stale/README.md`
  (портировано), `../../V6-relyacionnost/questions.md` RQ3, `../01-edge-as-citizen/README.md`
  (паспорт ребра — носитель полей)

## Суть

Связь стареет по собственной динамике, отдельно от узлов, которые она соединяет: оба узла живы и
валидны, но контекст изменился, и утверждение «A связано с B» уже не отражает реальность (классика
— «работает в компании X» после увольнения: узлы целы, ребро протухло). Объект защиты —
**собственный `confidence`/`stale` на ребре**, который никто не путает с деградацией данных внутри
узлов.

## Границы

- **Входит:** поля `confidence`/`last-affirmed` на ребре, независимые от аналогичных полей узла;
  кто и как пересчитывает (движок по расписанию / агент по запросу / оба); порог, после которого
  `stale`-ребро скрывается из дефолтного среза графа, но не удаляется.
- **НЕ входит:** сам факт, что у ребра-утверждения ЕСТЬ такое поле в паспорте — это решено в 01
  (В4); что происходит с рёбрами при удалении УЗЛА (→ 02, каскад); подтверждение/забывание как
  глаголы цикла памяти (`../../L0-memory-unit.md`, фаза C) — здесь это частный случай, применённый
  к ребру, а не новый механизм.
- **Тонкая граница с 01:** там — «есть ли у ребра это поле вообще (паспорт)»; здесь — «как оно
  меняется во времени и кто триггерит пересчёт».

## Развилки

1. **Кто пересчитывает `stale`.** Движок по расписанию (батчевый пересчёт confidence по правилу
   волатильности) [+ равномерно, не зависит от активности / − тратит ресурс на рёбра, которые никто
   не читает] vs агент по запросу (пересчёт только когда ребро попало в контекст) [+ дёшево,
   ленивая оценка / − «забытые» рёбра годами не пересчитываются, стухший граф выглядит свежим] vs
   оба (ленивый пересчёт + фоновая подчистка раз в период) [+ лучшее из двух / − два источника
   правды для одного поля, риск гонки, RQ3].
2. **Порог видимости.** Жёсткий отсекающий порог (`stale`-ребро исчезает из дефолтного среза при
   confidence < X) [+ простое правило, предсказуемо / − резкий обрыв, ребро было почти достоверно и
   вдруг пропало] vs плавная деградация (вес ребра в выдаче убывает непрерывно, «фаза фокуса» по
   аналогии с В1 узла) [+ мягче, соответствует решению В1 owner про фазы видимости / − сложнее
   реализовать ранжирование, нет чёткого «включено/выключено»].
3. **Триггер пересчёта.** Время (волатильность по расписанию, как у узла) [+ переиспользует уже
   решённый механизм узла / − для связи может быть неверная эвристика — время не единственный
   фактор протухания отношений] vs событие-триггер (упоминание/подтверждение/опровержение одной из
   сторон меняет confidence связанных рёбер) [+ точнее отражает реальное протухание / − нужен
   механизм распространения события по графу, дороже].
4. **Источник сигнала.** Только явное подтверждение/опровержение человеком или агентом
   (Act→Confirm из цикла L0) [+ калиброванно, соответствует решению L0 «доверие меняется от
   использования» / − связи, которые никто не трогает, зависают в неопределённости навсегда] vs
   косвенный сигнал (совместное появление узлов в новых контекстах поддерживает confidence,
   отсутствие — снижает) [+ не требует явного действия / − легко перепутать корреляцию с
   подтверждением, ложный сигнал доверия].
