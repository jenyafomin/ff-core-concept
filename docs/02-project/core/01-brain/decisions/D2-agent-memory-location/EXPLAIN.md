# D2 — «Где живёт память агента: на столе или в библиотеке» (объяснение для владельца)

## 1. О чём вопрос

**Session** — это рабочий стол одного агента на время одной задачи: открыл — работает — закрыл.
**Домен 01** — это общая библиотека всей памяти системы: файлы, факты, инсайты. То, что должно жить
долго, быть проверяемым, подчиняться правилам доверия/согласия/забывания.

Вопрос: когда агент во время работы «что-то помнит» — эта память лежит прямо **у него на столе**
(как содержимое Session), или на столе лежит только **стикер с номером полки** (тонкая ссылка на
узел библиотеки), а сама «книга» стоит в общем хранилище?

## 2. Три варианта

**А. Память внутри Session.** Всё, что агент запомнил за сессию, хранится прямо в записи Session —
как содержимое стола.

**Б. Session = только тонкая ссылка (thin-ref) на домен 01.** На столе — координаты: какие узлы
общей библиотеки сейчас в работе. Сама память физически лежит в библиотеке.

**В. Гибрид.** По умолчанию Б (ссылка), + короткий **локальный буфер** на столе — черновик: то, что
«варится в голове» прямо сейчас и ещё не оформлено как факт (окно диалога, промежуточное резюме).
Когда черновик созревает — отдельным шагом переносится в библиотеку как настоящий узел.

## 3. Плюсы / минусы

| | А. Память в Session | Б. Только ссылка | В. Гибрид |
|---|---|---|---|
| Дублирование | Да — своя копия, может разойтись с библиотекой | Нет — одна книга, один экземпляр | Почти нет — буфер это то, чего в библиотеке ЕЩЁ нет |
| Единая правда | Нет — стол становится вторым источником истины | Да — правда одна, в библиотеке | Да для всего оформленного; черновик — временный, не претендует на правду |
| Скорость в моменте | Высокая — всё под рукой | Чуть дороже — обращение к библиотеке | Высокая для черновика + надёжно для долгой памяти |
| Приватность черновика | Черновик защищён, но и факты тоже спрятаны от графа | Даже сырая мысль сразу подчиняется общим правилам согласия/забывания — шумит в общей памяти | Черновик реально приватный, пока не стал фактом |
| Удаление/замена агента | Память рискует пропасть вместе со столом | Память не пропадает — она принадлежит библиотеке, не столу | Черновик пропадает (это нормально), оформленное — остаётся |

## 4. Что меняется от выбора

**А ломает правило проекта** «стол = проекция, не вторая правда» (это же правило уже стоит риском
№1 всей архитектуры — «control-plane как второй источник истины»). Если стол пересобирают с нуля
(разрешённая операция первого дня), вариант А стирает реальную память, а не просто координаты.
Также правило «память НЕ шарится между репликами агента» (уже зафиксировано) при варианте А
неоднозначно — непонятно, копировать содержимое стола в реплику или начинать пустым. При Б это
решается само: у новой реплики просто нет ссылок, ссылки на библиотеку — общие и видны всем.

**Б без буфера** заставляет каждую сырую мысль агента сразу проходить через тяжёлые правила
библиотеки (согласие, доверие, забывание) — рискует засорить общую память черновиками.

**Гибрид** снимает оба риска, но требует одного нового правила, которого пока нет: **когда именно
черновик становится настоящим фактом** («момент консолидации»). Это отдельный, не блокирующий вопрос.

## 5. Рекомендация

**Гибрид, с Б как база по умолчанию.** Основания:
- В самом описании Session уже заложено поле «окно контекста/резюме» — то есть черновик-буфер
  подразумевался с самого начала, просто не был назван отдельно.
- Правило «стол не должен быть второй правдой» уже принято как правило дня для всей оркестрации.
- «Память не шарится между репликами» чисто резолвится только через ссылку.
- Двое из агентов, разбиравших этот вопрос параллельно, независимо сошлись на «ссылка, стол = координата».

«Оба» — жизнеспособный ответ, не компромисс-затычка: в проекте уже есть похожий приём (VariantGroup —
«оба варианта живут, выбор — отдельная пометка, а не удаление»). Здесь то же самое: черновик и
оформленная память — два разных по природе объекта, а не спор «либо-либо».

**Уже можно принять сейчас:** база — тонкая ссылка (Session = координата, не хранилище). **Открыто
на потом:** точный размер/форма локального буфера и правило «когда черновик становится фактом» —
это детали реализации, не блокируют текущее решение.
