# 🧭 ОБЗОР темы: у связей памяти теперь есть «имя» (edge-identity)

## Что это одной мыслью
Раньше у **единиц** памяти был свой id, а у **связей между ними** — нет. Теперь у связи тоже есть собственное «имя» (`id`) и место под сквозную идентичность (`canonical_id`). Связь стала **полноправной памятью того же ранга**, а не служебной ниткой. Это ценность **Реляционность (Ц6)** в форме данных.

## Зачем именно СЕЙЧАС
Это **единственное**, что нельзя переделать потом без переписи журнала: журнал append-only, и если рёбра начнут копиться без «имени», позже придётся мигрировать всю историю. Поэтому мы замкнули **форму** заранее.
🟢 **Экономия, не переделка** — ровно то, что ты просил: заложить фундамент, который не пересаживать.

## Что уже сделали (сколько ума вложено)
За ночь 2026-09-15 тему прогнали через несколько независимых линз:
- **architect** — спроектировал форму id.
- **critic** — адверсариал поймал реальный дефект: первый вариант включал в «имя» ребра время (`validFrom`), и это **тихо теряло бы рёбра** (конфликт с тем, как движок склеивает связи). Исправили: «имя» = `{источник, тип связи, цель}`.
- **builder** — реализовал аддитивно, **0 миграций**.
- **2× reviewer** — финальный вердикт PASS.
- Тесты: **222 → 238 зелёные**, никаких регрессий, журнал и логика склейки не тронуты.

## Как ложится на 7 ценностей
- **Ц6 Реляционность** 🟢 — связь = память со своим паспортом.
- **Ц2 Тождество** 🟢 — «имя» переживает изменения (правки meta/времени id не «прыгает»).
- Форма **аддитивна и обратима** — старые рёбра типизируются без изменений.

## 🟡 Открытые развилки (отложено осознанно)
- 🟡 **Поведение** — склейка/расщепление связей, перенос `canonical_id` при слиянии — пока НЕ включено (Reserved-Form: зарезервировали форму, поведение позже).
