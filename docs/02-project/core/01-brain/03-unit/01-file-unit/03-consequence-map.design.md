# Карта последствий — файл↔единица на реальном коде FF

> Пара к `01-reality-map.analysis.md` (та фиксирует, что ЕСТЬ; эта — что СТАНЕТ с кодом при каждой модели).
> Read-only разбор, DESIGN-фаза, ничего не строит и не выбирает разрез — даёт владельцу цену каждого выбора
> в терминах уже написанного кода. Якоря `file:line` из reality-map не дублирую, ссылаюсь на них.

## 0. Три опоры реальности, об которые бьётся любой выбор

1. **`@ff/core` уже 1:1** — `FileNodeStore` кладёт один `FFNode` в один `.md` (`store.ts:35-37`),
   «files ARE the graph» (`store.ts:21`). Рода `file` в `NODE_KINDS` НЕТ.
2. **`@ff/engine` уже act-first и ЗАМОРОЖЕН** — единица записи = `Act` в append-only журнал; payload
   идёт ТОЛЬКО по ссылке (`payloadRef/payloadHash`, `types.ts:265-282`); сигнатура `write(act):Ack`,
   10 полей envelope и `resolve()` PEP — FROZEN; Стадия-1 УЖЕ закоммитила `erased`-акт + `PayloadStore.shred`
   (`types.ts:170-182`), которые предполагают payload-by-ref.
3. **ADR-0006 уже принял два спорных для этого вопроса решения:** §(c) «**файл = БАНДЛ узлов, 1:1 — НЕ закон**»
   (прямо против опоры 1!) и §(g) «access/policy/registry-типы — **DB-first ТОЛЬКО, никогда не file-first**»
   + §(e) замок «в канон пишет только движок». Плюс CQRS (ADR-0008): **лог = system-of-record, граф =
   пересобираемая проекция**.

Любая модель файл↔единица оценивается по тому, помиряет она опоры 1↔2↔3 или ломает одну ради другой.

---

## M-a · Файл ЕСТЬ единица (1 файл = 1 единица, мировоззрение `@ff/core` расширенное на всё)

1. **`store-md.ts` становится:** канонический стор — carrier-блоб исчезает, но «схлопыванием ВНИЗ»: `.md`-файл
   объявляется самой единицей, `EnvelopeNode` сводится к `FFNode`. Две модели узла коллапсируют в одну ценой
   **разжалования журнала** — состояние живёт в файле, а не в логе актов. `writeAct`/append-only-журнал теряет
   первичность.
2. **ADR-0006 file-first:** **противоречит.** M-a делает file-first универсальным законом, а ADR-0006 §(b)/§(c)
   держит его опт-ином на тип и прямо запрещает 1:1 (§c) и file-first для access/policy (§g). «Файл=единица»
   разрешил бы переписать поле `access` правкой файла = privilege-escalation в обход §(e)-замка.
3. **Migration cost: ВЫСОКАЯ, ломающая.** Разворачивает CQRS (I-5): файл, а не журнал, становится write-model.
   `erased`-акт + `shred` + payload-by-ref из Стадии-1 повисают — если истина inline в файле, стирать
   payload-by-ref нечего. Не аддитивно — это реверс фундамента, уже закоммиченного.
4. **Substrate vs ergonomics:** лучшая для ручного редактирования ОДНОГО дока, **худшая для agent-first
   субстрата** (msg-141): трейсы/память/метрики машинные и объёмные → 10⁴ файлов-трейсов, ЯВНО отклонено в
   ADR-0006 Alternatives 1. Дёшево для `@ff/core`-легаси, дорого для замороженного engine.

## M-b · Файл — payload-грань единицы (единица = конверт в логе; файл = один by-ref-facet)

1. **`store-md.ts` становится:** блоб растворяется в ПРАВИЛЬНУЮ сторону. Конверт остаётся единицей (лог/проекция),
   `.md`-файл становится **payload-хранилищем по ссылке** (`payloadRef`) — тем самым `PayloadStore`, что уже есть
   в Стадии-1. `writeNode` перестаёт пихать весь envelope JSON-ом в тело `FFNode`; TODO(M3) proza→envelope
   переформулируется как «тело файла = payload-контент ОДНОЙ грани, поля конверта деривируются». **Формализует
   разделение двух моделей, НЕ схлопывает их.**
2. **ADR-0006 file-first:** **сохраняет, чисто.** file-first = автор правит payload-грань (`.md`), движок
   выводит акт диффом (ровно текущий `ingest()`/`detectStale()`, store-md.ts). §(c) «файл=бандл» работает: один
   файл может нести payload нескольких единиц, потому что файл≠единица, адресность по `id` (I-1). Субсумирует
   file-first как частный случай авторства грани.
3. **Migration cost: САМАЯ НИЗКАЯ, аддитивная.** `write(act)` не меняется — `payloadRef` уже в замороженной форме
   `Act` (`types.ts:265`). Стадия-1 (`erased`+`shred`+by-ref) построена ИМЕННО под эту модель — 0 правок
   контракта, журнала, 10-полей, `resolve()`. Работа только внутри `store-md` (сделать файл настоящим payload-blob
   вместо opaque-envelope-JSON) — это и есть содержание TODO(M3), НЕ смена контракта.
4. **Substrate vs ergonomics:** **лучшая для обоих.** Всё, с чем работает агент, — единица-в-логе (акты, трейсы,
   память), payload-by-ref держит PII/стирание/масштаб; файлы там, где человек авторит грань (§g опт-ин). Модель,
   к которой ADR-0006 + Стадия-1 УЖЕ склонены.

## M-c · Файл — линза/проекция единицы (файл = материализованный вид, не источник истины)

1. **`store-md.ts` становится:** **экспорт-материализатор** (`ff-engine export <slice>`, ADR-0006 §d, DB→file
   по требованию). Файл — производный read-only вид; `loadEnvelopeNodes` как источник истины исчезает (файл не
   читается обратно как правда). Разделение формализовано, но в DB-first-сторону: единица в логе/PG, файл —
   сносимая проекция (совместимо с осью АКТ→ГРАНЬ→ЛИНЗА, где линза не хранится).
2. **ADR-0006 file-first:** **не может его вместить (частичное противоречие).** Чистая линза read-only → правка
   человеком `.md` = правка проекции, а I-5 запрещает проекции быть вторым источником истины. Но §(f) требует для
   «человеческих» типов, чтобы `md+journal` БЫЛ write-model. M-c поддерживает только §(d)-экспорт, не §(f)-авторство
   → рушит весь смысл file-first (владелец правит `.md`/промпты голосом каждый ход, §g тип 3).
3. **Migration cost: контракт цел, но выбрасывает УЖЕ написанный код.** Лог остаётся SoR (совместимо с CQRS +
   Стадией-1), но `ingest()`/`detectStale()` (file-first слайс, уже в `store-md.ts`) становятся бессмысленны —
   файл никогда не авторитетен. Заставляет всё, что владелец сейчас правит как `.md`, гнать через
   `engine.write()`.
4. **Substrate vs ergonomics:** хорошая для agent-first (лог-first, файлы одноразовые), **худшая для ручного
   редактирования** — владелец не может править `.md` как истину. Прямо против главной причины file-first в
   ADR-0006.

## Вердикт (не выбор — ранжирование по цене на реальном коде)

| Модель | `store-md.ts` во что | ADR-0006 file-first | Migration vs frozen/Стадия-1 | Agent-first + ergonomics |
|--------|----------------------|----------------------|-------------------------------|---------------------------|
| **M-a** файл=единица | канон-стор, журнал разжалован | **противоречит** (§c/§e/§g) | **ломающая** (реверс CQRS, повисает erased/shred) | ergonomics да / substrate НЕТ |
| **M-b** файл=payload-грань | реальный payload-by-ref store (= PayloadStore) | **сохраняет+субсумирует** | **аддитивная, ~0** (построено под неё) | **оба да** |
| **M-c** файл=линза/проекция | export-материализатор | **не вмещает §(f)** | контракт цел, но стрендит `ingest()` | substrate да / ergonomics НЕТ |

**Самая дешёвая и самая agent-first одновременно — M-b.** Она единственная (1) не трогает замороженный
`write(act)`/envelope/`resolve()`, (2) — та модель, под которую УЖЕ закоммичена Стадия-1 (payload-by-ref +
`erased` + `shred`), (3) сохраняет ручное редактирование через file-first §(f), и (4) единственная снимает
конфликт опоры-1 (1:1) ↔ ADR-0006 §(c) (файл=бандл), расцепив тождество единицы (`id`) от файла-носителя грани.
M-a и M-c каждая жертвует одной опорой ради другой (M-a — журналом/субстратом ради ergonomics; M-c — ergonomics
ради лог-чистоты). **Это не ратификация разреза** — OQ-6/OQ-3 остаются за владельцем; здесь только цена в коде.
