# Состояния (states) — короткая рекомендация

Оформление склонности владельца (см. `PROCESS-UPGRADE-2026-07-17.md` §3, §8 Q2), не переизобретение.

## 1. Где физически лежит `states/`
Один фиксированный уровень — **корень проектного дерева доков**: `docs/00-states/`. Это единственная
точка входа (не разбросано по темам). Внутри — плоский список `00-states/NN-<slug>/`, тема указывается
полем `theme`, а не вложенной папкой. Причина: правило владельца — `state` не живёт «внутри произвольных
папок»; папки тем (`02-project/core/...`) остаются местом контента, а не местом состояний.

## 2. Что внутри одного `states/NN`
Минимальный набор полей/файлов:
- `state.md` (frontmatter): `id (NN)`, `theme`, `status (active|paused|done)`, `opened_at`, `updated_at`,
  `agents: [...]` (кто привязан сейчас), `plans: [ссылки на plan-файлы/папки]`.
- `log.md` или `conversations/` — что происходило внутри state по времени (append-only).
- Ссылки, не копии контента: state указывает на реальные доки/темы через `Related`, не дублирует их.

## 3. Правило многопоточности (когда новый state)
Новый `state` заводится **на каждую параллельную ветку работы**, которая должна двигаться независимо:
новый план, новый плагин/улучшение, конкурирующая гипотеза. Правило: **1 активный план = как минимум
1 state**, но не наоборот (один state может держать несколько связанных планов одного русла). Признак
«нужен новый state»: работы могут блокировать/путать друг друга, если идут в одном — тогда разделяем.

## 4. Как агент «входит» в state
Агент получает `state_id` в момент старта хода (жёсткая привязка на этот отрезок времени, не «навсегда»).
Пока агент активен — пишет прогресс в `log.md` этого state и не трогает чужие state. Смена state = явное
переключение (аналог смены ветки), фиксируется в `state.md` (`agents`) с таймстампом входа/выхода —
это и даёт срез «кто что делает» по времени, фильтруемый по `theme`/`status`/`agent`.

## 5. Риски
- **H** — «никогда не удалять» + рост числа параллельных states → дерево `00-states/` разрастается без
  компрессии; нужен ранний механизм архивации (`status: done`, не удаление) + git как история.
- **M** — плоская нумерация `NN` без вложенной темы теряет читаемость на масштабе; смягчается полем
  `theme` + индексом (README/INDEX в `00-states/`), а не структурой папок.
