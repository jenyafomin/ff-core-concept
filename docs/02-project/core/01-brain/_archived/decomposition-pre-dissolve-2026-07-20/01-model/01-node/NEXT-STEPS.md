# ▶ СЛЕДУЮЩИЕ ШАГИ + подхват (свежая сессия)

## 1. Следующий несущий узел = АКТ (план папок)
Разложить «Акт/журнал» той же волной, что и «единицу». Предлагаемая структура (зеркалит `unit/`):

```
decomposition/01-model/
├── 06-act.md                  # карта-тема: акт = вторая единица (глагол)
└── act/
    ├── TREE.md · README.md    # дерево + описание (раздельно)
    ├── 01-act-passport/       # паспорт акта: actor · authority · idempotency-key · ref+hash · time
    ├── 02-journal/            # append-only журнал: запись/чтение = тоже акты; rebuild-from-journal
    ├── 03-idempotency/        # ключ идемпотентности (лечит дубль-баг шлюза заодно)
    ├── 04-propagation/        # КОНТРАКТ ПРОПАГАЦИИ (см. §3) — lineage+инвалидация+freshness
    └── 05-plugin-api/         # плагин = актор+словарь; вся поверхность = API актов
```
Параллельно — черновик **ADR «Акт и журнал»** (закрывает DEC-6, гонку D8-Q3, self-escalation, идемпотентность, и определяет plug-in API).

## 3. Свести в ОДИН механизм (Fable): «контракт пропагации»
Мои D-U5 (variant-cascade) + D-U6 (re-check at emit) + D-U7 (consent-на-hop) + erase-каскад +
stale-вариант + derived-кэш = **пять имён одной механики**: lineage + инвалидация + freshness-policy.
Проектировать как ОДИН модуль, не пять решений.

## 4. Что могли упустить за один проход (список на перепроверку)
Владелец прав: один проход неполон. Кандидаты в слепые зоны для следующей волны:
- **Вне-графовое забвение** — отправленные сообщения, эмбеддинги, память других агентов (Fable+критик: дыра, механизма нет).
- **Сегментация контента по референту** — новое слабое звено hard-erase; свободный текст резать нечем (связь с гранулярностью D-4 anchor/span).
- **Бюджет/цена read-time проекций на масштабе** (~100k узлов — death-by-design кандидат): нужен контракт материализации/кэша.
- **Прямое управление БД из системы** (сценарий владельца) — как система/агент правит структуру напрямую и безопасно.
- **Эволюция схемы живого типа** (D8-Q4) → решается `namespace@version` + маппинг-рёбра.
- **Полнота enforcement** (кто и где физически принуждает доступ на всех путях).
- **Мульти-пользователь** (сейчас отложен, R5=один владелец) — когда включаем ось.
