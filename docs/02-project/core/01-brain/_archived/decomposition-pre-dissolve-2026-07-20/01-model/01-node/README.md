# 🧩 Разбор ЕДИНИЦЫ — «что храним» (описание к дереву)

> Задача сформулирована как **набор переменных**. Эта волна берёт группу **B (единица)** и её два
> самых тугих узла — **policy-блок** и **резолвер контекста** (как агент получает правильный контекст).
> Не строим — вскрываем глубину и держим альтернативы.

## Оценочная функция (зачем — группа A)
Любое решение по единице проверяем: **держит ли оно все 7 ценностей?**
Читаемость · Тождество · Доверие · Витальность · Суверенность · Реляционность · Согласие.
Деградация грани = дефект, а не компромисс.

## Переменные, которые вскрываем (группа B и её швы)

| # | Переменная | Ключевой вопрос волны | Папка |
|---|-----------|------------------------|-------|
| B1 | **Поля паспорта** | Полон ли набор `id·type·label·owner·author·referent·scope·storageLevel·salience·temperature·confidence·policy`? Чего НЕТ? Что дёшево-скан vs payload? | `01-passport/` |
| B2 | **Policy-блок** | Привязка: к ЯЧЕЙКЕ / ГРУППЕ / ГРАНИ / ТИПУ? Что именно объявляет? Где живёт (в данных vs системный слой)? Альтернативы? | `02-policy-block/` |
| B3 | **Резолвер контекста** | Как из «агент + состояние + запрос» собирается правильный срез (ссылки → линза → порог доступа)? Живёт в данных или как система? Помогает ли человеку? | `03-context-resolver/` |
| B4 | **Варианты и проекции** | Одна информация, описанная по-разному: `variant-of` (варианты) vs `view-def` (проекции). Кто выбирает под состояние агента? | `04-variants-projections/` |

## Метод (как режем)
- **Сначала расхождение** (генерим варианты, ничего не режем), **потом схождение** (критик отклоняет, но
  отклонённое остаётся в файле с пометкой «почему»).
- Каждый разбор — в файл. Форма ответа агента: **вердикт + веер вариантов + топ-развилки**, без сырья.
- Правило подъёма: идея на ≥2 ценности → поднимается в `../../infrastructure/`.

## Границы волны
- НЕ решаем стек БД (это отдельный трек `02-stack/` + гейт Fable).
- NE закрываем hard-erase-спор целиком (самое слабое звено интеграции) — только фиксируем, как он ложится на policy-блок.
- Мульти-пользователь — держим как ось, но глубина позже (сейчас R5 = один владелец).
