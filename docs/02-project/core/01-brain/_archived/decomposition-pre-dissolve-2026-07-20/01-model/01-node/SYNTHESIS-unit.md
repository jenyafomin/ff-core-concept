# 🧩 СВЕДЁНКА — разбор ЕДИНИЦЫ (4 агента, 2026-07-16)

> Свод 4 параллельных разборов (поля паспорта · policy-блок · резолвер контекста · сквозной критик).
> Форма — вердикт + развилки. Все решения ПРЕДВАРИТЕЛЬНЫЕ (агентские), ждут подписи владельца.

## 👑 Главное схождение — 3 агента об одном
**«policy-блок» как 12-е поле паспорта — категориальная ошибка (риск бог-таблицы).**
И агент по полям, и агент по policy независимо: `consent · ACL · retention · confidence` — это **поля
паспорта (ЗНАЧЕНИЯ)**, уже ратифицированы (DL-12), а НЕ содержимое policy. Формула-арбитр:

> **policy = ПРАВИЛО · паспорт = ЗНАЧЕНИЕ · view-def = ЛОГИКА.** Три ведра, одна проверка.

Это прямое продолжение главного принципа интеграции («храни минимум в одном доме, не дублируй»).

## 🟦 B1 — Поля паспорта
- Список владельца (12) = подмножество; канон ~22 поля.
- **Пропущено, но нужно:** `status` + `committed` (черновик/подтверждено — без него не работает
  rebuild-from-journal) · `provenance` + `created/updated` (Доверие/аудит) · `validFrom/validUntil`
  (bitemporal) · `epistemic` · `acl-to-agents` · `language/locale`.
- **НЕ поле** (отсеяно): `derived_from`→ребро · `price_hint`,`lifecycle-stage`→view-def ·
  `key_mode`→суб-атрибут `storageLevel` · `pending`→node-type · `anchor/span`→поле ребра.
- **Граница паспорт↔payload:** поле, если (а) ограниченный тип, (б) нужно движку/гейту без вскрытия узла,
  (в) участвует в WHERE/ORDER на масштабе. Иначе — payload.
- ⚠️ **Тихий дрейф:** богатый паспорт (~22) де-факто уже перевесил «минимальный шейп» (DL-12), но нигде
  не подписан владельцем как ответ на развилку Р3. → закрыть явно.

## ⚖️ B2 — Policy-блок
- **Две ортогональные оси** (их смешение = путаница владельца «ячейка или группа?»):
  **Авторитет** (Конституция>policy>integrity, вертикаль) × **Охват** (сколько ячеек, горизонталь).
- **Привязка (ось охвата), широко→узко:** глобально (Конституция) · слой/scope · **тип** (дешёвый) ·
  группа/категория (контейнер + `member-of`) · грань/facet (открыто, span не выражается) · **ячейка**
  (`governed-by`, побеждает по охвату).
- **Единый паттерн наследования:** ячейка НЕ носит правило инлайн-копией — **ссылается** на policy-узел;
  любой уровень = другой `subject`; новый уровень = INSERT, ноль кода. **Конфликт в 2 шага: сначала
  авторитет (Конституцию не пробить), потом охват (частное бьёт общее).**
- **Содержимое policy = только узкие governance-декларации.** Единственный чистый per-type флаг =
  `erase-capability`. «Умные категории» (derivation-rule) — не policy, а view-def.
- **«Описать всё внутри данных» (Ц5)** = самоописательность **через ссылку, не копию** (`governed-by` +
  `policy_source` + значения на паспорте; тело правила — один раз в реестре; экспорт = снимок).

## 🧭 B3 — Резолвер контекста
- **Формула:** контекст = **Достижимое ∩ Релевантное ∩ Разрешённое** над одним графом от узла-якоря.
  Слои: (1) ссылки — обход рёбер по id; (2) линза (view-def) под состояние агента; (3) паспорт+порог
  (read · use≠read · redacted).
- **Пересечение, НЕ конвейер** + capability-pushdown: запрещённые подграфы не обходятся вовсе.
- **Резолвер = именованный ШОВ (resolve-contract), не новая опора:** собирает порог (#5) + линзу (#6) +
  паспорт (#7). Новых примитивов нет. **НО нужен явный владелец → консолидировать с D-7 / D8-Q2.**
- **Где живёт — гибрид:** рецепт (якорь-ребро, view-def, policy, selector) = ДАННЫЕ; исполнение и
  принуждение = ДВИЖОК.
- **Разные агенты = разные срезы, пересекаются по `canonicalId` — без силосов.** «Не одна память на
  проект» = scope-полоса + owner/tenant + категория-view, ноль новых колонок.
- **Enforcement (ответ D8-Q2):** физически принуждает **ДВИЖОК в точке порога, непробиваемо**; БД-RLS =
  бэкстоп. **Человеку помогает тот же механизм:** кокпит = `resolve(human-anchor, cockpit-lens, ownerIdentity)`.
- **Отклонено:** физические per-agent силосы (рушат Реляционность); материализация снапшота как истины
  (рушит read-time проекцию — только derived-кэш).

## 🔴 Критик — топ-дыры (ранжир по несущести)
1. **Erase двудомный на живом кейсе:** `audit-log-entry` (системный слой, erase=false) содержит PII
   референта → референт требует hard-erase → тип отказывает → согласие нарушено без арбитра. (C-1, weakest link)
2. **Consent-gate дырявый сбоку:** порог заражения/consent-taint описан ТОЛЬКО для авто-индекс/derived;
   прямая навигация A(приватный)→B→C резолвером тем же порогом не гейтится → утечка.
3. **Гонка резолвер vs журнал:** контекст собран в t0, согласие отозвано в t0+ε, ответ агента в t1 с
   устаревшим содержимым — нет snapshot-контракта (D8-Q3).
4. **Stale variant воскрешает стёртое:** hard-erase к одному `variant-of` не каскадит на сиблингов того
   же факта → информация переживает удаление через параллельную формулировку.
5. **owner vs referent vs author при erase:** запись author=agent-от-owner, referent=третье лицо;
   референт требует erase, owner против → три «независимые» роли сталкиваются без правила приоритета.
- Рядом: «кто охраняет policy-запись» (policy пишется тем же INSERT → self-escalation) · type-squatting
  между модулями с одинаковым `node_type` · trust-laundering контекста между агентами разного клиренса ·
  эволюция схемы живого типа (D8-Q4).

## ❓ Развилки на подпись владельца
- **Ф1 (несущая, weakest link) — hard-erase:** оси авторитет×охват. Рек: `erase` объявляет ТИП (охват),
  слой накладывает конституционный `no-erase` (авторитет); 2-шаговое разрешение → слой побеждает. Плюс
  принять ADR «журнал без инлайн-payload». **Кандидат в Fable-гейт** (высокая цена ошибки).
- **Ф2 — приоритет трёх ролей (owner/referent/author) при erase:** кто главнее — референт (согласие) над
  owner? Ввести роль «опекун согласия»? (этическая развилка, связана с Ц7).
- **Ф3 — форма паспорта:** подписать «богатый ~22 поля» (де-факто) vs минимальный шейп. Добавить
  `status·committed·provenance·timestamps·validFrom/Until·acl-to-agents`.
- **Ф4 — variant-cascade при erase:** hard-erase каскадит на все `variant-of` одного факта? (закрыть №4).
- **Ф5 — snapshot-контракт резолвера:** как согласовать отзыв согласия во время сборки контекста (№3).
