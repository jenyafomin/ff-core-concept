# Критика полноты — линза ПАМЯТЬ (что упущено с точки зрения хранения)

> Цель: найти дыры, не хвалить. Классификация: БЛОКЕР / ЖЕЛАТЕЛЬНО / МЕЛОЧЬ.

## 1. Виды памяти без node-type

- **[узел] Расписание / будущие события / повторы** — `event` в node-types.md определён как эпизод
  ПРОШЛОГО (`occurredAt`, «якорь эпизодической памяти»). Нет узла для будущего/повторяющегося
  (напоминание, встреча-план, recurrence-rule). Проект заявлен как «агрегатор всей жизни» (CLAUDE.md) —
  календарь/расписание это ядровой сценарий, а не периферия. **БЛОКЕР** — заявленная ценность продукта
  не покрыта ни одним узлом.
- **[узел/ребро] Отношения между людьми** — есть `profile-ref` (ссылка на человека) и `same-as`/`owned-by`/
  `steward-of` (governance-рёбра M-G5), но нет обобщённого ребра «личные отношения» (семья/друг/коллега/
  контакт). `reports-to` занят под атрибуцию журнала агентов (коллизия #3 в SYNTHESIS-matrix), не годится.
  **БЛОКЕР** для «личного менеджмента» — CRM-функция жизни человека отсутствует как класс.
- **[узел] Pending/open-loop** — упомянут в `values/04-vitalnost/05-pending-open-loops`, не вошёл в
  `node-types.md` реестр домена 01. **ЖЕЛАТЕЛЬНО**.
- **[узел] Affect/эмоция** — FQ17 «5-plan-affekt» открыт, осознанно не решён; ни узла, ни поля.
  **ЖЕЛАТЕЛЬНО** (не забыт, но не закрыт — риск, что легко забудется при ADR).
- **[узел] Числовые/денежные метрики (бюджет, KPI, time-series)** — ни один пример в `growth.md` не
  протестировал сценарий «агрегация чисел» (только текст/note/событие/папка). Останется ли `cell` со
  свободным payload пригодным для запросов «сумма за месяц»? Не проверено. **ЖЕЛАТЕЛЬНО** проверить до ADR.
- **[узел] Черновики** — вероятно покрыто полем `committed` (bool) в общем паспорте — НЕ дыра, но нигде
  явно не подтверждено, что `committed=false` = «черновик». Пометка **МЕЛОЧЬ** — свести терминологию.

## 2. Поля паспорта — упущено для полноты

- **[поле] confidence / калибровка** — Ц-3 Доверие (`policy.md`) явно требует «confidence калибруется
  использованием», `values/03-doverie/02-calibration` — целое направление. В общем паспорте
  (`node-types.md`, строка 16) поля `confidence` НЕТ вообще — только `provenance`. **БЛОКЕР перед ADR**:
  Ц-3 останется декларацией без данных.
- **[поле] bitemporal valid-time/tx-time** — общий паспорт даёт только `created/updated` (один timestamp).
  Bitemporal явно назван «В2» и属 к `event.occurredAt`, но Ц-2 (`policy.md`) требует bitemporal ГЛОБАЛЬНО
  («различает тот же узел изменился vs другой вариант» — это не только для событий). `M-G1/README.md`
  перечисляет «bitemporal-колонки» ОТДЕЛЬНО от паспорт-колонок в разделе «какую память требует» — неясно,
  это часть общего паспорта или нет. **БЛОКЕР** — M-G1 сам называет bitemporal «заложить сейчас, ретрофит
  невозможен»; сейчас не ясно на каком node-type это в итоге будет полем.
- **[поле] temperature** — `values/04-vitalnost/03-forgetting-lifecycle` пишет «уже есть как temperature в
  паспорте», но в `node-types.md` общего паспорта такого поля нет. Расхождение между слоями документации.
  **ЖЕЛАТЕЛЬНО** свести перед ADR (иначе типовой коллизии дня прибавится ещё одна).
- **[поле] TTL/expiry** — `storageLevel: ephemeral` (M-G4) подразумевает истечение, но явного
  expiry-timestamp рядом нет. **МЕЛОЧЬ/желательно**.
- **[поле] язык payload** — RU/EN смесь (голосовые транскрипты, доки), нигде в паспорте не фиксируется.
  **МЕЛОЧЬ**.
- **[поле] origin vs effective (кто СЕЙЧАС ручается)** — `values/03-doverie/01-provenance` предлагает пару
  origin/effective; в реестре есть только `confirms` (origin→effective) для узкого случая «импорт≠человек»
  (FQ19), не для общего случая дрейфа ручательства. **ЖЕЛАТЕЛЬНО**.

## 3. Забвение / жизненный цикл — путь узла

- **[механизм] Два примитива забывания (soft sleep vs hard-erase, FQ7)** — детально проработаны в
  `values/07-soglasie/05-revocation-erasure`, но НЕ отражены ни в `node-types.md`, ни в `M-G1`, ни в `M-G4`,
  ни в `M-G5`. Путь узла «создание→жизнь→устаревание→забывание→hard-erase» нигде не описан на уровне
  движка/реестра — только на уровне ценностей (доклад владельцу). **БЛОКЕР** — FQ7 назван «самый острый
  конституционный конфликт», а инженерный слой его игнорирует.
- **[механизм] Гарантия невлияния в эмбеддингах/кэше/копиях при hard-erase** — M-G4 детально описывает
  материализацию (`live/cache/copy`) и инвалидацию, но НЕ упоминает hard-erase вообще: cache/copy
  инвалидируются по свежести (TTL), не по «стереть везде безусловно». **БЛОКЕР** при первом реальном
  стирании — право на забвение физически не реализуемо текущей схемой каскада.
- **[механизм] Судьба `canonicalId` при hard-erase** — tombstone vs полное освобождение id — открытый
  вопрос в values, не появляется в M-G5 (которая владеет `canonicalId`). **ЖЕЛАТЕЛЬНО** притянуть в M-G5.

## 4. Провенанс и версии

- Провенанс как общее поле паспорта присутствует (`provenance`), `wasDerivedFrom`-ребро описано —
  это выглядит решённым. Но `origin`/`effective` (см. §2) не обобщены за пределы FQ19-импорта.
- Версии решаются через `supersedes`-цепочку (bitemporal) — механизм есть, но нет способа дёшево
  спросить «diff между версией N и N-1» без полного bitemporal-прохода; названо в M-G1 как «read-time
  проекция», не проверено на реальном примере. **МЕЛОЧЬ** (архитектурно ок, не протестировано).

## 5. Ценности, требующие памяти, но не отражённые в типах/полях

- **Ц-3 Доверие** — confidence-поле отсутствует (см. §2, БЛОКЕР).
- **Ц-4 Витальность** — стадии lifecycle (nascent/active/cooling/cold) не в паспорте, только `salience`
  (число) + недокументированный `temperature`. **ЖЕЛАТЕЛЬНО** решить: явный enum-стадия или чистый
  континуум.
- **Ц-7 Согласие** — hard-erase/revocation полностью отсутствует в инженерном слое (см. §3, БЛОКЕР);
  consent-таint зарезервирован только как «слот на ребре», не на узле — а согласие часто про сам узел
  (кому видно ЭТО воспоминание), не только про производные рёбра.

## Что НЕ проблема (проверено, выглядит покрытым)
- Провенанс на уровне «откуда факт» — есть поле + ребро.
- Дедуп/canonicalId/слияние БД — детально закрыто в M-G5.
- Черновики — вероятно `committed=false`, но терминология не явная (мелочь).
