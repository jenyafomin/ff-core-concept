# Наблюдатель-MVP — адверсариал-чекпойнт вектора

> Единственный источник ВЕРДИКТА о честности гейтов и о том, что доказывает observer-MVP.
> `plan.md` и старый HANDOFF на него ССЫЛАЮТСЯ, не копируют. Форки, ждущие владельца — в `OWNER-QUEUE.md`.

## 0. Что произошло
По просьбе владельца «перепроверить весь вектор дополнительными линзами и сверить с ключевыми целями»
прогнаны две синхронные волны (метод рекурсивной оркестрации): 4 линзы на сам вектор (высота · адверсариал ·
сверка-с-целями · заземление-на-код), затем волна дизайна (F1 честный рефрейм · F2/F3 настоящие гейты) +
адверсариальная верификация ДРУГИМИ агентами (закон 5). Все находки заякорены в код (file:line).

## 1. Сходящийся вердикт 4 линз — вектор в ТЕКУЩЕМ тесте не фальсифицируется
Вектор «Единица носит свой закон» (Git для памяти) сам по себе может быть здоров, но выбранный гейт-фальсификатор
**беззуб** — он не может провалиться, значит доказывает не вектор, а то, что уже работало:

- **U4 (было ★G1)** — спрашивает движок про `readable_by`, который **уже** реализован как reserved-key
  ДО observer-MVP (`packages/engine/src/core/projection.ts:54,105-108`; READ-решение = плоский `||` двух
  allowlist, `core/resolve.ts:243`). Это **regression-тест существующей фичи на реальных данных**, НЕ
  доказательство вектора. Именно поэтому это «размер S» — механизм уже есть.
- **U5 (было ★G2)** — «перенос» между `store-memory`/`store-md` идёт через ОДИН чистый редьюсер
  `core/projection.project` (`adapters/store-durable-fs.ts:15-17`: «same code path, only the SOURCE differs»).
  Это **кросс-адаптерная сериализуемость ОДНОГО движка**, НЕ переносимость в ЧУЖОЙ движок (явно вне scope,
  `plan.md:34`). Вдобавок `store-md` — НЕ независимая вторая реализация `StorePort` (делегирует в `MemoryStore`);
  два по-настоящему независимых рельса = `store-memory` + `store-durable-fs`.
- **Сверка с целями (7 ценностей + «доверяемая композиция»):** нагружен только урезанный **V5**; **V2 тождество**,
  **V3 доверие**, **V7 согласие** (=ядро «доверяемой композиции») этим гейтом НЕ проверяются. V7-согласие = форма
  (enforcement=0, `test/consent-not-enforced.test.ts` — инвертированный триппер). ⇒ MVP приближает **оболочку**
  названной цели, не её ядро. Честно самоограничен — это плюс; риск в том, что «зелёный U4/U5» прочитают как
  «вектор подтверждён».
- **Заземление на код:** якоря плана ТОЧНЫ, размер S реален, 30 актов на диске реальны. `readable_by` в реальных
  данных = **0** (все узлы сегодня default-deny — честно). Один minor: `resolve.ts:242-243` — фактический
  default-deny `return` на ~256, не 243.

## 2. Что переименовано (честность на верхнем уровне)
- `G1` → **U4** «regression-тест существующей readable_by-фичи, НЕ доказательство вектора».
- `G2` → **U5** «кросс-адаптерная сериализуемость ОДНОГО движка, НЕ перенос в чужой движок».
- Слово «гейт-фальсификатор ... а не форму» уточнено: гейты фальсифицируют свою узкую грань (видимость /
  сериализуемость), не весь вектор.

## 3. Настоящие гейты с зубами — спроектированы и верифицированы (F2 + F3, дополняют друг друга)
Критик (закон 5) подтвердил: оба МОГУТ провалиться и атакуют РАЗНЫЕ, непересекающиеся половины «единица носит
свой закон». Рекомендация — **оба**.

> ✅ **ОБНОВЛЕНО 2026-09-06 — оба ПОСТРОЕНЫ** (владелец: «строй оба»), reviewer PASS (честные фальсификаторы,
> не тавтологии), полный сьют зелёный (153 passed), ядро/адаптеры/боевой `.data` не тронуты. **Честный итог:**
> **F3 зелёный ⇒ вектор ДЕРЖИТ на полу** (простой `readable_by`-закон переносим чужому читателю без кода движка);
> **F2 зелёный ⇒ вектор НЕ держит на потолке** (движок игнорирует composite `read_expr`, закон в коде `resolve.ts:243`).
> Файлы: `packages/engine/test/observer-read-expr-gate.test.ts`, `test/foreign-reader-gate.test.ts`,
> `test/_throwaway/{read-expr-oracle.ts,foreign-reader.mjs}`. Статусы форков — `OWNER-QUEUE` (Q-obs-F2/F3 = answered/built).

- **F2 «read-expr» (ось V3 — выразительность/консистентность закона).** Новое правило-как-данные, которого в
  движке НЕТ (grep `read_expr|acl_expr|all_of|any_of` = 0 hits): self-describing AST `{op:AND|OR|NOT, terms}`.
  Throwaway-оракул (в `test/_throwaway/`, выбрасываемый — НЕ постоянный 2-й путь чтения, иначе ломает Ц3)
  интерпретирует только `body.read_expr`, не импортит `resolve.ts`. RED: единица `AND(family, NOT estranged)`,
  viewer в обоих → оракул DENY, движок ALLOW (чтит плоский `readable_by`) ⇒ закон живёт в коде, не в данных.
  ⚠️ **Правка до внедрения (критик):** обоснование F2 было ЛОЖНЫМ — `policy:access-priority` аспирационен,
  нигде не читается (`resolve.ts:8` — только комментарий). Реальная асимметрия: у WRITE есть per-subject deny
  через capabilities, у READ — нет никакого per-viewer negation. Переформулировать обоснование на этот факт.
  Плюс коллизия имени — `f2-closure.test.ts` уже существует (не связан) → переименовать.
- **F3 «Тест Чужого Читателя» (ось V5 — переносимость закона через границу движка).** Читатель ВНЕ `@ff/engine`
  (jq/python, ноль импортов движка) знает ровно одну wire-конвенцию (имя ключа `readable_by`) + freshest-wins и
  обязан соблюсти policy. Единица — строго self-owned `census:2026-09-01:life-change-discipline`
  (`actor:owner`, без `referent`; НЕ брать `referent≠self` узлы — риск V7). RED: закон читается только через код
  движка ⇒ не «едет в единице». Критик: НЕ G2-lite (invariants.test.ts:275 даже слабее, чем думали — не
  ассертит `readable_by`). ⚠️ Честно: `readable_by` в реальных данных = 0 ⇒ тест опирается на ФАБРИКОВАННЫЙ
  supersede-акт (фальсифицирует гипотезу, не подтверждает практику).
