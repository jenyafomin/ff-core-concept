# Синтез 2026-07-12 — БРЕЙН многоуровневый (scopes) + идентичность пользователя

> Уточнение владельца (голос, 2026-07-12) в ответ на мою путаницу с «строкой Жени в БД».
> Здесь — его модель своими словами, приведённая к структуре. НЕ решение, а зафиксированная рамка.

## 1. Две развилки — как решил владелец

**«Несколько чатов»:**
- **Сейчас:** (a) несколько топиков **только для себя**, поверх разных групп/проектов — как уже работает.
- **Направление (обязательно развивать, но позже):** (b) несколько **людей/ботов** — это другая
  инфраструктура (роли, `IUser`, ADR access-roles). Не «быстрый вин», но курс туда обязателен.

**«Брейн»:** на самом деле **и (a), и (b)** — брейн по своей природе многоуровневый (см. §2).

## 2. Брейн = три scope (уровня видимости памяти)

Владелец описал память как минимум на трёх уровнях (ложится на уровни Конституции
Universal/Project/…):

| Scope | Что здесь живёт (слова владельца) | Пример |
|---|---|---|
| **Глобальный / пользователь** | «пользователь видит **свою** базу среди разных проектов»: его настройки, его логи, его сессии, его агенты. «Что-то — вне проекта». | одна «Я»-подложка, общая для всех проектов |
| **Проектный** | «открывая в проекте — у него это есть»; «что-то в самом проекте, указано в виде файлов / визардов / концептов». | память конкретного проекта FF / agents-manager |
| **Локальный / для пользователей** | «что-то может быть даже локально, то есть для пользователей». | приватная/локальная область пользователя |

**Поведение брейна:** ведёт **качественно, по документации** — создаёт её и, возможно, **реплицирует в
файл проекта**. То есть брейн не просто хранит — он курирует доки и зеркалит их в проект.

## 3. Идентичность («строка Жени») — как это снимается

Проблема, которую я плохо назвал: сейчас данные лежат в НЕСКОЛЬКИХ файлах-БД (общий `gateway.db` +
по-проектные). Вопрос был: «Женя» — это **одна общая запись** для всех проектов, или **отдельная копия
в каждом проекте** (которые могут разъезжаться)?

Ответ владельца из §2 фактически решает: **есть глобальная «Я»-подложка (одна), а проекты добавляют
свои проектные/локальные слои поверх.** → идентичность = **один глобальный узел пользователя +
проектные расширения**, а не копия-на-проект. (Стыкуется с FQ18 «мета-узел Самости» и FQ22 «профиль
+ каскад как CSS».)

## 4. Как это связано с адресацией концептов (уже проработано)
Три scope 1:1 ложатся на схему адресов: глобальный ↔ node-ID/alias (переживает переезд),
проектный ↔ полный путь `path`, кросс-проект ↔ `ref: <проект>:<путь>`. То есть многоуровневый брейн и
гибкая адресация — одна и та же идея с двух сторон.

## Открытые вопросы (в триаж)
- Границы записи между scope: что пишется глобально, что в проект, что локально — правило или движок?
- «Реплицировать в файл проекта» — когда зеркалим, а когда держим только в глобальной БД?
- Локальный «для пользователей» scope — это про мультипользователя (развилка b) или про приватность одного?
