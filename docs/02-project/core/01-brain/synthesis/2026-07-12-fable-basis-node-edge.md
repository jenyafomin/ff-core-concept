# Синтез 2026-07-12 — БАЗИС памяти (совет Fable): узел · связь · интерпретатор

> Первый заход Fable-советника (трек B, экономный). Диалог ОТКРЫТ (копит контекст). НЕ решение — сильный
> кандидат в ратификацию/ADR. Ждёт проверки владельцем + 3 деталей (см. низ файла).

## 1. Базис = 2 хранимых примитива + 1 интерпретатор. Третьего примитива НЕТ
- **Узел** («что есть») и **связь** («как относится») — всё, что ХРАНИТСЯ.
- **Папка-грань** — не новый примитив: папка = **узел особого типа** (`container`) + структурные рёбра
  `member-of`. Тогда «рёбра-над-папками» = обычные рёбра узел↔узел. Совпадает 1:1 с сущностью `Concept`
  у агентов (рекурсия/type/scope) — сильный сигнал правоты.
- **Оркестрация · поток · реактивность · память-как-процесс** — ОДНА категория: **интерпретатор поверх
  тех же двух таблиц**, не третья таблица. Канон это уже трижды решил (реактивность=слой 07-07; F6;
  propagation=движок). «Следующее измерение» = **время/процесс**, и оно заложено (bitemporal В2 + движок).
- Модель: **точка → линия → обход**. Третий примитив появится, только если возникнет «вещь, на которую надо
  СОСЛАТЬСЯ, но которая не выражается ни узлом, ни ребром». Пока таких нет.

## 2. Узел vs связь: критерий — АДРЕСУЕМОСТЬ → два класса хранения
**Критерий:** *нужно ли когда-либо указать НА само отношение* (оспорить, забыть, дать/отозвать согласие,
спросить «кто утверждает?»). Да → ребро = отдельная сущность с id+паспортом (на поле чужой записи не сослаться).
- **assertion-edge** (сущность + id + узкий паспорт + тип): инсайт «A caused B» (свой автор/провенанс/жизнь;
  forgetting-cascade стирает ЕГО, не трогая A/B; consent-taint течёт через него).
- **thin-ref** (поле узла, без паспорта, судьба = судьба узла): `home`, `facet-of` — навигация, никто не оспаривает.
> Это доведение В4 до правила: **одна концепция «связь», два класса хранения**.

## 3. Грани ребра: СЕЙЧАС / ПОЗЖЕ (retrofit-cost)
| Грань | Вердикт |
|---|---|
| **Тип ребра** (открытый реестр, малый seed) | 🔴 СЕЙЧАС (нетипизированные рёбра задним числом не растипизировать) |
| **Endpoint = canonicalId, НИКОГДА path** | 🔴 СЕЙЧАС (рёбра-по-путям умирают при реорганизации — суть «рёбер-над-папками») |
| **DAG-инвариант** на derived/cascade-рёбрах | 🔴 СЕЙЧАС (навесить DAG на циклический граф потом — невозможно) |
| Кросс-узловая семантика (паспорт на assertion-edge) | ✅ уже В4 |
| Реактивный триггер | 🟡 слот-поле СЕЙЧАС (декларативно), механика — read-time, ПОЗЖЕ |
| Поток (обход, flow-gated auto-close) | 🟢 ПОЗЖЕ — проекция обхода; auto-close ещё и обходит согласие (Ц-7) |
| Папка-как-узел | 🟢 ПОЗЖЕ, дёшево (подтип узла при canonicalId) |

- **Папка-оркестрация = узел особого типа** (НЕ слой scope: scope=«где живёт/кому видно», оркестрация=«как
  ведёт»; НЕ отдельная инфра-сущность). «Своё всё» = паспорт + policy-as-data на узле-контейнере.
- **Память-diff (§3.4) = НЕТ в эту сессию.** F6+ChangeTrace+В2 уже дают diff как запрос. Зафиксировать одну
  строку-инвариант: **«diff/снапшот-за-период = проекция над bitemporal, никогда не хранимая сущность»** + завести FQ.

## 4. Мост: 2 инварианта в ОБЕИХ системах
- **I-1. Единое пространство `canonicalId`** — всё адресуемое (узел, assertion-edge, Concept, Task, Plan) имеет
  глобально уникальный стабильный ID; ссылки по ID, не по путям (= их F10 + наша Ц-2). Ключ будущего слияния БД.
- **I-2. Поведение — данными, исполнение — движком** — тонкий паспорт + payload; всё «живое» (каскад, триггер,
  policy, паттерн петли) декларируется данными, исполняет сервис. Покрывает разом propagation/реактивность/F6/loop-as-data.
