# FQ4 · Зачем / почему возник

Источник: [`values/2026-07-05-L1-values-fable.md`](../../values/2026-07-05-L1-values-fable.md) §3
«Упущение 1», §5 FQ4.

L0 («волна и частица») заявил разделение: частица = что хранится (узел, тонкий паспорт), волна =
«зерно есть свойство ВЗГЛЯДА, не вещи» — но не дал волне механику. Fable (упущение 1) выдвинул
гипотезу: волна живёт в **линзе** — линзе, которая коллапсирует граф в грань под конкретный вопрос.
Если линза не сохраняется, «полисемия» (много ответов на разные вопросы) остаётся лозунгом: некому
хранить сами *вопросы/углы*, только их сиюминутные результаты. Отсюда — вопрос: должна ли линза
получить статус сохраняемой единицы.

Отягчающее обстоятельство: `portrait/cell-portrait-now.md` уже содержит зачаток — «линза-политика
(hard-ABAC/soft) — control-plane узел», то есть Opus/портрет уже дали линзе статус узла, но узкого,
служебного (кому какую грань раскрыть), а не «сохранённая точка зрения как содержательная память».
Путаница между «линза-как-политика-доступа» и «линза-как-точка-зрения-агрегатора-жизни» сама по
себе не была разведена — источник конфляции, на которую указывает независимая перепроверка
(2026-07-07, [checks/2026-07-07-recheck.md](checks/2026-07-07-recheck.md)): вопрос мог оказаться
**ложной развилкой/дублем** уже принятых FQ16 («Точка зрения» = план брейна) и FQ22 (узел-профиль),
а не самостоятельной новой единицей. Развилка «нужен ли FQ4 вообще» → зафиксирована в
[INDEX.md](INDEX.md), раздел 3 — ждёт владельца.
