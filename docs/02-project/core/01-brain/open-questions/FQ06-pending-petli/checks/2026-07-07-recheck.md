# FQ6 recheck — `pending`-петли

## ВЕРДИКТ: ОСПОРЕНО (уверенность ~70%)

Оспаривается не потребность (она реальна), а **рекомендация «склоняюсь да → спец-статус
`pending`, заложить сейчас»**. Правильная форма ответа — **производный ВИД над планом
Намерение (FQ16)**, а не поле/статус паспорта. Это НЕ death-by-design, ретрофит возможен.

---

## A. Формулировка — НЕ острая, наводящая, склеена

- «…— против «компакт-тревоги»?» — **встроенный ответ в вопрос**: рамка предполагает, что
  `pending` уже есть решение компакт-тревоги. Наводящая. Надо разделить БОЛЬ (не терять
  открытые намерения между сессиями) и МЕХАНИЗМ (спец-статус vs производный вид).
- Склеены два референта: «незакрытые **дела**» (у задач уже есть статус в слое задач) и
  «незакрытые **вопросы/намерения**» (это план Намерение). Разные дома — разный ответ.
- «Петля» не определена: узел? ребро? вид? По L0 память — РОЛЬ, «волна = свойство взгляда».
  Открытость петли по природе — свойство ВИДА (рёбер), не частицы. Вопрос это не ловит.

## B. Стилман «склоняюсь да» — ОПРОВЕРГНУТ

1. **Противоречит ядру L0/ADR-0002:** «0 новых обязательных полей паспорта». `pending` как
   поле/статус паспорта ломает ратифицированный тонкий паспорт.
2. **Выводимо из графа:** «петля открыта» = существует узел-намерение, на который НЕ указывает
   ребро `answers/closes`. Это ЗАПРОС (волна/access plane), а не хранимый флаг. Вычислимо
   в любой момент → вид, не поле.
3. **Дублирует FQ16:** план **Намерение** уже даёт намерениям дом. `pending` поверх плана —
   ретрофит на уже существующую структуру.
4. **Боль уже адресована:** компакт-тревога — заявленная МОТИВАЦИЯ всего L0 («контракт
   повторного входа», Найти/push, снапшот FQ12, метаболизм). Решение на неверном слое.
5. **НЕ death-by-design (ключевое отличие от FQ7):** открытость всегда пересчитываема из рёбер
   задним числом. Необратимости нет → «заложить сейчас» не обосновано.
   Единственный элемент «сейчас» — *захват намерения как узла* — это **FQ16 (✅), не FQ6**.

Скрытые допущения: (а) петля бинарна open/closed — реально есть brошено/отложено/заблокировано/
частично; флаг это прячет; (б) `pending` принадлежит памяти, а не runtime сессии агента —
компакт-тревога может быть runtime-состоянием, не гранью паспорта; (в) «боль владельца ⇒ поле»
— классический скачок, который критик обязан пометить.

## C. Триаж «спорно» — мис-триаж по срочности

Лейбл ⚠️ «копнуть» уместен. Но FQ6 стоит в **Гр.4 «заложить сейчас»** рядом с FQ7/критично —
это завышает срочность: ретрофит возможен, death-by-design нет. Направление рекомендации
(«да → спец-статус») сомнительно. После рефрейма схлопывается к варианту B (без спец-статуса) +
зависимость от FQ16 → ближе к ✅, чем к живой развилке.

## D. Анатомия vs FQ7 — ДЕФЕКТ

FQ6 = только `INDEX.md`. Канон папки (см. open-questions/INDEX.md): «Спорный (⚠️) → добавляются
`zachem/overview/rekomendaciya`; эталон FQ7». FQ6 помечен ⚠️ → `zachem.md` и `overview.md`
**обязательны и отсутствуют**. «Зачем» = одна строка, «Рекомендация» = «Склоняюсь к да» без
разбора. Ниже стандарта FQ7. Дефект.

## E. Связи — ОТСУТСТВУЮТ (сам по себе смелл)

В INDEX нет ссылок на: **FQ16 Намерение** (определяющий дом ответа), **FQ12 снапшот-в-момент**
(тоже про компакт/аудит, пересечение), **FQ17 Аффект/значимость** (salience решает, КАКИЕ петли
всплывают push/«запах»; pending без salience = каждая петля кричит), **L0 контракт повторного
входа**, ценности (В1 Читаемость / В4 Витальность фаз видимости). Изоляция FQ6 — причина, по
которой он выглядит дубликатом: он не ссылается на планы, что его уже покрывают.

## Правки (1-5)

1. **Рефрейм вопроса:** отделить боль (не терять открытые намерения между сессиями) от
   механизма (спец-статус vs производный вид). Убрать наводящее «против компакт-тревоги».
2. **Добавить вариант C в overview:** `pending` = **производный ВИД** (запрос над планом
   Намерение: узел-намерение без ребра `answers/closes`), НЕ поле паспорта. Сохраняет тонкий
   паспорт (0 новых полей). Вероятный ответ.
3. **Создать `zachem.md` + `overview.md`** (обязательны для ⚠️ по канону папки; сейчас дефект).
4. **Ре-триаж:** вынести из «заложить сейчас/критично» — ретрофит возможен, не death-by-design.
   Единственный «сейчас»-элемент — захват намерения — уже закрыт FQ16.
5. **Проставить связи:** FQ16 (дом), FQ12 (снапшот), FQ17 (salience/push), L0 (реэнтри), В1/В4.

## Развилка владельцу

**Спец-поле/статус `pending` в паспорте** (нарушает тонкий паспорт «0 полей», дублирует план
Намерение FQ16, но «состояние» явно на узле) **VS** **производный вид над планом Намерение +
всплытие через salience (FQ17)** (0 новых полей, ретрофит возможен, петля живёт в рёбрах/виде).
→ Рекомендую второе.

## Под-вопрос (нужно для разрешения)

Где живёт «петля» — узел, ребро или вид? И где кончается ПАМЯТЬ и начинается **runtime-состояние
сессии агента**: компакт-тревога — это грань паспорта памяти или состояние рантайма? От этого
зависит, принадлежит ли `pending` брейну вообще.
