# FQ11 — Закон композиции политик

## 1. Вопрос
Два уровня, ранее слитые в один вопрос — теперь разделены явно:
- **(а) Нужен ли движку единый арбитр композиции политик** (когда две ячейки говорят разное про
  один и тот же факт)? — ✅ решено.
- **(б) Что именно говорит этот закон в конкретных случаях** (кто побеждает и почему, по каким
  осям политики — retention/видимость/право на изменение)? — открыто, см. [overview.md](overview.md).

Смешение (а) и (б) в одной галочке ✅ — источник путаницы прошлой версии этого файла (см.
[checks/2026-07-07-recheck.md](checks/2026-07-07-recheck.md), раздел A).

## 2. Рекомендация
**(а) ДА** — движок обязан нести единый арбитр композиции. Альтернатива «каждая ячейка решает
ad hoc» отвергается тем же аргументом, что и в FQ3 (тихий откат к движку-командиру,
непредсказуемое поведение при первом же конфликте).

**(б) НЕ РЕШЕНО.** Единственный найденный конкретный случай — конституционный инвариант из FQ7:
согласие референта нельзя переопределить политикой владельца. Это не универсальный закон, а одна
частная норма. Для конфликта «владелец-A политика vs владелец-B политика» без референта — правила
нет вообще. 2-3 кандидата на общий алгоритм — [overview.md](overview.md); выбор — за
owner/system-architect на этапе engine-spec, здесь фиксируются только варианты.

## Возражения (стилман, из recheck §B)
- **«Композиция — деталь реализации, не столп?»** Частично верно: сам факт «нужен арбитр» —
  архитектурное решение (без него первый конфликт решается ad hoc в движке). Но конкретный алгоритм
  композиции — действительно деталь реализации, которая раньше выдавалась за уже решённую.
- **«Неразрешимые конфликты политик — какое правило?»** Не описано ни одного общего случая. FQ7
  даёт ровно один частный: референт побеждает владельца. Для owner-A vs owner-B общего факта без
  референта — правила нет.
- **Скрытое допущение:** что универсальный закон вообще ФОРМУЛИРУЕМ как единое правило. Возможно,
  разные оси политики требуют разных правил (иерархия, не единый закон) — это тоже кандидат в
  overview.md, а не факт.
