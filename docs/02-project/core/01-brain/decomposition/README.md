# 🗺️ ДЕКОМПОЗИЦИЯ — картина того, что сказал владелец (2026-07-14)

> Это НЕ сессия и НЕ организация — это **топикальный разбор** большого голосового сброса, разложенный
> по темам, «как я это понимаю». Владелец: сначала увидеть КАРТИНУ-концепт → потом из неё запускать
> потоки агентов, которые каждую тему улучшают/апгрейдят.
>
> Дословные слова владельца (источник) — по частям P0–P13 в
> `docs/01-organization/session-handoff/2026-07-14-vector-and-defektovka/00-RAW-owner-input.md`.
> Каждая карточка ниже помечена ← P#, откуда взята.

## Как читать
- **3 группы** (по чёткому разделению доков): модель · стек · метод.
- **Каждая тема = карточка** по единой схеме: *что хранит · зачем (для кого) · где ляжет в канон ·
  открыто · связи · какой поток агентов её берёт.*
- Тема разрастётся → карточка станет папкой (правило роста session-logging).
- Картину целиком видно через `PICTURE.concept.json` (визор).

## Сквозной режим
**«Сломать концепт»** (P12) — не тема, а РЕЖИМ для группы 01-model: каждый поток агентов по теме модели
идёт с критиком/советом, чья задача — refute, а не согласиться.

## Ключевой сдвиг порядка (зафиксирован)
Владелец переоткрыл: **сначала форма модели → потом БД** (БД «не принципиальна»: критерий = Docker +
переносимость + GraphQL-fit). Это меняет прежний вектор «решить БД → строить». Форма модели ДИКТУЕТ стек.

## Следующий шаг
Владелец смотрит эту картину (концепт) → правит понимание/границы тем → **после этого** запускаем потоки
агентов (по одному на тему группы 01-model, каждый с критиком), которые наполняют карточки в глубину.
