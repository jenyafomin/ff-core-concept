# ❓ Дом вопросов — свести разбросанное в один порядок

> Боль владельца: **вопросы в разных местах**. Здесь — где они живут и как вопрос из `concept.json`
> кристаллизуется в файл-документ. Граница: тип ВОПРОСА (concept.json) = `concept-first`; тип ФАЙЛА
> при кристаллизации = `doc-discipline`. Один слой — один хозяин, маппим одно в другое.

## Где вопросы разбросаны СЕЙЧАС (инвентаризация)
| Место | Что там | Проблема |
|---|---|---|
| `open-questions/FQ01-24/` | 24 модельных вопроса (по ценностям), с `checks/` | оторваны от единицы, к которой относятся |
| `unit/_critique.md`, `unit/analyses/` | критика/разборы конкретной единицы | живут только у Вещи |
| `unit/FABLE-BRIEF-*`, `FABLE-ANSWER-*` | развилки на подпись Fable | смешаны с телом единицы |
| `*/concept.json` (`questions[]`) | рантайм-навигатор витков | эфемерно, легко разъезжается с файлами |

## Два типа вопроса — не путать
- **Рантайм-вопрос** — живёт в `concept.json` направления, тип `open-question/analysis/risk/verification`.
  Дешёвый, подвижный, ведёт виток. Отвеченный не удаляется → `answered` + ссылка.
- **Кристаллизованный вопрос** — дорос до документа: тип файла `question/gaps/analysis/decisions`.
  Постоянный дом = его механизм/единица.

## Правило кристаллизации (маппинг concept → файл)
```
concept.json.type   →   файл на диске (doc-discipline)
open-question        →   <единица>/questions/NN-<slug>.question.md
analysis             →   <единица>/<узел>/analysis-*.md
risk                 →   <единица>/questions/NN-<slug>.question.md (тег risk) или _critique.md
verification         →   критерий в README «Критерии готовности» / плане
```

## Развилка дома (Q-3) — где физически лежит вопрос
- **A · Централь** — один `01-model/questions/` (как нынешний `open-questions/`) для ВСЕЙ модели.
  + одно место; − вопрос оторван от единицы.
- **B · Со-размещение + подъём** — вопрос живёт в `<единица>/questions/`; сквозной (≥2 единиц)
  поднимается в центральный `questions/`. + рядом с предметом; − нужен дисциплинированный подъём.
- **Рекомендация: B** — зеркалит правило подъёма в `infrastructure/` (единый принцип «дом рядом,
  сквозное — вверх»). `open-questions/FQ*` тогда = центральный слой сквозных модельных вопросов.
