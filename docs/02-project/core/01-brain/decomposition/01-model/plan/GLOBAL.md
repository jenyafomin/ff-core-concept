# 🌍 GLOBAL — ключевые планы + горизонты

## Тезис фазы
Готового много и хорошего. Единственное, что нас отличит, — **скорость правильными шагами**.
**Строить, не переделывать.** Переделка/переосмысление = испорченный контекст = потеря информации.

## Поэтапный путь к постройке (крупные шаги)
1. **Структура-дерево** (идёт) — чистое, самонавигируемое дерево модели; каркас `_shared`+`plan` стоит.
2. **Миграция контента** — перенести знание в дерево один раз (unit→01-node, карты→README, deepening→README).
3. **Passport-контракт** (`_shared/passport/`) — общий, разблокирует edge/act/lens.
4. **Углубление примитивов** — Акт → Связь → Проекция (делегирование fable-orchestrator).
5. **Cross-cutting механизмы** (`_shared/mechanisms/`) — propagation · hard-erase · dedup · snapshot.
6. **Дизайн-очередь** — D-7 разводящее правило + hard-erase кластер (см. `design-queue.md`).
7. **Engine-spec → ТЗ** — движок (Postgres, DL-21, Temporal-lite) → техзадание → build-репо `TOOLS/` (DL-16).

## Процесс качества (постоянный)
Перепроверки · доп. взгляды (критик/совет) · доработка деталями документации · подготовка к ТЗ ·
придумывание инфра-механизмов. Масштаб глубины — под сложность задачи.

## 🔭 Горизонты (захват идей владельца — НЕ трогаем сейчас, чтобы зафиксировать)
- **Интеграции** — внешние источники/инструменты как акторы+словарь (plug-in API = поверхность актов).
- **Plug-in / Marketplace (ключевая идея):** клиент, подключаясь к базе, **строит приложение С ПОМОЩЬЮ неё**
  (данные общего поля, у данных есть владельцы; продовая база показывается не всем — для marketplace).
- **Монетизация:** участники **хостят marketplace-продукты/плагины**; оплата за использование или подписка
  (деньги за онлайн-использование плагинов). Полностью офлайн «всё» не выйдет — онлайн-слой обязателен.
- Связь с существующим: `VISION-SIMPLE` (plug-in заложен с 1-й итерации), `Combination`-концепт (marketplace-модель).

> Горизонты — это НЕ текущие задачи. Они здесь, чтобы идея не потерялась и легла в правильное место позже.
