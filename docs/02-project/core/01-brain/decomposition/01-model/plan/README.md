# 📋 plan — планирование как дерево

> Планы и задачи — тоже дерево, раскладывается в себя. Контекст указывается на любом уровне.
> Цель слоя: держать «что нужно сделать, поэтапно» так, чтобы агент шёл по шагам, а не искал.

## Уровни (дерево раскладывается в себя)
```
GLOBAL (ключевые планы на проект)
└── MODULE-план (у каждого примитива/механизма — свой, в его папке: <дом>/plan/ или в GLOBAL)
    └── ЗАДАЧА (плановый пункт)
        └── ПОД-ЗАДАЧА / чек-лист
            └── (контекст: ссылки на узлы/файлы, которые смотреть)
```
- Узел дерева = **план** ИЛИ **задача** (одно перетекает в другое по мере детализации).
- На каждом узле можно указать **контекст** (что читать) и **статус**.
- Ключевые планы на проект живут ГЛОБАЛЬНО (`GLOBAL.md`); детальные — в доме своего модуля.

## Процесс качества (как взаимодействуем, чтобы уровень держать)
Не «написал и всё» — цикл: **перепроверка · дополнительные взгляды (критик/совет) · доработка
документации деталями · подготовка к ТЗ (техзаданию) · придумывание инфра-механизмов**. Дорогие
развилки — через `fable-advisor`/`ask-council`; глубина масштабируется под сложность.

## Где что
- `GLOBAL.md` — ключевые планы + горизонты (включая marketplace/монетизацию).
- `design-queue.md` — что уходит в дизайн ПРЯМО сейчас (D-7, hard-erase).
- Текущие прямые задачи (живой список) — `../NAV.concept.json` (`thinking.current_direct_tasks`).
