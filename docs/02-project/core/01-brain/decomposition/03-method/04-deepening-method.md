# 🧭 Метод углубления единицы — повторяемый шаблон + 2 режима

> Обобщение того, что сделано в `unit/`. Одна единица углубляется одним способом → вторая единица
> и вторая итерация ложатся в тот же дом без изобретения структуры заново.

## Скелет папки единицы
```
0N-<единица>/
├── README.md          # описание (бывшая «карта-тема»)
├── TREE.md            # структура единицы (только папки)
├── 0M-<тугой-узел>/   # нумерованные узлы: разбор = вердикт+веер+развилки
├── questions/         # БЕЗ номера — дом вопросов единицы (общий формат)
└── critique/          # БЕЗ номера — 01-critique.md · 02-critique.md … (номер ВНУТРИ)
```
Номер = порядок (примитив/узел); без номера = сквозной формат (`questions`, `critique`) — закон дерева (`TREE.md`).

## ⭐ Два режима наполнения ЛЮБОЙ папки (правило владельца)
Каждый раз, когда углубляемся в новую папку — выбираем режим:

- **Режим S · «структура сразу»** — устройство ИЗВЕСТНО → определяем нумерованные под-папки
  (`01-… 02-…`) и пишем прямо в них. Быстро, когда путь ясен.
- **Режим T · «темами»** — устройство НЕизвестно → пишем разведкой: `тема-1.md · тема-2.md ·
  analysis/…` (стейджинг, без номеров) → потом **СБОРКА**: анализы кристаллизуются в нумерованный
  скелет; сквозное → в общий `analysis/` единицы или прямо в узел.

> Правило по умолчанию: **не знаешь дом → режим T** (стейджинг), затем сборка. Знаешь → режим S.
> Это ровно `doc-discipline`: топик-стейджинг → кристаллизация в механизм. Предложить внести в скилл-дерево.

## Конвенция critique/
- Папка `critique/` (без номера) в любой единице/узле.
- Внутри — нумерованные проходы: `01-critique.md`, `02-critique.md`, … (порядок = когда прогнали).
- Каждый файл в шапке называет **относительно ЧЕГО** критика (какой узел/решение) и какой призмой.

## 6 шагов углубления (цикл)
1. Назвать единицу одной фразой (чем отличается от 3 других кубиков).
2. Вскрыть тугие узлы (3-5 швов с развилками).
3. Расхождение — веер вариантов, ничего не режем.
4. Схождение — критик отклоняет; отклонённое остаётся с пометкой «почему» (в `critique/`).
5. Проверка 7 ценностей — деградация грани = дефект.
6. Подъём сквозного — ≥2 единиц/ценностей → `../../infrastructure/`; вопрос → `questions/`.

## Закон роста дерева (как система развивается)
- **Новый примитив** → новая нумерованная папка `0N-<единица>/` по скелету. (Сейчас 4 кубика; 5-й = осознанное решение.)
- **Новый сквозной аспект/формат** → папка БЕЗ номера рядом (`policy-as-data`, `layers`, `questions`).
- **Глубже внутри единицы** → новый нумерованный узел `0M-*` (режим S) или стейджинг-темы (режим T).
- **Дерево — ОДИН вид:** дубли карта↔папка запрещены (правило 1 закона дерева). Карта = README дома.

## Форма ответа агента (делегирование)
**вердикт + веер вариантов + топ-развилки, без сырья.** Глубокий разбор — параллельным
`fable-orchestrator` (по узлу на агента), диспетчер сводит вердикты; сырьё к диспетчеру не тянется.
