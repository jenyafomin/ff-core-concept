# 📁 Схема на сущность  ← P2

## Что это
Правило документирования: каждая сущность (узел / ребро / грань / тип) записывается **по отдельности**,
имеет **свою схему** (что представляет, что хранит, зачем), желательно **в своей папке** — т.к. вокруг
копится много анализа, связей, вопросов. Прогноз: папки будут расширяться.

## Предлагаемый инвариант
`SCHEMA.md` в каждой папке-сущности: *назначение · что хранит (поля) · зачем/для кого (агент/пользователь/
понимание) · инварианты · связи · открытые вопросы.* Тема разрослась → карточка-файл становится папкой.

## Зачем (для кого)
Единый формат, на который лягут все потоки агентов по группе 01-model; агент точно знает, куда писать.

## Где ляжет в канон
Конвенция документации (метод); шаблон — рядом с этой картой и в `domains/`.

## Открыто
- Единый шаблон `SCHEMA.md` (поля) — утвердить.
- Как `SCHEMA.md` соотносится с `.concept.json` (машиночитаемая проекция).
