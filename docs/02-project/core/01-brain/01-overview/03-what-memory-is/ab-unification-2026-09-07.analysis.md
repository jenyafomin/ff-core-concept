# Объединение A⊕B — синтез обсуждения (3 линзы + помощник, 2026-09-07)

## Вердикт: A и B — НЕ развилка, они одно
Владелец захотел объединить двери A (память = уже существующий субстрат) и B (новый слой «GitHub-над-всем»).
Волна независимо сошлась: **объединение = наш существующий вектор «единица носит свой закон» = Ц5 Суверенность
в продуктовой форме.** B — это ИМЯ аспирации, уже заложенной в A (V5+V6), а не второй слой. Значит правильный
ход — не выбирать A/B, а **ратифицировать рефрейм** (кандидат в ADR по Q-obs-vector).

## Несущий фрейм (важно — НЕ «GitHub для данных»)
«GitHub для данных» — метафора, которая тащит boil-the-ocean. Чистый фрейм:
> **Само-версионирующийся граф типизированных само-описываемых ЕДИНИЦ; движок = тонкая проекция;
> git — ОДНО из зеркал/проекций (того же ранга, что «грязный файловый слой»), а НЕ источник модели.**
Паттерн (ветвимое знание vs одно-версионная запись) = **policy-as-data на ТИПЕ** (M-G3), не отдельная подсистема.

## Что уже есть vs реальный гэп (маппинг архитектора)
| Из видения | Статус | Опора |
|---|---|---|
| «коммит» единицы | ✅ есть | `domain_event`-акт в append-only логе (ADR-0008; `projection.ts`) |
| «версия» единицы | ✅ есть (линейно) | `state.version` = глубина цепи, freshest-wins per `source_ref` |
| единица носит schema+паттерн как данные | 🟡 спроектировано | `meta:type` + policy-as-data (M-G3) |
| разные паттерны (ветвимое vs одно-версионное) | 🟡 спроектировано | `temporal: uni\|bi` опт-ин на тип (ADR-0006) |
| указатель на внешний файл/git | 🟡/❌ | file=placement (ADR-0006); remote-VCS-ссылка как объект — нет |
| ВЕТКА как объект | ❌ дизайн | `variant-of`-ребро + `source_ref`-линия + active-branch lens (retrofit-ДЁШЕВО) |
| MERGE-семантика | ❌ нет | act-kind дёшев на write; сам алгоритм «глубже git» — ПОТОМ |
| модуль/плагин-под-тип | 🟢 позже-дёшево | 3 plugin-порта (M-G3) |

**Retrofit-невозможного НОВОГО видение не добавляет** — конверт акта, `canonical_id`, registry-as-nodes уже заморожены.

## Сложность приручается ТОЛЬКО при трёх условиях (иначе прячется, не снижается)
1. **Малый ЗАКРЫТЫЙ словарь паттернов** (как closed-core `edge_type`), не «поддержать всё».
2. **НЕ строить git-инструмент merge/branch сейчас** — движок остаётся тонким, различие живёт в policy-данных типа.
3. **Единица носит паттерн как ДАННЫЕ на ТИПЕ**, а не «ветка/чат навязывает паттерн».

## Guardrail (критик): это BOIL-THE-OCEAN, если строить целиком
Видение тихо просит 5 отдельных продуктов разом: git-ветки/merge · БД-grade схемы · плагин-платформа ·
git-remote-зеркало · consent-as-data движок. Внутреннее противоречие самого видения: п.3 «не делать работу git»
vs п.7 «merge глубже git» = буквально работа git. **Не строить всё сразу.**

## Якорь-реальность (не обольщаться)
Гейты 2026-09-04: закон-в-данных **держит на ПОЛУ** (flat `readable_by`, F3 зелёный), **ломается на ПОТОЛКЕ**
(composite `read_expr` игнорится движком, F2; enforcement согласия=0; V1 не решена). Объединённое видение = ровно
ПОТОЛОК. ⇒ путь = **доказать ХРЕБЕТ дёшево**, не строить собор.

## Минимальный срез, доказывающий объединение (архитектор, в стиле F2/F3)
Два `meta:type`-узла через ОДИН путь движка (`write→meta:type→admit`, та же `projection.foldInto`, тот же read-time policy):
- **`plan-week`** — policy `pattern: branchable` → якорь + 2 варианта (`variant-of`) + active-branch lens; оба сосуществуют.
- **`client`** — policy `pattern: single-version` → попытка форка ОТКЛОНЕНА движком по policy САМОГО ТИПА; только supersede-линия.
Различие живёт ЦЕЛИКОМ в двух policy-узлах, **ноль веток в коде движка**. Прямое расширение kernel add-type теста.

## Открытые форки → OWNER-QUEUE (дом решений)
- **Q-obs-vector** — теперь: ратифицировать РЕФРЕЙМ (A⊕B = единица-носитель-паттерна, git=зеркало) как кандидат в ADR.
  Текст ADR ОБЯЗАН честно фиксировать «форма есть, enforcement=0» — иначе повторим ошибку, что поймал чекпойнт.
- **Q-crossbranch-consent** (НОВЫЙ, из волны) — при «N веток = одна память» чьё `visibility`/`referent`-согласие
  действует при пересечении веток: исходное или per-branch? Потолок 07.C (referent неоверрайдабельна) на межветочный случай.
- **read_expr-примитив** (Q-obs-F2) — если хотим закон-в-данных на ПОТОЛКЕ (composite ACL), это тот примитив; иначе потолок остаётся в коде.
