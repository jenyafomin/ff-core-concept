# Вопрос: чьё согласие действует при «N веток = одна память»?

## Суть
Видение владельца «5 веток = одна память» (owner-vision п.4, 9). При пересечении/слиянии (merge) веток
чьё `visibility`/`referent`-согласие главенствует — **исходное** согласие единицы или **независимое
per-branch**? Расширяет напряжение F4 (владелец чата/ветки НЕ переопределяет согласие референта, потолок
Ц7 07.C) на межветочный и merge-случай.

## Варианты (без вердикта, цена у каждого)
- **согласие едет с единицей поверх веток** (исходное всегда) — безопаснее для Ц7, но жёстче.
- **per-branch независимое** — гибче, но риск утечки согласия при merge.
- **гибрид** — референт-потолок неоверрайдабелен (Ц7 07.C), остальное per-branch.

## Рычаг
Блокирует дизайн merge-семантики (F2-меню) и «чат = зона доступа» (F4); без ответа merge может утечь согласие.

## Тип
🔴 Односторонняя дверь — утечка согласия при первом реальном merge необратима.
