# 🗺️ ДОМЕНЫ brain — как хранятся данные (вход)

> Заведено 2026-07-12 под следующую сессию. **Домен = крупная область данных со своим способом хранения.**
> На графе-субстрате (узлы+рёбра+реестры типов) домен = набор `node-type`/`edge-type` + policy-as-data.

## 🎯 Цель следующей сессии
**Агентная система как АРХИТЕКТУРА, живущая В БД.** Все архитектурные решения вращаются вокруг сущности
«база данных» и наоборот. Fable — координирует и явно подсказывает. Настройки системы: **глобальные (все
проекты) ↔ под конкретный проект**; модуль планов (позже, взаимодействует с БД и агентами); кросс-связь
многих модулей; **локальное ↔ глобальное** знание. Итог — не идеи, а **готовые механизмы**.

## 🔀 Метод двух направлений (владелец 2026-07-12)
1. **От ДАННЫХ:** описываем домены (как хранятся) → инфра-модули «ложатся» на данные.
2. **От МОДУЛЕЙ:** явно описываем инфра-модули → выводим, какая память им нужна.
3. **Комбинируем оба** → реальные готовые механизмы. Большую часть механизмов пишем как инфраструктурные;
   уже пронумерованные — в отдельный модуль-реестр; остальное = идеи (уже есть в `values/*/`, `infrastructure/`).
