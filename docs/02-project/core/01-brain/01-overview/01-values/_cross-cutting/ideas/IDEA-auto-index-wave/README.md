# IDEA · Авто-индекс / домен-как-волна

> Статус: draft · Дата: 2026-07-08 · Родитель: [../../README.md](../../README.md)

## Суть

Домены и индексы над графом узлов не назначаются вручную (пользователь не тегирует "это —
проект X", "это — здоровье") и не жёстко зашиваются в схему заранее. Вместо этого они
**собираются автоматически, как волна или запах распространяется по дереву связей**: узел
попадает в домен не потому, что кто-то его туда положил, а потому что его связи/содержимое
резонируют с существующим кластером — домен возникает как ЛИНЗА, проекция графа под неким
углом, а не как контейнер, в который что-то физически кладут.

Ключевое отличие от обычной кластеризации/тегирования: волна распространяется по РЁБРАМ
("рёбра проводят поток" — уже зафиксировано как грань хребта), затухая с "расстоянием" —
похоже на активацию в нейросети или диффузию запаха, а не на SQL-запрос с фильтром. Один и тот
же узел может резонировать с несколькими доменами одновременно (не эксклюзивная
принадлежность), и сила резонанса — это динамическая, а не статическая метка.

## Какие ценности задевает

- **Ц1 Читаемость** — риск: если домен "собрался сам", пользователь может не понимать, ПОЧЕМУ
  узел в этом домене → волна обязана оставлять прослеживаемый след (см. отклонённый кандидат
  К-4 Объяснимость — это требование, а не отдельная ценность, встраивается сюда).
- **Ц3 Доверие** — автоматическая категоризация без объяснения снижает доверие к системе;
  волна должна быть воспроизводимой/детерминированной или явно помечена как вероятностная.
- **Ц6 Реляционность** — прямое попадание: сама механика волны — это буквально работа со
  связями/рёбрами графа, реляционность как ценность здесь и есть механизм волны.
- **Ц7 Согласие** — если волна "затягивает" узел в чужой домен (например, приватную запись —
  в общий проектный домен), это конфликтует с согласием референта; волна не должна
  пересекать границы согласия автоматически.
- **Инвариант движка (К-2, масштаб)** — волна по всему графу на каждый новый узел — потенциально
  дорогая операция; должна быть инкрементальной/ленивой, иначе не переживёт рост объёма.

## Открытые вопросы

- Детерминированная волна (стабильный алгоритм) vs агентная (LLM решает резонанс) — разная
  цена, разная предсказуемость, разное доверие.
- Как хранить результат волны: материализованный индекс (кэш, пересчитывается) vs
  вычисляется on-the-fly при каждом запросе? Пересекается с Ц5 "материализация live/кэш/копия".
- Порог/затухание волны — где остановиться, чтобы домен не "расползся" на весь граф.
