## Суть

Объект суверенности здесь — **ПОВЕДЕНИЕ**. Правила обращения с ячейкой (кто может читать, когда забывать,
как считать salience, как сжимать) записаны ВНУТРИ ячейки **как данные**, а не выведены в код движка.
Движок при переносе не «интерпретирует по-своему» — он **исполняет** политику ячейки, запрашивая у неё
примитивы. Это ядро суверенности: баг/замена движка не должны менять смысл памяти.

## Границы

- **Входит:** `policy`-блок в паспорте (правила как параметры/формула, не ссылка на код); что именно
  политика описывает (доступ · забывание/фазы фокуса · salience · сжатие/rollup); формат политики
  (декларативные правила vs выражения); наследование политики от шаблона (Г32) с правом override.
- **НЕ входит:** КТО автор политики и метка источника → `05 ownership-keys`; ЧЕМ ограничена политика
  сверху (согласие референта, единый порог) → `06 constitutional-ceiling`; форма самой ячейки → `01`.
- **Тонкая граница с 06:** здесь — «ячейка САМА задаёт свои правила»; в 06 — «каких правил ячейка задать
  НЕ вправе». policy-as-data без потолка (06) превращается в лазейку — грани парные.

## Развилки (веер «как», не режем)

1. **Выразительность политики.** Фиксированный набор параметров (TTL, visibility-фазы, salience-веса)
   [+ просто, быстро на масштабе / − не покрывает экзотику] vs декларативные правила (условие→эффект)
   [+ гибко / − нужен вычислитель] vs встроенные выражения/мини-DSL [+ мощно / − риск, дорого, аудит].
2. **Кто исполняет политику.** Движок читает параметры и делает сам [+ контроль, оптимизация / − движок
   должен знать все виды правил] vs ячейка «запрашивает примитивы» у среды услуг (Fable) [+ чистая
   суверенность / − оверхед на каждый доступ] vs гибрид: типовое — движок, особое — запрос-примитив.
3. **Наследование vs автономность.** Политика по умолчанию от системного шаблона, override владельцем
   (Г32) [+ дедуп, разумный дефолт / − «чья воля» размыта → тянет метку из 05] vs каждая ячейка полностью
   своя [+ явно / − дубль, тяжело менять массово].
4. **Кто уважает политику на ЧТЕНИИ.** Только хранилище проверяет доступ [− линза/авто-индекс обходит
   сбоку, «зомби-память»] vs **линза-исполнитель**: любой путь извлечения (pull/push/волна) обязан
   уважать `policy`-блок затронутой частицы [+ единый порог / − нужен PEP на read-plane] — тема B.
5. **Масштаб исполнения (тема C).** Индивидуальная интерпретация каждой ячейки [− узкое место на
   миллионах] vs **fast-lane/slow-lane**: 95% на системном default-policy идут batch-путём, 5% кастомных
   — медленным [+ скорость + суверенность / − две ветки] vs компиляция политик в общий индекс.
