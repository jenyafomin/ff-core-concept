## Суть

Значимость единицы — не застывший тег, а **живое число**: падает, если единицу не используют,
поднимается при обращении/подтверждении. Формула на манер Generative Agents × W-TinyLFU
(recency + importance + use_freq, каждая своим темпом). Объект защиты — **честность и настраиваемость
самого веса**, до того как он превратится в решение «показать/скрыть» (это уже направление 03).

## Границы

- **Входит:** формула веса (компоненты, темпы), где живёт формула (движок) vs параметры (паспорт
  ячейки/класса), симметрия/асимметрия decay↔reinforcement, что именно считается «использованием».
- **НЕ входит:** что происходит, когда вес падает ниже порога — стадии/видимость (→ 03
  forgetting-lifecycle); кто ограничивает СУММУ весов по всей базе (→ 06 metabolism-governance); как
  разные КЛАССЫ данных получают разные рецепты по умолчанию (общий принцип — здесь, полная
  классификация — → 06).
- **Тонкая граница с 06:** здесь — «как считается вес одной единицы»; в 06 — «кто ставит потолок,
  чтобы рецепт ячейки не обошёл общий бюджет».

## Развилки

1. **Формула веса.** Единая глобальная формула с параметрами в паспорте [+просто, сравнимо между
   ячейками / −негибко для экзотичных типов данных] vs каждый класс несёт свою формулу целиком
   [+гибко / −несравнимые числа, тяжело мониторить общий бюджет] vs гибрид: общий каркас (3
   компоненты) + веса компонент настраиваются в паспорте [+баланс / −сложнее объяснить владельцу].
2. **Симметрия decay/reinforcement.** Симметричные темпы (один коэффициент вверх-вниз) [+просто /
   −не похоже на живую память, где забыть легче, чем вспомнить] vs асимметрично «падает медленно,
   поднимается быстро» (легко реанимировать) [+ближе к интуиции доверия / −два параметра вместо
   одного, риск дрейфа] vs асимметрично наоборот — «падает быстро, поднимается медленно» (анти-накрутка
   собственной важности) [+защита от спама самоподнятием / −цена ошибки для реально важного, что
   забылось подтвердить].
3. **Что считается «использованием».** Только явное Подтвердить (Г7) [+чистый сигнал / −редко
   случается, вес почти не растёт] vs любое чтение, даже частичное измерение паспорта [+много сигнала
   / −«мельком глянул» ≠ «подтвердил важность», шум] vs послойно: чтение паспорта = микро-плюс,
   вскрытие payload = средний плюс, Подтвердить = полный плюс [+соответствует «послойному оцениванию»
   из L0 / −три коэффициента вместо одного].
4. **Где хранятся параметры рецепта.** В паспорте ячейки индивидуально [+суверенность конкретной
   единицы / −дрейф, тяжело чинить политику разом] vs в паспорте КЛАССА (шаблон), ячейка ссылается
   [+централизованно чинится / −ячейка не может выделиться при реальной нужде] vs default от класса +
   override в ячейке как исключение [+баланс, паттерн Strategy+override / −нужен явный лимит на
   override, иначе см. направление 06].
