  цикла 0), `../../V4-vitalnost/ideas/IDEA-incremental-metabolism-at-scale/README.md`,

## Суть

Мета-слой НАД остальными пятью направлениями: бюджет внимания принадлежит БАЗЕ/движку (DB-control),
не отдельной ячейке или агенту (Г15); кто-то физически исполняет фазу C (садовники); разные КЛАССЫ
данных метаболизируют по разным рецептам, включая отдельный класс `ephemeral` для мыслей агента
вслух; всё это не имеет права сломаться при росте базы — масштаб здесь **условие дожития ценности**,
а не оптимизация задним числом.

## Границы

- **Входит:** механизм ограничения общего бюджета (жёсткий/мягкий/гибрид), кто и когда запускает
  садовника, рецепты по классам данных (включая ephemeral-класс агента вне общего бюджета),
  инкрементальность пересчёта (dirty-list vs полный граф).
- **НЕ входит:** конкретная формула веса одной единицы (→ 01 salience-weight); конкретный механизм
  консолидации/эмердженса (→ 02); конкретные стадии видимости (→ 03) — governance ставит потолок и
  расписание НАД этими процессами, а не изобретает ещё один шестой процесс метаболизма.
- **Тонкая граница с 01:** «рецепт живёт в ячейке» (01) — это ЧТО настраивается внутри одной единицы;
  здесь — КТО и КАК ставит общий потолок, чтобы рецепт ячейки/класса его не обошёл.

## Развилки

1. **Механизм бюджета (VQ2, цикл 0).** Жёсткий лимит (top-N живых единиц, остальное принудительно
   cold) [+предсказуемо, детерминированный потолок / −резкие обрывы на границе N] vs мягкий (штраф за
   превышение через понижающий множитель всем сразу) [+плавно / −никто явно не «top», сложно
   объяснить владельцу приоритет] vs гибрид: hard-cap по классу данных + soft-штраф внутри класса
   [+баланс / −два параметра настройки вместо одного].
2. **Кто крутит фазу C.** Фоновый крон по расписанию, отдельно от чтения [+предсказуемый ресурс /
   −задержка до суток] vs встроено в путь чтения — ленивый пересчёт при обращении [+всегда актуально /
   −читатель платит цену пересчёта своим временем ответа] vs «садовник» — асинхронный агент, будимый
   и по расписанию, и по порогу накопленных изменений (dirty-list) [+совмещает свежесть и
   предсказуемость / −нужен надёжный dirty-tracking].
3. **Рецепты по классам данных (тема A, цикл 0).** Один глобальный рецепт для всех классов [+просто
   сравнивать вес между единицами / −насилие над разнородностью: эмоция ≠ задача ≠ ephemeral-скретч
   агента] vs рецепт по классу (шаблон), ячейка может override [+гибко, class-as-policy / −override
   может обойти класс-лимит, нужен потолок из развилки 1] vs отдельный класс `ephemeral` вообще ВНЕ
   общего бюджета — свой микро-бюджет, живёт минуты-часы, не участвует в Г15 совсем [+не засоряет
   основной бюджет «мыслями вслух» агента / −требует чёткой границы, когда скретч становится памятью].
4. **Инкрементальность (тема C, цикл 0).** Полный проход по графу при каждой консолидации [+просто
   реализовать первым / −не масштабируется: Витальность — «первая ценность, которая ломается» при
   росте базы, прямая цитата владельца] vs dirty-list — только изменившиеся/использованные узлы с
   последнего прохода [+масштабируется / −нужен надёжный трекинг изменений, риск пропустить
   transitively задетый узел] vs гибрид: dirty-list + редкий полный проход как страховка от
   накопленной ошибки трекинга («ночной глубокий сон»).

## Пул идей

| Идея | Индекс | Задевает ещё | Метка |
|---|---|---|---|
| Инкрементальный метаболизм (dirty-list, не полный граф при каждом проходе) | P1 · M · высок | — | перенесено из цикла 0 (`IDEA-incremental-metabolism-at-scale`), условие дожития до масштаба, не оптимизация |
| Ephemeral-класс агента вне общего бюджета (свой микро-бюджет, минуты-часы) | P2 · M · сред | 01-chitaemost (граница скретч/память), 02-tozhdestvo (когда скретч становится тождественной единицей) | **→ infra** |
| Hard-cap по классу + soft-штраф внутри класса (гибрид VQ2) | P2 · M · сред | 05-suverennost (класс = делегированная автономия рецепта) | **→ infra** |

> Теги: 04 (сам governance), 01 (граница ephemeral), 02 (тождество ephemeral→memory), 05 (делегированная
> автономия класса). Не покрыто в L0 прямо: «кто крутит фазу C» — явно вынесено сюда как открытый
> вопрос направления, не только владельца-цикла.
