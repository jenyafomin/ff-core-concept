## Суть

Самый синхронный срез вопроса «та же самая или другая»: перед нами **две записи прямо сейчас** — это
одна единица или две? Объект защиты — **критерий равенства** (что именно делает записи «той же») и
**операция схлопывания** дублей в один `canonical_id`. Ключевая ставка владельца/L0: **дедуп ДО
импорта, не после** — грязь не должна попасть в граф и потом требовать чистки.

## Границы

- **Входит:** предикат тождества (по каким полям/ключу/хэшу/смыслу две записи равны); присвоение
  `canonical_id`; момент дедупа (до импорта / после / непрерывно); механизм слияния (кто «победитель»,
  что переживает merge — payload, история, рёбра, паспорт); откат ошибочного слияния (split back).
- **НЕ входит:** «одна вещь, изменившаяся во времени» → 02 (диахрония); намеренные РАЗНЫЕ сиблинги →
  03 (варианты); две частицы, ПРОТИВОРЕЧАЩИЕ об одном факте (они не дубли!) → 05; гарантия порядка/
  конкуренции под union-find → 06.
- **Тонкая граница с 03:** дедуп и вариант — **зеркальные вердикты** одного вопроса «same or other?».
  Merge говорит «две записи = одна» (схлопнуть), variant говорит «похожи, но НАМЕРЕННО другие» (не
  схлопывать). Ошибка в любую сторону дорога: ложный merge стирает вариант, ложный split плодит дубли.
- **Тонкая граница с 05:** дубль = один референт + согласное содержимое → merge; ко-референция =
  один референт + РАЗНОЕ содержимое → конфликт-протокол (не merge). Различить их — задача критерия.

## Развилки (веер «как», не режем)

1. **Предикат равенства.** Точный ключ/детерм. хэш содержимого [+ дёшево, воспроизводимо / − ловит
   только буквальные дубли] vs совпадение выделенных «якорных» полей [+ терпит форматирование /
   − надо выбрать поля] vs вероятностное сходство (эмбеддинг + порог) [+ ловит перефраз / − ложные
   срабатывания, недетерм.] vs арбитраж человеком/агентом на серой зоне [+ точно / − дорого, не масштаб].
2. **Момент дедупа.** ДО импорта — адаптер нормализует и матчит на входе (L0-ставка) [+ граф чист /
   − адаптер сложнее, нужен доступ к «уже есть ли такое»] vs ПОСЛЕ, фоновый метаболизм схлопывает
   [+ импорт быстр / − окно грязи, чистка = риск искажения] vs непрерывно (стрим-дедуп) [+ баланс / − инфра].
3. **Кто «победитель» при слиянии.** Старший `canonical_id` поглощает [+ стабильный адрес / − теряет
   свежесть новой записи] vs новый становится каноном, старые → алиасы [+ свежесть / − адрес «плывёт»]
   vs без победителя: обе живут, связаны ребром `same-as` (ленивое слияние) [+ обратимо / − N адресов].
4. **Механизм схлопывания.** **Union-find** над классами эквивалентности [+ O(α), инкрементально /
   − нужен движок, → 06] vs явный merge-узел (обе записи → дочерние одного канона) [+ история видна /
   − лишний узел] vs перезапись ссылок (все рёбра переводятся на канон) [+ чисто / − необратимо].
5. **Что переживает merge.** Только payload победителя [+ просто / − теряем провенанс проигравшего]
   vs объединение паспортов (провенанс обоих, max confidence) [+ богаче / − конфликты полей] vs
   payload победителя + сохранённые «тени» проигравших для отката [+ обратимо / − место].
6. **Обратимость (split back).** Merge необратим [+ дёшево / − ошибка фатальна] vs merge как
   закрываемая транзакция (можно расклеить) [+ безопасно, роднит с bitemporal 02 / − сложнее] —
   владелец ценит обратимость (ср. «архив вместо delete» в соседних ценностях).
