# Направление 03 — Ветвление и варианты (`variant-of`)

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md` (ценность Ц-2), `../../../L0-memory-unit.md` (Г28 «быть вариантом без связи
  с др. вариантами»; Г25 «проявление в пространстве: варианты/ветки»; В2), `../02-tozhdestvo-vo-vremeni/README.md`
  (зеркало: эволюция ≠ вариант), `../01-kriteriy-i-dedup/README.md` (зеркало: вариант ≠ дубль).

## Суть

Иногда «другая» — это НЕ ошибка и не эволюция, а **намеренный сиблинг**: разные планы недели, ветки
сценария, альтернативные редакции. Владелец (Г25/Г28): варианты «записаны по-разному», в момент
планирования — **переключение ВЕТКИ**, каждый вариант = **независимая ячейка, возможно не связанная с
другими вариантами**. Объект защиты — тождество как **веер от якоря**: у каждого варианта свой
`canonical_id` + ребро `variant-of` к якорю; связность отображается «интересно», но варианты автономны.

## Границы

- **Входит:** новый `canonical_id` + ребро `variant-of`/`branch-of` к якорю; выбор «активной ветки»
  (переключатель); степень связности вариантов (веер от якоря vs полностью независимые); что общего у
  вариантов (наследуют паспорт/поля якоря или нет — шов с наследованием Г32); закрытие/победа ветки.
- **НЕ входит:** ТОТ ЖЕ id, меняющийся во времени → 02 (эволюция); схлопывание дублей → 01; композит из
  частей → 04; наследование шаблон→экземпляр как отдельная механика (Г32) → это Реляционность/типы, тут
  только шов.
- **Тонкая граница с 02 (несущая, В2):** «я записал иначе» — это НОВАЯ ВЕРСИЯ той же ячейки (эволюция,
  02) или НОВЫЙ ВАРИАНТ (сиблинг, 03)? В2: форк только для намеренных вариантов. Кто и КАК объявляет
  «это вариант, а не правка» — ключевая развилка ниже.
- **Тонкая граница с 01:** дедуп схлопывает похожее в одно; вариант СОХРАНЯЕТ похожее как разное.
  Дедуп-движок обязан НЕ съесть варианты (у них общий `variant-of`-якорь = «руки прочь»).

## Развилки (веер «как», не режем)

1. **Кто объявляет форк.** Явно человек/агент («сделай вариант») [+ намеренно, чисто / − ручной труд]
   vs эвристика движка (сильно разошлось → предложить форк) [+ ловит незаявленное / − ложные форки]
   vs всегда версия, вариант — лишь помеченная версия-ветка [+ единая механика с 02 / − стирает
   различие «сиблинг vs эволюция»].
2. **Связность вариантов.** Веер от общего якоря (все `variant-of` → anchor) [+ видно семью, легко
   перечислить / − якорь обязателен] vs цепочка `forked-from` (вариант от варианта) [+ история
   ветвления / − нет единой «семьи»] vs полностью независимые, связь опциональна (Г28 «возможно не
   связанная») [+ максимум автономии / − теряем «это варианты одного»].
3. **Активная ветка.** Указатель «активный вариант» на якоре [+ один переключатель / − один активный
   на всех] vs активность = свойство запроса/контекста (в проекте A активна ветка-1, в B — ветка-2)
   [+ мультиарендно, роднит с Ц-5 / − нет глобального «текущего»] vs все равноправны, «активность» —
   вычисляемый вид [+ гибко / − надо считать].
4. **Общее наследство.** Варианты наследуют паспорт/поля якоря (дельта-хранение) [+ компактно,
   шов с Г32 / − связаны сильнее, чем «независимы»] vs каждый вариант самодостаточен (копия) [+ Г28
   автономия / − дублирование] vs наследует только паспорт (title/тип), payload свой [+ баланс / − две модели].
5. **Судьба ветки.** Вариант «победил» → сливается в якорь (шов с merge 01) [+ ветвление сходится /
   − когда мержить?] vs варианты вечно параллельны [+ чистая автономия / − рост] vs закрытие ветки =
   bitemporal-закрытие (шов с 02) [+ единый контракт отката / − связывает 02+03].
