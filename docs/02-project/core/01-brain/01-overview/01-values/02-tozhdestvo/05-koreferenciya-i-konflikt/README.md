## Суть

Самая тяжёлая и **не покрытая в L0** грань. Две РАЗНЫЕ частицы говорят об **одном референте** (событии,
факте, человеке) — и **противоречат** друг другу. Это НЕ дубли (их нельзя мержить: разные носители,
разные свидетели, разный провенанс), но и не независимые вещи. Ключевой рефрейм Opus: **ко-референция ≠
тождество носителя** — «три свидетеля одного события» = три памяти + один общий якорь-референт, а не одна
запись. Объект защиты — чтобы **противоречие было ВИДИМО третьему** (Г17), а не тихо деградировало
доверие ко всему графу. Тождество тут работает «наружу»: разделить *носитель памяти* и *то, о чём память*.

## Границы

- **Входит:** узел-референт (event-anchor / entity-anchor), на который ссылаются разные памяти;
  ребро `about`/`refers-to` (память → референт); обнаружение конфликта (две памяти об одном референте
  расходятся); **протокол-конфликт** (как противоречие фиксируется и живёт); видимость конфликта третьему
  (Г17); разрешение (оставить обе + confidence / выбрать / эскалировать / оставить открытым).
- **НЕ входит:** две записи, которые ОДНА вещь → 01 (merge, не конфликт); версии одной ячейки во
  времени → 02; варианты-сиблинги → 03; РАСЧЁТ самой confidence/доверия как процесса → Ц-3 Доверие
  (здесь только «конфликт как сигнал»); согласие субъекта-третьего-лица (Г20) → Ц-7 Согласие (шов).
- **Тонкая граница с 01 (критическая):** один референт + СОГЛАСНОЕ содержимое = дубль → merge (01);
  один референт + РАСХОДЯЩЕЕСЯ содержимое = конфликт → НЕ merge (05). Критерий (01) обязан различать,
  иначе движок либо съест свидетеля, либо расплодит «дубли», которые на деле спор.
- **Тонкая граница с Ц-3:** конфликт ВСКРЫВАЕТ рассогласование; что с доверием ДЕЛАТЬ (взвесить,
  откалибровать) — Ц-3. Здесь — только структура «спор виден».

## Развилки (веер «как», не режем)

1. **Носитель референта.** Явный узел-anchor (событие/сущность как отдельный узел, памяти → `about`)
   [+ споры собираются в одном месте, «три свидетеля» видны / − ещё сущность, кто создаёт anchor?] vs
   попарные рёбра `contradicts` между памятями [+ без лишних узлов / − спор размазан, нет «единого места»]
   vs вычисляемая ко-референция (эмбеддинг/ключ находит «про одно») [+ авто / − ложные связи, недетерм.].
2. **Кто создаёт anchor.** Явно при записи (адаптер знает «это про событие E») [+ точно / − не всегда
   знаем] vs метаболизм постфактум связывает памяти в anchor [+ ловит незаявленное / − окно «спор невидим»]
   vs anchor рождается в момент ОБНАРУЖЕНИЯ конфликта [+ дёшево, по нужде / − до конфликта ко-референции нет].
3. **Фиксация конфликта.** Конфликт = ребро-с-паспортом `conflicts-with` (В4-стиль, провенанс спора)
   [+ аудируемо, откатываемо / − тяжелее] vs флаг на anchor «оспорено» + список сторон [+ одно место /
   − детали спора беднее] vs конфликт = отдельная память-узел «наблюдение о споре» [+ спор сам метаболизирует
   / − рекурсия].
4. **Разрешение.** Оставить ОБЕ + confidence/вес (граф терпит противоречие, Г17) [+ честно, не теряем
   свидетеля / − потребитель должен выбирать] vs выбрать «победителя» по провенансу/свежести [+ чистый
   ответ / − теряем меньшинство] vs эскалация владельцу (клапан) [+ важное решает человек / − не масштаб]
   vs оставить открытым с пометкой [+ честно / − вечный спор].
5. **Видимость третьему (Г17).** Конфликт всплывает при чтении ЛЮБОЙ из сторон (память «пахнет спором»,
   роднит с волной) [+ нельзя проглядеть / − шум] vs виден только на anchor [+ тихо / − легко пропустить]
   vs push-сигнал в метаболизм/владельцу при рождении конфликта [+ проактивно / − прерывания].
6. **Разделение носитель ⟂ референт (рефрейм Opus).** Жёстко: память НИКОГДА не «есть» событие, только
   `about` [+ чисто, «три свидетеля» естественны / − всегда нужен anchor] vs мягко: мелкий факт = сама
   память, anchor только для спорного/многосвидетельского [+ дёшево / − граница «когда заводить anchor»].
