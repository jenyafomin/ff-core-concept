# Направление 02 — Тождество во времени (диахрония, Г12)

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md` (ценность Ц-2), `../../../L0-memory-unit.md` (В2 = bitemporal; Г9 «as-of T»;
  Г12 «меняться не теряя себя»; «Забыть» = закрыть tx-time), `../03-vetvleniye-i-varianty/README.md`
  (там — новый id + `variant-of`; здесь — ТОТ ЖЕ id, версия), `../06-dvizhkovyy-dolg/README.md`
  (глобальный порядок времени, без которого «as-of» бессмыслен).

## Суть

Та же ячейка меняется — консолидируется, переоценивается, забывается — и **остаётся собой** (Г12).
Объект защиты — **непрерывность `canonical_id` сквозь собственные изменения во времени**: «текущее»
читается чисто, а «что я утверждала в момент решения» (Г9) восстанавливается для аудита. Решение В2 уже
принято: **bitemporal-версионирование** (`canonical_id` стабилен; каждое изменение = новая темпоральная
версия valid-time + transaction-time; забыть = закрыть transaction-time, не удаляя). Здесь — раскрыть
его развилки, а не переоткрывать.

## Границы

- **Входит:** модель версий (valid-time = когда факт был верен; transaction-time = когда система это
  знала); чтение «as-of T» (Г9-снапшот); «Забыть» как закрытие tx-time (Г12, обратимо) vs жёсткое
  удаление; гранулярность версии (вся ячейка / поле / паспорт); стоимость истории (сколько держать).
- **НЕ входит:** намеренное ветвление в РАЗНЫЕ сиблинги (новый id) → 03; схлопывание ДВУХ записей в
  одну → 01; part↔whole и смена типа → 04; кто физически проставляет глобальный T → 06.
- **Тонкая граница с 03 (несущая, В2):** эволюция (ТОТ ЖЕ id, новая версия) vs вариант (НОВЫЙ id +
  `variant-of`). Правило В2: «текущее чисто, старое as-of; форк — только для намеренных вариантов, не
  для эволюции». Ошибка сюда — либо мутация без истории (потеря Г9), либо форк-на-каждый-чих (рой id).
- **Тонкая граница с Ц-4 Витальность:** метаболизм (consolidation/forget) — там ПРОЦЕСС (кто крутит,
  когда протухает); здесь — как этот процесс НЕ рвёт тождество (контракт версии/отката).

## Развилки (веер «как», не режем)

1. **Битемпоральность целиком или частями.** Полный bitemporal (valid+tx) на каждой ячейке [+ полный
   аудит Г9 / − вес, сложность] vs только transaction-time (append-only лог версий) [+ проще / − нет
   «когда факт был верен»] vs версии лишь на «горячих»/спорных ячейках, холодные — снапшот [+ дёшево /
   − неоднородный контракт, спорит с Г6 «одно правило на зуме»].
2. **Гранулярность версии.** Версионируем всю ячейку [+ просто, целостно / − дублирует неизменное] vs
   поле/паспорт отдельно (дельты) [+ компактно / − сборка «as-of» дороже] vs payload реже, паспорт
   (confidence/valid) чаще [+ дёшево-читаемо, роднит с Ц-1 / − две скорости версий].
3. **Забыть = ?** Закрыть tx-time, содержимое живёт скрытым (Г12, обратимо) [+ откат, аудит / −
   «зомби-память»: влияет через эмбеддинги — L0 «не покрыто»] vs вынести в холодный слой [+ чисто-быстро
   / − две подсистемы] vs жёсткое удаление по политике [+ приватность Ц-5 / − необратимо, теряем Г9].
4. **Хранение истории (сколько глубоко).** Вечная история [+ полный аудит / − рост без границ] vs
   TTL/оконная история (старые версии сворачиваются) [+ дёшево / − «дыра» в as-of] vs политика на самой
   единице (policy-as-data: единица несёт свою глубину истории) [+ автономия Ц-5 / − разнородность].
5. **Смена типа во времени = версия или новая ячейка?** (шов с 04) Смена типа = новая версия того же
   id [+ тождество цело / − паспорт «прыгает» тип] vs новая ячейка + `succeeds` [+ чисто по типу /
   − рвём непрерывность адреса] — вынесено в 04, здесь фиксируем шов.

## Пул идей

| Идея | Индекс | Задевает ещё | Метка |

| **Забыть = закрыть tx-time** (обратимо, не удаляя; контракт отката Г12) | P1 · M · высок | Ц-4,Ц-5 | **→ infra** (шов с Витальностью) |
| **Снапшот «as-of решения»** (Г9-аудит «почему агент так сделал») | P2 · S · высок | Ц-3 | **→ infra** (аудит-читаемость) |
| **Дельты паспорта отдельно от payload** (две скорости версий) | P2 · M · сред | Ц-1 | локально (+шов Ц-1) |
| **Глубина истории как policy-as-data** (единица несёт свой TTL версий) | P2 · M · сред | Ц-5,Ц-4 | **→ infra** (policy-as-data) |
