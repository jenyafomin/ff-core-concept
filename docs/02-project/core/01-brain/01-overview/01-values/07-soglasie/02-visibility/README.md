# Направление 02 — Видимость: кому показать

- **Status:** draft — дивергенция · **Owner:** JenyaFomin · **Date:** 2026-07-09
- **Related:** `../README.md` (ценность Ц-7) · цели Г18 (скрыть себя), Г24/Г31 (роли, «свой мир»,
  capability-шеринг) · Ц-1 Читаемость (метка, не стена) · Ц-6 Реляционность (шеринг по рёбрам) ·
  07.C Конституция (visibility референта неоверрайдабельна)

## Суть

Согласие на **показ/чтение** — кому конкретно единица открыта: только владельцу, кругу людей, агенту,
всему миру. Механизм — **линза-политика** (`policy-as-data`): зерно от строки до поля, роли и «свой мир»
проекта (подключил кого-то, кто видит НЕ всё), capability-шеринг, tenant-изоляция. Плюс единица должна
уметь **СКРЫТЬ себя** (Г18), а не только объяснить. Объект защиты — **поверхность чтения**: кто и на
каком зерне может единицу увидеть.

## Границы

- **Входит:** `scope`/`visibility` как производное от референта; модель доступа (ABAC / RBAC / capability);
  зерно видимости (вся ячейка / field-level / cell-level); роли и «свой мир» проекта (Г24/Г31);
  capability-шеринг; tenant-изоляция; hide-self (Г18).
- **НЕ входит:** право ДЕЙСТВОВАТЬ на основании (→ 03 use-vs-read); наследование при агрегации (→ 04 taint);
  отзыв доступа (→ 05); enforce неоверрайда (→ 07.C).
- **Тонкая граница с Ц-1 Читаемость:** собственный ИИ-владельца видит всё (эпистемический статус — метка,
  не стена); visibility ограничивает показ **другим** — людям, чужим агентам, миру, — не своему ИИ.
  Исключение из этого — только use-consent (→ 03) и hide-self по требованию референта.

## Развилки (веер «как», не режем)

1. **Модель доступа.** ABAC (атрибуты субъекта × ресурса, `policy-as-data`) [+ гибко, переносимо / − трудно
   рассуждать, дорого проверять] vs RBAC роли [+ понятно / − грубо] vs capability (у кого «ключ» — тот видит)
   [+ децентрализованный шеринг, Г31 / − отзыв ключа труден].
2. **Зерно видимости.** Вся ячейка [+ просто / − грубо] vs field-level (паспорт виден, payload — нет)
   [+ ровно Г1 «оценить не вскрывая» бесплатно / − сложнее движок] vs cell/edge-level [+ максимум точности
   / − взрыв правил].
3. **«Свой мир» проекта.** Жёсткая tenant-изоляция (отдельные под-графы) [+ нет утечки / − нет дешёвого
   шеринга, дубли] vs единый граф + линза-фильтр [+ шеринг и связность дёшевы / − утечка при баге линзы]
   vs гибрид (общий граф, изоляция как атрибут).
4. **Hide-self (Г18) — где живёт правило.** Ячейка сама несёт «не показывать классу X» (`policy-as-data`)
   [+ переносимо в plug-in / − доверяем самой ячейке] vs видимость только во внешнем ACL хоста
   [+ централизовано, надёжно / − не переносится при экспорте узла].
5. **Дефолт видимости.** Приватно (owner-only), расширяют явно [+ безопасно, нет утечки по умолчанию /
   − трение] vs видно владельцу + его агентам [+ удобно / − надо помнить сузить, когда референт непуст].
