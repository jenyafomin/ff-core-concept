## Суть

Референт/владелец может **отозвать согласие позже** — но это ДВА разных акта, требующих ДВУХ разных
примитивов движка, а не одного: **(а)** «перестань показывать» — обратимо, `salience→0`, bitemporal
хранит историю («забыть ≠ удалить»); **(б)** «сотри совсем» — **hard-erase**, право на забвение,
настоящее необратимое уничтожение payload. Объект защиты — **горизонт отзыва и стирания**. Здесь живёт
самый острый конституционный конфликт ценности (FQ7).

## Границы

- **Входит:** два примитива забывания; hard-erase / tombstone; судьба `canonical_id`; каскад отзыва на
  потомков (обратный taint); безусловность hard-erase референта; забвение в эмбеддингах/копиях/кэше.
- **НЕ входит:** рутинное «забывание по витальности» без участия согласия (→ Ц-4 метаболизм); аудит самого
  акта сокрытия (→ 06); enforce безусловности (→ 07.C, инвариант И2).
- **Тонкая граница с Ц-4 Витальность:** дефолтное «забыть ≠ удалить» — это витальность (обратимо, спит);
  hard-erase — это согласие (необратимо, по требованию). **Один механизм НЕ покрывает оба** — вот почему
  FQ7 требует решения владельца, а не тихого выбора движка.

## Развилки (веер «как», не режем)

1. **Один механизм или два.** ДВА примитива — обратимый sleep + необратимый erase [+ честно к обоим, право
   на забвение реально / − сложнее движок] vs один bitemporal «close transaction-time» [+ просто, единый
   контракт / − **нет настоящего стирания**, ломает право референта → нарушает Г20]. **Это и есть FQ7.**
2. **Судьба `canonical_id` при hard-erase.** Tombstone: id-пустышка + факт «здесь было, стёрто по требованию
   референта», рёбра целы [+ целостность графа Ц-2, ссылки не рвутся / − остаётся след существования]
   vs полное освобождение id, рёбра рвутся намеренно [+ ничего не осталось / − дыры в графе, потеря
   целостности]. (Q-hard-erase-id)
3. **Каскад отзыва.** Отзыв каскадирует на всех потомков (обратный consent-taint 04) [+ согласованно,
   агрегаты не переживают запрет / − дорого, может стереть много] vs только исходник [+ точечно / − внуки
   переживают отзыв].
4. **Кто исполняет и когда.** Синхронно по требованию (движок-долг, немедленно) [+ гарантия / − нагрузка]
   vs фоновый метаболизм с гарантированным SLA-сроком [+ масштаб / − окно, где ещё видно после отзыва].
5. **Забвение в эмбеддингах / копиях / кэше.** Гарантия невлияния: payload стёрт, но модель/индекс мог
   «запомнить» → требуется вычистить и производные [+ настоящее забвение / − технически трудно, дорого] —
   **заложить требование сейчас**, даже если реализация позже.
