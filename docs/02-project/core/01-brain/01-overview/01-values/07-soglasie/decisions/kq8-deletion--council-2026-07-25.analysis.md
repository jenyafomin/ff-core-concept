# 🗑️ KQ-8 — что такое «удаление»? (синтез совета 2026-07-25)

## 1 · Вопрос
Что есть «удаление»: tombstone vs projection-hide vs физическое стирание — на пересечении
иммутабельного лога (**I-4**) и консент-эрейжа (право быть забытым).

## 2 · Результат совета
**«Удаление» = ТРИ несвязанных обязательства под одним словом:**
undo/коррекция · storage-hygiene · legal-consent-erasure. **Ни один единый режим** не удовлетворяет
одновременно I-4 (replay-recoverability) И консент-необратимость.

**Разрешение = split иммутабельных `acts` от стираемого `payload`** (ref + hash). Три режима:

- **(A) tombstone + hide** — дефолтное логическое удаление (дёшево, детерминированно). **НЕ erasure**:
  payload выживает. Сам tombstone = атрибутированный **монумент существования** (факт «тут что-то было»).
- **(B) crypto-shred** — единственный настоящий консент-эрейж, но ТОЛЬКО при предусловиях, которых
  **ещё нет в ADR-0006**: PII никогда не инлайнится в акт; отдельное **удаляемое key-store**. Гейтится
  консент-клапаном; сам эрейж **записывается КАК акт** → replay остаётся детерминированным-до-границы.
- **(C) plugin-removal** — данные выживают (**I-12**); нужен неспецифицированный **fallback-рендерер
  «unknown-type»**.

**Redaction-акт** = ТОЛЬКО коррекция качества данных; **никогда не продавать как erasure** (оригинал
остаётся в append-only → иллюзия стирания).

## 3 · Настоящее решение = гейт ДОПУСКА (admission)
Ключевой вопрос — **«какие данные слишком чувствительны, чтобы вообще стать каноническим актом»**.
Это решение **дня-1 схемы** (не времени удаления): такие данные должны с момента записи жить в
**эфемерной / неканонической полосе**, а не превращаться в неизменяемый акт.

## 4 · Нерешённые трещины (НЕ замазывать)
- **Гранулярность ключа vs collateral-erasure**: ключ общего сегмента стирает co-referents.
- **Taint-closure уже эмитированных производных** (сводки, ушедшие в Telegram и т.п.) — в прошлой
  архивной критике оценено как **«SLOMAN»** (не решено).
- **Metadata-residue** (утечка самого факта существования) — неустранима в append-only.

## 5 · Что нужно
- Новый инвариант **I-15** (payload-separability + erasure-as-act) + явный **carve-out I-4** для границ эрейжа.
- **ADR-0007**, расширяющий ADR-0006.
