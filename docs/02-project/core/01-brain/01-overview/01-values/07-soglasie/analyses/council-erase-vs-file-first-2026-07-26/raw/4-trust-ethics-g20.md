# Линза 4 · Доверие / этика (Г20)

Позиция: «кому больно, когда обещание эрейжа не исполняется, и что честно обещать.»

## 1. Обещание гибкости = обещание дыры
- Принцип проекта: «клапан доверия — только на внешние необратимые действия; видно, что делает ИИ».
  Эрейж — ровно такое внешнее необратимое действие, ему нужен НАСТОЯЩИЙ клапан, а не имитация.
- Продать в UI «истинное удаление / право быть забытым», пока субстрат физически не может это дать для
  file-first-контента, = **сломанное обещание, бьющее по самой бесправной стороне** (референт без
  аккаунта). Это хуже, чем не обещать. Честный fail: «скрыто, не стёрто».

## 2. Г20 — детонатор на маркетплейсе
- Владелец пишет о лице X; X не давал согласия быть узлом. В личном режиме терпимо (дневник). В момент
  plug-in/маркетплейса данные X текут к другим акторам/плагинам — **вот точка взрыва** (L0 Г20,
  README 07-soglasie: «ретрофит невозможен»).
- Значит грань `referent` + флаг `erasure-eligible`/класс-согласия надо заложить в паспорт **СЕЙЧАС**,
  даже если 99% записей — о себе (референт пуст, ничего не меняется).

## 3. OQ-4 — безусловность референта vs субстрат
- Конституция ценности (И2): «hard-erase референта исполняется безусловно», И1: «согласие референта
  нельзя переопределить политикой владельца».
- «Безусловно» **неисполнимо**, если данные X в git владельца и клонах → конституция обещает то, что
  субстрат ломает. Честный ремонт: (а) переформулировать «безусловно **в пределах shreddable-субстрата
  и до внешней эмиссии**», И (б) admission-запрет данных референта в не-shreddable сторах (git). Тогда
  безусловное обещание исполнимо в объявленных границах.

## 4. OQ-5 — каскад согласия по потомкам
- Отзыв согласия референта должен каскадировать на lineage-производные (сводки, insight-рёбра,
  эмбеддинги) — иначе «стёрли» ячейку, а факт живёт в производной (adversarial-сценарий 02 это уже
  называл). In-substrate каскад = долг движка (SPEC R3). Off-graph производные — граница OQ-2.

## 5. Маркетплейс-гейт
- До ЛЮБОГО шеринга узла наружу (plugin/marketplace) — гейт проверки referent-consent +
  erasure-eligibility. Ретрофит невозможен → грань закладывается сейчас, гейт — обязательное предусловие
  включения шеринга.

## Вердикт линзы
Честность требует: (1) НЕ заявлять «истинный эрейж» там, где субстрат его не даёт (file-first git); для
такого — только tombstone/hide с честной меткой. (2) Заложить грань `referent` + класс-согласия в паспорт
сейчас (ретрофит невозможен). (3) Переформулировать конституционную «безусловность» референта в честную
границу + запретить данные референта в git. (4) Гейт согласия/eligibility ПЕРЕД маркетплейс-шерингом.
