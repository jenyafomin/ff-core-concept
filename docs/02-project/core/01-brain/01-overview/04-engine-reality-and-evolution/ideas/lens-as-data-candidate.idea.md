# 💡 Линза / projection-as-data (candidate — gated, НЕ направление)

> **status: candidate — ПРИПАРКОВАНО. НЕ заводим `00-directions/09-`. Статус направления заслужит только
> пережив реальные данные (перепись эпизодов). Прошлый critic флагнул D9 как незапрошенный дрейф — держим
> МИНИМАЛЬНО, без раздувания в трек.**

## Идея одной фразой
**Проекция (вид) = ДАННЫЕ, а не enum.** Вид никогда не второй источник истины — это чистое вычисление
над субстратом: `вид = f(units, lens)`. Одни данные, много одноразовых поверхностей на лету
(таблица → граф → таймлайн → канбан).

## Почему это не новое направление, а READ-сторона того, что ЧАСТИЧНО уже есть
Это не 9-е направление с нуля. Это **READ-сторона субстрата, которая уже частично построена**:
`view-compiler.ts` / `ViewDef` (4-стадийный пайплайн `from · traverse · filter · shape`, сегодня 3 frozen
kinds). Рефрейм Able:
- **D8 schema-constructors = ГЕНОМ** (письмо: как построить/эволюционировать тип, policy-as-data).
- **Линза = ФЕНОТИП** (чтение: как один паттерн разворачивается в N поверхностей, projection-as-data).
Оси ортогональны — линза поперёк типов (cross-type), не дублирует D8.

## Ставка на ценность (V5)
**Линза сама = переносимая единица памяти** со своим `id`/policy → реюз, версионирование, шаринг,
портируемость. Не только маркетплейс схем (D8), а маркетплейс ВИДОВ. Прямое V5.

## Риск (держать в уме, не проглатывать)
**Бесконечная гибкость ↔ удобство:** если паттерн придумывать каждый раз с нуля — порог входа РАСТЁТ
(«теперь я архитектор своей базы» вместо «я просто работаю»), плюс «каша типов» (десятки почти-одинаковых
паттернов) бьёт по V1 (читаемость) и V2 (тождество/дубли). Митигация (loop-агент предлагает консолидацию
сверху) намечена в D8, но НЕ построена.

## Что становится ВОЗМОЖНО (глазами владельца — сохранено из черновика §5, LOSE-NOTHING)
1. Одни данные — карточка / строка / узел графа / лента таймлайна; вид переключается мгновенно, без пересохранения.
2. Завожу новый тип сущности сам (паттерн-набор полей) — без программиста, без риска сломать остальное.
3. Переиспользую готовый паттерн («объект с локацией+статусом+историей») для чего угодно нового.
4. Срез «всё за месяц по клиенту/машине» за 10 сек, а не рытьё по таблицам/чатам.
5. Правила поведения единицы настраиваю как данные — не трогая ядро.
6. Единица носит схему при себе → переносима в другой движок без «рассыпания» (**V5**).
7. Экспериментирую с новой структурой безопасно (черновик-паттерн), откатываю, если не зашло.

## Самый дешёвый способ ДОКАЗАТЬ гибкость на РЕАЛЬНОМ примере (сохранено из §7 — вяжется с переписью)
Не абстрактный конструктор в вакууме. Взять ПЕРВЫЙ реальный кусок (3–5 эпизодов, не весь массив) и прожить
цикл **«завёл новый тип → увидел таблицей → графом → таймлайном»**. Это ТОТ ЖЕ ход, что перепись загорания
на реальных эпизодах (`../questions/real-episode-census.question.md`). Гибкость доказывается не статьёй, а
тем, что реальные данные **легли и переключились** между видами без переписи. → это и есть способ, которым
кандидат может «заслужить» direction-статус.

## Гейт

и требует отдельного адверсариала ДО любой стройки. **Кандидат заслужит direction-статус только пережив
реальные данные.** Сейчас — только эта заметка-стаб.
