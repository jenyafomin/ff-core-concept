# 🗺️ Две карты памяти

> Два разных НОЖА по ОДНОМУ субстрату. Карта №1 режет по **ЦЕННОСТЯМ** (V1–V7) — отвечает «ЗАЧЕМ»
> единица так устроена. Карта №2 режет по **ПАТТЕРНАМ ЖИЗНИ ДАННЫХ** — отвечает «КАК» единица проживает
> время. Обе — дешёвые ВИДЫ над субстратом, НЕ второй дом истины: дом Ц-смысла = `_CARDS-2026-07-08.md`,
> дом реальности = код + полки честности UNIT-SPEC §9.

> **Субстрат.** Обе карты описывают `@ff/engine` (`EnvelopeNode` + `Act`), НЕ `@ff/core` (простой
> `FFNode`). Ценности V1–V7 приземляются на engine.

> ⚙️ **РЕГЕН-ТРИГГЕР:** регенерируемый снимок реальности-против-обещаний. **регенерировать при изменении
> `packages/engine/test/value-collisions.test.ts`** (и файлов движка, на которые ссылаются ячейки).
> Строгий статус «держит / обещание / не построено» по каждой возможности — в
> `capability-map-2026-09-17.analysis.md` (T1–T7). Здесь — панорама двух осей.

## Словарь (чтобы карты не расплылись)

| Термин | Одна строка |
|---|---|
| **концепт** | абстрактная модель («доверяемая композиция», «единица носит свой закон») — то, что карта делает видимым. |
| **образ / view** | одна ячейка карты — проекция одного среза субстрата (напр. «V3 в машине»). |
| **карта** | набор образов по ОДНОЙ оси (ценности ИЛИ паттерны жизни) — дешёвый вид, не второй дом истины. |
| **субстрат** | над чем строятся карты: **лог актов** (append-only) + **граф** (проекция) + **единицы** (узлы/рёбра) в их **состоянии**. |
| **состояние** | текущее значение единицы = свёртка её актов (`rebuild --from journal`); карта показывает срез этого состояния. |

## Карта №1 — ось ЦЕННОСТЕЙ (V1–V7)

Строка = ценность. **ТЕОРИЯ/форма** = что обещает канон (`_CARDS`). **МАШИНА** = что РЕАЛЬНО исполняет
код (движок зелёный). **Пустой слот** = чего в машине НЕТ. Цитаты `file:line` — из черновика, привязка к
`@ff/engine`.

| Ценность | Что обещает (ТЕОРИЯ/форма) | Что уже в engine (МАШИНА, файл) | Пустой слот (чего НЕТ) |
|---|---|---|---|
| **V1 Читаемость** | Отдать нужную грань по нужной цене (`label→summary→payload→trace`), не вскрываясь целиком; `temperature` cold/hot как гейт видимости; линза при чтении. | Уровни зума `L1/L2/L3` из title/body (`core/levels.ts`, `core/node.ts:6-11`); линзы-виды компилируются `from·traverse·filter·shape` (`core/view-compiler.ts`, `ViewDef` `types.ts:214`); дёшево-читаемый конверт vs `body`/payload (`types.ts:145`). | `temperature` как машинный гейт видимости — НЕ реализован (`cold` только как статус `surface/day-graph.ts:25`, не как политика чтения); `summary`/`price_hint`/progressive-disclosure — форма без движка. |
| **V2 Тождество** | Иммутабельный `canonical_id` переживает всё; «та же/другая»; merge/split с историей; freshest-wins. | Проекция по стабильному ключу `provenance.source_ref` — один узел на ключ; «freshest wins» по `snapshotHash` (`core/projection.ts:4-14,43`); `rebuild --from journal` восстанавливает состояние. | Merge/split, union-find, индекс кандидатов слияния — НЕТ; `canonical_id` единицы как отдельный примитив тождества (сейчас тождество несёт `source_ref`, не UUID-якорь). |
| **V3 Доверие** | `source`+`author`+`confidence` (калибруется использованием); supersession/самоаннулирование; провенанс; порог заражения. | Провенанс на акте (`Provenance` `types.ts:280`) и на ребре (`Edge.provenance` `types.ts:36`); supersession по source_ref+snapshotHash (`projection.ts:14`); admission-gate против inline-«тихой лжи» (см. V7). | `confidence`-калибровка (байес, пересчёт при чтении) — НЕТ движка (поле лишь в edge `meta`, никто не пересчитывает); `contagion_threshold`, `effective_time`/годность-вперёд — форма/promise. |
| **V4 Витальность** | `salience` затухает; `decay_policy`; `lifecycle_stage` nascent→active→cooling→cold; садовник батчем; консолидация/эмердженс. | **Почти пусто.** Только ДЕШЁВЫЙ структурный прокси: ранг по степени-графа (число инцидентных рёбер) `surface/day-graph.ts:45,118,133`. | **Зияет.** `body.salience` = зарезервированный ПУСТОЙ слот, всегда null (`day-graph.ts:12-13,42-43,90`); «NO weight/decay engine yet» — прямая цитата кода; decay/cooling/консолидация/эмердженс/`cold`-перевод — НЕТ. |
| **V5 Суверенность** | Ячейка носит `policy`+схему; `key_mode` anchored/portable; `engine_contract_version`; переносима в другой движок; foreign-data-wrapper. | `policy_ref[]` слот на узле (`types.ts:156`); реестры как ДАННЫЕ, инжектятся арендатором (`PredicateRegistry` `predicates.ts:20-23`, tenant `@ff/ingest-rentacar`); тип объявляет форму данных (policy-as-data заложена). | Портируемость между движками (handshake `engine_contract_version`, `key_mode`) — форма/promise, переносом не проверена (см. T5); foreign-data-wrapper, materialization live/cache/copy — НЕТ. |
| **V6 Реляционность** | Ребро = единица того же ранга: свой `id`, `edge_type`, `confidence`, `stale`; каскад по типу; derived≠declared; ссылочная целостность. | Ребро — типизированный примитив (`Edge` `types.ts:32`); fold по КАРДИНАЛЬНОСТИ-как-данным `one`/`many` без клоббера, чужие рёбра целы (`predicates.ts:2-14`, `projection.ts:72-73,114`); derived content-address `edgeIdOf()` вычисляется чисто (`core/edge-identity.ts`). | `edgeId`/`canonical_id` ребра НЕ материализуются и НЕ enforced (tripwire `edge-identity-not-enforced.test.ts`); своё `confidence`/`stale`, каскад по типу, merge/split ребра — reserved form; защиты от сирот-рёбер нет (см. capability-map GAP 7). |
| **V7 Согласие** | `referent`/`owner`/`visibility_scope`; `use_consent`≠`read_consent`; consent-taint; `revocation`/`hard_erase`; гейт перед показом И использованием. | **Только на СТОРОНЕ ЗАПИСИ:** admission no-inline-PII gate, fail-closed ДО журнала (`core/admission.ts:2-10`); PII только by-ref (`payloadRef`+`payloadHash`); терминальный `erased`-акт (`core/erasure.ts`, `buildErasedAct`); инвариант `owner=one/referent=many` в ядре. | **Read-side = ambient-authority, НЕ субстрат** (UNIT-SPEC §9). `ConsentAssurance` — SCHEMA-ONLY, НЕ enforced: движок «happily acts along a revoked edge» (`types.ts:97-108`, tripwire `consent-not-enforced.test.ts`); `PrincipalAssurance` seam — reserved, 0 поведения (`types.ts:296-338`); `read:payload`-политика пуста. |

## Карта №2 — ось ПАТТЕРНОВ ЖИЗНИ ДАННЫХ

Альтернативный нож по ТОМУ ЖЕ субстрату: не «зачем» (добродетели), а «КАК единица живёт». Паттерн сам =
ДАННЫЕ (policy-as-data на типе), не хардкод — вектор `ab-unification-2026-09-07` и UNIT-SPEC §4.

| Паттерн | Пример единицы | Состояния | ТЕОРИЯ vs МАШИНА |
|---|---|---|---|
| **Append-only акт** (позвоночник) | `domain_event` / `observation` / `erased` акт в логе | пишется-один-раз → (никогда не UPDATE) → `erased` (терминальный, payload by-ref затирается, хэш-свидетель остаётся) | **МАШИНА:** реально. `Act`-конверт заморожен (`types.ts:348`), `ACT_KINDS` (`types.ts:249`), erased-акт (`erasure.ts`). |
| **Одно-версионно-канонический** | `client` (одна версия навсегда, привязан к менеджеру по дате) | создан → супер-версия (freshest по snapshotHash замещает) → актуальное состояние | **МАШИНА:** реально через CQRS-проекцию: один узел на `source_ref`, freshest-wins (`projection.ts:4-14`). |
| **Материализованная грань** (проекция графа) | day-graph / process-view над актами | акты → детерминированная свёртка → узел графа; `rebuild --from journal` | **МАШИНА:** реально. Граф = проекция лога (ADR-0008), `projection.ts`, поверхности `surface/day-graph.ts`, `process-view.ts`. |
| **Линза-при-чтении** (не хранится) | cost-tree / visible-to / actions-by-agent view | вычисляется на запрос из viewer+policy, не материализуется | **МАШИНА:** реально (структура). `view-compiler.ts`, `ViewDef` (`types.ts:214`), пайплайн `from·traverse·filter·shape` заморожен. Агрегации (sum/avg) намеренно НЕ залочены. |
| **Ветвимо-версионный** | `plan-week` («git по данным», merge глубже git) | draft → active-ветка → (variant-of / версия) → судьба ветки = merge | **ТЕОРИЯ (promise).** Дом развилок есть (`01-values/02-tozhdestvo/03-vetvleniye-i-varianty/`), `variant_of`/bitemporal — форма в `_CARDS` V2; в engine веток/merge-инструмента НЕТ. Минимальный срез назван (`ab-unification`: `plan-week` branchable), не построен. |
| **Затухающий / метаболизирующий** | любая единица с `salience`/`temperature` | nascent → active → cooling → `cold` → (консолидация/эмердженс) | **ТЕОРИЯ (пустой слот).** Форма в `_CARDS` V4; в engine `salience` пуст, decay-движка нет (`day-graph.ts:12-13`). |

## Как две карты соотносятся (кросс-инсайт)

- Ось №1 (ценности) отвечает **ЗАЧЕМ** единица так устроена; ось №2 — **КАК** она проживает время.
- Обе — ВИДЫ над ОДНИМ субстратом (лог + граф + единицы в их состоянии), не второй дом истины.
- **Оси ПЕРЕСЕКАЮТСЯ в одних и тех же зияниях, и главная точка совпадения — V4 Витальность:** «пустой
  слот V4» (карта №1) = «паттерн затухающий = теория» (карта №2). Это одна и та же дыра, увиденная с двух
  сторон: у движка нет вещества метаболизма данных. «Read-side V7» (карта №1) НЕ имеет своего паттерна
  жизни в карте №2 — потому что enforcement согласия ещё не стал веществом, ему нечего проживать.
- Строгие статусы возможностей (🟢 держит / 🔴 обещание / 🟡 не построено) — в
  `capability-map-2026-09-17.analysis.md`.
