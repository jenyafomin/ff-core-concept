# ❓ Двери в одну сторону (retrofit-impossible)

> **status: open — НЕ ратифицировать молча. Каждая дверь = архитектурное обязательство, которое почти
> невозможно «доделать потом». Ретрофит стоит переписи всех данных. Поэтому каждой нужен owner sign-off /
> отдельный ADR ДО стройки, а не тихая фиксация в коде.**

Из лестницы эволюции данных (`DRAFT-data-evolution-ladder.md`, §«Дальний горизонт»): восхождение L0→L4
задумано аддитивным (0 миграций) ТОЛЬКО если эти поля/решения заложены в форму СЕЙЧАС. Отложил — ретрофит
невозможен без переписи. Это делает их несущими развилками, а не деталями реализации.

## 4 необратимые двери

1. **Тройка `author / owner / referent` в паспорте — заложить СЕЙЧАС.** (V7 Согласие, V3 Доверие.)
   Кто написал ≠ кто владеет ≠ о ком запись. Без всех трёх с самого начала нельзя различить согласие/
   атрибуцию задним числом. Ретрофит невозможен: у старых единиц этих граней просто нет.

2. **`canonical_id` = immutable-якорь.** (V2 Тождество, V5 Суверенность.)
   Тождество должно пережить смену типа, движка, merge/split, tombstone. Если id меняемый или
   дериватив-по-содержанию — тождество рвётся при первой же эволюции. Неизменный якорь закладывается один раз.

3. **Ребро — first-class единица** (`id / confidence / stale`). (V6 Реляционность.)
   Связь = полноправная память того же ранга, а не служебная нить. Reserved-форма уже заложена в движке,
   но полноценный паспорт ребра — обязательство: без него нельзя задним числом дать рёбрам доверие/устаревание
   и ссылочную целостность.

4. **Линза = ДАННЫЕ, не enum.** (V1 Читаемость, V5 Суверенность.)
   `ViewDef.kind` сегодня — frozen enum ×3. Держать разморозку доступной: если проекции зашиты как enum
   в код, «вид как переносимая единица» уже не сделать без переписи движка представлений. Связано с
   кандидатом `../ideas/lens-as-data-candidate.idea.md`.

## Явно: чего НЕ делаем
- **НЕ фиксируем** «аддитивное восхождение (0 миграций)» как решённое — его посылки (эти двери) открыты.
- **НЕ пишем** эти обязательства в код без ADR. Форма может опережать enforcement НАМЕРЕННО (поле лежит,
  движок игнорирует) — но само решение «заложить поле» = дверь, и оно требует owner sign-off.

## Вопрос владельцу
По каждой двери: закладываем форму СЕЙЧАС (готовим ADR) или сознательно откладываем, принимая цену
будущей переписи? Порядок/приоритет дверей — тоже за тобой.
