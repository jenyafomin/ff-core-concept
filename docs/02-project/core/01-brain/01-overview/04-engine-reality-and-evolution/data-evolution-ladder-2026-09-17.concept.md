## 1. Иерархия сложности L0→L4

Каждая ступень привязана к КОНКРЕТНОМУ пустому слоту движка `@ff/engine` (не `@ff/core`) и к тесту-возможности
T#, который она перевела бы из 🔴/🟡 в 🟢. Триггер регенерации карты возможностей —
`/Users/mac16/Documents/IT/Apps/FF-Personal-Managment/packages/engine/test/value-collisions.test.ts`.

| Уровень | Что добавляется | Ценности | Пустой слот движка (якорь) | Тест-флип |
|---|---|---|---|---|
| **L0 плоская форма** | поле→значение (`body: Record`) | — (сырьё) | `EnvelopeNode.body` (`types.ts`) | — |
| **L1 единица-с-паспортом** | тонкий паспорт (`id · label · salience · author · referent`) + `edges[]` | V1 (грань дёшево), V2 (id-якорь), зачаток V6 | `ENVELOPE_FIELDS`; `foldEdges` REPLACE/ACCUMULATE | T6/T7 🟢 |
| **L2 кластер единиц** | совокупность типов под `PredicateRegistry` (кардинальность-как-данные) | V6 всерьёз, V3 (provenance) | реестр-впрыск; ядро `DEFAULT_PREDICATES={}` | T3 🟢 |
| **L3 версионируемая система** | CQRS лог→граф→вид; merge/split, bitemporal, freshest-wins | V2 (жизненный цикл id), V3 (аудит) | `edgeCanonicalIdOf` только деривирует; merge НЕ построен (ADR-0015 Reserved) | T2 🟡 |
| **L4 живая система** | метаболизм (salience→cold), консолидация, эмерджентные грани, ФОРСИРУЕМОЕ согласие, произвольные линзы | V4, V1 на пределе, V5, V7-enforced | `ViewDef.kind` — замороженный enum ×3; нет полей `salience`/`confidence` | T1/T4/T5 🔴🟡 |

**«Что по стоку не идут» — несущие, но забываемые механизмы** (каждый — потенциальная ступень внутри уровня):
1. **Ребро-как-память** со своим доверием и `stale`, каскад по типу (V6).
2. **Provenance каждого ПОЛЯ отдельно** — «тихая ложь» в одном поле, не в единице целиком (V3).
3. **Частичное согласие на ГРАНЬ, а не на единицу** (V7).
4. **Конфликт двух паттернов на одной единице** — `one` vs `many` → fail-closed отказ (V1/V2).
5. **Тождество, переживающее merge/split** — `merged_from` / `split_from` (V2).
6. **Salience-градиент** — бюджет внимания принадлежит БАЗЕ, не ячейке (V4).
7. **Линза-как-переносимая-единица** — проекция = данные, не enum (V1/V5).
8. **Тройка `author/owner/referent`** — ретрофит невозможен (V7/V3).

## 2. Апгрейд-путь — 4 шага (ПРЕДЛОЖЕНИЕ, обратимо, каждый требует sign-off/ADR)

Порядок «самая большая дыра → наименьший объём» вперёд. **Ни один шаг не одобрен.** Каждый — архитектурное
изменение, поэтому перед стройкой заводится свой ADR и берётся явное «строй».

1. **Consent-as-read-policy.** `resolve()` / `admit()` начинают ЧИТАТЬ `consent.status` (сегодня поле инертно).
   Закрывает «edge status инертен», флипает T1. Проверяет **V7**. *(Самая большая дыра при наименьшем объёме кода.)*
2. **Метаболические поля-данные** (`salience` / `temperature` / `confidence`) → калибровка доверия + затухание
   до `cold`. Закрывает V4/V3, флипает T4. Проверяет **V4**.
3. **Lens-as-data (кандидат-направление D9/Линза).** Разморозить 3-видовый enum `ViewDef.kind` → декларативный
   реестр линз (projection-as-data); линза = переносимая first-class единица. Физический механизм «один паттерн
   → N поверхностей». Проверяет **V1/V5**. Кандидат, gated на перепись реальных эпизодов.
4. **Identity-lifecycle + portability-handshake.** merge/split/retarget + каскад рёбер (ADR-0015 Reserved→built)
   + `engine_contract_version` / round-trip экспорта. Закрывает T2/T5. Проверяет **V2/V5/V6**.

## 3. Принцип «аддитивного восхождения» — ⚠️ ПРЕДЛОЖЕНИЕ / DEFER

**Гипотеза:** L4 достижим БЕЗ миграций, потому что L1-паспорт УЖЕ несёт поля, которые движок пока ИГНОРИРУЕТ
(`consent.status`, `policy_ref`, `salience`). Форма опережает enforcement НАМЕРЕННО → тогда восхождение = флип
красных тестов в зелёные снизу вверх, аддитивно, без переписывания хранилища.

**Почему это НЕ ратифицировано (честно):** посылка «0 миграций» держится на четырёх **«дверях в одну сторону»**
(схема-обязательствах, которые нельзя откатить дёшево). Пока эти двери ОТКРЫТЫ, «аддитивное восхождение»
остаётся гипотезой, а не свойством системы. Двери и их разбор — в
`./questions/one-way-doors.question.md`. Кратко, четыре двери:

1. **Тройка `author/owner/referent` в паспорт СЕЙЧАС** (V7) — ретрофит после накопления данных невозможен.
2. **`canonical_id` = immutable-якорь**, переживающий смену типа / движка / tombstone (V2/V5).
3. **Ребро — first-class** с `id/confidence/stale` (V6) — Reserved-форма уже заложена (ADR-0015).
4. **Линза = ДАННЫЕ, не enum** (V1/V5) — держать разморозку `ViewDef` доступной.

**Следствие для процесса:** прежде чем строить любой шаг апгрейд-пути или объявлять «аддитивное восхождение»
свойством движка — нужен явный owner sign-off и ADR на соответствующую дверь. До этого документ описывает
НАПРАВЛЕНИЕ, не обязательство.

## 4. Три параллельных направления и точка схождения

Наказ владельца — смотреть данные с трёх сторон одновременно:
- **(а) механика одной единицы** — что кладётся в паспорт;
- **(б) совокупность разных единиц** — как единицы адресуют друг друга;
- **(в) прогон в сложной системе** — как противоречия сходятся.

**Схождение — узел `foldEdges` / `resolve()`:** именно здесь (а) что кладётся, (б) как адресуются, (в) как
разрешаются конфликты, встречаются в одном шве. **День-3 (конфликтный день) — точка схождения всех трёх
направлений**: синтетический сценарий, где сталкиваются кардинальность, дедуп и противоречие источников,
проверяет ровно этот узел. Реализация лестницы-теста —
`/Users/mac16/Documents/IT/Apps/FF-Personal-Managment/packages/engine/test/day-scenarios.test.ts`
(единица L1 → пара L2 → шум/дедуп L2 → конфликт-кластер L3 → совокупность 3 дней в одном движке L3→L4).
