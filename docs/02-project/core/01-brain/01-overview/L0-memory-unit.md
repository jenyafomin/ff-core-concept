## Ядро — что есть единица памяти

**Единица памяти — не тип узла, а РОЛЬ узла (или ребра): взятое вместе с «контрактом повторного входа» —
гарантией, что будущий читатель (часто — ты сам как незнакомец) сможет её НАЙТИ, ОЦЕНИТЬ не вскрывая,
ДОВЕРИТЬСЯ в меру, ВПИСАТЬ под своим углом — и что след её использования вернётся в неё саму.**

- *Память — письмо незнакомцу, которым окажешься ты сам.* Компакт-тревога — ровно это: каждая сессия читает чужие записки.
- **Память замыкается на использование.** Без обратной петли это каталог, а не память.
- **Память — глагол, не существительное.** В мозге нет «клетки памяти» — есть нейроны + то, что сон/гиппокамп с ними ДЕЛАЮТ.

## Главная проблема (через информацию, не через ценности)

Информация рождается **многомерной** (зерно, охват, время, уверенность, перспектива…), а каждый акт
**записи** и **чтения** — **одномерен**. Формула:

> **Как одна запись обслуживает много будущих вопросов, под которые она не писалась.**

Все боли — симптомы одной болезни: многомерному дают один адрес и один застывший вид.
«Субстрат для агентов · дешёвый контекст · накопление между сессиями» — *следствия* решения этой формулы, не суть.

## «Волна и частица» — рабочее разделение

- **Частица** = data plane: узел-запись, тонкий паспорт, честный «коллапс» одной проекции (задекларированной в паспорте). То, что *хранится*.
- **Волна** = access plane: узел через рёбра *является* группой/файлом/пунктом — **зерно есть свойство ВЗГЛЯДА, не вещи.** Живёт в рёбрах.
- **Измерение** = агент втягивает узел в контекст, волна коллапсирует в грань под вопрос. Чтение паспорта без вскрытия payload = *частичное измерение, почти бесплатно* → экономика памяти: **память — то, что можно оценить до покупки.**
- **Инвариант «та же память»** во всех проекциях = `canonical_id` + паспорт.

## Развязка спора «просто узел ⟂ своя природа»

Спор был об этажах — обе ветки правы:
- **Уровень данных:** память = обычные узлы, **0 новых обязательных полей** паспорта (ADR-0002 уже есть контракт памяти).
- **Уровень системы:** своя природа есть, но живёт **не в узле, а в ЦИКЛЕ.**

**Вывод L0:** проектировать надо не новый узел (готов), а **слой процесса** над обычными узлами.

## Цикл — 6 глаголов в 3 фазах

**A. Вход** — 1. **Записать** (честный коллапс + декларация проекции в паспорте).
**B. Доступ** — 2. **Найти** (pull + push) · 3. **Оценить** (послойно: паспорт → title/desc → payload) · 4. **Действовать·Подтвердить** (агент применил узел → результат вернулся как confidence-сигнал; Act без следа — просто чтение).
**C. Метаболизм** — 5. **Переработать** (консолидация/дедуп/реконсолидация; меняет *содержимое*, риск искажения) · 6. **Забыть** (меняет *доступность*, не содержимое; риск потери / «зомби-памяти»).

**Забыть отделено от Переработать намеренно:** разные контракты отката (Rework → версия/форк; Forget → восстановление доступа + гарантия невлияния через эмбеддинги/копии). Самый болючий — **фаза C (метаболизм):** именно она отличает *память* от *лога* и лечит компакт-тревогу.

## Ребро — полноценная единица памяти

Инсайт «A → B» *по природе* — ребро, не узел. Ребро повышается до гражданина 1-го класса:
- **Собственный тонкий паспорт ребра:** `canonical_id · confidence · provenance · last-verified`.
- **`priority` (важность на ребре, ратифицирована) ≠ `confidence`:** priority = «насколько важно отсюда», confidence = «насколько это правда». Не путать; паспорт добавляется К priority, не отменяет.
- **Глаголы Подтвердить и Забыть применяются к рёбрам тоже** (устаревший инсайт опровергается и забывается).

## Оси многомерности: канон vs производные

Ось в **канон**, только если по ней надо *отдельно фильтровать / забывать / действовать*.

**Канон (6):** 1. Зерно (зум) · 2. Охват/scope (общая·проект·агент·пользователь) · 3. Время-истинности **+ Волатильность** (когда было верно / как быстро протухает — запускает Забыть) · 4. Уверенность (теперь *процесс*, Подтвердить пишет сюда) · 5. Ставки / цена ошибки (управляет глубиной «Оценить») · 6. Перспектива (level why/what/how/data).

**Производные / не в канон:** провенанс (вход для расчёта уверенности, живёт в паспорте ребра) · стоимость верификации (= ставки × волатильность × хопы) · модальность кодирования (L1-инженерия) · адресат (свойство запроса, не узла — память мультиарендна).

> Из 11 предложенных осей — 6 в канон, 5 из них уже покрыты паспортом. **Новое по сути одно: волатильность/ставки как явные управляющие оси метаболизма.** Мощнее, но не тяжелее.

## Метафоры — пара по слоям

- **Data plane (хранение):** **«запись в бортовом журнале»** (уточнённое «письмо») — адресована многим, датирована, машина сканирует корешок-паспорт тысячи раз дёшево, payload вскрывают редко.
- **Access plane (проактивность):** **«запах / резонанс»** — частица *пахнет* по осям; когда контекст резонирует, она всплывает сама (push, ассоциативный триггер).
- Формула: **память хранится как журнал (частица), но работает как запах (волна).**

## Истинные ЦЕЛИ единицы памяти (мост к L1-ценностям)

> Свод: Fable (9 целей, отделены от средств) + независимый критик (9 пропущенных + 2 сдвига границы + слепой угол). Средства (паспорт, цикл, salience, классы) — НЕ цели. Ниже — только «ради чего». `★` = несводимый костяк (Fable).

**Группа 1 — Дёшево понять и достать**
- **Г1 ★ Оценить не вскрывая** — понять «стоит ли брать» до оплаты содержимого.
- **Г2 Найтись двумя путями** — по запросу (pull) и по резонансу (push/«запах»).
- **Г3 Сжаться в сводку под бюджет контекста** — сотни единиц → одна сводка без потери контракта доверия (rollup).
- **Г4 Читаться человеком без агента-посредника** — независимый канал проверки, если агент сломан/скомпрометирован.

**Группа 2 — Отвечать многим вопросам**
- **Г5 ★ Обслужить вопрос, под который не писалась** — ядро-цель.
- **Г6 Читаться на любом зуме одним правилом** — самоподобие (группа/атом/ребро — снаружи дёшево, внутри дорого).

**Группа 3 — Живое, калиброванное доверие**
- **Г7 ★ Держать актуальную степень истинности** — доверие меняется от использования, не застывает.
- **Г8 Знать свою временную годность (вперёд)** — сама сигналит «протухаю/вечна».
- **Г9 Помнить, что утверждала в МОМЕНТ решения (назад)** — снапшот для аудита «почему агент так сделал».
- **Г10 Нести происхождение/цепочку авторства** — источник значим сам по себе (финансы, юр. данные).
- **Г11 Защита от отравления памяти** — кто вправе писать подтверждение; откат массовых ошибочных «подтверждений».

**Группа 4 — Жить и эволюционировать**
- **Г12 ★ Меняться не теряя себя** — переработка/забывание без потери тождества.
- **Г13 Масштаб по «температуре»** — один контракт на 5 живых решений и 20 тыс. холодных строк.
- **Г14 Носить свою политику жизни** — автономия (видимость, распад, всплытие) без внешней схемы.
- **Г15 Хранить бюджет внимания как ИНВАРИАНТ** — не всё может стать важным разом; иначе «один рычаг salience» тихо развалится на два скора.

**Группа 5 — Множество единиц вместе**
- **Г16 Мультиарендность** — разные агенты читают/пишут след одной единицы без молчаливого затирания.
- **Г17 Заявить конфликт с другой единицей** — противоречие видимо третьему, иначе тихая деградация доверия ко всему графу.

**Группа 6 — Границы, доступ, перенос**
- **Г18 Разграничение доступа/приватность** — уметь не только объяснить, но и СКРЫТЬ себя (иначе утечка по умолчанию в любой plug-in).
- **Г19 Портируемость между системами** — пережить смену хоста/схемы/агента (plug-in/маркетплейс в видении).
- **Г20 ⚠️ СЛЕПОЙ УГОЛ: чья это память, когда предмет — третье лицо.** Данные о людях, не давших согласия быть узлом в чьей-то базе. Взрывоопасно в момент маркетплейса. Ось «за/для кого память», которую вся конструкция пока не видит.

**Сдвиг границы (средство, которое на деле ЦЕЛЬ):**
- **Раздельность паспорта и payload — это ЦЕЛЬ, не побочка** (иначе кто-то «упростит», склеит, и Г1 станет недостижима незаметно).
- Бюджет внимания (Г15) — то же: инвариант, а не деталь реализации.

## Запрос Fable на аналитику (3 точечных ресёрча, prior art — чтобы цели→ценности стояли на прецеденте, не на вкусе)
- **Р-1 (приоритет 1). Живая память и забывание** — cross-domain: когнитивистика (spacing, консолидация), кэш-политики (LRU/LFU/ARC/TTL), LLM-memory (MemGPT, generative agents). → какие 2-3 модели «фаз фокуса» реально работают и переносимы. Питает Г8, Г12, salience.
- **Р-3 (приоритет 2). Знание, носящее свой контракт (self-describing/portable)** — RDF/JSON-LD, data contracts, W3C PROV, confidence/temporal на рёбрах KG. → минимальный набор полей для переносимости без внешней схемы. Решает судьбу ребра-с-паспортом. Питает Г1, Г7, Г14, Г19.
- **Р-2 (приоритет 3). Классы данных по «температуре»** — hot/warm/cold tiering, data lifecycle, CQRS, lambda/kappa. → где проходит граница живое/холодное и по каким метрикам. Питает Г13.
- НЕ исследовать: нашу кодовую базу, Obsidian-заметочники, общий обзор «что такое память».

## Грани-кандидаты, раунд 2 (владелец, 2026-07-05 голос) — к учёту в целях/ценностях

- **Г21. Многомерность «одна единица — записана по-разному» + чистка.** Как одна и та же единица живёт в разных записях/проекциях и как её нормализовать/чистить (частично = Г5/Г13, но нужно явно).
- **Г22. Пополнение через адаптеры + общий конфиг.** Данные втягиваются извне через адаптер (напр. Telegram), есть общий конфиг, откуда тянем; данные пересекаются между собой.
- **Г23. Данные со своим паттерном / гибкость.** Понимание ВСЕХ возможных аспектов ценности, которые могут быть критичны; у данных свой паттерн; гибкость единицы.
- **Г24. Приватность в scope проекта + роли + «свой мир».** К проекту можно подключить кого-то, кто видит НЕ всё; у единицы/проекта «свой мир»; разные задачи/роли; гибкое подключение — «живая часть системы». (расширяет Г18)
- **Г25. Проявление в пространстве: наследование · варианты · переиспользуемость.** Варианты (напр. разные планы недели) записаны по-разному; в момент планирования — переключение ВЕТКИ; каждый вариант = независимая ячейка, возможно не связанная с другими вариантами; связанность отображается интересно.
- **Г26. Типы со своими структурами.** Разные типы могут нести свои своеобразные структуры.
- **Г27. Данные + API / внешняя база модуля.** Модуль с большими данными выносится в свою личную БД, сам управляет; достаётся через API с чёткой инструкцией; кэш с жёстким удалением; сохранять/документировать API и коннекторы внутри проекта.

## Решения Opus по В2/В4 (после ресёрча Р-1/Р-3, делегированы владельцем)

- **В4 — ДА, ребро-с-паспортом, но узко.** Повышаем до 1-го класса НЕ все рёбра, а только **рёбра-утверждения** (инсайты «A→B», выведенные паттерны). Мин. паспорт ребра = `confidence · provenance(wasDerivedFrom) · valid-time · epistemic` (подмножество узлового, RDF-star-стиль — метаданные НА связи, связь не становится тяжёлым узлом). Структурные рёбра (home, facet-of) паспорт НЕ несут. `priority` остаётся отдельно. → снимает страх «вдвое больше сущностей».
- **В2 — ни чистый форк, ни слепая мутация: BITEMPORAL-версионирование.** `canonical_id` стабилен; каждое изменение = новая темпоральная версия (valid-time + transaction-time); старое читается «as-of T» (аудит Г9), но «текущее» чисто. Забыть = закрыть transaction-time, не удаляя (Г12). Форк (новый id + `variant-of`) — только для намеренных ВАРИАНТОВ (Г28), не для эволюции одной ячейки.

## Ответы владельца (2026-07-05, голос) + маршрут решений

- **В1 — РЕШЕНО, с разворотом.** Не единый глобус «агрессивность забывания», а **свойство самих данных**: у информации есть «вектор» — часть **живая** (освежается, метаболизируется), часть **холодная** (20 тыс. пользователей, аналитика, данные для модулей) — её не «забывают», её фильтруют/ищут; это другая сфера со своими правилами. → **Разные КЛАССЫ памяти = разные правила метаболизма.** Забывание не бинарно (видно/не видно), а **фазы видимости / грань фокуса** — карточка плавно теряет фокус; фазы единица может сама настраивать (2 или несколько). Новая грань: у ребра/группы может быть **своя внутренняя структура-уровни** — L0=схема/индексы «для системы, что всё контролирует» (control plane, оптимизируем) → далее overview → далее сам контент (без нумерации). Часть данных этой структуры не имеет — просто данные.
- **В2 — делегировано Opus.** Владелец: «я за любые изменения во благо; выбери так, чтобы получилась ОДНА единая ячейка-конструктор, отвечающая на разные вопросы для любых систем и данных — реальный нужный инструмент». → решаю я.
- **В3 — ОТКРЫТО (тонкая грань).** «Запах» = возможно составная часть разных групп, где был контекст, который единице мог быть нужен, а мог и нет; связано с «гранью фокуса» (В1). Обдумать, не закрывать.
