- **Потребитель:** каждая новая сессия/агент про память и шлюз · **Поглощает:** разрозненные «NEXT» из хендоффов арки 2026-10-05…09 (они остаются как trace)

## Цель (одной мыслью)
ОДНА память на всё. Агент, система и владелец работают ЧЕРЕЗ неё. Ядро типов запечатано, плагины приносят группы
типов и связываются рёбрами → позже маркетплейс. Кухня шлюза тоже переезжает в память — по лестнице.

## Как решаем (наказ владельца, не обсуждается)
1. От **7 ценностей** (`01-values/_CARDS-2026-07-08.md`).
2. **Компаунд-инжиниринг** (`~/.claude/rules/compound-engineering.md`): шаг может быть дольше, но удешевляет следующие;
   НИКАКИХ «теперь всё переписываем» (файлы→Postgres = добавочный адаптер); не плодить путаницу.
3. Одному агенту не доверять: каждый артефакт — другой агент-критик. Спорное → альтернативы владельцу.
4. Скорость результата: идём кратчайшей лестницей, но без закрывания дверей.

## Принятые решения (ratified 2026-10-09)
- **ADR-0016** approved — мозг = отдельный сервис (pm2 + MCP), файловый журнал сейчас (отступление от ADR-0006 принято).
- **ADR-0017** approved — `docs/architecture/ADR/ADR-0017-type-layers-packs-storage-seam.md`:
  F1 ядро = голые имена + валидатор `CORE_NAMES`; остальные `pack:`/`sys:`/`u:` · F2 Postgres = добавочная проекция
  журнала (хук `JournalSink`), по триггеру ~50k актов/запись >200мс · F3 плагин пишет как `pack:<id>` · F4 класс хранения —
  резерв · F5 первый бумажный плагин = баг-трекер · **F6 кухня шлюза → память по лестнице R1–R6** (правда в памяти,
  горячая копия локально; свод `M-G3…/analyses/2026-10-09-plugins-and-system-types/f6/SYNTHESIS-f6.md`).
- **G1** влит в шлюз (`agents-manager` `feat/phase-0-unblock` @ `9a12bda`): мозг-MCP за флагом `GATEWAY_BRAIN_MCP=1`
  (выкл.), стоп-лист `~/.ff-brain` активен сразу. Нужен рестарт pm2 `agent` (владелец).
