Потребитель: следующая сессия (старт прогона). Поглощает: обзор Explore-агента 2026-10-31.

## Что там (факты обзора)
- Живой продукт: аналитика аренды авто (Дубай, ~20 авто), Sheets → PostgreSQL → порталы P1/P2/инвестор + Telegram; NestJS, 21 домен, ABAC-пакет; Phase 5 почти готова.
- Знания: 795 md в `docs/` (plan 622: p2-platform 310, domains 265; architecture 56; ba 9; spec 18; discovery 29). Связи — markdown-ссылки + id в тексте: BP (314 упоминаний), ADR (104), GAP (58), BR (42), BUG, FEAT. Frontmatter у 55 файлов, `status:` у 26; статусы задач — в таблицах `_INDEX.md`.
- Гниение: `plan/_INDEX.md` не обновлялся с 2026-04-09; дубли ADR-0001/0002; 12 файлов handoff/next-session в одной ленте; `old (deprecated)/`.
- Повторяющийся шаблон «тип + статус + время + связи» в коде: заказ, задача, транзакция, штраф, машина, претензия, перегон, клиент (`packages/types/src/enums/*-status.enum.ts`).
- ПДн клиентов: `customer.types.ts`, таблица `documents`, `crmRawData`, фото в `apps/back-end/data/uploads/`, `data/raw`.

## Оценка
- **Платформу НЕ переписывать на память.** Операционные данные (брони, клиенты, деньги) остаются в её Postgres; ПДн — никогда в ff-brain (V7 не форсится).
- **Слой ЗНАНИЙ — идеальный первый живой случай.** BP/BR/GAP/ADR уже «единицы» с id, но живут текстом: статусы в таблицах, связи вручную, индекс сгнил. Память = адресный слой: запись на каждую единицу (`source.ref`+`hash`, тело в git), тип, статус, рёбра (BP реализует BR, GAP висит на BP, ADR решает GAP). Карта/виды отвечают: «открытые GAP по процессу», «правила без процесса», «что устарело (hash изменился)».
- **Проверяет шаг 3 свода** (типы ДАННЫМИ): `business-process`, `business-rule`, `gap`, `adr` — реальные ≥2 новых типа без кода.

## Цена (следующая сессия)
1. Область (слаг навсегда, напр. `rentacar`) + `/access` — 10 мин (владелец).
2. Скан ПДн/секретов по `docs/ba`, `docs/spec` (есть `m8-scan.mjs` в launch-kit) — 15 мин.
3. Импортёр-адресов: парсер id BP/BR/GAP/ADR → записи-адреса + рёбра — ~0.5 дня (builder) + ревью.
4. Типы как данные (шаг 3 свода, с закрытием дыры V3) — 1–2 дня; до него — `note` + `fields.kind`.
5. 3–4 вида-вопроса владельца по бизнесу — после 3–4.

Итог: отложено до старта следующей сессии по слову владельца; начать с пунктов 1–2.
