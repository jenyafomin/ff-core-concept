## 3. Слой людей (п.8) — безопасность и дыра
Дверь реальна наполовину: id случайный (`domain/ids.ts:23-25`), имён в id нет по построению; `name` — единственный разрешённый ключ (`schemas.ts:37`), значение всё равно сканируется. Но:
1. 🔴 Стирание (`erased`, `engine/src/core/erasure.ts`) НЕ подключено в `@ff/brain` (grep erase по `brain/src` пуст) → дверь односторонняя только на бумаге.
2. 🔴 `label_hint` у `person` = «имя + роль» (`genesis.ts:163`), а `label` виден в `find` и соседях. Имя в label вне payload. Правило слоя: label person = роль/хэндл, имя только в `fields.name`.
3. 🔴 Person-узлы `readable_by` только владелец (`pii-scope.ts:101-115`), невидимые цели читаются как dangling. Значит агент НЕ может использовать слой людей как знание — п.8 «не только риск» сейчас невыполним. Проектное предложение (B5/архитектору): парный узел-псевдоним (pii none, роль/отношение) с `referent` к настоящему person; агент ходит по псевдониму, стирание чистит только person.
4. Решение 10-10 п.7: неделя 1 без третьих лиц → жизнь слоя = 0 по решению.
