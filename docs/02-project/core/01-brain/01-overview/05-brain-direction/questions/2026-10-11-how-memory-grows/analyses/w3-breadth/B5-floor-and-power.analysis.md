## 0. Главная находка
Пол недели 1 — это не «построить hard_erase». Это **три решения-двери до первой записи**, потому что в журнале append-only необратимы разные вещи на разных уровнях:

| Что необратимо в неделе 1 | Чем держится сегодня | Источник |
|---|---|---|
| payload (label, fields) лежит **inline** → стереть можно только переписью журнала | ничем; seam в engine требует by-ref | `engine/src/core/erasure.ts:117-121`, `brain/src/domain/to-act.ts:169` |
| `actor` = принципал привязки чата/топика; `agent_id` принимается заголовком и нигде не пишется | ничем | `brain/src/domain/validate-act.ts:541`, `contract.ts:575` |
| `provenance` (`source.ref`, `derived_from`) — неизменяемая мета, вне зоны стирания | дисциплина: имя в пути файла останется навсегда | `erasure.ts:38-50` |
| копии: 14 бэкапов, зеркало, `journal-torn-*` (не прунятся), `outbox/`, транскрипты шлюза | ничем | `service/backup.ts:4-5`, `contract.ts:144`, `brain-mcp/src/outbox.ts:5-7` |
| имена и секреты в тексте | промпт «граница на тебе»; код ловит только email/телефон | `PROMPT-memory-protocol.md:12`, `admission.ts:76,81,157-160` |
| агент пишет `active` по умолчанию; `proposed` только если сам поставил `initiative` | это и есть «доверие Всегда» (10-10 п.9) | `validate-act.ts:577` |

Держит **кодом**: id без смысла (`ids.ts:1`), referent≠owner → видимость owner (`validate-act.ts:589-594`), агент не может сам стать owner-authority (`contract.ts:535-537`, `validate-act.ts:354-357`).

## 2. Узел-«против»
Сильнейший аргумент: один владелец, ноль данных, неделя 1 — «только свои задачи без имён». Единственный необратимый риск (имена) закрыт промптом и фильтром, а hard_erase для журнала в папке 0700 — удалить строки и бэкапы руками. Строить by-ref и tombstone до живых данных — слой N+1 без живого N (START §6). Рамка «стирание» подменяет К4: настоящий пол — не что стереть, а что **не попадёт** в журнал.
Верно для payload; не верно для `actor`, `provenance` и копий — они необратимы или размножены в день 1. Вывод: **ветвь B5 целиком — не «куда сейчас», её дверной срез — да.**

## 3. Дыры, которых никто не назвал
1. **Слой людей (п.8) опирается на фразу «в id/рёбрах/провенансе нет имён».** Код гарантирует только id. Провенанс и `note` ребра — свободный текст; фильтр ловит email/телефон, имя пройдёт. Односторонняя дверь B4 держится дисциплиной, не кодом.
2. **Восстановление из бэкапа (RUNBOOK:132-142) возвращает стёртое.** Стирание без зачистки копий — декоративное; а зеркало `~/Backups/ff-brain-mirror` вообще вне сервиса.
3. **«Владелец утверждает» — через агента.** Сообщение владельца доходит до мозга как authority=agent; owner-authority только у мандата шлюза. Пути «владелец нажал да» в коде нет (w1 inventory §1: пинга нет) — очередь proposed копится без читателя, а F2-бюджет «≤5 дел» нечем мерить.

## 5. Оценка «куда сейчас»
Формула Fable: целиком 2 × 0.3 × 0.5 = **0.3** (код в brain отсутствует, чтения не даёт). Дверной срез (inline-door, floor-k4, principal-collapse): 3 × 1 × 0.5 = **1.5** — решения без кода. Контур B1→B3→B2 ≈ 4. Вывод: B5 не конкурент контуру, а **чек-лист перед шагом 5 RUNBOOK** (час владельца, не волна агентов). Формула слепа ко времени закрытия двери. Уверенность 0.6; код читала одна линза, тесты не запускались.

Итог: решение (для W5) — вынести три двери в гейт «до первой записи»; задача в плане — реестр К4 с колонкой «кто держит»; отложено до первой реальной записи — erase-in-brain, retention, consent-use, trust-policy.
