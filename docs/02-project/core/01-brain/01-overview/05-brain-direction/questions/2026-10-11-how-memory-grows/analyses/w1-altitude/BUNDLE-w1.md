## а) Что поняли о глубине (≤8)
1. «Растёт» склеивает три роста: содержимое / форма / правила роста (abstract §1). Ловушка — проектировать третий (слой N+1) вместо первого.
2. Настоящая проблема — не данные, а утечка хода мысли между сессиями; и внимание владельца как самый дорогой ресурс.
3. Вещество одно, власть разная: агенты пишут акты, правила роста меняет только владелец (поправка к конституции).
4. Курица уже есть (цикл в доках). Яйцо = **чтение обратно**: следующая сессия берёт открытые вопросы из памяти, не из START.
5. ~80% механики роста выражается существующими `record/link/decision/derived-from/supersedes/initiative:agent` (analyst §4); недостаёт процесса и запуска, не кода.
6. «Сильная база» верна для сервиса и дисциплины, ложна для готовности к росту: в мозге 0 записей, `ff-brain` не в pm2 (critic §0).
7. Голос агента — не бюллетень: одна семья моделей = один независимый голос; решает владелец; число «за» якорит.
8. Главный риск — рекурсия: исследование роста исполняется процессом роста и ничем внешним не проверяется. Лекарство: у каждого вывода опровергаемое предсказание о живом мозге + дата.

# Линза высоты (w1): что значит «память развивается» — и верно ли поставлен вопрос
- **Status:** draft · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-11
- **Потребитель:** лид + помощник волны 1 · **Поглощает:** ничего
- **Вопрос-цель:** «Как должна РАЗВИВАТЬСЯ сама система памяти — и правильно ли мы вообще ставим этот вопрос?»
- **Опора:** `../../../../START-NEXT-SESSION.md` · `../../../../ideas/2026-10-11-constructor-for-ai.idea.md` · `../../../../analyses/2026-10-11-capture-graph-intake/metamorphosis/abstract-growth-pattern.analysis.md` · `.../altitude/question-genealogy.analysis.md` · `../../../../../01-values/_CARDS-2026-07-08.md`

## 1. Лестница абстракции: что на самом деле «растёт»
Во фразе «память развивается» склеены **три разных роста**:
1. **Содержимое** — записи жизни (задачи, люди, источники). Растёт само, от использования.
2. **Форма** — паттерны, типы, линзы, пороги («тип = тропа»). Меняется реже, по итогам использования.
3. **Правила роста** — как мы решаем развилки, кто голосует, когда владелец говорит «да». Сейчас живут **вне памяти**:
   в `.claude/rules/` (петля высоты, рекурсивная оркестрация, дома-темы) — то есть в Claude Code, «первом прототипе конструктора».

Ступени «зачем»:
- Зачем памяти развиваться? → чтобы решения о проекте не терялись и их было дёшево пересмотреть.
- Зачем это? → потому что главная потеря проекта сейчас — не данные, а **ход мысли**: сессии стартуют «с холода»,
  START-файлы переписываются руками, docs:code ~14:1.
- Зачем это владельцу? → **его внимание** — самый дорогой ресурс; рост должен его экономить, а не съедать.

**Настоящая проблема:** не «как растёт память», а «**как мышление проекта перестаёт утекать**, становясь данными в той же
памяти, при неизменном полу и с владельцем как последней инстанцией».

**Проверка гипотезы «процесс мышления и память — одно вещество».** На уровне ФОРМЫ — да: развилка = узел, голос агента =
ребро с паспортом (`author`, `confidence`), решение = акт с `derived_from` (уже в `abstract-growth-pattern` §1). Но гипотеза
неполна в одном месте, и оно несущее: **вещество одно, ВЛАСТЬ разная.** Если правила роста живут в памяти как данные, процесс
может переписать сам себя. Нужна неподвижная точка: пол (V7, стирание, id без смысла) и «да» владельца — вне досягаемости
самого цикла. Значит: обычный рост = агентские акты; изменение правил роста = **поправка к конституции**, только актом владельца.

## 2. Курица и яйцо: где рвётся цикл
**Аналогия — раскрутка компилятора (bootstrapping).** Первый компилятор языка пишут на другом языке; потом он компилирует
сам себя. Стадия 0 у нас уже идёт: цикл роста живёт в доках (эта папка — ручной прототип журнала). Курица уже есть.

**Точка разрыва — не запись, а ЧТЕНИЕ ОБРАТНО.** Цикл начинает жить в памяти в тот момент, когда **следующая сессия берёт
открытые вопросы из памяти, а не из START-файла**. Минимальный шаг:
- в мозге есть узел-вопрос «как должна расти память?» + 1–2 акта, ссылающихся на него (`derived_from`);
- в начале следующей сессии лид получает список «открытых вопросов» запросом к памяти — пусть один, пусть вручную.

Запись без чтения — архив, а не жизнь (совпадает с критерием START §3: «запись, которую агент достал не по пути из дока»).

**Что делать руками ДО этого:**
- Держать доки **изоморфными будущим записям**: у каждого файла `id`, `derived_from`, `author`, `status` во frontmatter.
  Тогда перенос = копирование, а не переосмысление (компаунд).
- Не переносить правила роста (`.claude/rules`) в память раньше времени — это слой «система» (N+1), гардрейл.
- Помнить: стадия 1 зависит от трека А (владелец запускает RUNBOOK). Без запуска — честно «бумага».

**Тест эквивалентности (из раскрутки компиляторов):** память-стадия-1 должна воспроизвести то, что даёт стадия-0 —
свежий агент объясняет решение ≤5 строк по линзе «почему». Уже заложено в семя — подтверждаю.

## 3. Развилки + голоса + «владелец в курсе»: лучшая модель
| Аналогия | Что даёт | Чем врёт |
|---|---|---|
| Парламент | голосование | большинство решает — у нас голос агента ≠ решение; **отбросить** |
| Git | история, blame, ветки | не знает «почему» и несогласия; хорош как журнал, не как форма развилки |
| Эволюция | накидать → отбор → отвергнутое остывает | слепа, нет цели; хороша для цикла роста |
| Иммунитет | своё/чужое, защита от отравления | хороша для пола (V3), не для развилок |
| Научный метод | гипотеза + как опровергнуть | нет инстанции «кто решил» |
| **Прецедентное право** | **лучшая** для формы развилки | медленное — нужен триаж |

**Главная модель: суд прецедентов + научная оговорка.**
- Развилка = **дело**. Агенты-линзы = эксперты/стороны; их голоса = **мнения с автором и уверенностью**.
- **Особое мнение сохраняется** (это закон 8: расхождение линз = сигнал). Отщепенец не стирается — остывает (V4).
- Владелец = **последняя инстанция**; решение = **прецедент** с коротким «почему» (ratio, V1) и ссылками на мнения (V3, V6).
- Будущие дела **цитируют прецеденты**; отмена прецедента не стирает старый (V2, LOSE-NOTHING).
- От науки: у каждого решения есть **условие пересмотра** («вернёмся, если …»). Так решение само знает, когда оно устарело (V3).

**Что следует для формы (без новой машинерии):**
- Узел-развилка: вопрос · рамка · мнения (рёбра `opinion_of`, `author`, `confidence`) · особые мнения · решение
  (акт владельца) · ratio ≤3 строки · условие пересмотра · статус.
- «Владелец в курсе» = **реестр дел** (одна линза «ждёт тебя»), а не поток уведомлений по каждому акту. Бюджет внимания
  владельца — параметр (данные), не случайность.
- **Триаж обязателен:** не каждая развилка — дело. Несущие (меняют вектор, необратимы, двери) → дело. Остальные → агент
  решает сам с записью акта. Иначе церемония съест внимание (анти-ценность).
- Голосов не считать: это доказательства с весом, а не бюллетени.

## 4. Ловушки рамки
**Ловушка А — «память о памяти» без жизни.** Рост, который питается только собой (вопросы про память → ответы про память),
это замкнутый контур без входа. Риск повторить историю проекта: красивый процесс над пустым хранилищем. Цикл роста нужен
**корм** — жизнь владельца (туду, люди, источники).
**Ловушка Б — склейка трёх ростов** (§1). Обсуждая «как растёт память», легко проектировать правила роста (слой N+1),
когда растить надо содержимое (слой N).
**Ловушка В — церемония.** «Все вопросы через разных агентов» масштабируется в бюрократию; дорожает каждое решение.

**Переформулировка 1:** «Как сделать, чтобы решения проекта переставали теряться и дёшево пересматривались — так, чтобы
**первым реальным жильцом** памяти стал её собственный процесс решений, но не единственным?»
**Переформулировка 2:** «Какой процесс решения развилок мы **уже** ведём руками — и что в нём ломается, если перенести
его в память без изменений?» (описать существующее, а не проектировать новое).

**Вопрос, вскрывающий неверную рамку:** «Если убрать из памяти всё, что она знает о самой себе, — ради какой ситуации из
жизни владельца она всё ещё нужна на первой неделе?» Нет внятного ответа → мы строим зеркало, а не память.

## 5. Вопросы высоты для следующей волны
1. **Граница власти:** что в росте памяти может менять агент сам, а что — только акт владельца («поправка к конституции»)?
   (Родня вопроса генеалогии «где граница пол/паттерн и кто её двигает».)
2. **Триаж:** по какому признаку развилка становится «делом», а не рядовой правкой? Сколько дел в неделю владелец готов читать?
3. **«В курсе»:** владелец хочет реестр, который открывает сам, или толчки? Что для него «не в курсе» — какой эпизод это показал?
4. **Чтение обратно:** какое первое чтение из памяти (не запись!) докажет, что цикл живёт в ней?
5. **Корм:** какую долю первых записей занимает «мета» (память о памяти) и где порог, после которого это избегание жизни?
6. **Пересмотр:** как решение узнаёт, что пора его пересмотреть, — и кто будит дело заново?

## Ценности — кратко
Укрепляет: V1 (ratio ≤3 строки), V2 (отмена прецедента не теряет тождество), V3 (провенанс мнений, условие пересмотра),
V4 (особые мнения остывают), V6 (голос = ребро). Напряжение: **V5** — правила роста сейчас зашиты в Claude Code, не в
данных; переносимы станут только как policy-as-data (позже, слой N+1). **V7** — голоса агентов без третьих лиц; ок.

Итог: решение (предложение) — рамка «одно вещество, разная власть» + модель «суд прецедентов с условием пересмотра» + точка разрыва «первое чтение обратно из памяти»; вопросы §5 — вход волны 2; правила роста в память не переносить до живого слоя N.
Вопрос-цель: ответил частично — вопрос был поставлен неточно, потому что склеивал три разных роста (содержимое / форма / правила роста) и не различал «то же вещество» и «ту же власть».

**Вопрос-цель:** где направление «сначала понять, как должна расти система памяти» нас обманет или потратит время?

Факт-проверка на входе (2026-10-11): `pm2 jlist` показывает pg, healer, agent, cdx-* — процесса `ff-brain` НЕТ. Мозг не запущен. Трек А = ноль.

## 1. Пять способов, как трек Б станет очередным витком «анализа как избегания»

**1.1. Рекурсия: исследование роста само есть цикл роста.** Семя «как должна расти память?» исполняется ровно тем процессом, о котором оно спрашивает (накидать → сгруппировать → расширить → критик). Результат нельзя проверить ничем, кроме самого процесса: замкнутая петля без внешнего эталона. «Курица и яйцо» из п.24 превращается в оправдание: бумага сама себя доказывает.
- Признак в моменте: критерий «готово» читается как «свежий агент объясняет решение ≤5 строками» (START §5.3) — это проверка понятности, не правильности. Если к концу ни один вывод не мог бы оказаться ложным — это оно.
- Предохранитель: каждый вывод цикла обязан нести **опровергаемое предсказание о живом мозге** («после 7 дней в мозге будет ≥N узлов-вопросов с ≥1 ответом-агентом, иначе вывод неверен»). Без предсказания — в `ideas/` как candidate, не в `decisions/`.

**1.2. Волна 1 из четырёх линз — это 4 новых файла про то, что уже написано.** Инвентарь «сильной базы» (analyst) + рамка (abstract) + развилки (architect) пересказывают START, INTAKE, constructor-idea, генеалогию (~31 вопрос), 566 .md в `01-brain`. Код+тесты брейна ≈22k строк против ≈38k строк md в том же дереве, а по проекту в целом исторически 14:1.
- Признак: в свод попадает доля фраз, которых нет в источниках, <30%; «новое» — переупаковка (лестницы, таблицы слоёв).
- Предохранитель: от analyst — не инвентарь, а **список «что из базы ни разу не исполнялось»** (file:line теста/кода либо «только текст»). Волна 2 не стартует, если волна 1 не вернула хотя бы 1 вещь, которую можно сделать руками сегодня.

**1.3. «Развилки как отдельные глубокие вопросы» — фабрика вопросов без потребителя.** Наказ: каждая развилка → глубокий вопрос → голосование → решение. Генеалогия уже дала ~31 вопрос, К0–К5 ещё 6; новая волна даст ещё 10–20. Правило altitude-loop само ограничивает 3–7, но «развилки» обходят лимит, потому что названы не «вопросами», а «развилками».
- Признак: число open-вопросов в `questions/` растёт быстрее, чем `answered` (compound-engineering триггер 6: «открыто +N / закрыто M»).
- Предохранитель: тест значимости из прошлого критика («изменит ли ответ действие в ближайшие 7 дней?») применять к КАЖДОЙ развилке; нет → parked без обсуждения. Бюджет: ≤5 развилок, остальные в одну строку.

**1.4. Протокол голосования и «владелец в курсе» — это уже построение «машины голосования», которую START §6 прямо запрещает.** Постановка просит system-architect дать «протокол голосования + как владелец в курсе, в терминах примитивов памяти». Это проектирование слоя N+1 (процесс решений) до живого N (ни одной записи). Запрет §6 «машину голосования / движок процессов» обходится словом «протокол».
- Признак: в выходе появляются роли, статусы, пороги кворума, схемы типов (`vote`, `decision`) — любые новые типы узлов.
- Предохранитель: протокол допустим только как **чек-лист из ≤7 строк, исполняемый руками лида над файлами в `questions/`**, без новых типов в мозге (ADR-0017). Тип рождается после 3-го ручного повтора.

**1.5. Подмена «чьей» проблемы: владелец-в-курсе решается документами, а его реальное узкое место — его внимание.** Проект 4 месяца, владелец уже не успел прочитать часть ночных материалов (п.7 зёрен). Каждый новый артефакт увеличивает долг чтения. «Владелец в курсе» через ещё больше md — противоречит цели.
- Признак: итоговый артефакт владельцу >1 экрана или требует прочесть >1 файла для решения.
- Предохранитель: выход волны = **один OVERVIEW на ≤30 секунд** + не более 3 вопросов с дефолтом «ок» (по правилу theme-homes). Остальное — приложение.

## 3. Как задача могла быть дана неверно

Гипотеза-рамка лида: владелец просит «спроектировать рост» (трек Б, цикл в доках). Альтернативное прочтение его слов («все вопросы, идеи, коррекции прогоняются через разных агентов и развиваются; развилки голосуются; владелец в курсе; память сама с этим работает»): это **описание желаемого режима работы, который можно начать сегодня**, а не тема исследования. Любой вопрос/идея сегодняшней сессии (включая ЭТУ волну) — уже сырьё для такого процесса. Тогда правильная единица работы — не «цикл в доках про рост», а «эта волна записывается как первый реальный вопрос в живой мозг, и мы смотрим, что сломается».

Дополнительно: п.24 «запустить процесс **в совокупности**» трек Б (независимый от А, «идёт, даже если А не стартовал») буквально противоречит. Независимость треков = очередь, а не совокупность.

**Вопрос владельцу, вскрывающий рамку (голосом, один):**
«Если бы сегодня вечером ты мог либо (а) получить готовое описание того, как память должна расти, либо (б) положить в живой мозг один твой настоящий вопрос и увидеть, как агенты его раскручивают и что ломается — что бы ты выбрал, и почему?»
Ответ (б) = Б надо переопределить как «первый акт в мозге», не как документ. Ответ (а) = нужно уточнить, какое решение это описание должно изменить.

Сопутствующий вопрос-детектор: «Запускал ли RUNBOOK и если нет — что мешает: время, страх, неясность, или не хочешь, пока не всё продумано?» Если последнее — трек Б усугубляет избегание.

## 4. Голосование агентов: где ложная уверенность

- **Коррелированные голоса.** Все линзы — одна модель семейства, один корпус (START + INTAKE), одни и те же рамки в промпте. «4 из 4 согласны» ≈ 1 голос, умноженный на 4. Расхождение, как раз ценное по закону 8, может не возникнуть вовсе, а согласие будет принято за подтверждение. Проверка START «3 холодных прогона → UNDERSTOOD» уже страдает этим.
- **Лид пишет вопрос и пересказ.** Голосуют по рамке, которую задал голосующий же оркестратор (закон 7 нарушается неявно).
- **Невозможность проигрыша.** Нет базы данных исходов: голосование без отслеживания «решение → что случилось через 7 дней» не калибруется. Уверенность растёт, точность не измеряется.
- **Ложное «владелец в курсе».** Если владелец отвечает «ок» по дефолту на дайджест, это не голос, а подпись.

**Вместо / вдобавок (дешёвое):**
1. Голос агентов = **разведка вариантов и контраргументов, не решение.** Решает владелец; число «за» не показывать вообще (оно якорит).
2. Минимум один голосующий — **не из этой семьи**: человек (владелец одним предложением), либо реальный эксперимент, либо внешний источник (prior-art), либо роль «почему это неверно» с запретом ссылаться на корпус.
3. **Отложенная калибровка:** каждое решение-черновик получает проверяемое предсказание + дату проверки (GATE-7days); через неделю считать, сбылось ли. Это единственный честный «голос» реальности.
4. **Метка «согласие подозрительно»:** если все линзы за — запускать закон 8(б)-② «довести до абсурда» принудительно.

# Процесс роста как данные: минимальная форма на существующих примитивах

- **Status:** draft · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-11
- **Потребитель:** лид волны 1 + помощник (приёмка) + critic; позже — тот, кто будет писать первые узлы роста в мозг (точка схода трека А/Б).
- **Поглощает:** ничего. Опирается на `../../../../analyses/2026-10-11-capture-graph-intake/metamorphosis/*` (там есть таблица «элемент → где есть»). Здесь — **форма записи и правила процесса**.
- **Вопрос-цель:** какой минимальной формой из УЖЕ существующих примитивов живёт цикл «вопрос → голоса → развилка → голосование → решение → коррекция» так, чтобы владелец был в курсе, а память могла с этим работать?

## 0. Сверка с кодом (что реально можно записать сегодня)
Проверено по `packages/brain/src` и `packages/brain-mcp/src`:
- MCP даёт 4 глагола: `record` · `find` · `read` · `link` (`brain-mcp/src/server.ts:96-130`).
- Ядро-тип **`decision`** уже есть и имеет статусы `proposed|accepted|superseded`, поля `decided_at`, `rationale` (`brain/src/domain/genesis.ts:157`). Есть `note`, `task`, `raw`.
- Ядро-предикаты уже покрывают позвоночник: `derived-from`, `motivated-by`, `informed`, `about`, `part-of` (все many), `supersedes` (one), `variant-of` (one, «резерв») (`genesis.ts:210-226`).
- **Неизвестный тип НЕ ломает запись:** он ложится как `raw` с `declared_type` и порождает friction (`validate-act.ts:394-423`). Значит `question`, `idea`, `vote` пишутся как `u:`-тропы **без нового ядро-типа** (ADR-0017 F1) и копятся как кандидаты для садовника типов («тип = тропа»).
- **Неизвестный предикат запись ОТКЛОНЯЕТ** (`validate-act.ts:552,686`, `UNKNOWN_PREDICATE`). Поэтому `endorses/opposes/corrects` придумывать нельзя. Нужно обходиться ядро-предикатами.
- `link` несёт паспорт ребра: `confidence`, `note`, автора ставит сервер (`contract.ts:388-396`). Это готовое «ребро с паспортом».
- `initiative:'agent'` → статус `proposed` (`contract.ts`, AC-45). Агент только предлагает, это уже встроено.
- `record` принимает `source:{kind:'file'|'act'|'url', ref}`. Это «адрес, не копия».
- ⚠️ **Дыра V3:** все агенты под шлюзом пишут одним принципалом (`sys:gateway`, `sys-types.ts:SYS_GATEWAY`). Сервер различает «кто» только до уровня мандата, а модель и роль агента ему не видны. Поэтому роль, модель и уверенность голоса приходится нести **в полях записи**, а не в авторе.

## 1. Эскиз: семь элементов, ноль новых ядро-типов
| Элемент | Как пишется | Ключевые рёбра (только ядро) |
|---|---|---|
| **Вопрос** (семя/развилка) | `record type:'question'` → `u:question` (raw-тропа); поля `kind: seed\|fork`, `load_bearing: bool`, `decider: owner\|agents`, `status: open\|answered\|changed\|reframed\|dropped` | `part-of` → родительский вопрос (дерево генеалогии, п.16); `motivated-by` → то, что его породило |
| **Идея / вариант** | `record type:'idea'` (`u:idea`), `initiative:'agent'` → `proposed` | `part-of` → вопрос-развилка (many, ветвление не ограничено; `variant-of` не берём, у него `one`/резерв) |
| **Голос агента** | `record type:'vote'` (`u:vote`); поля `stance: for\|against\|abstain`, `role` (critic/analyst/…), `model` (`opus`/`sonnet`/`haiku`/`fable`), `family` (поставщик и модель), `confidence 0..1`, `why` (≤1 строки) | `about` → вариант; `derived-from` → анализ-источник (`source:file` на `.analysis.md`) |
| **Развилка** | это просто вопрос с `kind:fork` | `part-of` → вопрос-родитель; варианты — его дети |
| **Голосование** | **не сущность.** Это вид, который собирают через `find(type:'u:vote', edge:{pred:'about', to:<вариант>})` | — |
| **Решение** | ядро-`decision`: агент пишет `proposed`, владелец переводит в `accepted` | `motivated-by` → вопрос; `derived-from` → выбранный вариант и голоса; `link informed` от ключевых анализов с `confidence` |
| **Отвергнутое** | вариант остаётся (LOSE-NOTHING), получает `status: rejected`, а записи ставится `temperature: cold` (V4) | ребро `about` от голосов сохраняется. Отвергнутое помнит, **почему** его отвергли |
| **Коррекция** | новое `decision`, `supersedes` → старое; старое переходит в `superseded` (`projection.ts`: правило freshest-wins/supersede) | `motivated-by` → новый факт или вопрос, который вызвал коррекцию |

Голос сделан **записью**, а не ребром, потому что ребру нужны роль, модель и семья, а паспорт ребра несёт только `confidence`/`note`. Ребро с паспортом остаётся там, где хватает `confidence` (`informed`). Это осознанное отступление от «одного примитива», и его нужно проверить у critic.

### Пример: развилка «копировать или адресовать» (К2)
```
Q-1  u:question  kind:seed  «Как должна расти память?»
Q-7  u:question  kind:fork  load_bearing:true decider:owner   part-of→Q-1
     «Ничего не терять = копия всего или адрес+связь?»
I-7a u:idea  «Копировать сырьё в мозг»         part-of→Q-7  (proposed)
I-7b u:idea  «Хранить адрес (source) + рёбра»  part-of→Q-7  (proposed)
V-1  u:vote  for  I-7b role:critic    model:sonnet family:claude conf:0.8 derived-from→critic.analysis.md
V-2  u:vote  for  I-7b role:analyst   model:sonnet family:claude conf:0.7
V-3  u:vote  for  I-7a role:abstract  model:opus   family:claude conf:0.5 why:«поиск по телу»
D-7  decision proposed  «Адрес, не копия» motivated-by→Q-7 derived-from→I-7b,V-1,V-2,V-3
     ⇒ владелец «да» → accepted; I-7a → rejected+cold (с голосом V-3 как «почему могли бы»)
D-7' (через месяц) decision «Адрес + кэш тела для поиска при visibility=owner» supersedes→D-7
```
Ответ на вопрос «почему адрес?» читается обходом `D-7 → derived-from/motivated-by`. Ответ на «что было на 11-10?» получается реплеем журнала до даты. Отдельного читателя для среза «на момент» в коде пока нет, это слой N+1 (analyst-exists §3).

## 2. Развилка = глубокий вопрос: правила
**Порог несущести.** Развилка поднимается в отдельный `kind:fork`, если выполнено **≥2 из 4**:
1. меняет ВЕКТОР, а не формулировку;
2. это односторонняя дверь: откат дорогой, затрагивает id/рёбра/провенанс или формат журнала;
3. задевает ценность по её каноническому смыслу (чаще всего V2, V5, V6, V7);
4. линзы разошлись по детектору закона 8б (изолят + уверенный отщепенец + несущая развилка).

Если набралось меньше двух условий, это вариант внутри текущего вопроса, и отдельный узел не заводится.

**Проход линз.** Не меньше 3 ролей разного когнитивного типа (analyst · critic · abstract), плюс в каждой волне одна линза ищет переформулировку («вопрос был неверен?»). Это правило altitude-loop, закон 3.

**Голоса коррелированы.** Голос — это **метка с провенансом, а не вес** (metamorphosis/critic). Голоса считаются **по семьям, а не по головам**: три голоса Claude-sonnet дают **один независимый голос** с разбросом уверенности. Для настоящего второго голоса нужна другая семья (Fable/Gemini, если доступна) **или** другой вход, то есть другие факты в `derived-from`. «Единогласие» засчитывается, только если голоса пришли от ≥2 семей или опираются на ≥2 разных источника.

**Кто решает.**
- **Владелец**, если: `load_bearing` и односторонняя дверь; затронуты V5/V7 или пол К4; детектор расхождения 3/3; решение выходит за пределы его собственной памяти (третьи лица, системы с ролями).
- **Агенты**, если: решение обратимо, укладывается в одобренный ADR/спек, а голоса единогласны по правилу семей. Даже тогда решение остаётся `decision: proposed` и **сразу видно** в ленте. Агенты действуют по нему, но `accepted` ставит только «да» владельца, или решение переходит в `accepted` по явно делегированному правилу (policy-as-data, решение 10-10 п.9, позже).
- Голоса **никогда** не повышают доверие автоматически. Веса доверия считаются только по «да» владельца (К3).

## 3. «Владелец в курсе»: одна линза
**Лента развилок** — это одна таблица-вид, без UI:
`🔴 блок / 🟡 нужен твой выбор / 🟢 решено агентами (обратимо, можно вето)` · вопрос одной строкой · варианты · голоса по семьям («3 голоса, 1 семья, за I-7b») · что меняет · ссылка.

- **Сейчас:** `FORKS.md` в корне дома `questions/2026-10-11-how-memory-grows/` собирается из frontmatter файлов в `questions/`. Рядом лежит `.concept.json`-визард только для 🟡, чтобы владелец ответил голосом пачкой. В Telegram уходит одна карточка через `md2tg` при каждом новом 🟡/🔴, а 🟢 идут сводкой раз в сессию.
- **Позже, в мозге:** тот же вид даёт `find(type:'u:question', status:'open')` + `read(depth 1)`. Новый пресет или новая `shape` линзы (`sys:lens` сейчас знает только `compose`) — это слой N+1, его делаем после того, как лента прожила 2 недели в md.

## 4. Ручной режим → память
**Сейчас (в доках, трек Б):** каждый файл в доме несёт frontmatter **той же формы, что и будущий `record`**: `type`, `label`, `status`, `edges: [{pred, to}]` (только ядро-предикаты), у голосов — `role/model/family/confidence`, у всех — `id` вида `Q-7/I-7a/V-1/D-7`. Компаундный эффект в том, что перенос в мозг становится механическим: переписывать ничего не придётся.

**Единственный переход:** после смоука трека А и «да» владельца (START §5 п.4) запускается одна операция **«пересадка по адресу»**. Для каждого узла дома выполняется `record` с `label`, полями, рёбрами и `source:{kind:'file', ref:<путь .md>}`, а в frontmatter файла дописывается `brain_id`. Тело остаётся в md. Дальнейшие шаги цикла пишутся **сначала в мозг** (`initiative:'agent'` → `proposed`), а md становится видом. Новые ядро-типы, предикаты и движок не нужны.

**До `hard_erase` нельзя:**
- хуки авто-захвата голосов и шагов;
- класть в payload дословные тексты агентских прогонов или чатов: в мозге только `label` + `why` ≤1 строки + адрес;
- писать имена третьих лиц, в том числе «кто предложил», если это не владелец и не агент-роль;
- делать «голосовалку», которая сама переводит `proposed` в `accepted`.

## 5. Семь ценностей
- **V1 Читаемость** 🟢: в `label` + `status` + сводку голосов по семьям ложится дешёвая грань, тело не вскрывается. 🟡 Голос как отдельная запись утяжеляет `find`, лечится видом-сводкой.
- **V2 Тождество** 🟢: коррекция идёт через `supersedes`, и решение «меняется, не теряя себя». 🟡 Ручные id `Q-7` нужно однозначно связать с `brain_id`, иначе при пересадке появятся дубли (страхует дедуп по label 24ч).
- **V3 Доверие** 🟢: провенанс решения проходит через `derived-from`, у голоса есть `confidence`. 🔴 Под шлюзом один принципал: роль и модель агента — это **заявление в полях, а не факт сервера**. Голоса легко подделать или перепутать. Это вход для critic.
- **V4 Витальность** 🟢: отвергнутое переходит в `rejected` и `cold`, а не удаляется. 🟡 Механику остывания по времени (`temperature`) сверить с кодом, сейчас она скорее метка.
- **V5 Суверенность** 🟢: везде `u:`-тропы и ядро-предикаты, и всё переносится. 🟡 Поле `family` привязывает данные к поставщикам моделей, поэтому словарь должен быть открытым.
- **V6 Реляционность** 🟡: у рёбер `about/part-of` нет своего паспорта «почему связано», а голос пришлось вынести в запись. Ребро с паспортом здесь только частично.
- **V7 Согласие** 🟢: проходит только адрес без тел и без третьих лиц, авто-захвата нет до `hard_erase`. Enforcement согласия в движке не подключён, держится на дисциплине.

## Открытое для critic
1. Голос как запись (`u:vote`) или как `link informed` с `confidence` + `note`, где роль и модель зашиты в `note`? Я выбрал запись, чтобы различать семьи.
2. Достаточно ли порога «2 из 4», или он поднимет в развилки слишком много?
3. Нужен ли отдельный ядро-кандидат предиката `answers/refines`? Мой ответ — нет, пока `part-of` + `motivated-by` справляются на живых данных.

Вопрос-цель: **ответил** для формы данных и правил. Частично под вопросом V3: «кто голосовал» сервер не удостоверяет, это решается только при отдельных мандатах агентов (слой N+1).

Итог: решение-черновик — процесс роста живёт как `u:question/u:idea/u:vote` (тропы через raw) + ядро-`decision` + ядро-рёбра (`part-of/about/derived-from/motivated-by/supersedes`), голоса считаются по семьям и решения не принимают. Сейчас frontmatter в доме повторяет форму `record`, а после смоука трека А один переход «пересадка по адресу» переносит его в мозг. Задача в плане — critic на §1 (голос как запись или как ребро) и §2 (порог).
