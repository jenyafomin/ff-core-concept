## Вердикт
План — 5 строк волн без критерия «готово», без формата карты и без правила выбора шага. Как есть: **карта-описание, а не карта-подсказка.** Ширина по определению ничего не приоритизирует; приоритизацию нужно закладывать явно.

## 1. Три главных риска + предохранитель
**R1. Бумага (CRITICAL).** Ярус B свода (ff-brain в pm2 + `find` по узлу) требует руку владельца — ночью он недостижим по построению. Значит ночь гарантированно даёт только ярус A. START §5.3: «второй цикл Б не начинать», если А не стартовал; docs:code ≈14:1. Ночь = нарушение собственного стопа, если не оформить как исключение.
*Предохранитель:* (а) записать в NIGHT-PLAN явное исключение: наказ владельца (голос) > стоп START, срок — одна ночь; (б) потолок: итог = ОДИН граф-файл + ОДИН OVERVIEW ≤30 с, всё сырьё — приложение; (в) в хендоффе дословно «Б = бумага, пока нет яруса B».

**R2. Корреляция голосов (CONCERN).** «Тысячи агентов» = одна семья Claude, один корпус. Согласие не доказательство (свод уже признал, план — нет). Число не добавляет независимости.
*Предохранитель:* считать не агентов, а ЛИНЗЫ×семьи; на каждую ветвь обязательно одна «против»-линза (инверсия-адвокат); в W5 — один голос не из семьи Claude (доступен gemini-notebook MCP; только непубличное без PII/имён). Единогласие при 1 семье не засчитывать.

**R3. Распухание карты (CONCERN).** W3–W4 «перепись всех под-узлов» без потолка → 300 узлов, карта нечитаема (V1).
*Предохранитель:* жёсткий бюджет: ≤12 узлов на ветвь, глубина ≤3, всего ≤60; новый узел вытесняет старый (слияние, не добавление). Лишнее — в `questions/` без приоритета (правило altitude-loop).

**R4. Потеря «отыгрывать себя» (CRITICAL).** Слова владельца неоднозначны: «окупаться» (польза > затрат) или «воспроизводить себя» (карта растёт из памяти)? План не выбрал. Ширина без критерия «что окупится первым» даст инвентарь.
*Предохранитель:* каждому листу — поля `payoff` (какое наблюдаемое событие и когда ≤7 дней), `cost` (мало/средне/много), `unblocks`. Выход обязан содержать функцию выбора, не только узлы. Трактовку R4 — одним вопросом владельцу (вместе с F1).

## 2. Критерий «готово» (проверяемый, скриптом + холодным читателем)
1. Ровно **1 рекомендованный шаг «СЕЙЧАС»** (≤1 день, действие, а не тема) + 2 альтернативы + почему проиграли (с расходящимся голосом).
2. У шага: ожидаемое «было→стало», `check_date` ≤7 дней, опровергающее наблюдение.
3. Покрытие: каждый из 24 пунктов START §2А и 8 «легко потерять» (8,9,10,11,13,14,16,18) привязан ≥1 узлом ИЛИ явно «не тронуто». Скрипт проверки.
4. Ссылочная целостность: нет сирот-рёбер, нет циклов `part-of`, все узлы с `source` (линза/семья).
5. Лимиты R3 соблюдены; раздел «слепые зоны» не пуст.
6. Холодный читатель без START за 5 минут называет шаг и первое действие; не назвал → не готово.
7. Приёмка co-orchestrator + critic ДРУГИМ агентом, а не автором карты.

## 3. Формат пересадки 1:1 (карта = данные, mermaid — только вид)
Источник истины — `MINDMAP.graph.jsonl`, одна строка = один `record` (аргументы `contract.ts`: `type,label,fields,edges[{pred,to}]`). Поля: `id` (стабильный `Q-/N-…`, не пересчитывается), `label` ≤80, `status` (open|answered|changed|reframed|dropped), `fields`: `payoff, cost, check_date, source_family, confidence`. Рёбра ТОЛЬКО из существующих предикатов (`part-of`, `derived-from`, `about`, `supersedes`; genesis.ts:213-223). Новых предикатов (`blocks/unblocks`) не вводить: спор analyst/architect решить в пользу architect; «почему связано» — текстовым полем узла-источника, т.к. у ребра в `RecordEdgeInput` только `pred+to` (V6-дыра — зафиксировать, не лечить). Ветка = узел `part-of` корня. Mermaid генерируется скриптом из jsonl, не пишется руками (иначе второй дом истины). Пересадка — dry-run Карты 1 (из свода) идёт ПЕРВОЙ, до формата, иначе формат придуман вслепую.
