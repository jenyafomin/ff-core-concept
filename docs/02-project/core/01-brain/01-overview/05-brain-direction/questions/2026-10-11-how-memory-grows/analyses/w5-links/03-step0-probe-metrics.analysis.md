- **Status:** draft · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-11
- **Потребитель:** w5-links / решение «строить ли читатель» · **Поглощает:** ничего
- Содержимое сообщений здесь НЕ приводится; личные кандидаты — в gitignored trace (`docs/_log/2026-10-11-night-memory-map/step0-reader-probe.md`).

**Вопрос-цель:** может ли читатель над логом шлюза уже сегодня вернуть владельцу то, чего нет в START — его реально открытые дела/темы с адресами?

## Метрики
| Что | Значение |
|---|---|
| Источник | таблица `messages` БД шлюза, read-only |
| Окно / фильтр | 14 дней, только `direction=in` (все — один владелец) |
| Прочитано сообщений | 234 (~244 тыс. символов) |
| Топиков | 29 (3 топика дают ~35% объёма) |
| Шум | ~4% («тест связи»), ~3% пересланное чужое (исключено как источник) |
| Кандидатов «открыто» | 10, у каждого адрес-алиас `gw:topic<N>/m<id>` |
| Новых против START | 10 из 10 — но START узок (только мозг); память/мозг-топики (~19% сообщений) в START уже есть |
| Оценка «реально открыто» (модель) | ~4 из 10 средняя+ уверенность; статус закрытия по логу неизвестен |
| Время / цена | ≈10 мин / ≈$0.5–1 |
| Готовый поиск у шлюза | нет (только SQL по тексту) |

## Вывод
- Технически читатель возможен уже сегодня: схема простая (текст, время, `sessionKey` = чат+топик, `channelMessageId` = адрес), алиасы строятся без chat id.
- Ценность: проба вернула дела, которых в START нет (операционные проекты), с адресами. Но «открыто/закрыто» модель по входящим не знает: нужны ответы бота (`out`) или явная отметка владельца.
- Проверка гипотезы критика (признает <3 из 10 — шум) ЕЩЁ НЕ выполнена: нужен ответ владельца да/нет по 10 пунктам. Порог шума: <3.
- Риск: в логе открытым текстом секреты (пароли серверов) — читателю нужен фильтр секретов и фильтр V7 (пересланное от третьих лиц) до выдачи.

Итог: решение отложено до ответа владельца по 10 кандидатам (триггер: утро); читатель технически осуществим, фильтр секретов обязателен.
