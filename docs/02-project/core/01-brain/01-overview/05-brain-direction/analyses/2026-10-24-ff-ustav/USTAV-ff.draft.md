# Устав общей памяти ff-brain

> Устав = ЧТО и ЗАЧЕМ (закон). КАК (вызовы, поля, отказы) — в скилле `ff-brain-use`.
> Память держит адреса, решения, задачи и связи. Тело документа живёт в git.

0. **Кто пишет.** В проектных областях (`ff`, `agents-manager` и будущие) агент пишет САМ по этому уставу:
   решения с причиной, задачи, итог сессии. **Не больше 3 `record` за ход.** В `personal` — только по слову
   владельца; имена и факты о третьих лицах — никогда (п. 11). Владелец видит записанное через `/state` и помечает лишнее.
1. **Сначала карта.** В начале сессии и перед вопросом «что решено / что открыто» — `find preset:overview`
   (карта областей), потом `open` или `morning` своей области. Не нашёл — так и скажи, не выдумывай.
2. **Перед записью — поиск.** Каждый `record` начинается с `find(text, type, scope)`. Нашлось похожее —
   обнови его тем же `id`, а не заводи второе.
3. **Пиши решения с причиной.** `decision`: в label — что выбрано («выбрано X»), в `rationale` — почему,
   `decided_at` — когда. Решение без причины не пишем. В `rationale`/тексте помечай источник: «со слов владельца»
   или «вывод агента».
4. **Пиши задачи, которые можно закрыть.** `task`: label = глагол + предмет; `due` — если известен; `why` — одной
   строкой (с пометкой «со слов владельца» / «вывод агента»). Исполнителя не пишем. Закрывает задачу (`done`) только слово владельца.
5. **Итог сессии — заметка-адрес, один раз за сессию.** Один `note` с 1–2 строками сути и `source.ref` + `hash` на файл хендоффа/артефакта.
   Ссылка на файл вместо копии тела — всегда, для любого документа.
6. **Не пиши мусор.** Сырой чат, черновики, логи, пересказ файлов, догадки, дубли — в память не идут.
   Пишем только то, что пригодится другому агенту или владельцу через неделю.
7. **Область — по смыслу.** Запись проекта — в его область (напр. `agents-manager`). Касается ≥2 проектов
   или системы в целом — в `ff`. `personal` — только личное владельца.
8. **Label — коротко и ищется.** ≤ ~60 символов (жёсткий предел 120), слова, по которым будут искать;
   проект — префиксом («шлюз: …»). Без «см. выше», без дат-номеров вместо смысла.
9. **Связь — ребром, не текстом.** Если запись про другую — `link` с предикатом, а не «см. запись такую-то».
10. **Устаревшее — помечай, не плоди и не стирай.** Файл изменился → тот же `id`, новый `hash`. Факт заменён →
    новая запись + `link supersedes` на старую (у `decision` — статус `superseded`). Ошибка → `retract` с причиной.
11. **Никаких секретов и чужих данных.** Ни паролей, ключей, токенов, ссылок с токенами, номеров документов,
    адресов; ни id чатов и юзеров. Имена/ники/факты о третьих лицах — никогда, даже в пересказе и со слов владельца. Стирания нет — записанное навсегда.
    Сомневаешься — не пиши, спроси владельца.
12. **«Записал» — только по квитанции.** Нет `ok:true` + `receipt` — запись не состоялась.
