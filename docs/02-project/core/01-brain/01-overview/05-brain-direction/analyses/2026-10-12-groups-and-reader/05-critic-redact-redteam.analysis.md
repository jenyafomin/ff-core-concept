## Итог
Из 50 враждебных строк **27 прошли** (26 целиком + A17 с утечкой значения), 23 скрыты. Вендорные префиксы (AKIA, sk-, JWT, TG-токен, sk_live, npm_, AIza) держатся на 100%. Дыра — **разговорные формы владельца**: нет ключевых слов «пасс/pw/parol/опечатки/pasword», значение на следующей строке через пустую строку, логин+пароль без ключевого слова, пароль отдельным сообщением. Из 15 безобидных скрыто 3 (допустимо при fail-closed). Вердикт: фильтр держит «книжные» секреты, но НЕ держит голос→текст. 7 blocker.

Цена ложных срабатываний низкая (теряется строка, а не сообщение); для fail-closed это допустимо. F04/F01 стоит смягчить только если станут мешать работе, пока не трогать.

## Blocker (оставлять нельзя)
- **B1. Нет ключевых слов разговорного пароля:** `пасс`, `pw`, `parol/paroli`, `pasword`, `парль`, `пароьл`, leet `p4ssw0rd`, «логин/пароль» (A02, A05, A18–A21, A26, A43). Основной путь утечки при голос→текст и опечатках.
- **B2. «Ключ:» без «доступа/api»** (A07) и «доступ:», «креды» с разделителем `/` (A08).
- **B3. Пара `root / Qwerty123`, `логин admin пароль admin`, `мой пароль Qwerty`** (A04, A06, A24): слово после ключа без цифры/символа не считается значением; «пароль» + слово + слово без разделителя прошло.
- **B4. Значение через пустую строку:** KW_TRAILING скрывает только i+1, а оно пустое (A17). Также «пароль на следующей строке» (A03).
- **B5. IP:порт:логин:пароль и `user@host pw X`** (A05, A09): нет правила на колонки/пары.
- **B6. CLI-флаги:** `-pSECRET`, `--password=…`, `-p SECRET` (A28; `--password=` ловится только через KW+разделитель, `-pXXX` нет).
- **B7. Пароль отдельным сообщением.** Фильтр построчный и в пределах одного сообщения (reader.ts:126,164 вызывает `redactText(l.row.text)` на одну строку БД). «Пароль от сервера» → следующий Telegram-месседж `Xk9mP2` пройдёт по определению. Реальнее всего для Telegram. Поведение гейтит только отдельное сообщение без контекста.

## Допустимо с пометкой (concern)
- A15/A16/A38 пароль словами и фраза-парольная (diceware): нельзя отличить от речи. Нужен контекст «после ключевого слова в строке с KW → скрывать всю строку».
- A32 по буквам, A33-подобные цифры по одной: частично держится, «по буквам» нет.
- A34 SMS-код: короткоживущий, риск низкий; можно не скрывать, но пометить.
- A35 seed phrase: высокий ущерб (кошелёк), но нужен триггер `seed|мнемоник|recovery`. Рекомендую в blocker, если у владельца есть крипто; иначе concern.
- A37 голое `P@ssw0rd`: PASSWORDISH применяется только рядом с `user@host`. Допустимо, пока нет контекста.
- A49, A50: карта/CVV (PCI) — отдельный класс; добавить Luhn-правило, цена низкая.
- Не проверено: редактированные сообщения (edit), caption у вложений, поле `text` у reply-цитат, имена топиков/labels через `gw_label` (server.ts:123 фильтрует note, но не `label`/topic title).

## Предлагаемые правила (не код, а спека для builder)
1. **KW расширить** (с `iu`): `пасс\p{L}*|парол\p{L}*|пароьл|парль|parol\p{L}*|pasw\p{L}*|passw\p{L}*|p[a4@]ss?w[o0]rd|pw|pwd|pass|pas|логин\p{L}*|login|user(?:name)?|доступ\p{L}*|креды|кред\p{L}*|ключ\p{L}*|key|seed|mnemonic|мнемоник\p{L}*|recovery`. Оставить пароль-строгие слова (`парол*`, `pass*`, `pw`, `parol*`) в режиме «hide-whole-line», а слабые (`ключ`, `доступ`, `login`, `key`) — только с разделителем или value-like токеном рядом.
2. **KW_TRAILING / соседство:** вместо i+1 скрывать следующие **первые 2 непустые** строки (пропуская пустые), `/^\s*$/` не считается.
3. **Строка «логин/пароль» целиком:** `/(?:логин|login|user(?:name)?)\s*[:=]?\s*\S+.*(?:парол|pass|pw)/iu`, и просто скрывать любую строку, где в одной строке есть **KW_STRONG и ≥1 токен после него** (не только value-like): `${NB}(?:парол\p{L}*|pass\p{L}*|pw|parol\p{L}*)\b.*\S`. Цена: ложных сработает больше (F01/F12-класс), но это fail-closed.
4. **Пара через слэш:** `/(?<!\S)\S{2,}\s\/\s\S{4,}(?!\S)/u` внутри строки с KW_ANY либо `^root|admin|ubuntu|deploy`.
5. **Колонки:** `/\b(?:\d{1,3}\.){3}\d{1,3}(?::\d{2,5})?(?::[^\s:]+){2,}/u`, `/\b(?:ssh|scp|sftp|mysql|psql|redis-cli)\b.*(?:\s-p\S+|\s--?pass\w*[ =]\S+|\s(?:pw|pass)\s+\S+)/iu`.
6. **Окно между сообщениями (B7):** в reader.ts вести «хвост»: если предыдущее сообщение того же топика, в пределах 5 минут, закончилось/содержало KW_STRONG без значения (KW_TRAILING или «пароль/пасс от …»), то следующее короткое (<80 символов) сообщение целиком скрыть. Контекст можно передать флагом `carry` в `redactText(text, {prevWasKw})`.
7. **Дополнить вендоров:** `sk_(?:live|test)_`, `rk_live_`, `npm_[A-Za-z0-9]{30,}`, `xox`, SendGrid `SG\.`, Twilio `AC[0-9a-f]{32}`, Luhn 13–19 цифр (с пробелами/дефисами) + `cvv|cvc`, BIP39 «≥12 слов подряд после seed|мнемоник».
8. **Тесты:** добавить A02–A09, A17–A21, A24, A26, A28, A39, A43 как красные тесты `test/redact.test.ts` (сейчас 8 `it`), плюс F02/F03/F06–F11/F13–F15 как «не режем».

## Противоречия / оговорки
- Заголовок redact.ts: «when in doubt the line is hidden» — A02/A04/A26 прямое противоречие: сомнения нет, но строка не скрыта.
- Фильтр не вычислял энтропию для коротких значений (<32 симв.). Любой пароль ≤31 символа без KW — вне охвата. Это структурный предел, а не баг: доверять фильтру как «единственной» защите нельзя; нужен второй слой (ограничение окна `days`, owner-only inbound уже есть).

**Итог:** решение — blocker B1–B7 закрыть до подключения читателя к модели; правила 1–8 передать builder (задача в плане); concern-пункты — отложено до первого живого прогона `smoke:live`.
