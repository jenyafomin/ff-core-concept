## Топ-5 для «жить в памяти» на ближайшие 7 дней
1. **G-07 (+G-08 как след)** — трение «кнопка на каждую запись»: сломает туду-сценарий в первый же день. Дёшево: «Всегда» разово. Данные-версию не строить до живого опыта.
2. **G-06 + G-05** — включить shadow+MCP и положить протокол в слой топика 56 (RUNBOOK 4–5). Без этого память не используется; рестарт — в простое.
3. **G-20** — дубль голосового: владелец диктует зёрна голосом, дубль убивает ход/память-запись. Проверить жив ли фикс-ветка и вернуть владельцу «land + restart». Иначе записи в память дублируются (идемпотентность записи — вопрос к G-07/протоколу).
4. **G-01 (гейт shadow→R1.1)** — измерять `equal:true` 7 дней; решение «идти в brain» принимать по числам (GATE-7days). Без `/prompt`→мозг (G-02) владелец правит файлом, shadow ресинкает.
5. **G-21** — фоновые агенты: туду-лист + ночные оркестрации требуют синхронности; зафиксировать в протоколе агента «память пишется в конце каждой волны, не из фона».

## Топ-3 повторяющихся болей
1. **Дубль/потеря хода при сбое доставки (G-20, G-21, G-22)** — три поколения записей (июль, август, сентябрь) об одном: ход обрывается или повторяется, фоновая работа гибнет. Корень в ingress и в «ход = процесс».
2. **Тупик блокировки без выхода (G-17, G-07, G-16)** — стоп-лист/апрув: «всё равно всё на мне» (голос 2026-09-30); сейчас добавилось трение записи в память.
3. **Фикс «в коде, ждёт деплоя/land» (G-23, G-24, G-20, P1-P6)** — готовое лежит, не доезжает до живого бота: деплой=рука владельца+рестарт, который сам рвёт ходы. Лечится одним ритуалом «окно рестарта» (кандидат на скилл по правилу «3-й раз вручную»).
