### Что выявил аудит (пробел → какой провал он вызвал бы)

1. **Карточка D устарела по отношению к направлению.** `DIRECTION-v2.md` патч 3 заменил «карту лупов в 4 словах» на «≥3 соперничающих видения + 6 слов архитектора», но текст карточки D (`co-orch-taskcards.md:71-82`) остался прежним. Если вставить её дословно, команда сделает ровно то, что критик отверг (`critic-direction.analysis.md:13-15`): одну рамку, «склад» V6 и сплющенный «читатель». **Корень:** у карточки нет поля «по какой версии направления она написана». → новый пункт 7.
2. **Пункт 1 «4 слова» сам задаёт рамку.** Обязательный пункт навязывает одно видение. Критик: «рамка сплющивает V6, V5, V7 сквозные» (`critic-direction.analysis.md:14`); архитектор расширил до 6 слов (`DIRECTION-v2.md:12`). → пункт 1 должен допускать «или назови соперничающую рамку».
3. **Карточка F (живой бот) без границ «не делаем».** Задача «проверь, жива ли ветка `fix/p2-voice-dedup-ingress`» (`co-orch-taskcards.md:98`) — это git-команды в репозитории живого шлюза. Без строки «только чтение, никаких checkout/worktree prune/restart» скаут может повторить инцидент 07-26 (`agents-manager/docs/_logs/2026-07-26-concept-live-card-build/analysis/2026-07-26-INCIDENT-overwrote-uncommitted-src.md`). **Пробел, которого нет в карточке вообще:** «конверт безопасности для живых систем». → пункт 6 расширен.
4. **Ни в одной карточке нет цены и потолка.** `investigation-economics/RULE.md:18-20`: «прогон, стоимость которого нельзя назвать, считается незавершённым»; §1:27 «явно указывать `model` в каждом agent()». Модель и лимит слов co-orch добавил отдельной строкой «Тип: …» — но вне 10 пунктов, а потолка/стоп-условия нет нигде. → пункт 9.
5. **Нет поля «Меняет:».** Правило ночи (`DIRECTION-v2.md:8`) появилось после карточек. Это самый сильный фильтр против «анализа как избегания» (docs:code 14.5:1) — должно быть в карточке, первой строкой. → пункт 1.
6. **Пункты 2 и 7 дублируют друг друга** (эпизод и file:line — оба «держись за реальность»), а пункт 8 почти всегда ритуальный («заменяет 4 файла»). → слиты: 2+7 → один пункт, 8 → в пункт «Выход».
7. **Нет списка чтения.** Карточки дают якоря, но не говорят «читай ЭТИ N файлов и не больше». Итог: критик W2 прочёл все 5 скаутов целиком (`critic-direction.analysis.md:4`) — допустимо, но на опусе дорого. → пункт 7.
8. **Самоприменение к моему собственному запуску (догфудинг).** Промпт, которым запустили эту задачу: есть «Меняет», список чтения, выход, лимит ответа ≤200. Нет: явной модели (наследуется — нарушение RULE §1), лимита слов на файл, метрики, потолка. Имя файла в карточке E (`agent-launch-standard.analysis.md`, `co-orch-taskcards.md:93`) ≠ имя в реальном запуске (`E-agent-launch.analysis.md`). **Вывод:** между черновиком карточки (помощник) и реальным промптом (лид) идёт дрейф; карточка должна быть тем, что вставляется ДОСЛОВНО, а не пересказывается.

### Уточнённая карточка (10 пунктов, вставлять дословно)

```
КАРТОЧКА ЗАДАЧИ (заполняет помощник, сверяет лид, вставляется в промпт ДОСЛОВНО)
1. МЕНЯЕТ + ПЕТЛЯ: «Меняет: <строка RUNBOOK / GATE / протокола / визарда / файл кода>». Не меняет ничего — не запускать.
   Петля: источник → запись → связь → читатель → действие → сигнал. Если рамка спорная — назови соперничающую.
2. РЕАЛЬНОСТЬ: эпизод владельца (дата/топик) ИЛИ живое трение + опоры `file:line` с дословной строкой.
   Всё без опоры помечать «гипотеза».
3. ЧИТАТЕЛЬ И МЕТРИКА: для кого (владелец / агент / шлюз) и каким числом поймём, что сработало (два счётчика, если читателей двое).
4. ЦЕННОСТИ: 1–3 из V1–V7 по `_CARDS-2026-07-08.md` + вопрос «укрепляет или ломает?».
5. ДВЕРИ: что необратимо (имя/родитель области, id, запись о третьем лице, push в git, данные в живой мозг) — решает владелец; команда только формулирует.
6. НЕ ДЕЛАЕМ + КОНВЕРТ: вне скоупа; код только после «строй»; стоп-лист пути памяти не обходить; git — сначала `git status --porcelain` ОТДЕЛЬНОЙ командой;
   живой бот/сервис: без checkout/restore/reset/restart в его дереве; без секретов/.env; без PII в документах.
7. ВХОД: версия направления (`DIRECTION-vN`) + список чтения ≤N файлов по порядку. Остальное не читать без причины.
8. ВЫХОД: ровно один файл, полный путь, шапка Status/Owner/Date/Потребитель/Поглощает/Меняет, последняя строка `Итог:`;
   что он заменяет. Лиду — ≤200 слов выжимки.
9. ИСПОЛНИТЕЛЬ И БЮДЖЕТ: тип агента · модель ЯВНО · лимит слов · потолок (агентов / время / $) · СТОП-условие («остановись и верни, если…»).
10. ПРОВЕРКА: кто проверяет (другой агент, не автор) · как (по чему) · вопрос, вскрывающий неверную рамку: «как эту задачу могли поставить неправильно?».
```

## 2. Рецепты под 4 будущих направления

**Вставить builder’у дословно:**
```

«Готово» = `tsc` зелёный + тесты затронутых пакетов зелёные, ЦИФРАМИ в отчёте. «Сервис стартует» ≠ готово (P7).
```
