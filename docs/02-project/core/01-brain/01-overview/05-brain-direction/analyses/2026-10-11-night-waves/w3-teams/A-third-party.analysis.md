Смягчение: читаемость в `personal` ограничена владельцем (`readableByFor`), но запись остаётся в журнале навсегда (стирания нет, M-01 не построен) и в export.

## 2. Правило агента (текст протокола)
Три класса, чтобы агент не гадал:
- **СТОП-писать:** секреты (ключ, токен, пароль, PIN, CVV, одноразовый код, ссылка с токеном), документы/номера (паспорт, карта, ИНН, адрес).
- **Обезличить:** любое имя/ник/@юзер третьего лица, телефон/email (даже если сервер пропустит), название компании, если по нему узнаётся человек. Роль вместо имени: «подрядчик по сайту», «менеджер банка», «врач».
- **Можно:** имя самого владельца, публичные названия (сервис, магазин, город), роли.
Проверка перед КАЖДЫМ record: «в label/why/fields есть заглавное слово — это человек?». Нужное имя для действия (кому звонить) остаётся у владельца в телефоне; в задаче — роль + срок.
Если владелец сам диктует имя: не писать, ответить одной строкой «записал без имени: <label>», не требовать.

## 3. Прогон на 5 фраз
Реальных фраз топика 56 в карточке нет; ниже типовые, ПОМЕЧЕНО как гипотеза (не из транскрипта). Лиду: подставить 5 реальных при применении.
1. «Напомни позвонить Андрею по сайту в пятницу» -> `task` «Позвонить подрядчику по сайту», due пятница. Имя ушло.
2. «Запиши пароль от роутера 8x...» -> отказ, ответ «пароли не пишу». Сервер НЕ остановил бы.
3. «Оплатить за Марию аренду до 5-го» -> «Оплатить аренду (за близкого) до 5-го» без имени.
4. «Решили с Сашей брать план Б» -> `decision` «Выбран план Б», rationale без участника.
5. «Сохрани ссылку https://x.io/?token=ey...» -> не писать ссылку с токеном; записать «ссылка у владельца».
Все пять проходят правилом. Критик-вопрос «имя нужно для пользы туду»: потеря малая в первую неделю (кому звонить владелец знает сам); цена реальная только когда задачи станут чужими для памяти владельца. Это и есть повод для варианта C ниже, но не раньше M-01.
