Потребитель: владелец (развилки) + следующие сессии трека «мозг». Поглощает: raw/01–03 (приложения).

## Вопрос владельца → переформулировка
Было: «как память будет развиваться, как её будут читать, как взять максимум ценности».
Стало (critic + abstract-thinker сходятся): **«что должно происходить САМО, чтобы за неделю набралось ~20 записей, которые я захотел перечитать — и перечитал?»** Проблема не в архитектуре роста, а в потоке записи и возврате.

## Сходится у трёх линз
- Боль №1: агент начинает каждый ход с нуля, владелец пересказывает. Память = **журнал смены, который агент читает первым**, не архив.
- Петля разорвана в 3 местах: (1) чтение на входе не обязательно; (2) нет МОМЕНТА записи (устав говорит «что», но не «когда»); (3) владелец не видит, что записано → не доверяет → не возвращается.
- Фронтенд, mind map, сервисы-виды, MCP сервисов, плагины, Postgres — **слой N+1 над пустым N**. Отложить до порога (ниже). Видение сохранено в идее 2026-10-23.
- Человеку нужен ОДИН дешёвый вид уже сейчас — в Telegram, тот же, что читает агент (не отдельный фронт).

## Вектор на 1–2 недели: «память заменяет хендофф»
1. **Вход:** строка в CLAUDE.md проектов «первым ходом — карта памяти (overview) + открытое». ✔ дёшево.
2. **Момент записи:** в конце значимого хода/сессии агент пишет решения/задачи/итог по уставу (или кандидатов — развилка Р1).
3. **Вид для человека:** команда в Telegram (`/state <область>` или утренний дайджест «что записано вчера») — переиспользовать браузер-движки шлюза (`agents-manager/src/channel-telegram/browser/`). Позже — export в md для Obsidian.
4. **Порог через 7 дней:** ≥20 живых записей · ≥3 реальных find из другого топика · ≥1 раз владелец поймал/исправил расхождение · сессии открываются без пересказа. Прошли → разблокировать вид-сервисы/Postgres/типы. Нет → стоп слоям, чинить поток.

## Поправка к analyst

## Развилки владельцу
- **Р1 (несущая): кто разрешает запись?** (а) агент пишет сам в свою проектную область по уставу, владелец видит дайджест и помечает лишнее (дёшево, быстрее петля); (б) агент предлагает кандидатов, владелец подтверждает (чище, но тормозит). personal и любые данные третьих лиц — только по слову владельца в обоих вариантах. Рекомендация лида: (а) для ff/agents-manager.
- **Р2:** вид для человека — `/state` по запросу или утренний дайджест сам? (можно оба, начать с одного).
- Устав: 4 вопроса в `USTAV-ff.draft.md`.

Итог: решение ждёт владельца по Р1/Р2 + утверждение устава; далее — строй пунктов 1–3 вектора.
