## 1. Настоящая потребность — одной фразой

**«Всё, что происходит между мной и агентами, должно оставлять след, по которому потом можно найти и связать — без
моей ручной дисциплины».**

**Это ТО ЖЕ видение, что msg 141** («всё, с чем работают агенты, живёт в графе; всё видно ИИ»). Новых целей нет.
Изменилось три слова: **сейчас · вживую · само** (хуком, а не ручной записью). То есть это не новая система, а
**расширение поверхности захвата**: первая тропа (туду + хвосты) → вторая (разговор/тема/действие).

Лестница «почему» (короткая):
- Почему граф? → чтобы достать и увидеть картину целиком.
- Почему достать? → потому что знание теряется между ходами/топиками/проектами.
- **Теряется ли оно на самом деле?** — **Нет, сырьё уже хранится** (транскрипты сессий Claude, логи шлюза, `docs/`).
  Теряется не СОДЕРЖИМОЕ, а **НАХОДИМОСТЬ и СВЯЗЬ**. → Ключевой рефрейм:

> **«Не терять» ≠ «копировать всё в память». «Не терять» = у каждого значимого события есть АДРЕС (указатель +
> подпись + связи), а содержимое остаётся там, где уже лежит.**

Это снимает главный конфликт с неделей 1: журнал мозга неудаляем, стирания нет, имена третьих лиц запрещены
(SYNTHESIS §2.1 «D. Секретарь» = НЕТ). Копирование переписок в журнал нарушило бы все три. Указатель — нет.

## 2. Рамка, объединяющая дерево + связи + теги + лог

**«Один журнал актов; дерево, карта, теги, хронология — ЛИНЗЫ (виды) над ним».**

Аналогия: **бухгалтерия.** Есть одна книга проводок (журнал, append-only). Баланс, отчёт по контрагенту, отчёт по
проекту, выписка за месяц — это не четыре книги, а четыре **отчёта** по одной книге. Никто не ведёт «дерево проводок»
отдельно от «ленты проводок».

| Что просит владелец | Что это в рамке |
|---|---|
| Лог «что последовательно сделано» | сам журнал, линза «по времени» (почти бесплатно — журнал уже упорядочен) |
| Дерево / майнд-мап проекта | линза по рёбрам `part-of` (иерархия = частный случай ребра) |
| «Перевязанный между собой» | рёбра любого типа — та же сущность, что и `part-of` |
| Категории и пометки | теги = тоже рёбра (к узлу-тегу) или поле; линза-фильтр |
| «Видеть всю картину» | линза-карта (UI по видам — зерно 10-10 п.6) |

**Это уже архитектура мозга, а не новое предложение:** ADR-0016 (файловый журнал), ADR-0017 F2 (Postgres =
проекция журнала), `lens:prompt-compose` — первая линза-данные. Зерно владельца просит **вторую и третью линзу**, а
правило «≥2 случаев» (SYNTHESIS §2.3, push-строка) говорит: второй экземпляр линзы делает lens-as-data законным.

Проверка ценностями:
- **V1 Читаемость** — укрепляет, *если* акт захвата = подпись + указатель (дешёвая грань), а не тело переписки.
  Напрягает, если хук пишет полные тексты: каждый взгляд на карту = чтение всего. → правило: в журнал — label/summary/ref.
- **V4 Витальность** — **главное напряжение.** «Ничего не терять» звучит как «всё вечно и равнозначно» — прямой
  анти-паттерн Ц4. Разрешение: захватываем всё как *трассу* (дешёвую, остывающую), значимость (`salience`) растёт
  от обращений/связей; линза-карта по умолчанию показывает горячее. Без затухания карта станет шумом за неделю
  (триггер «cold» в SYNTHESIS §2.3 сработает сразу).
- **V6 Реляционность** — укрепляет и **требует**: дерево и перевязи держатся только если ребро — полноправная запись
  (id, источник, confidence), а не поле. Триггер «первая межпроектная связь» (§2.3) — это зерно его и дёргает.
- **V7 Согласие** — **односторонняя дверь.** Переписки содержат третьих лиц; журнал неудаляем; `hard_erase` мозг
  не выставляет. Вывод: пока нет стирания, в журнал идёт только то, что о владельце и его делах (роль вместо имени),
  а содержимое остаётся в удаляемом сырье. Указатель на сырьё не переносит чужие данные в неудаляемое.

**Альтернативная рамка, которая изменила бы рекомендацию:** «граф = отдельная база знаний (wiki/Obsidian-стиль),
журнал — только для задач». Если владелец под «графом» имеет в виду *курируемую карту проекта, которую ведёт
он сам*, то задача не захват, а редактор карты — и хуки вторичны. Вопрос Q1 ниже это вскрывает.

## 4. Самый дешёвый живой эксперимент (дни, без нарушения правил недели 1)

**«Дневник хода топика 56»:** в конце хода в топике 56 агент предлагает ОДНУ строку итога (что решили/сделали,
без имён) + ссылку на ход; после «да» — обычный `record` в `personal` типом-итогом (ядро или `u:`-тип, решает
лид), с ребром к `task`, если итог касается дела. Линза: команда «что было за день/неделю» → лента итогов.

- Вписывается в протокол недели 1: тот же механизм «предложил → да → record», та же граница имён, тот же топик,
  тот же export-стоп-кран. По сути — **это вариант М5 (итоги к записи), уже вынесенный в утренний визард** с дефолтом
  «нет в неделю 1; включается порогом с дня 4».
- **Мера пользы (через 3–4 дня):** владелец хоть раз спросил «что было» и получил ответ без перечитывания
  переписки — да/нет; доля «да» на предложения; ≥1 межтемная связь, которую агент нашёл по итогам.
- **Чего НЕ делаем в эксперименте:** хуки шлюза на авто-запись, копирование текстов, другие топики/проекты,
  карта-UI. Хук = шаг после стирания (Q5).

## 5. Связь с завтрашним запуском — ПОСЛЕДОВАТЕЛЬНОСТЬ, не замена

Тот же мозг, тот же журнал, та же петля (источник → запись → связь → читатель → действие → сигнал). Меняется
только **источник** (не фраза-обязательство, а итог хода) и **читатель** (лента/карта, а не утренний туду).

1. **День 0** — запуск как есть (туду + хвосты). Зерно не трогает кит.
2. **День 4** — если порог М5 пройден → включается «дневник хода» (§4) = первый живой шаг этого зерна.
3. **Конец недели 1** — `hard_erase` (триггер уже записан в §2.3) → открывает дверь Q5.
4. **Неделя 2** — хук-указатель «был ход» (R2-изменение шлюза, через agent-builder/«да») + вторая линза (карта).
5. Дальше — по триггерам: межпроектные рёбра (V6), затухание (V4), второй топик/проект.

Риск порядка: если подменить запуск этим зерном, получим ещё одну неделю проектирования без данных («замок на
пустом хранилище», HANDOFF 2026-08-16). Зерно — **причина запустить завтра**, а не причина отложить.

## Что эта модель НЕ покрывает (честно)
- Как читать сырьё по указателю, когда транскрипт Claude удалён/ротирован (указатель-сирота — та же болезнь, что V6).
- Ходы БЕЗ шлюза (обычные сессии Claude Code) — их хук другой; пока вне рамки.
- Нужен ли владельцу курируемый майнд-мап руками (альтернативная рамка) — вскрывает только Q1.

Итог: решение-рамка (один журнал, виды-линзы; «не терять» = адрес, не копия) → в лестницу вопросов новой сессии;
живой шаг = «дневник хода» с дня 4 через уже вынесенный М5; авто-хук отложен до `hard_erase` (конец недели 1).
