## 3. Высота старта

**Что сделано правильно:** петля B есть (цель, ценности, 5 вопросов, таблица статусов); вопрос 5 («неверная рамка?») и признание в E, что рамка могла быть неверной («владелец мог ждать продолжения видения»), — честно и ценно. Ни кода, ни git не трогал.

**Где скатился:** сообщение владельцу (C) — на ~80% операционное. «Запускал ли RUNBOOK» первым, «Предлагаю сегодня не рисовать дальше, а включить». К2, К3, К5 и ратификация видения прямо отнесены в «потом». Абстрактные вопросы высоты B1–B5 владельцу не отправлены вообще. Владелец же в последнем сообщении просил обратное: держать концепцию (п.24 «держа абстрактную концепцию»), понять связи вопросов (п.16).

**Приоритет «запускал ли?»:** как ФАКТ — первым ставить корректно (он ветвит план, README правила не запрещает). Как ПЕРВОЕ СООБЩЕНИЕ ВЛАДЕЛЬЦУ — смещение: этот факт добывает analyst из pm2/логов в той же волне (D1), владельца для этого дёргать не нужно. Правильнее: первым владельцу — рамка в двух абзацах (цель: запустить память В СОВОКУПНОСТИ с циклом метаморфозы; конструктор держим), затем «запускал?» как один из вопросов. Вердикт: НЕ чистый скат, но смещение к операциям; оправдано START §5, а не логикой владельца. Владелец хочет ОБА — лид выбрал одно.

Также: лид на B2 сам себе ответил «ни один из К1–К5 не блокирует» и использовал это, чтобы убрать вопросы. Это нарушает дух правила закона 3 (бюджет на вопросы): вопросы владельцу = вход, а не помеха запуску.
