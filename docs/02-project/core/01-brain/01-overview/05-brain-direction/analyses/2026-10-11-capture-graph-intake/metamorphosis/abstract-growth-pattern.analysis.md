# Линза высоты: метаморфоза = процесс первой системы. Паттерн «цикл роста»
- **Status:** draft · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-11
- **Потребитель:** лид следующей сессии; синтез папки `metamorphosis/`; видение `../../../ideas/2026-10-11-constructor-for-ai.idea.md`
- **Поглощает:** зерно владельца п.20–24 (`../../../ideas/2026-10-11-owner-seed-capture-graph.idea.md`), на уровне рамки
- **Вопрос-цель:** метаморфоза и «луп — развивать память» — это две вещи или одна?

## 1. Одна вещь, два взгляда
Да. Луп — взгляд **снаружи** (цель + линза «вопросы без ответа»). Метаморфоза — взгляд **изнутри**: путь, который проходит один узел. Единая модель в 5 строк:
1. Всё начинается с **узла-вопроса** (семя).
2. Каждый шаг цикла — **акт** в журнале (кто, когда, что сделал), не перезапись.
3. Каждая связь «выросло из / сгруппировано в / отвергнуто ради» — **ребро с паспортом** (V6).
4. **Решение** — узел с цепочкой `derived_from` к вопросам, идеям, анализам, голосам.
5. Луп = повтор цикла над всеми открытыми вопросами под одну цель; майнд-мап = линза над журналом на момент t.

## 2. Паттерн «цикл роста» (слой 2 конструктора)
**Шаги:** накидать → сгруппировать → расширить → (не расширяется) углубить → решить → остудить отвергнутое → родить новые вопросы.

**Триггеры (по умолчанию, хранятся как политика-данные, не в коде):**
- ≥7 несгруппированных детей → группировать.
- Попытка расширить дала <2 новых соседей → углублять внутрь.
- Ветка стабильна 2 цикла ИЛИ владелец просит → решать (сначала критик).
- Отвергнутое → `cold`, не удаляется.

**Роли:** владелец (сажает семя, вето, ратифицирует) · генераторы (агенты накидывают) · синтезатор (группирует) · критик (другой агент, до решения) · голосующие (линзы; голос = ребро с `author`).

**Выход:** узел-решение + рёбра `derived_from` + остывшие ветки + новые открытые вопросы. Следующий цикл питается именно этим.

| Ценность | Чем паттерн её держит |
|---|---|
| V1 Читаемость | у решения есть `label` + 3-строчное «почему», историю раскрываешь только по запросу |
| V2 Тождество | группировка и разделение меняют рёбра, не `canonical_id`; ветку после слияния можно найти |
| V3 Доверие | у решения видно провенанс: на каких анализах и голосах оно стоит и насколько свежих |
| V4 Витальность | проигравшие ветки остывают и могут ожить, база не раздувается «вечным-равнозначным» |
| V6 Реляционность | «выросло из», «голосовал за» — это память того же ранга, что и сами узлы |

## 3. «Git для смысла»
| Git | Для мыслей | Цена / ценность |
|---|---|---|
| commit | акт в журнале (уже есть в модели) | ~0 / основа |
| log | журнал, отфильтрованный по поддереву вопроса | дёшево / **много** |
| blame | **линза «почему»**: решение → цепочка `derived_from` | дёшево / **максимум** |
| branch | вариант = узел-сосед с ребром `alternative_of` | дёшево / средне |
| merge | группировка в тему, тождество сохраняется (V2) | средне / средне |
| diff | два среза линзы на моменты t1 и t2 | дорого / позже |

Самый дешёвый рычаг: **blame + log**. Оба — просто чтение рёбер и журнала, нового механизма не нужно.

## 4. Курица и яйцо: семя
Семя — **один реальный вопрос из этого чата: «как должна расти память?»**. Прогоняем один цикл вручную:
- **Сейчас, в доках:** один дом-узел с папками `questions/ ideas/ decisions/`; у каждого файла во frontmatter `derived_from`, у голосов — `author`. Накидать ≥15 → сгруппировать в 3–5 тем → каждую один раз расширить или углубить → критик → одно решение.
- **После запуска мозга:** тот же цикл, но записями (это и будут первые 5 реальных записей, гардрейл соблюдён).
- **Стоп-условие:** один полный цикл ИЛИ 2 сессии, что наступит раньше. **Тест успеха:** свежий агент без чата отвечает «почему принято это решение» по цепочке за ≤5 строк. Не прошло — паттерн неверен, это тоже итог.

Курица и яйцо снимаются так: процесс и память стартуют **одним** прогоном, потому что первая запись памяти — это и есть след процесса.

## 5. Что НЕ строить
- Движок процессов / оркестратор цикла: процесс = линза + политика.
- Отдельную сущность «метаморфоза»: это акты + рёбра.
- Свою VCS или хранилище «как git»: журнал уже append-only.
- Машинерию голосования: голос — это ребро.
- Авто-кластеризацию для «сгруппировать»: группирует агент-синтезатор.
- Визуальный майнд-мап UI и diff-линзу: только после живого цикла.
- Жёстко зашитые числа в триггерах.

**Ответ на вопрос-цель:** это одна вещь. Вопрос был верен.

Итог: задача в плане — ручной прогон одного цикла по семени «как должна расти память?» в доках (стоп: 1 цикл / 2 сессии, тест «почему за ≤5 строк»), затем повтор записями в мозге после запуска по RUNBOOK.
