## Мысль владельца в одной фразе (сошлись 3 линзы)
«Всё важное, что происходит между мной и агентами, оставляет след, который потом можно НАЙТИ и СВЯЗАТЬ в общую картину —
без моей ручной дисциплины». Это и есть исходное видение проекта (msg 141); новое — «сейчас, вживую, автоматически».

## Ключевой рефрейм
Сырьё уже не теряется: транскрипты Claude, БД шлюза (сообщения, суммарии, журнал решений) — всё лежит. Теряется
**адрес и связь**: найти и увязать нельзя. Значит «ничего не терять» = **у каждого важного события есть адрес** (ссылка +
короткая подпись + связи + теги), а **не копия текста** в неудаляемом журнале. Дерево, майнд-мап, теги, лента-лог —
это **ЛИНЗЫ (виды) над одним журналом**, а не четыре системы. Мозг уже так устроен (ADR-0016/0017, `lens:prompt-compose`).

## Что уже есть / чего нет (analyst, с file:line в сырье)
Есть: узлы, рёбра (`link`, `traverse`), области, `find/read/lens`, журнал актов; в шлюзе — сырьё разговоров.
Нет: типа «разговор/тема/итог хода» (временно — `note` + рёбра `about`/`part-of`), поля тегов (тег = узел+ребро),
моста «ход → запись», хука записи (в шлюзе подключён только стоп-лист), вида «карта проекта» из мозга, поиска по телу.
F6 (R1–R6) захват разговоров как ЗНАНИЯ не планирует — это новый шаг лестницы.

## Красные линии (critic, сходится с неделей 1)
- Чаты полны третьих лиц, сервер ловит только email/телефон → **нельзя авто-писать текст чатов**.
- Журнал неудаляем, стирания нет → **авто-захват только ПОСЛЕ `hard_erase`** в мозге.
- V4: «всё вечно» → нужен «остывание» и вид «только активное» по умолчанию.
- Не сбить гейт 7 дней: новый захват — отдельным типом и счётчиком.

## Последовательность (не замена запуску)
Запуск по RUNBOOK (туду) → с дня 4 «дневник хода»: агент предлагает 1 строку-итог, пишет после «да», роль вместо имени →
конец недели 1: `hard_erase` в мозге (спек+код) → неделя 2: хук шлюза пишет «был ход: топик·время·ссылка», агент — подпись
→ первая линза «лента дня по топику» → потом «карта проекта» (майнд-мап с поперечными связями).
