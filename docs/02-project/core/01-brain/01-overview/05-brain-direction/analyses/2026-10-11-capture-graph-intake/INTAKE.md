## Мысль владельца в одной фразе (сошлись 3 линзы)
«Всё важное, что происходит между мной и агентами, оставляет след, который потом можно НАЙТИ и СВЯЗАТЬ в общую картину —
без моей ручной дисциплины». Это и есть исходное видение проекта (msg 141); новое — «сейчас, вживую, автоматически».

## Ключевой рефрейм
Сырьё уже не теряется: транскрипты Claude, БД шлюза (сообщения, суммарии, журнал решений) — всё лежит. Теряется
**адрес и связь**: найти и увязать нельзя. Значит «ничего не терять» = **у каждого важного события есть адрес** (ссылка +
короткая подпись + связи + теги), а **не копия текста** в неудаляемом журнале. Дерево, майнд-мап, теги, лента-лог —
это **ЛИНЗЫ (виды) над одним журналом**, а не четыре системы. Мозг уже так устроен (ADR-0016/0017, `lens:prompt-compose`).

## Что уже есть / чего нет (analyst, с file:line в сырье)
Есть: узлы, рёбра (`link`, `traverse`), области, `find/read/lens`, журнал актов; в шлюзе — сырьё разговоров.
Нет: типа «разговор/тема/итог хода» (временно — `note` + рёбра `about`/`part-of`), поля тегов (тег = узел+ребро),
моста «ход → запись», хука записи (в шлюзе подключён только стоп-лист), вида «карта проекта» из мозга, поиска по телу.
F6 (R1–R6) захват разговоров как ЗНАНИЯ не планирует — это новый шаг лестницы.

## Красные линии (critic, сходится с неделей 1)
- Чаты полны третьих лиц, сервер ловит только email/телефон → **нельзя авто-писать текст чатов**.
- Журнал неудаляем, стирания нет → **авто-захват только ПОСЛЕ `hard_erase`** в мозге.
- V4: «всё вечно» → нужен «остывание» и вид «только активное» по умолчанию.
- Не сбить гейт 7 дней: новый захват — отдельным типом и счётчиком.

## Последовательность (не замена запуску)
Запуск по RUNBOOK (туду) → с дня 4 «дневник хода»: агент предлагает 1 строку-итог, пишет после «да», роль вместо имени →
конец недели 1: `hard_erase` в мозге (спек+код) → неделя 2: хук шлюза пишет «был ход: топик·время·ссылка», агент — подпись
→ первая линза «лента дня по топику» → потом «карта проекта» (майнд-мап с поперечными связями).

## Один примитив (Fable, сошлись architect + prior-art)
**Всё — типизированное РЕБРО с паспортом** (Ц6 уже ратифицирована); узлы — дешёвые якоря с подписью. Метки, связи задач
между проектами, слой людей, политики хранения, линзы, цели — это утверждения о связях **в том же графе**: граф описывает,
как себя читать. Держится на «полу» из ~5 механизмов в коде (валидатор имён, шлюз согласия, `hard_erase`, корневая
линза-для-линз, остывание). Текст в рёбрах не живёт («адрес, не копия»).

## Как ложатся желания владельца
| Желание | Форма в памяти | Когда |
|---|---|---|
| глубокий майнд-мап | дерево = линза по рёбрам `part-of`; поперечные — любые типизированные рёбра | линза-лента сразу, карта потом |
| слой людей | `person` = узел-роль (непрозрачный id); имя — отдельный псевдоним-узел через ребро `named-as`, со статусом согласия; имя только в стираемой зоне payload | форма сейчас, имена — после `hard_erase` |
| удаление по категориям/источникам/плагинам | `policy`-узел (never / ttl / по запросу) + ребро от класса источника; never — до записи в журнал, ttl — садовник стирает payload | ADR (номер после 0018) |
| задачи ↔ источники разных типов | рёбра `informed` / `part-of` / `motivated-by` (уже в ядре) | сразу |
| метки, умные фильтры, категории | метка = узел + ребро; умный фильтр = сохранённая линза | сразу (вручную) |
| цель лупа + наслоение | `u:goal` (кандидат); ответы цепляются рёбрами (`answers`/`informed`); «вопрос без ответа» = следующая задача лупа; линза цели рисует картину по областям | после первого живого лупа |

| луп «развивать память» | цель-узел «память» + луп, пишущий ответы/пробелы; тест вручную в этом чате | эксперимент |

## Односторонние двери (решить ДО реальных данных) — новое
1. **В id, рёбрах и провенансе НИКОГДА нет имён и смысла** — стирание вычищает только payload, а id/рёбра/провенанс вечны
   (`packages/engine/src/core/erasure.ts:34-44`). Проверено: id юнитов случайные (`packages/brain/src/domain/ids.ts:22`) ✅;
   поле `why` = провенанс → имена запрещены (уже в протоколе недели 1) ✅. Добавить в чек-лист ADR-0017.
2. Метка/тег — ребро со своим id, не массив `tags[]` в поле.
3. Паспорт / стираемый payload разделены физически (шов есть, by-ref стирание не построено).
4. `referent` + `origin` на каждом акте (кто/о ком, откуда).
