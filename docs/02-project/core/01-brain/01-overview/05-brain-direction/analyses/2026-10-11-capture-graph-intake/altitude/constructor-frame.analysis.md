## 1. Стек конструктора — шесть слоёв, не пять
Предложенный стек «принципы → паттерны → пакеты/системы → экземпляры → виды» верен с одной поправкой: **«пакет» и «система» — разные слои**. Пакет — словарь (типы, предикаты, политики, линзы), переиспользуемый. Система — *собранный живой экземпляр* словаря: пакет(ы) + роли + процесс + цель, привязанный к области. Склеить их — повторить ошибку «цель ≠ организация» (п.18) уже в архитектуре.

| # | Слой | Что это | Где живёт СЕГОДНЯ |
|---|---|---|---|
| 0 | **Пол** (принципы) | код, не данные: Конституция, валидатор имён, consent-gate, `hard_erase`, корневая линза «показать линзы», decay | `constitution.ts`, `erasure.ts`, двери данных (SPEC-brain-data-doors) — есть, кроме erase/decay |
| 1 | **Паттерны** | формы-как-данные: `type-def`, `predicate-def`, `policy`, `lens`, **role**, **process** | type/predicate-def в genesis, `sys:lens@1`, `sys:prompt-layer`, policy-узлы M-G3; **role и process как данных нет** |
| 2 | **Пакеты** | именованный версионированный набор паттернов | манифест `manifest_v:0` — зарезервирован (ADR-0017 D5), 0 экземпляров |
| 3 | **Системы** | пакет(ы) × область × роли × цель × луп («организация», «баг-трекер», «луп с целью») | **не существует**; ближайшая тень — `scope` (`in-scope`) |
| 4 | **Записи** | акты, узлы, рёбра | журнал |
| 5 | **Виды** | линза, применённая через `sys:viewed-through` | `lens:prompt-compose@1`; вьюер concept.json шлюза |

Дыра — слой 3. Система должна быть **узлом** (`sys:system`/`u:system`) с рёбрами `uses-pack`, `has-role → principal`, `governed-by → policy`, `motivated-by → goal`, `viewed-through → lens`. Если система останется строкой-областью, она не экспортируется цепочкой (V5) и не несёт политик (Ц5).

## 2. Что такое паттерн и как он переиспользуется
Паттерн = **пятёрка данных** под одним именем `name@major`: (1) type-def(ы), (2) predicate-def(ы), (3) политика-умолчание (retention, visibility, approval), (4) линза-умолчание, (5) слоты ролей = какие принципалы вправе писать (`capabilities_requested`). Всё пять уже имеют дом в ADR-0017 D1/D5 — нового слоя ядра не требуется, нужен только явный узел-паспорт, который их связывает.

Три операции переиспользования, все уже ратифицированы, но названы разрозненно:
- **instantiate** — ребро `instance-of`; id записи непрозрачен и не меняется при смене паттерна (V2, ADR-0017 D1).
- **extend** — `extends`/`implements: ["task@1"]`; ломающее → `@2` + upcaster, журнал не правится.
- **compose** — пакет `requires.packs`; конфликт кардинальностей → `assertForwardMonotone` fail-closed (`patterns-as-rules` §5). Следствие честно: «любой паттерн» = «любой не конфликтующий с уже наложенным». Ограничители композиции как данные — открытая задача, не решать до второго пакета.

Неочевидное: два режима тождества. Записи — непрозрачные `u_…`; паттерны — **семантические имена** (`typedef:task`), на которые указывают рёбра. Значит переименование паттерна невозможно — только `supersedes`. Для троп `u:` это правило надо сказать до первой тропы: имя тропы — навсегда.

## 3. Проверка аналогией: Claude Code = первый прототип конструктора
| Claude Code | Конструктор | Статус у нас |
|---|---|---|
| `CLAUDE.md` каскад user→project→topic | prompt-layer + `lens:prompt-compose` (порядок слоёв) | **уже в памяти** (R1) — слой 1 обжит |
| `rules/` (проза, всегда в контексте) | policy — но у нас это *исполняемые* данные, а не текст | разрез «пол vs данные» — то, чего CC не имеет |
| `skills/` (frontmatter + процедура; description грузится всегда, тело по триггеру) | паттерн = линза `layout: wizard` + **поле `trigger`** | концепт.json-мост (архитектор §1); `trigger` — отсутствует |
| `agents/` (роль + границы + tools) | role = принципал `sys:`/`pack:` + capability | принципал есть, role-как-узел нет |
| `hooks/` | пол (код), никогда не данные | совпадает с Fable §1 |
| `plugins/` + marketplace | pack + реестр пакетов | манифест резерв; маркетплейс — позже |
| `settings.json` permissions | `capabilities_requested` | есть форма |

Брать: (а) **прогрессивное раскрытие скилла** — description всегда, тело по триггеру — это ровно Ц1 `label → summary → payload`, и это даёт паттерну поле `when` (условие включения в контекст); (б) frontmatter как паспорт паттерна. Не брать: у CC нет тождества, согласия, остывания и журнала — файлы перезаписываются. Честный диагноз нашего `.claude/`: это **пакет без системы** — есть правила и агенты-прозой, нет ролей-данных, процесса и цели как узлов.

## 4. Управление контекстом — первоклассный паттерн
«Интерфейс для ИИ» (п.17) — не экран, а то, что попадает в окно контекста. Значит **линза = композитор контекста**, и `lens:prompt-compose` уже доказал это на промптах. Обобщение: контекст хода = Σ линз, применённых к `ctx{bot, chat, topic, user, project, agent, goal}`, с бюджетом. Для этого `sys:lens@2` обязана нести `budget` (токены) и ярусы раскрытия (label/summary/payload по бюджету) — тогда `price_hint` из Ц1 становится реальным, а не идеей. Без `budget` в линзе композитор контекста уйдёт в код — это дверь.

## 5. Первая система — «луп с целью: развивать память»
Кандидаты: личный туду — уже запускается, но это тропа, доказывает слой 1, не 3. Баг-трекер F5 — бумага, доказывает слой 2, но без ежедневной тяги владельца. Наш POS-сетап как данные — самое амбициозное, но мета и огромно: язык до 50 актов (ловушка Fable §4). **Выбор — луп с целью** (п.15): единственный кандидат, в котором есть ВСЕ слои сразу и малыми: цель = `u:goal`; роли = лид/помощник/критик (уже описаны в методе — переводятся в принципалов); процесс = петля вопросов старт→волны→критик→хендофф (`altitude-question-loop`), выраженная НЕ workflow-движком, а линзой «следующий шаг» = `asks` без `answers`; записи = итоги ходов этого чата; вид = линза цели. Он поглощает туду как данные (`task motivated-by goal`), не заменяя запуск, и компаундит: каждая сессия кормит граф, вопросы становятся узлами (закон 4 правила вопросов). Тест успеха за 5 сессий: **хендофф генерируется линзой цели, а не пишется руками**. Если для этого понадобился новый код — примитив ложный.

## 6. Односторонние двери
Добавляет: (1) `status` записи = 4 ядровых (`proposed|active|retracted|superseded`), доменное состояние — поле `state` в payload под паттерном; иначе баг-трекер потребует второй enum в коде. (2) `sys:lens@2` несёт `budget`/ярусы. (3) Система — узел, не строка области; человек↔роль — ребро `person → principal`, не имя в строке принципала. (4) Имя тропы `u:` — навсегда, только `supersedes`. (5) Паттерн несёт `when`/`trigger` (условие включения в контекст) — ретрофит дёшев, но без поля композитор не бутстрапится.
Снимает: дверь «процессный движок» (процесс = линза + политика переходов, не workflow-engine); дверь «своя UI» (виды = линзы через существующий вьюер); напряжение «пакет vs тропа» (всякая система рождается тропой, повышение = перепривязка `instance-of`, уже в ADR-0017).

Итог: решение-предложение — стек из 6 слоёв (пакет ≠ система; система = узел с рёбрами к пакетам/ролям/цели/линзе); паттерн = пятёрка данных `name@major`; первая собранная система = «луп с целью развивать память» в этом чате; 5 дверей §6 — в спек данных до первого `u:goal`; critic проверяет до фиксации.
