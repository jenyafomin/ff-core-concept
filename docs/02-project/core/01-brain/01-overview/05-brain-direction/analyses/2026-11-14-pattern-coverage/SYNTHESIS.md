## Компас (abstract, принят лидом)
Память, где **любое утверждение знает: откуда оно, когда верно, чьё оно, кому видно и что из него следует** — и агенты работают во всех доменах ОДНИМ механизмом.

## Что сделано (3 волны, 8 линз)
- Каталоги: 54 паттерна аренды (P) + 34 универсальных (U: Wikidata, Datomic/XTDB, gUFO, RDF 1.2, Fowler; личная жизнь) + инвентарь 21 примитива ff-brain по коду.
- Бумажная компиляция 4 сценариев (37 шагов): ущерб→залог→долг · бронь→начисление→доля инвестора · давление и сон · друг/долг/обещание.
- **Сейчас: 7 ✅ / 20 🟡 / 10 ❌.** Чаще всего ломает: тип нельзя завести данными (12 шагов), нет значения/производного/баланса (11), нет времени «с–по» (6), нет утверждения-как-единицы с ролью/условием/рангом (6).
- **На новой грамматике: 30 ✅ / 2 «исполнение вне памяти по замыслу» / 5 🟡 / 0 ❌.** Тест «Петя в двух мирах» (клиент с долгом аренды = друг, которому я должен): все 5 ответов выводятся из 14 записей без доменного кода — при 3 доработках (H1, H2, H4).
- Цифра «94% паттернов» — самооценка автора, НЕ доказана (critic); доказательство — компиляция по шагам выше.

## Грамматика — три уровня (снятие расхождения 9 примитивов vs 6 мета-классов)
1. **Атомы:** единица (тождество) · **утверждение** (адресуемый атом факта: свой id, роли/уточнители, источники — как statement в Wikidata; ребро с паспортом, провенанс и ранг — ОДИН механизм) · значение (сумма+единица, «нет» ≠ «неизвестно»).
2. **Оси на каждом утверждении («пол», общий для всех доменов):** время (когда верно / когда узнали) · вера (ранг, уверенность, модальность: факт/гипотеза/план/обещание) · доступ (политика, согласие).
3. **Классы поведения:** мета (тип, предикат, вид, правило — тоже единицы) · событие (участники в ролях + интервал) · производное (результат со ссылками на входы и версию правила) · вид. **Акт-транзакция** (несколько утверждений атомарно, сумма проводок = 0, сторно вместо правки) — инвариант акта, не класс.
Граница: **что, когда, насколько верно, кому — данные; кто считает, будит, стирает — код** (8 общих гарантий кода, без доменного кода; вычислители — в пакетах домена).

## Что композиция даёт сверх примера (E1–E9, подтверждено «Петей»)
Один человек в нескольких ролях без утечек · «тот же человек» ≠ «та же сторона долга» (−550 сводить нельзя) · сама связь «клиент = друг» — секрет · доверие к цифре = слабейшее звено цепочки · «что было известно на дату» · «почему» как цепочка решений · один детектор дыр/противоречий на все домены · вид-как-запись = линза для любого домена · схема учится из трения · агент сам живёт в памяти и проверяется теми же механизмами · новое действие «запросить согласие».

## Односторонние двери — до ЛЮБЫХ реальных данных (одним ADR «форма»)
1. Непрозрачный id утверждения (+ необязательный естественный ключ); старые hash-id остаются.
2. Время «с–по» на утверждении, явное `unknown` (не выдумывать `valid_from = recordedAt`).
3. Форма акта: много утверждений атомарно, сторно для проводок. Конфликт: устав «≤3 записи/ход» → считать акт, а не утверждения.
4. Кодировка значений: decimal строкой, тег типа, `none`/`unknown`.
5. Разделение тела и меты под будущее стирание (иначе реальные ПДн нельзя).
6. Открытый слот уточнителей; всё меняющееся во времени — утверждением сразу, не полем.
+ из компиляции: H1 политика на отдельном утверждении (врач видит давление, не сон) · H2 вывод наследует самый строгий доступ входов · H4 регистр/баланс по контрагенту.

## Порядок
1. **ADR «Грамматика v2 — форма»** только из дверей выше (1–2 дня, бумага).
2. **Тип как данные** (агент предлагает → владелец утверждает) — обратимо, снимает `raw`, «строй» уже был в гибком росте; параллельно.
3. Заливка документов FF как адресов (SPEC 11-01) — уже в новой форме утверждения.
4. Фактический прогон на обезличенном срезе аренды (сценарии S1/S2) после Postgres-шва.
Здоровье: доля записей в `raw`/без класса падает, число атомов и осей не растёт.

## Цена
Запись дороже в 2–3 раза (S1 ≈34 записи против 12) → балансы хранить готовыми записями-сводками, ежедневные начисления только вычислять на дату (V1).
