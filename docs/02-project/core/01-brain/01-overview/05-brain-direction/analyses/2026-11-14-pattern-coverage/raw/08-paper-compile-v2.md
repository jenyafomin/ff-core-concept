## 0. Нотация и метки
`U{type@v, facets}` — единица G1, тип — единица G3 (`t_x@v`, заводится один раз через proposed→owner). `S{subj·pred·obj, q:{…}, src, rank, ep, vt:[from,to)}` — утверждение G2/G4/G6. `$` = `money{amount,cur}`, `Q` = `quantity{amount,unit}` (G7). `D{calc@v, in:[id@rev]}` — производное G8. `V{…}` — вид G9. `P{…}` — политика G10. `occ` — событие G5.
✅ — данные выражаются, нужен только общий (не доменный) код движка · 🟡в — данные есть, исполнение вне памяти по замыслу (§4 в 04) · 🟡д — дыра грамматики · ❌ — не выразить.

## 2. Эксперимент «Петя в двух мирах»
**Минимальные записи (14):** `u_p1` person «Пётр» (personal, src: телефон) · `u_p2` «Petya» (personal, telegram), `canonical_id:p1` · `u_p3` клиент (rentacar) · `S{p3·same_as·p1}` P:owner-only · `u_co` компания · claim approved + charge $1200 + deposit $3000 + проводки → долг p3→co $1450 · personal: проводка me→p1 $2000 + обещание до 1-го · `S{p1·address, src:anya, ep:hypothesis, pii}` · 3× окно W + contradicts · decision D (grounds: claim).

| В | Ответ | Путь (примитивы) | Код |
|---|---|---|---|
| 1. Один человек? | Да, для владельца: p2→p1 (canonical), p3 same_as p1 | G1 + G2 + G10 | резолв canonical; ⚠ same_as **пересекает области** — его видимость должна быть у утверждения, а G10 только на единице (H1) |
| 2. Агент аренды узнаёт о личном долге? | Нет: проводка в personal, грант агента = rentacar; **и** same_as скрыт — агент не узнаёт даже, что клиент — друг | G10 + области M:N | гейт чтения; если вид сводит обе области, итог должен наследовать строжайшую политику входов — в грамматике нет (H2) |
| 3. Сколько мы с Петей должны? | **Не одно число.** p3 должен компании $1450 (asserted, по одобренной претензии); владелец должен p1 $2000 (со своих слов). Свёртка «−550» ЗАПРЕЩЕНА: стороны разные (компания ≠ я) | G7 + G8 баланс по паре (регистр, контрагент) + G9 вид owner-only + G6 | `ledger.balance`; ключ баланса — контрагент, а не человек (H4) |
| 4. Возьмёт адрес со слов Ани? | Нет, по двум причинам, и обе объяснимы: ep=hypothesis (клапан на внешнее действие требует asserted+preferred) и pii в personal — агенту не видно | G6 + G2 src + G10 | гейт внешних действий: правило — данные `sys:rule`, исполняет код |
| 5. Почему залог не вернули? | «Удержано $1200 по претензии, одобренной решением D (2 подписи); срок окна не установлен — 3 противоречащих источника, вопрос открыт» | G2 обратный обход + G8 входы + G6 contradicts + G4 as-of | обход провенанса — обязательная операция G9 |

**5/5 выводятся на бумаге**, ни одной строки доменного кода; прогноз 06 (провал на 2/3/4) не сбылся — но 2 и 3 держатся только при закрытии H1/H2/H4.

## 3. Эмерджентность, проявившаяся на деле
1. **«Тот же человек» ≠ «та же сторона».** Ни аренда (не знает друга), ни личное (не знает компании) не может сказать, что свёртка −550 ложна. Общая память обязана это различать — иначе её главная фича (одно тождество) порождает ложные выводы.
2. **Связь — сама информация.** Утечка шла бы не через долг, а через ребро same_as: «клиент — друг владельца». Ни одна система отдельно этого риска не имеет.
3. **Отказ с объяснением.** В4 даёт не «нельзя», а две причины-записи; это тот же механизм, что «почему» в В5 — объяснимость одна на отказ и на ответ.
4. **Честное «не знаю» в цепочке.** В5 включает неизвестное (окно W) как часть ответа — дыра становится видимой задачей.
5. **Заблокированная ценность как продукт.** Подтверждённый адрес из личного улучшил бы контакт аренды, но согласия нет → естественное действие «запросить согласие у Пети» — его нет ни в одном домене.

- **Рост ×2–3 на бизнес-сценарий** — от паспортов, подписей, противоречий. Правило «поле = утверждение без паспорта, inline в facets» обязательно, иначе С-1 даёт ~60 строк.
- **Конфликт с уставом MCP «≤3 record за ход»:** S1 = 34 записи → нужен **один атомарный акт со многими утверждениями**, иначе агент пишет сценарий 10 ходов.
- **V1 (дешёвый взгляд):** баланс через обход всех проводок дорог → материализованный `D` с label/summary обязателен; посуточные начисления (S2·3) хранить нельзя (~30 строк на бронь в месяц) — только ленивое as-of (H6).
- `canonical_id` и same_as удешевляют чтение, но каждый вопрос вида «на дату» по `tstzrange` — индекс GiST на `statement`, не опция.
