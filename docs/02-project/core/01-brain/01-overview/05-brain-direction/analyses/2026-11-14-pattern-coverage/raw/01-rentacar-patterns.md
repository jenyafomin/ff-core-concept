## Составные сценарии (5+ паттернов вместе)
**S1. Ущерб → претензия → штраф → залог → долг.** Находка при приёме (P-26 гейт) → сверка фото выдачи (P-25 шаг, P-33 фото-вложение) → `ST-claimed→approved` (P-28) с суммой выше порога → Владелец (P-51/P-49) → штраф «Damage» (P-18 журнал) → таймер окна залога (P-19, P-20 с расходящимися 14/21/30, P-45/P-46) → удержание из залога, остаток = долг клиента (P-35). Исход «закрыто вручную» (P-30), претензий в данных 0 (P-47). Источник: `flows/damage/_overview.md`.

**S2. Бронь → выдача → начисление → доля инвестора → выплата.** Заказ (P-01, P-02) → сутки аренды капают виртуальным начислением (P-35, P-34) → условия задним числом пересобирают период (P-24) → держатель машины по периодам (P-17) → месячный движок инвестора `Income × share − Expenses` (P-34, P-40) → «не сходится» 1 820 vs 2 360 (P-39, P-46) → бухгалтер проверяет, владелец утверждает (P-41, P-42, P-51) → выплата зеркальной проводкой (P-36). Источник: `engines/investor-accrual.md`, `P/DECISIONS.md` D93/D105/D121.

**S3. Деньги с руки на руку (держатель + передача).** Водитель сдал наличные (P-31 «Передал»→«в пути») → у ценности один держатель (P-32) → получатель «Принял» целиком/частично с расхождением 1 450 vs 1 400 (P-26, P-39) → баланс только после «Принял» (P-35) → «в пути» дольше 20:00 видно бухгалтеру (P-19) → вид владельцу утром (P-52, P-21) → грант на чужую кассу на срок (P-49). Источник: `patterns/PAT-handover.md`, `PAT-holder-grant.md`, `views/owner-daily`.

## Заметка по глубине
