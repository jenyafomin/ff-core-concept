Потребитель: свод волны pattern-coverage (приоритет грамматики). Поглощает: ничего (сырьё линзы).

## Формат и правила, по которым компилировал (по коду)
- `record{type,label,fields,scopes,edges[{pred,to}],initiative,id,retract,reason,derived_from[u@rev],source{kind,ref,hash}}` — `contract.ts:244-262`. `link{from,pred,to,confidence,note,status}` — `contract.ts:409-417`.
- Ядро-типы: task·decision·note·person·day (+служебные) — `genesis.ts:150-196`. Неизвестный тип → `raw` + `declared_type`, поля терпятся как есть — `validate-act.ts:437-457, 245`. Объявить свой тип нельзя (03-primitives §2.1).
- Предикаты: 16 из genesis (`genesis.ts:210-227`). Неизвестный предикат → ошибка `UNKNOWN_PREDICATE`, не raw.
- Поля: только скаляры и `string[]`; число без единицы; дата — просто поле.
- Ребро: id = hash(from·pred·to). На одну пару и предикат приходится одно ребро, без времени и условия.

Метки: ✅ ложится как есть · 🟡 с костылём · ❌ не выразить. Коды недостающих примитивов (M) — в сводке внизу. Имена обезличены, суммы условные, область `rentacar` / `personal`.

**Выводы для грамматики (вывод агента):**
1. Все 7 ✅ — слой знаний: заметка, решение, задача, `derived_from`, ретракт, `proposed`. Как граф знаний память держит. Ломается всё, что есть **вещь со своей формой** (M1), **число** (M3) или **время действия** (M2).
2. **M1 ломает чаще всего, и чинить его дёшево.** Это не односторонняя дверь: в flexible-growth уже решено «строй», маршрут — «агент предлагает тип, владелец утверждает». Пока M1 не закрыт, любой бизнес-объект попадает в `raw` и не виден пресетам. Начинать с него.
3. **M3 — граница пола.** Нужна форма «правило + входы → запись с провенансом» и значение с единицей. Половина уже есть: `derived_from[u@rev]` закрыл шаги С-1·6 и S2·6 по провенансу. Не хватает версии правила и количества.
4. **M2 и M4 — по частоте меньше, но по цене первыми.** Это односторонние двери (03-primitives §4.1–4.3): журнал append-only, id ребра без времени. Valid-time и паспорт ребра, не записанные сейчас, для старых актов потеряны навсегда. Порядок по риску: M2/M4 зафиксировать формой до реальных данных, M1 построить, M3 спроектировать.
5. M4 и «источник-человек» сходятся с наблюдением из 02-universal §2: паспорт ребра, провенанс и ранг — один механизм (statement с квалификаторами). Делать их двумя примитивами — ошибка.
