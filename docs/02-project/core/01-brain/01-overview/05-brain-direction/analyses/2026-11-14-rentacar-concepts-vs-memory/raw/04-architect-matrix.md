## 2. Итог
**Топ-5 расширений:** (1) одна память на несколько проектов (области M:N); (2) `proposed` по коду, а не по договорённости; (3) шов согласия `referent`; (4) мягкий вход неизвестных типов с трением; (5) адрес вместо копии (`source.ref`+hash) — лечит «6 мест хранения».
**Топ-5 ограничений:** (1) нет вычислительного ядра и SQL — ядро rentacar некуда поставить; (2) типы и предикаты в коде, реестр не данные; (3) ребро беднее: нет `found_in/src_anchor/weak/conds`; (4) права только на уровне области, без ролей, сроков и `deny`; (5) масштаб: журнал в памяти + лимиты ≤50/≤2 против 15 тыс. рёбер.
Честно: по 8 осям из 13 bp-docs сильнее. Память сильнее только в межпроектности, согласии и строгости `proposed`.

## 3. Модель отношений
**Рекомендация: Б сейчас + В на бумаге. Модель А отвергнута.** Паттерн — Ports & Adapters: каждый экземпляр сам владеет хранилищем и вычислениями; общий только **контракт грамматики** (единица · ребро с паспортом · тип-как-данные · статус знания · адрес).
- Б: мозг держит про rentacar только решения и вопросы с `source.ref` на `entity.id` bp-docs; тело и граф — в bp-docs. Копия сущностей = вторая правда.
- В: проверить «7 примитивов × 3 вещи» (`03` §4). Общий код — только после прохода теста.

**Что ff-brain стоит взять из bp-docs (по цене):**
1. `found_in` + `src_anchor` + `weak` в паспорт ребра — мало, много веса (V3, V6). Сюда же: meta не входит в id ребра.
2. `presence`-набор (renamed/stub/absent) поверх retract/supersede — мало (V2, V4).
3. Реестр типов и предикатов как данные со схемой — средне, закрывает общую дыру.
4. Снимки all/normal для любых агрегатов (overview, stats): закрытое не протекает в числа — мало (V7).
5. ACL-гранты со сроком и `deny`, позже материализованные — средне. Но только с выходом на Postgres (ADR про хранилище уже есть).
6. Query-DSL по белому списку видов — средне. Нужен, когда `find` перестанет хватать.
7. Ядро как чистая функция + оракул — это шаблон для «процесс = линза». Сам движок не берём.
Чего не брать: двойной дом истины (git ↔ живой слой без обратного пути) — у bp-docs это признанный предел.

## 4. ADR
Нужен один ADR, после теста В: «Отношение ff-brain ↔ доменные системы (bp-docs): читатель по адресам + общий контракт грамматики». Внутри:
- запрет копировать тело;
- формат адреса `bp:<entity.id>`;
- расширение паспорта ребра (`found_in/anchor/weak`) — это меняет схему и потому одностороняя дверь до первых реальных данных;
- какой реестр типов признаём общим.

Модель Б начинается без ADR (это просто записи с `source.ref`); отказ от А — строкой в том же ADR.

Итог: решение — Б сразу, В после бумажного теста, ADR о контракте грамматики и паспорте ребра.
Вопрос-цель: ответил — память расширила бы межпроектность, согласие и строгость предложений; ограничила бы вычислениями, реестром типов, паспортом ребра, ACL и масштабом. Верная модель — независимые экземпляры с общей грамматикой, связь только по адресам.
