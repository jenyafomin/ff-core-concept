## Настоящий вопрос
Не «помогла бы память rentacar», а: **два проекта независимо построили один и тот же конструктор — «модель как данные, растёт записью, а не кодом». Какая у него общая грамматика и где она должна жить?**
Пять «почему»: зачем сравнивать → чтобы не строить дважды → а почему строят дважды → потому что у памяти нет слоя «система» (слой 4 конструктора), а bp-docs и есть такая система, только на бумаге и в своей базе → значит, rentacar не клиент памяти, а **второй живой случай**, которого ждал гейт «обобщать только из ≥2».

## 1. Примитивы: одно и то же под разными именами
| Примитив | rentacar bp-docs | ff-brain | Вывод |
|---|---|---|---|
| Единица | `entities` + `facets jsonb` | запись, `canonical_id`, открытые поля | одно |
| Тип | `info-types.yaml`, 52 типа строкой; «своё у типа нигде не записано» | объявление типа данными — маршрута нет, 13 типов в коде | **одна и та же дыра** |
| Вложение | `parent_id`; любой шаг может быть процессом | область, рёбра, папки-узлы | одно |
| Связь | 696 описанных связей, «у связи своя страница» | V6: ребро — память того же ранга | одно |
| Слой знания | «гипотеза до да», утверждено 0 из 9 | `proposed → active` только владельцем (V3) | одно |
| Тождество | id вечны, `deprecated + deprecatedBy` | V2, `supersedes` | одно |
| Провенанс | «чьё слово», г.NNN | `source`, «со слов владельца» | одно |
| Вид | фокус · путь · проекция · слой | один исполнитель вида + плоские параметры | одно |
| Пустота | «не описано» — это список работ | трение `UNKNOWN_TYPE` | близко |
| Состояние | состояние ≠ ситуация, переходы | категории статусов open/active/done/cold | rentacar богаче |
| Процесс / вычисление | процессы, 16 движков, виртуальные сущности, Начисление | «процесс = линза, движок не строить» | **расходятся** |
| Время | коммиты корпуса | журнал, blame/log | одно по смыслу |
| Согласие | нет | V7 (форма) | есть только у памяти |
| Адрес | 6 мест хранения, путь до сайта один | адрес, а не копия (`source.ref` + hash) | память отвечает на боль rentacar |

Шаблон: **знаниевая половина совпадает почти целиком, вычислительная (движки, деньги, переходы) есть только у rentacar.** Боль у обоих одна: одна вещь лежит в нескольких домах, и они не связаны («80 % нет» там, `_log` против дерева против мозга здесь).

## 2. Три модели отношений
| Модель | Выигрываем | Теряем | Цена |
|---|---|---|---|
| А. rentacar на памяти | общий контекст агентов, ценности «из коробки» | транзакции, движки, скорость сайта; ломаем живой продукт (вывод 10-31 в силе) | много |
| Б. память поверх rentacar (читатель/индекс) | агенты FF видят решения и вопросы rentacar по адресам id; rentacar не трогаем | общего роста нет; риск второй правды, если копировать тело | мало |
| В. общее ядро примитивов, два экземпляра | гейт «≥2 случая» закрыт; обе стороны учатся; путь к плагинам | координация двух живых треков; риск преждевременной платформы | средне (на бумаге — мало) |

Вывод линзы: **В как грамматика на бумаге + Б как единственная живая связь.** Общий код — нет, пока грамматика не выдержала проверку. Ни один не плагин другого: оба — экземпляры одного конструктора.

## 3. Что поднять и что дать
**Из bp-docs в общий паттерн (живы в двух местах):**
1. «Тип описывает, что у него своё» (состав граней по типу) — дыра у обоих, закрывать одним решением.
2. Пустота — это выход вида («не описано: …»), а не пустой блок; пустоты = очередь наполнения.
3. Ворота досягаемости: каждая единица доступна за N шагов; сироты — дефект (у FF аудит сирот уже в топе).
4. Состояние ≠ ситуация и переходы между состояниями — обобщает наши категории статусов.
5. Метод «две тонкие нитки насквозь, потом по виду за круг, правило — с одобренного образца».

**Из памяти в rentacar:**
1. Адрес, а не копия: один id на вещь поверх MODEL-v4e, корпуса и базы — лечит «6 мест».
2. Провенанс и утвердивший у каждой ячейки (V3), а не только у страницы.
3. Остывание вместо удаления (V4) — у них уже `deprecated`, не хватает `cold`.
4. Шов согласия (V7) — до клиентских ПДн.
5. Вид-запись со спекой и hash: «закрепить / пересобрать».

## 4. Рефрейм и дешёвый тест
**Рефрейм:** rentacar — не потребитель памяти, а первая «система» конструктора, собранная вручную. Вопрос «перенести?» меняется на «какие ≤7 примитивов общие, а что — пакет домена (деньги, движки)?». Fable rentacar сам задал этот вопрос (`ESSENCE-145/FABLE-essence.md`, вопрос 1) — ответ общий для двух проектов.

**Тест (1 сессия, бумага, без ПДн и кода):** одна карточка грамматики, ≤7 примитивов. Разложить через неё три вещи: «Машину» rentacar, «Начисление» rentacar и запись `decision` ff-brain.
- Провал А: хоть одной вещи нужен 8-й примитив.
- Провал Б: примитив нужен только одной стороне.
- Ожидаемый итог: знаниевое ядро общее, вычисление — пакет домена. Если и вычисление ложится — модель В сильнее, чем думаем.

## Что модель скрывает
- Совпадение имён ≠ совпадение семантики (например, «вид» у rentacar рисует сайт людям, у памяти собирает контекст агенту).
- Два живых трека с разными владельцами сессий: общая грамматика может замедлить оба. Повышение до домена — только с одобрения владельца (конституция).
- Числа rentacar взяты из снимка 11–14.11, я их не пересчитывал.

Итог: задача в плане — тест «карточка 7 примитивов × 3 вещи» до выбора модели; модель Б допустима сразу (только адреса).
Вопрос-цель: ответил — настоящий вопрос не «помочь rentacar», а «общая грамматика двух экземпляров одного конструктора»; кто чей плагин — никто, оба экземпляры; в ядро — знаниевая половина, вычисление остаётся пакетом домена (гипотеза до теста).
