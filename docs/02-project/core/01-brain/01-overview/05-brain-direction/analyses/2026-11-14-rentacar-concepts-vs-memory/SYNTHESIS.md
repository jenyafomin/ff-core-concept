## Что нового в rentacar (28.10–14.11)
Документация выросла в **платформу bp-docs** — «проверяемая модель бизнеса как данные, сайт = окно». Спуск: бизнес → раздел → сущность → данные/процессы/движки/прототипы. Решения D116–D130: ячейка = сущность (D117), процесс читается схемой и рекурсивен (D118), варианты = копилка видов (D119), виртуальный баланс «слегка» (D121). Построено: новый вид `/v/:id`, сеть вещей `/net`, страница вещи `/m/:id`, 9 слоёв, стили, ядро вычислений (правда · решённость · «не сходится» · дыры), ACL в Postgres, MCP 27 tools. Объём: ~4,9 тыс. сущностей, ~14,9 тыс. связей (>½ слабые refs); модель показа v4e — 160 единиц/696 связей. Открыто: голоса 156–164 без D-номеров, «состояние ≠ ситуация» без решения, переходов 0, «кто читает/пишет» у 28% полей. «Таблица» — вероятно таблицы БД CRM (54 файла `TBL-*`) как слой описания вещи (уточнить).

## Главный вывод (сходятся 4 из 5 линз)
**Рамка перевёрнута по зрелости.** bp-docs уже стала «памятью одного бизнеса» и по 8 из 13 осей сильнее ff-brain (3 записи). Вопрос не «перенести rentacar на память», а «два экземпляра одного конструктора — что общее, кто что берёт у кого».

## Что память РАСШИРИЛА бы rentacar
1. **Межпроектность** — одна память на все проекты (области M:N); решения/вопросы rentacar видны агентам FF и шлюза.
2. **Строгое «агент предлагает → владелец утверждает»** кодом (`proposed`, утверждает только владелец).
3. **Шов третьих лиц** — запись о человеке видна только владельцу (форма согласия; полного цикла согласия нет ни у кого).
4. **Мягкий вход неизвестных типов** (`raw` + счётчик трения) — спрос на новый тип виден, а не ломает ingest.
5. **Адрес вместо копии** — лечит «6 мест хранения» rentacar: ссылка + hash, без второй правды.

## Какие ОГРАНИЧЕНИЯ внесла бы
1. **Нет вычислений и SQL** — ядро «правда/решённость», деньги, агрегаты остаются вне памяти.
2. **Типы зашиты в код** (11 типов, 16 связей) — у bp-docs реестр типов уже данными.
3. **Ребро беднее** — нет «откуда взято / где в тексте / слабое»; у bp-docs есть `found_in`, `src_anchor`, `weak`, `conds`.
4. **Доступ грубее** — права только на область целиком; у bp-docs гранты со сроком, `deny`, маски, снимки all/normal.
5. **Масштаб** — журнал-файл целиком в памяти, find ≤50, обход ≤2/≤50 узлов; на 15 тыс. связей мало (до Postgres).
Плюс общее: реальные ПДн нельзя ни туда, ни туда; стирания в мозге нет.

## Расхождение линз и как снято
architect: «согласие — сильная сторона памяти»; critic: «у памяти V7 — только форма, а у bp-docs доступ реально исполняется». Оба правы на разных осях: **доступ (кто видит) ≠ согласие (на что дано)**. Доступ сильнее у bp-docs; шов третьих лиц — только у памяти; цикла согласия нет ни у кого.

## Модель отношений (рекомендация)
- **А «rentacar на памяти»** — отвергнута (дорого, ломает живой продукт, память слабее).
- **Б «память-читатель по адресам»** — сразу: память держит про rentacar только решения/вопросы со ссылкой `bp:<id>`, сущности не копирует.
- **В «общая грамматика»** — на бумаге, до ≥2 живых случаев (сейчас один живой + один на бумаге).
- **Обратный поток — ff-brain берёт у bp-docs** (дёшево): паспорт ребра (`found_in`/`src_anchor`/`weak`) — односторонняя дверь, пройти ДО импорта 1350 адресов FF; состояния присутствия (renamed/stub/absent); снимки all/normal для сводок. Средне, при Postgres: реестр типов данными, гранты со сроком/deny, запросы по белому списку. Не брать: двойной дом истины git+БД без обратного пути (признанный предел bp-docs).

## Риски
Третий дом истины (адрес поверх v4e/корпуса/БД) — согласовать с параллельным чатом rentacar «документация и данные» (их этап 0 = мост модель↔база, `JOINT.md`). Ещё одна волна сравнений вместо работы.

## Дешёвый шаг (critic)
Дать сессии FF read-токен bp-docs MCP, задать 3 реальных вопроса про rentacar, в память ничего не писать. Провал: >3 вызовов на вопрос или ответ без номера D-решения. Даёт факт «чем MCP bp-docs уже полезен агентам» вместо догадок.

## Вопросы владельцу
1. Какое решение ты примешь иначе, узнав ответ? (если «куда писать живой слой решений» — это выбор дома истины, не сравнение)
2. «Таблица» — это таблицы БД CRM как слой вещи, или что-то другое?
3. Берём паспорт ребра из bp-docs в ff-brain ДО импорта доков FF?
4. Read-токен bp-docs MCP для пробы — ок?
