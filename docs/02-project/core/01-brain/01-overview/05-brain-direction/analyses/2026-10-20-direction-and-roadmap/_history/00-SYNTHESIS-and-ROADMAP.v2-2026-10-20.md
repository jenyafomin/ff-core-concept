## 1. Свод шести линз

1. **Сошлись 4 из 6 по ядру (01/02/04/05), 03 и 06 — с оговорками:** код готов к запуску (5 пакетов, ~620 тестов, код-блокеров нет — `raw/01` §1–2); живых записей 0 за ~2 месяца; узкое место — руки владельца, а не план. Оговорка: все линзы — одна семья моделей; согласие ≠ доказательство (`raw/03` критерий 7).
2. **Сошлись 02/04/05/06:** «одна документация» — это **адресация, а не хранение**. Тело дока в git, мозг знает адрес, кто ссылается, что устарело. Самая дорогая боль — «нет единого адреса факта» (`raw/05` §1, D2/D3/D5).
3. **Сошлись 02/04/06:** двусторонний синк файлы↔мозг запрещён (ADR-0006 §(d)). Синк = детерминированный код по хешу; LLM-агенты только помечают (`status: proposed`). **Честно:** «конверт без тела, тело только в git» — **новое решение**, не следствие ADR-0006: там §(c) делает `md+journal` write-model, а KQ-9 (входит ли `doc` в file-first типы) открыт частично. Фиксируем в ADR-0019 (Этап 2).
4. **Сошлись 01/02/04/06:** PG и NestJS — по триггеру; качество = швы и контракт-тесты (Graphiti: журнал = истина; Cognee: «всё в PG» позже; Nest не наш профиль — `raw/06` §2, §4).
5. **Разошлись (владелец vs линзы):** «качество, PG/Nest, если правильнее» vs «PG по триггеру». Развязка — §2.
6. **Разошлись (наказ п.7–9 «десятки агентов» vs compound п.5–6):** вынесено владельцу как **выбор с ценой** (§8 В4), не как дефолт.
7. **Разошлись (02 vs 04):** PG-проекция для поиска в неделю 1–2 или гипотетика. Развязано триггером: ≥2–3 провала поиска за неделю (`friction`).
8. **Ново (01):** мозг не готов под «доки» **по данным**, не по коду: нет типа `doc`, нет чтения файла по `source`, нет slug-адреса; regex `source.ref` (`contract.ts:152-153`) отвергает кириллицу, `@`, цифровые серии ≥9; лимит длины ref — 200 символов (`contract.ts:140`).
9. **Ново (01):** шов хранилища готов на ~0.5: порт синхронный, 3 привязки к `DurableFsStore` (`domain/schemas.ts:5,14,53,64`), ≥8 файлов знают «журнал = файл». Это код, не данные.
10. **Ново (03):** «**узко по слоям, глубоко по дверям**»; диагноз: «каждый слой готовится к жизни следующего, ни один не живёт сам».
11. **Ново (05):** запуск A1–A9 = «цикл реальной пользы без лида-разработчика»; тесты и ADR не считаются.
12. **Ново (02, 07):** каждому проекту-читателю нужна запись в `readers.json` (ADR-0016 D8) **и** маршрут к сокету мозга (§4 Э1 шаг 5) — одной строки allowlist мало.

## 2. Развязка «качество/PG сейчас» vs «PG по триггеру»

**Главная опора:** владелец уже одобрил это отступление — ADR-0016 (approved 2026-10-09) прямо говорит «файловый журнал сейчас, адаптер за портом» (`ADR-0016:3,108`). Это не новое решение свода, а исполнение одобренного.

**Мир, где оба правы.** Владелец прав: то, что нельзя откатить, делаем на уровне продакшена уже сейчас — это **двери данных** (§6). Линзы правы: носитель журнала — не такая дверь, если записи переносятся в другой адаптер без переписи. **Честно: это пока гипотеза, а не факт.** Есть только `replay-equivalence.test.ts` (журнал→журнал); контракт-теста `StorePort` для второго адаптера нет, шов готов на ~0.5.

**Фальсификатор с датой (вариант а+):** параллельно Этапу 1 агент пишет contract-тест `StorePort` + replay копии журнала во второй in-memory адаптер (только тест, код вне теста не трогаем; минут владельца — 0). **Доказательство — к 2026-11-03.** Красный тест → шов чиним ДО второй недели записей, и это меняет приоритет Этапа 2.

Надёжность сейчас без PG: fsync на запись (`store-durable-fs.ts`), бэкап каждые 50 актов + каждые 15 мин + ночной + зеркало (`backup.ts:3-5,79-84`). Не хватает: **проверенного восстановления** (A9, Этап 1) и **копии вне машины** (§5, P1).

| Вариант | Цена | Вес | Что ломает |
|---|---|---|---|
| **(а+) Файл-журнал + двери + contract-тест порта параллельно Э1; PG по триггеру** | **мало**: двери ≈ час решений; тест 1–2 дня агента параллельно; шов в Э2, async-порт в Э3 по триггеру | **много**: запуск на этой неделе; «без переписи» доказано к 11-03, а не обещано | ничего; если тест красный — узнаём дёшево и рано |
| (а) То же без параллельного теста | мало | средне: доказательство сдвигается в Э2 | владелец неделю живёт на обещании |
| (б) PG сразу | **много**: 3–5 дней (async-граница через ≥34 вызова `store.*`, lock/backup/repair за интерфейс) + эксплуатация PG | средне: конкурентной записи нет (1 писатель, 0 записей) | первая запись −1–2 недели: повтор «готовим фундамент» |
| (в) PG + NestJS сразу | **много+**: (б) + 1–2 дня + ESM↔CJS | мало: Nest не добавляет ценности V1–V7; второго HTTP-потребителя нет | (б) + риск V5: плагины привязываются к фреймворку |

**Рекомендация: (а+).** Словами владельцу: «PG позже» ≠ «не качественно». Качественно — когда переезд на PG ничего не переписывает, и это **покажем тестом к 11-03**.

## 3. Модель «мозг дополняет git» (один экран)

Гибрид по типу: у каждой единицы ровно один хозяин тела. Опора: ADR-0006 §(b),(d),(f),(g) + новое решение «конверт без тела» (→ ADR-0019).

| Вещество | Где истина тела | Что хранит мозг | Кто пишет | Направление |
|---|---|---|---|---|
| **file-mastered**: doc, ADR, spec, prompt, rule, skill, config | файл в git | конверт: `id`, `source{ref, hash}`, label/summary, области, рёбра, статус. Тело не пишется | человек/агент правит файл | файл → мозг (детерминированный `sync` по хешу) |
| **brain-mastered**: task, decision из чата, note, person, day, friction | журнал мозга | всё | агент через MCP `record` | мозг → файл только экспортом |
| **derived**: сводки, `_generated/shared-docs.md`, индексы | никто, пересобирается | `derived_from: id@rev` + `stale` | синк или линза | ручная правка затирается (баннер) |

**Есть сейчас (Э1 обещает ровно это):** запись-конверт с путём-источником; `find` по области; чтение конверта (label/summary/ref). Агент второго проекта открывает файл сам по пути.
**Построить (не в Э1):** чтение тела по `source.ref` + сверка hash → `stale` (Э2, A5); `_generated/shared-docs.md` (Э3; сверить: в нём путь repo-relative по D-2, не абсолютный — `raw/02` §2); поле `placement` (в коде нет, grep 0 → ADR-0019).

- **Единственная запись мозга в файл** — `brain_id` во frontmatter. Отдельным коммитом, с согласия владельца.
- **Promotion:** заметка вырастает в документ — разовая передача хозяина, не синхронизация.
- **LLM-агенты:** кандидат-рёбра `duplicate-of`/`supersedes` со `status: proposed`. Тела файлов не трогают.
- **Мозг лёг → документация жива** (она в git). Падает поиск и граф.

## 5. НЕ делаем сейчас (и что включит) + P1-риски

| Не делаем | Триггер включения |
|---|---|
| PG-проекция | ≥2–3 провала поиска за неделю при ≥2 проиндексированных репо |
| PG как носитель журнала | второй писатель, >~50k актов или запись >200 мс; предусловие — contract-тест зелёный |
| NestJS | третий входной адаптер или второй транспорт; только как хост |
| Двусторонний синк / LLM пишут в источники | никогда (ADR-0006 §(d)); только `proposed` |
| Тела документов в журнале | после payload/конверта + hard_erase (Э4) |
| gw-reader / автозахват | пароли сменены + фильтр секретов до модели (Э4) |
| pgvector | полнотекст + рёбра не находят дубли |
| Новые аналитические волны | по решению владельца (§8 В4) |
| Маркетплейс, роли, другие люди | Э3 живёт ≥2 недели + назван второй пользователь |

**Наказ п.6 «проверить рефакторинг» → вердикт:** гигант-файлы (`validate-act.ts` 745 и др.) и мёртвый код (`store-md.ts`, `surface/*`) — отложены до боли с file:line · 3 привязки `DurableFsStore` + nvm-дефолт — Э2 · дубль `contract.ts` brain/brain-mcp — Э3 · async-порт — Э3 по триггеру · contract-тест порта — **сейчас, параллельно Э1**.

**P1 (цена → решение):**
- **Бэкап вне машины.** Зеркало `~/Backups/ff-brain-mirror` — тот же Mac; A9 ≠ защита от потери машины. Решение: в Э2 добавить второе место (внешний диск или зашифрованное облако), владелец выбирает. Цена мало, вес много.
- **Ошибочная запись необратима до Э4** (нет hard_erase, label/summary уходят в журнал навсегда). Правило: первая запись — один безопасный док, summary проверен глазами (Э1 шаг 6); третьих лиц и id не писать.
- **Ротация паролей из лога шлюза.** Не зависит от мозга — можно сделать в любой момент (~15–30 мин владельца); обязательна ДО включения gw-reader. Рекомендация: в Э2, не ждать Э4.
- **Стоимость токенов протокола.** Слой `PROMPT-memory-protocol.md` ≈ 6 КБ (~2–3 тыс. токенов) на КАЖДЫЙ ход топика + схемы 4 MCP-инструментов + вызовы `find`. С кешем промпта цена мала, но умножается на 3 топика. Решение: в Э2 мерить токены/ход до и после на топике 56, расширять на 65/92 только если «изменило действие» ≥3.
- **Офлайн/телефон:** мозг на одном Mac; без Mac владелец в мозг не пишет (доки в git живы). Принять до Э3.
