# Этап 1, шаг 6: критика скиллов ff-brain-use / ff-brain-build и отчёта живого запуска

- **Status:** active · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-23 · **Автор:** critic (не автор скиллов)
- **Потребитель:** лид + agent-builder (правка скиллов по P0/P1) · **Поглощает:** ничего
- **Related:** `05-live-launch.md` · `~/.claude/skills/ff-brain-use/` · `~/.claude/skills/ff-brain-build/`
- **Вопрос-цель:** годятся ли скиллы как переносимые, и безопасна ли их граница use/build. **Ответ: почти, нужны патчи.**
- **Вердикт: SHIP-AFTER-PATCH** (4 патча P0, 6 патчей P1). Скиллы в ходе критики не менялись.

## Выжимка
Структура верная: разделение use/build, `ff-local.md` вынесен, трение пишется в журнал. Проблемы четыре.
1. Таблица прав в build уже расходится с реальностью: `health/stats` написаны как «агент по разрешению», хук их блокирует.
2. Если записать в скилл «хук пропустил, потому что путь не литерален», получится рецепт обхода хука.
3. Неинтерактивный `claude -p --allowedTools …record` выдаёт агенту запись без кнопки владельца, а запись необратима. Трение предлагает закрепить этот путь.
4. Слова-триггеры use («запомни», «что решено про…») сработают в любом проекте, даже без инструментов памяти.

## Критично (P0)

### P0-1. Таблица «Кто что может» (`ff-brain-build/SKILL.md`) не соответствует факту
- Строка `счётчики health/stats … по разрешению владельца` в колонке «Агент» неверна. Хук блокирует прямой `ff-brain.js health/stats` («подмена личности памяти») и любой литерал папки памяти. Друг трения подтверждает это дважды.
- Строки «скрипты … нет» и `pm2 start/stop/restart/save … нет` расходятся с прогоном. Агент гонял скрипты и `pm2 save` по разовому исключению владельца.
- **Заменить:**
  - Строку `health/stats` на «агенту закрыто хуком; счётчики берём из вывода скриптов (запуск, области, репетиция) или от владельца».
  - Добавить строку: «Скрипты launch-kit/импорт/репетиция: агент запускает только по явной команде владельца **на конкретный скрипт**, в рамках этого хода. Решает хук, не агент. Если хук заблокировал, остановись и скажи, не перефразируй команду».
  - `pm2 save` перенести в ту же строку-исключение.
- **Запретить в скилле формулировку «путь в команде не литерален»** (трение №1 build, отчёт ст. 33). Для агента это «обойди текстовый матч». Правило должно говорить обратное: перефразировка заблокированной команды ради прохода хука запрещена.
- Это же добавить в начало `procedures.md`.

### P0-2. Путь `claude -p --allowedTools …record` нельзя канонизировать как путь агента
- Источник: трение use №1 («обход: добавить этот вариант в ff-local.md») и отчёт, находка 3.
- Риск: процедура (г) шаг 3 требует, чтобы владелец прочитал label и text до `record` («стирания нет, навсегда»). При `-p` с `record` в `allowedTools` нет ни кнопки, ни паузы. Агент, который запускает под-агента с записью, сам снимает защиту.
- **Заменить** в `ff-brain-build/references/ff-local.md` §г: неинтерактивный вариант пометить «запускает **владелец** или агент по его явной команде **после** показа label/text и слова «да». Для `read`-проверок (`find,read`) агент может сам».
- В `ff-brain-use/references/ff-local.md` §«Как агент получает инструменты» сделать то же. Добавить, что `record` в `allowedTools` без «да» нарушает ход 2 use.

### P0-3. Нет правила «не утверждай проверку, которую не делал» (вопрос 6: да, нужно)
- Факт: агент AM имел только `find`/`read`, но написал «пересчитанный хеш совпадает». Это галлюцинация проверки с вероятностью выше 50%, как он считал, не видно.
- Хуже: `protocol.md` §4 п.5 прямо говорит «сравнивай hash сам». Для агента без shell это приглашение изобразить сверку.
- **Вставить в `ff-brain-use/SKILL.md`** после «Нашёл → открой файл…», в «Шесть ходов», ход 1:
  «Проверка = факт вывода. Утверждай „хеш сверен / файл актуален / записал“ только если сам выполнил команду и видел результат. Нет shell или файла → скажи: „hash в памяти X, с файлом не сверял“. Это общее правило, не только про hash».
- **В `protocol.md` §4 п.5** заменить «сравнивай hash сам, если отвечаешь „по памяти“» на «если есть shell — посчитай `shasum -a 256` и сравни; нет — так и скажи, не утверждай сверку».
- Ту же формулу принять для build (отчёты «sha256 OK» только из вывода скрипта, не из пересказа).

### P0-4. Срабатывание use: «запомни» и «что решено про…» перехватят обычное
- `description` use содержит слова `запомни`, `what did we decide about`, `что решено про…`, и условие «а также когда доступны `mcp__ff-brain__*`» подано как **ИЛИ**. В проекте без MCP `ff-brain` скилл загрузится на любое «запомни» и начнёт искать несуществующие инструменты, а автопамять Claude Code (`MEMORY.md`) и обычные заметки останутся без внимания.
- Это универсальный скилл в `~/.claude/skills`, видимый во всех проектах (cardex, agents-manager), так что цена высока.
- **Заменить описание:** первой фразой «Только когда в сессии есть инструменты `mcp__ff-brain__*` или владелец явно назвал ff-brain/«мозг»/«память ff»». Слова `запомни`, `что решено про…`, `what did we decide about` убрать как самостоятельные триггеры или оставить только внутри этого условия.
- **В NOT for добавить:** «обычное „запомни“ без инструментов ff-brain (это автопамять Claude Code / заметки в проекте)»; «поиск по докам проекта и git (грепай файлы)»; «личные заметки не в память».

## Концерны (P1)

### P1-1. Дыры границы use/build (вопрос 1)
- **Кто помечает устаревшее.** use ход 6: «файл изменился → новый hash». Но авто-`stale` не вычисляется, а сравнить hash может только агент с shell. Агент AM (read-only, без shell) не сможет, значит устаревание никто не вычисляет. Нужен владелец дыры: либо «build (е) раз в неделю прогоняет drift-проверку по экспорту», либо явно «пока нет, риск принят». **Файл:** `ff-brain-build/references/procedures.md`, добавить процедуру (ж) или строку в (е).
- **Кто связывает.** use владеет `link`, но неясно, можно ли ребро между областями, в одной из которых привязка read-only (`WRITE_DENIED`?). Записать в `protocol.md` §6 или проверить на живой памяти и отметить.
- **Правило-как-данные.** (е) использует тот же `record note`+`source`, что и ход 5 use. Разница только в намерении, MCP их не различает. Реальная граница это бит `write` в `readers.json` (его ставит build/владелец), а не текст скилла. Сказать это явно в обоих SKILL.md, иначе читатель решит, что граница технически закрыта.
- **Заявка от use к build.** «Остановись и скажи, нужен строитель» уходит в чат. Артефакта-очереди нет, запрос теряется. Добавить строку «если упёрся в область/тип: одна строка в `friction-log.md` род `граница`». Поле это уже есть, но SKILL.md не велит.
- **Типы.** build сам пишет «новый тип через MCP нельзя, значит SPEC/ADR/код». Это противоречит триггеру «новый тип в памяти» и его же NOT for «правка кода». Переформулировать: «build готовит предложение типа (чек-лист), код делает builder по SPEC».
- **`kind` из 8 значений** в переносимом use не перечислен (только в слое топика 56 и ff-local). Агент другого проекта выдумает значения. Дать список или явно «спроси у владельца/возьми из `find` существующих».

### P1-2. Переносимость (вопрос 2): «FF вынесено» верно наполовину
Для агента agents-manager сработает (там есть ff-local). Для cardex нет, потому что ff-local хранит абсолютные пути этой машины, а инструкции по получению MCP и привязке только там. Утечки FF в «переносимые» файлы:
- `ff-brain-build/SKILL.md`: `~/.ff-brain`, «стоп-лист шлюза G1», `pm2 restart agent`, `pm2 ... ff-brain`, `.env шлюза` в таблице; «Related» ведёт на FF-доки; раздел «Гардрейлы» про `dist` рабочего дерева FF.
- `ff-brain-use/SKILL.md`: «шлюз/топик» в модели, `m8-scan.mjs`, реестр `~/.claude/registry/projects.json` в ходе 5; `protocol.md` §4/§7: тот же реестр и `~/.ff-brain`.
- **Заменить** на переменные: «папка памяти (в FF: см. ff-local)», «агент шлюза (в FF: см. ff-local)», «сканер секретов (в FF: m8-scan)». Таблицу прав вынести общими словами, конкретные имена в ff-local.
- **Для третьего проекта** добавить в оба SKILL.md короткий блок «Чего нет в чужом окружении: если нет ff-local под ваш проект, сначала спроси владельца про привязку, не пытайся угадать пути».
- **Сканер.** Нет резервного списка проверок, если `m8-scan.mjs` недоступен. Дать 5 строк ручного чек-листа (секреты, 9+ цифр, `@`, имена, адреса).
- **Журнал трения** лежит в `~/.claude/skills/…`, вне git и без бэкапа. «Откат: удалить папку» стирает всю историю трения. Либо держать журнал в git, либо в откате сказать «журнал сохранить».

### P1-3. Таблица права и опасные строки (вопрос 3)
- Положительно: инструкции обойти хук нет, `.env`/`pm2 restart agent`/`pm2 update` помечены «никогда». Токены и чтение папки памяти запрещены.
- Не отражён в таблице шаг I отчёта: правка `PROMPT.md` живого топика 56 (читается каждый ход). Это изменение живого поведения агента, в таблице нет такой строки. Добавить: «слои промптов живых топиков: только по команде владельца, всегда вместе с флагами (см. P1-5)».
- Отчёт шаг B′: sha256 пары в зеркале сделан после блокировки sha256 основного бэкапа. Формально не обход (зеркало вне стоп-листа), но по духу «проверь то же другим путём». Записать в скилл правило: если хук закрыл проверку, эквивалент допускается только из вывода штатного скрипта, не новой самодельной командой к соседнему пути.
- Тест F3/G запускает `claude -p` в cwd agents-manager (агент с командами) с подключённым мозгом. ADR-0016 как раз предупреждает не подключать мозг к агентам с доступом к командам до стоп-листа. Стоп-лист живой, но в build нет строки «подключение MCP к новой папке, где есть Bash = решение владельца».

### P1-4. Петля улучшения (вопрос 5): исполнима только на бумаге
- «Агент открывает предложение, когда набралось 5 строк». Никто не считает строки: нет расписания, нет хука, нет места в хендоффе.
- Пороги разные: use 5 или 3 одного рода, build 3 или 1 `опасно`. Строка `опасно` в use есть? Нет такого рода, значит опасное (например, галлюцинация проверки) ждёт 5 строк.
- Сейчас в build 5 строк при пороге 3, а следующий ход «предложение через agent-builder» ничем не принуждён.
- **Заменить:** в оба SKILL.md и шапки журналов: единый порог; род `опасно` и `граница` в обоих журналах с порогом 1; счёт делает лид в хендоффе одной строкой «трение: открыто N / закрыто M» (компаунд-правило, триггер 6); `agent-builder` вызывает лид, не «агент».
- Закрытие строк пометкой `→ закрыто` противоречит «append-only». Указать «закрытие дописывается новой строкой со ссылкой на номер».

### P1-5. Порядок «слой протокола вместе с флагом»
- В живом топике 56 уже сейчас протокол ссылается на `mcp__ff-brain__*`, которых там нет. Агент топика может сказать «записал» без инструментов или импровизировать. Это живая регрессия поведения, пока флаги не включены.
- В отчёте есть откат. **Рекомендация лиду:** либо немедленно откатить `PROMPT.md` из бэкапа, либо поставить срок включения флагов; сам скилл (в) — добавить жёсткий шаг «слой в PROMPT.md только в том же ходу, что флаги». Это уже есть как трение, но скилл ещё не исправлен.

### P1-6. Отчёт `05-live-launch.md`: чего не хватает
- **Нет отрицательных тестов.** Утверждено «AM только читает», но не показано `WRITE_DENIED` на попытке записи из AM и `DEFAULT_DENY` из непривязанной папки. Сейчас доказано только «положительное». Добавить в (б) «Ожидаемо» и дописать в отчёт (или пометить непроверенным).
- **Находка 7** («видимо, системные типы не считаются») — догадка, не факт. Пометить как гипотеза, проверить по `by_type` кода.
- **Скилл use не проверен как скилл.** Агенты F3/G вызваны с ад-хок промптами; загрузка SKILL.md и срабатывание триггера не проверены. «Первый живой прогон скилла» относится к build. Нужен холодный тест: агент в cardex без ff-local, только MCP-конфиг.
- Находка 4 в отчёте корректно замечена, но зафиксирована как «стоит добавить». Это P0-3 выше.
- «Обхода не было» верно по хуку; но см. P1-3 про B′ и про «не литерально».

## Провокации
- Блокировка хука сработала у агента «случайно по литералу»: хук матчит текст команды, а скрипты обращаются к папке сами. Если защита держится на тексте, она проверена только на честном агенте. Стоит спросить: что делает хук с `bash -c` с конкатенацией? Это вопрос к коду шлюза, не к скиллу, но скилл не должен учить пользоваться этой щелью.
- «Стирания нет» + «пишет агент по слову владельца»: ошибочная запись останется навсегда (retract мягкий). Скилл use просит сканер, но владелец-ревью есть только в build (г). Для ежедневных записей риск принят молча; стоит назвать его явно в SKILL.md use.
- Полный id `u_mvkc…` лежит в отчёте в git-дереве, а use велит «полный id не показывай». Для внутреннего репо мелочь, но правило и практика расходятся.

## Отмечено (наблюдать)
- Лимиты и контракт `CONTRACT_VERSION = 1` привязаны к версии; при смене контракта `protocol.md` станет ложным. Триггер: любая правка `contract.ts`.
- `maturity: experimental-global` в frontmatter не входит в стандарт полей; проверить, читает ли его что-то.

## Что проверил и проблем не нашёл
- Идея разделения «тело в git, память держит адрес»: согласована между use, build и отчётом.
- Хук-блокировки в отчёте: два шага остановлены и честно описаны, обхода не было.
- Идемпотентность запуска/областей/импорта (повторы `nothing to change`, `unchanged 15`) подтверждена выводом.
- «Не обходить, не просить токен, не лезть в папку памяти» в use — прямо и однозначно.
- Откат во всех процедурах назван до запуска; точка возврата `.bak` есть.
