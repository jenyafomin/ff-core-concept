## 3. «Запуск состоялся» — измеримые критерии приёмки

Запуск ≠ «код собран» (собран уже, 0 живых записей за ~2 мес). Запуск = **хотя бы один цикл реальной пользы без участия лида-разработчика.**

| ID | Критерий | Как проверить | Порог |
|---|---|---|---|
| A1 | В мозге есть живые записи по документации, созданные в РЕАЛЬНЫХ ходах, не тестовым скриптом | `find`/мозг-инструмент по `source`: счёт записей с `source != test/fixture`, дата ≥ день запуска | ≥ 10 записей за первые 7 дней (ГИПОТЕЗА порога — согласовать с владельцем) |
| A2 | Записи охватывают ≥ 2 проекта из реестра | счёт уникальных `project/namespace` | ≥ 2 |
| A3 | Кросс-проектное чтение: агент проекта A находит и корректно цитирует факт из проекта B | сценарий-тест: заранее выбранный факт из FF; задать вопрос агенту из топика agents-manager; сверить ответ + путь-источник | 3 из 3 вопросов отвечены верно, с указанием источника |
| A4 | Нет дубля: факт, диктуемый дважды, не создаёт двух «правд» | продиктовать одно решение в двух топиках; счёт записей по `canonical_id` | 1 запись + связь, не 2 копии |
| A5 | Сдвиг расхождения: после правки файла-источника запись мозга помечается stale/обновляется | правка файла → проверка метки в течение согласованного срока | метка появляется; ложных срабатываний < 20% на выборке (ГИПОТЕЗА порога) |
| A6 | Протокол агента реально включён | промпт-слой в `.gateway/conversations/<chatId>/<threadId>/PROMPT.md` топика; агент выполняет `find` до ответа | виден в логе хода (gw-reader) в ≥ 5 ходах |
| A7 | Владелец пользуется сам | число обращений владельца к мозгу голосом за неделю; ответ владельца на вопрос «стало ли проще найти» | ≥ 3 обращения/нед. + «да» (субъективный, фиксировать цитатой) |
| A8 | Безопасность/согласие не нарушены | в записях нет имён третьих лиц/PII (решение 10-10 п.7); бэкап `/Users/mac16/Backups/ff-brain-mirror` обновляется | 0 PII-находок; бэкап ≤ 24ч |
| A9 | Откат возможен | восстановление из бэкапа на чистом каталоге | проходит один раз до «запуск» |

Анти-критерий (что НЕ считать запуском): количество тестов зелёных, количество написанных ADR/доков.

## 4. «Через месяц» — гипотезы и вопросы владельцу

Из слов владельца (10-15): «читать и работать с одной документацией из разных проектов»; «мозг дополняет git»; «надёжная система, на которую можно опереться». Всё ниже — ГИПОТЕЗЫ, не требования.

| H | Гипотеза: чего владелец захочет через месяц | Что нельзя/трудно на файлах (ГИПОТЕЗА) | Проверка |
|---|---|---|---|
| H1 | Спросить «что я решил про Х» и получить ответ с учётом ВСЕХ проектов, без знания, где лежит | файлы: надо знать путь или grep по 8 корням; нет единого индекса и тождества (одно решение = N упоминаний) | Q1 |
| H2 | Чтобы изменение правила (например, ответа на вопрос шлюза) подхватывалось всеми проектами сразу | файлы: правка в N CLAUDE.md; сейчас 27 копий md2tg = эталон проблемы | Q2 |
| H3 | Видеть, что устарело/противоречит (supersession) | файлы: `status` во frontmatter ставится руками, никто не проверяет | Q3 |
| H4 | Доступ/согласие по областям (чужие проекты — другим людям, например `jenek`/партнёры) | файлы: права на уровне папки, не записи; Telegram-роли (`analyst` в music-video) | Q4 |
| H5 | Связи между проектами (Cardex ↔ Forms-Sidebar ↔ crm-server) как граф с поиском «что затронет» | файлы: ссылки гниют; в реестре связи только в `note` текстом | Q5 |
| H6 | Агент сам приносит нужное в ход (push, зерно 10-10 п.3) | файлы: статичный CLAUDE.md одинаков для любой задачи | Q6 |

Что файлы делают ХОРОШО (честно, чтобы не переоценить мозг): диффы, git-история, ручная правка, чтение любым агентом без инфраструктуры, переносимость. Мозг должен быть производным над ними (согласуется с п.5 идеи 10-20).

### Вопросы владельцу (по одному смыслу, приоритет)

1. **(must)** Назови 2–3 РЕАЛЬНЫЕ ситуации за последний месяц, когда ты или агент искали «а где это записано / какое решение действует» и не нашли или нашли два разных. Какие проекты? (Проверяет D5 фактом, не моей оценкой. Заодно: что за проект «Мириса»?)
2. **(must)** Какой ОДИН документ ты бы хотел видеть живущим в одном месте и читаемым из всех проектов в первую очередь (правила шлюза? ценности? ADR? описание проекта)?
3. **(must)** Если запись мозга и файл расходятся — кто прав по умолчанию: файл (git = источник) или мозг? От этого зависит вся синхронизация.
4. **(should)** Сколько записей/обращений за первую неделю ты бы счёл «запуск удался»? (порог A1/A7)
5. **(should)** Кто ещё кроме тебя должен читать мозг через месяц (партнёр jenek, агенты других людей)? Это переворачивает приоритет V5/V7.
6. **(nice)** Туду-лист всё ещё первый сценарий или документация его заменила?
