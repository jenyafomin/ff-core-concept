## 1. Инверсия-адвокат: сильнейший аргумент ЗА «PG сейчас» (честно)

Мы все шесть линз + два критика говорили «PG по триггеру». Это одна семья моделей (`raw/03` критерий 7). Вот почему владелец может быть прав.

1. **Момент переезда никогда не будет дешевле, чем сегодня.** Пользовательских записей 0. Стоимость миграции растёт монотонно с живыми данными, хэш-цепочкой, `u_…` в frontmatter доков, бэкапами. «Дверь односторонняя» — именно тот класс, который наказ владельца («без будущих переписываний») велит закрывать ДО данных. Свод относит носитель к «не-двери» только гипотезой (§2: «пока гипотеза, а не факт», шов ~0.5).
2. **Фальсификатор (а+) слабее, чем выглядит.** Contract-тест порта против in-memory адаптера доказывает форму интерфейса, а не семантику PG: транзакции, порядок, идемпотентность `idem`, блокировки вместо PID-lock, поведение при обрыве. Зелёный in-memory тест к 11-03 оставляет вопрос «а на настоящем PG?» открытым. Единственное честное доказательство «переезд ничего не ломает» — настоящий адаптер. Значит (а+) не дешевле (б), а откладывает ту же работу плюс платит за тест-двойник.
3. **Категорийная ошибка в таблице §2.** «(б) PG сразу: 3–5 дней, первая запись −1–2 недели» смешивает агентные дни и руки владельца. Узкое место — руки владельца (`raw/04` §0), а не агентские дни. Работа агента над адаптером НЕ блокирует первую запись, если идёт параллельно. Вычет «−1–2 недели» ничем не обоснован.
4. **«Мозг везде» + «сервер + MCP для всех агентов» уже подразумевают сетевой/общий носитель.** Файловый журнал + PID-lock + pm2 на одном Mac = один писатель, один хост. Свод сам признаёт P1: копии вне машины нет, телефон/офлайн не назван, зеркало на том же диске. PG (с `pg_dump` наружу) закрывает копию вне машины «из коробки»; файловый вариант требует отдельного решения.
5. **V7/hard_erase.** Стирание в append-only хэш-цепочке на файле тяжелее, чем разделение payload/конверта в строках PG. Этап 4 свода («много») при PG-носителе дешевле. Это довод про будущую цену, а не про сегодняшнюю.
6. **Мотивация владельца — ресурс, и это не «слабость».** 0 записей за ~2 месяца, 4 пересмотра рамки (`raw/04` §1). Если «огромный смысл» в PG — то, что вернёт владельца к руке, это входит в расчёт. Честная оговорка: та же энергия может быть избеганием, одетым в инженерию. Различить можно только по тому, происходит ли запись (см. п.4).

**Что остаётся от довода:** PG-носитель — не ошибка. Ошибка — ставить его ПЕРЕД первой записью вместо РЯДОМ.

## 2. Где расширение раздувает Этап 1

До ответов Этап 1 был: одна запись + одно чтение. После ответов в него просится: PG, сетевой сервер+MCP, правила и организации, кастомные карты, центральная точка, логи, слои типов, мультипроекты, задачи по всем проектам. Это та же механика, что `raw/04` §1(б): каждый ответ рождает работу, которая требует новой волны. Ни одна запись при этом не появилась.

| Элемент | До первой записи? | Почему |
|---|---|---|
| Выбор носителя + **ADR** (ADR-0016 approved говорит «файл сейчас»; конституция требует ADR на смену хранилища) | **ДА, как решение (1 день), не как код** | без ADR кодить носитель = нарушение процесса |
| Двери данных §6 (D-1, D-2, области `ff`/`agents-manager`, слаги навсегда) | **ДА** | односторонние; единственное, что действительно нельзя откатить |
| Один путь записи/чтения (`--mcp-config`, `readers.json`) | **ДА** | иначе записи нет |
| Бэкап + проверенное восстановление | **ДА** (для любого носителя) | журнал без hard_erase |
| Слои типов («какая ветка какой памяти») | **НЕТ** как реализация; **ДА** как имена в одной строке двери | добавление типа аддитивно (по ADR-0017, **не проверено: отвергает ли валидатор неизвестный тип**) — проверить за 15 минут, это единственная ревизия до записи |
| Сетевой сервер/MCP для «всех агентов» | **НЕТ** | не назван второй хост/агент; сеть = токены, TLS, `readers.json` на каждого. Двери доступа свод уже называет (никогда chat-level ключ) |
| Правила / организации / кастомные карты | **НЕТ** | согласие V7 в движке не подключено (только форма, `recursive-orchestration-method` V7). Строить enforcement поверх неработающего согласия = слой N+1 без N |
| Центральная точка «как CLAUDE.md» | **НЕТ как генератор; ДА как один рукописный файл** | страница-указатель «вызови `ff-brain find`, вот области, вот линзы» — 0 кода, закрывает желание владельца дёшево |
| Логи в мозг | **НЕТ** (см. §3) | |
| Задачи по всем проектам, `sync`, `doc`-тип | **НЕТ** | Э2–Э3 свода |

**Скрытая посылка, которой нет в ответах:** «везде» = несколько машин? В памяти проекта и в своде (P1) мозг на одном Mac, шлюз тоже на нём. Мультимашинность не подтверждена ни одним названным вторым хостом. Если её нет, «сервер для всех агентов» = локальный сокет, который уже есть.

## 3. «Логи docs/_log в мозг сразу» — риски

Факты (из своих файлов): `docs/_log/` — gitignored trace; в логе шлюза есть пароли, ротация не сделана, `gw-reader` заморожен до ротации (`raw/07` §4, свод §5); журнал без `hard_erase` до Э4; зеркало бэкапа дублирует всё.

1. **Секреты/PII.** Gitignore сегодня и есть единственный барьер. Перенос в журнал снимает его: ошибочная запись остаётся навсегда и уходит в зеркало. Транскрипты Telegram содержат третьих лиц, голосовые расшифровки, чужие имена: V7 нарушается тихо.
2. **V3 отравление.** Лог = заявления агентов, часто устаревшие или опровергнутые. Запись в мозг превращает их в «ячейки», которым агент доверяет. Без supersession/provenance-калибровки старый «решено X» читается как факт.
3. **Объём и мусор.** docs:code 14.5:1; сессий десятки. Каждый акт навсегда в журнале; триггер «>50k актов» свода (§5) станет достижим сам собой. Шум снижает точность `find` (V1) и убивает V4 (всё вечно-равнозначно, нет `cold`).
4. **Два вещества** (doc-tree закон 1: trace ссылается на knowledge, не хранит его). Переезд trace целиком в журнал нарушает собственный закон без ADR.
5. **Пересечение с ADR-0018/gw-reader.** «Логи в мозг» по сути = автозахват, который свод отложил в Э4 до фильтра секретов ДО модели.

**Что обязано быть до этого:** (а) ротация паролей (15–30 минут владельца, независима от мозга); (б) фильтр секретов/PII ДО записи (минимум: regexp-сканер + счётчик попаданий = 0 как гейт); (в) модель «конверт без тела»: лог остаётся файлом, в мозг идёт только `ref+hash+summary проверенный глазами+рёбра` по белому списку; (г) пилот на 1 папке сессии (её `HANDOFF`), а не на `_log/`; (д) правило supersession для логов; (е) лимит: ≤30 конвертов в пилоте, dry-run отчёт ДО записи.
Сырые логи в журнал — **никогда** (до hard_erase и фильтра).

## 4. Порядок: PG-сейчас и первая запись в ОДНОЙ короткой границе

**Идея:** PG идёт РЯДОМ, не ПЕРЕД. Первую запись принимает то, что уже есть; PG принимает её воспроизведением. Тогда замена носителя проверяется на настоящих данных, а не на пустом хранилище.

**Граница: 2026-11-03.** Внутри: первая запись **10-27** (жёсткий потолок свода) + переключение носителя на PG **до 11-03**.

| Когда | Дорожка A (руки владельца, как Э1) | Дорожка B (агент, 0 минут владельца до 10-27) |
|---|---|---|
| 10-21…10-22 | «ок» дефолтам §6; отчёт по `gw-reader`/`workspaces/` | **ADR «носитель журнала = PG за портом»** (черновик, 1 день, меняет ADR-0016 только в части «файл сейчас»); проверка: отвергает ли валидатор неизвестный тип |
| 10-22…10-27 | RUNBOOK 1, 1б, 2; `stage1-scopes.sh`; **первая запись; кросс-чтение; репетиция восстановления** | async-граница через ≥34 вызова `store.*`; PG-адаптер; contract-тест `StorePort` на **двух** адаптерах (in-memory и настоящий PG); потолок 5 агентских дней |
| 10-27 | **Гейт:** есть запись и чтение → дорожка B продолжается; нет → B ставится на паузу, этап урезается (правило свода) | |
| 10-28…11-02 | владелец: установка/запуск PG (≤30 минут), «да» | реплей **реального** журнала (с первой записью) в PG; сверка состояния; `pg_dump` + восстановление во временную БД; копия вне машины |
| 11-03 | **Переключение:** один флип конфигурации + 1 рестарт `ff-brain`; файловый журнал остаётся холодным зеркалом 14 дней как откат | |

**Условия переключения (все):** contract-тест зелёный на PG · реплей реальной записи эквивалентен · восстановление из дампа проверено · дамп вне машины. **Не прошло хотя бы одно → остаёмся на файле, триггер возвращается в §5 свода, время владельца не потрачено.**

**Потолок:** дорожка B ≤5 агентских дней, ≤1 владельческий час до переключения. Превышение = стоп, не продление.

**Вне границы (запрещено добавлять):** правила/организации, кастомные карты, сетевой сервер, логи, задачи кросс-проектные, sync, `doc`-тип. Разрешено одно: **рукописная «центральная точка»** (одна страница-указатель), создаётся после 10-27.
**После 11-03 по порядку:** ротация паролей → пилот логов (§3) → второй док/`sync` (Э2) → правила (ADR отдельно).

## 5. Классификация

- **CRITICAL:** смена носителя без ADR (ADR-0016 approved + конституция). Первый день дорожки B — ADR, иначе «PG сейчас» нарушает собственный процесс.
- **CRITICAL:** «логи в мозг сразу» при непроведённой ротации паролей и отсутствующем hard_erase = необратимая запись секретов/третьих лиц в журнал и зеркало. Не до пилота по §3.
- **CONCERN:** таблица §2 свода сравнивает агентские дни с руками владельца: аргумент «первая запись −1–2 недели» не доказан. Параллельная дорожка снимает его.
- **CONCERN:** (а+) in-memory тест не доказывает семантику PG; обещание «без переписи» без настоящего адаптера остаётся обещанием.
- **CONCERN:** расширение (правила/центральная точка/логи/задачи) повторяет механизм избегания (`raw/04` §1): каждый ответ владельца добавляет работу, запись не появляется.
- **PROVOCATION:** «мультимашинность» и «сервер для всех» не подтверждены ни одним названным вторым хостом/агентом. Возможно, это желание «чтобы было серьёзно», а не требование.
- **PROVOCATION:** «центральная точка как CLAUDE.md» может быть одним файлом, а не подсистемой правил. Дешёвый тест: полезна ли страница-указатель агентам за неделю?
- **NOTED:** критерии «надёжно» (ответ 5) делегированы лиду: поставить измеримые до 10-27 (запись не потеряна; восстановление; тест переезда на PG зелёный; копия вне Mac).
- **NOTED:** `pg` в pm2 «stopped, 278 рестартов» (`raw/07`): выяснить до установки нового PG, чтобы не получить второй.

**Что искал, но проблем не нашёл:** довод владельца «PG на нём всё равно будет» логически не ломается: PG как носитель за портом совместим с ADR-0017. Ломается только порядок и объём.

Ответил / не ответил / вопрос был неверен потому что: ответил на все 5 пунктов. Рамка «PG или первая запись» неверна: они не конкурируют за одни ресурсы (агентские дни и руки владельца), и их можно развести по двум дорожкам с общей границей.
