## 2. Носитель истины: PG сейчас, две дорожки в одной границе

**Было (v2):** вариант (а+) — файл-журнал, contract-тест на in-memory адаптере к 11-03, PG по триггеру. Таблица v2 (а+/а/б/в) — в `_history/…v2…` §2.
**Стало (v3):** решение владельца «PG сейчас» **принято** (`OWNER-ANSWERS` п.4). Почему изменили: (1) момент переезда дешевле всего при 0 записей; (2) in-memory тест не доказывает семантику PG (`raw/12` §1 п.2); (3) таблица v2 смешивала агентские дни и руки владельца — PG не конкурирует с первой записью за руки (`raw/12` §1 п.3).

**Рамка:** PG меняет **только носитель истины**. Паттерн — «C-минимум» (`raw/09` §1.1): журнал в PG — истина, проекция в RAM — кеш, fail-stop. Async `JournalPort {open, append, lock, health, backup}` живёт в оболочке brain; `Engine.write` (sync, `engine.ts:73`, заморожен ADR-0010) и ~50 вызовов `store.*` **не меняются**. Граница async = `WriteQueue`: `ok:true` только после COMMIT (ADR-0016 D10 сохраняется). Адаптеры `FileJournal` (текущий JSONL) и `PgJournal`; файловый **не удаляется** (тесты, экспорт V5, аварийный replay pg→file).

| Дорожка | Кто | Что | Срок |
|---|---|---|---|
| **A — первая живая запись** | руки владельца, как Э1 | запись + кросс-чтение на **файл-журнале** (проверенный путь: fsync, 214 тестов, гейт AC-19…23) | до **2026-10-27** |
| **B — PG как носитель** | агент, в **отдельном worktree** (`refactor-tree` грязное → git-safety) | P0–P6 (`raw/09` §1.2), ниже | переключение **~2026-11-03…07** |

**Дорожка B, шаги (`raw/09` §1.2):** P0 contract-тест **одним набором на оба адаптера** (`describe.each([file, pg])`: verbatim, порядок, `recordedAt`, рваный хвост, второй писатель падает на локе, replay A→B побайтно равен) · P1 снять 3 привязки `DurableFsStore` (`schemas.ts:5,14,53,64`, `registry.ts:200`) · P2 «журнал = файл» → `FileJournal` (≥8 файлов) · P3 async-загрузка + коммит в очереди + fail-stop · P4 `PgJournal` (миграции аддитивные, advisory lock, роль без UPDATE/DELETE) · P5 replay file→pg (`engine/src/adapters/replay.ts`) + CLI `ff-brain migrate --to pg` · P6 docker-compose `ff-brain-pg` postgres:17, порт 5433→127.0.0.1 (не pm2, не brew — владелец 10-21(2)), роль `ff_brain` только unix-сокет/localhost, ночной `pg_dump -Fc` → шифрование → **копия вне Mac**, репетиция восстановления.

**Порядок внутри B:** день 1 — **ADR-0020 черновик** (CRITICAL `raw/12` §5; конституция: смена хранилища = ADR). P0 (только тесты) можно сразу; P1–P5 — после того как ADR-0020 прошёл **критика** и стал `proposed`; `approved` — до переключения.

**Потолок агента:** оценка `raw/09` 6.5–8 дней vs потолок критика ≤5 (`raw/12` §4) — **расхождение, сводим так:** контрольная точка на 5-м дне (P0–P3 зелёные, иначе стоп), жёсткий потолок 8 дней; превышение = стоп, не продление. Руки владельца в B — ≤1 ч до переключения (установка PG, место копии, «да»).

**Условия переключения (все):** contract-тест зелёный на `pg` · replay **реальных** записей дорожки A эквивалентен (export/find/read побайтно) · восстановление из дампа проверено · дамп вне машины. Переключение = один флип `JOURNAL=pg` + 1 рестарт `ff-brain`. **Откат:** файловый журнал остаётся холодным зеркалом 14 дней. Не прошло хоть одно условие → остаёмся на файле, время владельца не потрачено.

**Условие на данные A:** до переключения записи только из белого списка (§8: без третьих лиц и id) — иначе replay унесёт их в WAL, `pg_dump` и копию вне Mac, откуда не стереть.

**ADR-0020 «Postgres — носитель истины журнала (C-минимум)»** — черновик позже (день 1 дорожки B). **Заменяет** пункт ADR-0017 F2 «C-bis: файл — истина, PG — индекс» (C-bis остаётся как будущая проекция) и часть ADR-0016 «файловый журнал сейчас». Содержание: рамка выше + `JournalPort` + fail-stop + двери PG-1…PG-9 (§8). **Критик обязателен до `approved`.**

**NestJS — не нужен** (`raw/09` §2.3): `http.ts` 248 строк, 8 глаголов; удалённый MCP = ~150–300 строк адаптера; Nest добавит DI, ESM↔CJS трение и привязку плагинов к фреймворку (V5). Триггер пересмотра прежний: третий входной адаптер / второй транспорт; и тогда только как хост.

**Доступ агентов:**
- **Локально — уже работает:** агент → `brain-mcp` (stdio, процесс на сессию, `index.ts:8,20`) → HTTP по **unix-сокету 0600** + Bearer (`client.ts:218-248`, `http.ts:211-233`) → один сервис, одна очередь. Не хватает онбординга (`--mcp-config` + строка `cli` в `readers.json`, ~5 мин/проект → позже скрипт `ff-brain onboard <ключ>`). PG здесь ни при чём.
- **Удалённо — этап позже:** MCP Streamable HTTP (SSE deprecated) + **токен на клиента** (хранить хеш, отзыв) + **Tailscale** (без публичного порта). Это смена границы доверия ISO-2 → сеть (ADR-0011) → **отдельный ADR**, триггер «названа вторая машина / облачные сессии». Цена 2–4 дня + security-review. `readers.json` остаётся корнем доверия (курица и яйцо).

**Блокер дорожки B:** в pm2 есть остановленный процесс `pg` (278 рестартов, `raw/01` §1.1, §5.8г) — Postgres здесь уже падал под pm2. Чей он — **выяснить у владельца** (§10 В1) до установки нового PG.

## 3. Модель «мозг дополняет git» (один экран)

Гибрид по типу: у каждой единицы ровно один хозяин тела. Опора: ADR-0006 §(b),(d),(f),(g) + «конверт без тела» (→ ADR-0019). Подтверждено владельцем (`OWNER-ANSWERS` п.2): текст в git, мозг — адрес/связи/устаревание; git остаётся для проектно-специфичного.

| Вещество | Где истина тела | Что хранит мозг | Кто пишет | Направление |
|---|---|---|---|---|
| **file-mastered**: doc, ADR, spec, prompt, rule, skill, config | файл в git | конверт: `id`, `source{ref, hash}`, label/summary, области, рёбра, статус | человек/агент правит файл | файл → мозг (`sync` по хешу) |
| **brain-mastered**: task, decision из чата, note, person, day, friction, **trace** (новое, логи) | журнал мозга | всё (для trace — конверт, см. ниже) | агент через MCP `record` | мозг → файл только экспортом |
| **derived**: сводки, `_generated/shared-docs.md`, индексы | никто, пересобирается | `derived_from: id@rev` + `stale` | синк или линза | ручная правка затирается |

**Есть сейчас (Э1):** запись-конверт с путём-источником; `find` по области; чтение конверта. Агент второго проекта открывает файл сам по пути.
**Построить (не в Э1):** чтение тела по `source.ref` + hash → `stale` (A5); `_generated/shared-docs.md` (путь repo-relative по D-2); поле `placement` (в коде нет → ADR-0019).
- Единственная запись мозга в файл — `brain_id` во frontmatter, отдельным коммитом с согласия.
- Promotion «заметка → документ» — разовая передача хозяина, не синхронизация.
- LLM-агенты: кандидат-рёбра `duplicate-of`/`supersedes` со `status: proposed`; тела файлов не трогают.
- Мозг лёг → документация жива (в git); падает поиск и граф.

**Логи (`docs/_log`) в мозг (новое v3).** Было: «gw-reader / автозахват — Э4». Стало: владелец хочет логи в мозге «сразу, с лучшими связями» → **да, но конвертами и после двух условий** (`raw/12` §3, CRITICAL): (1) **ротация паролей** из лога шлюза; (2) **фильтр секретов/PII до записи** (regex-сканер M8, гейт «0 попаданий»). Затем **пилот на одном HANDOFF:** лог остаётся файлом, в мозг идёт конверт без тела (`ref + hash + summary, проверенный глазами + рёбра`), ≤30 конвертов, dry-run отчёт до записи, правило supersession (старое «решено X» не читается как факт, V3). Сырые логи в журнал — **никогда** до hard_erase. Это не нарушает doc-tree закон 1: trace остаётся файлом, мозг держит адрес.

**Слои типов («какая ветка какой памяти», `OWNER-ANSWERS` п.2) = свойства типа, не новая сущность** (`raw/10` §2). Слой = пара фасетов type-def: **хозяин тела** (`file-mastered · brain-mastered · derived`) × **класс хранения** (`event · state · config · ephemeral`, ADR-0017 D2). Правила → file/`config` · решения → brain или file/`state` · логи → brain(конверт)/`event` · задачи → brain/`state` · доки-адреса → file/`config`. Фасеты становятся полями **в момент первого потребителя** (пресет `root`, §4); до этого — таблица тип→ветка в самой линзе. Проверка за 15 мин (до записи): отвергает ли валидатор неизвестный тип (`raw/12` §2).

## 4. Центральная точка и правила в памяти (новое v3, `raw/10`)

**Находка:** каскад «как CLAUDE.md» уже есть — `sys:prompt-layer` + `sys:target` + `sys:applies-to` + линза-данные `lens:prompt-compose@1` (`packages/brain/src/domain/sys-types.ts:52-118`, интерпретатор `read/lens.ts:96-194`, SPEC `docs/spec/SPEC-brain-r1-prompt-layers.md`). Сейчас заточен под Telegram-контекст и открыт только мандату шлюза (`service/runtime.ts:259-267`). Задача — **обобщить, а не строить второй механизм.**

**Центральная точка = пресет `root`** (паттерн `read/presets.ts:120-187`, без новой поверхности мандата). Один экран, ≤4000 симв.: (1) кто ты — принципал и области из мандата; (2) действующие правила твоей цепочки областей с манифестом `[id, rev, source_hash]`; (3) карта слоёв — счётчики по семействам со ссылками-фильтрами; (4) доступные линзы. Проход агента: `root` → слой/линза → `find` с фильтром → `read` → файл по `source.ref`. Обобщение до `lens:root@1`-как-данные — когда появится вторая карта (compound-триггер 4). Кастомная карта = линза с другой `spec`; организация с другими правилами = её слои + своя версия линзы.

**Наследование правил — в линзе, не через видимость.** Ловушка: видимость в мозге идёт **вверх** (запись видна, если замыкание `member-of` её областей пересекает области читателя, `read/access.ts:235`, `validate-act.ts:142-160`, ≤2 хопа). Дать проекту родительскую область ради правил = он увидит всех соседей (V7). Правильно: правило цепляется `applies-to` к цели вида `scope`; линза при сборке идёт по `member-of` вверх и собирает слои предков (предок раньше, ребёнок перекрывает). Правила живут в отдельной области «свод правил», `pii: none`.

**`~/.claude/rules` остаются истиной, мозг индексирует** (вариант C → лестница D, `raw/10` §3). Харнесс грузит файлы до первого хода — мозг этого не заменит; агент без мозга должен быть безопасен.
