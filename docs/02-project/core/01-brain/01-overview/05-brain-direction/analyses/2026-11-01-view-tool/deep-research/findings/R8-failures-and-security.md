Потребитель: синтез deep-research view-tool. Поглощает: A3-gaps M1, M2.
Пометки: [В] = открыл страницу/сниппет поиска сам; [СЧ] = со слов вторичных источников, не проверено по первоисточнику.

## Находки

1. **NN/g: меняющийся UI ломает обучаемость.** «Constantly changing UIs will cause usability problems»; чем чаще пользуешься, тем эффективнее, а genUI может показывать другой UI каждый раз; дизайнер должен балансировать выигрыш кастомизации и потерю консистентности. Что именно держать стабильным, NN/g не говорит. [В, nngroup.com/articles/generative-ui/]
2. **Gajos и др., CHI'08: точность важнее предсказуемости, но оба поднимают удовлетворённость.** Предсказуемая модель = та, которую пользователь может смоделировать в голове. Точность сильнее влияет на скорость и использование адаптивной зоны. Количественного порога «сколько можно менять» нет. [В, сниппет поиска, harvard.edu/~kgajos]
3. **Провал №1 по бенчмаркам: поддержка между ходами.** EvoGenUI-Bench (150 пятишаговых задач): узкое место не однократное качество, а сохранение вида между ходами. Design Theater вводит индекс гомогенности. arXiv-id из выдачи поиска; PDF не читался. [СЧ]
4. **Eval ещё не зрелый.** Один LLM-судья даёт один неявный взгляд (UIPersonaBench, панель персон). Для замкнутого каталога eval проще: схема-валидность + снимки вывода, а не «красота». [СЧ]
5. **«Смертельная тройка» (Willison, июнь 2025):** приватные данные + недоверенный контент + канал наружу. EchoLeak (CVE-2025-32711, M365 Copilot) эксфильтрирует через markdown-картинку, которая грузится при рендере. [В, сниппеты; по EchoLeak со слов]
6. **MCP tool poisoning / rug pull (Invariant Labs).** Инструкции в описаниях и схемах, которые читает модель, а человек нет; сервер мутирует после одобрения. Средний успех атак ~36.5% [СЧ]. Для FF аналог: текст документа/записи в графе, попавший в промпт генератора вида.
7. **CaMeL (DeepMind, arXiv 2503.18813):** план выполняется из доверенного запроса, недоверенные данные не влияют на control flow; 77% задач AgentDojo с доказуемой безопасностью против 84% без защиты. Но требует ограниченного интерпретатора Python. [В]
8. **A2UI / MCP Apps / json-render:** граница безопасности = клиентский каталог (компонент вне каталога не рендерится); MCP Apps: iframe на отдельном origin, CSP-allowlist, действия только через хост (openLink, callServerTool). Худший выход json-render = ошибка валидации. Но аудит Thesys-пайплайна всё же отметил риск инъекции. Каталог защищает от кода, но не от вредного ТЕКСТА внутри разрешённых компонентов. [В, сниппеты]

## Обязательные контроли в коде (≤7)

1. **Каталог = allowlist типов и пропсов**, валидация схемой ДО рендера; неизвестное = отказ, а не «лучшее усилие».
2. **Фильтр видимости до генерации:** генератор видит только поля, доступные читателю (label/summary/адрес), а не тела. Исполнитель вида повторно режет по читателю при выдаче.
3. **Нет внешних URL в данных вида:** картинки и ссылки только на внутренние id/адреса; без автозагрузки внешних ресурсов (закрывает markdown-эксфильтрацию). Текст рендерится как текст, не как markdown с картинками.
4. **Разрыв «текст записи → решения генератора»:** содержимое записей передаётся как помеченные данные; выбор компонентов и запросов делается из доверенного намерения владельца (идея CaMeL без интерпретатора: спека фиксируется до чтения недоверенных тел).
5. **Действия из вида только из закрытого списка** (open address, link, record-proposed), с подтверждением человеком для записи; писать «proposed», не «active».
6. **Лимиты:** число узлов, глубина, число запросов исполнителя, размер вывода.
7. **Провенанс-метка в хроме, не в генерируемом:** «вид собран ИИ, хеш спеки, источники» рисует каркас, модель не может подделать.

## Граница: стабильный каркас / генерируемое

- **Каркас (неизменно, рисует код):** навигация, место и вид действий, метки доверия и провенанса, индикаторы согласия/видимости, предупреждения, структура «где что». Это то, что нужно для мышечной памяти (вывод из п.1–2, не измерено).
- **Генерируемое:** выбор и порядок блоков из каталога внутри слотов, группировка, плотность, заголовки. Для повторного открытия того же вида: спека закреплена хешем и воспроизводима; меняется только по явному действию «пересобрать».
- Порог в числах литература не даёт; нужен собственный тест (вопрос ниже).

## Инновационные ходы

1. **Вид как закреплённая запись с хешем:** генерация один раз, дальше открытие идёт из зафиксированной спеки; «пересобрать» даёт diff от прошлой версии. Убирает главный провал (нестабильность между показами) и даёт регресс-тест.
2. **Eval без глаз человека на замкнутом каталоге:** три автопроверки: валидность схемы, «утечка» (канарейка-поле, невидимое читателю, не должно появиться в выводе), «инъекция» (запись с вредным текстом не меняет набор компонентов/действий). Прогон на каждом изменении каталога.

## Что не брать

- Интерпретатор кода/выражения во виде (CaMeL целиком): второй язык, против принципа.
- Произвольный HTML/iframe с кодом (MCP Apps целиком): песочница нужна, только если есть код; у нас кода нет.
- Полную «пер-сессионную» генерацию каркаса (genUI по NN/g): ломает обучаемость.
- LLM-судью красоты как единственный eval.
