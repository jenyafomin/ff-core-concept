Вопрос-цель: какие решения интерфейса реально толкнут FF вперёд (человек и ИИ) и в каком порядке строить. Метод свода: сверка находок между собой; первоисточники я не открывал (см. §8).

## 1. Где линзы сходятся
Сила: ●●● три и больше независимых линз · ●● две · ● одна.
1. **Вид = запись памяти (ephemeral → pinned, версия, hash)** ●●●: R1 (1, 2, 5), R3 (ход 2), R4 (ход 1), R8 (ход 1). Хранится спека, намерение, запрос, а не пиксели; рендерер сменный. Оговорка: цельного примера «вид-запись в графе памяти» нет, R1 и R4 прямо пишут «это мой синтез».
2. **Каркас кодом, содержимое в слотах** ●●: R8 (граница), R1 (Jelly 5, слои 6), R2 (каналы фиксированы, правило данными), R3 (не генерировать на каждый вопрос). Числового порога «сколько менять» нет нигде (R8).
3. **Граф как надзор, не шар** ●●●: R4 (1, 3, ход 2), R5 (ход Б), R2 (без hairball). Окрестность ≤2 или срез с одним вопросом.
4. **Утренний дифф памяти / входящие одобрений** ●●●: R5 (А, Б, 1, 2, 4), R4 (ход 2), R3 (6: живёт регулярный отчёт).
5. **Бюджет внимания вместо «показать всё»** ●●: R2 (DOI, 4) и R7 (PPR, бюджет токенов, ход B) — одна идея для человека и агента. Миссии её не связали, это находка свода.
6. **Сводка кластера как грань** ●●: R7 (ход A, 3) и R2 (3, уровень Cluster). Для агента опора только GraphRAG, со слов.
7. **Лестница деградации Telegram** ●: только R6 (R3 косвенно: Atlas, Poke). Не сходимость.
8. **Грамматика состояния (stale→туман, confidence→насыщенность)** ●: R2. Остальные только косвенно (R4-3, R8-метки). Не сходимость.

## 2. Расхождения и детектор (е)
- **D1, сработал 3/3.** Изолят R5-А (авто-приём записей) против «агент пишет только proposed, человек подтверждает» (R8-5, R1-2, R4-1, устав, V7). Уверенность R5 высокая, развилка несущая (кто решает, что память истинна). Хитрая проверка: ② авто-принять всё = слепое «да», от которого R5 и лечит; ③ мир, где оба правы: авто-приём только класса «заметка сессии без пересечений», decision всегда человеку; ④ валюта: дешевле опровергнуть неделей «тени» (система только пишет, что приняла бы; владелец сверяет выборку). Вывод: в карту идёт только тень.
- **D2, конфликт с уставом.** R3 ход 1 пишет каждый эфемерный вид в память. Устав: ≤3 record за ход, не писать мусор, стирания нет (V4). Решение: эфемерные виды и счётчик возвращений живут в кэше исполнителя, в память только при «закрепить».
- **D3.** Закреплять по умолчанию (R8, R1) против «вид = намерение, перегенерировать» (R3-2). Оба правы: хранится спека с hash, перегенерация по явному «пересобрать». Вопрос 3.
- **D4.** «Полностью генеративно» (наказ) против R8 (каркас не генерировать, NN/g) и R1 (без следа нельзя). Оба правы: композиция свободна, каркас и каталог закрыты. Это уже линия волны 2.
- **D5.** R6 ход 2 оценён «мало», но Mini App требует публичного хостинга, а у шлюза HTTP для людей нет (только unix-сокет). Цена = много.
- **Дыры, не споры:** тождество вида при смене спеки (R1) · позицию записи на карте хранить или считать (R2).

## 3. ТОП-7 ходов
1. **Вид-запись: спека + hash, «закрепить»/«предложить».** Хороший вид закрепляется как закладка и не меняется, пока не нажмёшь «пересобрать». Опоры: R1-1,2,5; R3-2; R4-1; R8-1. Владелец узнаёт вид; агент стартует с ближайшего закреплённого. Цена: **средне**. Зависит: исполнитель вида, решение о тождестве.
2. **Каркас в коде, содержимое и правило стиля данными (A2UI, закрытый каталог, метка провенанса в рамке).** ИИ собирает экран свободно, рамка, доверие и действия наши. Опоры: R8; R1-5,6; R2 (ход 1). Цена: **средне**. Зависит: спайк, 7 контролей. Грамматику состояния откладываем.
3. **Утренний дифф + очередь «на твой взгляд».** Один экран «что изменилось с вчера»; причина отказа возвращается агенту (R5-2). Опоры: R5, R4-ход 2, R3-6. Цена: **средне**. Зависит: полнота журнала (не проверено), карточка Telegram.
4. **Аудит дефектов графа:** сироты, битые ссылки, без hash, открытые proposed. Опоры: R4-3, ход 2. Уже есть данные (472 битые ссылки, волна 2). Цена: **мало**. Зависит: импорт docs.
5. **Формат вида для агента:** incident-блоки, `detail=ids|labels|summary`, бюджет токенов, потом PPR. Опоры: R7-1,2,8,9, ход B; R2-4. Агенту дешевле и точнее. Цена: **мало** (эксперимент 1 день), потом средне. Зависит: 1350 адресов после импорта.
6. **Сводка кластера (digest) как запись.** Агент отвечает на «что у нас по X» без чтения 1350 узлов. Опоры: R7-A, R2-3. Цена: **средне**. Зависит: рёбра (в памяти сейчас 0) или scope-группы; доля глобальных вопросов.
7. **Лестница Telegram:** Rich Message → PNG → кнопка Mini App по полю `needs`. Опоры: R6 (1, 2, ход 1). Цена: **мало** для карточки, **много** для Mini App. Зависит: проверка лимитов Rich Messages.

## 4. Порядок поверх волны 2
Волна 2 (импорт 1,5д → исполнитель 2д → спайк 1д) остаётся. Меняется:
- **Вход:** A0 владельца (вопрос 1). Без него шаги 4–5 вслепую.
- **Эксперимент R7 (1д)** после импорта, параллельно исполнителю: 10 вопросов с золотыми ответами, 5 форматов. Результат определяет вывод исполнителя и `detail`.
- **Спайк 1д → 1,5д:** + каркас/слоты, метка провенанса, 7 контролей как приёмка.
- **Шаг 4 (1д):** тип вида-записи. Только после живого спайка (N+1 после N).
- **Шаг 5 (1,5д):** аудит дефектов + утренний дифф, Markdown-карточка. Авто-приём только тень.
- **Параллельно (0,2д):** один вызов Rich Messages, закрыть 4 неизвестных R6.
- **Позже, по триггеру:** digest (порог по логам вопросов агентов), грамматика+DOI (рёбер ≥50), Mini App (владелец хочет менять, не читать), линзы Cambria (первая реальная смена спеки).
- **Потолок:** волна 2 ≈4,5д + новое ≈4д = ≤9 рабочих дней. Стоп: владелец за неделю не открыл вид сам; форматы R7 не различаются.

**Новые требования SPEC:** R9 `u:view@1` (спека, `schema_version`, hash, `pinned`/`proposed`, эфемерное вне памяти) · R10 `detail` + бюджет токенов в `read`/`find` · R11 каркас/слоты/метка провенанса · R12 вид-аудит дефектов · R13 вид-дифф из журнала · R14 тень авто-приёма · R15 проба Rich Messages. Приёмка: AC7 три автопроверки (схема, канарейка, инъекция) · AC8 повторное открытие закреплённого = тот же hash · AC9 аудит показывает 472 битые ссылки.

## 5. Обязательные контроли в коде (R8)
1. Каталог = allowlist типов и пропсов, схема-валидация до рендера, неизвестное = отказ.
2. Фильтр видимости до генерации (генератор видит label/summary/адрес, не тела); исполнитель режет по читателю повторно.
3. Нет внешних URL в данных вида, текст как текст (без markdown-картинок).
4. Разрыв «текст записи → решения генератора»: выбор компонентов из доверенного намерения, тексты как помеченные данные.
5. Действия только из закрытого списка; запись из вида только `proposed`, подтверждает человек.
6. Лимиты: узлы, глубина, запросы, размер вывода.
7. Метка «собрано ИИ, hash, источники» рисует каркас.

В SPEC сегодня есть только п.2 (R7) и частично п.1 (R8). П.3–7 отсутствуют. Заголовки 1350 доков — недоверенный текст, п.4 нужен уже на спайке.

## 7. Вопросы владельцу (≤5)
1. Назови 1–2 вида, которые откроешь каждый день/неделю. Что первым в утренней карточке: ждёт ОК, протухло/осиротело или окрестность проекта? Достаточно читать или нужно менять (R3, R4, R6)?
2. Какие записи агентов ты готов не видеть вовсе: только заметки сессий или и decision (R5)? Согласен на неделю «тени» вместо авто-приёма?
3. Знакомый вид важнее свежести: закреплённый по умолчанию, «пересобрать» по кнопке? Принимаешь «полностью генеративно = свободная композиция внутри закрытой рамки»? (R8, D3, D4)
4. Нужна ли «пространственная память» (карта помнит, где что лежало), то есть хранить позицию? (R2)
5. «Строй» на эксперимент форматов R7 (1 день) и пробу Rich Messages (0,2 дня)?

## 8. Не проверено и дрейф (г)
**Не проверено по первоисточникам:**
- Я сверял находки между собой; веб не открывал. Большинство опор [С]/[Ч] (сниппеты, чужие слова).
- R2: шапка признаёт «страницы целиком не открывал», но пункты помечены [П]. Метки ненадёжны.
- Цифры без первичной проверки: удержание Lovable/v0/Bolt, закрытие Atlas, покупка Poke (R3); 93–97% одобрений и 13,6% против 89% (R5, источники расходятся); GraphRAG 2–3%, Zep +18,5%, Mem0 +2–2,6 (R7, со слов).
- R6: Bot API 10.1–10.3 и Rich Messages взяты из пересказа WebFetch. Лимиты, топики, клавиатура, drafts неизвестны.
- R8: EvoGenUI-Bench не читался.
- Данных удержания именно генеративного UI нет ни у кого (R3, R4, R6). «Нет продукта с дифом графа памяти» (R5) — слабое отрицание.
- В коде не проверил: что журнал ff-brain полон (R1, R5 это предполагают), рёбер 0, записей 3 (беру из волны 2).

**Дрейф:**
- Ход «вид = запись» предложен четырьмя линзами под разными именами (спека, намерение, запрос, hash). Свёл в один; не плодить четыре типа.
- Слово «линза» в R1 (миграции Cambria) сталкивается с «lens-as-data» проекта (candidate/gated, D9 не минтили). Брать reuse, отдельно не заводить.
- `view-style` (R2) = часть описания типов (шаг 2 гибкого роста), а не новый тип.
- Метки «Толкает: много» не откалиброваны; цена в §3 — мои.
- Критерий волны 2 («≥3 вопроса отвечены <1 мин») ресёрчем не оспорен. Риск: UI-инновации опередят, что владелец реально откроет. Страж: A0.
- Кода нет, «строй» не нарушен.

Итог: решение — строить по порядку волна 2 → эксперимент R7 → закреп вида → аудит и утренний дифф; автоприём только в тени, Mini App и грамматику состояния откладываем по триггерам; ждём A0 и 5 ответов владельца.

## Поправки critic (SHIP-AFTER-PATCH, 2026-11-01) — ПЕРЕКРЫВАЮТ разделы выше (см. CRITIC.md)
1. **D1 переформулирован:** устав уже разрешает агенту писать в проектные области сам (решение владельца 10-26). Вопрос владельцу: нужна ли очередь подтверждения для обычных записей — или только для decision? «Тень» авто-приёма — только при ≥20 записях агентов за неделю, иначе отменяется.
2. **D2 + AC8:** закреплённый вид несёт метку ДАТЫ ДАННЫХ (не только hash спеки), иначе устаревший вид выглядит доверенным (V3); потолок числа pinned (V4).
3. **Порядок стройки ≠ ТОП.** Первым — **аудит дефектов графа** (данные уже есть: 2651 ссылок, 472 битых) Markdown-карточкой в Telegram, за часы, без исполнителя и UI. Вторым — эксперимент R7 (формат вида для агента, 5 форматов × 10 вопросов) — единственный, кто измеряет пользу агенту. Затем импорт → исполнитель вида → спайк UI → вид-запись → утренний дифф (при 3 записях он пуст).
4. **Потолок реалистично 12–14 рабочих дней**, не ≤9: импорт 3–4 дня (ПДн-скан, бэкап/откат, служебный принципал, битые ссылки/длинные заголовки), контроли R8 п.3–7 в SPEC.
5. **Наказ «полностью генеративно» не растворять:** в спайке UI — один свободный эксперимент, где ИИ сам предлагает композицию из каталога без закрепа; смотрим, что он соберёт.
