# R6 — Telegram как канал вида

Потребитель: синтез deep-research. Поглощает: ничего.
Метки: [П] проверено по core.telegram.org (через пересказ WebFetch, не руками); [С] со слов вторичных источников.

## Находки
1. **[П] Bot API дошёл до 10.3 (24.08.2026).** Ключевое для нас: 10.1 (11.06) принёс **Rich Messages** (`sendRichMessage`): структурированный текст с блоками — заголовки, списки, таблицы, коллажи/слайдшоу, фото/видео/документы, раскрывающиеся блоки (details), карты, цитаты; 10.3 добавил блоки-кнопки, expandable quote, document-блоки. Правится через `editMessageText` с `rich_message`.
2. **[П] Стриминг:** `sendMessageDraft` (9.3 — топики в личке, 9.5 — всем ботам) и `sendRichMessageDraft` — прогрессивная сборка карточки.
3. **[П] Не выяснено:** числовые лимиты Rich Messages, поддержка `message_thread_id` в форум-топиках, совместимость с inline-клавиатурой, ограничение drafts приватными чатами. Пересказ докой не дал. Это первый тест до любых решений (дешёвая проверка: один вызов).
4. **[П] Mini App (Web App):** 8.0 — fullscreen, ярлык на домашний экран, геолокация, скачивание файлов; хранилища: CloudStorage 1024 ключа, DeviceStorage 5 МБ, SecureStorage 10 элементов (9.0). Ссылка-на-вид: `t.me/bot/app?startapp=<param>`, параметр приходит как `tgWebAppStartParam` (лимит в доках не указан).
5. **[П] Авторизация:** initData подписан HMAC-SHA256 от токена бота; есть Ed25519-`signature` для проверки третьей стороной без токена. Поля: `user.id`, `chat_instance`, `chat_type`, `start_param`, `query_id`, `auth_date`; свежесть по `auth_date` проверяет сам сервер (срок не задан). Итого Mini App даёт **криптографически подтверждённую личность Telegram-пользователя без логина**.
6. **[С] Poke** живёт в iMessage/SMS/Telegram без своего приложения; в Apple Messages (одобрен 04.06.2026) показывает структурные карточки и пикеры, в остальных каналах — текст и ссылки, деградирует «вниз». Это тот же принцип «один вид → разные рендереры по возможностям канала».
7. **[С] A2UI называют «Telegram Mini App для ИИ»** (LogRocket); json-render (Vercel) — каталог компонентов на Zod. Публичных примеров «Mini App рендерит A2UI/json-render-дерево» я не нашёл — значит, это не готовый паттерн, а наш шов (поиск на 1 запрос, не исчерпывающий).
8. **[С/слабо]** Данных о ретеншне утилитарных Mini App vs inline-кнопок нет; найденные цифры (15–20% завершения inline-флоу) — маркетинговые, не брать.

## Где мессенджер ломается
- Нет интерактивной сортировки/фильтра/графа внутри сообщения; карточка — снимок (устаревает, нужен edit).
- Лимит ~3500 знаков карточки (наш практический, не API); Rich Messages, возможно, смягчают — см. п.3.
- Mini App: холодный старт, отдельный веб-хостинг, хранение сессии; в форум-группе контекст топика приходит только через `chat_instance`/`start_param`.
- Картинка графика: статична, не копируется как данные, но читается мгновенно на телефоне.

## Два инновационных хода
1. **Лестница деградации одного дерева вида (без новых слоёв).** Один декларативный узел вида имеет 4 рендера по цене: (a) Rich Message-блоки/Markdown-карточка → (b) PNG с сервера (для графиков/таблиц) → (c) кнопка «Открыть вид» = Mini App `startapp=<view_id>` → (d) React web. Рендерер выбирается по полю `needs: [interactive|graph|edit]` в самом дереве: нет needs — остаёмся в чате, есть — карточка кончается кнопкой «развернуть». Чат — по умолчанию, Mini App — эскалация, не замена.
2. **initData как готовый гейт видимости.** Mini App = тонкий React-рендерер, открывающий `view_id` из `start_param`; сервер проверяет initData (HMAC/Ed25519) → получает `user.id` → прогоняет через тот же гейт `reader/visibility`, что и /access. Короткоживущий view-токен не нужен: ссылка в чате безопасна, потому что ссылка — только `view_id`, а право даёт личность. Бонус: ссылку нельзя переслать в чужой чат с утечкой (чужой initData → отказ). Минус: привязка к Telegram-личности; веб-вариант вне Telegram потребует другого входа.

## Что не брать
- Крипто/игровые Mini App-паттерны, платёжные флоу, монетизацию.
- Mini App как основной вид «вместо» чата: цена хостинга/холодного старта выше пользы, пока нет сценария интерактива.
- Любую опору на лимиты Rich Messages и топики до проверки п.3.
- Цифры ретеншна из маркетинговых блогов.

## Вопрос владельцу
Какой ежедневный вид владелец реально хочет «раскрыть» из чата — только прочитать (карточка/картинка достаточно) или менять (тогда Mini App оправдан)? Назови один конкретный вид из последней недели.

Источники: core.telegram.org/bots/webapps, /bots/api, /bots/api-changelog; blog.logrocket.com/is-a2ui-the-telegram-mini-app-of-ai; infoq.com/news/2026/03/vercel-json-render; letsdatascience.com (Poke в Messages).

Вопрос-цель: ответил частично — минимальный ежедневный вид = карточка (Rich Message/Markdown) + эскалация кнопкой в Mini App; ломается на интерактиве и актуальности; не проверены лимиты Rich Messages и поведение в топиках.
