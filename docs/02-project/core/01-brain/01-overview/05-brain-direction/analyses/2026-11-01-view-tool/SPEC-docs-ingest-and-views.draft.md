Потребитель: builder после «строй». Поглощает: ничего (новый).

## Проблема
Память ff-brain не в рабочем состоянии: 3 записи. Знание проекта (≈1350 доков FF) лежит в git, агенты не видят его как граф; человеку нечем его смотреть.

## Цели / не-цели
Цели: адреса доков FF в памяти (обратимо, без дублей); один исполнитель вида для агента и человека; генеративный UI из закрытого каталога.
Не-цели: тела доков в памяти; rentacar (до вычитки ПДн и слова владельца); GraphQL; генерация кода UI; выражения в дереве UI.

## Требования
R1 Тип `u:doc@1`: поля `ref` (путь), `hash`, `kind` (analysis/idea/decision/adr/question/note/navigator/plan/spec/concept), `status_raw`, `status` (категория open/active/done/cold), `date`, `node` (папка-узел); label ≤60. Ребро `u:refs`.
R2 `ingest-docs` — служебный путь сервиса (не агентский record, вне лимита ≤3/ход), отдельный автор-принципал, rate-limit сохраняется.
R3 Идемпотентность: ключ (`scope`,`ref`); тот же hash — пропуск; новый hash — правка той же записи (тождество V2).
R4 Партия: метка `batch`, бэкап до заноса, снятие партии = `retract` всех её записей с причиной.
R5 Область `import-ff` (песочница), перенос в `ff` — решением владельца.
R6 Пропускать `_log/`, `_archived/`, `raw/`, хендоффы; ПДн-скан до заноса, сигнал = файл не заносится.
R7 Исполнитель вида: `find` + `group_by`, `fields`, `sort`, фильтры равенство/наличие по полям, категории статусов, `view_v`; группировка строго после гейта видимости.
R8 Генеративный UI: каталог ≤3 компонентов (список/таблица, доска по статусу, граф узла); ИИ отдаёт A2UI-подобное дерево, которое ссылается на вид; рендер Markdown (Telegram) + React (локальный web).

## Критерии приёмки
AC1 Пилот 50 доков `05-brain-direction/`: 50 записей, повторный прогон — 0 новых. AC2 Изменение файла → та же запись, новый hash. AC3 Снятие партии оставляет память как до заноса (по find overview). AC4 Вид «доки области по статусу» одинаков через MCP и /state. AC5 Одно дерево UI рендерится в Markdown и React без правки каталога. AC6 0 срабатываний ПДн в занесённом.

## Верификация
Тесты brain (golden-снимки пресетов до/после) · прогон dry-run-docs.mjs перед каждой партией · ручной смоук владельца: 3 его вопроса.
