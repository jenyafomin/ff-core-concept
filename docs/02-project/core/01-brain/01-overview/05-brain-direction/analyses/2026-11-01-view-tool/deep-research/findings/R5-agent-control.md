# R5 — Контроль агентов

- Потребитель: итоговый свод deep-research (вид «владелец + агенты»). Поглощает: ничего.
- Related: ../missions/A2-market.md (M3).
- Метки: [П] = страница открыта в поиске, содержание из выдачи (полный текст не открывал); [Ч] = с чужих слов (агрегаторы, блоги). Все цифры без первичной проверки.

## Находки

1. **LangChain Agent Inbox** [П]. Отдельный UI над LangGraph `interrupt()`: агент встаёт на паузу, задача падает во «входящие», человек принимает / правит / отклоняет / отвечает. https://github.com/langchain-ai/agent-inbox · https://blog.langchain.com/introducing-ambient-agents
   Идея: одобрение = письмо во входящих, а не модалка в чате. FF: proposed-записи ≤3/ход это те же «письма». Толкает: **много**.

2. **HumanLayer** [П]. `require_approval` блокирует вызов, запрос уходит в Slack/email/SMS/Discord, ответ с комментарием возвращается агенту; есть `human_as_tool` (агент сам просит ввод). https://humanlayer.dev
   Идея: одобрение живёт в канале владельца, с комментарием «почему нет», который агент читает. FF: Telegram-шлюз уже такой канал, не хватает комментария-причины как возврата в агента. Толкает: **много**.

3. **Letta ADE** [П]. Панель Core Memory: блоки памяти агента видны человеку, правятся руками, можно смотреть, как агент правит их вживую. https://docs.letta.com/guides/ade/core-memory
   Идея: память показана как редактируемый текст, а не как граф. Дифа и очереди нет (в выдаче не нашёл). FF: показ записи = карточка с полями + правка. Толкает: **средне**.

4. **Mem0 history** [Ч]. Неизменяемый журнал событий ADD/UPDATE/DELETE: old_memory, new_memory, actor_id, время; дашборд показывает историю изменений каждой записи. https://deepwiki.com/mem0ai/mem0/5.4-history-and-audit-trails
   Идея: лента = журнал событий с old/new и автором-агентом. FF: ложится прямо на supersedes/retract и статус proposed. Толкает: **много**.

5. **Cursor / Copilot / Devin: ревью результата, а не процесса** [Ч/П]. Агент работает в фоне, человек получает diff/PR; у Copilot каждый коммит агента ссылается на лог сессии для аудита, вкладка Agents = центр всех задач. https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/agents/coding-agent/agent-management · Cursor: https://www.datacamp.com/blog/cursor-3 [Ч]
   Идея: «итог + дифф сверху, лог процесса по ссылке». FF: у записи `source.ref` на сессию агента = та же схема. Толкает: **средне**.

6. **Усталость от одобрений** [Ч]. Anthropic (март 2026): пользователи одобряют ~93–97% запросов, люди ловили 13,6% опасных команд против 89% у классификатора; Auto mode стал дефолтом с 14 августа [Ч, цифры расходятся между источниками]. https://tessl.io/blog/claude-code-gets-auto-mode-to-cut-approval-fatigue/ · https://hyrax.dev/blog/claude-code-auto-mode-default-august-14
   Идея: очередь, где всё надо одобрять, превращается в «да, да, да». FF: проект-области с низким риском должны авто-приниматься, человеку показывать только отклонения. Толкает: **много**.

7. **Annotation queues Langfuse/LangSmith** [П]. Очередь на проверку: фильтр отбирает трейсы, ревьюер ставит оценку + комментарий. У LangSmith есть маршрутизация и приоритет риска, у Langfuse нет. https://langfuse.com/docs/evaluation/evaluation-methods/annotation-queues
   Идея: очередь не FIFO, а по риску. Это про разработчиков (анти-цель миссии), берём только приоритет. Толкает: **мало**.

## Две инновационных хода

**А. «Одобрение по исключению с ленивой выборкой».** Очередь не показывает все proposed. Система сама авто-принимает записи, которые не конфликтуют ни с чем (нет пересечения с существующими, низкий риск, область ff/agents-manager), а владельцу утром приходит ОДИН дайджест: «принято сама N (свернуто), на твой взгляд M: конфликт/спорное/впервые». Плюс случайная выборка 1–2 авто-принятых «на проверку честности» (против слепого «да»). Это ответ на 93–97% одобрений.

**Б. «Дифф памяти за день как один сгенерированный вид».** Не поток карточек, а один экран: «что изменилось в моей голове с вчера»: новые узлы/рёбра, замены (было → стало), и кто из агентов написал. Генерируется из журнала событий (как Mem0 history, но по графу, с рёбрами как первоклассными), чтобы владелец за 30 секунд видел картину. В Telegram идёт сжатой карточкой + ссылка на веб-вид. Не нашёл готового продукта, который показывает дифф графа памяти человеку [нет данных, не утверждаю, что нет].

## Что не брать

- Полный LLM-трейсинг (Langfuse/Phoenix-стиль, спаны и токены): для разработчика, не для владельца.
- Модалку «одобрить каждый вызов»: усталость, 97% «да».
- Лог процесса как главный вид: показывать только по ссылке из записи.
- Правку памяти руками как основной путь (Letta): у FF владелец утверждает, а не пишет.
