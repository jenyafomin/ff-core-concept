## Находки

1. **Talk like a Graph (Google, ICLR 2024)** — [arXiv 2310.04560](https://arxiv.org/pdf/2310.04560) [проверено, блог Google]. Способ текстового кодирования графа меняет точность до ~60%; «incident»-кодирование (узел: список соседей) лучшее в целом; топология и размер модели тоже влияют. Для FF: вид узла = «узел + его соседи с типом ребра», а не плоский список троек. Толкает: средне.
2. **Прогрессивное раскрытие на LLM-вики** — [arXiv 2607.04576](https://arxiv.org/pdf/2607.04576) [проверено, абстракт]. 709 страниц markdown, 4 версии доступа к тем же страницам: качество в рамках допуска, стоимость упала во всех условиях. Но сильный агент вообще не грузил большой индекс; качество при принудительной загрузке каталога не доказано; согласие человека и LLM-судьи слабое. Для FF: не заставлять агента читать overview целиком, дать дешёвый find. Толкает: много.
3. **GraphRAG, сводки сообществ** — [Microsoft Research](https://microsoft.com/en-us/research/blog/graphrag-new-tool-for-complex-data-discovery-now-on-github) [с чужих слов]. Иерархические сообщества, у каждого сводка; на верхних уровнях ~2–3% токенов против суммаризации исходников, на средних 20–70%. Подходит для вопросов «про всё». Для FF: сводка области/кластера как грань между label и summary. Толкает: много.
4. **LightRAG** — [с чужих слов] двухуровневый поиск (сущность + тема) без предвычисленных сводок сообществ, индексация дешевле на порядки. Для FF: дешёвая альтернатива п.3, если сводки кластеров устаревают. Толкает: средне.
5. **Zep/Graphiti** — [arXiv 2501.13956](https://arxiv.org/html/2501.13956) [с чужих слов]. Три яруса: эпизоды, сущности, сообщества; рёбра с периодом валидности; LongMemEval +до 18.5% при −90% задержки. Для FF: наш паспорт ребра (status/supersedes) это то же самое, нужно отдавать «актуально на дату» прямо в виде. Толкает: средне.
6. **HippoRAG 2** — [arXiv 2502.14802](https://arxiv.org/pdf/2502.14802) [с чужих слов]. Personalized PageRank от найденных узлов; +7% на ассоциативных вопросах. Для FF: ранжировать обход ≤2 по PPR, а не обрезать по ≤50 слепо. Толкает: средне.
7. **Mem0 graph** — [arXiv 2504.19413](https://huggingface.co/papers/2504.19413) [с чужих слов]. Граф даёт лишь +2–2.6 п. на multi-hop/temporal, цена ~2× токенов (~14K против ~7K). Для FF: граф окупается только на связных вопросах, не по умолчанию. Толкает: мало.
8. **TOON и компактные форматы** — [arXiv 2605.29676](https://arxiv.org/abs/2605.29676) [проверено, абстракт]: TOON −18% токенов, но −9 п. точности и каскадные сбои в агентских мульти-ходах (TRON −27%, до −14 п.). Бенчмарки авторов TOON (~−40% токенов, +1–4 п.) [с чужих слов] относятся к однородным таблицам. Выигрыш реален только для табличных данных; [arXiv 2603.03306](https://arxiv.org/abs/2603.03306) [проверено]: для генерации plain JSON точнее. Для FF: таблица «id | type | label | status» в TOON/CSV для чтения, JSON для записи. Толкает: средне.
9. **Anthropic: инструменты и контекст** — response_format concise/detailed (≈⅓ токенов в примере статьи), лёгкие идентификаторы + догрузка по требованию [с чужих слов, пересказы]. Для FF: параметр `detail` в find/read. Толкает: средне.

## Два инновационных хода

**Ход A. Сводка кластера как узел графа (label → cluster-digest → summary → body).** Раз в N записей считаем сообщества (Leiden по рёбрам, либо готовые scope/type) и записываем digest ~150 токенов как запись type=digest с рёбрами `summarizes` и паспортом (hash состава, stale при изменении >X% членов). Агент сначала видит 15–30 digest (~3K токенов), потом спускается. Закрывает «глобальные» вопросы без чтения 1350 узлов; хранится в самой памяти, переносимо.

**Ход B. Вид «стабильный каркас + incident-блоки + ранжирование PPR».** Ответ read: заголовок узла, затем сгруппированные по типу ребра соседи в табличной строке, обход ограничен бюджетом токенов, а не числом узлов (ранжирование по PPR от стартового узла). Параметр `detail=ids|labels|summary`.

**Мини-эксперимент (локально, 1 день).** Выбрать 10 вопросов по реальным данным: 3 точечных (какой статус у X), 3 двухшаговых (какие решения связаны с задачей X и устарели ли), 2 агрегатных (чем занимается область Y), 2 временных (что заменило решение Z). Золотые ответы разметить заранее руками. Форматы кормить одной моделью и одним промптом: (1) список троек, (2) JSON-adjacency, (3) markdown-outline с incident-блоками, (4) TOON/CSV-таблица узлов + ребра отдельной таблицей, (5) вариант 3 плюс digest кластеров (ход A). Мерить: точность (судья LLM + ручная проверка 20%, помня о слабом согласии из п.2), токены на вход, число вызовов инструментов. Масштаб: всё 1350 узлов, label+summary.

## Что не брать
- Полный GraphRAG-индекс (дорого, вердикт сообществ по сырому тексту нам не нужен: тела в git).
- TOON как формат записи/ответа агента (сбои мульти-хода, п.8).
- Векторную БД ради вида: для адресов с label хватает find + граф.
- Мнение «граф всегда лучше»: п.7.

## Вопрос
Какая доля реальных вопросов агента к памяти глобальные («что у нас по X вообще») против точечных? От этого зависит, нужен ли ход A сразу.

Вопрос-цель: ответил частично — направление (incident + digest + detail-параметр) названо, но точность форматов на ~1350 узлах не измерена, нужен мини-эксперимент.
