## M1. Где генеративный UI проваливается у человека
- **Вопрос-цель:** при каких условиях «UI каждый раз разный» вредит (предсказуемость, мышечная память, нагрузка), и какой минимум стабильности нужен?
- **Линза:** доверие и когнитивная нагрузка.
- **Что искать:** исследования и постмортемы generative/adaptive UI; Nielsen Norman, CHI/UIST/IUI (adaptive UI predictability, Gajos); отчёты о провалах adaptive menus; метрики consistency.
- **Где:** arXiv, ACM DL, NN/g, постмортемы Vercel v0 / Claude Artifacts / Copilot-интерфейсов.
- **Сильная находка:** количественный порог (что можно менять между показами, а что нет) + паттерн «стабильный каркас, генерируемое содержимое».
- **Анти-цель:** обзоры «топ-10 genUI-инструментов», маркетинг.

## M2. Безопасность UI-канала: injection, утечка, ложное доверие
- **Вопрос-цель:** как сгенерированный вид становится вектором атаки (инъекция из текста документа в граф → в UI → в действие) и что реально закрывает это при декларативном формате без кода?
- **Линза:** adversarial security + согласие/видимость.
- **Что искать:** indirect prompt injection через рендер (markdown-картинки-эксфильтрация, фишинговые ссылки/кнопки, поддельные «карточки доверия»); CVE и разборы MCP Apps / A2UI / artifacts-песочниц; confused deputy при действиях из вида; утечка полей шире читателя.
- **Где:** Simon Willison, Embrace The Red, OWASP LLM Top 10, advisories MCP-спеки, security-разделы A2UI/MCP Apps.
- **Сильная находка:** конкретный эксплойт-класс + проверяемый контроль, который укладывается в «безопасность в коде» (allowlist компонентов, поле-уровневая фильтрация до генерации).
- **Анти-цель:** общие «prompt injection существует»; контроли, требующие второго языка/скриптов.

## M3. Как агент ПОНИМАЕТ граф (скрытый рычаг №1)
- **Вопрос-цель:** какое представление графа (сериализация, саммари сообществ, schema-first, адреса без тел) даёт LLM наилучшую точность вида на ~1350 адресах + рёбрах, и сколько стоит?
- **Линза:** качество входа важнее качества выхода.
- **Что искать:** GraphRAG (Microsoft), LightRAG, text-vs-graph encoding for LLMs («Talk like a graph», GraphQA), graph-to-text бенчмарки, ошибки на multi-hop; работа только с метаданными (label/summary) без тел.
- **Где:** arXiv, репозитории GraphRAG/LightRAG, бенчмарки STaRK/GraphQA.
- **Сильная находка:** сравнение форматов на малом графе (не web-scale) с ценой токенов; рецепт, воспроизводимый локально.
- **Анти-цель:** вендорные векторные БД, масштабы миллиардов узлов.

## M4. Стабильность, провенанс и локальность видов
- **Вопрос-цель:** как закреплять/версионировать сгенерированный вид (вид = данные, воспроизводимый, переносимый), показывать происхождение каждого элемента и работать офлайн/локально?
- **Линза:** стабильность + провенанс + переносимость.
- **Что искать:** pin/save generated UI, spec-as-data, детерминизм (seed, кеш по хешу спеки), eval генеративного UI (LLM-judge, рубрики, регрессия); provenance в UI (W3C PROV, C2PA-идеи, citation UI); local-first (Ink & Switch), малые локальные модели для UI-спек (Ollama, structured output/grammar).
- **Где:** Ink & Switch, W3C PROV, статьи по eval v0/Artifacts, llama.cpp grammars, Outlines.
- **Сильная находка:** схема «вид-как-запись» с хешем/провенансом + способ автотеста вида без глаз человека + оценка, тянет ли локальная модель 80% видов.
- **Анти-цель:** облачные only-решения, привязка к конкретному движку.
