# Возражение 04: свой Postgres + NestJS при 0 записях — уровень N+1
- **Статус:** accepted · - **Потребитель:** лид · **Поглощает:** ничего · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-14
## Суть
Жизнь = 0: мозг собран, не запущен, читатель не привязан. Правило «слой N+1 только после живого N» (OVERVIEW, compound п.5) прямо против. ADR-0017 уже решил: Postgres = чисто добавочный адаптер, истина = журнал; 00-SYNTHESIS Д4: БД = пересобираемый индекс «когда появятся несколько писателей» — писатель один. NestJS — веб-фреймворк (DI, HTTP-контроллеры) поверх сервиса, который есть stdio-MCP под pm2: ничего из этого не нужно, пока нет второго клиента. Новая поверхность: бэкапы, миграции, секреты подключения (в логах шлюза уже лежат пароли), pm2 `pg` — чужой YashaBot. Docs:code ~14:1 -> «поднять инфраструктуру» это ещё одна форма избегания первой записи.
## Контр-довод (честно)
0 данных = миграция бесплатна; ADR-0017 шов хранилища НЕ проверен вторым адаптером — пока адаптера нет, «шов» гипотеза. Возможно, ранний PG-адаптер вскроет дыры шва дешевле, чем поздний.
## Вердикт
Не сейчас как инфраструктура; сейчас — только узкий эксперимент с потолком (compound п.5): contract-тест порта хранилища на in-memory/SQLite-файле; PG — после триггера (2-й писатель ИЛИ запрос, который журнал не тянет).
