# Критика: «обе двери как настройки» + «свой Postgres + NestJS»
- **Status:** draft · **Owner:** jenya.stasik@gmail.com · **Date:** 2026-10-14
- **Потребитель:** лид · **Поглощает:** ничего
- **Вопрос-цель:** Где «обе двери как настройки» и «мозг на своём Postgres + NestJS» обманут нас — и как задача может быть поставлена неверно?
- **Related:** ideas/2026-10-14-owner-seed-settings-and-pg.idea.md · contra/01..05

## 1. «Обе как настройки»
- CRITICAL: дрейф семантики (contra/01) — журнал append-only, режим не записан в ребро; переключатель переосмысляет историю молча (V2/V3).
- CONCERN: V5 + комбинаторика (contra/02) — смысл вне единицы не переносится; 2^n режимов тестов без данных для их различения.
- CRITICAL: отказ от решения (contra/03). Критерий честности: настройка не меняет ни байта журнала и ни одного инварианта. Честно: вид md, сортировка, язык, пороги отображения, «умные группы» как ЛИНЗА. Нечестно: что значит part-of, тип vs роль. Д3 решается ролью (надмножество) — настройка не нужна. Д2: либо два `kind` ребра (тогда это два типа, не настройка), либо один смысл — выбрать.

## 2. PG + NestJS сейчас (contra/04)
За «сейчас»: 0 данных = миграция бесплатна; шов ADR-0017 не проверен вторым адаптером.
Против: N+1 при жизни 0; ADR-0017 уже: PG = добавочный адаптер, Д4: БД = индекс при нескольких писателях (писатель один); NestJS не решает ни одной текущей боли; новая поверхность секретов/бэкапов; ещё один способ не писать первую запись.
Вердикт: НЕ сейчас. Допустим узкий experimental-эксперимент: contract-тест порта хранилища (in-memory + файл), потолок 1 день. PG-адаптер — по триггеру: 2-й писатель или запрос, не тянущийся журналом.

## 3. Вопрос, вскрывающий рамку (contra/05)
«Что ты хочешь делать с мозгом через месяц, чего нельзя на файле? Один запрос и один реальный эпизод.» Побочные: «какую запись ты уже хотел сделать и не смог?»; «Д2 нужна для первых 5 записей, или ты решаешь её впрок?»

## 4. Минимальный опровергающий тест до любой стройки
Сделать 5 реальных записей в мозг на ТЕКУЩИХ файлах, включая 2 группы (part-of), и выполнить 3 чтения (одно — по входящим рёбрам). Опровержение «PG/настройки нужны»: если все 8 действий проходят без Д2/Д3-переключателя и без БД — стройка не нужна. Если упёрлись, то в КОНКРЕТНОЕ место: оно и есть спецификация. Стоимость: час владельца + запуск мозга.

## NOTED
Шов хранилища: contract-тест порта дёшев и компаундит (работает для любого будущего адаптера).

Итог: решение — не строить PG/NestJS и не вводить Д2/Д3-переключатели; сначала живой прогон (тест п.4); Д3 = роль; Д2 — выбор владельца одним словом.
