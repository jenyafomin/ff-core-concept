## 🔴 БОЛЬШОЙ сквозной форк (назвали 4 агента независимо → критичный)
**«Производное состояние = read-time проекция ИЛИ материализованное поле?»**
Проявился как: integrity (M-G3), DataResidency-паспорт (M-G4), gateState петли (M-P3), reports-to (M-G2).
Все — один вопрос: где грань, за которой удобство кэша порождает ВТОРОЙ источник истины (главный риск консилиума).
**Кандидат-правило:** проекция-первой + rebuild-с-нуля как операция первого дня; материализация/кэш — 🟢 позже, помечена как производная. → на адверсариальную проверку (могут ли быть исключения: офлайн, кросс-БД, перф).

## 🟡 Точечные форки (каждому — владелец/Fable)
1. **M-G1 ↔ M-G3** — один модуль или два? Грань «исполняет vs декларирует».
2. **integrity** — уровень каскада ИЛИ долг движка (правило, не хранимые узлы)?
3. **reports-to** — дерево или DAG?
4. **DataResidency** — отдельный node-type или паспорт-колонки?
5. **«чей я»** — уровень данных (узел/паспорт) или движка/деплоя (кто открывает сессию)?
6. **Session ↔ домен 01** — Session хранит память (payload) или только thin-ref на узлы домена 01? *(2 агента сошлись: thin-ref, Session = координата исполнения, не хранилище).*

## ✅ Решено этой волной
- **policy = много узлов + один каскад** Конституция>policy>integrity (один гигант ломает I-1/I-2). Развилка владельца закрыта.
- **7 ценностей → 7 policy-узлов** с конкретным требованием каждой (см. `domains/01-knowledge-graph/policy.md`).
- **canonicalId** = ключ идемпотентного слияния БД (одинаковый UUID = одна сущность; разные ID → `same-as`, не мутация).
- Домены 01 и 02 раскрыты в **папки** (node-types/edge-types/policy + growth).

## ⚠️ Пробелы (не покрыто этой волной)
- **M-P1 Планы**, **M-P5 Категории / Домен 03** — не углублялись (домен 03 = кандидат: грань домена 01 через `container`-узел).
- Граница домен01↔02 названа тремя агентами, но не ратифицирована.

## 🛡️ Поправка правила «проекция-первой» (адверсариальная проверка V1)
Правило **выживает С ПОПРАВКОЙ** (как есть — несостоятельно: `DataResidency` и «≤1 Active» стоят в 🔴-списке дня один и уже материализованы).
**Уточнённая форма:** default = read-time проекция. **Материализация легитимна, если:** derivation-rule
объявлено явно + rebuild-from-scratch проходит + маркер `derived=true`/provenance + для concurrency/security
(uniqueness `≤1 Active`, breaker-счётчики, ACL-гранты) — **синхронная инвалидация на запись**, не ленивый TTL.
Легитимный класс материализации: uniqueness-констрейнты · hot-path счётчики-инварианты · federation-реплики.
