## Сырьё (из Telegram)
«Одна личность старается держать в памяти контекст, где она работает. Нужно не перегружать
активные темы у определённой личности (запущенный агент). Механизм по времени — определять, над
чем работает каждый ассистент. Ассистентов можно клонировать, но держать ровно столько, сколько
есть бюджета и количество задач. Желательно не перегружать контекст начиная с 40–65%, иначе
затраты. В идеале просчитать все затраты… важно создать по этому задачу.»

## Суть
Каждый агент-«личность» имеет рабочий контекст и набор активных тем. Нужен **рантайм управления
ассистентами**: следить, чем занят каждый, не перегружать его контекст (порог ~40–65%),
клонировать агентов под нагрузку, но держать ровно столько, сколько позволяют бюджет и число
задач. И — считать затраты.

## Разбор на под-идеи
1. **Загрузка контекста (%).** Считать объём контекста агента; держать в 40–65%, выше — дороже и
   хуже качество. → мониторинг токенов + политика компакта (см. CHAT-HIERARCHY-AND-CONTEXT §5).
2. **Кто над чем работает (во времени).** У агента есть активные темы/задачи; видно загрузку.
3. **Пул агентов по бюджету.** Клонировать агента под задачи, но число ограничено бюджетом и
   очередью задач → планировщик/оркестратор.
4. **Учёт затрат.** Оценивать стоимость (токены × цена модели); по возможности точный учёт.

## Легко / сложно
- 🟡 Считать загрузку контекста и порог 40–65% (счёт токенов доступен).
- 🟡 Оценка затрат по токенам и ценам моделей (приблизительно — реально; точный учёт — задача).
- 🔴 Пул/клонирование агентов по бюджету, балансировка нагрузки, «кто над чем во времени» —
  это ядро рантайма автономии (та самая единственная трудная инфраструктура).

## Риски
- Преждевременная оптимизация: это сложная инфраструктура; строить рано = заброс. Сначала пусть
  агенты вообще заработают (лёгкие, по запросу), потом — управление их пулом.
- Порог 40–65% — эвристика; нужно проверять эмпирически, не догма.
