## Сырьё (из Telegram)
«Каждый раз когда я пишу сообщение, я создаю новую сессию для сообщения, но при этом система
должна сама продумать и придумать, что можно присоединить друг к другу. У нас уже должны быть
понимания в системе, что информация из себя представляет. Где-то это личности в виде ассистентов
(их отдельно, у них своя жизнь), но есть и другие важные вещи (информация).»

## Суть
Каждое новое сообщение = **новая сессия/узел**, но система **сама** определяет, к каким уже
существующим узлам его привязать. Для этого система должна понимать **природу информации**:
часть узлов — «личности» (агенты, у них своя жизнь/контекст), часть — «информация» (заметки,
задачи, источники, темы).

## Место в системе
- Сообщение → узел (`kind: message`/`chat`); агент-**линкер** привязывает его к графу.
- Различение природы уже есть в модели `@ff/core`: `kind: agent` (личности) vs остальные kind
  (информация). То есть фундамент заложен.
- «Сама продумать что присоединить» = агент-линкер из каталога (находит связи по смыслу/тегам).

## Легко / сложно
- 🟢 Каждое сообщение → узел; различение «личность vs информация» (это `kind`).
- 🟡 Авто-связывание «что к чему присоединить» — агент-линкер; качество зависит от структуры и
  порога уверенности.
- 🟡 «Новая сессия, но с пониманием прошлого» = подгрузка релевантного контекста из графа
  (граф = память; окно = кэш — уже наш принцип).

## Риски
- Авто-связывание может связать неверно → шум в графе. Нужен порог уверенности или быстрый
  «подтверди/отклони связь».
