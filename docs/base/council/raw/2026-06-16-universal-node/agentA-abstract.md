> Условие: «догадаться к чему владелец клонит» (msg 184-185). Condensed-faithful.

## INTENT (куда метит)
Он перестал проектировать «схему ноды» и начал проектировать **грамматику смысла** — минимальный набор
измерений, по которым ЛЮБАЯ единица становится понятной ИИ ДО того, как известен её тип. «Особенности,
оборачивающие ноду» — это не поля, а **фасеты интерпретации**: оси, по которым ИИ режет, фильтрует и решает
как обращаться с ячейкой. Ядро ноды = не данные, а **протокол толкования**: «по этим N осям меня можно понять,
остальное — внутри payload по правилам типа». trust+valve = первые два открытых им члена ряда; просит достроить.
→ **Он ищет «периодическую таблицу аспектов единицы смысла»** — наименьший полный набор граней, общих для
задачи/человека/книги/плана/памяти-агента, по которым ИИ + система + человек реагируют одинаково, не зная типа.

## ГРУППЫ (10; принцип: грань в ядре, только если ИИ должен знать её НЕ открывая payload и НЕ зная тип)
Три кольца: IDENTITY (что это) · INTERPRETATION (как понимать — тут trust+valve) · RELATION (как связано/разворачивается).
1. **Identity** — id + тип@версия + заголовок [CORE]
2. **Substance** — body + типизированный payload (JSON) [CORE-конверт / MODULE-форма]
3. **Epistemic** — статус знания: факт/гипотеза/черновик/архив [CORE-универсал = его trust]
4. **Agency/Valve** — можно ли действовать вовне + нужно ли одобрение [CORE-универсал = его клапан]
5. **Temporal** — когда произошло / когда истинно / срок [CORE битемпор. / MODULE ряды,рекуррентность]
6. **Belonging** — один владелец-дом (контекст+важность) [CORE]
7. **Relation** — N типизир. рёбер: cascade/variant-of/instance-of/reply/link [CORE-механика / MODULE-смысл]
8. **Branching** — параллельные ветки/варианты + указатель активной [CORE-примитив / MODULE-смысл]
9. **Access/Scope** — principal + область (личное/проект/плагин) [CORE-ось default-deny / политики]
10. **Provenance** — источник + автор + трейс [CORE]
> Ядро хранит у каждой грани ТОЛЬКО ярлык/указатель, не содержание (epistemic=метка, valve=флаг, belonging=один id).

## ВНУТРЕННЯЯ СТРУКТУРА (controlled vs flexible)
У каждого типа — declared shape со «степенью контроля» `mode`, и эта shape — САМА нода (тип-как-узел).
`mode: controlled | open | hybrid`; fields с kind/required/enum/constraint; `rules: when/then` («функции как
условия» — ДЕКЛАРАТИВНО, не код); `open_tail`. Один контракт — три читателя: ИИ (что писать/как толковать),
движок (валидатор+индекс-план), человек (рендер формы: enum→дропдаун, constraint→подсказка, required→звёздочка).
Реактивная/исполняемая логика — отдельно (ось ACT, ADR-0002); внутри ячейки живут ОГРАНИЧЕНИЯ, не поведение.

## РЕФРЕЙМ (самый острый)
**Ядро ноды — не запись данных, а ПАСПОРТ интерпретации. Универсальны не поля — универсальны ВОПРОСЫ, на
которые каждая ячейка обязана ответить, чтобы ИИ обращался с ней не зная типа.**
Аналогия: ячейка = морской КОНТЕЙНЕР. Внутри что угодно (payload, дело модуля); снаружи — стандартные
маркировки: ID, опасность груза (=trust), нужна спецтаможня (=valve), отправитель (=provenance), пункт
назначения (=belonging), коды стыковки (=relation). Кран в порту (ИИ) штабелирует миллионы, НЕ вскрывая.
→ «Особенности, оборачивающие ноду» = эти внешние маркировки. Тонкое ядро vs богатые модули перестаёт быть
компромиссом. Расширяемость безопасна. trust+valve — просто 2 из маркировок, он почувствовал что мало, и попросил весь набор.

## Спорные точки (для critic)
Кандидаты на СЛИЯНИЕ: Provenance↔Epistemic, Belonging↔Access. Кандидат на 11-ю ось: **Lifecycle/Freshness**
(свежесть/устаревание) — пока внутри Temporal, спорно. «Точка расхождения с другим агентом = что считать
отдельной осью, а что частным случаем» — самый полезный спор для владельца.
