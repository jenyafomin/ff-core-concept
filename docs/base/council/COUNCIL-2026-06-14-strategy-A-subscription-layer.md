## Что оценивали
Продукт-слой ПОВЕРХ подписки самого пользователя: (1) поставка `.claude/` конфигурации
(пред-настроенные агенты/скилы/MCP/контекст/хуки), (2) пассивная «прослушка» сессий (чтение
транскриптов `*.jsonl`), (3) советник по контексту/топикам — человек в петле, без нашего API-биллинга.

---

## КОНСЕНСУС
1. **Сильнейший, дешёвый, чистый по доверию кусок = дистрибутив `.claude/` конфигурации.**
   Асимметрия доверия (Pragmatist): конфиг = ноль сопротивления (пользователь уже доверяет
   Anthropic своими данными); доступ к транскриптам = отдельный, более тяжёлый акт согласия.
2. **Статичный конфиг = retention 0** (Skeptic, принято Pragmatist). Чтобы жить, это должна быть
   **живая, версионируемая, обновляемая экосистема агентов** (новые агенты, обновлённые скилы,
   community-пресеты через CLI/update-loop). Distribution-loop = механизм возврата (его никто не
   специфицировал — пробел).
3. **«Прослушка» — самая хрупкая/низкодоверная/жидкая по сигналу часть.** Если делать — то
   минимально и за «портом»: Ports&Adapters + антикоррупционный слой, парсить транскрипт
   **намеренно бедно** (только структурные паттерны: повтор, откат, длинный цикл, брошенная ветка —
   высокий precision, низкий recall). Хрупкость ∝ числу полей, на которые завязан. Opt-in с preview.
4. **Советник переосмыслен:** его настоящий выход — не сами советы, а **DecisionLog / карта
   доверия**: что владелец принимает/отклоняет/игнорирует. Архитектурно (Architect): event-sourced
   `AdviceEvent`-лог + проекция `TrustScore` как ПЕРВИЧНЫЙ агрегат в `@ff/core`; транскрипт =
   вторичное сырьё, не актив.

## НЕРАЗРЕШЁННЫЕ РАЗВИЛКИ (сохранены)
- **F1 — Есть ли у A ценность САМА ПО СЕБЕ, или это только мост/маркетинг для B?**
  - *Skeptic (0.81, ужесточился):* A коллапсирует до «умных dotfiles»; лог доверия ценен ТОЛЬКО
    если B существует («дневник без читателя»); если A = starter-pack в гите — это open-source,
    не SaaS; switching-cost через лог слабый (экспорт в markdown ломает за 5 мин). «Reframer не
    спас A — он описал B в шапке A».
  - *Reframer (0.7, сдвинулся):* СНЯЛ «A — фаза для B»; теперь A самоценен как калибратор доверия
    («зеркало недоверия»), ценность БЕЗ B.
  - *Architect (0.7):* DecisionLog делает A автономно ценным (аудит решений) даже без B — явный
    диссент против «двух фаз».
  - **Итог: главный спор A не разрешён** — лог решений это реальный актив или красивая рационализация?
- **F2 — Дрейф объекта.** A улучшает Claude Code, а НЕ «жизнь» (исходная цель владельца — агенты,
  расширяющие меня). **Reframer прямо признал дрейф реальным** («чиним Claude Code, не жизнь»).
  Серьёзный флаг: A может быть уходом от цели личной системы в сторону dev-tool продукта.
- **F3 — Хочет ли владелец видеть свою «карту недоверия»?** Это зеркало, не дашборд; если больно —
  отрицательный retention по причине, отличной от «ценностного вакуума».
- **F4 — Где платёжный триггер до появления B?** Живой конфиг-дистрибутив — реальный (скромный)
  подписочный продукт; монетизация советника/лога без B неясна.

## ВЗВЕШЕННАЯ РЕКОМЕНДАЦИЯ
- **Защитимое ядро A = живой версионируемый дистрибутив пред-настроенных агентов/скилов/контекста**
  (`.claude/`) с update-loop. Чисто по ToS, дёшево, немедленная польза, высокое доверие. Реально, но
  СКРОМНО (категория: «экосистема конфигов / starter-pack как подписка»). Это же — твои
  «пред-настроенные чаты».
- **Слой наблюдение+советник+DecisionLog** — выше риск, выше хрупкость, упирается в приватность, и
  его самостоятельная ценность реально спорна. Делать его минимально, за портом, opt-in, и только
  если DecisionLog действительно нужен (как аудит решений и/или мост к B).
- **Честные флаги:** дрейф объекта (A ≠ цель «управление жизнью»); хрупкость (недокументированный
  `*.jsonl`, нет API «% контекста»); retention держится только на update-loop; советник рискует
  «ценностным вакуумом».

## Несокращаемые риски (severity H)
- Thin-wrapper / ценностный вакуум → retention 0 без update-loop (Skeptic).
- Хрупкая зависимость от формата `*.jsonl` (Architect/Pragmatist).
- ToS-дрейф: соблазн «чуть автоматизировать» хуком = автономное действие в сессии (Skeptic).
- Дрейф цели: строим менеджер Claude Code, забываем жизнь (Reframer).

## Gate-критерий (Skeptic)
Если после 3 советов поведение пользователя не меняется — слой советника мёртв (вернуться к
чистому конфиг-дистрибутиву). Нужна метрика качества совета, иначе gate неизмерим (пробел).
