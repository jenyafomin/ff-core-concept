## Главный итог
Два совета **растворили дихотомию**. A и B — не конкурирующие стратегии, а **одна труба с
растущим клапаном**:
- **A = труба:** дистрибутив пред-настроенной `.claude/` конфигурации + лог наблюдений/доверия.
- **B = диаметр клапана:** сколько сайд-эффекта проходит без подтверждения владельца.
- Линия одна: **конфиг → лог доверия → cron-наблюдатель (клапан 0, только предлагает) →
  аккредитованное действие (клапан растёт по зонам, обратимое-первым)**.

Не «A или B». Не «сначала A, потом B». А: **B — это диаметр A.** Один и тот же код при клапане=0
безопасен (наблюдает), при росте клапана — действует. Аккредитация открывает клапан по истории.

## Сравнение

| Ось | A (слой на подписке) | B (рантайм на API) |
|---|---|---|
| Кто платит за агентов | пользователь (его подписка, $0 нам) | мы (API, ~$2/мес B-lite, потолок $15) |
| Главная ценность | конфиг-экосистема + лог доверия | агент реально ДЕЛАЕТ работу (push) |
| Автономия | нет (advisory, человек кликает) | да, но обратимо-первой и по аккредитации |
| ToS | чисто (чтение своих транскриптов + поставка конфига) | чисто (API для автоматизации) |
| Retention | только через update-loop (иначе 0) | через доказанный ROI |
| Главный риск | дрейф цели + ценностный вакуум | необратимый сайд-эффект + токен-взрыв |
| Соответствие цели «расширять меня» | слабое (улучшает инструмент) | прямое (агенты делают за меня) |
| Сложность для solo | низкая | средняя (гасится «одним cron-агентом») |

## Где советы СОШЛИСЬ (оба)
1. **Начать с ОДНОГО крошечного агента, не со строительства платформы.** (Совет B — единогласно;
   Совет A — конфиг как первый кусок.)
2. **Граф = источник правды, окно = одноразовый кэш.** Оркестратор STATELESS → авто-чистка
   контекста перестаёт быть проблемой.
3. **Человек в петле / обратимость / proposal-перед-commit.** Автономия зарабатывается, не выдаётся.
4. **Лог доверия (что владелец принял/отклонил)** — общий актив обеих стратегий; он и есть то,
   что открывает клапан B.

## Решающий вопрос — за владельцем
**Облегчение или тревога?** Когда агент сделал что-то без тебя — ты чувствуешь облегчение
(«система работает за меня») или тревогу («я потерял контроль»)?
- Если **облегчение** → цель = autonomy-runtime, клапан открывать быстрее (на обратимом).
- Если **тревога даже при верном действии** → цель = **proposal-runtime**: система предлагает,
  последнее слово за тобой; клапан открывается медленно и по аккредитации.
Это определяет скорость, НЕ направление. Покажет первый реальный брифинг.

## Рекомендуемая единая линия (следующие шаги)
1. **Закалить стор `@ff/core`** (пререквизит из Совета B): тип узла `proposal`
   (draft|approved|committed|rejected), оптимистичная конкурентность (CAS/`expectedVersion`),
   idempotency-key на commit, узел-счётчик бюджета. Без этого многоагентная запись опасна.
2. **Клапан-0: один cron-агент на Haiku, proposal-only** — читает инбокс/`docs/` → предлагает
   задачи/обзор → пишет `proposal` + trace в граф; ничего не делает наружу. ~$2/мес,
   потолок-предохранитель $15. Это и B-lite, и первая запись в лог доверия.
3. **Утренний брифинг** как первый ощутимый момент (push read-only) — проверяет вопрос
   «облегчение или тревога».
4. **Открывать клапан по аккредитации** — обратимые действия авто-апрувятся после N верных
   предложений в зоне; необратимое всегда гейт. Guardrails: gate-0 (расширение scope = явное
   решение), sunset (30 дней без ROI → удалить агента).
5. Параллельно (опционально, дёшево): `.claude/` конфиг как живой дистрибутив (ядро A) — если
   захочется продукта для других; но осознавая дрейф цели.

## Честные флаги (перенесены из советов)
- A в одиночку дрейфует от цели «управление жизнью» к «менеджер Claude Code».
- B в одиночку без proposal-гейта и бюджета — необратимые ошибки и токен-взрыв.
- «Маленький ≠ безопасный» — scope крошечного агента надо ЗАМОРОЗИТЬ (gate-0) и поставить sunset.
- Вопрос «облегчение/тревога» не отвечен — он управляет скоростью открытия клапана.
