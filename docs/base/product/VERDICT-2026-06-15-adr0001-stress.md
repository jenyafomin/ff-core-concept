## TL;DR
Ядро ADR-0001 **подтвердилось и право** (epistemic⟂state, открытые типы, битемпоральность, git=карточка,
один дом убивает недетерминизм мульти-родителя). **Но к коду НЕ готово**, и ломается сильнее всего там, куда
ты вложил больше всего веса — **кластер 4 (субстрат агентов): 1✅/5⚠️/6❌**.
**Главная причина одна:** `home` одновременно = «единственный владелец (card-1)» И «единственный источник
каскада». Это верно для ЗАМЕТОК, но неверный примитив для СУБСТРАТА АГЕНТОВ.

Суммарно по кластерам: 1) 4✅/6⚠️/2❌ · 2) 3✅/3⚠️/4❌ · 3) 4✅/4⚠️/2❌ · 4) 1✅/5⚠️/6❌ · 5) adversarial: 4 CRITICAL.

## ✅ Что подтвердилось (не трогаем)
- **epistemic ⟂ state** — хвалят все 5 линз. Корневой фикс «одно поле status = бардак».
- **Открытые типы + `type@version`** — растворяют закрытый enum, который блокировал commit/pr/bug/prompt (кластер 3).
- **Битемпоральность** `valid_from/until/supersedes` — реальный выигрыш (меняющиеся факты, история цен).
- **git = книга, узел = карточка `href`** — чистая победа.
- **Один дом убивает недетерминизм мульти-родителя** — правильный отказ (важность/контекст определены).
- **ULID-id** (связи не рвутся при переименовании) — верно.

## 🔴 ГЛАВНАЯ структурная правка (load-bearing для рефрейма)
**Расщепить ВЛАДЕНИЕ и КАСКАД.** Сейчас `home` тащит оба. Из-за этого в кластере 4 непредставимы:
членство в чате/команде (3,6), экземпляры агента (12), реальный контекст-конверт (10) — каждому нужно
БОЛЬШЕ одной *каскадирующей* принадлежности.
→ **Решение (архитектор):** оставить `home` (card-1, владение/re-home) + добавить на рёбра `cascade:true` +
`cascade_order:int` с детерминированным слиянием (ближайший-побеждает + порядок + maxDepth). Каскад
становится **opt-in и упорядоченным** — это и есть ответ на исходную причину отказа от мульти-родителя
(недетерминизм). Контекст-конверт = `home ∪ N каскад-рёбер ∪ запрос памяти`, а не только цепочка дома.

## 🟠 Обязательные правки схемы ДО кода (иначе тихая порча)
1. **Цикл-гард по `links` + maxDepth + сигнал «обрезано на глубине N»** — сейчас проза, не поле/контракт.
   `getContext`/broadcast зациклятся или молча усекут контекст (CRITICAL ×2).
2. **`href` ОБЯЗАТЕЛЕН** (true=url / false=id). Только так движок отличает битую внутреннюю ссылку от внешней
   и ловит висячие рёбра (CRITICAL).
3. **Бэклинки = first-class** (движок держит обратный индекс по `links[].to`). Без них соц-граф, стейкхолдеры,
   история взаимодействий, кросс-областные запросы непредставимы (кластер 2: 4 ❌).
4. **Дедуп-поля** `aliases[]` + `canonical_of:id?` (или явно вынести дедуп из v2 и убрать обещание). Иначе
   «Anna»/«Аня» фрагментируют граф за неделю (CRITICAL).
5. **`instance-of`** (шаблон-роль агента vs экземпляр-в-чате со своей памятью); память хоумится к экземпляру (12).
6. **`inReplyTo`/`thread`** — ответы агент↔агент = DAG, сейчас непредставим (8).
7. **`decision: none|proposed|approved|rejected`** (+approver/decided_at) — отдельно от `epistemic`; апрув ≠ доверие (9).
8. **`archived`/`valid_until<now` выпадают из ДЕФОЛТНЫХ горячих запросов** (узкое исключение к Принципу 3) —
   иначе компакт не работает (11).
9. **Контракт запросов В ADR** (фильтры по type/rel/to/диапазон дат/state + пагинация) — иначе схема «только на запись».

## 🟡 Доменные дыры (важные, не блокеры ядра)
- **Рекуррентность/расписание** — нет поля (привычки, повторяющиеся траты, дни рождения) — кластер 1 ❌.
- **Метрика — одно-скалярная**: составные (вес+повторы, план+факт) ломаются → `secondary[]` + `derived:bool`.
- **Свежесть/хеш** для «понимания кода» (устаревает при изменении файла) — `observed_hash/at` на ребре (кластер 3 ❌).
- **Rollup/derived** прогресса (цели, бюджет, курс) — нет контракта агрегации.
- **`due`** отсутствует в каноническом блоке (кластер 2).
- **Реестр типов** должен быть запрашиваемым из графа (self-hosting через один bootstrap-тип `type-decl@1`),
  иначе «всё видно ИИ» нарушено для управляющего слоя + type sprawl (meeting/call/sync/interview).
- **`description` обязателен в ADR, но отсутствует в `node.ts` v1** — прямое doc↔code противоречие, не пропустить.

## ⚖️ Вердикт
ADR-0001 — крупный шаг вперёд, ядро право, но **остаётся `proposed`/в ревью**: нельзя писать `node.ts` v2,
пока не закрыты 9 правок схемы (особенно расщепление владение/каскад — без него рушится субстрат агентов).
Это НЕ «инфра на потом» — это пред-условия корректности.

## Рекомендуемый следующий шаг
1. Свести правки в **ADR-0001 v2.1** (или ADR-0002 «cascade & integrity»), с расщеплением владение/каскад как заголовком.
2. Один владельческий выбор перед v2.1: подтвердить «каскад = opt-in рёбра `cascade:true`+order» (это меняет
   ментальную модель «один дом» на «один владелец + N каскад-рёбер»).
3. Потом — закрыть инфра-гарды, затем переписать ядро.
