## 🔑 Рефрейм (оба агента независимо)
**Ядро ноды — это не запись данных, а ПАСПОРТ интерпретации.** Маленький фиксированный набор ГРАНЕЙ, на
которые отвечает каждая ячейка, чтобы ИИ обращался с ней **не вскрывая payload и не зная её тип**.
> Аналогия: ячейка = морской контейнер. Внутри — что угодно (payload, дело модуля). Снаружи — стандартные
> маркировки (грани). Кран в порту (ИИ) штабелирует миллионы разных, НЕ вскрывая.

**Архитектурный ключ (Принцип 0):** сам тип/схема/ограничения/ветки — ТОЖЕ узлы графа (control plane = данные,
не код). Это «всё — узел» распространённое на управляющий слой. Из него следует вся расширяемость.

## 🧱 Внутренняя структура ячейки (controlled vs flexible) — ключевой запрос
**Тип = узел** `type:model-def`; его payload = дескриптор схемы. ОДНА декларация — ТРИ читателя.
```yaml
type: model-def   namespace: garden   group: user   project_area: garden-project
description: "Растение"            # ← ИИ: интерпретация (agent-first)
payload:
  mode: controlled | flexible | hybrid       # ГЛАВНЫЙ переключатель строгости
  fields:
    species: {kind: string, required: true, ai_hint: "лат. имя", ui: {widget: text, label: "Вид"}}
    health:  {kind: enum, values: [healthy, wilting, dead], default: healthy}
    interval:{kind: int, range: [1, 90]}
  open: false                                 # false=строго (controlled); true=hybrid (свободный хвост)
constraints:                                   # ЛЕСТНИЦА выразительности
  - {field: interval, rule: range, args: [1,90]}            # L1 декларативные (движок нативно)
  - {when: {field: health, eq: dead}, require: {field: cause, present: true}}  # L2 условные
  - {predicate: 01J_PRED_xyz, message: "..."}               # L3 «функции как условия» = узел type:predicate
```
- **Режимы:** controlled (строго по shape) · flexible (свободный JSON, «запихнуть что угодно») · hybrid (ядро+хвост, дефолт).
- **«Функции как условия»** = узлы `type:predicate` (чистый предикат в песочнице) → логика остаётся ДАННЫМИ в графе.
- **Правило declarative-first:** предикат только когда деклараций не хватает (иначе движок не оптимизирует/не объяснит ИИ).
- **Single Source of Schema — 3 проекции одной декларации:** ИИ←description/ai_hint/message · движок←kind/required/range/enum/predicate · человек←ui/widget/label (форма автогенерится). Это и есть «самые большие возможности ячейки»: не больше полей, а одна декларация работает на троих.

## 🔌 Расширяемость (плагин = пакет N моделей)
`type:plugin-manifest` — узел, владеющий пакетом model-def + predicate + relations в неймспейсе.
- **namespace** = префикс типа (`garden/Plant`, `core/task`; `core/*` зарезервирован) → нет коллизий.
- **group: system | user** ⟂ неймспейс (system = движок завязан, неудаляемо; маркетплейс = только user).
- **system-user ≠ app-user** = два принципала (кто администрирует тип vs чьи данные) → фундамент ABAC.
- **project-area при подключении** = привилегированный home-предок: данные плагина каскадно в области, отделены
  от общих личных (`personal/root`). Глобальный апгрейд = набор МЕЛКИХ задач-узлов + перепроверка (не атомарный скачок).

## 🌿 Ветки ячейки (Branches)
Ветка ≠ supersedes (время) ≠ variant-of (вечные варианты). Ветка = рабочая альт-линия: «подготовить новый
план, переключиться, вернуться». **Именованные ветки + активный указатель + diff-оверлей**; **identity узла
СТАБИЛЕН** (внешние рёбра на id, не на ветку → переключение не рвёт граф); ветка несёт свой `epistemic`
(черновая=proposal → клапан не даёт действовать наружу). Механика=ENGINE, семантика мёржа=MODULE.
