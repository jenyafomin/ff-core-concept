# Сравнение с конкурентами (Stage: L3 Ресёрч)

> Три параллельных разбора. Фаза = DESIGN. Цель — извлечь идеи и понять, где мы сильнее/слабее, НЕ копировать.
> Сырьё — в `docs/council/raw/2026-06-24-competitors/`.

## Сквозной вывод одной фразой
**Наша модель стоит на редком пересечении C∩D** (темпоральный граф знаний ∩ файлы-как-истина, agent-first) —
почти никто это не совмещает. Ближайшие соседи частичны: каждый закрывает 1-2 наших свойства, никто — все четыре
(граф + файлы=истина + тонкий паспорт с эпистемикой + control-plane как узлы). Конкуренты дают **готовые словари и
UI-паттерны**, но ни один не задаёт нам новых обязательных полей паспорта.

## 1. understand-anything — что это и чему учит
- **Что:** инструмент онбординга в КОД — превращает репозиторий в интерактивный граф знаний (read-only). ~54.7k⭐,
  MIT, Lum1104 → Egonex-AI. Это НЕ «агрегатор жизни»; пересечение с нами — только архитектура данных.
- **Хранение:** один `knowledge-graph.json` (производный, одноразовый — потерял → пересобрал из кода). **Узел «толстый»**
  (summary/tags/complexity/domainMeta встроены). **Типы узлов/ребёр = TypeScript-enum** (21 узел / 35 ребёр).
- **Где они СЛАБЕЕ нас (валидирует наши решения):**
  - enum-типы → расширение только форком+редеплоем → подтверждает наш **control-plane как УЗЛЫ**.
  - толстый узел в одном JSON → нельзя читать метаданные без парса всего; git-конфликты → подтверждает **тонкий
    паспорт + файл-на-узел**.
  - граф read-only, агенты только строят, человек смотрит → наш «агенты читают И пишут, клапан на необратимое» — это
    другой, более амбициозный продукт.
  - нет epistemic/sensitivity/principal вообще.
- **Где у них есть чему поучиться (заимствовать):**
  1. **Таксономия ребёр** — 35 типов в 8 категориях + `direction` + **`weight(0..1)`** + `description`. Зрелый словарь
     семантики связей; `weight` (сила связи) у нас отсутствует — дешёвый полезный сигнал.
  2. **UI-паттерн вьюера:** `/`-фокус-поиска, `?`-модалка-справки, **Escape-каскад** (закрыть → назад к обзору), один
     источник истины для шорткатов (массив `{key,category,description,action}` → и биндинг, и справка; хук глушит ввод
     в полях кроме Esc), кросс-платформенный рендер ⌘/Ctrl.
  3. **Persona-adaptive view (junior/PM/power)** = ровно наш **LENS**, но у них захардкожен. Подтверждает ценность
     LENS — и что наш вариант (lens = узел) сильнее (пользователь добавит свою линзу).
  4. **Двухрежимный поиск Fuzzy + Semantic БЕЗ vector store** — их «semantic» = LLM-запрос к графу, не эмбеддинг-БД.
     Намёк: на старте смысловой поиск можно делать как агент-запрос, отложив векторы.
- **Что мы можем сделать ЛУЧШЕ их интерфейса (просьба владельца):**
  - **Навигация по графу с клавиатуры** — у них стрелки заняты под туры, «ходить по рёбрам» с клавиш нельзя (только
    мышь). Для agent-first вьюера: **j/k/стрелки по `home`/`facet` рёбрам + Cmd+K командная палитра** (прыжок к любому
    узлу/типу/линзе).
  - **Редактирование с клавиш** — у них всё read-only; у нас вьюер должен и создавать/менять узлы (с клапаном).

## 2. Память агента / память пользователя — как решают другие
Ключ: **мы уже сидим на пересечении «темпоральный граф (C)» ∩ «файлы-как-истина, agent-curated (D)»**, которое
почти никто не совмещает. 4 доминирующих паттерна в индустрии:

- **A. Vector-first fact store** (mem0, Cognee, OpenAI Memory, LangMem-default): LLM извлекает факты → эмбеддинг →
  similarity search; граф опционален; забывание = decay-эвристики.
- **B. Tiered / OS-память** (Letta/MemGPT, MemoryOS, Claude context editing): горячее-в-контексте / тёплое-по-запросу
  / холодный-архив + авто-миграция (вытеснение, heat-score, компакция). Ортогонально хранению.
- **C. Темпоральный граф знаний** (Zep/Graphiti): связный граф фактов с **bi-temporal валидностью**; забывание =
  **инвалидация ребра**, не удаление.
- **D. Файлы-как-истина, agent-curated** (Claude memory tool, Basic Memory): plain-md, агент читает/пишет,
  just-in-time чтение, человек и ИИ на одних файлах.

**Ближайшие соседи и наш отрыв:**
- *Basic Memory* (md+граф+файлы=истина, wikilinks) — но без эпистемики и без типизированных рёбер.
- *Claude memory tool* (файлы=истина, agent-first) — но плоский, без id-графа.
- **Наш отрыв** = тонкий паспорт (epistemic/sensitivity/principal) + типизированные рёбра (home/cascade/facet-of) +
  control-plane как узлы. Никто не даёт всё это вместе.

**Заимствования (ранжировано):**
1. **Bi-temporal инвалидация ребра** (Zep/Graphiti) — добавить «срок валидности факта» + «погасить ребро» вместо
   удаления. Идеально ложится на «всё видно ИИ, ничего не стирается». → кандидат в инвариант / ADR-0004.
2. **Just-in-time чтение + протокол сессии** (Claude memory tool): initializer → progress-log → end-of-session update.
   Тонкий паспорт для того и нужен — дёшево решить, какой узел открыть. Резонирует с нашей DECISIONS-LOG/компакт-тревогой.
3. **Heat-score важности** (MemoryOS) поверх рёбер — важность у нас статична на ребре; heat = динамическая эволюция.
4. **Self-editing + sleeptime-консолидация** (Letta) — агент сам чистит/консолидирует свои узлы-классы в простое.
5. **Таксономия semantic / episodic / procedural** (LangMem) как узлы-классы: procedural = prompt-узлы (есть),
   episodic = трейсы, semantic = факты.

## 3. Векторная БД — когда реально полезна
**Правило решения:**
- **ДА**, когда есть измеримый провал «не нашлось по смыслу»: NL-запрос не совпал со словами узла; нужен fuzzy/
  семантический recall, **кросс-язык** (ru-запрос ↔ en-термины в паспорте — реально для нас), near-dup дедуп,
  «похожие по смыслу», recall агента по перефразировке. Векторы выигрывают ⟺ совпадение нужно ПО СМЫСЛУ, не по
  строке/полю/связи.
- **НЕТ**, когда запрос точный: lookup по id/типу/тегу, фильтры по epistemic/sensitivity/source, обход рёбер
  (home/facet), любая «истина»/каскад, малый корпус, или где FTS/BM25 уже отвечает.
- **НИКОГДА:** вектор как источник истины / замена графу / дефолт с первого дня.

**Гибрид-с-графом (мейнстрим 2025):** граф = структура+истина; **вектор = ВТОРИЧНЫЙ семантический индекс ПОВЕРХ графа**,
эмбеддинги ключатся на `id`; слияние через Reciprocal Rank Fusion. Прямой аналог нашей идеи — Zep/Graphiti (semantic +
BM25 + обход графа + темпоральные окна). Бенчмарки: graph-over-vectors = +точность / −скорость (~3× на multi-hop);
hybrid GraphRAG = +8% factual correctness.

**Рекомендация для нас (файлы=истина, тонкий паспорт):**
- Вектор-индекс = **derived/secondary индекс в слое ДВИЖКА**, рядом с rollup/cache. Источник = файлы, ключ = `id`,
  паспорт НЕ заменяет. **Файлы-как-истина — это ПРЕИМУЩЕСТВО:** индекс полностью одноразовый и воспроизводимо
  пересобираемый из .md → снимает обычный страх vendor-lock / реиндекса.
- **Последовательность:** сначала **FTS/BM25** (sqlite-fts / ripgrep по frontmatter+payload). Векторы — ТОЛЬКО на
  доказанной боли (>~10-15% промахов keyword). Инструмент при необходимости: **sqlite-vec + sqlite-fts** (встроенный,
  local-first, zero-server, гибрид в одном файле БД) — в духе files-first. pgvector/LanceDB/dedicated = overkill сейчас.
- **Расходы заложить:** staleness (нужен watcher + content-hash при правке файла), пересборка при смене модели,
  приватность (sensitive-узлы НЕ эмбеддить в облако → локальный эмбеддер или исключение по sensitivity-метке — паспорт
  это уже поддерживает).

## 🟡 Развилки к владельцу (для будущих ADR, НЕ строим)
1. **Bi-temporal рёбра** (Zep): добавляем ли «срок валидности + инвалидация ребра вместо удаления»? → кандидат в
   инвариант или в ADR-0004 «Движок».
2. **Векторы:** принять принцип «вектор = derived-индекс в движке, FTS первым, векторы по доказанной боли»? И открытый
   под-вопрос: эмбеддить **тонкий паспорт** (дёшево, семантически беднее) или **payload** (богаче, дороже, упирается в
   sensitivity)? → вход в engine-spec.
3. **`weight(0..1)` на ребре** — заимствуем «силу связи» как поле ребра?
4. **Вьюер:** фиксируем ли как стандарт паттерн `/`+`?`+Escape-каскад + один источник шорткатов; и делаем ли наш
   дифференциатор — клавиатурная навигация по рёбрам (j/k, Cmd+K) + редактирование под клапаном?
5. **Протокол сессии агента** (Claude memory tool: initializer→progress-log→end-update) — оформляем как паттерн-узел?
