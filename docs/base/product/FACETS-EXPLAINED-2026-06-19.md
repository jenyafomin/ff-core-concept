# Грани ячейки — объяснение в обучающем формате

- **Status:** explainer (по просьбе владельца msg 198 — «прими позицию учителя, объясни каждый пункт»)
- **Date:** 2026-06-19
- **Контекст:** это ревизованный «тонкий паспорт» из `VERDICT-2026-06-19-facets-multicritic.md`.
  Грань = группа базовых ПОЛЕЙ, которые мы храним на КАЖДОЙ ячейке снаружи (ИИ читает, не вскрывая содержимое).

## 0. Что такое «грань» (рамка)
Грань — это группа полей-«маркировок» на конверте ячейки. Их немного и они ОДИНАКОВЫ для любой ячейки
(задача, человек, план). ИИ по ним навигирует и держит безопасность, **не открывая содержимое и не зная тип.**
Само содержимое (payload) — внутри, по правилам типа. Граней ~5; полей внутри них — чуть больше.

## 1. Identity — «кто это»
- **Поля:** `id` (уникальный неизменный адрес — как номер контейнера; по нему ссылаются другие ячейки, НИКОГДА
  не меняется), `type@version` (какого типа ячейка и версия её схемы; неймспейс тут же — напр. `garden/Plant`).
- **Зачем ИИ:** адресовать + понять, ПО КАКИМ правилам читать (тип = ключ интерпретации).
- **Альтернативы:** тип как код в движке — отвергли (новый тип = выкат кода). Версию схемы — в каждой ячейке
  vs в узле-типе (склонились: в ячейке указатель, правила — в узле-типе).
- ⚠️ **Сомнения:** «заголовок» (имя для человека) — в Identity или это уже минимальное содержимое? Критики:
  скорее содержимое, не паспорт. `id` и `тип` меняются с разной частотой (id никогда, тип — при миграции) → две под-оси.

## 2. Belonging — «где живёт»
- **Поля:** `home` (ОДИН владелец-родитель — одна полка для книги; по нему наследуется контекст и важность),
  `importance` (важность 1-5), возможно `principal` (чей арендатор).
- **Зачем ИИ:** понять контекст и приоритет ОДНОЗНАЧНО, не вскрывая («задача под Здоровьем, важность 4»).
- **Альтернативы:** мульти-родитель (несколько домов) — отвергли (неоднозначная важность/контекст). Решение:
  один дом + прочие принадлежности как обычные связи.
- ⚠️ **Сомнения:** важность — отдельная грань или под-поле дома? Сошлись: под-поле, но фиксировать ЯВНО (теряется).
  `principal` (арендатор) — слот здесь или в слое доступа? Открытый вопрос (C).

## 3. Temporal — «время»
- **Поля в ядре:** `created`/`updated` (когда создана/изменена — системное время, ставит движок),
  `stale`/свежесть (устарела ли — флаг/подсказка).
- **Зачем ИИ:** сортировать, понимать актуальность, не работать с протухшим.
- **НЕ в ядре (важно):** `occurred` (когда событие случилось в реальности), `valid_from/until` (срок истинности
  факта) — зависят от типа (у задачи дедлайн есть, у заметки нет) → в модуль. `supersedes` (что заменяет) — это
  связь → ребро, не время.
- **Альтернативы:** «битемпоральность» (3 времени как 3 оси) — критик предложил, потом снял: это разные ПОЛЯ
  одной грани, не три оси.
- ⚠️ **Сомнения:** «свежесть» — поле или вычисляет движок? Частично пересекается с `valid_until` (модуль).

## 4. Trust — «насколько верить и кому показывать» (ДВЕ оси)
- **Поля:** `epistemic` (факт / черновик-предложение / гипотеза — насколько ВЕРНО содержимое),
  `sensitivity` (приватно / для своих / можно делиться / публично — кому ПОКАЗЫВАТЬ).
- **Зачем ИИ:** сердце безопасности. Не принять черновик за факт; не показать приватное наружу — всё не вскрывая.
- **НЕ ось:** `valve` (клапан на внешнее необратимое действие) — это ПОЛИТИКА движка («если черновик → внешнее
  закрыто»), а не свойство ячейки. На ячейке максимум ручной override «я одобрил».
- **Альтернативы:** сначала Trust = epistemic + valve; критики развели: valve → политика, вместо него вошла sensitivity.
- ⚠️ **Сомнения:** нужен ли градиент уверенности (не только факт/черновик, а «70%»)? Отложили.

## 5. Provenance — «откуда пришло»
- **Поля в ядре:** `source` (источник: telegram / email / ручной ввод / такой-то агент).
- **Зачем ИИ:** источник влияет на доверие (надёжный сенсор vs черновик пользователя) и помогает не плодить дубли.
- **НЕ в ядре:** `actor` (кто именно создал) и `trace` (ссылка на лог действий ИИ) → наблюдаемость, живёт в движке/логах.
- **Альтернативы:** слить Provenance в Trust (оба про доверие) — не стали: «откуда» (факт) ≠ «насколько верить» (оценка).
- ⚠️ **Сомнения:** грань ужалась до одного поля `source` — возможно это под-поле Trust, а не отдельная грань. На грани слияния.

## 6. Relation — «связи» (спорная грань) + 3 открытых вопроса
- **A. Связи:** `home` (одна привилегированная связь) — точно в паспорте. Остальные типизированные связи
  (этот→тот + тип связи) — хранятся НА ячейке, но СБОРКА графа (обойти, найти кто ссылается на меня) — работа
  движка. «Связь на ячейке, граф собирает движок».
- **B. Дубликаты:** `canonical_id` («это та же сущность, что вон та») — скорее служебное поле движка, не «ось» для ИИ.
- **C. Арендатор** (`principal`, пользователь системы ≠ пользователь приложения) — тонкий слот в Belonging vs слой доступа.
- ⚠️ Это то, по чему ждём решение владельца (A/B/C; можно «как советуешь»).
