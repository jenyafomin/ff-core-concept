## 0. Главный вердикт (одной картиной)

**Паспорт здоров; вся T3 ложится на ДВИЖОК и control-plane с НУЛЁМ новых полей паспорта и НУЛЁМ новых полей ребра** (доказал архитектор §5; подтвердил критик §5 «что НЕ нашёл как проблему»). Стресс-тест назвал движок риском №1 — этот раунд **превратил «движок» из слова-корзины в контур контрактов**. НО критик вскрыл то, что синтез стресс-теста пропустил: **движок — не один модуль, а 3-4 подсистемы с РАЗНОЙ частотой изменения, и его изящество держится на ТРЁХ непроверенных допущениях** (транзакционность поверх md, безопасность холодного старта, граница клапана против агента-нарушителя). Эти три — не «отложить в движок», а **именованные дыры**, которые надо закрыть ДО «строй».

**Структурный стержень всего T3 (архитектор §0):** все границы движка = ОДИН паттерн — **«разделяй обход по СПИНЕ (home, ациклична, корректность каскада) и обход по ССЫЛКАМ (любой граф, корректность данных)»**. Это инвариант «принадлежность ⟂ ссылка» (И-2 ADR-0002), применённый к глубине, к терминатору и к вычислению линз. Кто слил два обхода в одну ручку — получил баг.

## 1. ЧТО ДОКАЗАНО / решено (пруфы, не «работает»)

Тройное согласие линз (аналитик предложил → архитектор разместил → критик не оспорил, §5):

1. **Split `maxDepth` → `cycle_guard` + `cascade_depth`** — РЕШЕНО (высокая уверенность, все три линзы).
   - `cycle_guard` (`visit_set`, «первый визит выигрывает») = терминатор обхода ПО ССЫЛКАМ (граф циклится → стоп по факту повтора, не по числу хопов). Внутренний инвариант движка, не настраивается данными.
   - `cascade_depth` (дефолт **unbounded**) = бюджет ПРОЕКЦИИ по home-спине (спина = лес, убежать не может; глубокий код = 6-8 home-хопов, единый `maxDepth=3` молча обрывал каскад sensitivity/scope — баг КОРРЕКТНОСТИ, не скорости). Это ручка показа, не безопасности.
   - **Пруф:** разделение мотивировано данными dogfood (`project→packages→core→src→node.ts` уже 4 хопа) — единый потолок ломал реальный каскад.

2. **Терминатор ПАТТЕРНА = enum `prune | mark-cycle`** — РЕШЕНО (заполнение существующего слота ADR-0002 §4, 0 нового).
   - `prune` (дефолт каскада): повтор отбрасывается без следа — нужно ОДНО унаследованное значение.
   - `mark-cycle` (данные/рендер): повтор эмитится как маркер обратного ребра — инструмент «покажи граф вызовов / круговые импорты» обязан ПОКАЗАТЬ цикл, а first-visit-wins его молча СПРЯЧЕТ.
   - **Инвариант (архитектор §2.2, критично):** enforce-классы (hard-ABAC, каскад, клапан, promotion) **принудительно `prune`**; свободный выбор — только у read/soft-perception паттернов. Движок отклоняет регистрацию hard-ABAC-паттерна с `mark-cycle` (иначе недетерминированный каскад в enforce-пути).

3. **`level` ≠ `centrality` — две разные линзы над двумя классами рёбер, НИКОГДА не сливать** — РЕШЕНО (высокая).
   - `level` (зум/абстракция) считается по СПИНЕ принадлежности/уточнения (`home`/`refines`/`grounds`, ациклична).
   - `centrality` (важность/нагрузка) считается по фан-ину ССЫЛОК (`called-by`/`depends-on`, циклится).
   - **Третий, ручной носитель — `priority` на ребре** (N-041, ставит человек). **Три ортогональных понятия важности**, ни одно не выводится из другого: ручная `priority` (ребро) · вычисленная `centrality` (линза по ссылкам) · зум `level` (линза по спине). Ядровая утилита «глубокая но центральная» — не противоречие, а два корректных ответа.

4. **Backlink-index (обратная карта `{target→[source,rel]}`)** — ДОКАЗАНО как обязательный (аналитик §1.1, критик согласен §5). Без него «кто ссылается на X» = O(N-файлов) скан; **блокирует клапан v1** (нужен быстрый обратный поиск «прямо задействованных нод»). Эфемерная производная, ребилд с нуля за O(E).

5. **Правило стоимости «что достойно узла»** — ДОКАЗАНО структурно (3 условия, критик §5 не оспаривает структуру): вещь = узел ⟺ (a) стабильный id при правках + (b) свой осмысленный home + (c) ценность как единица запроса. Следствие: строки кода / call-sites / транзитивные зависимости = **НЕ узлы**; функции = **ленивые производные**; сообщения/коммиты = **stream-записи**. (Пограничный случай функции-с-ULID — открыт, см. §3 CC-4.)

6. **Индекс = эфемерная производная, файлы = истина** (архитектор §4.1) — снимает половину рисков консистентности: рассинхрон индекса не теряет данные, только требует ребилда.

## 2. ЧТО ЧИНИТЬ и ГДЕ ЖИВЁТ (карта размещения)

Дисциплина тонкого паспорта удержана: **Δ паспорта = 0, Δ ребра = 0** по всем пунктам ниже, КРОМЕ одного честно-помеченного роста (`seq`, см. ⚠️).

| Что | Где живёт | Δ паспорт | Δ ребро | Статус |
|---|---|---|---|---|
| `cycle_guard` (терминатор по ссылкам) | ДВИЖОК (внутренний инвариант обхода) | 0 | 0 | решено |
| `cascade_depth` (бюджет проекции по спине) | ДВИЖОК + контракт ПАТТЕРН (заменяет `maxDepth`) | 0 | 0 | решено |
| enum `prune \| mark-cycle` + енфорс `prune` для hard-ABAC | CONTROL-PLANE (ПАТТЕРН) + ДВИЖОК (инвариант регистрации) | 0 | 0 | решено |
| `level`-линза ≠ `centrality`-линза | ДВИЖОК (2 примитива: ярус-по-спине, фан-ин-по-ссылкам) + CONTROL-PLANE (2 ЛИНЗА-узла) | 0 | 0 | решено + **1 строка R0 в ADR-0002 §1** |
| backlink-rollup фан-ина (`{count, paged}`) | ДВИЖОК (производное) | 0 | 0 | решено как обязательство |
| home-spine section-index (`count/tail_seq/диапазон/member_ids`) | ДВИЖОК (производное) | 0 | 0 | решено как обязательство |
| abstract-by-name rollup потоков (N-043) | ДВИЖОК + stream-модуль (ПАТТЕРН `compose(поток)→абстракт`) | 0 | 0 | контур; форма абстракта — по типу потока |
| derived-cache invalidation (граф зависимостей pull-инвалидации) | ДВИЖОК (правило инвалидации) | 0 | 0 | контур; полнота графа — открыта (CC-2) |
| **`seq` на ребре** (порядок ≠ важность: шаг-3 не «важнее» шага-2) | **РЕБРО** | 0 | **⚠️ +1 поле** | стресс §2A; в ADR-0002 НЕ зафиксирован → нужна явная фиксация (критик §4) |
| 3 инварианта движка (I-A клапан-самоодобрение · I-B derived read-only · I-C `schema`=единственный ключ валидатора · I-D контейнер home≠категория) | ДВИЖОК (enforcement) | 0 | 0 | записать явно (молчание = баг) |

**Честный рост (отмечаю по дисциплине):** единственное расширение поверхности данных за весь T3 — **`seq` на ребре** (из стресс-теста §2A, для последовательностей коммитов/сообщений/шагов плана, где `priority` перегружен порядком). Это **+1 опциональное поле ребра**, не паспорта. Всё остальное — обязательства движка и заполнение существующих слотов.

## 3. ОТКРЫТЫЕ ВОПРОСЫ

### 3.1 🔴 ВЛАДЕЛЬЦУ (архитектурные/безопасность — не делегируемы агенту)

**OQ-1 (КРИТИЧНО) — Как достигается транзакционность при «файлы=истина»?** *(критик C-2/QC-2)*
md-файлы не транзакционны, но клапан, re-home и section-index опираются на «в той же транзакции». Многофайловые операции (удалить home-A → перевесить на B → обновить index = 3 файла) при сбое оставляют сироту/phantom-ребро/состояние-без-аудита. Варианты: (а) WAL поверх md; (б) **«тонкие данные (паспорт+рёбра+индекс) в SQLite — транзакционно; тело в md — читаемый архив»**. Вариант (б) потенциально ПЕРЕОПРЕДЕЛЯЕТ принцип «файлы=истина» ADR-0001/0002 → решение владельца, не техника.

**OQ-2 (КРИТИЧНО) — Клапан v1: движок строит список задействованных нод САМ или принимает от агента?** *(критик C-3/QC-3)*
Если от агента — агент-нарушитель просто не цитирует опасный узел, и клапан его не видит (приватная метрика, на которую ссылается сообщение, утекает). Это разница между «защита от ОШИБОК» и «защита от ЗЛОНАМЕРЕННОГО агента». Если v1 защищает только от ошибок — **зафиксировать это явно**, чтобы не создавать ложного ощущения безопасности до ADR-0003. Security-позиция, не деталь.

**OQ-3 — Безопасность холодного старта.** *(критик CC-1)*
Backlink-index нужен клапану; ребилд при старте = O(E) (минуты на GitHub-масштабе). Клапан недоступен/работает-без-гарантий во время прогрева — а агент может стартовать вместе с системой и сразу действовать вовне. **Флаг владельцу: «система небезопасна в момент холодного старта»** — нужно решение (блокировать внешние действия до окончания прогрева?).

**OQ-4 — Нужен ли отдельный ADR-0004 «Движок»?** *(критик P-1/QC-4)*
ADR-0002 = паспорт-слой (фронтенд, детально). Движок = бэкенд, сейчас = список обязанностей. Транзакционность + enforcement + индексирование = архитектурные решения с последствиями (хранилище, порядок старта, зависимости подсистем). Без ADR они «откладываются в реализацию» и порождают противоречия. (Контр-аргумент: сначала стресс-тест движка, потом ADR.)

**OQ-5 — Терминатор ПАТТЕРНА по умолчанию + dual-role home+facet (Q3/N-086).** *(аналитик Q3/Q4)*
Дефолт `prune` прячет реальные циклы / `mark-cycle` раздувает ответ — затрагивает UX агентов. И: dual-role (узел одновременно home и категория) — движок ЗАПРЕЩАЕТ на записи или предупреждает? Жёсткий запрет проще для инвариантов, но бьёт по любимому сценарию владельца «проект-как-папка, которая и группирует, и классифицирует» (N-074). Завязано на консилиум Q3 (N-086).

### 3.2 🟡 АГЕНТАМ (реализационные пороги/границы — дизайн-раунд)

- **EQ-A — «Движок» как архитектурная единица:** декомпозировать на (a) горячая дорожка чтения/запроса · (b) транзакционный enforcer (write+инварианты) · (c) индекс-слой · (d) холодный реестр типов — **разные частоты изменения**. *(критик C-1/QC-1)*
- **EQ-B — Контракт глаголов движка** (8 глаголов, STATE N-054): какие синхронные/асинхронные, какие требуют транзакцию, какие читают индекс. Без этого «движок» = слово. *(критик C-1)*
- **EQ-C — Пороги rollup/индекса: пер-механизм, не единый.** Backlink-rollup триггерится по ФАН-ИНУ (~500), section-index — по ШИРИНЕ контейнера (~2000), общий индекс — по числу узлов (~300, STATE). Единый порог прост, но неверен. *(аналитик Q1/Q5, архитектор EQ-6)*
- **EQ-D — Lazy vs eager пересчёт `level?`-дефолта при смене TYPE-узла.** Предложение: lazy. НО критик (CC-3): маркер `level?_stale:true` — это **новое техническое поле, которого нет в паспорте** → скрытое расширение через чёрный ход, нарушает «тонкий паспорт». Решить, где живёт маркер согласованности (агрегат типа, не узел). *(аналитик Q2, критик CC-3)*
- **EQ-E — Полнота графа инвалидации:** таблица аналитика пропускает смену `sensitivity` (кэш решений клапана?), смену `promotion-policy` (ретроактивно ли? — старые `fact` остаются?), смену ЛИНЗЫ (каскадный сброс кэшей проекций?). *(критик CC-2)*
- **EQ-F — `centrality` жадно или по запросу?** Дешёвый вариант = `called-by count` из backlink-rollup; дорогой = настоящая betweenness (глобальная метрика). Не строить граф-аналитик раньше времени. *(архитектор EQ-4)*
- **EQ-G — `cycle_guard` на home-спине: тихо стоп или ОШИБКА целостности?** Повтор визита на спине = нарушение инварианта «home=лес». Рекоменд.: **поднимать ошибку** (как 2+ home), не тихий prune — иначе баг данных невидим. *(архитектор EQ-2, рекоменд. зафиксировать сейчас)*
- **EQ-H — Гранулярность «агент не одобряет сам себя»: principal или agent-id?** Если на уровне principal=owner — инвариант тривиален (любой агент owner'а одобряет любого), слабее лестницы «verifier≠автор» ADR-0002 §3. При мульти-агентном совете (синтезатор одобряет критика) — один principal? Уточнить. *(критик P-3/QC-5)*
- **EQ-I — Граница «узел vs производная» для функции с системным ULID.** Если движок присвоил стабильный id — функция по правилу (a) становится УЗЛОМ с протухшим состоянием, а не «ленивой производной». Уточнить: id выдаётся системой ДО первого изменения ⇒ функция≠узел; либо граница задаётся политикой ТИПА, не общим правилом. *(критик CC-4)*

## 4. МИНИМАЛЬНЫЕ СЛЕДУЮЩИЕ ШАГИ (дизайн, без «строй»)

Порядок мотивирован: сначала закрыть три CRITICAL-дыры (они блокируют безопасность), потом конкретизировать контракты.

1. **Решение владельца по OQ-1/OQ-2/OQ-3** (транзакционность · граница клапана · холодный старт) — это три не-делегируемые развилки; от OQ-1 зависит природа «файлы=истина».
2. **Записать 4 инварианта движка** (I-A…I-D) + **EQ-G** (ошибка на цикле спины) — 0 нового, молчание = баг.
3. **Зафиксировать `seq` на ребре** (единственный честный +1) — уточнением ADR-0002 §РЕБРО или в своде Stage 4.
4. **Решить про ADR-0004 «Движок» (OQ-4)** — если да, он держит: декомпозицию EQ-A, контракт глаголов EQ-B, транзакционную модель OQ-1, границу клапана OQ-2, 4 механизма индекса/rollup/кэша как контракты.
5. **Внести 1 строку R0 в ADR-0002 §1** (`level`≠`centrality`, граница линзы) — **в своде Stage 4**, а не ad-hoc правкой approved-документа (EQ-5/архитектор).
6. **Делегировать агентам EQ-C…EQ-I** (пороги, полнота инвалидации, гранулярность) — дизайн-раунд по движку.
7. *(Вне рамок T3, флаг)* **Реактивность/реактор** — кэш-инвалидация §4.2 = PULL (пересчёт по запросу), НЕ push/реактор. Не путать. Реактивность = #1 отсутствующий КЛАСС, ждёт D1/topic-4 + ADR-0003.

## 5. Сухой остаток для STATE / DECISIONS-LOG

- **T3 РЕШИЛ 6 пунктов** (split maxDepth · enum терминатора · level≠centrality · backlink-index обязателен · правило-стоимости · индекс=эфемерная-производная) — все на ДВИЖКЕ/control-plane, **0 полей паспорта**.
- **Единственный честный рост:** `seq` на ребре (+1 опц. поле ребра).
- **Движок ВСКРЫЛ 3 CRITICAL** (транзакционность поверх md · граница клапана против агента-нарушителя · холодный старт) — **владельцу, не агенту**; от первого зависит «файлы=истина».
- **Кандидат — ADR-0004 «Движок»** (бэкенд-слой): декомпозиция 4 подсистем + контракт глаголов + транзакционная модель + клапан-граница + индекс/rollup/кэш-контракты.
- **Дисциплина удержана:** сложность ушла в движок/control-plane; паспорт не растолстел. Изящество **по-прежнему условно** на движке — но теперь движок описуем контурно, и контур виден.
