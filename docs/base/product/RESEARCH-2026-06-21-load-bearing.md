## 0. TL;DR
1. **Несущее ядро подтвердилось и НЕ выросло.** Ни один из ~40 худших сценариев не потребовал нового
   ОБЯЗАТЕЛЬНОГО поля на ноде. Сильный сигнал: тонкий паспорт верен.
2. **Инвариант несущести (общий у абстракта и архитектора):** *поле несущее ⟺ по нему ИИ/движок принимает
   решение, как обращаться с ячейкой, НЕ вскрывая payload и НЕ зная тип.* Это стоп-правило против раздувания.
   Абстрактно — 4 первичные операции по паспорту: **сослаться · разместить · довериться · датировать.**
3. **Важность-на-ребре (N-041) верна — но вернула ДРУГУЮ проблему: слияние КОНТЕКСТА при мультиродителе**
   (не важности). Это главный новый риск. Решается, но решить надо ДО кода.
4. **Структурный рычаг:** «вектор наблюдения / уровень абстракции / авто-связи / зум огромных секций /
   паттерны-рекурсия» — это **ОДИН механизм: ЛИНЗА (проекция подграфа через предикат)**. Не пять подсистем,
   не поля ноды. → control-plane = **три рода узлов: тип · линза · паттерн**.
5. **Самый острый блокер — не структура, а ДОВЕРИЕ:** не определено, *кто* имеет право поднять `epistemic`
   до `fact`, и клапан внешних действий не реализован. Без этого «контролируемая система» = декларация.

## 2. ГЛАВНЫЙ НОВЫЙ РИСК — мультиродитель вернул слияние контекста (3 линзы независимо)

N-041 («важность на ребре») снял неоднозначность *важности*. Но **не снял неоднозначность КОНТЕКСТА/КАСКАДА**:
- **Глобальный запрос ослеп (критик, блокер).** «Что делать прямо сейчас?» — базовый запрос агента. При
  важности per-parent у одной ноды N разных приоритетов. Нет правила агрегации → нет ответа.
- **Слияние при мульти-контексте (архитектор #4, критик #2).** Нода в «Проект Alpha» (prio 1) и «Бэклог»
  (prio 10). Дейли-агент смотрит оба. Какой контекст/важность каскадит? Не определено.
- **re-home / сирота (архитектор #10, критик #4).** Какой из N родителей «настоящий дом»? Что при удалении одного?

**Решение (совпало у архитектора и критика, и это ровно старая модель N-020):**
**ровно ОДИН привилегированный `home`-edge = дефолтный каскад/контекст; остальные родители — opt-in каскады с
явным порядком; глобальные запросы важности либо запрещены без контекста, либо имеют явный алгоритм агрегации.**
→ Важность-на-ребре (владелец) и один-привилегированный-home (N-020) **НЕ противоречат — они складываются.**

## 3. Три напоминания владельца (N-045) — вердикт

**(1) Уровень абстракции (почему/что/как/data) — ГЛАВНЫЙ СПОР 3:1.**
- *Аналитик (за поле):* в 3 сценариях ломается принцип «не вскрывать payload»; нужно поле `level: why|how|what|data`.
- *Абстракт/архитектор/критик (против поля):* это **отношение наблюдатель→нода, не свойство ноды** — один и тот
  же узел «почему» для CEO и «как» для разработчика. Поле = ложная точность, будет заполняться непоследовательно.
  Правильно: **ось ЛИНЗЫ** (второе семейство зума рядом с уровнями в `levels.ts`) / опц. тег-подсказка / параметр запроса.
- **Срединное (рекоменд.):** уровень абстракции **реален и нужен как ИЗМЕРЕНИЕ ЛИНЗЫ**, не как обязательное поле
  паспорта. Ячейка может нести *опциональный* тег-подсказку (`level?`), но истина — в проекции, которую строит агент.
  → **это решение за владельцем** (он измерение и поднял).

**(2) Статус «черновик/набросок» — это ось `epistemic`, не новое поле (консенсус).**
Уточнения: критик — главная дыра не дублирование, а «кто авторизован менять epistemic до fact» (см. §4). Аналитик —
человеческий черновик ≠ предложение агента; предлагает добавить значение **`draft`** в enum
(`draft | proposal | hypothesis | fact | archived`). Абстракт — пометить как кандидата на расщепление
`epistemic`⟂`maturity`, если потечёт. **Рекоменд.:** одна ось + добавить значение `draft`.

**(3) Вектор наблюдения — отдельно, и это ЛИНЗА, а НЕ поле ноды (единогласно).**
Все 4: поле ноды → God-object. Вектор = **сохранённая линза/проекция = узел control-plane** (предикат + политика
раскрытия id/заголовок/payload + класс: право-hard-ABAC vs перцепция-soft). Важность сортирует ВНУТРИ проекции;
линза ВЫБИРАЕТ проекцию — разные слои. Паспорт лишь даёт ОСИ фильтрации (тип, epistemic, время, sensitivity, home).
**Нужны 2 документа раздельно:** (а) «поля-инструменты вектора» в паспорте; (б) «контракт запроса с viewport» в движке.

## 4. Реальные блокеры до кода (отделены от страшилок)

1. **Кто авторизует `epistemic=fact` + клапан внешних действий не реализован.** Если агент сам поднимает до
   факта — клапан открыт на любое необратимое действие по самооценке. Назван «первым к закрытию» ещё в ADR-0001. **#1.**
2. **Глобальная важность / правило слияния контекста при мультиродителе** (§2). Без него агент-планировщик не строится.
3. **Метка `derived` на авто-рёбрах + контракт «ручные рёбра=файл, авто=движок».** Иначе (а) ИИ видит свои догадки
   как факты; (б) «файлы=истина» расщепляется с кэшем движка. Нарушает принцип наблюдаемости «видно, что делает ИИ».
4. **`maxDepth`/гард циклов в коде** — рекурсия/паттерны/авто-рёбра при мультиродителе взорвут обход.
5. **`section-index`-конвенция** для огромных секций (чат/архив) — точки входа по имени/источнику.
6. **Типизировать `source`** (human/agent/system) — иначе epistemic-доверие формально.
7. **Тонкий `principal`** — multi-tenant и маркетплейс заблокированы без него (критик: это несущее, не «спор C» 2:2).

## 5. Структурный рычаг (абстракт) — три рода control-plane
Симметрия, покрывающая 5 из 10 «непокрытых» сценариев и прямо ложащаяся на просьбы владельца («простая ячейка →
много возможностей», «паттерны к моделям», «дизайн-паттерны»):
- **ТИП** — как вскрыть ОДНУ ячейку (схема payload, валидация).
- **ЛИНЗА** — как найти/спроецировать ПОДГРАФ (вектор наблюдения, уровень абстракции, авто-связи, зум секций).
- **ПАТТЕРН** — как СОБРАТЬ подграф из многих (декоратор/композиция + терминатор рекурсии).
Все три = узлы графа (Принцип 0). Один движок проекций вместо пяти подсистем.
