# Рантайм агентов: как программно управлять Claude Code

- **Status:** draft (reference)
- **Owner:** jenya.stasik@gmail.com

- **Related:** [IDEA-agent-context-budget](../ideas/IDEA-agent-context-budget.md), [AGENT-WORKSPACES](AGENT-WORKSPACES.md), [CHAT-HIERARCHY-AND-CONTEXT](CHAT-HIERARCHY-AND-CONTEXT.md)
- **Источник:** исследование claude-code-guide по актуальной документации (см. ссылки внизу). Детали по биллингу/ToS и лимитам ПЕРЕПРОВЕРИТЬ по текущим докам перед тем, как на них закладываться.

## Вопрос владельца
Как построить инструмент, который программно управляет Claude Code: сам создаёт новые сессии,
к которым можно подключиться как к отдельному чату и читать сообщения; как обходить ограничения;
какими инструментами/библиотеками; и как реализовать модель «один чат — 5 агентов, общий контекст,
агенты пишут друг другу».

---

## 1. Чем управлять — инструменты
- **Claude Agent SDK** (TypeScript и Python) — встраивает агентный цикл Claude Code в твой процесс.
  TS: `npm i @anthropic-ai/claude-agent-sdk`, точка входа `query({ prompt, options })`, читаешь
  поток через `for await (const message of query(...))`. **TS-версия ложится прямо в наш монорепо.**
- **Headless CLI** — `claude -p "..." --output-format stream-json --verbose` — выдаёт построчный
  JSON событий в реальном времени; `--resume <id>` продолжает сессию; `--output-format json` даёт
  `session_id`, `result` и `total_cost_usd`.

## 2. Сессии и чтение сообщений
- **Создать сессию** = вызвать `query()` / `claude -p`; из init-события берёшь `session_id`.
- **Продолжить** = `options.resume = session_id` (SDK) или `--resume <id>` (CLI).
- **Читать как отдельный чат:** три способа —
  1. стрим `--output-format stream-json` (пайпишь в свой UI);
  2. **транскрипт-файлы** `~/.claude/projects/<project>/<session-id>.jsonl` — можно `tail -f`
     в реальном времени (одна строка = одно событие);
  3. для Managed Agents — серверный стрим событий (`/v1/sessions/{id}/events/stream`).
- **Hooks** (PostToolUse и т.п.) — детерминированные колбэки вне ИИ-цикла; можно дёргать твой
  дашборд при каждом действии агента.

## 3. ⚠️ Главный нюанс — подписка vs API (честно)
Это и есть ответ на «как обходить ограничения»: **не обходить, а выбрать правильный режим.**

| | Подписка (OAuth, Pro/Max) | API-ключ |
|---|---|---|
| Аутентификация | `claude login` | `ANTHROPIC_API_KEY=sk-ant-…` |
| Интерактивный Claude Code | входит в подписку | — |
| Программная автоматизация (SDK, `-p`, оркестратор) | **не предназначена**; упирается в лимиты; с 15 июня 2026 — отдельный месячный Agent-SDK-кредит, биллится по API-ценам | да, явно для этого |
| Устойчивый мульти-агентный рантайм по ToS | **нет** (подписка — для человека) | **да** |
| Лимиты | пользовательские, не под параллельных агентов | организационные, выше, масштабируются |

**Вывод:** для настоящего рантайма (оркестратор, который постоянно крутит несколько агентов)
— **использовать API-ключ**, а не подписку. Подписка — для человека в интерактиве; API — для
автоматизации. Не строить «хитрые обходы» лимитов подписки: это против условий и ненадёжно.
*(С 15.06.2026 у подписок появился отдельный Agent-SDK-кредит — но это для лёгких скриптов, не
для постоянного оркестратора. Перепроверить актуальные цифры/условия по докам.)*

## 4. «5 агентов в одном чате, общий контекст, общаются друг с другом» — три паттерна
- **A. Субагенты через Agent-tool** (одна сессия). Общий контекст, один «начальник» делегирует;
  агенты НЕ говорят свободно друг с другом. **Это ровно то, что я уже делаю в советах.** 🟢 просто.
- **B. Несколько параллельных сессий + внешний оркестратор** (твой код брокерит сообщения между
  ними). Настоящая параллельность, изолированные контексты, ты сам передаёшь «а ты сделал X?».
  🟡 больше логики, максимум контроля.
- **C. Managed Agents API** (координатор + агенты в песочнице Anthropic). **Нативно: агенты сами
  пишут друг другу** (события `agent.thread_message_received`), до ~25 параллельных тредов. Ближе
  всего к твоей модели «равноправные агенты общаются». Требует API-ключ. 🔴 мощно, но сложнее и платно.

Истинно «равноправный круглый стол» = Pattern C (или B со структурой раундов). «Начальник
делегирует» = Pattern A. Это разные вещи (мы это уже отмечали в CHAT-HIERARCHY §3).

## 5. Кирпичи для нашего оркестратора
- **`@anthropic-ai/claude-agent-sdk`** (TS) — спавнить агентов из нашего монорепо.
- **`@anthropic-ai/sdk`** (TS) — Managed Agents API, если нужен нативный мульти-агент.
- **Конкурентность:** `p-limit` / `Promise.all` (TS) — держать N агентов параллельно (≈ наша идея
  «пул по бюджету»).
- **Общий контекст/состояние:** выставить наш **`@ff/core` граф как MCP-сервер** — тогда все агенты
  читают/пишут один граф. Это и есть «общий контекст» + «граф = память».
- **Учёт затрат:** `--output-format json` → `total_cost_usd` на вызов; Usage & Cost API на уровне
  организации. → закрывает задачу [[task_cost_accounting_research]] (путь известен).
- **Наблюдаемость:** `tail -f` транскриптов `*.jsonl` или стрим событий → наш фронтенд-«офис».

## 6. Как это ложится на наш проект
1. **Субстрат уже есть:** `@ff/core` (граф). Выставить его MCP-сервером = общий контекст для агентов.
2. **Рантайм:** TS-оркестратор на Agent SDK (Pattern B) поверх API-ключа; позже — Managed Agents (C)
   для нативного «агенты говорят друг с другом».
3. **Наблюдение/чат:** читать `stream-json`/транскрипты → наш Electron-фронтенд показывает «офис».
4. **Биллинг:** API-ключ для автоматизации; подписка остаётся для твоей ручной работы в Claude Code.
5. Это и есть та «единственная трудная инфраструктура» (автономия+персистентность+интеграция) —
   теперь у неё есть конкретные инструменты и честная цена.

## 7. Слой ПОВЕРХ подписки пользователя (observe + augment) — новый поворот

Идея владельца: не мы гоняем агентов через API, а **сам пользователь запускает Claude Code под
своей подпиской**, а наш сервис — слой сверху: настраивает агентов, «прослушивает» сессии и
помогает управлять контекстом/топиками. Разбор по ToS-границе (по докам):

### Что ЧИСТО (subscription-OK)
- **Пассивная «прослушка» своих сессий** — читать транскрипты `~/.claude/projects/<project>/<id>.jsonl`
  (`tail -f`, одна строка = событие). Это твои локальные файлы, нарушения нет. Лаг — пара секунд.
- **Наблюдательные хуки** — `PostCompact`, `SessionStart/End`, `Stop`, `PostToolUse` могут логировать
  и дёргать твой скрипт/дашборд. Енфорсмент (запрещать плохие действия) — ок.
- **Поставлять конфигурацию** — `.claude/` (skills, agents/субагенты, MCP в `.mcp.json`, CLAUDE.md,
  permissions, енфорсмент-хуки). Пользователь запускает под своей подпиской, сам вызывает.
  **Это поддерживаемая Anthropic модель** «augment, не replace». Самый чистый продуктовый путь.
- **Advise-петля** — твой UI читает транскрипт и СОВЕТУЕТ («контекст наполняется — нажми /compact»,
  «этот топик исчерпан — переключиться?»), человек кликает. Чисто.

### Что НЕ чисто / упирается в API
- **Автономно ДЕЙСТВОВАТЬ на интерактивной сессии** (сам триггерить `/compact` на 65%, авто-сменять
  топики, инжектить ввод) — **нельзя**: внешний процесс не может «вводить» в интерактивную сессию
  (нет stdin/PTY-захвата; и это было бы автоматизацией). Хук, который АВТОНОМНО рулит сессией, уже
  на грани «программирования сессии». Для реальной автоматизации → SDK/`-p` = API-биллинг.
- **Нет чистого машинного «% контекста».** `/context` рисует визуальную сетку, не JSON; официального
  флага «контекст на 65%» нет. Порог 40–65% придётся мерить эвристикой (размер транскрипта как
  прокси) — это хрупко. Честная оговорка.

### Хуки жизненного цикла контекста
- `PreCompact` — может **заблокировать** компакт, но НЕ видит разговор (нельзя «умно» решить).
- `PostCompact` — после компакта; может запустить твой скрипт, который читает транскрипт и сохраняет
  кастомное резюме в файл (≈ «компакт → резюме → новый топик»). Минус: срабатывает уже ПОСЛЕ.
- `SessionStart` — инжектить контекст при resume. `UserPromptSubmit`/`Stop` — модификация на грани.

### Топики = сессии
Встроенного понятия «топик» внутри сессии НЕТ. Топик = отдельная **сессия** (`--session-id`/`-n имя`/
`--resume`). «Переключиться на другой топик» = `--resume <другая сессия>` (текущая закрывается).
Параллельные топики = worktrees. Инструмент: листает `~/.claude/projects/<project>/`, мониторит
каждый транскрипт, помогает навигировать/переключать; человек запускает resume.

### Продуктовый вывод (честный)
- **Чистая модель = «дистрибутив конфигурации + компаньон-наблюдатель + советник»**, НЕ демон.
  Поставляем `.claude/` (агенты/скилы/MCP/контекст/енфорсмент-хуки) → пользователь запускает под
  своей подпиской → наш слой читает транскрипты и СОВЕТУЕТ по контексту/топикам (человек в петле).
- **Автоматическая чистка контекста и оркестрация** на чистой подписке **не получаются** — это
  либо advisory (человек кликает), либо API (SDK/`-p`, отдельный кредит).
- Это снимает страх владельца «их агенты эффективнее моего сервиса»: мы НЕ заменяем их Claude Code,
  а делаем его управляемым (агенты, контекст-гигиена, топики, «офис»). Их мощная подписка — нам в плюс.

## 8. Решающая развилка для продукта
- **Если продукт для ДРУГИХ людей с их подписками** → путь §7: конфиг + наблюдатель + советник
  (чисто, без нашего биллинга, но управление контекстом — advisory, не авто).
- **Если рантайм для СЕБЯ / полная автономия** → §3–6: API-ключ + Agent SDK/Managed Agents.
- Можно совместить: ядро-конфиг (§7) для людей + опциональный API-режим (§3) для тех, кому нужна
  настоящая автономия. Но не выдавать API-автоматизацию за «работу на подписке».
