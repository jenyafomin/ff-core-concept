# Предложение: «шаг-0» в виток concept-first (O-11)

> ⚠️ **НЕ применено к скиллу.** Правка скилла = R1, идёт через `agent-builder` **после одобрения
> владельца** (правило doc-discipline: «себя молча не переписываешь»). Здесь — только предложенный диф
> + снятие риска дубля с воронкой L0.

## Проблема (O-11)
Виток concept-first сейчас стартует с шага 1 «Цель одной фразой» → сразу «Развернуть вопросы». На
практике вопросы **повисают без якоря**: непонятно, какую ЦЕННОСТЬ/НАПРАВЛЕНИЕ они обслуживают, и
рождается веер вопросов «вообще про идею», а не «про эту ценность».

## Предложенный шаг-0 (вставить перед «Цель одной фразой»)
> **Шаг-0. Якорь на ценность/направление.** Прежде чем разворачивать вопросы — назови, какую
> **ЦЕННОСТЬ** (или направление из лестницы `value-decomposition`) двигает этот виток. Вопросы витка
> растут ИЗ этого якоря, а не из идеи вообще. Нет ясной ценности → первый вопрос витка = «какой
> ценности это служит?» (тип `open-question`, приоритет 1).

## 🔴 Снятие риска дубля (обязательная оговорка)
Проект уже несёт воронку **L0 Цель/Боль → L1 → … → L5** (`CLAUDE.md`) и воронку топика-56
(`ЦЕЛЬ → ЦЕННОСТИ → КОНЦЕПТ → ИДЕИ → ИНФРА`). Шаг-0 **НЕ вводит третью воронку** — он **ссылается**:
- Шаг-0 = вход в существующую воронку (L0→ценность), а не её копия.
- Формулировка в скилле должна прямо сказать: «якорь берётся из L0/ценностей проекта (см. CLAUDE.md),
  concept-first их не переопределяет, а навешивает рекурсию вопросов поверх».
- Иначе получаем два конкурирующих описания одного L0 → рассинхрон (ровно боль, которую лечим).

## Что решает владелец
1. Принять шаг-0 в таком виде (со ссылкой на L0, без новой воронки)? да/нет/правка.
2. Если да → передать `agent-builder` для вшивания в `~/.claude/skills/concept-first/SKILL.md` (R1).
