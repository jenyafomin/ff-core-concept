# Механизм 2 — Управление агентами через топики + уровни ответа

## Простое описание (без техники)
Один бот подключает НЕСКОЛЬКО агентов в один Telegram-топик, чтобы владелец получал **команду специалистов
в одной рабочей комнате**, а не бегал по отдельным чатам. У каждого агента задаются независимо две вещи:
**КОГДА ему вообще дают слово** (всегда слушает / молчит, пока не позовут по нику-команде / всегда молчит) и
**ГОВОРИТ ЛИ он вслух в чат, когда слово получил** (отвечает открыто / отчитывается тихо в фоне / вообще
ничего не пишет наружу) — путать эти две вещи и есть источник старой путаницы. Поверх этого **сразу, а не
потом**, нужны правила: кто отвечает первым, если несколько агентов могли ответить одновременно (арбитраж);
может ли ответ одного агента разбудить другого (межагентный триггер) и как это не превратить в бесконечную
перекличку; и отдельно — что **куратор** (главный агент над всеми) сам, своими руками, создаёт новые темы,
чистит контекст каждого подчинённого и настраивает их, не дожидаясь владельца. Всё это разрешено включать на
автопилоте только вместе со стражем (AI Guard) — без него автоматизация становится бесконтрольной автономией.

## Ключевые ценности (ранжировано)
1. **Одна рабочая комната вместо разбегания по чатам.** Сегодняшняя боль — переключение между сессиями за
   разными «руками»; несколько агентов в одном топике убирают беготню.
2. **Тишина по умолчанию — экономия ВНИМАНИЯ, не только токенов.** «Молчит, пока не позовут» защищает от
   хора из пяти мнений там, где нужен один ответ; мерило — сколько текста владелец готов прочитать.
3. **Предсказуемость «кто ответит» + арбитраж — уже в первом срезе.** Как только в топике два «всегда
   отвечает»-агента (или общий @ник), хаос без правила «кто главный» возникает сразу.
4. **Куратор — самостоятельный принципал со своими правами, а не «тоже агент».** Сам заводит темы, чистит
   контекст, настраивает подчинённых без владельца как узкого места. Это отдельная ось (управление
   сессиями/контекстом), а не часть таблицы «кто говорит».
5. **Отчётность — осознанный выбор владельца, а не спам.** Кто докладывает в чат, кто работает тихо; отчёт
   в чужой топик — отдельное действие со своим лимитом частоты, иначе отчётность сама станет шумом.
6. **AI Guard — обязательное условие включения автоподтверждения, не декоративная безопасность.** Без стража
   «уровни ответа» + автоподтверждение = автономия без присмотра.

## Поведения / уровни (концептуально)
- **Уровень получения слова (когда дают ход):** всегда слушает и реагирует / молчит, пока не позовут по
  нику-команде / никогда не получает ход.
- **Уровень права говорить вслух (получив ход):** отвечает открыто в чат / делает тихо и не пишет наружу /
  полностью нем.
- **Арбитраж одновременного ответа:** отвечают все / отвечает один заранее назначенный / «всегда отвечающий»
  отвечает лишь когда его тоже явно назвали.
- **Ограничитель цепной реакции (hop-бюджет):** у сообщения-триггера есть счётчик пройденных шагов
  агент→агент; после предела цепочка обязана остановиться.
- **Права куратора:** создавать темы сам, чистить/настраивать контекст каждого подчинённого по отдельности,
  управлять сессиями без обращения к владельцу.
- **Автоподтверждение на срок** (окно) повышается по накопленным подтверждениям; необратимое-вовне — никогда.
- **AI Guard** включается только для неочевидных команд; явно безопасное проходит мгновенно, опасное — к человеку.

## Нельзя упустить
- **Hop-бюджет нужен СРАЗУ**, а не «в последнюю очередь» — два «всегда отвечает»-агента уже создают риск
  бесконечной переклички. (В одном из разборов это ошибочно отложено — это расхождение, не факт.)
- **Арбитраж одновременных ответов — условие первого шага**, хаос виден уже при двух агентах.
- **«Всегда молчит» двусмысленно:** либо ход вообще не дают, либо ход дают, но без права говорить вслух
  (думает и работает тихо) — это два разных состояния, нельзя сливать в одну галочку.
- **Управление сессиями/контекстом куратором — отдельная забота**, легко потерять, свернув всё в табличку
  уровней ответа.
- **AI Guard — единая точка отказа:** уязвим к перегрузке пограничными командами и к атаке, растянутой на
  серию по отдельности безобидных шагов; «при неуверенности блокировать» не спасает от текста, специально
  созданного дать ложную высокую уверенность.
- **Отчёт в чужой топик — отдельное действие со своим лимитом частоты.**
- **Предусловие включения автоподтверждения:** механизм, который при неясности сегодня молча пропускает
  действие, исправить ДО первого окна автопилота.
- **Риск «двух домов истины»** для таблицы разрешений (копия в шлюзе vs канон в памяти) — единый источник
  правды с первого дня, а не «синхронизируем потом».

## Развилки владельцу
- Первый шаг: «молчит-до-вызова» (дёшево, но ценно лишь при втором агенте) или автоподтверждение+страж
  (боль «сейчас», дороже/рискованнее без готового стража)?
- Арбитраж — правило целого топика («здесь отвечает один») или свойство каждого агента (свой приоритет)?
- Отчётность — простой переключатель на старте или сразу слойные правила (агент/топик/группа)?
- Управление сессиями куратором — часть этого механизма или отдельная 4-я тема?
- Один страж на всё сейчас — принимаем риск горлышка как временный компромисс или сразу закладываем деление
  проверки по критичности?
