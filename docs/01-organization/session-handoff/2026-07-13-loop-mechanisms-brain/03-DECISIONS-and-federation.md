# 🧩 РЕШЕНИЯ ВЛАДЕЛЬЦА (2026-07-13) + новая развилка «федерация сущностей»

> Владелец ответил голосом на 2 вопроса из HANDOFF и поднял новую несущую проблему. Зафиксировано дословно по смыслу.

## ✅ Ответ на Q1 — ручная правка md-узлов
**НЕТ, сам руками обычно не редактирует — правка идёт через агента.**
→ **Следствие для дизайна:** `edit-capture`-событие (легализация ручной правки файла) **НЕ входит в P0** первого движка.
НО событийный фундамент (C1) обязан уметь принять его позже без ретрофита — оставляем «дырку под событие», не строим сам механизм.

## ✅ Ответ на Q2 — плагины: свои → мультитенант
**Сначала СВОИ плагины, потом ТОЧНО мультитенант — как marketplace.**
Модель маркетплейса (слова владельца): плагин можно просто подключить — «скачать свой фронт», а к базе данных
**чётко подключить все нужные связи/подключения». → **Следствие для дизайна:**
- Физический enforcement READ-стен (C4) — **НЕ P0** (пока плагины свои). Но `grant`/`scope`/namespacing типов — **заложить СЕЙЧАС** (P0-схема), иначе ретрофит дорог.
- «Фронт отдельно, БД-связи чётко» = подтверждение курса: плагин = фронт + декларация нужных узлов/рёбер, которые он видит/пишет.

## 🔴 НОВАЯ РАЗВИЛКА — федерация сущностей между плагинами (owner raise)
Дословный смысл: в системе будут **дополнительные типы, НЕ одинаковые** у разных плагинов. Пример владельца:
> «Кто-то в одной системе создал юзеров, другой тоже юзер — как они между собой будут взаимодействовать технически?
> Это разные юзеры, потенциально одинаковые. Можем их делать через адаптеры или ещё что-то. Пойдём подумать.»

**Ядро проблемы:** два независимо-авторских плагина каждый вводит свой тип (напр. `user`). Технически это РАЗНЫЕ узлы,
но семантически могут быть ОДНИМ реальным субъектом. Как:
1. регистрировать пересекающиеся/конфликтующие типы в общем реестре (M-G3), не ломая друг друга;
2. решать «этот `user` плагина A = тот `user` плагина B» (тождество через границы плагинов, ось M-G5 `canonicalId`);
3. дать взаимодействие между ними — через **адаптеры**, общий канонический профиль, или маппинг-рёбра.

Это задача СЛЕДУЮЩЕГО раунда размышления (аналитик→Fable). Результат — отдельными файлами в этой же папке.
