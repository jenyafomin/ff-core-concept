# CAPTURE-2 2026-07-10 — управление темами/агентами + rich-message

> Сырьё голосового заброса. Владелец: «этого много ключевого, ты часто выпускаешь → запусти
> 1-2 агента на детальный разбор, чтобы ты понял». Здесь — точки, чтобы ничего не потерять.

## Правки-фидбек
- **Правило отчётности — я понял НЕ так.** Владелец пришлёт **реальный путь-пример**, на который
  надо посмотреть. Суть: у отчётов нужна **чёткая ПОСЛЕДОВАТЕЛЬНАЯ структура** — можно пройти по
  порядку и явно увидеть, что было сделано; навигация по папкам (улучшить позже). → ЖДУ ПУТЬ.

## Rich-message (раз уже реализовано — довести до канона)
- **RM-1:** ВСЕ сообщения рендерить через rich (grammY / HTML).
- **RM-2:** агенты пишут в документы → скрипт **шлёт файл целиком** одним сообщением.
- **RM-3:** добавлять **МОДЕЛЬ** (кто писал) в сообщение/отчёт.
- **RM-4:** продумать, что именно **копируется**: пути — НЕ по отдельности; использовать
  **code/monospace** на каждый ряд → лучше копируется.
- **RM-5 · BUG (чинить первым):** владелец **НЕ ВИДИТ жирность**. Bold не доходит. Вероятно md
  `**` → HTML `<b>` не конвертится в egress (или клиент). Первый фикс.

## Управление темами/агентами (ГЛАВНОЕ · «можно сделать очень быстро»)
- **TM-1 · Один УНИВЕРСАЛЬНЫЙ механизм жизненного цикла темы:** закрытие темы = ВСЕГДА сохранение.
  Из новой темы можно быстро `resume` существующую. Закрыл → новая начинается в любом случае.
- **TM-2 · `new`** = полностью новая тема (текущую закрыть/сохранить). Может быть кнопка «новая тема»
  (пока пустая, наполнить позже).
- **TM-3 · `resume` / переключение тем** — более понятный механизм переключения между сохранёнными.
- **TM-4 · handoff + сразу новая тема** — сохранить что есть, начать заново; опционально **явно
  связать контекст** перехода (новая тема несёт часть контекста старой).
- **TM-5 · Имя темы:** при закрытии спрашивает — оставить текущее / ввести новое / **отдать агенту**
  (сам придумает) → 3-4 варианта (+ «назад»). ← это UI на кнопках (rich message!).
- **TM-6 · Смена РОЛИ/ЛИЧНОСТИ агента:** есть личности-агенты (запрограммированы, вели сессии,
  закреплены за топиком). Реплицируем/запускаем личность в сервисе; у неё свой **личный промт** +
  **доп. промт топика** (рекомендации) + доп. слои → **многослойный контекст**. Сменить личность =
  как сменить тему (тот же принцип: new / resume).
- **TM-7 · Управление агентом (явно протестировать):** агент сам может поставить нового
  «пользователя»-агента в топик; управляться из чата (General / любого); создавать топики и
  управлять ими.
- **TM-8 · Всё в чёткую БД:** кто / по какому вопросу / когда / о чём беседы; ссылки на план(ы)
  (глобальный и др.), к чему относится; какие темы **ждут вопросов/ответов** (финал). «По-моему
  что-то уже есть» — но нужен **явный контроль и запись**. NB: «темы ждут вопросов» финально решит
  ПАМЯТЬ (позже) — сейчас только упомянуть; скоро делаем требования через агентов.
- **TM-9 · Центральное звено** управляет разными агентами; у каждого свои настройки; отчитываются
  в чат или нет; собираем разного рода информацию.

## TM-10 · Автоподтверждение команд / автономный режим (КРИТИЧНО, «на заметку»)
Владелец: хочу дать задачу, уйти спать и быть уверен, что через час она выполнена — без ручных
нажатий (забываю жать approve). Нужно автоподтверждение команд — через отдельного агента ИЛИ
другой механизм, но с проверками, чтобы команды не были опасными.

**Ключевой принцип (уже в конституции проекта):** «клапан доверия — только на внешние
НЕОБРАТИМЫЕ действия». → авто-ДА для обратимого/безопасного, жёсткий гейт для необратимого/внешнего
ДАЖЕ когда владелец спит.

**Набросок механизма (гибрид, дёшево→гибко):**
1. Детерминированный allowlist/denylist (hook, без токенов): безопасные обратимые операции → авто-yes;
   необратимые/внешние (push --force, rm, деплой, трата денег, внешняя отправка, смена доступов) →
   всегда гейт/стоп.
2. Неоднозначное → дешёвый агент-судья классифицирует «опасно/безопасно» (можно обмануть → только
   поверх детерминированного слоя, не вместо).
3. Гардрейлы автономного прогона: cost-cap, time-cap, «всё логируется и видно, что делал» (эпистемпринцип),
   стоп по превышению.

**Связи:** approval-gate уже есть в коде (governance-gate callback); loop-prompting/HITL (I-11 / CAPTURE.md);
клапан доверия (глобальная память). **Это изменение модели прав/безопасности → нужен ADR перед стройкой**
(docs-standard: смена auth/permission = ADR; риск-класс R3). Не делать blanket `--dangerously-skip-permissions`.
