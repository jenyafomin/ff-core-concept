# Конвенция нумерации папок — короткая рекомендация

## 1. Правило (одна формулировка)
Любая **именованная папка-узел** получает порядковый префикс (`01-`, `02-`…) в момент создания —
по очереди, в которой тема встала в обсуждение (не заранее продуманная финальная схема); при
пересборке («форма проступила») номера/имена перенумеровываются под новую структуру. Это ровно
формализация уже принятого П2 (`growth-and-sequencing/INDEX.md`) как обязательной нормы для
**всех** папок, а не только для «растущих». Исключение: **универсальные контейнеры во
множественном числе** (`analyses/ questions/ ideas/ plans/ states/`) номера не получают — они не
узел темы, а типовая корзина; но файлы **внутри** них по-прежнему нумеруются той же
последовательной логикой (пример: этот файл — `analyses/01-numbering.md`).

## 2. Неизвестная папка → доска в `INDEX.md`, не `rules/`
Выбор: **не заводить подпапку `rules/`.** Это имя уже занято в реестре типов-разделов —
`rules-and-skills/` означает место под `.claude/rules` (обязательные системные ограничения), другой
смысл; переиспользование создало бы коллизию терминов. Вместо этого: папка без известного типа
**обязана иметь `INDEX.md`** (уже требуется П1 для абстракций) с верхним блоком-доской из 3 строк:
`Концепт` (по какому направлению/гипотезе растёт) · `Ожидаемый тип` (если предполагаем, во что
скристаллизуется — `values/scenarios/decisions/...` из реестра, либо «пока неизвестно») ·
`Проверка зрелости` (что должно случиться, чтобы папка переехала в типизированную структуру).
Доска живёт в уже обязательном файле — не плодит новую сущность.

## 3. Как это подхватывает `concept-first`
Разводка ролей не меняется, только фиксируется: `concept-first` сигналит **момент** («путь найден» /
«пора переструктурировать», см. SKILL.md критерии), но механику файлов/папок/имён отдаёт
doc-discipline (уже прописано в SKILL.md, строки 67, 78–82). Практически: пока направление в
`concept.json` имеет статус `exploring` — папки под него можно не заводить (работа живёт в
навигаторе); как только концепт получает `path` (папку) — она уже подчиняется правилу №1 (номер по
очереди) и правилу №2 (доска в `INDEX.md`, если тип ещё не устоялся). Кристаллизация вопроса в файл
(маппинг типов concept.json → типы doc-discipline) не меняется этим правилом.

## 4. Риски
- **Гонка номеров** — при параллельной работе нескольких агентов/сессий два новых направления могут
  одновременно взять один и тот же следующий номер (нет единого счётчика). Митигировать вручную:
  проверять `ls` родителя перед созданием, конфликт решает сравнение дат.
- **Номер по очереди ≠ смысловой номер** — до пересборки последовательность обсуждения не отражает
  логическую связь тем (риск навигационной путаницы между сессиями). Приемлемо по правилу владельца
  («со временем перестроится»), но требует, чтобы пересборка реально случалась, а не откладывалась
  бесконечно — иначе накопится «мусорная» нумерация без логики.
