## 1. Суть в 5 строк

Три реорга — не ошибки раскладки, а плата за то, что СМЫСЛ закодирован в ПУТИ: перенос файла рвёт ссылки, индексы и память, поэтому каждая правка структуры = большая операция руками.
Закон роста = маленькая порождающая грамматика: реестр типов + монотонный локальный рост (добавить / расщепить на месте) + supersede вместо удаления + стабильные id вместо путей.
Стоп-критерий: структура «достаточна», когда новый документ ложится без единого решения (тип известен ⇒ путь вычислим); N документов подряд без переносов ⇒ freeze.
Глобализовать — грамматику (указателем), никогда — дерево. Это превращает R4-правку в R1-R2.
Ключевой рефрейм: дерево доков — первый живой экземпляр субстрата brain; закон роста доков = жизненный цикл единицы памяти (тип · связи · supersede). Один закон на оба.

## 2. Настоящая проблема (переформулировка)

- **A. Идентичность привязана к адресу.** Ссылки/индексы/MEMORY.md указывают путями. Любая перестановка = каскад битых указателей (дрейф brain-ссылок — уже симптом). Пока так — ЛЮБАЯ раскладка «дорогая», и копится до следующего big-bang.
- **B. Нет различия «скелет vs интерьер».** Каждый реорг переигрывал всё, включая стабильное. Нужен минимальный неизменяемый скелет (2 оси + реестр типов) и порождаемый правилами интерьер.

Следствие: анти-цель «чтобы 4-го реорга не было» в абсолюте вредна (ведёт к пере-дизайну — «death by design»). Правильно: **реорг перестаёт быть событием** — переносы дешёвые, локальные, не рвут ссылки.

## 3. По приоритетам

### P1 — Закон роста + стоп-критерий
5 правил грамматики (закрытый список):
1. **Тип ⇒ место.** Тип из реестра ⇒ путь вычислим без решения человека. Нет типа → dated-поток + вопрос в doc-discipline/open-questions.
2. **Рост монотонный и локальный.** Можно: добавить ребёнка; расщепить узел на месте (файл→папка+INDEX). Нельзя: перенос между родителями без tombstone-редиректа.
3. **Идентичность = id, не путь.** `id:` во frontmatter; ссылки по id (путь — подсказка). Резолвер id→путь: сперва grep, позже скрипт. Единственное правило, делающее переносы бесплатными.
4. **Ничего не умирает.** Только supersede/archived + ссылка на сменщика.
5. **Скелет заморожен.** Корней ≤5. Шестой корень / перенос узла уровня 1-2 — только через ADR.

**Стоп-критерий (freeze):** раздел → `Status: frozen`, когда 20-30 доков подряд (или 14 дней) легли по правилу 1 без переносов и новых корней. После freeze структурные правки только через ADR; add-child и split-in-place свободны. Разморозка — ADR. Позыв «хочу переставить» = баг-репорт против грамматики (строка в open-questions), не действие над папками.

### P2 — Граница universal / domain / project
| Слой | Что |
|---|---|
| Universal | 5 правил грамматики · «финал=файл, абстракция=папка+INDEX» · frontmatter-контракт (Status/Owner/Date/Scope/Related/id) · supersede · «вход=docs/INDEX.md» · 2 оси КАК/ЧТО |
| Domain | шаблоны типов (values, scenarios, decisions, open-questions, todo, plan) — ПОСЛЕ обкатки на dwizh (2+ проекта) |
| Project (FF) | core/{brain,agents,contract} · substrate · содержимое values · 03-projects |

Не-навязывание: universal задаёт только инварианты, НИКОГДА не перечисляет разделы. Проект подписывается явно — `grammar: v1` во frontmatter своего docs/INDEX.md. Без декларации — живёт по-старому.

### P3 — Саморост правил (версии N-003)
- Правило = папка: `<rule>/INDEX.md` + `v1.md`, `v2.md`… INDEX: `current: v2` + changelog.
- Frontmatter версии: `Status: draft|active|superseded`, `Supersedes: <id>`. Инвариант: ровно одна active.
- Агент: создаёт → всегда draft; находит → по id через INDEX; выбирает → единственную active (две active = ошибка целостности).
- Гейт по evolution.md: уточнение/пример = append (R0-R1, агент сам); смена смысла = новая версия, активирует владелец (R2+).
- Читать по умолчанию только active (экономия контекста).

### P4 — Безопасная R4-правка ~/.claude/CLAUDE.md
Сделать так, чтобы правка перестала быть R4:
1. Грамматика в `~/.claude/rules/docs-grammar/` (папка-правило, v1). Глобальный CLAUDE.md = +5-10 строк указатель + 3-строчный дайджест (агенты не всегда ходят по ссылкам).

## 4. Ранжированные идеи (идея · зачем · риск) — топ-14
1. **Стабильные id + ссылки по id + tombstone.** Переносы = не-события. Риск: полудисциплина хуже отсутствия — нужен чекер.
2. **Глобализация указателем, не деревом.** R4→R1-R2. Риск: агенты игнорят указатель → инлайн-дайджест.
3. **Freeze-протокол со счётчиком.** Объективный «стоп». Риск: преждевременный freeze → дешёвая разморозка через ADR.
4. **«Позыв к реоргу = баг против грамматики».** Энергия недовольства → в правило. Риск: копится backlog → ревью раз в 2 недели.
5. **Локально-монотонный рост (add/split-in-place only).** Физически исключает дрейф «brain переехал». Риск: копятся tombstone → сборка мусора при freeze.
6. **Линт-хук целостности** (frontmatter · одна active · INDEX перечисляет детей · нет висячих id). Дрейф ловит машина. Риск: тулинг в фазе дизайна → один скрипт ~100 строк.
7. **Гейт версий: агент драфтит, владелец активирует (кроме R0-R1).** Саморост без фонового переписывания канона. Риск: владелец-горлышко → авто-активация уточнений.
8. **Догфуд: дерево доков = первый экземпляр brain-субстрата.** Один закон вместо двух дисциплин. Риск: связать с недопроектированным brain → брать только id/тип/supersede.
9. **dwizh = второй проект-доказательство ДО глобального дефолта.** Выполняет правило промоции. Риск: задержка 1-2 недели — ок при указателе.
10. **N-005 как lookup, не конвенция.** «имя⇒тип⇒дети» работает только через файл-реестр, который агент обязан открыть. Риск: реестр-монолит → расщепить при freeze.
11. **Дата-поток ≠ дом.** N-004 (номера по дате) = append-only ЛОГ со ссылками; дом документа = типовое место. Иначе дата-папки = вторые topics/. Риск: двойная запись → лог держит только ссылку.
12. **Генерируемые виды (NAVIGATION, сводные INDEX) из frontmatter скриптом.** Вид не дрейфует — перегенерируется. Риск: преждевременно до движка → этап 2.
13. **Кап корня ≤5 + ширина 7±2 на узел** (число для N-006). Превышение = триггер расщепления. Риск: механика вместо смысла → сигнал, не догма.
14. **Явный pull-list из архивов** как todo. Риск: не дойдут руки — ок (N-002); критичны только ADR-0001/0002 и активный план из topics/30-plan.

## 5. Самокритика замысла (где план владельца хрупок)
1. **N-001 противоречит конституции владельца** (промоция → 2+ проекта, approval, rollback). Тот же импульс, что породил 3 реорга. Указатель закрывает мотив без нарушения.
2. **Анти-цель как абсолют** толкает к пере-дизайну. Реорг №4 будет — вопрос, big-bang руками или дешёвый локальный.
3. **N-004 vs N-006 скрытый конфликт:** дата-нумерация плодит плоские потоки (это устройство sn-того topics/), анти-разрастание требует группировать. Нужна разводка «лог vs дом» (идея 11).
4. **N-003 без гейта опасен:** инфляция правил + рост контекст-бюджета. Нужны draft-гейт и «читать только active».
5. **Мета-дрейф заложен:** правила структуры в 3 местах (~/.claude/rules, project CLAUDE.md, docs/01-organization/doc-discipline), ни одно не авторитетно. Нужна иерархия «docs-grammar (universal) > doc-discipline (project-экземпляр)».
6. **Дрейф ссылок — не мелочь, а доказательство** отсутствия правила идентичности (случился через день после реорга №3). Чинить адреса руками бессмысленно, пока ссылки = пути. Сначала правило id, потом починка.
