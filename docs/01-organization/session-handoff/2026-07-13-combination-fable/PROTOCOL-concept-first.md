# Протокол «concept-first» — как агенты документируют работу

- **Status:** draft (кандидат в проектное правило; при успехе → global rule по промоушену POS) · Date: 2026-07-13
- **Scope:** пока Project (FF + Combination). Источник: голосовое владельца 2026-07-13.
- **Related:** `~/.claude/CLAUDE.md` («Артефакты важнее чата»), session-logging SKILL, рефрейм msg141 (файл = тип узла).

## Правило (три пункта владельца)
1. **Всё конспектируется в файлы.** Каждый значимый артефакт/файл имеет конспект (что это, зачем, суть).
   Ничего важного не остаётся только в чате.
2. **Каждый агент сам документирует свою работу.** Закончив задачу, агент ПИШЕТ В ФАЙЛ **концепт** того,
   что сделал (в своей сессии/папке), а не только возвращает текст. Оркестратор не пересобирает это за него.
3. **Общаемся концептами, не отчётами.** В Telegram/чат — короткий концепт (суть + развилка + что нужно),
   а НЕ полный дамп. Полнота живёт в файлах; чат = указатель на файлы.

## Тип артефакта (метка «немного другая ценность»)
В frontmatter каждого артефакта — поле **`Type:`** (эпистемическая ценность, метка, не стена):
- `concept` — синтез/понимание (наша выжатая мысль). Высшая ценность для чтения.
- `raw` — сырой вывод агента (первичный материал, из него растёт concept).
- `file` — внешний/исходный файл или вложение (ценность = «источник», не наша мысль). ← «приставка файл».
- `report` — отчёт о проделанном (что сделал агент).
- `decision` / `question` — решение (ADR/лог) / открытый вопрос.

Правило именования (мягкое): сырьё агента — `raw/` или `CONCEPT-<agent>.md` рядом; исходные файлы —
префикс/тег `file:` в имени или `Type: file`, чтобы сразу было видно «это источник, не вывод».

## Как это применяется (петля одного агента)
1. Агент делает работу.
2. Агент пишет **свой** файл: `Type: report`/`raw` + короткий `concept` наверху («что сделал, к чему пришёл»).
3. Оркестратор из набора концептов делает **синтез** (`Type: concept`) и в чат отдаёт только его выжимку.
4. Развилки/вопросы — отдельными `Type: question`; решения — `Type: decision`.

## Почему (связь с дизайном Combination)
Это не только гигиена — это **провенанс** (слепое пятно В): «каждый агент штампует, что он сделал». Концепт
агента = узел-провенанс. То есть протокол = ранняя, ручная версия модуля M4 (Provenance & Certification).

## Перелинковка концептов (концепт-в-концепте) — запрос владельца 2026-07-13
Многоуровневая связь между концептами делается как мини-граф (ручной прототип субстрата Brain):
1. **`id:` в frontmatter** у каждого артефакта — короткий стабильный идентификатор.
2. **`links:` — типизированные рёбра** к другим id. Словарь рёбер (как в диалог-графе проекта):
   `grounds · refines · answers · raises · tension-with · synthesizes · supersedes`. Строка: `edge → id`.
3. **REGISTRY-файл** в сессии (`concepts/REGISTRY.md`) — таблица `id → путь → links`. Резолвит id в путь;
   обход графа = следовать рёбрам транзитивно (так и получается «концепт в концепте», многоуровнево).
4. Когда узлов >~20 — под-графы/неймспейсы. Автобэклинки и резолвер id→путь кодом — потом (= модуль M1
   Registry в «Combination»; провенанс = M4). Сегодня руками, завтра движком.
