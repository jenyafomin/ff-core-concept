# Выживший разрез — синтез Fable × critic (то, что пережило обе линзы)

- **Status:** active (синтез; вход в scaffold проекта «Combination») · Date: 2026-07-13
- Входы: `FABLE-VERDICT.md`, критика (critic), `VALUES-diverge-BA.md`.

## Принцип отбора
Оставляем тезис Fable, если он пережил атаку critic. «Трещит» → берём с ОБЯЗАТЕЛЬНОЙ правкой. «Падает» →
заменяем формулировкой, признающей возражение. Всё несогласие сохраняем как открытые вопросы, не стираем.

## Костяк, который держится (с правками)

### S1. Kernel ≠ module — ДА, с bootstrap- и kernel-upgrade протоколом
- **Держится:** отделить неудаляемое ядро (движок субстрата + Конституция + реестр типов + шина портов +
  integrity) от сменных модулей. Снимает главную циркулярность.
- **Правка (critic):** kernel НЕ «свободен от словаря» — он несёт **seed-словарь** (`Module, Manifest,
  Version, Type, LineageEdge, Port`), само-регистрируемый при инициализации (bootstrap-протокол, как
  компилятор компилирует себя). Явно описать.
- **Правка (critic):** нужен **kernel-upgrade протокол** — это ЕДИНСТВЕННОЕ место, где допустима настоящая
  миграция субстрата (смена canonical_id-алгоритма, формата bitemporal). Отдельная ось «kernel-ABI версия»,
  редкое governed-событие, НЕ через INSERT-not-migrate. → **ADR-C0 «Kernel, seed-словарь, апгрейд ядра».**

### S2. Модуль = манифест-гражданин — ДА, но совместимость ДВУХВОРОТНАЯ
- **Держится:** 8-частный манифест (идентичность+lineage · 2-осевая версия · словарь · порты · политики ·
  зависимости · поверхность · custody). Код — сменный адаптер. Модель: Postgres extension.
- **Правка (critic):** «код не участвует в совместимости» — СЛИШКОМ сильно. Совместимость = **два гейта:**
  (1) **словарь** (форма, статически — пересечение по версиям); (2) **поведенческий контракт** (семантика
  портов: at-least-once vs exactly-once, идемпотентность, побочки — объявляется в манифесте + проверяется
  contract-тестами). Аналогия с PG-extension рвётся именно на поведении портов — признать.
- **Правка (critic):** **линза обязана объявлять тотальность.** Нетотальная линза (нет поля во `@1`, нужного
  во `@2`) НЕ фабрикует тихо — помечает поле как `derived/low-confidence` (эпистемический статус Brain) или
  явный null-контракт. Никаких молчаливых домыслов (удар по Тождеству/Доверию).

### S3. Один субстрат истины + scratch — ДА как ЦЕЛЬ, с cutover и синхронной erase
- **Держится:** один логический субстрат истины; приватный scratch легален (перестраиваем + erase-hook).
  Граница по семантике данных: `jobs/queue/seen_updates` = scratch; `sessions/agents/bindings` = истина.
- **Правка (critic, важно):** «федерации НЕТ» — ложно СЕЙЧАС. Сегодня по факту федерация (SQLite шлюза +
  несуществующий граф). «Один субстрат» — ЦЕЛЬ, не факт. Нужен явный **cutover-план** (шаги, откат,
  критерии) и правило: **рабочий шлюз НЕ замораживаем/НЕ переписываем ради недостроенного Brain.** Переезд
  инкрементальный, через мост-адаптер. → **ADR-C6 «Cutover: федерация сейчас → субстрат потом».**
- **Правка (critic):** erase scratch **синхронизируется с истиной** — hook пишет на truth-сторону
  событие-факт («job aborted/erased»), не оставляет session в подвешенном «в процессе». Аудит инцидента
  (ср. баг dup-kill) сохраняется append-событием, даже если payload стёрт.

### S4. Апгрейд = линза, форк = lineage — ДА, с бюджетом стоимости и порядком линз
- **Держится:** апгрейд — линзы поверх нетронутой истории (schema-on-read/upcasting); форк = новый
  module_id + lineage-ребро + унаследованные типы; совместимость по словарю; Конституция = пол.
- **Правка (critic):** **цепочки линз дороги** на большом графе. Разрешить **материализованный кэш**
  апгрейженного вида — НО кэш = **scratch** (перестраиваем + erase-reachable). Так производительность
  примиряется с hard-erase (закрывает слепое пятно А самого Fable). Плюс периодическая **компакция**
  (governed сворачивание цепочки в новую канон-версию).
- **Правка (critic):** **порядок/конфликт линз при мульти-lineage** (узел унаследовал два предка) —
  определить: либо явный порядок применения, либо запрет мульти-lineage без явной merge-политики.

### S5. Combination = контракт + сертификация — ПАДАЛО, чиню
- **Падает как «движка нет вообще»:** conformance-suite физически требует рантайм + **sandbox** (чужой код
  marketplace). Либо это исполняет ядро Brain (циркулярность), либо Combination поднимает свой sandbox — и
  это и есть «третий движок».
- **Новая формулировка:** Combination владеет **контрактом + тестами совместимости + ТОНКИМ, честно
  признанным sandbox-рантаймом сертификации.** Скоуп рантайма строго = ГЕЙТ (проверить манифест, прогнать
  contract-тесты, изолировать чужой код), **НЕ данные, НЕ бизнес-логика, НЕ хранение.** Не «второй движок
  данных», но и не «чистые доки». Реестр-как-узлы по-прежнему живёт в ядре Brain (dogfooding), Combination
  только выдаёт «сертификат».
- **Правка (critic):** у Combination **своя governance-версия** — правила гейтов эволюционируют; нужна
  политика ре-сертификации уже одобренных модулей (не ретроактивный молчаливый провал). → **ADR-C4**.

### S6. Слепые пятна — расширенный список (Fable A/Б/В + critic)
- **A. Hard-erase против копий/кэшей линз** (Fable) → кэш = scratch, erase-reachable (см. S4).
- **Б. Ontology commons** (Fable): ядерный **core-словарь** (десяток базовых типов, владеет kernel, меняется
  как Конституция) + **неймспейсы модулей** + рёбра-маппинги. Иначе два «Task» балканизируют граф.
- **В. Provenance утверждений** (Fable): штамп `module@version` на каждой записи. Ретрофит невозможен.
- **NEW-1 (critic). Безопасность чужого кода** — крупнейшее упущение. Манифест доказывает авторство, не
  безопасность поведения. Нужна **capability/sandbox-модель** исполнения чужих линз/адаптеров против общего
  субстрата с PII. → ценность CV5, инфра-модуль Sandbox/Capability.
- **NEW-2 (critic). PII/право на забвение vs INSERT-not-migrate** — шире слепого пятна А: стирание САМИХ
  truth-узлов конфликтует с «никогда не переписывать». Разрешается через Brain hard-erase = единственное
  санкционированное физическое удаление (остаётся tombstone). Явно связать.
- **NEW-3 (critic). Мультитенантность** — чей граф модифицирует модуль, изоляция данных пользователей на
  одном субстрате. Пока владелец единственный автор — отложить, но зафиксировать (CV4/CV6).
- **NEW-4 (critic). Канал обновления форка** — lineage статичен; если предок чинит баг в `Task@1`, форк не
  узнаёт. Опциональная подписка «upstream-patch notification». (CV3.)
- **NEW-5 (critic). Uninstall/осиротевшие узлы** — при INSERT-not-migrate узлы модуля почти-вечны;
  «съёмность» модуля vs почти-вечность хранения. Деинсталляция → tombstone/quarantine, не молчаливое
  сохранение. → инфра-модуль Lifecycle/Uninstall.

## Практический guardrail (critic, жёстко)
Brain НЕ построен, шлюз построен и работает. **Не морозить и не переписывать рабочий шлюз ради чистоты
недостроенного Brain.** Combination сейчас = **проектный/контрактный трек** (docs + ADR + эталонный манифест
«Плана»), а не стройка. Первый боевой ход: **написать манифест «Плана» на бумаге и прогнать через него
шлюз** — где манифест затрещит, там настоящий ADR (совет Fable, подтверждён).
