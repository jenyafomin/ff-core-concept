# NEXT-01 · Представление концептов — прототип понимания (НЕ стройка)

> Дизайна тут почти нет: фиксируем ПОНИМАНИЕ структуры. Два экрана + два режима. Реализацию — потом.

## Боль (из PRB-02)
Сейчас концепты сыплются текстом в чат: нельзя скопировать, нет удобного полного пути, длинные имена файлов
не годятся для списка. Нужна нормальная навигация.

## Модель прототипа: ДВА ЭКРАНА (связаны)
1. **Экран КНОПОК** — список ~8–9 пунктов. Каждый = **короткий title** (не длинное имя файла!) + номер.
   Над списком — расшифровка по номерам (1,2,3… что это), чтобы читать номера и понимать файл, даже если
   имена похожи.
2. **Экран КОНТЕНТА** — показывает выбранный концепт (текст).
   Нажал кнопку на экране 1 → экран 2 меняет отображение. Экраны связаны.

## ДВА РЕЖИМА (переключатель — меняет отображение текста)
- **Режим A — Визард / последовательность.** Читает последовательность всех session-концептов (уже есть
  порядок в REGISTRY), даёт список — как «поиск нашёл», выбираешь из него. Идём 1→2→3 линейно.
- **Режим B — Дерево.** Навигация деревом. Важно: **дерево НЕ по структуре папок, а по ЛОГИКЕ концептов**
  (как один вытекает/решает другой). Дерево сильно упрощает и помогает видеть «какая идея → какие концепты».
  В дереве: смотрим либо текущую итерацию (чёткий поиск по концепту), либо путешествуем визардом, который
  читает `concept.json` и ведёт по узлам.

## Параметры отображения (обсудить в реализации)
- Размер текста — свой в каждом режиме.
- Навигация — по тексту; если показываем папки → навигация по папкам; зависит от того, что ищем → такая и
  визуализация (всё тянется к форме дерева).
- **Две области в контенте:** «область видения» (сам контент) и «область комментариев» — возможно выделять
  явно. + механизм **свернуть/скрыть** эту разметку и открыть файл целиком с тех же строк.
- Что показывать на разных этапах — зависит от **состояния** (какой информацией владеем сейчас) и
  **комбинаций состояний** → разные сценарии отображения.

## Связь с данными
- Режим-визард читает `concept.json` (машиночитаемый порядок/связи концептов) — сейчас его роль играет
  `REGISTRY.md` (руками). Следующий шаг: сделать машиночитаемый `concept.json` (id · title · path · links).
- Пересекается с NEXT-CARDEX: там уже есть движок кнопок и рекурсивный парсер JSON → можно переиспользовать.

## Что зафиксировать как под-задачи (когда пойдём делать)
1. Короткий `title` в frontmatter каждого концепта (отдельно от имени файла). ← дешёвая, сделать первой.
2. `concept.json` сессии (генерится из frontmatter id/title/links).
3. Мок двух экранов (кнопки↔контент) — сначала текстом (см. EXAMPLE).
4. Режим-дерево по логике (из `links`), не по папкам.
5. Область видения/комментариев + сворачивание.
