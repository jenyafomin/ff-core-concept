# Лог проблем сессии (каждая = отдельная запись, статус, место, поиск)

> Это ручной прототип **эволюционируемого механизма** (см. `NEXT-03-agent-evolution.md`): каждый раз,
> когда всплывает «пошли не туда / механизм сделан неверно» — фиксируем как запись `Type: problem` со
> статусом. Агенты не читают весь handoff — но ЭТИ записи ищут по типу/статусу.

Словарь статуса: `open` (не решена) · `in-progress` · `solved`. Каждая запись имеет `id: PRB-n`.

---
### PRB-01 · Ощущение «разъединённости», хотя цель — объединить
- **Type:** problem · **status:** open · **где:** `HANDOFF.md`, весь слой представления
- **Суть (владелец):** «вижу концепты, ищущие файлы — хорошо, но нет чёткого объединения».
- **Разбор:** смысловое объединение есть (граф id↔links, единый scaffold). Разрыв — в ПРЕДСТАВЛЕНИИ: текст
  сыплется в чат, нет единого просмотра. → решается NEXT-VIEWER.
- **Ссылки:** refines → REGISTRY; raises → NEXT-VIEWER.

### PRB-02 · Визуализация концептов ужасная
- **Type:** problem · **status:** open · **где:** чат-вывод
- **Суть:** нельзя скопировать; нет удобного полного пути; длинные имена файлов не годятся для списка/кнопок.
- **Требования:** копируемый полный путь; короткий `title` отдельно от длинного имени файла; список
  пронумерован.
- **Ссылки:** raises → NEXT-VIEWER.

### PRB-03 · План «Combination» не учёл слой представления/UX
- **Type:** problem · **status:** open · **где:** `../combination-scaffold/docs/plan/PLAN.md`
- **Суть:** план описывал контракт/модули, но не то, КАК человек и агент это просматривают (2 экрана, 2
  режима, дерево по логике концептов).
- **Ссылки:** grounds → PLAN-GAPS; raises → NEXT-VIEWER.

### PRB-04 · Агенты не заходят в session-handoff → аналитика теряется
- **Type:** problem · **status:** open · **где:** процесс
- **Суть:** реально в handoff-сессию агенты не ходят; ценны только аналитические моменты («механизм сделан
  неверно», «шли не туда»). Их надо делать первоклассными записями (`Type: problem`), искомыми, привязанными
  к плану.
- **Ссылки:** raises → NEXT-EVOLUTION.

### PRB-05 · Файлы не находились (глубокий путь + не по конвенции + STATE не обновлён)
- **Type:** problem · **status:** solved · **где:** канон входа
- **Суть:** владелец (и любая новая сессия) не мог найти работу. Причины: (1) вход назван `_START-HERE.md`,
  а конвенция ждёт `INDEX.md` в корне сессии; (2) путь очень глубокий; (3) **канонический `STATE.md` не
  обновлён** — новая сессия читает его первым, а моей сессии там не было.
- **Решение:** добавлен `2026-07-13-combination-fable/INDEX.md` (вход по конвенции) + пункт в `STATE.md`
  (топ RESUME) + дата STATE обновлена.
- **Урок (в NEXT-EVOLUTION):** правило — в КОНЦЕ каждой сессии обновлять `STATE.md` и класть `INDEX.md` в
  корень папки-сессии; иначе работа «невидима».
- **Ссылки:** refines → NEXT-EVOLUTION.

---
## Как это растёт (мини-правило)
- Владелец говорит «тут по-моему фигня, согласен?» → если агент согласен → **фиксирует PRB-n** (status open)
  + место + ссылки. Позже статус меняется на solved с указанием, где решено.
- Записи ищутся по `Type: problem` и `status:` — как отдельное «расширение» над файлами (см. NEXT-EVOLUTION).
