# Fable-вердикт — «модуль» как несущая единица (разрез)

- **Status:** active (разрез Fable, ждёт адверсариальной проверки critic) · Date: 2026-07-13
- Бриф: `FABLE-BRIEF.md` · Контекст: `CONTEXT-DIGEST.md`

## Итог одной строкой
Ядро — НЕ модуль; модуль — гражданин субстрата с манифестом (словарь+порты+политики); истина одна,
scratch легален; апгрейд — линзы поверх нетронутой истории; форк — lineage по словарю; **Combination —
контракт и сертификация, а не третий движок**. Первый ход DESIGN: написать манифест «Плана» на бумаге и
прогнать через него шлюз — где манифест затрещит, там и есть настоящий ADR.

## 1. Kernel vs Module (снятие циркулярности)
Brain целиком модулем быть не может (реестр модулей жил бы в модуле; Конституция снималась бы
деинсталляцией). **Режем Brain пополам:**
- **KERNEL (не модуль, не удаляем):** движок субстрата + Конституция + реестр типов + шина портов +
  integrity-обязанности. «Операционная система».
- **МОДУЛИ:** 16 инфра-кусков Brain, шлюз, «План» — граждане одного класса.

## 2. Определение + манифест (анатомия, 8 частей)
**Модуль — версионированный гражданин субстрата: подписанный манифест, декларирующий словарь (свои типы
узлов/рёбер), политики-умолчания и порты (требуемые/предоставляемые); код — сменный адаптер к декларациям.**
Ментальная модель: **Postgres extension** (`CREATE EXTENSION`) — каталог и планировщик у ядра.

1. **Идентичность:** module_id = canonical_id (модуль сам — узел графа); имя; lineage-ребро на родителя при форке.
2. **Версия по 2 осям:** версия КОДА и версия СЛОВАРЯ. Совместимость ломает только словарь.
3. **Словарь:** типы узлов/рёбер + инварианты (INSERT в реестр типов, DL-14 работает как есть).
4. **Порты:** требуемые + предоставляемые. Сюда без остатка сворачиваются 13 портов шлюза.
5. **Политики-умолчания:** policy-as-data шаблоны; при установке ядро валидирует ≤ Конституции.
6. **Зависимости:** на СЛОВАРИ других модулей с диапазонами версий (НЕ на код).
7. **Поверхность:** промпты/скиллы/команды (для агентных модулей).
8. **Custody:** какие ключи/секреты нужны (из Engine Contract #15).

Проверка на 3 экземплярах: **шлюз** = runtime-модуль (даёт IChannel/IAgentRunner, декларирует
session/topic/binding); **«План»** = vocabulary+behavior-модуль (типы Task/Plan + скиллы); **инфра-куски
Brain** = kernel-adjacent модули.

## 3. Хранилище: один субстрат истины + приватный scratch
**Выбор: один логический субстрат. Федерации равноправных сторов — НЕТ** (совместимость = совместимость
словарей; общий словарь без общей истины — фикция; Конституция неисполнима поверх федерации).
**Оговорка — модулю разрешён приватный scratch:** буфер, который (а) перестраивается из субстрата без
потери истины, (б) достижим для hard-erase через обязательный erase-hook порта. **Граница — по СЕМАНТИКЕ
данных, не по проектам:** `jobs/queues/seen_updates` шлюза = scratch (горячий путь); `sessions/agents/
bindings/summaries` = истина → переезжает узлами на субстрат. Заодно снимает write-amplification (очередь
джобов через API графа похоронила бы M2).
**Риски:** (1) scratch-дрейф (буфер тихо становится теневой БД) → правило «стирается в любой момент без
потери истины» + тест в conformance. (2) Классификация таблиц шлюза «истина/scratch» — первый боевой тест
контракта модуля.

## 4. Апгрейд / форк / совместимость
Не хватало одного слова — **upcaster (линза).**
- **Апгрейд поверх живой БД:** новая версия НИКОГДА не переписывает старые узлы. (а) INSERT новых версий
  типов (`Task@2` рядом с `Task@1`); (б) **линзы** — чистые функции чтения `Task@1 → Task@2` (upcasting /
  schema-on-read, Project Cambria). Старьё лежит нетронутым в битемпоральной истории; новый код читает
  через линзу; материализация = новое утверждение с новым valid-time, не мутация. DL-14 масштабируется этим.
- **Форк:** новый module_id + lineage-ребро на родителя + унаследованные canonical_id типов предка. Форк
  без изменения словаря = drop-in замена. Расширил словарь → обязан объявить diff.
- **Закон совместимости:** совместимость = ПЕРЕСЕЧЕНИЕ словарей по диапазонам версий, **код не участвует**.
- **Конституция = пол совместимости:** ни версия, ни форк не ослабляют инварианты; ядро валидирует манифест
  на install/upgrade (расширение integrity-as-engine-duty на install-time).

## 5. Что физически есть 3-й проект «Combination»
**НЕ третий репозиторий с движком** (третий движок = второе ядро = смерть архитектуры). Combination =
1. **Спека контракта модуля** (docs): формат манифеста, граница kernel/module, семантика 2-осевых версий,
   правила линз, erase-hook, install-гейт. 3-4 ADR.
2. **Conformance suite** — исполняемые проверки «ты валидный модуль» (манифест валиден; политики ≤
   Конституции; scratch перестраиваем; erase-hook работает) = «сертификат marketplace».
3. **Первый акт:** «План» пишется как эталонный экземпляр контракта; шлюз проходит сертификацию вторым.
**Владеет:** схемой манифеста, семантикой версий, правилами гейтов, тестами совместимости.
**НЕ делает:** не хранит (ядро Brain), не исполняет (runtime-модули), не содержит продуктовых фич.
Runtime-дом реестра модулей — ВНУТРИ движка Brain: реестр = узлы на субстрате (dogfooding).
Combination — конституционный суд, не министерство.

## 6. Слепые пятна (то, что analyst/critic не увидят)
- **А. Hard-erase против копий.** Marketplace размножает данные (scratch/экспорты/форки/кэши линз).
  «Безусловный hard-erase» определён над субстратом, но НЕ над экосистемой модулей. Erase-обязанность
  вшить в порт-контракт с 1-го ADR, иначе GDPR-класс проблема by design. Линза при реинтерпретации читает
  сырые старые узлы — обязана работать ПОД policy-движком, иначе апгрейд воскрешает скрытое политикой.
- **Б. Ontology commons (политика словаря).** Два автора объявят каждый своего «Task» → граф балканизируется
  (модули установлены, семантически глухи). Нужен ядерный core-словарь (десяток базовых типов, владеет
  kernel, меняется как Конституция) + неймспейсы модулей + рёбра-маппинги. Невидимо на 2 своих модулях —
  возникает на 3-м чужом.
- **В. Provenance утверждений.** Bitemporal версионирует данные, но не поведение, их породившее. Каждая
  запись штампуется `module@version` автора. Копейки сейчас, ретрофит невозможен. Фундамент доверия
  marketplace: «какой код это утверждал».

## 7. Инфра-модули-кандидаты для Combination
1. **Module Registry & Manifest** · сводит реестр типов Brain (DL-14) + реестр bot/agent шлюза (M5) ·
   паттерн: Postgres extensions / package manager с lockfile, registry-as-nodes · **ADR-C1 «Манифест и
   граница kernel/module»**.
2. **Vocabulary & Lenses** · INSERT-not-migrate + bitemporal + апгрейд живой БД · паттерн: event-sourcing
   upcasting, schema-on-read (Cambria) · **ADR-C2 «2-осевые версии и ленивая реинтерпретация»**.
3. **Port Bus / Capability Broker** · 13 портов шлюза + Engine Contract #15 + key-custody · паттерн:
   hexagonal ports + object-capabilities · **ADR-C3 «Порты как валюта модулей»**.
4. **Provenance & Certification** · трейсы агентов + approval-гейты + доверие marketplace: штамп
   module@version + conformance-suite как сертификат · паттерн: signed assertions + контрактные тесты · **ADR-C4**.
5. **Scratch & Erase Duty** · операционные сторы + Конституция: scratch легален, но перестраиваем и достижим
   для hard-erase через hook · паттерн: cache-with-obligations · **ADR-C5**.
