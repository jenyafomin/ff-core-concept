## Чего именно (объекты)
Единица «модуль»; манифест; граница kernel/module; реестр и discovery; изоляция сбоя модуля.

## Направления

### D1.1 — Единица модуля (манифест)
- **Суть:** что физически есть «модуль», чтобы Brain-инфра, шлюз и «План» были экземплярами одного класса.
- **Развилка (решена Fable):** модуль = версионированный гражданин субстрата = подписанный **манифест**
  (8 частей: идентичность+lineage · версия[код|словарь] · словарь типов · порты · политики-умолчания ·
  зависимости на словари · поверхность · custody). Код — сменный адаптер.
- **Идеи:** «модуль как узел графа» [CV1,CV2]; манифест-как-данные (валидируется ядром); модель Postgres
  extension.

### D1.2 — Граница kernel / module
- **Суть:** что НЕ модуль (неудаляемо) vs что модуль.
- **Развилка (решена, с правкой critic):** kernel = движок субстрата + Конституция + реестр типов + шина
  портов + integrity + **seed-словарь** (`Module/Manifest/Version/Type/Port/LineageEdge`, само-регистрация
  на bootstrap). Всё прочее — модули.
- **Открытый вопрос:** апгрейд самого kernel (единственное место настоящей миграции субстрата) → CQ1.

### D1.3 — Реестр и discovery
- **Суть:** где живёт список установленных модулей, как их находят агенты/система.
- **Развилка:** реестр = **узлы на субстрате внутри ядра Brain** (dogfooding) vs внешний манифест-стор.
  Выбор Fable: узлы на субстрате. Discovery по словарю/портам.
- **Идеи:** lockfile-подобная фиксация версий; «кто предоставляет порт X».

### D1.4 — Изоляция сбоя модуля
- **Суть:** упавший/битый модуль не роняет систему и не портит граф.
- **Развилка:** уровень изоляции — процесс/capability/транзакция? Связано с CV5 sandbox → M7.
- **Идеи:** порт-контракт с таймаутом; write только через API ядра (R6 Brain); карантин узлов при сбое.

## Приоритет
**must-now** — это сама несущая развилка; всё остальное (апгрейд, форк, совместимость) висит на определении
единицы. Без CV1 нет платформы.
