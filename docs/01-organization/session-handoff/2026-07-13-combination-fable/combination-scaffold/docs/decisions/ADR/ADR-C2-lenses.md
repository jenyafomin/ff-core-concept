# ADR-C2 — Двухосевые версии, линзы (schema-on-read) и форк-lineage

- **Status:** draft (proposed) · Owner: jenya.stasik@gmail.com · Date: 2026-07-13
- Related: `../DECISIONS-LOG.md` (CDL-08,09,10,11), M2, CV2, CV3, `../../SURVIVING-CUT.md` S4

## Context
Владелец просил апгрейды поверх ЖИВОЙ БД со старыми данными и связку версий/форков. Brain даёт bitemporal
+ INSERT-not-migrate. Critic вскрыл: линза — это код (стоимость цепочки, тотальность, порядок при форке).

## Decision
1. **Апгрейд = линза (upcaster), старьё не переписывается.** Новая версия INSERT-ит `Type@N` рядом с
   `Type@N-1` и поставляет чистую функцию чтения `@N-1 → @N` (schema-on-read; ср. Project Cambria).
   Материализация линзой = новое утверждение с новым valid-time, не мутация.
2. **Тотальность линзы обязательна к декларации.** Нетотальная линза НЕ фабрикует тихо: отсутствующее поле
   помечается `derived` + `low-confidence` (эпистемический статус Brain) либо явный null-контракт.
3. **Стоимость цепочки:** разрешён материализованный кэш апгрейженного вида, НО кэш = **scratch**
   (перестраиваем + erase-reachable, M5). Периодическая **компакция** цепочки линз в новую канон-версию —
   governed-событие.
4. **Форк = новый `module_id` + lineage-ребро + унаследованные canonical_id типов предка.** Без изменения
   словаря — drop-in замена. Изменил словарь — объявляет diff.
5. **Совместимость = пересечение словарей по диапазонам версий + поведенческий гейт порта (ADR-C1/M4).**
   Конституция — пол.

## Alternatives considered
- **Миграция-переписывание** (классика) — отвергнуто: ломает bitemporal-историю и hard-erase-аудит.
- **Линза фабрикует дефолты молча** — отвергнуто (critic): удар по Тождеству/Доверию.
- **Всегда лениво, без кэша** — отвергнуто: деградация latency на большой истории.
- **Всегда материализовать** — отвергнуто: копия конфликтует с hard-erase; поэтому кэш только как scratch.

## Consequences
- (+) DL-14 Brain масштабируется на marketplace; апгрейд без даунтайма и без потери старого.
- (−) Порядок линз при мульти-lineage не определён → **CQ2** (явный порядок ИЛИ запрет мульти-lineage без
  merge-политики).
- (−) Кэш-как-scratch требует дисциплины «стирается без потери истины» (тест в conformance).

## Validation
- Тест «эволюция БД» (запрос владельца): `Task@1`→`Task@2`→`Task@3`, старые узлы читаются через цепочку,
  hard-erase проходит и стирает кэши; аудит сохранён.
- Тест форка: два форка «Плана» на `Task@2` взаимозаменяемы.
