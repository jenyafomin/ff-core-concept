# ADR-C6 — Cutover: федерация сейчас → один субстрат потом (черновик-контекст)

- **Status:** draft (context only) · Owner: jenya.stasik@gmail.com · Date: 2026-07-13
- Related: M6, `../DECISIONS-LOG.md` (CDL-05,17), CV4

## Context
Critic (жёстко): «федерации нет» — ложно СЕЙЧАС. Шлюз построен и работает на своей SQLite; Brain-граф не
существует (фаза дизайна). Требовать переезд `sessions/agents/bindings` на несуществующий граф = риск
заморозить рабочий шлюз ради чистоты недостроенного фундамента. Прямой guardrail POS: не переписывать
живую систему под несуществующий фундамент.

## Decision (направление)
1. **Сейчас = федерация** (SQLite шлюза + будущий граф). Это переходное, не конечное состояние.
2. **Цель = один логический субстрат истины.** Переезд **инкрементальный**, через **мост-адаптер**
   (strangler-fig / anti-corruption layer): новые истины пишутся в граф через API; старые мигрируют
   партиями; шлюз продолжает работать всё время.
3. **Рабочий шлюз НЕ морозим и НЕ переписываем** ради чистоты. Порядок: сначала граф существует (Brain M0–M1),
   потом мост, потом переезд truth-таблиц; scratch-таблицы остаются в шлюзе.

## Validation / критерии
- Критерий готовности к cutover: Brain M1 зелёный (паспорт + edge-registry закрыты) + мост-адаптер + тест
  «двойная запись/чтение согласованы».
- Откат: мост выключается, шлюз работает на своей SQLite как раньше.

## Открыто
Порядок миграции конкретных таблиц; двойная запись vs read-through; CQ4 мультитенантность.
