# ADR-C1 — Манифест модуля и граница kernel/module

- **Status:** draft (proposed) · Owner: jenya.stasik@gmail.com · Date: 2026-07-13
- Related: `../DECISIONS-LOG.md` (CDL-03,12,13), M1, `../../SURVIVING-CUT.md` S2

## Context
Нужна единица «модуль», такая, что Brain-инфра, шлюз и «План» — её экземпляры, и marketplace-совместимость
на ней держится. Ключевое возражение critic: совместимость нельзя свести только к словарю — порты несут
поведение (at-least-once vs exactly-once), которое манифест обязан декларировать.

## Decision
**Модуль = версионированный гражданин субстрата: подписанный манифест, декларирующий словарь, политики-
умолчания и порты; код — сменный адаптер к декларациям.** Манифест (8 частей):

1. **Идентичность:** `module_id` = canonical_id (модуль сам — узел графа); имя; `author`, `license`
   (дёшево заложить под CV6); lineage-ребро на родителя при форке.
2. **Версия (2 оси):** `code_version`, `vocab_version`. Совместимость ломает только `vocab_version`.
3. **Словарь:** типы узлов/рёбер + инварианты (INSERT в реестр типов). **Неймспейс модуля** обязателен
   (против ontology-commons балканизации). Может ссылаться на **core-словарь ядра** (базовые типы).
4. **Порты:** требуемые + предоставляемые. **Каждый порт декларирует поведенческий контракт** (идемпотент-
   ность, доставка, побочки) — не только форму.
5. **Политики-умолчания:** policy-as-data шаблоны; ядро валидирует ≤ Конституции при install/upgrade.
6. **Зависимости:** на СЛОВАРИ других модулей с диапазонами версий (НЕ на код).
7. **Поверхность:** промпты/скиллы/команды (для агентных модулей).
8. **Custody:** требуемые ключи/секреты (из Engine Contract #15).

**Граница kernel/module:** см. ADR-C0. Ментальная модель — Postgres extension.

## Alternatives considered
- **Совместимость только по словарю** (исходный Fable) — отвергнуто (critic): порты имеют семантику.
- **Модуль = код-плагин (ports/adapters шлюза)** — недостаточно: не покрывает словарь/данные.
- **Модуль = только данные (policy-as-data Brain)** — недостаточно: не покрывает исполнение/порты.

## Consequences
- (+) Три экземпляра проверяют единицу: шлюз (runtime-модуль), «План» (vocab+behavior), Brain-инфра
  (kernel-adjacent).
- (−) Поведенческий контракт порта требует contract-тестов (M4) — сложнее, чем статическая проверка форм.
- Требует core-словаря ядра + неймспейсов (слепое пятно Б).

## Validation
**Первый боевой ход:** написать манифест «Плана» на бумаге и прогнать через него шлюз (описать шлюз этим
манифестом). Где манифест затрещит — там следующий ADR.
