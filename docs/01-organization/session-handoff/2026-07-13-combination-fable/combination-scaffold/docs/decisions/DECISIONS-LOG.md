# Combination — DECISIONS-LOG

- **Status:** active · Owner: jenya.stasik@gmail.com · Date: 2026-07-13
- Источник: `../../SURVIVING-CUT.md`. Формат: CDL-NN · решение · статус · обоснование.

| ID | Решение | Статус | Обоснование |
|----|---------|--------|-------------|
| **CDL-01** | Kernel ≠ module: неудаляемое ядро отделено от сменных модулей | accepted | снимает циркулярность (реестр не в удаляемом модуле) |
| **CDL-02** | Kernel несёт seed-словарь, само-регистрируемый на bootstrap | accepted (правка critic) | без него реестр не может существовать (bootstrap-проблема) |
| **CDL-03** | Модуль = версионированный гражданин субстрата = подписанный манифест (8 частей) | accepted | Brain-инфра, шлюз, «План» — экземпляры одного класса |
| **CDL-04** | Версия по 2 осям: код и словарь; ломает совместимость только словарь | accepted | код-адаптер меняется свободно, контракт данных — нет |
| **CDL-05** | Один субстрат истины — ЦЕЛЬ; сейчас федерация; cutover инкрементальный | accepted (правка critic) | «федерации нет» ложно сейчас; шлюз не морозим |
| **CDL-06** | Приватный scratch легален, если перестраиваем и erase-reachable; граница по семантике данных | accepted | снимает write-amplification; jobs=scratch, sessions=истина |
| **CDL-07** | Erase scratch синхронизируется с истиной (append-событие), аудит инцидента сохраняется | accepted (правка critic) | иначе тихая потеря аудита (ср. баг dup-kill) |
| **CDL-08** | Апгрейд = линза (schema-on-read), старьё не переписывается | accepted | масштабирует INSERT-not-migrate на marketplace |
| **CDL-09** | Линза обязана объявлять тотальность; нетотальная помечает поле derived/low-confidence, не фабрикует | accepted (правка critic) | защита Тождества/Доверия от молчаливых домыслов |
| **CDL-10** | Кэш апгрейженного вида разрешён, но = scratch (erase-reachable) + компакция цепочки | accepted (правка critic) | примиряет стоимость линз с hard-erase (слепое пятно А) |
| **CDL-11** | Форк = новый module_id + lineage-ребро + унаследованные типы; drop-in если словарь не тронут | accepted | совместимость по словарю |
| **CDL-12** | Совместимость = ДВА гейта: словарь (форма) + поведенческий контракт порта | accepted (правка critic) | «код не участвует» — слишком сильно; порты имеют семантику |
| **CDL-13** | Конституция = пол совместимости; ядро валидирует манифест на install/upgrade | accepted | расширение integrity-as-engine-duty на install-time |
| **CDL-14** | Штамп `module@version` на каждой записи (provenance) | accepted | ретрофит невозможен; фундамент доверия marketplace |
| **CDL-15** | Combination = контракт + conformance-suite + ТОНКИЙ sandbox-рантайм сертификации (не второй движок данных) | accepted (правка critic: тезис «движка нет» падал) | conformance физически требует sandbox для чужого кода |
| **CDL-16** | Combination имеет свою governance-версию + политику ре-сертификации | accepted (правка critic) | правила гейтов эволюционируют, нельзя ретро-молчаливый провал |
| **CDL-17** | Guardrail: рабочий шлюз не морозим/не переписываем ради недостроенного Brain | accepted | фаза DESIGN; не строить без «строй» |
