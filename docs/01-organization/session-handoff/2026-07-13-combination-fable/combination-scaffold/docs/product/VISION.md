## Цель (одним абзацем, человеческим языком)
У человека есть два куска: **память** (Brain — граф-субстрат, где живёт всё, с чем работают агенты) и
**руки/нервы** (agents-manager — шлюз, который слушает Telegram, запускает агентов, следит за ходами).
Сейчас это два разных мира со своими правилами и своими базами. **Combination** — это не «ещё один
движок», а **общая конституция и контракт**, по которым любая новая способность добавляется в систему
**модулем** — как расширение к базе данных. Кто-то собрал модуль «План», другой его форкнул и сделал
лучше; версии обновляются поверх живых данных, старое не ломается. Боль, которую снимаем: сегодня каждая
новая фича прирастает вручную и по-своему; завтра — по единому правилу, подключаемо, с апгрейдами и
маркетплейсом.

## Несущая идея (разрез Fable, переживший критику)
- **Ядро (kernel) — не модуль.** Движок субстрата + Конституция + реестр типов + шина портов + integrity.
  Неудаляемо. Модель: операционная система.
- **Всё остальное — модули одного класса.** 16 инфра-кусков Brain, сам шлюз, «План» — граждане субстрата.
- **Модуль = версионированный гражданин субстрата:** подписанный **манифест** (словарь типов + порты +
  политики-умолчания), код — сменный адаптер. Ментальная модель: **Postgres extension**.
- **Одна истина + приватный scratch.** Один логический субстрат истины; операционные буферы (очереди
  джобов) легальны как scratch, если перестраиваемы и достижимы для hard-erase. Граница — по семантике
  данных, не по проектам. (СЕЙЧАС по факту федерация → цель — субстрат; переезд инкрементальный, рабочий
  шлюз НЕ морозим.)
- **Апгрейд = линза (schema-on-read):** `Task@2` рядом с `Task@1`, чистая функция чтения `@1→@2`, старьё
  не переписывается. **Форк = lineage-ребро** к оригиналу; совместимость = пересечение словарей;
  **Конституция = пол совместимости**.
- **Combination владеет:** контрактом манифеста, семантикой версий, гейтами, тестами совместимости +
  ТОНКИМ sandbox-рантаймом сертификации (изолировать чужой код). **Не хранит, не исполняет бизнес-логику,
  не содержит продуктовых фич.** Реестр модулей физически живёт узлами в ядре Brain (dogfooding).

## Границы (что Combination НЕ делает)
- НЕ второй движок данных (иначе = второе ядро = смерть архитектуры).
- НЕ переписывает рабочий agents-manager ради чистоты недостроенного Brain.
- НЕ решает продуктовые фичи — их приносят модули.

## Фаза
DESIGN. Первый боевой ход: **написать манифест модуля «План» на бумаге и прогнать через него шлюз** — где
манифест затрещит, там настоящий ADR. Строить только по явному «строй» от владельца.
