## ⚠️ ЭТА СХЕМА ЗАМЕНЯЕТ старую («сессия = дата»)

Старый механизм — `docs/01-organization/session-handoff/<ДАТА>-<контекст>/` (committed в git, темы `NN-*.md`
внутри) — **больше не используется для НОВЫХ сессий**. Существующие папки этой схемы — исторический архив,
их **не переносим и не удаляем**. Логирование идёт по схеме ниже: дом лога `docs/_log/<YYYY-MM-DD-slug>/`
целиком вне git (`.gitignore **/_log/`).

## Ядро (одно правило, всё остальное — следствия)

**ТЕМА = ПРОЕКЦИЯ ДОКУМЕНТА, а не второй экземпляр контента.**
Суть работы всегда ложится в реальный канон-документ (brain, contract, реестр…). Лог разговора — это
ТОНКИЙ СЛЕД: что обсудили · через каких агентов · какие решения · **→ указатель на канон-док, куда легло.**
Логи не дублируют содержание — они проецируют и ссылаются. Это и удерживает систему от нагромождения.

### FILE-FIRST (следствие ядра, уточнено 2026-07-26)

- **Суть → файлы, не в чат и не в `_inbox`.** Анализ/результат кладётся в ПРАВИЛЬНЫЙ дом знания
  (по типу → `.doc-types.json`) как **маленькие, дешёвые-к-чтению файлы + `concept.json`** (читается
  первым: перечисляет `steps[]` и связанные файлы). Всё перелинковано по путям. TRACE (`_log/`) держит
  **только УКАЗАТЕЛИ**, не контент.
- **Меньше прозы, больше ссылок.** Предпочитай ссылку на готовый анализ пересказу. Каждый анализ —
  КОРОТКИЙ, со своими выводами; длинный — дроби на дешёвые-к-чтению куски. Обзоры — нумерованы и разбиты
  по темам (напр. `01-overview/…`).
- **Меньше сообщений владельцу в чат.** Существо — в файлы; в чат — короткий указатель на них.

## Структура (R3)

```
docs/_log/                             ← ВЕСЬ каталог в .gitignore (**/_log/) — ничего отсюда не коммитится
└── <YYYY-MM-DD-slug>/                 ← разговор = дата-slug (дом из .doc-types.json → conversation-log)
    ├── concept.json                   ← type:conversation-log · id · topic · status · summary · steps[]
    ├── 1/                             ← ОБМЕН №1 (нумерованная под-папка на каждый обмен)
    │   ├── 1-transcription.md         ← расшифровка голоса (ТОЛЬКО если это обмен голосом)
    │   ├── 2-task-understanding.md    ← понимание задачи (ТОЛЬКО когда реально полезно)
    │   └── 3-result.md               ← результат/указатель на дом знания, куда легло
    ├── 2/                             ← ОБМЕН №2 …
    ├── analyses/                       ← (опц.) разборы разговора — контейнер без номера, файлы NN-<slug>.md
    └── questions/                      ← (опц.) открытые вопросы разговора

docs/01-organization/session-handoff/
└── STATE.md                           ← ЕДИНСТВЕННЫЙ committed-указатель «где мы» (синк вручную из concept.json)
```

- **Разговор** = папка `docs/_log/<YYYY-MM-DD-slug>/` (дата-slug, дом из реестра `conversation-log`).
- **Каждый обмен = нумерованная под-папка** (`1/`, `2/`…). Внутри — нумерованные куски-«ознакомление»:
  `1-transcription.md` · `2-task-understanding.md` · `3-result.md`. Куски-ознакомление заводи **ТОЛЬКО
  когда реально полезно** — не механически; голосовой обмен → `1-transcription.md`, иначе можно пропустить.
- **`concept.json`** (читается первым) — навигатор разговора: проходит detectContent как
  `{type:'conversation-log', id, steps[]}` (закон суффикса D-1); `steps[]` перечисляют файлы обменов и
  **`canon_links`/`paths` наружу — в реальные дома знания**, без копирования контента.
- **Расшифровка голоса (`1-transcription.md`) допускается ТОЛЬКО в gitignored `_log/`** как локальный
  след обмена — она **никогда не коммитится, никогда не становится домом истины и не дублируется в дома
  знания**. (Уточняет прежний инвариант «сырой промпт не хранить»: в git — по-прежнему НЕ попадает; суть
  всё так же живёт в `summary` + `canon_links`.)
- **`STATE.md` остаётся единственной committed точкой входа** — краткое «где мы», синхронизируется вручную
  в конце разговора/сессии из `concept.json`. Сам `_log/` в git не попадает и историей репозитория не является.

## Схема `concept.json`

```json
{
  "type": "conversation-log",
  "id": "YYYY-MM-DD-slug",
  "started": "YYYY-MM-DDThh:mm",
  "topic": "короткое название темы разговора",
  "status": "open | closed",
  "summary": "2-4 предложения — что решили/поняли, без пересказа контента",
  "canon_links": ["docs/.../реальный-документ.md"],
  "steps": [
    { "title": "обмен 1", "paths": ["1/3-result.md"], "note": "куда легло → canon_links" }
  ]
}
```

- `type:'conversation-log'` + `id` + `steps[]` — обязательно, чтобы файл прошёл detectContent как
  ВИД-навигатор (закон суффикса D-1); иначе `concept-lint` его отклонит.
- `steps[]` — маршрут по обменам: каждый шаг перечисляет файлы обмена (`N/…`) и путь наружу в дом знания.
- `canon_links[]` — пути к реальным канон-документам, куда легла суть (единственная связь наружу).
- Статус `closed` выставляется в конце разговора, вместе с финальным `summary`.

## Процедура

1. **Старт разговора (`/new`):** создать `docs/_log/<YYYY-MM-DD-slug>/` + `concept.json`
   (`type:'conversation-log'`, `id`, `started`, `topic`, `status: open`, пустой `steps[]`).
2. **На каждый обмен:** завести под-папку `N/`; голосовой обмен → `1-transcription.md`; куски
   `2-task-understanding.md` / `3-result.md` — **только когда реально полезны** (не механически). Существо
   обмена — **file-first в дом знания** (маленькие файлы + `concept.json` там), а в обмене — указатель.
   **Дописывать** `concept.json.steps[]` и `canon_links` сразу, не в конце.
3. **Правило роста:** длинный разбор дроби на дешёвые-к-чтению куски и клади в дом знания (по типу);
   в `_log/` — только указатель. Обзоры — нумерованы и разбиты по темам.
4. **Конец разговора/сессии:** дозаполнить `summary`, `status: closed`, финальные `canon_links`; **вручную**
   синхронизировать `docs/01-organization/session-handoff/STATE.md` (единственный committed артефакт).
5. **Память:** в конце — указатель в auto-memory, что `STATE.md` = точка входа (как и раньше).

## Кто запускает и как настраивать

- **Кто:** оркестратор сессии (Fable/главная модель) — вызывает в начале и в конце. Позже можно выделить
  отдельного агента-логгера (sonnet) со спец-скиллом, чтобы разгрузить оркестратора.
- **Как вызвать:** «залогируй сессию» / «оформи хендофф» / «/new» на старте нового разговора.
- **Настройка (единственный параметр):** slug разговора — `<YYYY-MM-DD-slug>`, дата + короткая тема.
- **Инвариант:** не дублировать контент в логи (суть = file-first в дом знания); всегда заполнять
  `canon_links`/`steps`; `_log/` никогда не коммитится; расшифровка голоса допустима ТОЛЬКО в gitignored
  `_log/` (никогда не в git и никогда как дом истины).

## Границы

- Нумерация контейнеров (`analyses/ questions/`) и файлов внутри них — по конвенции R1, которую ведёт
  `doc-discipline` (контейнеры без номера, файлы внутри — с номером). Под-папки обменов (`1/ 2/…`) и
  куски внутри (`1- 2- 3-`) — нумерованные по порядку обмена. Этот скилл не переопределяет R1, только
  применяет его к `_log/`.
- Тип «состояние» (state) — отдельная сущность `docs/00-states/` (см. `doc-discipline`, R2); session-logging
  её не подменяет и не пишет туда.
