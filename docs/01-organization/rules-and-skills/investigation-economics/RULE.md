# RULE — Экономика расследований (мульти-агентные прогоны)

> Зачем: чтобы фан-аут агентов был экономически ВЫГОДНЫМ, а не «жёг токены вслепую».
> Триггер: любой Workflow / веер из ≥3 агентов (ресёрч, консилиум, аудит, миграция).

## Инвариант (родился из прогона 2026-07-10)
**Ни один мульти-агентный прогон без учёта стоимости.** Если харнесс не пишет usage —
инструментируем сами (см. §4). Прогон, стоимость которого нельзя назвать, считается
незавершённым.

## §1. Модельная лестница (жёстко)
- **Fable — НИКОГДА в вееере.** Только точечно, на мастер-развилке, руками владельца.
- **sonnet — дефолт** ресёрча и линз (широта, дёшево).
- **opus — только синтез/сходимость** (1 на тему, не на каждый под-шаг).
- **haiku — механика** (сбор, дедуп, форматирование, извлечение).
- Явно указывать `model` в каждом agent() — не наследовать (иначе веер может уехать в Fable).

## §2. Структура против переделок
- Каждый агент **пишет результат в файл** (research/*, council/*) + возвращает сжатую структуру.
  Файл = страховка от смерти фона (проверено: 6/8 выжило именно потому, что писали на диск).
- **Схема (StructuredOutput)** вместо парсинга текста — меньше повторов на несоответствии.
- **pipeline по умолчанию**, барьер (parallel между стадиями) — только когда нужен весь срез
  (дедуп, ранний выход на нуле). Барьер = потраченный wall-clock быстрых агентов.
- **Дедуп ДО дорогой стадии** (верификация/синтез), не после.

## §3. Границы веера (масштаб под задачу)
- «Быстрый вопрос» → 1-3 агента, без консилиума.
- «Тщательно/аудит» → веер + консилиум 3 линз + синтез. Не раздувать линзы >3 без причины.
- **human-in-the-loop только на КЛЮЧЕВЫХ развилках** — не спрашивать человека на механике.
- Верхняя граница на прогон: явный лимит агентов; при обрезке (top-N, no-retry) — `log()`
  что отброшено (тихая обрезка читается как «покрыто всё» — запрещено).

## §4. Инструментовка стоимости (обязательно, пока I-2 не готов)
- Если есть бюджет-директива («+Nk») — держать `budget.remaining()` как жёсткий потолок.
- Каждый agent() возвращает во внешний слой оценку своих токенов; прогон завершать строкой
  `log()` с суммой по фазам (ресёрч / консилиум / синтез).
- ⚠️ **Известная дыра (2026-07-10):** journal.jsonl мульти-агентного прогона НЕ содержит usage.
  → до закрытия темы I-2: снимать usage из результатов синхронных агентов; для фоновых —
  фиксировать хотя бы число агентов × модель × ~средний размер задачи как грубую оценку.

## §5. Критерий «выгодно ли было»
Прогон выгоден, если: (а) выход — артефакт-решение (не чат), (б) он снял развилки/подготовил
дорогой Fable-цикл, (в) стоимость названа и соразмерна снятой неопределённости.
Прогон невыгоден, если веер дублировал то, что решил бы 1 агент, или ушёл в дорогую модель без нужды.

## Долг → в трек памяти
Этот RULE — временный протез. Настоящий учёт (рекурсивное дерево делегирования, снапшоты во
времени, самообучение) проектируется как модуль I-2 в `01-brain/infrastructure/`. Мастер-вопрос
для Fable: **F5** — Эпизод/сессия и единица трейса — одна сущность или разные.
