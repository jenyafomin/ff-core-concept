# RULE — Отчётность агентов (concept/preset — навигируемый отчёт)

> ⚠️ ПЕРЕСМОТР 2026-07-11: прежняя схема `index.json` (плоский манифест) была НЕ той формы.
> Канон формата задан владельцем в agents-manager: **concept / preset (`attention-list`)** —
> навигируемый «отчёт-как-git-commit», который файловый визард шлюза проходит по порядку.

## Область применения (расширено 2026-07-12, голос владельца)
Правило шире расследований: **любой значимый отчёт/итог агента идёт через КОНЦЕПТ** (карточки + `*.concept.json`),
а не тонет в чате. **Особенно** — когда результат НЕ доставляется через Telegram: концепт остаётся на диске,
его можно анализировать и с ним работать (визард/агенты). Чат эфемерен — концепт навигируем и анализируем.
Стыкуется с `../full-paths/SKILL.md` (пути полные от корня) и принципом «артефакты важнее чата».

> **Scope-решение владельцу:** сейчас правило **проектное** (FF). Оно — **кандидат в глобальные**
> (`~/.claude/rules/`), т.к. механизм концепта кросс-проектный (шлюз). По конституции промоушен = после
> обкатки в 2+ проектах + твоё одобрение + план отката. Скажи «в глобал» — положу короткий указатель.

## Зачем такой формат
Агент по итогу работы кладёт JSON рядом с проектом и в отчёте даёт **кнопку-пресет** вместо
вываливания документов. Владелец жмёт → видит дерево «что делалось», ходит сам по кнопкам.
Группировка по `pool`/`role` читается как git-commit (что тронуто), только навигируемая и
последовательная (README-first обход). Это и есть «чёткая последовательная структура».

## Обязательный выход каждого прогона
1. **Report / синтез (человеку)** — один файл-ответ (напр. `VERDICT.md`), он и есть ответ.
2. **`*.concept.json` (машине+визарду)** — навигируемый пресет по схеме ниже, рядом с проектом,
   на пути которого он ссылается (пути внутри ПРОЕКТА, чтобы браузер их резолвил).

## Схема `*.concept.json` (канон — см. examples/ в agents-manager)
```json
{
  "type": "attention-list | report | *-graph",   // ОПОЗНАЁТСЯ по первому полю type (авторитетно)
  "id": "<slug>",
  "title": "<что это>",
  "relatesTo": "<путь к Spec/идее/плану — 'всегда помним, к чему это'>",
  "pool": "<верхний тег-пул>",
  "createdBy": "agent",
  "viewModes": ["preset", "all-files"],           // пресет ↔ всё дерево с подсветкой ключевых
  "keyFiles": ["<с чего начать смотреть>"],
  "paths": [
    { "path": "<полный путь в проекте>",
      "role": "start|key|changed|support|doc",    // вид метки файла
      "pool": "<подзадача: движок/проводка/просмотр/конфиг/план/обзор/…>",
      "note": "<зачем смотреть / что это>" }
  ]
}
```

## Правила
- **Опознание — по `type`** (первое поле). Имя `*.concept.json` / `*.graph.json` — только для
  быстрого поиска, НЕ источник истины.
- **Пути полные и внутри проекта** — дерево строится на лету из `paths[]` (со сжатием цепочек),
  граф НЕ храним.
- `role`: `start` (с чего начать) · `key` (ключевой) · `changed` (тронут) · `support` · `doc`.
- `pool` — обязательная группировка по подзадаче (это «пометка файла на пул», о которой просил владелец).
- **`note` — МИНИМУМ (2-4 слова).** Владелец (2026-07-11): описания были тяжёлые/непонятные —
  нужен минимум. Дерево + пул несут смысл; `note` только метка. Длинное — опционально в `noteLong`,
  показывать по запросу, НЕ по умолчанию.
- `relatesTo` всегда указывает, к какому плану/спеке относится отчёт.
- `keyFiles` — короткий список «открой это первым».
- Первым по обходу — `README`/`start`, дальше по `paths[]`.

## Зависимость (честно)
Визард, который ХОДИТ по этим JSON (Слой C «концепт→дерево», Слой D wizard) — фаза 2 бэклога
(F7/F8), ещё не построен. Слой A «открыть файл через Rich» — уже готов (ветка feat/sdk-runner).
→ Формат пишем УЖЕ СЕЙЧАС (forward-compatible): когда визард сядет — старые отчёты станут walkable
без переделки. До тех пор `*.concept.json` = обычный машинный индекс + `paths[].note` как оглавление.
