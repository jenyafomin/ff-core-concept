# Идейная студия — метод (направления + инфраструктура по файлам)

> Перенос метода из agents-manager (там полный регламент `docs/00-organization/value-decomposition-method.md`),
> адаптированный под FF: термины и нумерация — по FF (`docs/topics/00-canon/DOC-CONVENTION.md`, «never delete →
> 90-historical»). Отличие от исходной студии — **встроенная память** (`MEMORY.md`).

## 1. Лестница (одна операция рекурсивно)

`ЦЕЛЬ → ЦЕННОСТЬ → НАПРАВЛЕНИЕ → ИДЕЯ → ИНФРАСТРУКТУРА`

- **В FF «направление» = «концепт ценности»** (voronka топика 56: «X — ЧЕГО именно?» → чёткое направление).
  Это один и тот же средний слой, просто под привычным FF-именем.
- Операция одна: **различай вниз — объединяй вверх.** Режь «почему» по граням, пока разрез даёт новую
  развилку. На дне идея = пивот «почему → как» (решение на паттерне). «Как»-и с общим механизмом
  собираются вверх в инфра-модуль.
- **Правило глубины:** чем ниже — тем детальнее. Цель — абзац; направление — до развилок; инфра-модуль —
  максимум нюансов + ADR + критик.

## 2. Формы папок

```
values/<ценность>/
  README.md               # «чего именно» + список направлений + какие инфра-модули задевает
  <NN-направление>/        # = концепт ценности
    README.md              # Суть · Границы · РАЗВИЛКИ (веер вариантов +/−) · Пул идей (индекс)
    analysis/              # разборы агентов, когда начали копать
  share/                   # общий буфер для соседних направлений одной ценности
infrastructure/            # СОСЕД ценностей: сквозные и «глобальные» модули (≥2 тега)
  README.md                # структура + правило подъёма
  ideas/                   # все наброски (сырой пул кандидатов) — ничего не режем
  analysis/                # пунктные разборы возможных инфра-идей
  open-questions.md        # открытые вопросы/развилки
  <NN-модуль>/README.md    # определённое: забрали из ideas/ → сюда
```

- **Skip-тест направлений:** папку направления заводим только при **≥2 непересекающихся гранях**; одна
  грань → пул идей прямо в README ценности. Не плодим папки ради формы.
- **Группировка ≈10:** если на уровне >~10 элементов — вводим ещё абстрагирующий виток и прячем в под-папки.

## 3. Инфраструктура — размещение по охвату (правило подъёма по тегам)

Идея несёт **теги** — все грани, которых касается. Папка = где работаем; теги = чему служит.
- **1 тег** → локальна, живёт в своём направлении.
- **≥2 тега** → сквозная → в `infrastructure/`. Движение модуля: `ideas/` (набросок) → `analysis/`
  (разбор) → корень `NN-модуль/` (определён) → ADR/Spec. Не фильтруем «в лоб» — забираем определённое в корень.

## 4. Карточки идей (витрина, необязательно)

Заметную идею можно показать «в два слоя»: 🌍 просто (аналогия, ноль терминов) + 🔧 чуть техничнее
(механизм/паттерн, без кода) + что даёт. Карточка — вход; полный разбор — в `analysis/`.

## 5. Циклы самокритики (на каждом уровне)

Линзы: **analyst** (вглубь) · **business-analyst** (польза) · **abstract-thinker** (проще/паттерн) ·
**critic** (опровергнуть). Порядок жёсткий: **сначала расхождение** (BA + abstract генерят развилки и
**пишут в файл**, ничего не режем) → **потом схождение** (critic + analyst режут; отклонённое остаётся с
пометкой «почему»). Loop-until-dry, потолок **4 цикла** на уровень. Тяжёлый разбор — на агентах (сам по
папкам не ходишь). Владельцу — короткая карта веток **до** глубокого нырка.

## 6. Память (отличие этой студии)

- **В начале хода** читаешь `MEMORY.md`: где что лежит, что уже решено, какие развилки открыты.
- **В конце** дополняешь его: новые решения, сдвиги, открытые вопросы, указатели на созданные файлы.
- Память — быстрый живой контекст поверх FF-канона (`STATE.md` читается первым, память — второй слой студии).

## 7. Дисциплина

Артефакты, а не чат. Нумерация и статусы — по FF DOC-CONVENTION. Ничего не удаляем (→ 90-historical).
Каждый файл — frontmatter (Status/Owner/Date/Scope). Владельцу — простым языком, один вопрос в конце.
