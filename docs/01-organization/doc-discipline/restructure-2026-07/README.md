## Решение O-13 (граница модуля) — принято владельцем
**Оркестрация STATE·PLAN·TASK·LOOP принадлежит модулю `agent-manager`, но связана с базой (brain).**
- В `project/` есть **`01-brain` (база)** и **`02-agents` (agent-manager, движуха)**. Раскладываем прямо тут; репо-вынос (`TOOLS/agents-manager`) — позже (уже помечено в `02-agents/INDEX.md` как «модуль со ссылкой»).
- **База (`01-brain`)** держит: 4 примитива, Акт-журнал, policy-as-data, ценности, и **generic `plan` как СЕМЕЙСТВО** — базовый тип + механизм **вариаций/подтипов/апгрейд-линз** (ответ на «у нас будут ДРУГИЕ планы — как БД с ними взаимодействует»: спец-план под state, loop как вариация, апгрейды).
- **Модуль (`02-agents`)** держит: **конкретную** оркестрацию STATE·PLAN·TASK·LOOP как ГРАНИ над базой + конкретные plan-kinds + ADR оркестрации (переезжает из `01-brain/decisions/`).

## Решение O-14/O-15 (размещение + процесс) — принято
- **Дисциплина размещения обязательна** (боль повторяется). `decisions/`-куча = анти-паттерн → решения распределяются по домам своих тем; `DECISIONS-LOG.md` = сводный журнал-**указатель** (trace), не свалка.
- **Библиотекарь = навык** (doc-discipline-раннер), не новая личность. **Инбокс `_inbox/`** — агенты кладут «чёткими файлами» черновиком, библиотекарь параллельно разносит.
- **Порядок:** сначала явно записать (эти карты) → чуть отложить библиотекаря → сперва убрать текущий бардак по картам → дальше вопросы можно параллельно (складывая в инбокс).
