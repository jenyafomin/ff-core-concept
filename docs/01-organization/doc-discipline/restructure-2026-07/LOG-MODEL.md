# 🗂️ Единый `_log` — модель (решение владельца 2026-07-19)

> Свод: `_inbox` + `session-logging` (`logs/conversations/NN`) + `_logs` → **ОДИН `_log`**. Снимает
> противоречие O-17 (был конфликт: NN vs дата; хранить-сырой vs нет).

## Правила (из речи владельца)
- **`_log/`** — сквозной, underscore, на глобальном уровне дерева (`docs/_log/`). **gitignore** (`**/_log/`):
  это ТРАСС (указатели), истина течёт НАРУЖУ в дома. Библиотекарь читает локально даже gitignored.
- Внутри `_log/` — папки = **отдельные `conversation`**, каждый создаётся сразу при начале разговора
  (имя: `ГГГГ-ММ-ДД-<slug>`).
- Внутри conversation:
  - **Нумерованные файлы = поэтапность диалога:** `01-request` → `02-razbor` → `03-concept` (запрос →
    разбор → результат-концепт). Номер = шаг диалога, не тема.
  - **Плюральные контейнеры БЕЗ номера:** `analyses/`, `decisions/` (если рождаются по ходу).
  - **`concept.json`** — навигатор conversation: ссылается на файлы внутри + на дома, куда ушёл результат.
- **Результат хода** = чистый **концепт** (лучше `*.concept.json`, который перечисляет), который
  библиотекарь **выкладывает в дом** (tracked). `_log` лишь указывает на него.

## Почему `_log` gitignored, а результат — в git
Анти-потеря (doc-discipline): trace = указатели (можно локально/gitignore), знание = дома (tracked,
переживают сессии). Стейджинг живёт в `_log` локально; библиотекарь фильтрует → keeper’ы в дома → коммит.
Так «инбокс» и «лог» — одно: per-conversation скретч; в git попадает только отфильтрованный результат.

## Что меняется у существующего
- `_inbox/` — **растворяется** в `_log/<conversation>/` (стейджинг теперь per-conversation). Заглушка-указатель.
- `session-logging` SKILL (R3, `logs/conversations/NN`) — **обновить под `_log` + дата + чистый запрос**
  (правка скилла = R1/R3 → через `agent-builder` по «да» владельца). Пока канон правила — здесь.
