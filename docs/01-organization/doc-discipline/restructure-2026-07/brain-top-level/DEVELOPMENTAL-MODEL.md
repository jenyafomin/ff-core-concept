# 🌳 Модель развития brain — «ХРЕБЕТ и КЛЕТКА»

> Что чинит: дерево было «по папкам, но бардак», потому что не было продуманной МОДЕЛИ роста, и
> несущие части не имели дома. Здесь — одна человеко-понятная картина + дом каждой несущей части.
> Синтез двух агентов (перепись + архитектура) поверх DEC-1..DEC-7.

## Корень бардака (одной фразой)
Семья из **5 единиц** (`node · edge · act · lens · plan-family`) — РАЗОРВАНА фасет-шаблоном: node тянуло
в `entities`, edge в `relations`, а act/lens/plan-family не имели категории → скатились в `04-mechanics`
как `*--decomp` и погреблись. Владелец мыслит их как ОДНУ первоклассную семью — шаблон их растащил.

## Одна картина: фрактал «хребет × клетка»
Дерево растёт по ОДНОЙ оси (цепочка деривации = хребет). Каждая остановка на хребте — одна и та же
КЛЕТКА (фасет-шаблон), применённая рекурсивно. Ствол → ветви → лист, и каждый лист — мини-дерево.

```
        ХРЕБЕТ (ось роста, нумерованная — DEC-1)
  01-values → 02-domains → 04-modules → platforms
  (ценности)  (4 домена-   (инфра-      (plug-in
   +идеи       модели)      модули)      поверхности)
      │            │            │            │
      ▼            ▼            ▼            ▼
 ┌──────────── КЛЕТКА (одинаковая на любом уровне) ────────────┐
 │ 01-explain · 02-entities/units · 03-relations · 04-mechanics │
 │ · 05-policy · 06-nuances  +questions/ +decisions/            │
 │ + _shared/_cross-cutting/_unverified/_archived               │
 └─────────────────────────────────────────────────────────────┘
      клетка содержит под-клетки → та же клетка рекурсивно
```

## 5 законов роста (человеко-понятно)
1. **Рождение узла: идея → дом.** `идея/вопрос (questions/ или topics/ = staging) → разбор (analyses/)
   → решение (decision + decisions.INDEX) → ДОМ (кристаллизуется в слот клетки) → углубление по фасетам`.
   Пока «путь не найден» — узел в staging. Ясно чей и в какой фасет → переезжает в дом.
2. **Полнота области — фрактальная.** Область полна, когда на «вопрос полноты» (аспект 10) есть ответ по
   клетке: `01-explain` + каждый слот ЛИБО заполнен, ЛИБО явно помечен open-question, + свой `questions/`
   и узел-представление. **Пустой НАЗВАННЫЙ пробел ≠ бардак; безымянная свалка = бардак.**
3. **Углубление по фасетам, не в ширину.** Единица растёт вглубь по слотам (explain→entities→relations…).
   Один слот = один файл ИЛИ чёткий нумерованный ряд. Куча файлов = сигнал «слот просит стать под-клеткой».
4. **Два дома механик** (см. правило-распределитель ниже).
5. **Снапшоты → `_archived`, синтез → канон.** Дубли/старые декомпозиции не удаляются и не живут в хребте:
   уходят в `_archived/` рядом, содержимое СЛИВАЕТСЯ в канон LOSE-NOTHING. Хребет держит только текущий канон.

## Дом единиц модели — семья ВИДНА (решение боли «не вижу где 4 единицы»)
Для generic-домена фасет-шаблон верен. Но `knowledge-graph` — **фундаментальный домен-субстрат, его
предмет ЕСТЬ система типов.** Peer-отношение 5 единиц («вместе образуют модель») важнее их индивидуальной
фасет-категории. Санкционированное исключение: **тип-семья субстрат-домена = слот `02-units/`.**
> → **продвинуто:** `docs/02-project/core/01-brain/03-unit/UNIT-SPEC-v1.design.md` + ADR-0009 (2026-08-07) —
> первая реализация зарезервированного слота (разблокирован рефреймом стирание→единица). Статус слота НЕ
> superseded (план шире спеки), это указатель на движение.

```
01-knowledge-graph/
  01-explain/
  02-units/          ⭐ node·edge·act·lens·plan-family — первоклассная семья, ВИДНА
                     → продвинуто: 03-unit/UNIT-SPEC-v1.design.md + ADR-0009 (2026-08-07)
    01-node/ {01-explain·02-fields·04-mechanics·05-policy·06-nuances·questions·decisions}
    02-edge/ 03-act/ 04-lens/ 05-plan-family/  _shared/
  03-relations/      ← как единицы КОМПОНУЮТСЯ (node×edge, act→node, lens⊂graph)
  04-mechanics/      ← domain-local механики, спанящие несколько единиц (reification)
  05-policy/ 06-nuances/ questions/ decisions/  · knowledge-graph.concept.json (ВИД)
```
Правило-обобщение: *домен, чей ПРЕДМЕТ — сама система типов, представляет тип-семью слотом `02-units/`,
а не размазывает по entities/relations/mechanics.* Для остальных 3 доменов шаблон работает как есть.

## Правило-распределитель механик (снимает вечный спор «passport — чей?»)
**Ось А — ПРИНАДЛЕЖНОСТЬ (не «служение»!):** механика живёт в НАИМЕНЬШЕЙ единице, которая ею ВЛАДЕЕТ —
без которой единицу нельзя понять. «Служит многим» ≠ сквозная; «принадлежит многим / никому конкретно»
= сквозная. → passport СЛУЖИТ Читаемости и Тождеству, но ПРИНАДЛЕЖИТ node (его поля) = domain-local.
policy-as-data не принадлежит ни одному узлу = сквозная.
**Ось Б — СТАТУС:** выявлена, не решена → `_unverified/` (независимо от будущего дома).
**Определение vs реализация:** дизайн механики — в модели (дом по осям А/Б); КОД — в `04-modules/M-G*`,
связь ребром `implements`. Один смысл — два адреса, не дубль.

| Механика | Принадлежит | Дом (определение) | Реализация |
|---|---|---|---|
| passport | node (identity-поля) | `02-units/01-node/02-fields/` domain-local | M-G1 |
| canonical_id | identity через весь граф | сквозная `_mechanics/` | M-G1/M-G5 |
| policy-as-data | граф-широкий контракт | сквозная `_mechanics/` | M-G3 |
| PEP (enforcement) | движок-инвариант | сквозная `_mechanics/` | движок |
| hard-erase | любой узел + Согласие | сквозная `_mechanics/` | M-G1 |
| reification | knowledge-graph (спанит node+edge внутри домена) | domain-local `04-mechanics/` | M-G1 |

## Протокол синтеза дублей (LOSE-NOTHING) — 07-14 / 07-18 / архив
Три источника на единицы: `04-mechanics/*--decomp-2026-07-14` · trace `session-handoff/2026-07-18` ·
`_archived/decomposition-pre-dissolve-2026-07-20/01-model/` (богатейший оригинал). Строим на `MERGE-NOTES-2026-07-20`.
1. **Заморозить** три источника read-only.
2. **Завести пустые канон-дома** `02-units/0N-<unit>/` (фасет-слоты).
3. **Claim-ledger** — каждое утверждение/поле/решение из ВСЕХ трёх → строка `[claim · источник · целевой слот]`.
4. **Слить в фасеты.** Совпадения — раз. **Конфликты 07-14↔07-18 → НЕ выбирать молча:** decision-узел или open-question.
5. **Провенанс** (продолжить MERGE-NOTES): каждая строка источника → адрес назначения. 0 неучтённых = условие завершения.
6. **Пометить superseded**, оставить в `_archived/`.
**Гейт:** переезд единиц в `02-units/` — ТОЛЬКО после claim-ledger = 0 неучтённых из архивного оригинала.
