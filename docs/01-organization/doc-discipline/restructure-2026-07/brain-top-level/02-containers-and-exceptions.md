# 02 · Контейнеры-исключения (без номера)

## Правило
Номер получают ВСЕ именованные узлы. **Без номера** остаются только сквозные **плюрал-контейнеры** и
**`_`-папки** (уже в R1). Для brain top-level это:

| Без номера | Роль |
|---|---|
| `open-questions/` | контейнер открытых вопросов |
| `plan/` (plans) | планы; можно складывать **целыми объектами** |
| `to-do/` | список задач (теоретически — контейнер) |
| `topics/` | стейджинг тем (см. аспект 03; обязаны мигрировать) |
| `_shared/` | сквозное |
| `state/` | **форк BR-2**: глобальный `00-states/` vs brain-local |
| `decisions` → индекс | не папка-куча, а `decisions.INDEX.md` (аспект 07) |

## Всё остальное — с номером
`overview`, `values`, `domains`/`modules`, `infrastructure`, `architecture`, `db-readiness`,
`portrait`, `scenarios`, `synthesis` → едут в нумерованный скелет (аспект 04), а не лежат россыпью.

## BR-2 — РЕШЕНО: state глобальный
`state` живёт ТОЛЬКО глобально в `docs/00-states/NN-…`. brain-local `state/` **убрать** (не оставлять даже
проекцию). Тема заводит state на глобальном уровне.

## Правило-якорь
Записать в `doc-discipline` как закрытый список контейнеров-без-номера — «чтобы всегда выполнялось
одинаково» (слова владельца). Всё, чего нет в списке → нумеруется.
