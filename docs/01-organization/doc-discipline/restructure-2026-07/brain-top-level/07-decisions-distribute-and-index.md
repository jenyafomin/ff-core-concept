# 07 · Decisions: распределить + глобальный индекс

## Смысл (голос владельца)
- Решения **распределить по местам**, где живёт то, что они решают (co-locate с механизмом/темой).
  Это уже частично так: `decisions/D1-D5`, `SPEC-DRAFT-…`, `ADR-DRAFT-…`.
- Держать **ОДИН глобальный индекс решений** — «больше как индекс», только **ссылки + перелинковка**,
  НЕ контент. Все решения линкуются из него.

## Именование (форк BR-3)
- Рекомендую **`decisions.INDEX.md`** (или `INDEX.decisions.md`) — глобальный индекс-указатель.
- Свести с текущим **`DECISIONS-LOG.md`** (он уже журнал-индекс DL-01…DL-29) → переименовать/слить в
  единый `decisions.INDEX.md`, чтобы не было двух индексов.

## Правило (в doc-discipline)
- Решение живёт в доме своей темы (`…/decisions/` темы, D-папка, SPEC/ADR).
- Глобальный `decisions.INDEX.md` = ВИД: перечисляет по id + ссылка на дом, контент не дублирует
  (как уже требует тип `decisions` в реестре: «сводный DECISIONS-LOG = журнал-указатель»).

## Что сделать (следующий этап)
1. Пройти `decisions/` — что не распределено, увести в дом темы.
2. `DECISIONS-LOG.md` → `decisions.INDEX.md` (полная перелинковка по id).
3. Зафиксировать правило именования индекса в `.doc-types.json` (тип `decisions`).
