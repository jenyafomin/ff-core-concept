# Реорг brain + реестр общих типов-разделов (решение-замок)

> Основание: голосовое владельца 2026-07-06 (GO). Это источник истины для агентов-исполнителей.
> Агенты ИДУТ по этому файлу, а не по пересказу в чате.

## D1 — Перенос brain в дерево (вариант A)
Тело работы по памяти переезжает из `topics/10-synthesis/memory-unit/` → `02-project/core/01-brain/`
**целиком** (values, scenarios, decisions, open-questions, синтезы). В `topics/` остаётся только
**сырьё агентов** (raw digs, 20-analysis, 60-raw) — как архив-источник; канон ссылается на него, не наоборот.

## D2 — Общие типы-разделы = переиспользуемые шаблоны
`values · scenarios · decisions · open-questions · todo · plan` — это НЕ «папки brainа», а **готовые
структуры** (аналогия: «домен» — заведён один раз со своей известной внутренней структурой, дальше
переиспользуется везде, где нужен). brain лишь заводит свои экземпляры этих типов.

## D3 — Реестр типов (в doc-discipline)
Отдельный **реестр** описывает каждый тип: назначение · внутренняя структура (либо жёсткая 1-2-3-4,
либо мягкие подсказки «примерно что писать») · правила версий (v1 — без суффикса; v2/v3 — с суффиксом) ·
допускаются type-специфичные расширения (напр. кнопки/поля чисто под brain — но их держим при экземпляре,
не в общем реестре).

## D4 — L0-цели не выкидываем, синкаем
Группы целей в L0 (`topics/10-synthesis/2026-07-05-L0-memory-unit.md`) — возможно и есть ценности.
L0 переносим в `01-brain/`, держим **синхронизацию «values ↔ L0»**: не регенерим, сверяемся.

## D5 — TODO ≠ PLAN
- **TODO** — плоский список всех задач (что вообще надо).
- **PLAN** — последовательность выполнения (что за чем).
- Идеал: план действий живёт в графе/базе. Пока brain не построен — распределяем чётко по папкам.

## D6 — Разводка «вопросы / задачи / решения» (чёткие дома)
Не смешивать в одну кучу:
- **вопросы владельца** (что владелец спрашивает/должен решить),
- **вопросы агентов** (что агент не понял, нужен ответ владельца),
- **задачи** (что делать),
- **решения-к-принятию** (развилки, ждут выбора).
Каждому — явный дом (тип + место). Разложить в реестре типов (D3).

## D7 — Периметр
Остальные узлы дерева (01-organization/*, 02-project/substrate, 02-agents, 03-contract, архив topics/)
тоже надо описать/дотянуть и проверить, не застряло ли где ценное содержание не на своём месте (как brain).
Сначала — sweep-разведка, потом заполнение.
