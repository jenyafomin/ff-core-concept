# Правило роста и последовательности (как заводить структуру)

> Причина появления: 2026-07-06 дважды положили РАСТУЩУЮ вещь плоским файлом (баг; сохранение сессий).
> Это правило — чтобы такое не повторялось.

## П1 — Абстракция = папка, финал = файл
- **Финал** (готовый ответ, который не будет обрастать) → просто файл.
- **Абстракция** (будет копить анализ/подтемы/версии) → **папка сразу**, внутри `INDEX.md` + рост.
- Примеры-абстракции: баг (копит анализ) → `bugs/<имя>/`; сессия (копит темы) → `sessions/<сессия>/`.

## П2 — Структуру не знаем заранее → идём последовательно, пересобираем
Мы почти никогда не знаем правильную структуру в начале. Поэтому:
1. Начинаем **последовательно**: первая тема = папка создаётся, ставится цель/начальный запрос.
2. Нумеруем/датируем (`01-…`, `2026-07-06-…`) — порядок виден.
3. Логируем/индексируем по ходу: что сделали — сразу в запись.
4. Когда форма проступила — **пересобираем** в именованную структуру (папки по смыслу/датам).

> Не пытаться угадать финальное дерево наперёд. Сначала — поток и порядок, потом — структура.

## П3 — Анти-паттерн (признак ошибки)
Кладёшь плоским файлом то, что будет расти (баг, сессия, тема, ценность) → СТОП, это папка.
