# 🧭 КОНЦЕПТ — Docs-first + захват вопросов + карта файлов в хендоффе

> Запрос владельца (2026-07-13, голос): «все вопросы всегда записывать, чтобы были сохранены и
> обрабатывались концептом на глобальном уровне; все агенты через Telegram должны В ПЕРВУЮ ОЧЕРЕДЬ
> писать документацию в файлы и концептами строить навигацию; на каждый хендофф чётко видеть, с какими
> файлами было взаимодействие. Это одно из самых главных — не хотелось бы терять. Подумать, как правильнее».

## Диагноз (почему это болит сейчас)
1. **Вопросы теряются.** Они рождаются в чате и хендоффах, но живут разрозненно (десятки `values/V*/questions.md`,
   `open-questions/`, поля «вопрос владельцу» в синтезах). Единой карты нет → ответ владельца может «повиснуть», вопрос — забыться.
2. **Chat-first соблазн.** Под Telegram-шлюзом каждый ход эфемерен (`claude -p --resume`). Если агент не положил
   суть в файл СРАЗУ — она уходит с ходом. Правило «артефакты важнее чата» есть, но не операционализировано для gateway-агентов.
3. **Хендофф не показывает касание файлов.** Видно «что обсудили», но не видно карты «прочитано/создано/изменено» —
   нельзя быстро понять область воздействия сессии и что перепроверять.

Это НЕ новый механизм памяти — это **операционная дисциплина** поверх уже решённого (skill `session-logging`:
«тема = тонкая проекция канона»). Строим НА нём, не плодим сущность.

## Три механизма (минимальные, ложатся на существующее)

### M-A. Реестр вопросов (ни один не теряется)
- Единый навигатор `docs/01-organization/open-questions/INDEX.md` (уже создан). Тонкие строки + указатель на канон, НЕ дубль.
- **Инвариант:** вопрос, заданный владельцу, но не занесённый в реестр = процессная ошибка.
- **Жизненный цикл:** `open → answered(+ссылка на решение) → parked/obsolete`. Отвеченные не удаляем (провенанс: вопрос→ответ→решение).
- Гибкость (policy-as-data-дух): статусы и формат строки — данные конвенции, не код; кластер разросся → выносится в под-папку.

### M-B. Docs-first для gateway-агентов
- Любой агент, отвечающий через Telegram-шлюз, **сначала пишет суть в файл**, потом отвечает в чат. Ответ в TG = тонкое зеркало артефакта + указатель на путь.
- Навигацию строим **концептами-навигаторами** (как FABLE-READING-PACK / этот реестр), а не свалкой: концепт = карта, где что лежит.
- Согласуется с `investigation-reporting` RULE и глобальным «Artifacts over chat». Добавляет: для gateway это НЕ рекомендация, а порядок (file → then reply).

### M-C. Карта файлов в каждом хендоффе
- В `INDEX.md`/`HANDOFF.md` сессии — обязательная секция **«Карта файлов»**: `создано / изменено / прочитано-ключевое`, с 1-строчным «зачем».
- Даёт мгновенный охват области воздействия + список для перепроверки. Дешёвая правка шаблона `session-logging`.
- Живой пример — в хендоффе `2026-07-13-loop-mechanisms-brain/HANDOFF.md` (секция добавлена этой сессией).

## Как это связать (одно предложение)
Каждый ход gateway-агента: **суть → файл-канон** (M-B) → если родился вопрос, **строка в реестр** (M-A) →
в конце сессии **карта файлов + статусы вопросов** в хендофф (M-C). Реестр и карта — концепты-навигаторы, тонкие.

## Что заложить в шаблоны (предлагается)
1. `session-logging/SKILL.md` → добавить в шаблон хендоффа секцию «Карта файлов» и шаг «свести вопросы в реестр».
2. Новый тонкий RULE `docs-first-gateway` (проектный) → «gateway-агент пишет в файл до ответа; навигация — концептами».
3. Указатель на реестр из `STATE.md` и auto-memory (точка входа новой сессии).

## 🔀 РАЗВИЛКА ВЛАДЕЛЬЦУ (одна, реально меняет объём) — Q-2026-07-13-04
Продвигать это в **ГЛОБАЛЬНОЕ** правило (`~/.claude`, все проекты и все gateway-боты) **сейчас**,
или **обкатать проектно** (только FF) и промоутить после проверки?
- **Глобально сейчас:** быстро, единый стандарт для всех ботов. Минус — конституция требует «evidence из 2+ проектов» для Universal; риск зашить сырой процесс везде.
- **Проектно → промоушен:** по правилам эволюции (project → domain → universal, с evidence и rollback). Медленнее, но безопасно и обратимо.
> Рекомендация (предварительно): **проектно обкатать 1-2 сессии → промоушен в Universal**. M-A/M-B/M-C уже работают в FF с сегодня; как только подтвердится удобство — переносим в `~/.claude/rules` одним правилом.

## Death-by-design (честно)
- Реестр без дисциплины апдейта = мёртвый список. Лечится: инвариант «не занёс = ошибка» + шаг в хендофф-процедуре (не полагаться на память агента).
- Карта файлов может распухнуть → писать только КЛЮЧЕВОЕ прочитанное, не каждый `ls`.
- Docs-first под шлюзом стоит лишний ход записи → но это ровно цена «не терять», которую владелец назвал главной.
