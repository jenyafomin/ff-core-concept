# 🐞 ТЗ — «Tool permission request failed: Error: Stream closed»

> Для запуска в чате репо **agents-manager** (шлюз/SDK-раннер). Повторяется — не первый раз.

## Симптом
Вызовы инструментов (чаще всего **Bash**, а также Edit/Write/Read) периодически падают СРАЗУ, не исполняясь:
```
Tool permission request failed: Error: Stream closed
Tool permission request failed: Error: Stream closed before response received
```
Интермиттит: иногда восстанавливается в той же сессии, иногда лежит подряд много вызовов.

## Влияние
- Рвёт файловые операции посреди задачи (миграция, починка ссылок) → работа наполовину, нужны повторы = потеря контекста.
- **Убивает фоновых субагентов:** субагент (agent-builder) поймал отказ на КАЖДОМ Bash/Write/Read ~12 раз подряд, не смог применить ни одной правки, прервался.
- Недетерминированно → нельзя доверять «сделано».

## Свидетельства (сессия FF, 2026-07-19)
- Множественные `Bash`-вызовы вернули дословно `Tool permission request failed: Error: Stream closed`.
- Фоновый субагент — отказ на всех инструментах весь свой прогон; при этом `test -r` показывал, что файлы физически читаемы (т.е. проблема в КАНАЛЕ разрешений, не в файле/правах).
- Позже канал сам ожил (Edit/Write прошли) — подтверждает транзиентность.

## Гипотеза (где копать в agents-manager)
Канал ответа на запрос разрешения (`canUseTool` / permission-prompt IPC между шлюзом и Claude-SDK-раннером)
**закрывается до доставки ответа** → SDK отклоняет инструмент с «Stream closed». Вероятные триггеры:
1. **Конкуренция/дубли ходов** (известный gateway dup-bug): дубль входящего сообщения / параллельный ход
   гонятся за одним permission-стримом и рвут его. (Связать с `../gateway-dup/INDEX.md`.)
2. **Фоновые субагенты** — их tool-permission не проброшен/не held-alive отдельным каналом на время жизни субагента.
3. **`claude -p --resume`** при пересборке хода роняет in-flight permission-стрим.
4. Таймаут/преждевременный close stdio/IPC в раннере.

## Где смотреть (файлы)
SDK-раннер и обработка разрешений в `agents-manager/src/**`: спавн `claude -p`, wiring `canUseTool` /
permission-mode, и особенно как проброшены tool-permissions для фоновых/дочерних агентов.

## Репро
Ход с множеством Bash-вызовов и/или фоновым субагентом, делающим файловые операции → наблюдать интермиттентный
«Stream closed»; скоррелировать с дублем входящего сообщения / параллельным ходом.

## Направление фикса
- Держать permission-стрим живым на весь ход, включая субагентов; переустанавливать при close.
- Ретрай/бэкофф на транзиентный close ДО того как вернуть инструменту ошибку.
- Для доверенного проекта — permission-mode `bypass/acceptEdits`, чтобы tool-calls не зависели от живого prompt-стрима.
- Защита от dup-message concurrency, ломающей стрим активного хода (общий корень с dup-bug).

## Критерии приёмки
- 100+ подряд Bash/Write в одном ходе → **0** «Stream closed».
- Фоновый субагент на 20 файловых операций → завершается без отказа канала разрешений.
- Дубль входящего сообщения НЕ ломает permission-стрим активного хода.
