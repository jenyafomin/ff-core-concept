# БАГ шлюза: фоновые агенты не переживают рестарт процесса → владелец получает тишину

> Дом починки — шлюз `agents-manager` (`/Users/mac16/Documents/IT/Apps/TOOLS/agents-manager`).
> Зафиксировано на живом инциденте 2026-07-27 (постройка M1 инжеста аренды).

## Симптом
Агент, запущенный **в фоне** (`run_in_background`) в рамках хода, **не переживает завершение процесса
хода**. Шлюз гонит каждый ход как свежий `claude -p --resume` (см. проектный `CLAUDE.md`), и когда процесс
хода заканчивается, in-flight фоновый агент повисает/умирает. Владелец видит **тишину** — «ответа нет».
При возобновлении приходит уведомление вида `stopped · No completion record found ... may have been running
when the previous process exited`.

## Наблюдавшийся случай (2026-07-27)
- Запущен builder #2 (3b, ingest-адаптер) в фоне → процесс хода завершился → агент помечен `stopped`.
- Партиал НЕ потерян: транскрипт + частичная работа осели на диске (пакет `packages/ingest-rentacar/`
  был записан и даже собрался). Восстановлено проверкой диска + догоном синхронно. Но **если бы не проверили
  диск — выглядело бы как «молчание»/провал**.

## Родственные режимы отказа (один класс — «шлюз ломает асинхронность/интерактив»)
- **Дубль сообщения убивает фоновых агентов** → `../gateway-dup/INDEX.md`.
- **AskUserQuestion не доставляется** (кнопки теряются) → `../gateway-askquestion-not-delivered/INDEX.md`.
- **Разрыв MCP/стрима прав** → `../gateway-tool-permission-stream/TZ.md`.

## ⚖️ Закон для агента (обход, пока шлюз не починен)
1. **Под шлюзом/в нестабильной среде — НЕ полагайся на фоновых агентов для работы, чей результат нужен
   позже.** Запускай существенных агентов **синхронно** (`run_in_background:false`) ИЛИ делай работу инлайн.
2. **Делай работу резюмируемой:** артефакты пиши на диск кусками (не держи знание только в памяти агента),
   каждый шаг — отдельным файлом/коммитом, чтобы обрыв не терял прогресс.
3. **При «молчании»/`stopped` — сначала проверь диск** (партиал агента), потом догоняй, и **сразу скажи
   владельцу**, что был обрыв (не выдавай тишину за провал).
4. Вопросы владельцу — **обычным текстом** (не AskUserQuestion), варианты списком.

## 🔧 Директива на починку (дом — `agents-manager`; для будущей сессии)
> Владелец (2026-07-27): «надо это явно пофиксить, запустить параллельно агентов пусть пофиксят — может со
> следующего хендоффа получится в другом проекте запустить агента». → НЕ делаем сейчас (другой проект, идёт
> M1); заводим готовую директиву, которую следующая сессия подхватит.

**Задача (в проекте `agents-manager`):** сделать так, чтобы работа, начатая в ходе, переживала рестарт хода —
одно из:
- **(a)** detach/persist фоновых задач между `--resume`-ходами (супервизор процессов вне жизни одного хода);
- **(b)** при рестарте — **подхватывать** незавершённые задачи и **доставлять** их результат (не терять «молча»);
- **(c)** как минимум — доставлять владельцу **явный сигнал** «фоновая задача оборвана/висит», а не тишину.
- Сопутствующе закрыть родственные баги (dup-kill, AskUserQuestion-проброс) — один класс.

**Следующий шаг:** в новой сессии открыть `agents-manager`, поднять разбор (analyst+architect), проверить
ADR-0001 (sdk-runner) / ADR-0002 — где рвётся жизненный цикл хода vs фоновой задачи, и спланировать фикс.
