# F3 — Ось уровня `02-project` + `core→01-core`

## Вопрос
Кто **равноправные звенья** оси `02-project` — и является ли `substrate` звеном или дублем brain?
Нумеровать `core→01-core` после F1/F4.

## Варианты
- **(А)** `substrate` — самостоятельное звено оси.
- **(Б)** `substrate` — дубль brain (свести, не плодить).

## Ход мысли — что учесть (открыто, не исчерпывающе)
- Это же — путаница про `substrate` из уборки (та же тема, поверхность решения).
- Нумерация звеньев зависит от F1 (домены) и F4 (узел «платформа» может добавить звенья).

## От чего зависит / downstream
- F1 (домены), F4 (платформа может добавить звенья в ось).

## Ход мысли — раунд 2026-07-22 (проверка по дереву)
- **KEY-рефрейм (CLAUDE.md, msg 141)** уже утверждает: «база знаний — это рабочий СУБСТРАТ для ИИ-агентов»
  → brain и substrate называют ОДНУ сущность (agent-first граф узлов), не две.
- **Проверка по факту дерева, не по памяти:** `docs/02-project/substrate/INDEX.md` — единственный файл в
  папке, статус `draft` от 07-06, 4 буллета: (граф-узлов-как-продукт, движок библиотека/сервис, проекции
  БД→файлы, клапан на внешние действия). `docs/02-project/core/01-brain/02-infrastructure/01-overview/`
  уже содержит именно эту территорию **глубже и дальше спроектированную**: `architecture-README.md`,
  `MODULES.md`, `stack/`, `db-readiness/`, `scenarios/`, `infrastructure-open-questions.md`. Ни один из
  4 буллетов substrate не несёт уникального контента — это ранний конспект того, что brain уже прожил.
- **`docs/INDEX.md` (карта, актуальна на 07-21) уже фиксирует этот же вывод** в «Плане уборки»:
  `02-project/substrate/` 🔴 «почти пустой дубль brain-as-substrate → свернуть в 01-brain», риск низкий.
  F3 не открывает новый вопрос — ратифицирует уже увиденное владельцем/картой решение.
- **F1 (домен = data-субъект)** усиливает вывод: у нас один честный субъект данных — `knowledge-graph`.
  substrate как «отдельное звено» подразумевало бы второй data-субъект рядом с brain — его нет: это тот
  же субъект, увиденный с угла «граф/БД/движок» вместо угла «единица памяти».
- **Равноправные звенья оси `02-project`, как они реально стоят в дереве сейчас** (без substrate):
  - `core/` (→ нумеруется `01-core` после F1/F4) — узел связи двух ядер: `01-brain` (единица памяти /
    субстрат-граф — забирает контент substrate) · `02-agents` (руки) · `03-contract` (стык brain↔агенты);
  - `open-questions/` — plural-контейнер (без номера, закон №6 doc-tree.md), не звено оси, а сквозной сбор
    вопросов уровня проекта.
  - F4 (узел «платформа»/«модуль») может добавить ещё одно звено рядом с `core` — нумерация ждёт этого.

## РЕШЕНИЕ: **Б — `substrate` дубль brain, свести (LOSE-NOTHING)** (синтез 2026-07-22, ждёт кивка владельца → ADR)
1. `substrate` не самостоятельное звено оси `02-project` — это тот же субъект данных, что и
   `core/01-brain` (совпадает с KEY-рефреймом CLAUDE.md и с F1 «домен = data-субъект», единственный
   честный субъект — `knowledge-graph`).
2. **Направление слияния (LOSE-NOTHING):** контент `docs/02-project/substrate/INDEX.md` → в
   `docs/02-project/core/01-brain/02-infrastructure/01-overview/` (уже держит architecture/MODULES/stack/
   db-readiness/scenarios на эту тему). Ни один из 4 буллетов substrate не уникален относительно уже
   спроектированного там — переносим как со-размещённую датированную версию (закон №10 doc-tree.md), не
   стираем; если ревизия при слиянии найдёт расхождение — фиксировать отдельным open-question, не молчать.
3. После слияния `docs/02-project/substrate/` пустеет → редирект-заглушка на `01-brain/INDEX.md` (закон №9,
   дубли гасим редиректом, не удалением) либо папка убирается, если заглушка избыточна — решает исполнитель
   при переезде (R-строй), не блокирует канон.
4. **Равноправные звенья оси `02-project` (текущее состояние, до F4):** `core` (→ `01-core`) и
   plural-контейнер `open-questions` (без номера, не звено). `core` внутри держит `01-brain · 02-agents ·
   03-contract`.
5. **Нумерация `core → 01-core` — pending F4.** F4 (узел «платформа»/«модуль») может добавить звено рядом
   с `core`; финальный порядковый номер и полный список звеньев фиксируются только после F4 закрыт.
