# 🔎 Разбор 9 форков — компаньон к review

> **Зачем этот файл.** `README.md` = сухая таблица-навигатор. Здесь — «человеческий» разбор перед
> твоим кивком: по каждому форку **что решили · ГДЕ СУЗИЛИ ВЕКТОР (что закрыли) · на что смотреть · хвост**.
> Это ВИД, не второй дом истины: сами решения живут в `Fn/README.md`, консолидация — в ADR-0005.

## Сквозная линия — куда в целом сузился вектор
Мы шли не «графом всех возможностей», а сходились к узкому честному хребту. Три принципа, которые
связали почти все 9 решений (полезно держать в голове при ревью):

1. **Promotion-by-evidence — не раздувать онтологию раньше доказательств.** (F2, F4, F5.) Везде, где
   был соблазн завести новую сущность/ярус/тип «на будущее», мы сказали «нет, вводим по факту».
2. **Расщепление слов-омонимов.** (F1 «домен», F4 «платформа/модуль».) Слово, тащившее два смысла,
   разводится на два понятия — шов исчезает.
3. **Один арбитр вместо конкурирующих канонов.** (F9, и через него F7/F8.) Спайн `data-canon` —
   единственный источник истины; остальные доки уступают.

> Суть «сужения»: из широкого веера мы каждый раз выбирали **минимальную честную модель** + **checkable-
> предикат**, а не богатую-но-недоказанную структуру. Это осознанный крен в простоту и проверяемость.

## Пофорковый разбор

### 🚨 F1 — домен = субъект данных (не кластер ценностей)
- **Решение:** «домен» = data-субъект (регион, где анатомия примитива специализируется под правила).
- **Что сузили:** закрыли ветку «домен = 4 кластера забот (D1–D4)». Значит `02-domains` **больше НЕ
  выводится из 7 ценностей** — целая ось деривации отменена. Это самое крупное сужение из всех.
- **На что смотреть:** у слова теперь один смысл — но появился **безымянный концепт** (бывший D1–D4).
  Пока он без имени, путаница вернётся.
- **Хвост:** ⚑ назвать концерн-кластер ценностей.

### F2 — `02-units/` = исключение (n=1), не закон
- **Решение:** держим `02-units/` как один санкционированный случай, не возводим в общий закон.
- **Что сузили:** НЕ открываем машину «каждый домен получает units-слот по предикату». F1 починил
  *определение*, но второго реального случая нет → закон не рождается.
- **На что смотреть:** предикат записан как `experimental`; станет законом **только при 2-м реальном случае**.
- **Хвост:** — (авто-триггер при 2-м кандидате).

### F3 — `substrate` = дубль brain → слить
- **Решение:** свести `substrate` в `core/01-brain/02-infrastructure/01-overview/` (LOSE-NOTHING).
- **Что сузили:** не заводим `substrate` отдельным звеном оси `02-project`. Одно поколение мозга, не два.
- **На что смотреть:** нумерация `core→01-core` ждёт F4.
- **Хвост:** выполнить слияние (после кивка).

### F4 — НЕ вводить node_type «платформа»; расщепить платформа/модуль *(решал Fable)*
- **Решение:** «платформа» = сам субстрат+рантайм; «модуль» = композиция примитивов (1 manifest-узел +
  membership-рёбра + lens). Нового типа-тега нет.
- **Что сузили:** отказ от нового `node_type`. **Plug-in = обязательство перед КОНТРАКТОМ (граница+manifest),
  а не перед тегом-типом.** Это прямо в жилу твоей vision о модульности.
- **На что смотреть:** граница **конвенциональна** (manifest+рёбра), не типо-enforced → без линт-предиката
  возможны «дырявые» модули.
- **Хвост:** линт-предикат модуля (позже). Предикат: (1) ровно один manifest-узел, (2) все внутренние
  единицы достижимы от manifest по membership-рёбрам, (3) наружу — только через заявленные контракт-точки.

### F5 — ярус `_shared/` не вводить (пока)
- **Решение:** два уровня (domain-local ↔ сквозной); отдельный `02-units/_shared/` не заводим.
- **Что сузили:** не добавляем третий уровень «на будущее» — хватает стандарта `_shared/`+теги.
- **На что смотреть:** промоутим ярус по факту (2+ passport-контракта).
- **Хвост:** —.

### F6 — `hard-erase` дом = `07-soglasie`
- **Решение:** один дом — право на забвение принадлежит Согласию, служит всем.
- **Что сузили:** отвергли вариант «два дома» (SPEC + механика). Закон одного дома.
- **На что смотреть:** сквозная видимость — тегом/тонким указателем; enforcement — обязанность движка.
- **Хвост:** —.

### F7 — `reification` = сквозной
- **Решение:** реификация — базовая операция движка, не собственность одного домена.
- **Что сузили:** сняли конфликт Router↔AUDIT-MAP в пользу сквозного.
- **На что смотреть:** ⚠️ вывод по смыслу термина — **до простановки `Supersedes` сверить с DEVELOPMENTAL-MODEL**.
- **Хвост:** ⚑ сверка `reification` с DEVELOPMENTAL-MODEL.

### F8 — `category-taxonomy` закрыть
- **Решение:** закрыть форк (категория = грань графа); GROWTH-MAP уступает канону.
- **Что сузили:** не держим тему открытой из-за одного рассинхронного дока.
- **На что смотреть:** действие = ратифицировать в `decisions.INDEX` (DL-09/DL-10) + пометить GROWTH-MAP `Supersedes`.
- **Хвост:** ⚑ внести закрытие в `decisions.INDEX`.

### F9 — единый арбитр = спайн/`data-canon`
- **Решение:** один источник истины; при конфликте спайн побеждает.
- **Что сузили:** отвергли «по-темам победитель» (это плодило бы будущие рассинхроны).
- **На что смотреть:** проставить `Supersedes` в DEVELOPMENTAL-MODEL / 11-facet / AUDIT-MAP / GROWTH-MAP.
- **Хвост:** ⚑ проставить 4 `Supersedes`-пойнтера.
