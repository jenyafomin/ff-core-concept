# Data Canon — каноны субстрата (модель данных / БД)

> Правила, которым обязан подчиняться граф узлов. Это НЕ проектирование фичей,
> а инварианты хранения истины (файлы = истина, связи по id).

## 🦴 Хребет (читать первым)
- **[VOCABULARY-SPINE.md](./VOCABULARY-SPINE.md)** — словарь-хребет: канон имён
  (единица · примитив · домен · doc-type) + рефрейм «дерево = единица памяти» +
  механизмы самоописывающего контекста. Устоявшийся хребет, от него всё вниз механикой.
- **[spine.concept.json](./spine.concept.json)** — единый концепт-линза (само-описание всего дерева,
  detectConcept-валиден). Прошёл тест: слепой агент ориентируется по нему одному.
- **[CONFUSIONS-REGISTER.md](./CONFUSIONS-REGISTER.md)** — системное само-разрешение путаниц
  (STATE vs 00-states, topics архив/стейджинг, `_archived`≠мёртвое…). Холодный агент достаёт ответ отсюда. Растёт.
- **[forks/](./forks/)** — 9 открытых форков владельцу, каждый = узел-папка (блокер F1) + навигатор/приоритет/план следующих действий (R-A/R-B) в `forks/README.md`.

Что сюда кладём:
- ADR по схеме узла, паспорту, рёбрам, движку (когда ратифицированы → сюда как канон).
- Инварианты (конституция ячейки, единый порог доступа, право на забвение).
- Правила: DATA («что я есть») · DB («что мы вместе») · CONSTITUTION («что нельзя нарушить»).
- Пока БД нет — активная проработка живёт в `docs/topics/10-synthesis/memory-unit/` (см. 02-project/core/01-brain).
