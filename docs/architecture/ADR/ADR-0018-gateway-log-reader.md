# ADR-0018 — Читатель над логом шлюза

Потребитель: лид (подключение к пробному топику), агент топика · Поглощает: ничего

## Context
Владелец («строй», 2026-10-12): нужен читатель над логом шлюза, чтобы агент в топике видел, что владелец
писал, и это применить на практике. Лог — SQLite `data/gateway-ff-personal.db`, таблица `messages`
(нет колонок chat/thread/forward; chat+thread внутри `sessionKey`; `channelMessageId` только у `in`).
Текст хранится как есть, с паролями/URI-кредами; пересланное третьих лиц помечено лишь текстовым
префиксом. Шлюз живой (pm2), его код и главный чекаут трогать нельзя. Это интеграция шлюз↔память → ADR.

## Decision
1. **Отдельный пакет `@ff/gw-reader`, stdio MCP, только чтение.** БД открывается на вызов
   `node:sqlite` `readOnly: true` + `PRAGMA query_only=ON`, сразу закрывается. Ни миграций, ни записи.
2. **Адрес** `gw:<chatAlias>/t<thread>/m<channelMessageId>`, `chatAlias` = 6 hex `sha256(chatId)`,
   `t0` — без топика. Адресуемы только `in` с `channelMessageId`. `resolve` сверяет alias+thread+mid,
   коллизия → `ambiguous`; дубли шлюза одного сообщения схлопываются.
3. **Fail-closed фильтры до модели:** только владелец (`GW_READER_OWNER_ID`) и `direction=in`;
   пересланное исключается по маркеру `[Пересланное сообщение` в любом месте текста; секреты —
   построчная замена строки целиком, флаг `redacted`; поиск — по уже скрытому тексту; выдержка ≤300;
   stderr — только счётчики. Три яруса фильтра (ред-тим 2026-10-12, B1–B7): **сильное слово**
   (пароль/пасс/pw/parol/опечатки/leet/seed-фраза/CVV) где угодно → строка + следующие 2 непустые
   строки + **следующее сообщение того же топика в пределах 10 мин целиком** (окно переноса, fail-closed,
   без эвристики «короткое»); **слабое** (токен/ключ:/доступ:/логин:/пин/код доступа) — только с
   разделителем или значением рядом; **формы без слов** (вендорные префиксы, URI, ip:порт:логин:пароль,
   `-pXXX`/`--password=`, `x / y` рядом с root/admin/логин, номер карты по Luhn). SQL — `LIMIT 5000`.
4. **Метки владельца** (`open|closed|mute`) — append-only JSONL в собственном файле читателя
   (`GW_READER_LABELS`, деф. `~/.ff-gw-reader/labels.jsonl`), последняя побеждает. БД шлюза не пишется.
5. **Подключение без кода шлюза — ТОЛЬКО в отдельном cwd одного топика** (ревью M2): читатель через
   `.mcp.json` виден всем сессиям этого cwd, поэтому cwd не должен быть общим с другими топиками
   (не корень проекта). `.mcp.json` в cwd пробного топика + разрешение в
   `.claude/settings.local.json` (SDK-раннер грузит project-настройки, `settingSources` не задан).
   Рестарт шлюза не нужен. Подключает лид после ревью.

## Alternatives
- **Команда `/open` в шлюзе** — читает владелец, а не агент; правка `command-handler.ts` + рестарт. Отклонено.
- **Запись в `buildMcpServers` (а3)** — правильная целевая форма (идентичность хода в env, авто-allow),
  но правка живого кода, рестарт и конфликт с dedup-веткой. Отложено до разбора dedup.
- **Bash-скрипт + промпт** — агент может вызвать `sqlite3` напрямую и обойти фильтр. Отклонено.

## Consequences
- (+) Агент видит историю владельца без секретов и чужих пересланных; адрес стабилен и резолвится.
- (+) Ноль изменений шлюза; откат = удалить запись из `.mcp.json`.
- (−) Через `.mcp.json` читатель виден всем топикам/сессиям этого cwd и не знает свой топик: область
  задаёт агент аргументом. Поэтому проба — в отдельном cwd одного топика; allowlist топиков — позже.
- (−) Фильтр секретов эвристический и намеренно перекрывает с запасом (ложные скрытия допустимы).
- (−) Цитата чужого текста в ответе владельца маркера не несёт — известный пробел V7.
- (−) Метки пишутся под каноническим адресом (из `resolve`); строки журнала с невалидным адресом
  при чтении пропускаются.
- (−) `node:sqlite` экспериментален в Node 22 (предупреждение в stderr; глушится `--no-warnings`).

## Известные пробелы (фильтр секретов — не единственная защита)
Фильтр построчный и словарный; энтропия коротких значений (<32 симв.) не считается. Пройдёт:
- **Парольная фраза словами без ключевого слова** («correct horse battery staple» отдельным сообщением
  через >10 мин или с другим словом-вводом) — неотличима от речи.
- **По буквам / по одной цифре** в сообщении без слова-триггера («ку семь е три эр»); «п а р о л ь»
  по буквам ловится, значение по буквам в следующем сообщении — только окном переноса (≤10 мин).
- **Голый пароль без контекста** (`Tr0ub4dor` отдельным сообщением, без «пароль» в предыдущем сообщении
  топика за 10 мин); исключение — leet-формы самого слова (`P@ssw0rd`).
- PIN/код без слова-триггера, SMS-код без «смс/код доступа», редактированные сообщения (edit) и
  caption вложений — не проверены отдельно.
- Цена fail-closed: обсуждение паролей как темы («менеджер паролей», «пароли в мозге») скрывается
  (4 из 15 безобидных в ред-тиме), плюс следующие 2 строки и следующее сообщение топика за 10 мин.
Вторая линия: окно `days` ≤30, только владелец, подключение в одном топике (D5).

## Validation plan
- Тесты пакета на tmp-фикстурах: запись через соединение падает; amqp/пароль/password/token/ghp/PEM не
  в выходе; ред-тим-фикстуры `test/fixtures/redteam.ts` (50 вражеских — все скрыты, 15 безобидных —
  ≥10 проходят); окно переноса в `recent` и `resolve`; пересланные/чужие/`out` исключены; адрес однозначен при двух чатах с одним thread; выдержка
  ≤300 и тел нет в stderr; импорт ничего не запускает; метки только в своём файле.
- Смоук на живой БД read-only: только счётчики (`npm run smoke:live -w @ff/gw-reader`).
- После подключения: `git status --porcelain` главного чекаута шлюза до/после идентичен; один ход в
  пробном топике; решение о (а3) — после живого прогона.
