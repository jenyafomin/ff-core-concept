# ADR-0014 — Стратегия интеграции: память-субстрат ↔ агент-рантайм

## Статус
**proposed** — ждёт ратификации владельца. На диск лёг как решение-запись (чтобы не потеряться в чате); enforcement/стройка — по «строй».

## Контекст
DeepSeek Harness (MIT, TypeScript, мета-фреймворк Cordis, «всё — плагин») — работающий прецедент нашего же тезиса (D1 память-как-субстрат, D2 микросистемы, plug-in с 1-й итерации). Владелец: агентные системы плодятся быстро, но **единой системы памяти на рынке нет** — это наш зазор и продаваемое ядро (суверенность/переносимость единицы, V5). Вопрос: **как соотносятся наша память-субстрат и агент-рантайм** — брать готовое (Harness) или строить своё. Исследование в `07-harness-prior-art-study/` (2 волны скаутов + помощник + 3 критика + аггрегатор-тест).

## Решение
1. **Буквальная α «посадить Harness на нашу память» — отклонена как некогерентная.** Cordis владеет своей моделью состояния/сессий (`Context` = Proxy, `inject`-имена мертвы вне его рантайма, `SESSION_FORMAT_VERSION=0`); α по факту схлопывается в γ («наша память = один плагин среди 78 в ИХ рантайме»).

2. **Курс — δ: заимствуем ДИЗАЙН-ПАТТЕРНЫ Cordis (не код), рантайм = эволюция approved SDK-раннера Движа (ADR-0001).** Ноль кода Cordis.
   **Основание (честное, после критика — НЕ «δ быстрее к данным»):** δ — **структурно безопаснейший по V5** (policy/consent негде утечь, кроме поля единицы), **ноль операционного lock-in** к чужому dev-preview, **строит на том, чем уже владеем**. Заимствуемые паттерны: approval-как-свёртка-событий над append-only логом (почти точное совпадение с нашим `domain_event`), effect-scope disposer + LIFO-teardown, активация-по-доступности, isolate для мульти-tenancy.

3. **γ — задокументирован как отложенный вариант С ЯВНЫМ ТРИГГЕРОМ (правило двух, ADR-0009), не расплывчатым «на потом».** γ = FF владеет внешним циклом (session/consent/policy, истина в графе), Cordis-подсистемы (sandbox/mcp/lsp) — за FF-портом `execute(capability, op, args, grant) → lossless-JSON + provenance`. Включаем ТОЛЬКО когда появится конкретный второй прецедент, требующий их машинерии.

4. **Аггрегатор-тезис ратифицирован в ОГРАНИЧЕННОЙ форме:** память держит как ДАННЫЕ *состояние/топологию* любого паттерна (тождество, append-only история, рёбра-зависимости, словарь состояний — несколько почти точных совпадений с каноном Ц2/Ц3). Память НЕ кодирует как данные *живой движок* (реактивный DI, рендер-цикл — это исполнение). Это ровно наша доктрина **policy-as-data** (движок ИСПОЛНЯЕТ политику-данные, политика ≠ движок).

5. **Продаваемое ядро (переносимая единица с policy+схемой как данные) строим при ЛЮБОМ варианте** — это продукт, не рантайм.

## Честные условия (критик Этапа 3 — обязаны быть зафиксированы, не заметены)
- **C1.** Баллы рубрика **γ≈83 vs δ≈81.5 — почти НИЧЬЯ** (V3/V6 не нормализованы на одной линейке). Решение опирается на суверенность-безопасность + отсутствие lock-in + «строим на своём», а НЕ на разрыв 1.5 балла.
- **C2.** **run-logger (IRunLogger) ортогонален выбору γ/δ** — строится параллельно при любом. Не приписывать δ «скорость», которой у неё уникально нет. **Телеметрия agent-run ≠ перепись реальных жизненных эпизодов владельца** — два разных потока данных; committed-триггер стройки = реальные данные, не телеметрия.
- **C3.** **Consent/`hard_erase`-гейт спроектирован ДО первой строки кода IRunLogger** — иначе повтор класса регрессии P8 (сырые события append-only без согласия).
- **C4.** Форму Cordis `undefine()` (hard-delete без надгробия) **НЕ заимствовать** — противоречит нашему канону Ц2/Ц7 (tombstone).

## Рассмотренные альтернативы
- **α** (Harness на нашей памяти) — отклонена (некогерентна, п.1).
- **β** (свой рантайм с нуля, greenfield) — поглощена δ (дороже без выигрыша к суверенности).
- **γ** (Cordis-исполнитель за нашим портом) — не отклонена, **отложена с триггером** (п.3).
