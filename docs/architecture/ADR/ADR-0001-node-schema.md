## Контекст
Глубокий разбор C2+C3 (4 линзы) сошёлся на форме узла, но два решения оставались за владельцем. Владелец ответил:
- **Q-A (автономия):** всё сразу видно ИИ; ИИ не ограничен; ему видно, что он делает. → Нет стейджинга.
- **Q-B (форма):** НЕ наследуем Obsidian. БЗ — рабочий субстрат для ИИ-агентов («всё, с чем работают агенты»),
  не хранилище заметок. Файл — один из типов, не центр.

## Решение

### Принципы
1. **Agent-first, не notes-first.** Узел — единица, с которой работают агенты. Человекочитаемость — следствие
   (markdown+frontmatter), не цель формата.
2. **Файлы = истина** (md+frontmatter, git-друж), но БЕЗ привязки к vault Obsidian. Связи по стабильному `id`,
   не по `[[wikilink]]`.
3. **Всё видно ИИ.** Эпистемический статус — информационная метка, НЕ стена. «Клапан» доверия применяется к
   ВНЕШНИМ необратимым действиям, не к видимости/чтению графа.
4. **Две ортогональные оси статуса:** `epistemic` (доверие) ⟂ `state` (рабочий процесс).
5. **Один логический дом + N связей.** `home` = указатель (id), re-home = правка поля.
6. **Открытые типы.** Ядро + модульные типы с наслоённой валидацией; `type@version`.

### Каноническая схема (frontmatter + тело)
```yaml
# IDENTITY
id: <ULID>                 # стабильный, неизменный, КЛЮЧ связей (≠ имя файла, ≠ title)
type: <string>             # открытый реестр: базовые + модульные типы
schema: <type@version>     # какой валидатор применён (миграции)
title: <string>            # короткий ярлык
description: <string>      # 1-2 строки, ВСЕГДА; то, что агент читает первым (agent-first резюме)
# body = markdown ниже frontmatter (полный контент, L3)

# TIME (ось ВРЕМЯ)
created: <iso>             # системное время файла
updated: <iso>
occurred: <iso?>           # когда событие/факт реально случились
valid_from: <date?>        # битемпоральность: интервал истинности
valid_until: <date?>       # null = всё ещё истинно
supersedes: <id?>          # заменяет этот узел (история, не удаление)

# BELONGING (ось ПРИНАДЛЕЖНОСТЬ) — РОВНО один логический дом
home: <node-id?>           # указатель; источник каскада контекста+важности; re-home = правка поля
                           # (НЕ папка, НЕ wikilink). null только для inbox/корня.

# TRUST (ось ДОВЕРИЕ) — ортогональна, ИНФОРМАЦИОННАЯ (не стена видимости)
epistemic: proposal | fact | hypothesis | archived

# WORKFLOW — отдельная ось, определяется типом
state: <type-defined?>     # task: open|doing|blocked|done; др. типы — своё или пусто

# ENRICHMENT (маркер прогресса C3)
stage: inbox | routed | enriched

# EDGES — N типизированных рёбер по id; мульти-принадлежность ЖИВЁТ здесь
links:
  - to: <node-id | url>
    rel: <string>          # involves | triggered-by | sample-of | also-serves | supersedes | …
    href: <bool?>          # true = внешняя цель (url/git-commit), не узел

# IMPORTANCE
importance: 1..5           # ручная, контекстна дому; + наследование/touch (НЕ центральность)

# PROVENANCE / OBSERVABILITY
actor: user | agent:<id>   # кто создал (видимость «что делает ИИ»)
source: <string?>          # откуда сырьё (telegram:msg/141)

# TYPE PAYLOAD — валидируется type@version (не «свалка»)
<typeBlock>: { … }         # measurement:{metric,value,unit} · person:{handles,role} · …

tags: [..]                 # сквозные фасеты/направления, НЕ принадлежность
```

### Границы (СКИЛ / АГЕНТ / ДВИЖОК) — без изменений из разбора
- **ДВИЖОК `@ff/core`** (без ИИ): сериализация frontmatter↔узел, реестр+валидация, механика `route()`
  (запись, set stage, цикл/глубина-гарды), целостность ссылок.
- **СКИЛ:** `extract` (сырьё → ProposedNode[], всегда `epistemic:proposal`), политика `route` (предложить дом).
- **АГЕНТ:** Библиотекарь (зовёт extract/route), Inbox (захват), Хранитель (обогащение, переходы доверия).

### Поток (из Q-A: всё в графе)
`raw → (extract) → узел epistemic:proposal, stage:inbox, СРАЗУ в графе и виден агентам`
→ `(enrich батчем) → links/typeBlock/importance, stage:enriched`
→ `(повышение доверия) → epistemic:fact` (логируется трейс-узлом = лог доверия/«клапан»).
Внешние необратимые действия требуют доверия/апрува; чтение и внутренняя работа графа — нет.

## Альтернативы (отклонены)
- **Стейджинг вне графа** (узлы невидимы до апрува) — отклонено владельцем (Q-A: ИИ не ограничен, всё видно).
- **Obsidian-совместимый формат / папки-дома / wikilink-связи** — отклонено (Q-B: БЗ ≫ файлов; связи по id стабильнее).
- **Одно поле `status`** — отклонено (смешивает доверие и процесс; корень бардака).
- **Мульти-родитель с каскадом** — отклонено (недетерминированная важность/контекст).
- **Закрытый enum типов** — отклонено (блокирует модульность).

## Последствия
- (+) Прямо обслуживает модульность и автономию: открытые типы + всё видно ИИ + наблюдаемость через actor/трейсы.
- (+) Axis B растворена (дом = привилегированное ребро по id), Axis C (доверие) и время — first-class.
- (−, принято) ИИ видит и может опираться на непроверенные `proposal` — митигируется тем, что epistemic
  всегда в контексте + внешние действия за «клапаном» + дедуп перед созданием.
- (−, принято) Свои виды/навигацию строим сами (Obsidian-рычаг убран) — см. обновление C6 в карте возможностей.
- Требует переписать `@ff/core/node.ts` (diff: `docs/council/raw/2026-06-15-c2c3-extract-route/architect.md` §5,
  с заменой wikilink→id, folder→logical home).
