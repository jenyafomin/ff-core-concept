## Контекст

Свидетель целостности `payloadHash` (ADR-0007 §a) стоял на неразрешимом противоречии для **низкоэнтропийного
PII** (телефон, email, номер документа — перечислимое пространство ~10⁹ кандидатов):

- **Ц-3 Доверие** требует, чтобы hash **персистил** в иммутабельном логе — свидетель непорченности payload
  относительно immutable-акта.
- **Ц-7 Согласие** требует, чтобы после стирания содержимое было **неподтверждаемым НИКОМУ** — а голый
  `sha256(телефон)` в вечном логе есть **оракул**: дан кандидат X → пересчитал → подтвердил «стёртое было X».

Для низкоэнтропийного содержимого «пост-erasure верифицируемость» и «оракул-подтверждение» — это **одна и та
же способность**, а не две сцепленные (проверка = реконструкция, когда пространство кандидатов перечислимо).
Значит нельзя оставить одну и убить другую. Тот же шов рекурсивно бьёт по **выхлопу самого стирания** —
монумент-tombstone «стёрто по требованию R» несёт опознающее содержимое (атрибуция требователя = персональный
факт о R) ПОСЛЕ стирания.

Опора — тот же порядок арбитража: **Конституция > policy-as-data > integrity-as-engine-duty**. Свидетель как
функция admission-класса — политика-на-тип; рекурсивность шва — долг движка; безусловность стирания (И2) —
Конституция.

## Decision

Три несущих решения (①②③) — ратифицированы. Явно открытое (R3/R4/R5, carve-out I-4) — в секции «Pending owner».

### ① Свидетель = соль-в-blob (co-shredded salt) — сужённая формула Ц-3 ⟂ Ц-7

Конструкция свидетеля (ход (d) из Fable-advisory, строго сильнее admission-refuse-навсегда и keyed-shred):

- **`payloadHash = sha256(соль ‖ payload)`**, где `соль` — случайные 256 бит, хранящиеся **в самом blob рядом
  с payload** (в erasable-зоне), а НЕ в отдельном key-store.
- **Пока payload жив** — верификация целостности полна: читаем blob (соль+payload), пересчитываем, сверяем с
  immutable `payloadHash`. Ц-3 не теряет ничего до стирания.
- **После shred** — соль умирает **тем же shred'ом, что и payload** (один жест, один контур, ноль новой
  инфраструктуры). Оставшийся в иммутабельной мета хеш становится `sha256(мёртвая-соль ‖ телефон)` — перебор
  10⁹ телефонов бессилен, оракула нет.
- **Key-store НЕ нужен.** «Ключ» — не ключ, а пер-актовая энтропия, со-размещённая с веществом, чью судьбу
  она разделяет. Q-ERA-07 (тайминг key-store) **расцепляется** этим решением.

**Сужение формулы (несущая часть вердикта — важно):**

- **Ц-7 Согласие** забирает ровно **пост-erasure content-confirmability** — она И ЕСТЬ оракул; умирает вместе
  с солью; после стирания hash не подтверждает содержимое **НИКОМУ**. Это единственный атом, который Ц-7
  outranks Ц-3, и ранг вынужден (И2 hard-erase безусловен — конституционный ранг), а не вкусовой.
- **Ц-3 Доверие** держит ровно **pre-erasure tamper-evidence** — пока payload жив, hash доказывает
  непорченность относительно immutable-акта. Провенанс, монумент-факт, аудируемость самого акта стирания,
  tamper-evidence ДО стирания — **всё это соль-в-blob сохраняет нетронутым.**

**Расцепить `payloadRef` (адрес) и `payloadHash` (свидетель):** `payloadRef` НЕ обязан быть производным от
`payloadHash` (никакого content-addressing по солёному хешу — одинаковый телефон даёт разные хеши → разные
blob; потеря dedup для erasable-PII не цена, а **исправление** — per-act копии ⇒ per-act shred чист, без
over-/under-erase на shared blob, ADR-0007 boundary #3).

**Конструкция свидетеля = функция admission-класса энтропии** (дом предиката = ADR-0007 R-G3.4 schema
admission-gate): схема на впуске объявляет `entropy-class`/`erasable`; erasable/PII-класс → **солёный
свидетель по умолчанию** (несолёный — только явно объявленным исключением; high-entropy → несолёный, dedup
сохранён). Дефолт консервативен: unknown → считать низкоэнтропийным (энтропия — свойство прайора атакующего,
не строки; миссклассификация «на глаз» неизбежна).

### ② `hashScheme` закладывается сейчас (ретрофит-невозможный шов)

Формат акта (свидетель) — **единственная поверхность с настоящей ретрофит-невозможностью** (append-only лог
замораживает записанные байты; blob-store и key-store-машинерия — НЕ заморожены, мигрируемы, пока копия одна):

- **Поле `hashScheme`** закладывается в формат свидетеля **сейчас** (плюс опциональный `keyId?` в
  act/blob-метаданных для будущей гранулярности ключа, ADR-0007 OQ-1). Причина: конструкцию хеша нельзя
  пересолить/пересхемить постфактум в append-only журнале — старые акты честно помечены схемой, новые могут
  нести иную конструкцию без слома формата.
- **Машинерию** (крипто-shred payload'ов, key-store, ротация ключей) НЕ строим сейчас — она дорога, но НЕ
  ретрофит-невозможна. Строится **по триггеру первой второй-копии** (бэкап/реплика/экспорт — горизонт
  событий, после которого plaintext-прошлое недостижимо для крипто-shred навсегда).

Цена решения — R0/R1 (поле в спеке, без кода).

### ③ Рекурсивный шов — монумент самоанонимизируется

Шов ADR-0007 применяется **рекурсивно к собственному выхлопу**. Акт стирания узла X порождает запись-монумент
A; A декомпозируется на два вещества (тот же разрез payload/акт):

- **Опознающее содержимое ВНУТРИ монумента** — атрибуция требователя («стёрто по требованию R» = персональный
  факт о R, GDPR-класс) и опознающая типовая мета — это **erasable-content**, стирается тем же швом. Забвение
  достаёт всё идентифицирующее внутри монумента, **включая имя заявителя**.
- **Неопознающий структурный факт** — «здесь был авторизованный акт стирания в T, integrity-цепь цела, рёбра
  целы, id цел» — **персистит** по Ц-3/Ц-6/Ц-2. Аудиту нужен факт санкционированности и невозможность тихой
  мутации; ему НЕ нужно вечное имя требователя открытым текстом.

Дефолт «право не дотягивается до анонимного факта» (Q-ERA-03a) **подтверждён**; «дотягивается до опознающего
внутри монумента» (Q-ERA-03b) следует автоматически тем же швом. `canonical_id` обязан быть **непрозрачным**
(не смысловой) — тогда keep-id tombstone (Q-ERA-12) совместим с анонимизацией.

Единственный нередуцируемый остаток — **топология рёбер** («анонимная могила, соединённая с тремя узлами
Маши» — низкоэнтропийный отпечаток в малом персональном круге). Рёбра резать нельзя (ломает Ц-6). Остаток
живёт в своём законном доме — **ADR-0007 OQ-3 (metadata-residue)**; ADR-0009 его НЕ дублирует, только
ссылается (см. R3, Pending owner).

### Рефрейм (зафиксировать) — монумент = зарезервированная грань единицы

Из Fable-advisory о форме единицы (`fable-core-unit.advisory.md`): монумент — не отдельная сущность, а
**ЗАРЕЗЕРВИРОВАННАЯ ГРАНЬ** единицы памяти (первый прецедент терминальной грани через акт `erased`). Отсюда
честное именование фаз:

- **Стадию-1** честно зовём **«редакция + контроль впуска»** (envelope ref-не-inline + admission-gate + delete
  строки payload — уже approved в ADR-0007 day-1). Это НЕ полная машинерия монумента.
- **Полную машинерию монумента** (терминальный акт `erased` над `payloadRef`, порт `shred`, рекурсивный шов
  над выхлопом) строим **при реальном триггере «забыть»**, не раньше.

## Alternatives considered

1. **Голый (несолёный) hash как свидетель (`sha256(payload)`).** Отклонён для низкоэнтропийного PII: hash в
   вечном логе = оракул, убивает Ц-7 (пост-erasure подтверждение содержимого). Оставлен ТОЛЬКО для
   high-entropy содержимого (где оракул требует уже иметь точный контент — подтверждение не добавляет знания;
   dedup сохранён).
2. **Opaque-UUID вместо свидетеля** (заменить content-hash непрозрачным идентификатором). **Отклонён:** убивает
   **pre-erasure tamper-evidence** — теряется способность доказать непорченность живого payload относительно
   immutable-акта, а это ровно то, что Ц-3 обязан держать. Соль-в-blob сохраняет tamper-evidence ДО стирания
   и убивает оракул ПОСЛЕ — строго доминирует UUID.
3. **Keyed-shred свидетеля через отдельный key-store сейчас (Q-ERA-01r вариант b).** Отклонён: построен на
   ложной посылке, что для смерти оракула нужен key-store. Соль-в-blob даёт тот же эффект без key-store и
   расцепляет Q-ERA-07. (Key-store вернётся только ради детерминированных солей для dedup — чего для
   low-entropy PII хотеть нельзя.)
4. **Письменный остаточный риск вместо конструкции свидетеля (Q-ERA-01r вариант c).** Отклонён конституционно:
   «зелёное переобещает» = единственный грех синтеза («канон лжёт»); правило честности не отменяется письменным
   риском.
5. **Монумент «content-only vs erase-the-fact» как бинарная ось (Q-ERA-03 в исходной постановке).** Отклонён
   как ложная ось: правильный закон — забвение дотягивается до всего ОПОЗНАЮЩЕГО (включая опознающее внутри
   монумента) и ни до чего неопознающего. Рекурсивный шов ③ растворяет бинарность.
6. **Строить всю Стадию-2 (key-store + крипто-shred) сейчас.** Отклонён: over-proof (строгость до нужды);
   машинерия не ретрофит-невозможна, ретрофит-невозможен только формат-шов `hashScheme` (②).

## Consequences

**Что разблокируется (+):**
- **Q-ERA-01r закрыт:** свидетель для low-entropy PII безопасен (соль-в-blob) — не оракул после стирания,
  полный tamper-evidence до. Парадокс свидетеля снят без key-store.
- **Q-ERA-07 расцеплен:** тайминг key-store больше не блокирует свидетеля; закладываем только `hashScheme`-шов.
- **Q-ERA-03 закрыт:** монумент самоанонимизируется рекурсивно; забвение достаёт имя заявителя внутри
  монумента; остаётся неопознающий структурный факт.
- **`payloadRef` ⟂ `payloadHash` разделены:** адрес свободен от солёного свидетеля; per-act shred чист.

**Издержки / принятые минусы (−) — честно:**
- **Потеря content-addressing/dedup для солёных (erasable/PII) payload'ов** — одинаковый телефон → разные
  хеши → разные blob. Принято как исправление (per-act shred без collateral), не как чистая цена.
- **`hashScheme` расширяет формат свидетеля СЕЙЧАС** — ретрофит-долг закрыт полем, но поле обязано лечь ДО
  первого прод-payload'а под erasable-типом.
- **Топологический остаток (рёбра опознают референта) неустраним швом** — как hash-оракул не резался без соли,
  так топология не режется без разрыва рёбер (запрещён Ц-6). Остаётся open (R3, дом ADR-0007 OQ-3).
- **Стадию-1 нельзя называть «стиранием»** — честно «редакция + контроль впуска»; полная машинерия монумента
  (`erased`-акт, порт `shred`) — по реальному триггеру. Заявлять «право-быть-забытым исполнимо» сейчас без
  порта `shred` — переобещание.

## Validation plan

В духе walking-skeleton (на прогоне, не на слове). Наследует Validation ADR-0007 §1-6, добавляет:

1. **Salted-witness pre-erasure:** записать blob (соль+payload), пересчитать `sha256(соль‖payload)`, сверить с
   immutable `payloadHash` → **совпадает** (tamper-evidence жив). Подмена payload → mismatch (tamper-detected).
2. **Salted-witness post-erasure (oracle-death):** shred blob (соль+payload гибнут одним жестом) → взять
   immutable `payloadHash` + перебрать перечислимое пространство кандидатов (fixture из N телефонов) →
   **НИ ОДИН кандидат не подтверждается** (соль мертва → hash не оракул).
3. **`payloadRef` ⟂ `payloadHash`:** два акта с ОДИНАКОВЫМ низкоэнтропийным payload → **разные `payloadHash`
   (разные соли) И разные `payloadRef`** (нет content-addressing по солёному хешу); shred одного НЕ трогает
   blob другого (per-act shred чист).
4. **`hashScheme` forward-compat:** акт со схемой S1 (legacy-plaintext / salted-v1) читается после введения S2
   → свидетель верифицируется под ОБЪЯВЛЕННОЙ схемой акта, формат журнала не сломан.
5. **Recursive-seam монумента:** стереть узел X → монумент A → assert: опознающее содержимое A (атрибуция
   требователя R, опознающая типовая мета) **отсутствует во всех read-путях**; неопознающий структурный факт
   (авторизован, integrity-цепь, рёбра, непрозрачный id) **цел**; grep монумента по имени R = 0 совпадений.
6. **Admission-class witness-construction:** тип, объявленный `erasable`/low-entropy → свидетель солёный;
   тип `high-entropy` (явное исключение) → свидетель несолёный (dedup работает). Unknown → трактуется как
   low-entropy (солёный, fail-safe).

**Критерий выхода `open` → `approved` для Pending-секции (R3/R4/R5, carve-out I-4):**
1. Владелец явно называет наличие/отсутствие режим-B-классов (R4) ДО первой реальной записи PII.
2. Порог анонимности топологии (R3) вынесен как owner-rank suждение (дом ADR-0007 OQ-3).
3. Порт `shred` законтрактован → только тогда возможна подпись под остаточным риском (R5).
4. carve-out I-4 для монумент-содержимого ратифицирован в `invariants.md` (владелец, НЕ дизайн).
