# ADR-0010 — Trust-boundary: авторитет принципала ≠ атрибуция (шов аутентификации принципала для write-плоскости)

- **Title:** Движок НИКОГДА не берёт ОСНОВАНИЕ ПРАВ (авторитет) из самозаявленного поля тела акта — «кто ты» с точки зрения прав штампует ВЛАДЕЛЕЦ ШВА (как шлюз ставит `thread_id`, ядро ОС — `uid`). Записанная АТРИБУЦИЯ «кто сделал» может жить в теле, но как ДАННЫЕ, не как основание прав. ## Контекст

`Engine.write()` (`engine.ts:73`) финализирует `recordedAt`, но `actor` берёт из тела акта ВЕРБАТИМ, и
write-PEP (`engine.ts:99-126`) гейтит права против этой самозаявленной строки. Класс дыры вскрыт живым
эксплойтом (`REVIEW §2`): `mallory` ставит `actor:'user:admin'` в тело → эскалация. Он же в трёх масках:

- **`T-grant-forgery`** (`resolve.ts:136-141`) — `grantValid` слепо верит `minted_by==='system'` как строке в теле.
- **`T-policy-node-provenance`** — policy-узел перезаписывается (защита `canWriteNamespace` живёт ВНУТРИ
  `resolveWrite`, который в горячий путь не вклинён).
- **`T-write-pep-unwired`** (`engine.ts:73-108`) — write-PEP не подключён; корень остальных двух.

Стадия-1 (force-bind `minted_by`, uncommitted) лишь **перенесла форж** `minted_by`→`actor`: та же цена атаки,
тот же результат. Это доказало: точечная затычка одного поля не закрывает КЛАСС — движку нужен
**аутентифицированный источник «кто пишет», отдельный от тела акта**. Тело — свидетельство (audit), не
основание авторитета. Аналогии доверенного штампующего: **шлюз сам ставит `thread_id`** · **ядро ОС ставит
`uid`** · **mTLS client-cert** (личность доказана, не заявлена в теле).

Read-сторона шва ПОЛУ-построена: read-принципал имеет choke-point (`ViewerResolver.resolveViewer`, paper-freeze).
Write-принципала choke-point НЕТ. Северная звезда — плагинные/потенциально враждебные агенты по недоверенному
транспорту (marketplace) → устойчивость туда и есть настоящая цель модели доверия.

Опора — порядок арбитража ADR-0006: **Конституция > policy-as-data > integrity-as-engine-duty**. «Откуда движок
берёт авторитет принципала» — долг движка (integrity-as-engine-duty), не политика-на-тип.

## Decision

### ① ИНВАРИАНТ (ратифицирован) — авторитет принципала никогда из тела; атрибуция — можно, как данные

**Движок НИКОГДА не берёт ОСНОВАНИЕ ПРАВ (авторитет) из самозаявленного поля тела акта.** «Кто ты» с точки
зрения ПРАВ штампует **владелец шва** — доверенный вызывающий/издатель, аутентифицировавший сессию (как шлюз
ставит `thread_id`, ядро ОС — `uid`), а не сам актор своим заявлением в теле.

**Критическое различение (спасено критиком — без него однострочка схлопывает две оси и ломает Закон ② монумента):**

- **АВТОРИТЕТ** (основание прав: «под чьими правами исполнять этот акт») — **никогда** из тела. Только от
  владельца шва.
- **АТРИБУЦИЯ** (записанный факт «кто сделал»: монумент, импорт внешней истории, Закон ②) — **МОЖЕТ** жить в
  теле, но исключительно как **ДАННЫЕ/свидетельство**, никогда не как основание прав.

**Следствие — FORK-U3 растворён.** `force-bind` (движок штампует actor, тело игнор) vs `attest` (актор
предъявляет верифицируемый пруф) — это **одна форма, разные реализации** одного инварианта, а не
взаимоисключающая развилка. Ратифицирован ИНВАРИАНТ, не выбор реализации. `force-bind` — единственная
реализация, доступная сегодня; `attest` инварианту не противоречит и приедет, когда появятся плагинные агенты.

Это убивает весь класс из 3 масок разом: `grant` (`minted_by`), `policy` (provenance), `actor` — все они были
«самозаявленным свойством тела, которому верят как авторитету».

### ② РЕЗЕРВ ФОРМЫ (proposed — строить по «строй») — что заложить сейчас по Закону ①

Различаем ФОРМУ (шов в порту/типе/конверте — дорого/невозможно менять позже) от ПОВЕДЕНИЯ (enforcement —
откладываем безопасно). Резервируем СЕЙЧАС только истинно retrofit-невозможное, **аддитивно к типам** (как
`provenance` был расширен аддитивно, `types.ts:212`), **БЕЗ смены подписи `write(act): Ack`** (её разморозка
преждевременно зафиксировала бы A над B — критик правка #3):

1. **Доверие принципала ПЕР-ОСЬ** (не плоский enum). Две независимые оси: «кто-действовал» и «под-чьим-
   авторитетом», у каждой — уровень аутентичности (напр. `unverified | channel | attested`). Плоский 3-enum
   схлопнул бы обе оси обратно в одну — критик правка #2.
2. **Идентификатор штампующего (issuer-id)** — кто именно проставил доверие (какой канал/издатель). Тоже
   retrofit-невозможно: journaled-акт без записи «кем подтверждён» навсегда неоднозначен для будущего аудитора.
3. **Слот под делегацию** (пустой) — место под цепочку «под чьим авторитетом» (`T-actor-delegation`, 2 оси).
   Резервируем присутствие слота, НЕ его семантику — чтобы модель делегации позже не ломала конверт.

**Почему именно это невозможно отложить:** журнал append-only. Уже записанные акты несут `actor`/`minted_by`
БЕЗ доказательства. Ретроактивно аутентифицировать историю нельзя. Без per-act маркера доверия + issuer будущий
аудитор не отличит до-шовные (недоказанные) акты от после-шовных (доказанных) → журнал неоднозначен навсегда.

### ③ ПОВЕДЕНИЕ (open — форк владельца, отложено) — выбор источника и enforcement

Отложено безопасно до построения аутентифицированного источника принципала (M5 / `ViewerResolver` write-сторона).
Три варианта источника (детально — `DESIGN §1`), из которых форма ② сохраняет нейтральность:

- **A — доверенный канал** (принципал-параметр, force-bind): дёшево, in-process/один шлюз; слаб против
  недоверенного транспорта.
- **B — крипто-аттестация** (подписанный токен издателя): дорого (ключи/ротация/инфра), сильнейшее против
  spoofing, естественная делегация — цель marketplace.
- **C — принципал-handle** (ocap, force-bind из контекста handle): без смены подписи метода, сессионный
  lifecycle, делегация через attenuated под-handle.

**Гибрид (вероятная траектория):** резервировать форму под B (Decision ②); enforce A-или-C, когда появится
реально доверенный источник. **НЕ строить channel-theatre сейчас:** channel-trust как enforce сегодня даёт
~ноль сверх force-bind — аутентифицированного принципала ещё нет (`ViewerResolver`/M5 не построен), а баги
шлюза (dup/restart) подрывают само допущение «доверенный канал».

#### ③-bis — Design-wave findings (2026-08-12, **approved** — ратифицирован владельческим делегированием 2026-08-12; design-phase, enforcement НЕ включён)
Волна из 4 агентов (architect · analyst · critic · Fable-синтез) в `_shared/topics/03-actor-model/design/`
(`01-seam-and-lifecycle.design.md` · `02-caller-reality.analysis.md` · `03-values-and-threat.critic.md` ·
`04-SYNTHESIS-decision-ready.md`) сошлась: **DEFER build, RATIFY shape.** Строить seam-код сейчас = либо мёртвые
неподключённые порты, либо дефолт-handle журналит НЕзаслуженные trust-метки в append-only лог (делает F3-театр
ПОСТОЯННЫМ, отравляет ту самую retrofit-честность, ради которой резервировали ②). Форма ② ретрофит-невозможна и
уже в коде; механизм seam — 0 форс-миграций (доказано), потому deferrable бесплатно. **Ground truth (analyst):**
всё in-process, аутентифицированного источника личности НЕТ нигде, `ViewerResolver`/M5 — 100% не построен, CLI
`write` — мёртвый stub. Значит A/C сегодня не «trust upgrade», а channel-theatre.

**Что ратифицировать как ТЕКСТ сейчас (design-выводы, не поведение):**
- **A ≡ C — растворение под-развилки:** `submit(id, act) ≡ makeEngineClient(resolve(id)).write(act)` — один
  механизм на двух временах жизни (per-write vs per-session), не конкурирующие варианты. Настоящая ось — время
  жизни принципала, не «A против C». Seam = `PrincipalResolver` (обобщает `ViewerResolver`, один шов read+write) +
  `PrincipalStamper` (drop-and-re-stamp тела).
- **Настоящая master-развилка — МОДЕЛЬ ИЗОЛЯЦИИ** (in-process vs out-of-process/plugin) — вынесена в **ADR-0011**
  (prerequisite для ③): решает, станут ли A/C когда-либо реальными, обязателен ли B, и это скрытая посылка
  marketplace-северной-звезды. M5-форма зависит от того, где сидит граница → секвенс: **ADR-0011 → M5 → ③**.

**Guardrails — зафиксировать до постройки ③ (Fable, proposed):**
- **G1 (заострён): enforcement REFUSE'ит несовпадение принципала, НИКОГДА молча не переписывает `Act.actor`.**
  Тихий rewrite (как черновик stamper'а `01-…design.md`) прячет попытку подделки и ломает атрибуцию-монумент
  (Закон ②, Ц2 Тождество). Пишем ТОЛЬКО в `principal.*`, `actor` не затираем.
- **G2:** модель изоляции — ЯВНЫЙ prerequisite ③ (ADR-0011), не пассивная сноска.
- **G3: доверие НИКОГДА не растёт по умолчанию** — ни одной journaled-метки выше `unverified` без реального
  аутентифицированного источника (запрещает дефолт-`system/channel`-handle). Плюс пред-регистрации: F7 (consent —
  явный non-goal шва), F8 (будущий B-тест: verify не должен обходить единственный PEP-choke).

## Альтернативы (рассмотрены)

- **Оставить force-bind Стадии-1 как есть** — отклонено: `REVIEW §2` показал, что класс дыры остаётся открыт
  (форж переезжает `minted_by`→`actor`).
- **Полный `resolveWrite`-fold без аутентифицированного принципала** — отклонено: гейтит самозаявленное поле,
  тот же класс.
- **Ратифицировать «провенанс НИКОГДА из тела» (сильная форма)** — отклонено (критик правка #1): over-claim,
  ломает Закон ② (монумент/атрибуция). Заменено на различение авторитет≠атрибуция (Decision ①).
- **Плоский `principal_trust` enum** — отклонено (критик правка #2): схлопывает 2 оси, теряет issuer.
- **Разморозить подпись `write()` сейчас** (выбрать A-параметр) — отклонено (критик правка #3): преждевременно
  фиксирует A над B; аддитивные поля конверта A/B-совместимы при 0 миграций.

## Последствия

- **(+)** Trust-цель «агент не может назваться другим» достижима; write-плоскость перестаёт быть authority-blind.
- **(+)** Класс из 3 масок закрывается одним инвариантом, а не тремя точечными затычками.
- **(+)** Форма A/B/C-нейтральна и аддитивна → 0 миграций вызывающих при резерве; enforcement можно докрутить позже.
- **(−)** Настоящий enforcement требует построить аутентифицированный источник принципала (M5/`ViewerResolver`
  write-сторона) — отдельный проект; до него защита остаётся частичной (Стадия-1 = честное частичное ужесточение).
- **(−)** При выборе B — реальная инфра ключей/издателя/ротации.
- **(−)** Journaled-акты, записанные ДО шва, навсегда `unverified` — потому маркер доверия + issuer (②) обязаны
  быть заложены до накопления истории.
- **Координация:** будущая разморозка/использование `write`-порта затронет вызывающих (agents-manager M3, CLI,
  будущий HTTP) — планируется через аддитивную форму, не смену сигнатуры.

## План валидации (enforcement-гейт — обязан краснеть при включении поведения)

Объединённый адверсариал-гейт (все три форжа падают ВМЕСТЕ — AGENT-LAYER §3):

1. **`forge-actor`** — `mallory` пишет `actor:'user:admin'` без санкции → **REFUSED** (сейчас: эскалирует — тест
   обязан быть КРАСНЫМ до enforcement, это и есть открытая цель).
2. **`forge-grant`** — grant с `minted_by:'system'` без пруфа → **REFUSED**.
3. **`forge-policy`** — запись в `protected_namespaces` без авторитета → **REFUSED**.
4. **Делегация** — агент авторит КАК user без санкции → **REFUSED**.
5. **Аудит-читаемость** — до-шовные акты читаются как `unverified`; после-шовные несут ось-доверие + issuer.

До построения аутентифицированного источника (③) эти тесты фиксируют ЦЕЛЬ (красные = честный разрыв
дизайн↔код), а не регрессию. Мердж Стадии-1 и включение enforcement — отдельные кивки владельца.
