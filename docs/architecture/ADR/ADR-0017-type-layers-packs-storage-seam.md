## 0. Мандат владельца (2026-10-09) — принцип решения
> Решаем от наших **7 ценностей** и по **компаунд-инжинирингу**: шаг может занять чуть дольше, но обязан
> удешевлять следующие. Избегать архитектур, которые потом заставят «переписать всё» (пример: файлы сейчас →
> Postgres потом должно быть **добавлением адаптера**, а не переписью). Избегать путаницы. Спорное и
> неочевидное — явными альтернативами для владельца. У каждого варианта — **цена** (токены/время/внимание
> владельца/новые задачи) и **вес** (какую ценность двигает): мало/средне/много.

Производное правило: **журнал не переписывается**; новое — правило чтения, необязательное поле или адаптер.

## Контекст
Мозг v0.6 собран (ADR-0016), реальных данных нет. Видение: одна память, запечатанные-но-расширяемые типы,
пакеты, миллионы записей. Линзы назвали двери, закрываемые **первой реальной записью**. Сегодня: типы без
пространства имён (id определения `typedef:task`), в `provenance` — `schema_v=1`, `type`, `type_v` (целое),
id единицы `u_<ts36><6 rand>` (`ids.ts`).

## Решение

### D1. Пространства имён, версии, что лежит на записи
- **Слои:** `core:` (ядро: мета-типы `type-def`, `predicate-def`, `scope` + интерфейсные типы `task`,
  `decision`, `note`, `person`, `day`, `friction`, `raw` — ровно `GENESIS_TYPES`; `predicate-def` в genesis
  присутствует, валидатор имён предикатов применяется к ним и к любым будущим predicate-def) → `sys:<id>/…` → `pack:<id>/…`
  → `u:<name>`. **`sys:` и `pack:` сейчас только ЗАРЕЗЕРВИРОВАНЫ** (различаются лишь доверием, кода-различия
  нет — реализовать с первым пакетом). **Тропа** = тип `u:` со `status: candidate`
  (ADR-0016 D11); повышение тропы в пакет = новый type-def + ребро `instance-of` у записей; **id записей не
  меняются** (V2).
- **Каноническое написание ядра — голое имя.** Имя без `:` **есть** `core:`. `core:task` принимается на входе
  и нормализуется **в** `task`, не наоборот. Причина: id определения `typedef:<name>` — цель рёбер
  `instance-of`, а `edgeIdOf` (ADR-0015) хеширует `{source, predicate, target}` — смена канона ядра сломала
  бы тождество этих рёбер. Сегодня ни одно имя типа/предиката не содержит `:` (проверено). Разбор:
  `typedef:` берёт всё после **первого** `:`; в сегменте id пакета `:` запрещён. Глоссарий: capability
  `core:manage-*` (`constitution.ts`) — другое пространство, не слой типов.
- **Валидатор имён (дверь ДАННЫХ — обязателен до первого не-genesis определения).** Сейчас
  `Registry.addType` (`registry.ts:29-34`) пишет по голому имени, последний побеждает — коллизия `comment`
  двух пакетов реальна. Правила для type-def **и** predicate-def (cardinality предиката глобальна):
  (а) голое имя допустимо только из `CORE_NAMES` — он **ВЫВОДИТСЯ** из `GENESIS_TYPES`
  (`packages/brain/src/domain/genesis.ts`), а не ведётся вторым списком руками (иначе два списка разойдутся); (б) иначе префикс ∈
  {`sys:`,`pack:`,`u:`}, неизвестный → отказ; (в) переопределение ядерного имени не от genesis → отказ
  (иначе `task@2` плагина перекроет ядро); (г) в replay голое не-ядерное имя читается как `u:<имя>`
  (alias), журнал не правится.
- **Ref-позиции.** `resolveScopeRef` (`validate-act.ts:90`) считает любую строку с `:` готовым id —
  поэтому слаг области `:` не содержит, а имена типов в ref-позиции (scopes, цели рёбер) не попадают;
  тип записи адресуется только полем `type` или id `typedef:<name>`.
- **Версии:** ссылка на тип = `name@major`. `type_v` на записи = **major** (как сейчас, целое). В пределах
  major — только новые **необязательные** поля (minor живёт в type-def, на запись не пишется: любой minor
  читает любую запись своего major). Ломающее → `@2` + **upcaster** (чистая функция чтения в определении
  типа); журнал не переписывается. Наследование — `extends: "name@major"` (ADR-0016 D5); соответствие
  интерфейсу — новое необязательное поле type-def `implements: ["task@1"]` (не наследование).
- **На записи СЕЙЧАС — новых полей нет.** `type` + `type_v` + `provenance.schema_v` уже есть. Атрибуция
  записи/ребра к пакету = **принципал-писатель** (`actor`/`meta.author`, `to-act.ts:134,159,196`), его
  штампует шлюз/сервис, не клиент (`engine.ts:92`). Формат принципала — **дверь данных**: пакет ВСЕГДА
  `pack:<id>`, системный — `sys:<id>` (genesis остаётся `system:genesis`). Определение типа/предиката
  принимается только от принципала с тем же префиксом, что у имени. Делегирование (агент пишет за пакет,
  `engine.ts:97-98`) — необязательный `provenance.pack`; нет поля → атрибуция по `actor`.

| Вариант | Цена | Вес |
|---|---|---|
| **A. Префикс в строке `type`, ядро голое (выбран)** | мало (одно правило валидации + нормализатор) | много: V2, V5, V6 (рёбра не меняют id) |
| B. Отдельное поле `ns` | средне (два источника имени) | средне |
| C. Без пространств, уникальность реестром | мало сейчас, много потом (конфликт имён двух пакетов неразрешим) | мало |
| D. Канон `core:task` + переписать журнал | много (перепись, edge-id ломаются) | против V2/V6 |

### D2. Класс хранения на тип — ЗАРЕЗЕРВИРОВАНО (не писать до первого потребителя)
`parseTypeDef` молча отбрасывает неизвестные ключи (`registry.ts:~140`), исполнителя нет — обязательное
поле без потребителя = мёртвые данные. Поэтому ниже — **словарь-резерв**, не поле реестра сегодня.
- `persistence_class`: `event` (append-only, неизменно),
  `state` (текущее значение; история — по политике, а не акт на каждое изменение), `config` (версионируемый
  документ; файл может быть истиной, ADR-0016 D7), `ephemeral` (TTL, **не память, в журнал не попадает**).
  Когда появится потребитель: отсутствие читается как `state` (`friction` → `event`) — без переписи.
- `placement` (полоса хранения: `journal` | `pg` | `file`) — политика-данные на тип (ADR-0006).
- **Едины всегда:** один реестр типов, один id-простор, одно пространство рёбер (рёбра — записи, ADR-0016 D6;
  физическая полоса ребра — политика предиката, по умолчанию полоса ядра). Полоса — деталь размещения,
  не меняет ни id, ни тип, ни вид.

| Вариант | Цена | Вес |
|---|---|---|
| **A. Словарь-резерв сейчас, поле — с первым потребителем (выбран)** | мало | средне сейчас, много потом: V4, V5 |
| A′. Обязательное поле сразу | мало, но мёртвые данные навсегда | мало (нет исполнителя) |
| B. Всё в один журнал | мало | ломается на ~20–50k актов; против V4 |
| C. Хранилище+id на пакет | средне | против V6: «острова» |

### D3. Шов хранения
Цель: Postgres = **чисто добавочный адаптер**. Четыре варианта:

| Вариант | Цена | Вес |
|---|---|---|
| A. Сделать весь движок async (Promise во всех вызовах `Engine`) | много (правка ядра, всех вызовов; `write(act): Ack` заморожен ADR-0010) | много, но ценой переписи — против мандата |
| B. Sync-порт + всё в RAM + write-through в PG | мало | мало: миллионы не держатся в RAM; PG — лишь копия |
| C. Функциональное ядро + async-оболочка (порты `JournalPort`/`ProjectionPort`) | средне (новые порты + одна правка ядра: read-порт, инкрементальный `apply`) | много: V3, V5; нужен, когда журнал перерастёт RAM |
| **C-bis (аналитик). Хук `JournalSink.append(act, seq)` в `DurableFsStore.writeAct` после fsync (~20 строк) + PG-хвостовик как проекция (выбран как ШАГ 1)** | мало (0 правок Engine/порта/вызовов) | много сейчас: весь выигрыш PG-запросов (find/JOIN/pgvector); истина остаётся журналом |

**Рекомендация (F2):** C-bis сейчас; C — по триггеру (>~50k актов или запись >200 мс). Оба аддитивны, C-bis
не мешает C.
**Отказ проекции (C-bis):** если проекция (Postgres) недоступна или медленна, fsync-запись в журнал **НЕ
блокируется** и не откладывается; хук лишь фиксирует отставание, а проекция догоняет с сохранённого
смещения журнала (`seq`) после восстановления. Истина — журнал; проекция пересобираема.

**Суть C (на будущее; ядро правится ОДИН раз).** `Engine` читает хранилище внутри записи (idem —
`engine.ts:145`; полная перезагрузка проекции — `:53,153,158`), на миллионах это не живёт. Тогда: узкий sync
read-порт в ядре + инкрементальный `apply(act)`; `write(act): Ack` не меняется; async `JournalPort`/
`ProjectionPort` в оболочке brain. Sync-вызовы к переводу: `read/access.ts:125,165,238-240`,
`service/idem.ts:74`, `service/runtime.ts:155,211,263-272,404-413` (`close()`/`badLineCount` — в порт здоровья).

**Три кодовые привязки к файлу (снять до любого PG-адаптера; данные не затрагивают):** `BrainDomain.store:
DurableFsStore` (`schemas.ts:48,84`) → типизировать на `StorePort`; `scanJournalRegistry` читает файл мимо
порта (`registry.ts:200`) → проход 1 реестра за порт; backup копирует файл → за порт.

**Формат журнала.** Версия конверта — `provenance.schema_v`; отсутствует → 1; `provenance`-строка
(`types.ts:351`, старая форма) читается наравне с объектом. Читатели поддерживают **все** прошлые версии
навсегда (upcaster), журнал не переписывается. Адаптер хранит **акт целиком дословно** (PG: `jsonb` +
колонки-индексы), неизвестные поля сохраняются → replay без потерь.
**Правило replay/миграции (дверь данных):** идут **ниже Engine** (адаптер→адаптер), сохраняя порядок строк
(`seq` несёт смысл: `rev`, «последний побеждает») и `recordedAt`; через `Engine.write` запрещены (он
перештамповывает время, `engine.ts:74`). Битые строки replay **сообщает**, не теряет молча.

### D4. Id и ключ идемпотентности
- **Id непрозрачны**, их никто не разбирает (ts внутри — подсказка, не данные). Чеканит только мозг; плагины
  id не чеканят — получают в ответе. Внешние id → `source: {kind, ref}` (D7), не в наш id.
- Формат `u_…` остаётся валидным навсегда. Перед появлением **второго писателя** (PG-полоса или софт пакета)
  случайная часть расширяется до ≥12 символов — аддитивно (расширить шаблон; старые id валидны).
  **Измеримый триггер:** до того, как любому второму процессу/плагину выданы права записи, **или** при
  ≥100 000 выданных id — что наступит раньше.
- Рёбра — `edgeIdOf` (ADR-0015), детерминированы и переносимы между движками при условии канона имён (D1).
- **Idem:** текущая схема (штамп `<64-hex>.<tag>`, `idem.ts:10`) = **v1**. Будущие схемы — префикс `i2:`;
  порядок обязателен: **сначала читатель учится `i2:`** (сейчас иной формат при пересборке игнорируется),
  потом пишущие. Индекс idem — проекция, пересобирается из журнала. Сейчас ключ в пространстве **диалога**
  (`idemKey(dialog, …)`, `idem.ts:35`); для пакетов добавится пространство **принципала пакета** — это
  изменение (аддитивное), не текущее поведение. Открытое из ADR-0016 D10
  (id **входящего** сообщения) — закрыть до первой реальной записи.

| Вариант | Цена | Вес |
|---|---|---|
| **A. Непрозрачные id + версионируемый idem с префиксом (выбран)** | мало | много: V2, V5 |
| B. UUIDv7/ULID сейчас | средне (два формата сосуществуют) | средне; выгода только при многих писателях |

### D5. Манифест пакета — скелет (`manifest_v: 0`, **experimental**)
```
{ manifest_v: 0, id: "pack:bt", version: "0.1.0", requires: { core: "1", packs: {} },
  types: [type-def…  (+ implements; persistence_class — резерв D2)],
  predicates: [predicate-def… from/to по интерфейсам],
  policies: { retention, cold_after, visibility_default },
  consent_purposes: [{ id, meaning, types }],
  views: [{ id, query }],
  capabilities_requested: { read: ["task@1", …], write: ["pack:bt/*"] } }
```
Манифест — запись (V5: экспорт уносит цепочку). Писать типы пакета — только его принципал (capability на
тип, ADR-0010); ссылаться рёбрами — любой. Удаление пакета → типы `cold`, данные и рёбра живут (V4).
Установка = грант владельца по `consent_purposes` (V7 — форма). Сторонних пакетов нет до `manifest_v: 1`.

### D6. Кухня шлюза → ADR-0018 (будущий)
Лестница L0–L4 вынесена в ADR-0018. Здесь остаётся только **инвариант fail-open:** пока тип шлюза не
переключён на мозг, шлюз принимает, дедуплицирует и отвечает при любом состоянии мозга; запись в мозг идёт
через outbox и деградирует, а не блокирует.

## До первых реальных данных (data doors)
1. Валидатор имён типов и предикатов + замороженный `CORE_NAMES` (D1).
2. Формат принципала `pack:<id>`/`sys:<id>`, штамп только шлюзом/сервисом, «префикс определения = префикс
   писателя» (D1).
3. Закрыть id **входящего** сообщения (ADR-0016 D10) и пространство idem (D4).
4. Правило «replay ниже Engine, порядок + `recordedAt`, битые строки — отчётом» — как тест (D3).

## Можно позже (code doors)
Типизация на `StorePort` и три файловые привязки · `JournalSink`/PG-проекция · read-порт/`ProjectionPort`
(C) · `i2:` (читатель раньше писателя) · расширение rand в id · `persistence_class` · манифест · `sys:`/`pack:`.

## Последствия
- (+) PG, пакеты, тропы добавляются адаптерами/данными; журнал, id и атрибуция переживают всё (V2, V5, V7).
- (+) Межпакетные рёбра легальны через интерфейсы (V6).
- (−) До данных — 4 двери (≈1 день); кодовые двери растут линейно с кодом, но без миграции данных.
- (−) Потом (C) — двойственность sync-ядра и async-оболочки.
- (−) «Голое имя = ядро» неочевидно; лечится нормализатором и текстом ошибки.

## План валидации
1. **Бумажный баг-трекер** (0 кода): манифест `pack:bt` (issue/comment/label, `implements task@1`) +
   сценарий «создать → связать с задачей → закрыть» на 4 глаголах. Считать правки кода мозга. Ожидание:
   только валидатор имён. Нужны подписки/триггеры → следующий ADR о контракте софта пакета.
2. **Валидатор имён:** голое не-ядро, неизвестный префикс, ядерное имя от не-genesis, определение от чужого
   принципала → отказ; replay голого не-ядра → `u:<имя>`.
3. **Replay-тест журнала (ниже Engine):** журнал (вкл. акты без `schema_v`, `provenance`-строку, битую
   строку) → адаптер A и B → `find/read` побайтно равны; порядок и `recordedAt` сохранены; битая строка в
   отчёте; неизвестные поля целы.
4. **Стабильность тождества:** `edgeIdOf` и `typedef:` для ядра не меняются при вводе `core:`-синонима.
5. **Idem:** старый ключ v1 и новый `i2:` сосуществуют; повтор схлопывается; два пакета не сталкиваются.
   *(Часть про `i2:` — поздняя дверь кода (читатель учится `i2:` раньше писателя), не гейт первых данных;
   до неё проверяется только v1 + закрытие id входящего сообщения.)*

## Откат
Откат = убрать валидатор/нормализатор, хук и адаптеры; журнал не тронут, записи читаемы. Необратимо лишь
записанное после ратификации (канон имён, формат принципала, idem v1) — поэтому решаем сейчас.
