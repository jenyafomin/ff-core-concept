# 40-dialogue — Dialogue Graph Threads

**Group purpose:** The design dialogue graph — every owner-Claude exchange is a node.
This is the living record of HOW decisions were reached (process), not just WHAT was decided.

## What lives here
- `YYYY-MM-DD-THREAD-topic.md` — a dialogue thread (series of nodes N-001, N-002…)
- One file per major dialogue thread; nodes are sequential within the file.

## Ordering rule
DATE prefix: `YYYY-MM-DD-` (the date the thread started).
Within a file: node IDs are sequential (N-001, N-002…) and never reordered.

## Process
- Every significant owner response → becomes a node in the active THREAD file.
- Nodes have types: goal · principle · open-question · answer · insight · problem · decision
- Edges: refines / answers / raises / tension-with / grounds
- A thread is NEVER summarized away — it is the full record.
- DECISIONS-LOG (00-canon) = one-line digest; THREAD = the full graph.

## DECISIONS-LOG vs THREAD
- DECISIONS-LOG (in 00-canon): one line per key decision, for fast scanning.
- THREAD (here): full node graph with all context, for traceability.
